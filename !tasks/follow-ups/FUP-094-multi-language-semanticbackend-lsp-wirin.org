* Cross-Cutting Risks

- *Server install ergonomics*: not all servers ship as single binaries.
  jdtls, kotlin-lsp need JVM; sourcekit-lsp needs Swift toolchain.
  Install-hints must be platform-aware. Consider per-OS hint variants.
- *Cold start cost*: rust-analyzer (~10s), jdtls (~10s), clangd needs
  =compile_commands.json= or is degraded. Mitigation: warmup blocks,
  AnnotationSemanticBackend fallback during warmup.
- *Memory footprint*: 5 LSPs warm ≈ 2GB RAM. The =max-warm-servers 6=
  cap + LRU eviction in PLAN-319 W1 handles this, but verify on real
  multi-language workspaces.
- *Capability variance*: some servers don't implement =textDocument/inlayHint=
  or partial =workspace/symbol=. Capability discovery from =initialize=
  response gates feature use per PLAN-319 W2; verify each new server.
- *Multi-language workspaces*: a TS+Python+Go monorepo will spawn 3 LSPs.
  Confirm LRU keeps the hot ones warm and evicts cold ones.
