* Decision (W1)

=InteractiveMode.injectRemoteInput= routes remote text straight through =session.prompt=, which
handles =/slash= + extension commands but NOT the terminal-only prefixes the input-controller
intercepts: =!cmd= / =!!cmd= (run bash), bare =.= / =c= (empty continue).

This is INTENTIONAL for W1: a remote operator should not be able to execute arbitrary shell on
the host by prefixing =!=. So an injected =!ls= is sent as literal prompt text, not executed.

* Open question

Decide the long-term contract:
- Keep prompt-only (current) — safest; document in web composer help text.
- Allow =.=/=c= continue (harmless) but never =!bash=.
- Gate =!bash= behind an explicit per-session "allow remote shell" toggle.

* Acceptance (when picked up)
