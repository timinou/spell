** Important: declaration-kind keyword guard

In ~pi-treesit-declaration-kind~, the inner cond maps each keyword to a kind string. The defconst replaces the guard check (is this an Elixir def keyword?), NOT the individual kind mappings. Structure after the change:

#+begin_src elisp
((string= type "call")
 (let* ((target (treesit-node-child node 0))
        (target-text (when target (treesit-node-text target t))))
   (if (member target-text pi-treesit--elixir-def-keywords)
       (cond
        ((member target-text '("def" "defp")) "def")
        ((string= target-text "defmodule") "defmodule")
        ;; ... rest of kind mappings ...
        (t target-text))  ;; fallback within known keywords
     type)))  ;; non-keyword call node → raw type
#+end_src

Note the restructure: the catch-all ~(t type)~ that was previously inside the inner cond now becomes the else branch of the ~if~, making the control flow explicit: known keyword → map to kind, unknown call → return raw type string.
