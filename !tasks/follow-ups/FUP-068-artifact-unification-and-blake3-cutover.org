* Initial Message

What would it take for Spell's org mode to be a fully featured graph that also includes memories, simlar to the SurrealDB plan in the kdl worktree?

* Intention & Purpose

Track the deferred work item: turning =artifact://= and =agent://= into
first-class org items with =:KIND: artifact= and migrating
content-addressed storage from sha256 to blake3. Settled out of v1 of
the Org Graph Memory project ([[id:specs/org-graph-memory.md]]) because
v1 already ships ~8 weeks of work; artifact unification is a separable
~1 week effort that does not block any v1 capability.

* Context

After v1 lands, the artifact landscape is:

- =artifact://<session-id>/<agent>/<tool>/<n>.<ext>= — append-only log files via =ArtifactManager= in =packages/coding-agent/src/=
- =agent://<id>= — subagent markdown via =AgentOutputManager=
- blob storage: filesystem, sha256-addressed, in =~/.spell/agent/sessions/.../blobs/=

The graph memory model already reserves =:KIND: artifact= and the
=PRODUCED= edge from episode → artifact. v1 does not populate either
because the existing artifact stores keep working untouched.

This FUP describes what would change in a follow-up FEAT to close
that gap.

* Suggested Scope (for the eventual FEAT)

- New =artifact_kind "..."= KDL primitive matching the SurrealDB plan vocabulary (tool-log, subagent, export, brand-asset, meeting-notes)
- One org item per artifact under =<repo>/.spell/memory/artifacts/<kind>/<id>.org= with =:BLOB:= property pointing at the blake3 hash
- Filesystem layout: =<repo>/.spell/blobs/<h[0..2]>/<h[2..4]>/<hash>= (sharded)
- Hash algorithm: blake3 (write side); sha256 read-side compat shim accepts =sha256:<h>= references during a deprecation window
- Migration: walk existing =ArtifactManager= and =AgentOutputManager= stores, hash each blob, write the org item, leave originals in place behind a feature flag for one release
- Recall: =scope: ["artifact"]= surfaces blobs by FTS over their referenced metadata + graph walk via PRODUCED edges
- Tool surface: =read artifact://<kind>/<id>= still works; resolves through the new org item

* Out of v1 because

- 6 weeks of crate work (FEAT-A → FEAT-L) already lined up
- Existing artifact paths function correctly; there is no v1 capability that requires unification
- blake3 cutover invalidates blob references in active sessions; needs careful migration
- Each artifact-producing site (tool-log, subagent, brand-asset, etc.) needs review for retention and visibility settings
