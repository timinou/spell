* Context

FEAT "Stored programs (W4)" ships READ-ONLY stored programs (find/org-query/memory/
bash-read). Write tools (edit/create/org-set) are rejected at store time there, because
a stored WRITE program re-run unattended that errors halfway leaves PARTIAL EFFECTS
(error class E4). This FUP lifts that restriction — but ONLY after the partial-effect
class is structurally impossible.

* Blocked-by (HARD)

PLAN "D3: Transactional write lane for execute". W4-write MUST NOT enable any write
tool in a stored program until D3 makes program effects all-or-nothing. Until then a
flaky Monday-morning rollup that writes could half-corrupt the repo on every failed tick.

* Scope

- Remove the W4-read store-time rejection of write-tagged programs (effects.ts `write`
  set) — gated behind a check that D3's transactional lane is active.
- A stored WRITE program re-run wraps in D3's BEGIN…COMMIT/ROLLBACK envelope: the
  whole program commits atomically on success, discards on error. No partial landing
  across re-runs.
- Unattended callers (org tile tick, canvas refresh) that run a WRITE program must
  surface the commit/discard outcome (reuse D3.5 cost-meter enlisted-vs-committed
  counts) so a silently-discarded write tile is visible, not invisible.
- Decision: a WRITE stored program triggered on an automatic tick (not an explicit
  user/agent run) should default to DRY-RUN-then-confirm OR be explicitly opt-in per
  tile — pick at implementation; do NOT let an unattended tick silently mutate the repo
  without a visible record. (This is the one genuinely new risk W4-write introduces.)

* Tests

- A stored write program that errors mid-run → zero effects across the re-run (inherits
  D3's decisive test, exercised through the stored-program path).
- A stored write program that succeeds → atomic commit, outcome surfaced to the caller.
- A write program cannot be stored/enabled when D3's lane is inactive (guard holds).

* Acceptance

A stored program may mutate, but only transactionally (D3), and an unattended write tick
leaves a visible commit/discard record — never a silent partial mutation.

* Relationships

Depends on D3 (PLAN) + the W4 FEAT. Part of the "execute as sole lane" (D-3) endgame.
