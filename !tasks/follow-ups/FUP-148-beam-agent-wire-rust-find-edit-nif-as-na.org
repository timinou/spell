Parent: PLAN-344. The two highest-value extensions after v0, for actually USING the agent on code.

* (A) Wire the Rust kernel as native tools
v0 has only the homoiconic meta-tools + PTC compute. To make it a real CODING agent,
expose the proven pi-kernel NIF (beam/pi_kernel_nif, P3 — 3 gates green) as native
ToolRegistry entries:
- `find` (read/search/outline over the code-graph) — the read lane is already NIF-proven.
- `edit` — deferred to P5 in the roadmap (writes + lock-liveness); start with find.
Add them in SpellAgent.Tools as kind: :native entries calling the NIF, so the agent can
navigate + read code. Acceptance: (tool/find {:target "…"}) from inside a program returns
chunks identical to the napi path (the P3 gate-1 corpus).

* (B) Durable persistence of agent-defined tools
v0 stores defined tools in-memory (ToolRegistry Agent), lost on restart. Make a defined
tool a DURABLE stored program (the W4 vision, specs/beam-orchestrator/07):
- persist {name, params, doc, source} to org (a tools.org) or memory (kind: playbook with
  a :source block).
- on boot, hydrate ToolRegistry from the durable store.
Acceptance: define a tool, restart the app, the tool is still callable. A defined tool is
inspectable + diffable in git (code-as-data, the whole point).

* Notes
These are the natural next steps the user will reach for once playing with v0. (A) makes it
useful on real repos; (B) makes the self-coding persistent. Neither blocks v0 — both are
additive on the shipped substrate.
