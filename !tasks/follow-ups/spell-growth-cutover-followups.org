* Scope
** In scope
- Design and implement post-v1 support for sandboxed external action packages beyond first-party Spell packages.
- Revisit the v1 first-party action registry abstraction and extend it with a safe external plugin boundary.
** Out of scope
- Any v1 cutover-critical behavior. External packages are explicitly deferred from the main cutover plan.
** Boundary rationale
- The user wants external package support eventually, but unsafe plugin loading from prior growth implementations must not block or compromise the v1 cutover.

* Tests
- `packages/spell-server/test/plugins/external-registry.test.ts`
  - Explicit package declarations load or fail deterministically.
- `packages/spell-server/test/plugins/sandbox-boundary.test.ts`
  - External packages cannot escape typed state/artifact/provider/channel APIs.
- `packages/spell-server/test/plugins/process-isolation.test.ts`
  - Out-of-process plugin execution preserves typed RPC contracts and failure reporting.

* Edge Cases
- External packages must not gain arbitrary filesystem, network, DB, or process-spawn access by default.
- Failure reporting must preserve truthful plugin stderr/stdout and typed error shapes.
- Package reload/restart policy must be explicit; hot-reload is not assumed.

* Acceptance Criteria
- External action packages remain outside the v1 cutover path.
- A later implementation can load explicitly declared external packages through a sandboxed out-of-process runner with typed boundaries.
