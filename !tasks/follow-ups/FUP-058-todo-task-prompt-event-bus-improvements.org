* Candidate improvements

** Remove or demote `add_phase` legacy alias
:PROPERTIES:
:CUSTOM_ID: FUP-todo-01::drop-add-phase
:END:
- `add_phase` is documented as a legacy alias for `add_group`. Neither is used in 30 sessions. Either remove from schema or hide from prompt surface.
- Files: `packages/coding-agent/src/tools/todo-write.ts`, `packages/coding-agent/src/prompts/tools/todo-write.md`.

** Add "first action" rule to plan-mode-approved
:PROPERTIES:
:CUSTOM_ID: FUP-todo-01::first-action-rule
:END:
- Add directive to `plan-mode-approved.md`: "You MUST emit `todo_write` (or confirm auto-seeded) BEFORE any write-enabled tool call."
- Today's 2 aborts were triggered by users Ctrl-C-ing agents that skipped this.
- File: `packages/coding-agent/src/prompts/system/plan-mode-approved.md`.

** Surface gateArtifact in examples (0% usage)
:PROPERTIES:
:CUSTOM_ID: FUP-todo-01::gate-artifact-example
:END:
- `gateArtifact` is never used. Either it's redundant or the sniper-pattern examples don't illustrate when it adds value.
- Add one `gated-task` example using `gateArtifact` for a "must produce test output file" task.
- File: `packages/coding-agent/src/prompts/tools/todo-write.md`.

** Expose `todo:task:status` as extension hook
:PROPERTIES:
:CUSTOM_ID: FUP-todo-01::event-hook
:END:
- `todo-write.ts::emitTodoGraphEvents` emits `todo:task:status {from,to,taskUri}` on every status change.
- No extension hook surface consumes it. Add a `post_todo_status` hook to `packages/coding-agent/src/modes/components/hook-*` so `.spell/extensions/*` can react (e.g. auto-run migrations when `orgItemId: SCHEMA-*` completes).
- Keep backwards-compat: default no-op when no hook registered.
- Files: `packages/coding-agent/src/tools/todo-write.ts`, `packages/coding-agent/src/modes/components/hook-input.ts` (or equivalent).

** Gate verification as subscriber
:PROPERTIES:
:CUSTOM_ID: FUP-todo-01::gate-as-subscriber
:END:
- Gate verification currently runs imperatively in `todo-write.ts::execute` on the `update → completed` path. Move to a dedicated subscriber on `todo:task:status` with `pending→completed` transition, keeping the veto via `AbortSignal`. Decouples gate logic from the mutator and allows custom gate plugins.
- Deferred — only valuable if/when plugin API stabilizes.

** Structured DAG stream for external consumers
:PROPERTIES:
:CUSTOM_ID: FUP-todo-01::dag-stream
:END:
- `LoopDAG.qml` and `todo-dashboard-bridge.ts` each reconstruct DAG state from `todo:change { groups }`. A `todo:dag:snapshot` event emitted alongside `todo:change` with `{nodes, edges, readyFrontier}` would remove duplicated graph math on the consumer side.
- File: `packages/coding-agent/src/tools/todo-write.ts::emitTodoGraphEvents`.
