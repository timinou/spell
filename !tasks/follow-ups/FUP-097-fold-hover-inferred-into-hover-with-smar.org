* Initial Message

PLAN-319 shipped `#hover` (tree-sitter written sig via AnnotationSemanticBackend) and `#hover_inferred` (LSP-resolved type via LspSemanticBackend) as two separate qualifiers. UX feedback: this is taxonomy leak — the agent has to know which qualifier maps to which backend.

Fold both into a single `#hover` qualifier that does a smart merge.

* Behavior matrix

| written (graph)  | inferred (lsp)   | output                                |
|------------------|------------------|---------------------------------------|
| Some(x)          | Some(x)          | x  (no source label — clean agreement) |
| Some(x)          | None             | x  [source: graph]                    |
| None             | Some(y)          | y  [source: semantic]                 |
| Some(x)          | Some(y), x ≠ y   | written: x 
 inferred: y             |
| None             | None             | NotFound                              |

NB: "agree" = normalised-whitespace equality. Conservative — if in doubt, show both.

* CodePath surface

Before:
- `find { foo.ex::handler #hover }`           → graph-only
- `find { foo.ex::handler #hover_inferred }`  → lsp-only

After:
- `find { foo.ex::handler #hover }`                   → smart merge
- `find { foo.ex::handler #hover [source=graph] }`    → graph-only (cost escape hatch)
- `find { foo.ex::handler #hover [source=semantic] }` → lsp-only

`#hover_inferred` qualifier is hard-removed (no callers — qualifier shipped in PLAN-319 W3, was never wired to the agent prompt).

* Why now

PLAN-320 introduced #hover as edit-scope alias (#sig) at unified.rs:104-106. After the PLAN-319+320 merge, #hover has dual semantics:
- find  → "show me the type/signature"
- edit  → "operate on the signature scope"

This is fine (different tools). But the find-side semantics need to be unified before FUP-094 wires multi-language LSP; otherwise we ship 15 languages with two-qualifier taxonomy.

** Change

1. HoverOutcome enum in pi-code-graph::semantic::mod
   - Agreed { repr: String }
   - Single { repr: String, source: HoverSource }
   - Disagreed { written: String, inferred: String }
   - HoverSource ∈ { Graph, Semantic }

2. merge_hover(written: Option<HoverInfo>, inferred: Option<HoverInfo>) -> HoverOutcome
   - Normalise both reprs (trim, collapse whitespace, strip trailing semicolon)
   - Compare normalised; if equal → Agreed
   - If exactly one Some → Single
   - If both Some but different → Disagreed
   - If both None → return None (caller emits NotFound)

3. type_resolver dispatch
   - On #hover qualifier:
     - Read [source=…] predicate; default = Both
     - If source=graph: call AnnotationSemanticBackend only
     - If source=semantic: call LspSemanticBackend only
     - If source=both (default): call BOTH via Composite (or directly both)
   - Wrap result in HoverOutcome via merge_hover
   - Format Outcome → NodeRefDto with optional source label

4. Defensive: in pi-code-path::unified::TargetShape::classify, line 106 fallback for unknown qualifiers should return a diagnostic for read-only semantic qualifiers (#hover_inferred, #diagnostics, #type_definition, #signature, #inlay), not silently fall into TargetShape::Symbol.

** Edge Cases
- Both backends returning empty string → treat as None
- "Agree" normalisation must NOT cross structural boundaries (don't collapse "fn foo(x)" with "fn foo (x)" but DO collapse "fn  foo" with "fn foo")
- Annotation backend returns the written sig from SymbolNode::detail; for languages without LSP, source=semantic should return Single { source: Graph } (fallthrough not error)
- Disagreed case: order is (written, inferred), never inferred-first
- For symbols without an LSP server (no file-type match in CompositeSemanticBackend), source=both returns Single { Graph }
