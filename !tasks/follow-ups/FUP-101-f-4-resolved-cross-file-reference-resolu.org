* Outcome

Closes the F-4 finding from FUP-098 (cross-file def/ref/call edges
silently empty for engine-profile languages). Split into two parts; both
landed on =fup-099-live-semantic-dispatch=.

** F-4a (commit 6d9d50ff5): workspace-unique name fallback (S5)

=resolve_reference_target= gained a final strategy S5: after same-file
(S1/S2) and import-binding (S3/S4) miss, if exactly ONE symbol in the
whole workspace bears the target name, link to it. Ambiguity yields no
edge. =build_workspace_name_index= precomputes the unique-name map once
per build (O(symbols)), so S5 is O(log n) per unresolved reference.

This gives every tree-sitter language usable def/ref edges offline for
the common case of a workspace-unique target, even with empty import
bindings.

** F-4b (commit a1b2c3d4e): the premise was WRONG -- precise path already works

The F-4 finding claimed Rust does not populate import_bindings and
needed ~200 LOC per language. *Empirically false.* =rust_imports= +
=resolve_rust_import= + =rust_module_candidates= + the builder's
ImportBindingMap population loop are all present and functional. The
real gap was the absence of any END-TO-END test through the real
extractor + builder.

Added two regression-guard tests (real 4-file Rust crate fixture with an
*ambiguous* =render= so S5 cannot mask the result):
- =rust_use_binding_resolves_ambiguous_cross_file_reference= -> exactly 1 edge
- =rust_bare_call_without_use_does_not_resolve_ambiguous_name= -> 0 edges

Teeth verified: temp-breaking the binding-insertion loop flips the
positive test RED while the negative stays GREEN.
