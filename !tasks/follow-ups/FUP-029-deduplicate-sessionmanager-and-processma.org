* Scope
=packages/spell-server/src/session/session-manager.ts= and =packages/telegram-bridge/src/rpc/process-manager.ts= implement nearly identical session lifecycle logic (idle timeouts, crash cleanup, spawn args, state persistence) with different error handling.

PLAN-086 completion report documented this as a conscious deviation to avoid breaking telegram-bridge. The original PROJ-019 spec called for refactoring ProcessManager to use SessionManager, but this was skipped.

** Options
1. Refactor ProcessManager to delegate to SessionManager with TelegramLifecycle — preserves external API, removes duplicate logic
2. Extract shared =SessionCore= base class that both import — less invasive but still reduces drift
3. Keep separate and document alignment contract — lowest effort, highest drift risk

** Risk
Fixes to idle timeouts, crash cleanup, spawn args, or persistence applied to one implementation may not propagate to the other, causing divergent behavior between Telegram and autonomy modes.
