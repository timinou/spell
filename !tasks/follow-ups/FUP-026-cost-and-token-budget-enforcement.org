* Scope
Enforce =max_cost_usd= budgets on setups and goals. Usage is already tracked in state from RPC events; this work closes the loop by consuming token counts from =message_update= events, computing spend, and failing/escalating goals when configured budgets are exceeded. Exceeding budget should count as goal failure and follow the standard escalation path: Telegram notification, BUG org item creation, then pause.

* Edge Cases
- Missing token metadata in some =message_update= events should not undercount silently.
- Setup-level and goal-level budgets may both apply to the same run; smaller remaining allowance wins.
- Retried runs need clear rules for whether budget resets per run or accumulates within a schedule window.
- Optional Telegram integration should not block BUG item creation or pause behavior.

* Acceptance Criteria
- Budget ceilings are enforced, not merely tracked.
- Over-budget runs fail with explicit reason codes and trigger escalation.
- Tests prove accounting correctness from raw RPC event streams.
