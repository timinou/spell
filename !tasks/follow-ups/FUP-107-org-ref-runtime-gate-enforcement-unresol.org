** Two org-ref parity gaps (deeper than the cheap fixes already landed)

*** R1 \u2014 org gates injected-as-text but not runtime-enforced (P2, conf 0.6, BOTH reviewers)
For `org://` refs, `#injectVerificationContext` injects gate PROPERTIES as imperative MUST text, but runtime enforcement (`#buildRuntimeVerificationOptions` \u2192 `verifyTaskGates` fails the task on violation) is roster-only \u2014 it's reached via `rosterRefOf(originalTask)` which returns undefined for org refs (index.ts ~1667,1720). So org gates are advisory text while roster gates are actually enforced. Asymmetry: an org-linked subagent can skip a gate it was told it MUST satisfy.
Fix sketch: have `#buildRuntimeVerificationOptions` also accept an org-resolved gate set (resolve org item \u2192 RuntimeVerificationOptions), or unify both branches through a single resolved-gate struct. Needs the async org resolution result threaded to the runtime-verification call site (currently sync).

*** R2 \u2014 unresolvable/empty org:// ref \u2192 silent empty-assignment dispatch (P2, conf 0.6)
`#validateTaskBatch` only flags missing-assignment when `resolveRef(ref).kind === \"none\"`. An `org://` ref passes validation, but if org is disabled or the id is a typo, `resolveOrgRefItem` returns undefined and the task dispatches with an empty/context-only prompt. Also: a resolvable org item with an EMPTY body yields `## Task: <title>` only (no actionable instructions) \u2014 no minimum-content guard equivalent to roster's buildSniperAssignment.
Fix sketch: validation must become org-aware (async pre-resolve, or a post-resolution check that fails the batch / surfaces a model-visible warning when an org ref resolves to nothing or to an empty assignment).

Both are architectural (sync validation vs async resolution; parallel runtime-enforcement path). Deferred from the wave-1 cutover, which landed the two cheap parity wins (gate-property set extended to gateLlm/verificationArtifact/orgItemClosingId; gateCommit falsy-token handling).
