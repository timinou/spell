* Context

Using =pi-code-engine= =LanguageProfile= makes =pi-code-graph= language-parity feasible for declarations/imports/exports/generic references, but it does not fully replace the richer language-specific semantics that the current bespoke TypeScript extractor provides (=Calls=, =Inherits=, =TypeParameterOf=, and other higher-signal edges). The same applies to Elixir-specific render/call behavior and any future Markdown/Typst/Org semantic relations.

This follow-up tracks the second phase after baseline parity lands: recover or improve higher-signal edge kinds through optional enrichers layered on top of the declarative extractor.

* User Workflows

2. =code context= separates inheritance, render, and type-parameter relations from generic references.
3. Search reranking can boost true call-graph neighbors instead of generic identifier co-occurrence.
