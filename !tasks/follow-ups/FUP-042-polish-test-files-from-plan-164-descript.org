** Finding #5: Replace String.fromCharCode(10) with a single-line string literal

In =packages/coding-agent/test/loop/spec-ingestion.test.ts=, the new
test constructs its file content via =String.fromCharCode(10)= and an
array join. This is unnecessarily indirect. The neighbour test
=imports valid org specs and preserves id links= (at line 28 of the
same file) already writes its content as a single-line double-quoted
string literal using standard TypeScript backslash-n escape
sequences. Match that neighbour's style.

*** Reference template

Before editing, open line 28 of the same file and read the existing
=imports valid org specs= test. Line 28 is a single-line double-quoted
string literal whose content is the same shape as the replacement
required here: it starts with =#+TITLE:=, contains multiple logical
lines separated by the standard TypeScript newline escape (the
two-character sequence of backslash followed by lowercase n), and ends
with a trailing newline escape. Copy that form exactly.

*** Source to REMOVE (lines 49-56 before this edit, numbered relative to the file AFTER Finding #4 inserts a blank line above)

#+begin_src typescript
const NL = String.fromCharCode(10);
const content = [
    "#+TITLE: Spec",
    "#+CUSTOM_ID: SPEC-001-demo",
    "",
    "See [[id:SPEC-001-demo][the demo]]",
    "",
].join(NL);
#+end_src

*** Replacement to INSERT

A single statement that assigns to =const content= a double-quoted
string literal containing these four logical lines of content in this
order, each separated by one TypeScript newline escape (backslash + n),
and with a trailing newline escape after the fourth line:

1. =#+TITLE: Spec=
2. =#+CUSTOM_ID: SPEC-001-demo=
3. (empty line — produced by TWO consecutive newline escapes between
    the =SPEC-001-demo= line and the =See= line)
4. =See [[id:SPEC-001-demo][the demo]]=
5. (trailing newline escape after the fourth line)

The structural shape is identical to the string on line 28 of the
same file — copy that line's form, changing only the content bytes
between the quotes.

Delete the =NL= local const — after the replacement it is no longer
referenced.

*** Byte-equivalence proof

The array form joined on =String.fromCharCode(10)= produces the byte
sequence =#+TITLE: Spec<LF>#+CUSTOM_ID: SPEC-001-demo<LF><LF>See [[id:SPEC-001-demo][the demo]]<LF>=,
where =<LF>= denotes one LINE FEED character (U+000A). The replacement
double-quoted literal, when the TypeScript compiler resolves each
backslash-n escape sequence into a LINE FEED character, produces the
identical byte sequence. Bytes written to disk by the
=Bun.write(file, content)= call are byte-identical — only the source
form of how the =content= value is constructed changes.

*** Note on PLAN-164's prior justification

BUG-189 chose the array-join approach "to avoid fragile multi-line
string literals". A single-line double-quoted string that uses
backslash-n escape sequences is NOT a multi-line string literal —
that term refers to backtick template literals that span multiple
source lines. The original concern is satisfied equally by either
form; the =String.fromCharCode(10)= was unnecessary obfuscation.
