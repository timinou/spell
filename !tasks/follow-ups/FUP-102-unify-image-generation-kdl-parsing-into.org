## Context
`tools/image-generation/schema-loader.ts::loadImageSchemas` reads the three spell.kdl tiers (user/project/local) DIRECTLY to extract `image-generation { schema … / disable … }` override blocks, instead of flowing through `config/spell-kdl.ts::parseSpellKdl` like every other top-level block (agents, modes, providers).

Chosen deliberately during bring-up to keep the feature self-contained (zero plumbing through sdk.ts). Consequence: `image-generation` is the lone config block invisible to the central parser (hits `parseSpellKdl`'s `default: break`), and spell.kdl is parsed a second time per session.

## Task (do once the codebase's KDL handling has settled)
Unify into the house pattern:
1. `config/spell-kdl.ts`: add `case "image-generation"` in `parseSpellKdl`'s dispatch switch; capture the raw override nodes.
2. Store them as a typed field on `SpellProjectConfig` (e.g. `imageGeneration?: Node[]`).
3. Merge across tiers in `mergeSpellConfigs` (concat, preserve precedence order).
4. Thread the merged nodes to the tool factory and pass via the EXISTING `LoadImageSchemasOptions.overrideTiers` option — `loadImageSchemas` needs no signature change; it already accepts pre-parsed tiers for exactly this hand-off (used by tests today).
5. Drop the direct tier-file reads (`readTierBlocks` + the `getUserKdlPath/getProjectKdlPath/getLocalKdlPath` fallback) from schema-loader.ts.

## Acceptance
- `image-generation` discoverable in `parseSpellKdl` alongside agents/modes/providers.
