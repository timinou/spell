## Findings

### 1. `extractPlanWaves` has the same bug — it was not fixed

**What:** `exit-plan-mode.ts` line 65 has a third `[[id:...]]` regex with the same root cause: `\]\]` immediately after the target with no allowance for description form.

```typescript
const entryRe = /^\s*-\s+\[\[id:([^\]]+)\]\]\s+(.+)$/;
```

**Where:** `packages/coding-agent/src/tools/exit-plan-mode.ts`, line 65, inside `extractPlanWaves()`

**Why:** A PLAN whose wave entries use description-form links (the exact form this fix was supposed to make work) would pass the child-reference validation (`extractIdLinks` was fixed), but `extractPlanWaves` would silently discard every wave entry. The resulting `waves` array would be populated but all entries empty — todo auto-init would produce hollow phases. The user symptom: plan is accepted, execution starts, but no wave tasks are materialized.

The required fix is the same pattern already applied to the other two: `\[\[id:([^\]]+)\](?:\[[^\]]*\])?\]\s+(.+)$`.

**Effort:** trivial
