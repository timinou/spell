* Findings
- **What**: Cross-target worker naming uses the host platform instead of the target platform.
  - **Where**: `packages/natives/scripts/build-native.ts`, around `const exeSuffix = process.platform === "win32" ? ".exe" : "";`
  - **Why**: Cross-compiling a Windows worker from Linux/macOS will install it without `.exe`, so post-build lookup and embedding can miss the worker even though the build succeeded.
  - **Effort**: `trivial`

- **What**: Worker runtime discovery does not cover every path the native addon loader can use.
  - **Where**: `crates/pi-natives/src/embedding_worker.rs` (`worker_candidates()` / `versioned_native_dir()`), compared with `packages/natives/src/native.ts` (`compiledCandidates` includes `userDataDir`)
  - **Why**: If the addon is loaded from the `userDataDir` fallback, the worker is not searched there, so semantic features can fail even though the addon itself loads successfully.
  - **Effort**: `small`

- **What**: Conversation cache eviction is FIFO, not activity-aware.
  - **Where**: `packages/ai/src/providers/cursor.ts`, `setConversationCacheEntry(...)` near the top of the file
  - **Why**: Updating an existing `Map` entry does not refresh insertion order, so an older but still-active conversation can be evicted first after the 21st conversation ID appears, causing unexpected loss of cached state/blob data mid-session.
  - **Effort**: `small`

- **What**: Semantic index construction trusts worker output shape without validating it.
  - **Where**: `crates/pi-natives/src/code_graph.rs`, `build_semantic_index(...)` and semantic search query-vector handling
  - **Why**: If the worker returns fewer vectors than chunks, or vectors with inconsistent dimensions, the code silently truncates via `zip` or accepts bad dimensions. Because `PI_EMBEDDING_WORKER` is overrideable, this is externally reachable and can yield a corrupt vector cache while reporting success.
  - **Effort**: `small`

- **What**: Pending-delivery capping silently drops completion notifications.
  - **Where**: `packages/coding-agent/src/async/job-manager.ts`, `#enqueueDelivery()` and the failed-delivery requeue path in `#runDeliveryLoop()`
  - **Why**: When the queue exceeds 200, oldest deliveries are discarded with no log or surfaced state change. The job record remains, but the caller can miss the automatic completion delivery and perceive the job result as lost.
  - **Effort**: `small`

- **What**: Finished-job pruning uses `startTime` rather than completion time.
  - **Where**: `packages/coding-agent/src/async/job-manager.ts`, `#pruneCompletedJobs()`
  - **Why**: A long-running job that just completed can be pruned before a short job that completed much earlier, which makes “recent jobs” less truthful and can hide the freshest result under pressure.
  - **Effort**: `trivial`

- **What**: Automated coverage does not fully exercise the worker IPC contract from the `pi-natives` side.
  - **Where**: `crates/pi-natives/src/code_graph.rs` tests and `crates/pi-natives/src/embedding_worker.rs`
  - **Why**: The missing-worker error path is covered, but successful semantic indexing, malformed worker responses, and worker restart-after-failure behavior are only manually verified. A protocol drift between worker and host could pass `cargo test` and break runtime behavior.
  - **Effort**: `medium`
