* Findings
1. **What:** Quick Fix captures screenshots, but the backend discards them.
   **Where:** `.spell/extensions/phoenix-inspector/inspector.qml` in `dispatchQuickFix()` and `.spell/extensions/phoenix-inspector/index.ts` in `runQuickFixTask()`.
   **Why:** The “Include screenshot” affordance becomes misleading, and the task agent loses visual context for UI fixes.
   **Effort:** small

2. **What:** The new quick-fix backend depends on a non-contract `pi.pi.runSubprocess` API.
   **Where:** `.spell/extensions/phoenix-inspector/index.ts` in `runQuickFixTask()` / task-tier handling.
   **Why:** The focused tests pass because the harness stubs this method, but a real launch can fail if the host does not inject that exact runtime hook. That makes Quick Fix brittle outside the test harness.
   **Effort:** medium

3. **What:** Quick-fix error handling is not regression-tested.
   **Where:** `.spell/extensions/phoenix-inspector/index.test.ts`, the new `dispatches canonical quick-fix tasks...` case only covers success.
   **Why:** A failed task result could regress to stale or incorrect UI messaging without any test catching it.
   **Effort:** small
