* Findings
Audit findings, highest effort-to-impact first:

1. **What**: Cache fingerprinting is too broad and likely self-invalidates the graph cache
   - **Where**: `crates/pi-code-graph/src/cache.rs`, `CacheStore::fingerprint_root()`
   - **Why**: It fingerprints every file under the root, including non-source files and likely `.spell/graph` itself. That means the cache can become stale because of its own output or unrelated docs/artifacts changes, forcing unnecessary rebuilds and making `status`/lazy indexing less trustworthy.
   - **Effort**: `small`

2. **What**: Graph commands bypass read-only mode even though `index`/auto-index writes `.spell/graph`
   - **Where**: `packages/coding-agent/src/tools/code.ts`, graph command routing in `execute()` / `#executeGraphCommand()`
   - **Why**: `context`, `impact`, `deps`, etc. can trigger an implicit rebuild and write cache files, but only `edit` is guarded as a write. In a read-only session this violates the tool’s contract and mutates the workspace unexpectedly.
   - **Effort**: `small`

3. **What**: Type-only imports are parsed, then silently discarded by the graph pipeline
   - **Where**: `crates/pi-code-graph/src/language.rs` (`ExtractedImport.is_type_only`) and `crates/pi-code-graph/src/indexer.rs` import edge construction
   - **Why**: The extractor preserves `is_type_only`, but the builder never uses it. That means callers cannot tell whether a dependency is runtime or type-only, and dead-code / impact / deps results can over-report usage while hiding that distinction.
   - **Effort**: `small`

4. **What**: Symbol-only commands can silently fall back to file hits
   - **Where**: `crates/pi-code-graph/src/query.rs`, `resolve_symbol()`
   - **Why**: If exact symbol lookup fails, `resolve_symbol()` falls back to graph search over both symbols and files. `context`/`flow` therefore can return plausible output for a file when the caller asked for a symbol, which is a contract violation and hard to detect from the output.
   - **Effort**: `small`

5. **What**: TypeScript inheritance extraction produces false `inherits` edges
   - **Where**: `crates/pi-code-graph/src/language/typescript.rs`, `collect_heritage_references()`
   - **Why**: It walks identifiers inside `extends`/`implements` clauses too broadly. In practice this already surfaced as `CodeTool` appearing to “inherit” `codeSchema`, which is not a real inheritance relationship. That pollutes `context`/`impact` results with misleading edges.
   - **Effort**: `small`

6. **What**: Bare-name symbol indexing collides when multiple symbols in one file share the same name
   - **Where**: `crates/pi-code-graph/src/indexer.rs`, `symbol_nodes` map population and `resolve_reference_target()`
   - **Why**: The map is keyed by `(file, symbol.name)`, so duplicate method/function names within one file overwrite each other. References then resolve to whichever symbol was inserted last, making context, flow, impact, and dead-code results incorrect in common class-heavy files.
   - **Effort**: `medium`

7. **What**: `dead_code` has obvious false positives for constructors and some methods
   - **Where**: `crates/pi-code-graph/src/query.rs`, `graph_dead_code()`; root cause also in `crates/pi-code-graph/src/language/typescript.rs` reference extraction for `new_expression`
   - **Why**: `new Foo()` links to `Foo`, not `Foo.constructor`, so constructor symbols tend to look unused. The smoke output already showed entries like `ProxyMessageEventStream.constructor` as dead. A noisy dead-code report will quickly lose user trust.
   - **Effort**: `medium`

8. **What**: Elixir module resolution does not cover common Mix/Phoenix layouts
   - **Where**: `crates/pi-code-graph/src/language/elixir.rs`, `ElixirImportResolver::resolve()` / `module_name_to_path()`
   - **Why**: It maps `MyApp.Tools.Helper` directly to `my_app/tools/helper.ex`, but real projects commonly place modules under `lib/`, umbrella app roots, or other Mix-managed layouts. On typical Elixir repos, aliases/imports will fail to resolve and graph quality will drop sharply.
   - **Effort**: `medium`
