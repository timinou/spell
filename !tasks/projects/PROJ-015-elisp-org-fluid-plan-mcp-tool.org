Can you leanly improve/change the decomposition steps of plans and ultraplans to fully support these? As in: you remove Daedalus (just don't activate it anymore), but instead you create the org files, and the org subtasks can depend on each other and other file CUSTOM_IDs, and the execution manifest is built from there, and there is a way to spin several agents that will then also spin agents so that there are several threads, that are coordinated through the main agent? And then once the first DAG has been generated, Daedalus is generated with that DAG summary as the startying point, instead of the current way which has Daedalus generate the decomposition analysis before the DAG which makes no sense? * Edge Cases
- Items with both top-level CUSTOM_ID and sub-outline =::sub-slug= :: both included; sub-outline inherits parent's file location
- DEPENDS referencing items outside the PLAN's linked children :: warning emitted, dependency edge ignored (item treated as root within its component)
- Org items in DONE/BLOCKED state :: included in graph but flagged in output (coordinator decides whether to skip)
- Very large plans (50+ items) :: no algorithmic concern — union-find is O(n alpha(n)), Kahn's is O(V+E)
- Plan item with no =[[id:...]]= links :: error returned (empty plan)
