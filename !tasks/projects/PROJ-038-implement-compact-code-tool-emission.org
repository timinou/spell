* Context
This item consumes the normalized contract from [[id:PROJ-037-define-compact-code-tool-contract]] and applies it at the actual tool boundary. Today, `packages/coding-agent/src/tools/code.ts` returns raw pretty-printed JSON for file-local commands and only `{ command }` in `details`. Native code output is produced in `crates/pi-natives/src/code_buffer.rs`; graph commands already return compact text. The goal is to make new code-tool executions emit compact LLM-facing text plus rich structured details, with no legacy compatibility layer.

Existing patterns to follow:
- `packages/coding-agent/src/tools/search-tool-bm25.ts`: compact `content`, rich `details`, renderer reads details.
- `packages/coding-agent/src/lsp/index.ts` and `packages/coding-agent/src/lsp/render.ts`: request metadata stored in details, renderer uses structured details.
- Repo rule: prompts live in static `.md` files, so update `packages/coding-agent/src/prompts/tools/code.md` rather than embedding prompt strings in TypeScript.

* Target files
- Modify: `packages/coding-agent/src/tools/code.ts`
- Modify: `crates/pi-natives/src/code_buffer.rs`
- Modify: `packages/coding-agent/src/prompts/tools/code.md`
- Modify: `packages/coding-agent/test/tools/code.test.ts`
- Use contract from: `packages/coding-agent/src/tools/code-result.ts`

* Required design decisions to implement
1. `code.ts` must stop using `JSON.stringify(result.output, null, 2)` as the default file-local tool content.
2. `code.ts` must normalize every command result through the canonical contract and format the model-visible text from that contract.
3. `result.details` must include the command, schema version, and normalized/raw data needed by downstream renderers. Preserve all information.
4. Native Rust output may be reshaped where it meaningfully reduces noise or improves semantic naming, but TypeScript remains the owner of final LLM-facing phrasing.
5. `code` graph commands may keep their existing text output, but their `details` shape should be brought into the same contract family where practical.
6. The tool description in `packages/coding-agent/src/prompts/tools/code.md` must describe the new output behavior and stop implying that raw JSON blobs are the primary agent experience.
