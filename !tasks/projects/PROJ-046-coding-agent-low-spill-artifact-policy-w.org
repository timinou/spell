* Scope
In scope:
- Replace the current effective spill defaults for non-precision tool outputs with an aggressive artifact-first policy: spill when output exceeds 2.5 KB or 50 lines; keep only 1 KB / 50 lines inline on success.
- Preserve a slightly larger failure budget for non-zero exits and error paths: keep 5 KB / 120 lines inline after spill.
- Apply the low-spill policy to shell/process-style and broad text-returning tools, while exempting precision inspection/edit/query tools whose main value is exact inline content review.
- Unify the shared spill policy used by `wrapToolWithMetaNotice()` and streaming executors so `bash`, `python`, `ssh`, and notebook / kernel-style streaming paths stop hard-coding the legacy 50 KB behavior.
- Keep artifact-based follow-up workflows first-class: truncated results must continue to emit actionable `artifact://` references that agents can feed back into `bash`, `read`, or `grep`.

Out of scope:
- Changing artifact URI routing or internal URL expansion semantics.
- Removing existing tool-specific truncation semantics for precision tools such as `read`, `grep`, and `org`.
- Adding sticky session-level escape hatches for lenient shell output; that is covered by the bash-specific child item.

Rationale: `.local/token-usage/token-usage-review.data.js` shows that bash alone accounts for ~73.9M shared tokens over the sampled sessions, and the target leak classes (`tests`, `git inspection/staging`, `remote logs/status`) account for ~40.8M of those tokens plus ~496k estimated input-leakage tokens. The present 50 KB default is too high to catch most of the noisy-but-not-huge outputs that poison the next turn.

* Edge Cases
- Output that exceeds the line threshold but not the byte threshold must still spill.
- Output that barely crosses a threshold must not lose artifact references or report the wrong shown line range.
- Existing artifact-backed tools must not get double-truncated into incoherent notices.
- When artifact allocation fails, the tool must degrade truthfully instead of pretending the full output is still cheaply inline.
- Exempt precision tools must preserve existing paging / structured rendering contracts.
- Streaming tools must not keep a tiny success buffer in memory and then falsely claim a larger failure tail they can no longer reconstruct.

* Acceptance Criteria
- Non-precision tool outputs larger than 2.5 KB or 50 lines spill by default and keep only the agreed tiny inline residue on success.
- Non-zero-exit / error outputs keep the agreed larger inline residue without reverting the whole system to the old 50 KB default.
- Precision inspection/edit/query tools keep their current inline-first UX.
- Shared spill behavior is implemented once and reused by wrapper-level and streaming-output paths.
- Tests prove truthful truncation metadata, artifact references, exemption behavior, and byte-or-line trigger behavior.
