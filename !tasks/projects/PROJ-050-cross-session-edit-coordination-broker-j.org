* Initial Message

show me how the pi code engine can be used to keep track of which session edited what file across code edit instances. some sort of auto-find and socket communication for editing processes. I don't want any more errors happening because another agent edited something. maybe it's time for loro crdt? think about this also within the scope of making undo/redo smarter and only undoing/redoing the actions of the agents/sessions but also knowing what the other agents/sessions modified.

* Scope
Eliminate the class of "another agent edited something" errors by (1) making every mutating edit a short read-lock-write-release transaction against disk, (2) broadcasting commits via a dedicated Unix-socket broker so peers can subscribe and invalidate caches, (3) recording CodePath-granular attribution in a persistent journal, and (4) making per-session undo/redo best-effort aware of which revisions belong to whom.

Out of scope for this PROJ: character-level CRDT merge (Loro), cross-host coordination, semantic conflict resolution (e.g. deleted-fn-vs-new-call), Windows support. See specs/edit-coordination/design.md §"Non-goals".

* Operator directive (load-bearing)
"Equate an edit with a file change. Lock time per edit = literally lock-write-release. Asynchronous across agents and within sessions. Get updated if the file got updated. Reload and save MUST be standardized; undo/redo are best-effort; remove the class of stale-management problems."

This is the axiom. Every FEAT decision flows from it.

* Acceptance criteria
- Two spell processes editing the same repo on the same file serialize correctly; no =ExternalModification= error surfaces under normal operation.
- A pre-edit probe to the broker returns peer intents; overlapping intents produce a structured =PeerConflict= error carrying conflicting =sessionId=, =codePath=, =peerCommitTs=.
- Journal at =~/.spell/edit-journal/<repo-hash>/<file-hash>.jsonl= contains one entry per committed edit with CodePath-level attribution.
- `undo_scoped(sessionId)` walks history skipping peer revisions and reports skipped summaries in the returned payload.
- TUI status-line shows peer count when >0; tool output footer shows recent peer edits on the target file.
- Broker auto-spawns on first client; auto-exits 30s after last disconnect; reaps sessions whose pids die.
- All existing `code edit` tests continue to pass; new coord tests land green.
