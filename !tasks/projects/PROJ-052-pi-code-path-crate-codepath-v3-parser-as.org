* Scope

New Rust crate =crates/pi-code-path= implementing the CodePath v3 shared query algebra as specified in =specs/code-graph/code-path.md= and =specs/code-graph/code-path-dialects/README.md=.

** In scope
- Winnow parser for the full CodePath grammar (locator, query, combinators, axes, predicates, qualifiers, set ops, edge axis)
- CodePath AST types: =CodePath=, =Query=, =Step=, =Combinator=, =Axis=, =Predicate=, =Qualifier=, =EdgeKind=
- =NameLexer= trait definition (parse/render/matches)
- =LanguageDialect= struct (name_lexer, anchors, qualifiers, edge_kinds)
- =QualifierSpec= struct with =QualifierResolver= trait
- =AnchorPattern= struct
- Resolver engine that walks tree-sitter AST using CodePath queries
- Edge axis resolver that delegates to =pi-code-graph= for cross-file traversal
- Set operations on =NodeSet= (union, intersect, difference)
- Subquery predicates (has-descendant, has-ancestor)
- Round-trip: parse -> render -> parse identity
- Error envelope with span-aware diagnostics
- Sigil scheme: =§= (node-kind), =¶= (anchor), =→= (edge), =:= (field), =#= (qualifier)

** Out of scope
- Per-language NameLexer implementations (separate PROJ)
- NAPI bridge (separate PROJ)
- Code tool surface changes (separate PROJ)
- LegacyNameLexer for backward compat (handled in NAPI bridge)

*** pi-code-graph query API (pattern for edge resolution)
- File: =crates/pi-code-graph/src/query.rs=

- Parse =CodePath := Locator "::" Query Qualifier?=

** Implement tree-sitter resolver
:PROPERTIES:
:CUSTOM_ID: PROJ-052-pi-code-path-crate-codepath-v3-parser-as::proj-resolver
:DEPENDS: PROJ-052-pi-code-path-crate-codepath-v3-parser-as::proj-winnow-parser PROJ-052-pi-code-path-crate-codepath-v3-parser-as::proj-name-lexer-trait
:END:
- File: =crates/pi-code-path/src/resolve.rs=
- =fn resolve(path: &CodePath, ctx: &ResolveContext) -> Result<NodeSet, ResolveError>=
- =ResolveContext= holds: =CodeBuffer=, =LanguageProfile=, =LanguageDialect=, optional =&CodeGraph=
- Resolver walks the =Query= AST:
  - For each =Step=: dispatch on axis type
    - Semantic: use dialect =NameLexer::matches()= against children
    - Structural (§): use =matches_rule_expr()= with =RuleExpr::Types=
    - Field (:): use =Node::child_by_field_name()=
    - Anchor (¶): use dialect's =AnchorPattern::matcher=
  - For each =Combinator=: apply tree walk
    - =/=: filter visible children
    - =//=: recursive descent
    - =^=: parent
    - =^^=: walk ancestors until predicate matches
    - =<<=, =>>=: previous/next sibling
  - For each =Predicate=: filter current node set
  - For =Qualifier=: narrow to sub-range via =QualifierResolver=
- Result: =NodeSet= with =ResolvedNode= (path, byte range, node reference)

** Edge Cases

- Empty locator (=:: Foo=): resolve against current buffer context
- Glob locator (=src/**/*.ts :: Foo=): resolve across multiple files
- Ambiguous NamePayload: return =AmbiguousName= diagnostic with candidate list
- Cyclic edge traversal (=ref→= -> =def→= -> =ref→=): cycle detection with visited set
- Zero-match NodeSet: distinguish "valid query, no results" from "invalid query"
- Unicode in NamePayload: delegated to dialect NameLexer
- Escaped special chars in locator path: handle spaces, parens in file names
- Nested predicates: =[.§call[name=foo]]=  — predicate within predicate
- Set ops with cross-file NodeSets: maintain file context per node

** ITEM Implement dialect-switch resolver state machine
:PROPERTIES:
:CUSTOM_ID: PROJ-052-pi-code-path-crate-codepath-v3-parser-as::proj-dialect-switch-resolver
:DEPENDS: PROJ-052-pi-code-path-crate-codepath-v3-parser-as::proj-resolver PROJ-052-pi-code-path-crate-codepath-v3-parser-as::proj-noderef-content-types
:END:
- File: =crates/pi-code-path/src/resolve/dispatch.rs=
- Per spec =specs/code-graph/code-path-extensions.md= §3
- =ResolveScope= tracks current-dialect across step boundaries
- Initial scope = =FsDialect= rooted at cwd or =root= projection option
- After =§file= match → switch to file's code dialect (or stay FS if next axis is FS-class)
- First =§line=/=§chunk=/=§para=/=§span= axis → switch to text dialect for that file
- Text → code transition mid-file is rejected with =Diagnostic::TextToCodeMidFile=; must =^= to file root and re-enter via code axis
- =→= edge axis: cross-file; new file's dialect takes over
- URI Locator: scheme dialect first; then delegate per scheme table (PROJ-060)
- Cost discipline enforced: each step picks cheapest interpreter for its dialect
