* Context
The current `code` tool sends raw `JSON.stringify(result.output, null, 2)` text to the model for file-local commands in `packages/coding-agent/src/tools/code.ts`. Native file-local results from `crates/pi-natives/src/code_buffer.rs` include low-level payloads such as `changedRanges`, `inputEdit.startByte`, `inputEdit.oldEndByte`, and diff hunk arrays with `oldStart`/`oldCount`/`newStart`/`newCount`. Graph commands already emit compact text, but file-local commands do not. The redesign goal is full cutover for new sessions only: preserve all information, but move verbose/raw structure out of model-visible `content` and into structured `details`.

Stakeholders:
- LLM consumer: needs compact, task-oriented summaries, not byte-offset JSON blobs.
- Transcript/TUI maintainer: needs one stable contract that can render live streaming and rebuilt transcripts consistently.
- Native/TypeScript boundary maintainer: needs an explicit, typed schema instead of ad-hoc `unknown` JSON.

Existing patterns to follow:
- `packages/coding-agent/src/tools/search-tool-bm25.ts` returns compact `content` plus rich `details`.
- `packages/coding-agent/src/web/search/code-search.ts` formats LLM-facing text separately from raw provider response in `details`.
- `packages/coding-agent/src/tools/gemini-image.ts` and `packages/coding-agent/src/tools/python.ts` keep non-LLM-heavy data in `details` to avoid bloating context.
- `packages/coding-agent/src/session/messages.ts` sends `toolResult.content` to the model and excludes `details`, so the compact textual contract must live in `content`.

* Required design decisions to encode
1. Full cutover only for new sessions/transcripts. No indefinite dual-schema support.
2. Introduce a canonical TypeScript discriminated union for code-tool results, for example `CodeToolDetails`, keyed by command family.
3. Introduce a single formatter, for example `formatCodeResultForLlm(details: CodeToolDetails): string`, that emits compact model-visible text.
4. Preserve raw/native data in `details.native` or command-specific detail fields; do not expose byte offsets or entire raw JSON blobs in `content` unless the command is explicitly a raw/read-style command.
5. Edit-family commands (`edit`, `undo`, `redo`, `diff`, `save`) must summarize semantic outcomes first: file, version, edit count, changed regions/hunks, success/error, and any user-actionable warnings.
6. Read-style commands (`outline`, `read`, `navigate`, `buffers`, `languages`) may still expose structured content, but it must be compact, stable, and free of pretty-printed JSON indentation noise.
7. Graph commands keep their current compact text model unless the new shared contract needs metadata normalization in `details`.
