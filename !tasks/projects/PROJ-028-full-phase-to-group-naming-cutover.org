* Context

PLAN-173 introduced DAG-native groups as cosmetic containers (no execution semantics), but the codebase still uses =TodoPhase= type names, =phases= field names, and "Phase" user-visible strings. This creates a mismatch between the documented architecture (groups are cosmetic, DAG is the ordering authority) and the code surface (which implies phase-sequential semantics to callers and maintainers).

** Design Decisions

1. Use LSP rename where possible for type/method names. Use ast_edit or manual edit for field names in object literals and string output.
2. Rename targets (exhaustive):
   - =TodoPhase= → =TodoGroup= (interface, ~25 files)
   - =TodoWriteToolDetails.phases= → =TodoWriteToolDetails.groups= (remove the dead =groups?= field that was added as a compat bridge)
   - =getTodoPhases= → =getTodoGroups=, =setTodoPhases= → =setTodoGroups= (session interface + all implementations)
   - =getNextTodoIds(phases)= param → =getNextTodoIds(groups)=
   - =flattenTasks(phases)= param → =flattenTasks(groups)=
   - =cloneTodoPhases= → =cloneTodoGroups=
   - =getLatestTodoPhasesFromEntries= → =getLatestTodoGroupsFromEntries=
   - =completedPhaseIds= → =completedGroupIds= (local vars + =ApplyOpsResult= field + =FormatSummaryOptions= field)
   - =isPhaseComplete= → =isGroupComplete=
   - =buildPhaseFromInput= → =buildGroupFromInput=
   - =TodoFile.phases= → =TodoFile.groups=, =TodoFile.nextPhaseId= → =TodoFile.nextGroupId=
   - =fileFromPhases= → =fileFromGroups=
   - =applyOrgLifecycleHooks= params: =previousPhases= → =previousGroups=, =nextPhases= → =nextGroups=
   - =formatSummary= output: "Phase N/M" → "Group N/M", "Phase complete" → "Group complete"
   - Phase IDs in runtime: =phase-1=, =phase-2= → =group-1=, =group-2=
3. Schema backward compat: keep =phases= as an accepted property name in the =replace= op schema. Internally map to =groups=. The =add_phase= op stays as a schema alias for =add_group= (both accepted, both do the same thing). This preserves compat with existing LLM callers that have learned the =phases= vocabulary.
4. The =todo:change= event payload field changes from =phases= to =groups=. Dashboard bridge must update accordingly.
5. The =writeJournal= call in the execute method must update to pass =groups= instead of =phases= (or the journal function signature must accept the renamed type).
6. Session entry deserialization (=getLatestTodoGroupsFromEntries=) must handle BOTH old =phases= field name (from historical session entries) and new =groups= field name.
