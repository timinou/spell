** Implement transform pipeline
:PROPERTIES:
:CUSTOM_ID: PROJ-011-native-ts-scraper-framework::implement-transforms
:DEPENDS: PROJ-011-native-ts-scraper-framework::define-config-types
:END:

Files: domain/growth/src/scraper/transforms.ts

Transform types: regex (capture group), replace (find/replace_with), exists (boolean), chain (array of transforms). Each transform is a pure function: (input: string) => string | number | boolean. Chain applies transforms left-to-right, threading output as input. Regex with no match returns null for optional fields. All transforms stateless and side-effect-free.

** Implement paginator
:PROPERTIES:
:CUSTOM_ID: PROJ-011-native-ts-scraper-framework::implement-paginator
:DEPENDS: PROJ-011-native-ts-scraper-framework::define-config-types
:END:

Files: domain/growth/src/scraper/paginator.ts

Three strategies: infinite_scroll (scroll container, wait, check for new items, repeat until max_items or no new items), cursor (follow next_cursor URL parameter), next_button (click selector, wait for load). Each returns AsyncIterator of page states. Infinite scroll detects stall when item count unchanged after scroll. All strategies respect max_items cap and per-config timeout.

** Implement rate limiter
:PROPERTIES:
:CUSTOM_ID: PROJ-011-native-ts-scraper-framework::implement-rate-limiter
:END:

Files: domain/growth/src/scraper/rate-limiter.ts

Token bucket algorithm. Configurable: requests_per_minute, backoff_multiplier. Per-domain isolation (different limits for facebook.com vs google.com). Async: await limiter.acquire(domain) before each request. On HTTP 429 or error indicator match, exponential backoff up to configurable max_backoff_ms. Bucket refills at rate = requests_per_minute / 60 tokens per second.

** Implement SQLite persistence with schema manifest
:PROPERTIES:
:CUSTOM_ID: PROJ-011-native-ts-scraper-framework::implement-persistence
:DEPENDS: PROJ-011-native-ts-scraper-framework::define-config-types
:END:

Files: domain/growth/src/scraper/persistence.ts

Read SchemaManifest from config. CREATE TABLE IF NOT EXISTS for each entity. INSERT on each scrape (snapshot-per-scrape, no upsert — full history). CREATE VIEW latest_<entity> AS SELECT with ROW_NUMBER() OVER (PARTITION BY platform_id ORDER BY scraped_at DESC) WHERE rn = 1. FK relationships between entities (pages.id -> ads.page_id). Enable WAL mode and foreign keys on open. Use bun:sqlite. Dedup by platform_id + scraped_at to prevent duplicate runs.

* Edge Cases

- YAML config with invalid selectors: validation error at load time, not at runtime
- Scraper target page structure changes: extraction returns null for optional fields, throws ScraperExtractionError for required
- Rate limit hit (HTTP 429 or FB-specific dialog selector match): exponential backoff per error_indicators config, max_backoff_ms cap
- Pagination infinite loop: max_items cap + per-page timeout, stall detection on infinite_scroll
- SQLite concurrent writes: WAL mode enabled on open, single writer per scraper run
- Empty scrape result: no rows inserted, no error, done event emitted with count: 0
- Network timeout mid-scrape: retry per errorHandling.retries, screenshot saved to disk if screenshot_on_error: true
