* Intention & Purpose
Define the kernel's mutation API. Today =pi-code-path= is read-only:
=opts.command/opts.actions/opts.manage= in =CodePathOptions= are unused. This item
delivers the trait surface + spec doc + AST extension for actions; sibling items
implement actions per resolver.

Decision per planning Q3: kernel exposes an =Action= trait dispatched per-resolver.
Each resolver chooses how to apply (FS write, text-line edit, structural code edit).
This allows incremental migration: =executeCodeBuffer= can stay during transition.

* Context & Narrative
Per audit (agent://35-Resolvers): =Resolver=, =CodeResolver=, =EdgeResolver=,
=SchemeHandler= all expose only =fn resolve()=. No mutation method. =CodePathOptions=
fields exist but are dead. Phase A of PLAN-296 patched around this by routing
=create.ts= to direct =fs.writeFile= and =edit.ts= structural to =executeCodeBuffer=.

This item ships the trait + Action types + dispatch wiring **without** implementing any
specific action (siblings do). Pure type scaffolding so downstream items can land in
parallel.

* Edge Cases
- Action with mismatched params (e.g. Replace without =pos=) — Diagnostic
  =INVALID_ACTION_PARAMS= at apply time, not compile time (params are typed Optional)
- Multiple actions on same target — applied in order; earlier failures abort
- Cancellation during apply — Diagnostic =CANCELLED=, no partial state guarantees beyond
  what the resolver provides
