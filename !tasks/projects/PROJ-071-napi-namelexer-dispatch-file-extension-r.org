* Intention & Purpose

Replace the generic =DotLexer= used at the NAPI boundary with file-extension-driven dispatch
to the language-specific =NameLexer= implementations registered in =LanguageDialect=. Without
this, symbol queries like =foo.ts::Foo.bar= or =mod/lib.rs::path::Type= are parsed by a
lexer that only understands =[A-Za-z0-9_.]= — losing dotted structure for TS, =::= for Rust,
operators for Haskell, etc. The NAPI surface currently honours the spec only for FS and
text dialects; symbol dialects are silently weakened.

* Context & Narrative

In =crates/pi-natives/src/code_path/napi.rs:131-154= a generic =DotLexer= (alphanumeric +
=.= only) is hard-coded into =execute_code_path_inner= at line 171:
=parse_code_path(&opts.target, &dot_lexer)=. All 8 dialect =NameLexer= impls
(=crates/pi-code-path/src/dialects/{rust,typescript,python,go,haskell,html,css,mdorg}.rs=)
exist, are tested in isolation, and are wired into =LanguageDialect= factories — but never
selected at parse time. =CodeResolver= uses =NameLexer.matches()= during resolution, but
matches against a NamePayload that was parsed with the wrong lexer.

This is a pre-condition for FEAT-672..679 (per-dialect qualifier work) — the qualifier
resolvers only fire on correctly parsed NamePayloads.

* Edge Cases

- =foo.ts.snap::Snap= (file with multiple dots in extension) → use last extension =.snap=,
  fall back to DotLexer (no registered =.snap= dialect)
- =src/Foo.test.ts::Bar= → still routes to TS via final =.ts=
- Symlinks: dialect chosen by symlink target name, not link name. Resolved via
  =std::fs::canonicalize= when needed; if symlink dangling, fall back to extension on link
- Empty FS prefix (=::Foo=) → no FS literal, fall back to DotLexer
- Quoted backtick FS literal (=` foo bar.ts `::Bar=) → strip backticks before extension scan
- Non-UTF-8 paths → fall back to DotLexer; diagnostic emitted
