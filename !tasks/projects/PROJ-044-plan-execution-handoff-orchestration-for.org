* Scope
In scope:
- Align execution-facing prompt and orchestration surfaces so approved plans are consumed as instruction sources, not merely as tracking artifacts.
- Update `packages/coding-agent/src/prompts/system/plan-mode-approved.md` plus related `todo_write` / `task` guidance and prompt tests so execution follows the new execution-first contract.
- Ensure wave manifests, child-item sub-outline IDs, blockers, verification gates, and completion handoff remain consistent with the richer planning contract.

Out of scope:
- Defining the planning prompt contract itself; covered by sibling prompt-contract item.
- Adding validator invariants or parser logic in `exit_plan_mode`; covered by sibling validation item.
- Reworking unrelated runtime task execution features or auto-roster behavior beyond prompt/orchestration guidance required by this initiative.

Rationale: even with a better planning contract and stronger validator, the execution agent can still regress if approved-plan, todo, and task prompts treat the plan as a passive artifact. This item makes the execution side consume plan artifacts as direct instructions while preserving truthful orchestration and verification behavior.

* Edge Cases
- Execution guidance must not duplicate lifecycle bookkeeping already owned by `todo_write` / org hooks.
- Plans with wave manifests but no PLAN-level implementation instructions should be treated as lower quality handoffs, but approved-mode prompts must remain robust while both old and new plans coexist during migration.
- Auto-roster guidance must not conflict with manual todo seeding when a plan requires explicit gates or org links.
- Completion protocol must still emphasize truthful blocker reporting rather than forcing artificial closure.

* Acceptance Criteria
- Approved-plan prompt treats the plan artifact as a direct execution guide, not only as a record to mirror.
- Todo/task guidance maps execution work to wave + child-item + sub-outline structure clearly enough for fresh execution sessions.
- Prompt tests prove that execution guidance remains balanced: rationale/context preserved, actionable steps prioritized.
- Existing truthful lifecycle / completion protocol behavior remains intact.
- Orchestration wording does not contradict auto-roster, blocker, or org-hook semantics.
