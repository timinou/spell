Implement =MutationResolver= for =CodeResolver=, covering structural action kinds:

Decision: design allows incremental migration. Initial impl can delegate to
=pi-natives::code_buffer::edit_transaction= for actions where it already produces
correct results; over time, code paths migrate inward to pure =pi-code-path= logic.

* Context & Narrative
=pi-natives::code_buffer.rs::execute_code_buffer_inner= (1724 LOC) implements all
structural actions today, used by Phase A's =edit.ts::#executeStructural=. The
challenge: =pi-code-path= must NOT depend on =pi-natives= (cycle-free invariant). So
the impl strategy is:

1. =CodeResolver= in =pi-natives= (impl already lives there per audit) gains a
   =MutationResolver= impl that internally calls its existing structural-edit machinery.
2. The =MutationResolver= trait lives in =pi-code-path= so the contract is shared.
3. =execute_code_path_inner= dispatches actions to =CodeResolver::apply= which then
   internally consults =edit_transaction= where appropriate.
