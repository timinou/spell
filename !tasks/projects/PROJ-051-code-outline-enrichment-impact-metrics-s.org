Extend `code outline` with structured per-symbol enrichment so the tool surfaces signal that today forces a `code read resolution=3`.

## Scope

Layer additions over existing `OutlineEntry` (`crates/pi-code-engine/src/outline.rs:14`) without breaking the default output. Four tiers, additive via a new `enrich: ("signature" | "metrics" | "doc" | "graph")[]` parameter. Tier L0 (`loc`, `modifiers`, `decorators`, `deprecated`) is on unconditionally at resolution >= 1. Graph tier reuses `GraphContextResult` / `graph_impact` from `crates/pi-code-graph/src/query.rs`; when the index is missing or stale the natives layer blocks on a synchronous rebuild before returning.

## Non-goals

- No per-symbol BFS outside `exported_reach` (hard caps: depth <= 2, fanout <= 64).
- No git blame, no TODO tallies, no aggregated complexity score.
- No schema change when `enrich` is omitted -- byte-identical output on existing fixtures.

## Decisions (from design review)

- L0 auto-on at resolution >= 1.
- Graph gating: synchronous index on demand; header reports `graph: indexed (warm)` vs `graph: rebuilt`.
- `exported_reach` ships day 1 with depth <= 2, fanout <= 64, displayed as exact integer or `N+` on cap.
