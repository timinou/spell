* Context
This item delivers the user-facing desktop shell for the Typst WYSIWYG editor. The primary experience is editing-first and visual-first: non-technical users interact with a Notion/Word-style surface, not raw Typst. QML remains the application shell and should reuse the styling/component conventions already present in the repo. This item consumes the native document surface and the source-canonical edit engine from earlier items.

* Design Decisions You MUST Follow
- The visual surface is primary. Optional true preview is secondary and must not dominate the layout.
- Source/manual mode is hidden behind recovery/advanced affordances and is not first-class navigation.
- Unsupported regions must be shown honestly with disabled or preview-only affordances; do not pretend every visual element is editable.
- The UI should feel desktop-polished: keyboardable controls, focus treatment, explicit busy/error states, and clear recovery banners.

* Implementation
** Shell composition
Build a panel/shell that includes:
- the embedded native document surface as the central editing area
- toolbar with common text/block operations
- slash/insert menu or equivalent insert affordance
- contextual sidebar that changes based on current selection/block type
- template chooser and file/template navigation where applicable
- asset picker flow for images and document resources
- visible fallback/recovery state when interactive editing is degraded

** Contextual UX
The contextual sidebar and controls must support, at minimum:
- paragraph/heading/list formatting
- image replacement and caption-oriented controls
- table-oriented controls for supported table interactions
- variable/config editing panels for template-driven documents
- block reorder/delete/add affordances that call the edit engine rather than inventing a second document model

** Recovery and degraded states
Design and implement explicit UX for:
- renderer unavailable → preview-only banner
- unsupported construct → non-editable marker with explanation
- source recovery mode → hidden but reachable from error/fallback surfaces
- agent/collaborative update in progress → busy/refresh state without losing editor context

* Enumerated User Workflows
The UI and harness verification must cover all of these scenarios:
1. Open a template-backed document and start typing without seeing Typst source.
2. Apply heading/list formatting from toolbar/sidebar.
3. Use insert/slash affordance to add a supported block.
4. Select an image and replace its asset from a picker flow.
5. Open a contextual panel for variables/config values and update them.
6. Encounter an unsupported construct and receive a truthful preview-only affordance.
7. Enter hidden recovery/source mode from an error/fallback path.
8. Return from recovery mode back to the visual surface.
9. Receive an agent-applied update and continue editing without reopening the document.

* Edge Cases and Failure Handling
- Sidebar state must track selection changes without lagging behind the document surface.
- Fallback banners must not obscure the document beyond recovery.
- Keyboard focus must remain usable after modal pickers/drawers close.
- Preview-only regions must be visually distinguishable but not visually noisy.
- Long-running asset/template loads must surface progress and failure honestly.
