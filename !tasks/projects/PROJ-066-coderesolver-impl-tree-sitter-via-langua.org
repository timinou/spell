* Intention & Purpose

Implement =CodeResolver= trait against =pi-code-engine::LanguageProfile= + tree-sitter at =crates/pi-natives/src/code_path/code_resolver.rs=. Resolves =Foo.bar/§call_expression[name=fetch]/:arguments[0]= against an actual TS/Rust/etc. AST. This is what activates the per-language NameLexers shipped in =FEAT-656= through =FEAT-662=.

* Context & Narrative

The =CodeResolver= trait is declared in =pi-code-path/src/resolver/traits.rs=. It needs =LanguageProfile= context to: (1) parse a file with the right tree-sitter grammar; (2) call =NameLexer::matches()= with full context; (3) traverse AST applying combinators (=/=, =//=, =^=, =^^=, =<<=, =>>=, kernel-shared step walk).

The existing =resolve_symbol()= pattern in =pi-code-engine= (per PLAN-255 inventory) is the reference for top-level + member-chain walk. Anchors (=¶name=) consult =LanguageDialect::anchors= via =LanguageProfile.dialect=. Qualifiers (=#name=) consult =LanguageDialect::qualifiers= for body/sig/name range resolution.

* Edge Cases

- File with parse errors: tree-sitter still produces tree with error nodes; walker continues; emit =Diagnostic::PartialParse=.
- Symbol not found: empty stream + =Diagnostic::NoMatches=.
- Ambiguous symbol (e.g. two top-level decls with same name): emit all matches; let projection decide; optionally emit =Diagnostic::AmbiguousTarget { count: N }=.
- Qualifier on incompatible node kind (=#body= on a variable): =Diagnostic::UnsupportedQualifierForNodeKind=.
- File unsupported language (no =LanguageProfile.dialect=): fall back to text dialect; emit =Diagnostic::UnknownLanguage=.
