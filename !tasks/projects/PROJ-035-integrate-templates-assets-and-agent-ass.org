* Design Decisions You MUST Follow
- Templates and variables are part of the initial plan, not a later nice-to-have.
- Variable/config editing may use source-adjacent inputs where appropriate, but the relationship back to canonical Typst documents must remain explicit and deterministic.
- Agent operations are assistive. They must use the same canonical update path as user edits, not a parallel mutation pipeline.
- Asset replacement must update canonical references truthfully; no hidden shadow asset model.

* Implementation
** Template workflows
Support opening or creating documents from known templates. The editor should surface template-specific variable/config controls without exposing raw source in normal use. When variables are changed, the resulting canonical source/config inputs must be updated through the same mapping/orchestration layer used elsewhere.

** Asset workflows
Provide a user-facing asset picker/replacement flow for supported assets, especially images. The flow must:
- show current asset usage
- replace canonical references rather than mutating only the rendered surface
- surface validation errors for missing or invalid assets
- preserve document recovery when an asset cannot load

** Agent-assisted workflows
Define and wire agent affordances for actions such as:
- insert section from prompt
- rewrite selected paragraph/block
- populate template variables from structured data
- refresh a generated summary/analysis block

All agent changes must re-enter through the same edit engine and mapping refresh path as manual edits. If an agent proposes an unsupported construct, the system must surface it honestly and preserve recovery options.

* Enumerated User Workflows
1. Create a document from a template and fill required variables.
2. Re-open a template-backed document and preserve its variable panel state.
3. Replace an image asset and observe the canonical source/reference update.
4. Trigger an agent rewrite for a selected block and keep cursor/context stable afterward.
5. Ask the agent to insert a supported section or component.
6. Encounter a bad/missing asset and recover without losing document state.
7. Encounter an agent-generated unsupported construct and fall back truthfully.

* Edge Cases and Failure Handling
- Template metadata/schema mismatch must surface clearly.
- Missing template assets must not corrupt canonical source.
- Concurrent agent/user updates must avoid silent last-writer-wins lies; at minimum, show refresh/reload state truthfully.
- Variables edited through panels must stay in sync with rendered content after recompile.
