* Edge Cases
- A category can be low-value for persistence but still high-value for immediate inline debugging; the classifier must allow those distinctions.
- Transcript spelunking must not accidentally classify legitimate user-facing artifact reads as noise.
- Category decisions must survive pruned tool-result paths without corrupting the visible transcript.
- Summary-only persistence must preserve failure truth (`what failed`, `where`, `next follow-up surface`) without sneaking raw dump text into memory.
- Shared metadata must not force precision tools into low-spill or compact rendering behavior by accident.

* Acceptance Criteria
- A shared category/policy framework exists and is covered by focused tests.
- Raw low-value tool outputs no longer persist directly into memory; compact semantic summaries / diagnoses persist instead.
- Transcript spelunking is recognized as a first-class cross-tool policy category.
- Child items can reuse one summary-first / auto-escalation contract instead of inventing separate behaviors.
- The project is explicitly ready to unblock tool-specific follow-on items after `PLAN-239-bash-low-spill-artifact-policy-plan` lands.
