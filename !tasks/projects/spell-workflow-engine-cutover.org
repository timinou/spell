* Edge Cases
- Claim expiry and action submission must not race into double transitions.
- Action payload validation must be shared across APIs, Telegram, QML, and coding-agent tools.
- Artifact replacement must preserve full audit history and superseded references.
- Notification failures, downstream job failures, and KDL writeback failures must surface truthfully without corrupting workflow state.
- Atomicity model: state transition, audit append, artifact mutation, and writeback bookkeeping should commit together or fail together.

* Acceptance Criteria
- `packages/spell-server/src/http/routes/operator-actions.ts` is no longer the canonical growth-specific approval contract.
- Spell server exposes stable approval, downstream-job, and goal APIs backed by a dedicated workflow schema.
- Checkpoints can pause/resume runs, fail runs, launch follow-up goals, or create further approvals according to policy.
- The sync folder emitter produces JSON indexes and per-record JSON files that a separate QML session can consume without DB access.
