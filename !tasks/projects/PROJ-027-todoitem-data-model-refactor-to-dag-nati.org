* Narrative

This is the central refactor. Today =TodoItem= has a numeric =id= (=task-3=), belongs to a =TodoPhase= (execution barrier), and uses a flat =blockers: string[]= for DAG edges. Phases dictate ordering: "complete phases in order" is a prompt-enforced rule, not a code-enforced DAG property.

After this refactor:
- =TodoPhase= is eliminated as an execution barrier. It becomes an optional cosmetic label (like an org heading) with no scheduling semantics.
- =TodoItem.id= becomes a URI slug (=define-types=) that resolves to a full =task://= or =data://= URI via context.
- =TodoItem.kind= distinguishes work nodes (dispatched to agents) from data nodes (satisfied when content exists).
- The =MutableDag= is the sole authority on ordering. =blockers= are edges in the DAG. =normalizeInProgressTask= is replaced by DAG =getReady()=.
- Fine-grained typed events are emitted on every mutation via the typed =EventBus=.
- Branch-scoped views: a subagent's =todo_write= defaults to showing its own branch. It can query parent/sibling state via =task://= URIs.

This is the largest item in the plan. The sub-outline decomposes it into independently testable pieces.

* Design Decisions

1. =TodoPhase= interface survives as =TodoGroup= -- a cosmetic label. =TodoGroup.tasks= is a flat list. Groups have no scheduling semantics.
2. =TodoItem= gains: =kind: "work" | "data"=, =uri: string= (canonical task:// or data:// URI), =filesDeps?: string[]=, =children?: TodoItem[]=.
3. =TodoItem.id= is the slug portion of the URI. Backward-compat: =task-3= slugs still work.
4. =TodoItem.blockers= references URI slugs (resolved via context) or full URIs.
5. The internal state is a =MutableDag<TodoItem>=. =applyOps()= mutates the DAG. =getTodoState()= returns a view (groups + flat task list) derived from the DAG.
6. =normalizeInProgressTask= is replaced by a new =promoteReadyTasks(dag, isolationMode)= function that uses =dag.getReady()= and file-dep overlap checking.
7. Fine-grained events emitted after each op: =todo:task:created=, =todo:task:status=, =todo:task:blocked=, =todo:task:unblocked=. The coarse =todo:change= event is still emitted for backward compat (derived from fine-grained events).
8. The =todo_write= tool schema changes: =replace= op takes a flat task list with explicit =blockers= instead of phases. =add_phase= becomes =add_group= (cosmetic). =add_task= works on the flat DAG.
9. SMOL model optionally names categories from the DAG structure post-hoc. This is a rendering concern, not a data model concern.

** PROJ-027::promote-ready-tests
File: =packages/coding-agent/test/tools/todo-promote-ready.test.ts=

*** Isolation off: single task promoted
- DAG: a(pending), b(pending, blocks:[a]). isolationMode=false.
- =promoteReadyTasks(dag, false)= => a becomes in_progress, b stays pending.

*** Isolation on: multiple independent tasks promoted
- DAG: a(pending, files:["x.ts"]), b(pending, files:["y.ts"]). No edges. isolation=true.
- => Both become in_progress.

*** Isolation on, file overlap: serialized
- DAG: a(pending, files:["x.ts"]), b(pending, files:["x.ts"]). isolation=true.
- => Only a becomes in_progress.

*** Delegated tasks: excluded from promotion logic
- a(in_progress, delegated), b(pending). isolation=false.
- => b becomes in_progress (delegated a doesn't count).

*** Blocker resolution
- a(completed), b(pending, blocks:[a]). => b promoted.

*** Data nodes: satisfied when content exists
- data node d(pending, kind:"data"), work node w(pending, blocks:[d]).
- d has content => d auto-satisfied, w becomes ready.
