* Goal

Create a new Rust crate =crates/pi-org-engine/= that provides native tree-sitter-based org-mode file parsing. This replaces the Emacs daemon + org-element for structural understanding of org files. Follows the same architecture as =crates/pi-code-engine/= (buffer registry, tree-sitter parsing, command dispatch).

* Design Decisions

- Use milisims/tree-sitter-org grammar (MIT license), vendored into a workspace crate =crates/tree-sitter-org/= because the published crate (v1.3.3) requires tree-sitter <0.21 and the project uses tree-sitter 0.25
- Tree-sitter provides document structure (sections, headlines, drawers, bodies); custom Rust code extracts semantic content (TODO states, property values, timestamps, clocks, effort)
- OrgBuffer wraps tree-sitter parser for a single org file with incremental reparsing
- OrgItem is the primary output type: id, title, state, priority, tags, properties, body, children, level, file, line
- Two org item formats are supported:
  1. File-level items: =#+KEY: value= frontmatter, level 0, CUSTOM_ID from =#+CUSTOM_ID:= line
  2. Heading-level items: =* STATE title :tags:= with =:PROPERTIES:= drawer, level from star count
- Effort format: regex =^[0-9]+[hm]$= (e.g., "2h", "30m"). Effort is parsed to minutes for comparison.
- Timestamps: active =[<2024-01-15 Mon>]=, inactive =[2024-01-15 Mon]=, ranges, repeating. Parsed to a Rust Timestamp struct.
- CLOCK entries: =CLOCK: [2024-01-15 Mon 09:00]--[2024-01-15 Mon 10:30] => 1:30= in LOGBOOK drawers. Duration parsed to minutes.
- Org-to-markdown conversion: walk tree-sitter AST nodes, emit corresponding markdown (headlines -> #, bold -> **, links -> [](), etc.)

** =crates/pi-org-engine/src/buffer.rs=
- =OrgBuffer= struct: rope (Rope), tree (Tree), parser (Parser), path (Option<PathBuf>)
- =OrgBufferRegistry= (like CodeBuffer's BufferRegistry): open/close/list, keyed by path
- =open(path)=: read file, parse with tree-sitter-org, return OrgBuffer
- =reparse()=: incremental reparse after edit
- =items()=: extract all OrgItems from the current tree

** =crates/pi-org-engine/src/item.rs=
- =OrgItem= struct matching the TypeScript interface:
  #+begin_src rust
  #[derive(Debug, Clone, Serialize)]
  pub struct OrgItem {
      pub id: String,          // CUSTOM_ID
      pub title: String,
      pub state: String,       // TODO keyword
      pub category: String,
      pub dir: String,
      pub file: String,
      pub line: usize,         // 1-indexed
      pub level: usize,        // 0 for file-level, 1+ for headings
      pub properties: HashMap<String, String>,
      pub body: Option<String>,
      pub children: Vec<OrgItem>,
  }
  #+end_src
- =extract_items(tree, source, file_path)=: walk tree-sitter nodes, extract items
  - For file-level: find =directive= nodes with name "CUSTOM_ID", "STATE", "TITLE", etc.
  - For heading-level: find =section= -> =headline= -> parse stars/item/tags; find =property_drawer= -> parse =:KEY: value= lines
  - Body: text between property drawer end and next section at same/higher level
- =find_item_by_id(tree, source, id)=: locate specific item by CUSTOM_ID
- =find_section_range(tree, source, item_id, section_name)=: return byte range of a named sub-heading within an item's body (used for section editing)

** =crates/pi-org-engine/src/timestamp.rs=
- =OrgTimestamp= enum: Active, Inactive, Range, Diary
- Each variant contains: year, month, day, optional weekday, optional time (hour, minute), optional repeater
- =parse_timestamp(text: &str) -> Option<OrgTimestamp>=
- =timestamp_in_range(ts, from, to) -> bool=
- Handle formats: =<2024-01-15 Mon>=, =<2024-01-15 Mon 09:00>=, =<2024-01-15>--<2024-01-20>=, etc.

** =crates/pi-org-engine/src/clock.rs=
- =ClockEntry= struct: start (datetime), end (Option<datetime>), duration_minutes (u32)
- =parse_clock_entries(body: &str) -> Vec<ClockEntry>=
  - Parse lines matching =CLOCK: \[...\]--\[...\] =>  H:MM= or =CLOCK: \[...\]=
- =total_clocked_minutes(entries: &[ClockEntry]) -> u32=
- =clocked_on_date(entries, date) -> bool=

** =crates/pi-org-engine/src/effort.rs=
- =parse_effort(text: &str) -> Option<u32>= — returns minutes. "2h" -> 120, "30m" -> 30
- =effort_matches(effort_minutes: u32, op: &str, threshold: u32) -> bool=

** =crates/pi-org-engine/src/markdown.rs=
- =org_to_markdown(tree, source) -> String=: walk tree-sitter AST, emit markdown
  - headline stars -> # depth, bold -> **, italic -> *, links -> [](), lists preserved, code blocks -> triple backticks
- =org_to_plaintext(tree, source) -> String=: strip all markup
- =extract_keywords(tree, source) -> HashMap<String, String>=: extract =#+KEY: value= directives

** =crates/pi-org-engine/src/error.rs=

- Implement Display and std::error::Error

* Edge Cases

- Empty org file: returns empty items list
- File with only directives (no headings): returns single file-level item
- Properties with colons in values: =:URL: https://example.com= — only first colon after key is delimiter
- Multi-line body text with embedded headlines at lower level
- Unicode in titles and property values
- Malformed CLOCK entries (missing end time, no arrow)
- EFFORT without unit: "2" → None (invalid format)
- Heading with no TODO state: state should be empty string
- Tags: =:tag1:tag2:= format, parsed into Vec<String>
