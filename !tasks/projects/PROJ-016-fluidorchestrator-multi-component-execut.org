* Initial Message

Think about it. the wave-based dependency ordering only makes sense for one DAG, but orchestration flows can be several DAGs. Can you leanly improve/change the decomposition steps of plans and ultraplans to fully support these? As in: you remove Daedalus (just don't activate it anymore), but instead you create the org files, and the org subtasks can depend on each other and other file CUSTOM_IDs, and the execution manifest is built from there, and there is a way to spin several agents that will then also spin agents so that there are several threads, that are coordinated through the main agent? And then once the first DAG has been generated, Daedalus is generated with that DAG summary as the startying point, instead of the current way which has Daedalus generate the decomposition analysis before the DAG which makes no sense? That way we can unlock deep parallelism and the orchestration is way more more granular per subtask

Ask me many questions. Challenge me a lot.

* Edge Cases
- Single-component plan :: no splitting occurs, FluidOrchestrator backward-compatible with current behavior
- Plan with 0 agents :: =validatePlan= rejects (existing behavior preserved)
- Coordinator abort :: parent =AbortController.abort()= cascades to all coordinator controllers
- Coordinator failure :: only the failed coordinator is marked failed. No dependents since coordinators are independent (=dependsOn: []=)
- =canvasOutput= on coordinator nodes :: ignored (canvas output is per-task, not per-coordinator)
- Preset completed results :: still work for non-coordinator nodes; coordinator nodes are never preset-completed
