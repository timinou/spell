Critical runtime facts to preserve:
- Specialized tool descriptions are compacted via `compactToolDescription()` (`packages/coding-agent/src/tools/index.ts`).
- Compact extraction uses the first sentence; the first sentence must therefore stand alone as a truthful, useful capability summary.
- Hidden tools still reach subagents and must match the same voice even if the main UI hides them.

* Implementation
1. Rewrite every description above into the canonical terse shape.
2. For specialized tools, treat the first sentence as a hard interface contract:
   - it must be independently comprehensible
   - it must not rely on a following paragraph to explain the core use case
   - it must avoid abbreviations or sentence fragments that compact poorly
3. Expand critical stubs into complete but concise docs. Priority fixes include:
   - `gateway.md`
   - `gemini-image.md`
   - `resolve.md`
   - `cancel-job.md`
   - `render-mermaid.md`
   - `canvas-cast.md`
4. Preserve the stronger existing patterns where they already help:
   - `browser.md` preferring observe over screenshot
   - `inspect-image.md` and `inspect-image-system.md` evidence-first guidance
   - `checkpoint.md` and `rewind.md` lifecycle pairing
5. Upgrade loop tool descriptions from bare one-liners into the same canonical shape unless the spec explicitly allows a deliberately minimal one-liner for one of them. Default to canonical shape, not placeholders.
6. For `org`, `submit_result`, and `autonomy_state`, preserve the exact protocol truth. These descriptions must remain accurate about lifecycle, schema validation, state mutation semantics, and failure behavior.
7. If the topology item externalizes inline descriptions into markdown files, rewrite the new canonical files rather than leaving policy-rich descriptions inline in TypeScript.

* Edge Cases
- Do not let compacted first sentences become generic slogans like “Manages state” or “Handles jobs.” They must preserve actual differentiation.
- `inspect-image-system.md` is a system prompt fragment, not just a tool blurb; keep its evidence-vs-inference boundary explicit.
- `org` and `submit_result` are easy to oversimplify. Accuracy outranks token shaving.

* Acceptance
- Every specialized/hidden tool in scope has a first sentence that still works after compaction.
- Placeholder/stub descriptions are eliminated.
- Loop tools, hidden tools, and inline-description tools no longer lag behind the main tool docs in voice or completeness.
