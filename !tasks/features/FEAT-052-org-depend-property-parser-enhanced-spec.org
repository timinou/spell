* Scope
Parse org-depend conventions (BLOCKER, TRIGGER) and custom gate hint properties (GATE_CMD, GATE_ARTIFACT, GATE_LLM) from org spec files. Enhance the existing spec ingestion pipeline to extract structured ticket data.

** In-Scope
- Parse BLOCKER property from PROPERTIES drawers: list of IDs that must be DONE before this ticket starts
- Parse TRIGGER property: =ID(KEYWORD)= expressions and =chain-siblings(KEYWORD)= for sequential chains
- Parse custom properties: GATE_CMD (shell command), GATE_ARTIFACT (file path + optional regex), GATE_LLM (criteria string)
- Extract acceptance criteria from spec headings (look for =Acceptance Criteria= heading or =** AC= or =** Acceptance=)
- Extract structured data: EFFORT, PRIORITY, LAYER, tags from org properties
- Build dependency graph (edges from BLOCKER references)
- Build trigger rules (from TRIGGER expressions)
- Integrate with existing =ingestion/parser.ts= pipeline
- Support both file-level (=#+PROPERTY:=) and heading-level (=:PROPERTIES:= drawer) property formats

** Out-of-Scope

interface ParsedDependencies {
  blockers: string[];          // IDs from BLOCKER
  triggers: TriggerRule[];     // From TRIGGER
  gateHints: GateHint[];       // From GATE_CMD, GATE_ARTIFACT, GATE_LLM
}

interface TriggerRule {
  type: "id-keyword" | "chain-siblings";
  targetId?: string;
  keyword: string;
}

interface GateHint {
  type: "command" | "artifact" | "llm-review";
  command?: string;   // GATE_CMD
  path?: string;      // GATE_ARTIFACT
  regex?: string;     // GATE_ARTIFACT_REGEX
  criteria?: string;  // GATE_LLM
}

function parseDependProperties(properties: Record<string, string>): ParsedDependencies;
function parseBlocker(value: string): string[];
function parseTrigger(value: string): TriggerRule[];
function parseGateHints(properties: Record<string, string>): GateHint[];
#+end_src

* Edge Cases
- BLOCKER referencing non-existent ID: validation warning (not error - ID might be in a different spec directory)
- Self-referencing BLOCKER: reject as error
- chain-siblings with no next sibling: validation warning
- GATE_CMD with shell metacharacters: pass through as-is (bash -lc handles it)
- Empty PROPERTIES drawer: skip gracefully
- Multiple GATE_CMD properties: collect all as separate gate hints
- File-level =#+BLOCKER:= vs heading-level =:BLOCKER:=: both supported, heading-level takes precedence
