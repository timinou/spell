* Intention & Purpose
Stop the data-loss bug where `edit(target="file.ts::fnName", action={kind:"delete"})` deletes the entire file. Stop the silent-read bug where `get(target="any-file.ts")` returns "unknown qualifier: raw". Both are routing defects in `execute_code_path_inner`: FsResolver claims actions/queries that should reach a different resolver because the routing predicate ignores the qualifier/symbol portions of the parsed CodePath.

* Context & Narrative
Two related routing flaws surfaced after FEAT-687 migration. (1) FsResolver.supports() returns true for Action::Delete unconditionally; resolve_target_path discards the query selector; apply() runs std::fs::remove_file on the whole file. (2) For reads, get.ts auto-attaches `#raw` to bare files, but the routing predicate is_pure_text_query requires a structural query head (line/para/chunk). A bare file with #raw and no query head falls through to FsResolver, which only knows listing/tree/stat — so it errors "unknown qualifier: raw". Both root causes are in the dispatch logic, not the resolvers themselves.
