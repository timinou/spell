Wire the interactive mode's blocking points to emit events via the session bridge client, and race remote responses against local TUI input.

* Blocking Points to Instrument

** Plan Approval (=handleExitPlanModeTool=)

In =interactive-mode.ts= line ~1375, after =isPendingApproval = true= and before the selector:

1. Emit =blocking_event= with kind =plan_approval= to bridge
2. Payload: title, itemId, childItemIds, planContent (truncated summary), waves, selectorOptions
3. Race the =showHookSelector= call against the bridge's =waitForRemoteResponse()=
4. If remote response arrives first: use the chosen option, skip local selector
5. If local input resolves first: cancel the bridge event

** Ask Tool

The ask tool in =src/tools/ask.ts= blocks on user input. When bridge is connected:

1. Emit =blocking_event= with kind =ask= before blocking
2. Payload: questions array (id, question, options, recommended, multi)
3. Race local input vs remote response
4. Remote response format: array of {questionId, selectedOptionIndices} matching the ask tool's response format

** Hook Selectors and Inputs

The generic =showHookSelector= and =showHookInput= in =extension-ui-controller.ts= are used by various features. Only instrument the ones that represent genuine user-facing blocking states, not incidental UI:

- Plan approval selector (already covered above)
- Audit completion selector (=handleExitPlanModeTool= path)
- Any selector where =isPendingApproval= is true

Do NOT instrument every selector — most are transient UI choices during agent operation.

* Race Pattern Implementation

Create a helper =raceWithBridge= in =src/session-bridge/race.ts=:

#+begin_src typescript
async function raceWithBridge<T>(
  localPromise: Promise<T>,
  bridge: SessionBridgeClient | undefined,
  eventKind: BlockingEventKind,
  payload: unknown,
): Promise<{ source: "local" | "remote"; value: T }>;
#+end_src

- If bridge is undefined or not connected, just await localPromise
- Otherwise, emit blocking event and race the two promises
- When one resolves, cancel the other (abort the bridge event or resolve/ignore the selector)
- Return the result with source annotation for logging

* Edge Cases

- Remote response arrives for a selector that was already resolved locally: ignore (event was cancelled)
- Bridge disconnects while event is pending: local input takes over seamlessly
- Plan content too large for Telegram (4096 char limit): truncate to summary in the blocking_event payload. Full plan viewable via a follow-up Telegram command.
- Multiple blocking events in quick succession (e.g., ask followed by plan): each tracked independently by eventId
