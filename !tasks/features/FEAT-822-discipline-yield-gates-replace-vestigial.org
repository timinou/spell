# Discipline yield-gates: replace the vestigial todo-reminder system

## Motivation (evidence)

A harbor/Terminal-Bench run (jobs/2026-06-16__07-52-39, task
filter-js-from-html) scored reward 0.0: the agent shipped a regex/HTMLParser
sanitizer, claimed "Verified: ✓" on 12 hand-picked cases + 1 benign sample, and
the hidden verifier proved it wrong (3/28 XSS batches fired alerts; 5/12 clean
samples mutated).

Root cause is NOT infra (0 exceptions, exit 0). It is an *enforcement gap*:

1. The prose `<discipline>` honesty-trigger WAS in the system prompt (base
   template used; domain appended) — and was ignored. Prose norms do not bind an
   overconfident model.
2. The FEAT-816 `verify` gate (the only *mechanical* loop-closer) has **no
   enforcement hook at session yield** — it only fires on todo/task nodes
   (`todo-write.ts`, `task/ref-resolver.ts`). A headless `-p` run has no roster,
   so `verify` is dead code there.
3. A vestigial hard-coded system (`#checkTodoCompletion`) reminds the session
   up to 3× at yield when todos are incomplete — but only catches "unfinished
   todos", never "weak verification". It is bespoke, not data-driven.

## Goal

One data-driven yield-evaluation path, sourced from disciplines, that replaces
the vestigial system AND adds the missing mechanical verification gate.

## Non-goals

- No task/domain-specific logic. The XSS task is an *example* of a hard problem;
  the fix is generic scaffolds. No HTML/XSS/parser specifics anywhere.
- No changes to harbor or spell_harbor/. All work is in Spell core
  (packages/coding-agent).
- No task-classifier for `on auto` yet. `auto` ≙ always-on for now.
- No `verify.swarm` at yield (needs session-diff plumbing) — FUP.

## The unified primitive

A discipline's loop-closing power extends from the todo-node to the **root
session yield**. One function `#evaluateYieldDisciplines()` replaces
`#checkTodoCompletion()`, reusing its proven inject + scheduleAgentContinue +
max-reminders seam.

Two primitive pieces:

### (NEW) `Discipline.guard` — session-yield predicate
Sibling to node-scoped `verify` (yield-guards are session-scoped, not
node-scoped). Type `YieldGuard = "open-work"`. Cheap, always evaluated.
- `open-work`: ∃ pending/in_progress todos → re-prompt. Reproduces the old
  "incomplete todo" behavior generically.

### (EXISTING, new site) `verify.cmd` / `verify.review` — evaluated at yield
Only when the agent's final yield reads as a completion claim (conservative
regex; bounds cost in interactive mode). This answers C3/C4:
- **C4 shape** = `verify { cmd "…" }` at yield: Spell *runs* it; non-zero exit →
  re-prompt. Domain guidance becomes a real gate, not prose.
- **C3 shape** = `verify { review "…" }` at yield: the existing `review-judge.ts`
  (`createModelReviewJudge`, fail-open) judges the agent's final claim against
  generic criteria; reject → re-prompt. The Spell-native, fully-generic honesty
  check. No message parsing as the gate itself; the regex only *gates whether to
  spend* the review.

### Trigger wiring
`on auto` disciplines become session-active (always-on). `setDisciplines`
filters them into `#yieldDisciplines`. (Tool/layer/manual triggers unchanged.)

## Default always-on disciplines

Location: `packages/coding-agent/src/config/bundled-disciplines.kdl`
(the obvious, already-existing bundled-defaults location; `loadMergedDisciplines`
already merges them into every repo, user/project override by name).

1. `finish-the-loop` — `on auto`, `guard "open-work"`. Replaces the vestigial
   behavior. Generic inject.
2. `verify-before-claim` — `on auto`, `verify { review "…" }` with GENERIC
   criteria (no task/language/domain specifics). The mechanical honesty gate.
3. `mock-critique` — existing, unchanged.

## Acceptance criteria (observable)

1. `bun run check:ts` clean.
2. `bun run --filter @spell/coding-agent test` (discipline + todo suites) green.
3. A session with an incomplete todo + `finish-the-loop` active re-prompts at
   yield (old behavior preserved via the new path).
4. `todo_reminder` / `todo.reminders` / `TodoReminderComponent` fully gone
   (`rg` finds zero references in src).
5. A `verify { cmd "exit 1" }` discipline blocks yield; `cmd "exit 0"` does not.
6. `verify-before-claim` review: when the judge returns pass=false, the agent is
   re-prompted; fail-open (judge error) never blocks.

## Risks

- **Breaking**: removes a public extension/hook event (`todo_reminder`) and two
  settings. Mitigation: documented in changelog; the replacement is strictly
  more general.
- **Cost**: `verify-before-claim` adds one model-judge call per completion-claim
  yield (bounded by max-reminders=3, fail-open, gated by completion-claim regex
  so interactive chat is not judged). Reuses existing review-judge (no new infra).
- **Central code**: agent-session yield path is high blast radius. Mitigation:
  reuse the exact inject+continue+max seam; behavioral parity for the open-work
  case.
