* Narrative

Tasks and data live in the DAG. But agents need durable shared state that persists beyond a single session and is human-readable. Org items serve this role: the blackboard. Agents write findings, contracts, and progress to org items. The event bus bridges blackboard writes to =data://= node satisfaction in the DAG.

The blackboard is *separate* from the DAG. It is the persistent storage layer. =data://= nodes in the DAG are the logical references. When a blackboard entry matches a =data://= node's expected content, the event bus fires =swarm:artifact= and the scheduler satisfies that node.

* Design Decisions

1. Blackboard entries are org items in a =swarm= category. Prefix: =SWARM=.
2. Each swarm run creates a parent item. Agent writes are children.
3. Entries have PROPERTIES: =:AGENT:=, =:TYPE:= (artifact/finding/handoff/progress/contract), =:DATA_URI:= (optional, links to a =data://= node).
4. =SwarmBlackboard= wraps =OrgClient= calls. On write, if =DATA_URI= is set, emits =swarm:artifact= event. The scheduler picks this up and satisfies the corresponding =data://= node.
5. LOGBOOK entries on the parent item record swarm lifecycle events (start/complete/fail per agent).
6. Agents interact via existing MCP org tools. =SwarmBlackboard= is a convenience layer for the scheduler/runtime, not a new tool for agents.
