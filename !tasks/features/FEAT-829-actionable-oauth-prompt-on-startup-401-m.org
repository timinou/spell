* Problem

When a KDL-declared OAuth MCP server has no stored credential, startup connect fails with `HTTP 401 invalid_token` and `connectServers` (packages/coding-agent/src/mcp/manager.ts) just logs `MCP tool load failed`. The user has no signal that the fix is an OAuth login, nor a single command to run it. Silent dead-end — the exact experience we hit with Notion.

* Fix

1. Startup surfacing (`connectServers` error branch):
   - When a connect error occurs, run `analyzeAuthError(error)` (mcp/oauth-discovery.ts:192). If `requiresAuth === true` AND no credential is currently resolvable for the server (no `auth.credentialId` or agent.db miss):
     - Record a distinct, NON-FATAL status for that server: e.g. `oauthRequired` with message `"<name>: OAuth required — run /mcp login <name>"`.
     - Surface it through the same channel the loader uses to report per-server errors, but tagged so the UI shows an actionable hint rather than a generic failure. Do NOT throw; other servers must still load.

2. `/mcp login <name>` subcommand (mcp-command-controller.ts):
   - Thin composition of existing pieces: `#findConfiguredServer` (now KDL-aware from FEAT-828) → if already has valid cred, say so; else `#resolveOAuthEndpointsFromServer`/`discoverOAuthEndpoints` → `#handleOAuthFlow` (browser + localhost callback) → build widened `auth {}` (BUG-491 fields: credentialId, tokenUrl, clientId, [clientSecret env-name]) → persist via settings tier (FEAT-828 path) → reload → report connected.
   - `login` vs `reauth`: `login` = first-time (no existing cred, friendlier "not authed yet" copy); `reauth` = force re-run discarding existing cred. Share the core helper; differ only in pre-checks + messaging. Add to the `/mcp` help text.
