* Intention & Purpose
Fix the routing miss in =execute_code_path_inner= where symbol queries on
non-tree-sitter-Code dialects silently fall through to FsResolver, returning the file
node instead of the symbol. Spec §3 promises =doc.md::heading=, =styles.css::.btn=,
=index.html::div[@id]=, =doc.org::Task= return symbol-shaped nodes; today they don't.

* Context & Narrative
Per audit (agent://35-Resolvers): =napi.rs:194-237= routes Locator::Fs targets via:
1. =is_text_query(cp)= → TextResolver (for §line/§para/§chunk axes)
2. =cp.query.is_some()= → FsResolver walks files, then CodeResolver per file
3. else → FsResolver only

The =cp.query.is_some()= branch ALWAYS runs for symbol queries (=foo.X::Sym= produces a
query). It calls =code_resolver::new()= which uses =pi_code_engine::LanguageRegistry= to
look up tree-sitter languages — but mdorg, html, css resolution may behave differently
since their =NameLexer= isn't a simple identifier lexer.

This item ensures CodeResolver dispatches correctly to tree-sitter-markdown, html, css
parsers and that the symbol matching uses each dialect's =NameLexer.matches()= against
parsed AST nodes.
