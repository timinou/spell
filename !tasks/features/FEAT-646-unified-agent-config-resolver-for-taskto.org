* Initial Message

I want to customise the TASK tool even further. Look at how subagents are currently being launched and how I could e.g. assign all explore agents to a specific model. I think there's something around kdl policies about this somewhere?

* Intention & Purpose
Replace the single-knob `task.agentModelOverrides[name]` lookup in `TaskTool.#executeSync` with a unified `resolveAgentEffectiveConfig(...)` that integrates per-call (item + batch), spell.kdl agent rules (project + user), settings DB, frontmatter, role alias, and parent active model — in the precedence order the user committed to. Also resolves `disabled`, `thinkingLevel`, and `tools` overrides where rules supply them.

- Logic order in `resolveAgentEffectiveConfig`:
  1. Merge `projectRules` after `userRules` (project last → wins ties via declarationOrder).
  2. `match = matchAgentRules(agentName, mergedRules)` → `{ winning, conflicts }`.
  3. `disabled = winning?.disabled ?? settings.get("task.disabledAgents").includes(agentName)`.
  4. Compute model patterns by priority (each step short-circuits when it produces non-empty patterns):
     - per-task `perCallTaskModel?.trim()`
     - per-batch `perCallBatchModel?.trim()`
     - winning rule `winning?.model`
     - settings DB `settings.get("task.agentModelOverrides")[agentName]`
     - agent frontmatter `agent.model`
     - parent active model fallback (`activeModelPattern || fallbackModelPattern || settings.getModelRole("default")`)
     Each non-empty value passes through `resolveConfiguredModelPatterns(value, settings)`. The first source producing a non-empty array wins. If a single agent pattern equals `pi/task` (session-inherit), allow falling through to active model — preserves current `resolveAgentModelPatterns` semantics.
  5. `thinkingLevel = winning?.thinkingLevel ?? agent.thinkingLevel`.
  6. `tools = winning?.tools ?? agent.tools`.
- Reuse `resolveConfiguredModelPatterns` from `model-resolver.ts` for each step.

* Edge Cases
- Both per-task and per-batch `model` empty → fall through to rules.
- A rule sets `disabled #true` AND `model "..."` — disabled takes precedence; resolver skips to short-circuit.
- Rule sets `tools` to empty list (`tools` with no args) — interpret as "no tools at all"? Decision: empty list means "no override" (omit). Document in DEVELOPMENT.md (FEAT-648).
- Rule applies to bundled `task` agent which has frontmatter `spawns: "*"` — rule-level `tools` override does not strip `task` tool (still auto-included by depth gating in `runSubprocess`).
- Caching staleness: editing `spell.kdl` requires `/agents` reload or restart. Acceptable for v1; note in docs.
