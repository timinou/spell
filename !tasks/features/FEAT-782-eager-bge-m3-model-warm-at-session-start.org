** Current shape

- `tools/memory.ts::warmMemoryLane()` — sync void wrapper; under the
  hood now async (FEAT-780). Currently called from
  `MemoryStatusController.start()` after first peek shows `unavailable`.
- Daemon `open` opens the repo cache (FTS table + vector index handles)
  but does NOT load the bge-m3 model. Model load deferred to first
  `embed_query` / `embed_batch` call (`pi_knowledge_worker::embedder::ensure_loaded`).
- Cold-embed cost on 2727 files: ~280s wall — bge-m3 model load
  (~5-10s GPU/CPU) + first batch indexing.

** Why eager warm wins post-FEAT-780

Pre-FEAT-780 we couldn't kick warm at session_start because the synchronous
NAPI froze the event loop and made the bootstrap feel hung. Now warm
is genuinely fire-and-forget: status widget renders progress, agent
accepts input, manual `memory.search` queues behind the warm cleanly.

** Sketch

- New daemon command `warm { repo_handle }`: calls existing `open` →
  triggers `ensure_loaded` on the embedder → returns immediately;
  warmCompleted event arrives via existing W4 push-subscribe channel
  (`warm_completed` already in protocol).
- Client: dispatch `warm` from `agent-session.ts` bootstrap right after
  cwd is known; wire result to `MemoryStatusController` via the
  existing `setHookStatus` surface.
- Optional: warm a single sentinel embed ("hello") to flush the first
  candle forward-pass cost too — adds ~5s but removes the spike from
  the user's first real query.

** Acceptance

- Session bootstrap shows "warming memory" affordance within 100ms.
- First user-triggered `memory.search` after warm completes returns in
  RPC latency (~10-100ms), not 280s.
- Repos with no `.spell/` cache fall back gracefully (skip warm).
- Warm failure does not block session start.
