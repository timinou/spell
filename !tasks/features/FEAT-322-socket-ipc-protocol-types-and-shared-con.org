Define the JSON-lines IPC protocol types shared between spell-server (socket server) and coding-agent (bridge client). These types define the contract for session registration, blocking event notification, and remote response routing over a Unix domain socket.

* Protocol Design

Messages are newline-delimited JSON objects. Each message has a =type= field discriminating the union.

** Client -> Server Messages

- =register= — session announces itself on connect (sessionId, pid, cwd, mode, startedAt, projectName)
- =deregister= — clean session shutdown
- =blocking_event= — session entered a blocking state (kind: plan_approval | ask | pending_action | hook_selector | hook_input). Payload varies by kind:
  - plan_approval: title, itemId, childItemIds, planContent (summary), waves
  - ask: questions array with id, question, options, recommended, multi
  - pending_action: actionType, description
  - hook_selector: title, options
  - hook_input: title, placeholder
- =heartbeat= — periodic keepalive with session status

** Server -> Client Messages

- =registered= — ack after successful registration
- =event_response= — response to a blocking_event (eventId, response payload matching the event kind)
- =event_cancelled= — server cannot route the response (no Telegram user responded, timeout)

** Design Constraints

- Protocol types live in =packages/spell-server/src/socket/types.ts= — coding-agent imports them via relative path or re-export. No circular package dependency.
- Message IDs use the existing Snowflake generator for correlation.
- Events use a =eventId= for request-response correlation.
- The =blocking_event= payload for plan_approval mirrors =ExitPlanModeDetails= from coding-agent — reuse the shape, don't duplicate the type. Reference the fields by name in the protocol type.
- All messages include a =timestamp= field (epoch ms).
