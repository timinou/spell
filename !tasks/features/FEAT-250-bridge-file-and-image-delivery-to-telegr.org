* Scope
Modify the Telegram bridge's =ResponseStreamer= to intercept tool results containing file/image data and deliver them to the user via Telegram Bot API. Two delivery paths:

1. *Explicit*: =send_file= tool results -> =replyWithDocument()= / =replyWithPhoto()=
2. *Auto*: =generate_image= tool results -> =replyWithPhoto()= for each generated image (configurable via KDL)

* Design
** ResponseStreamer changes (=rpc-to-telegram.ts=)
In =handleEvent()=, the =tool_execution_end= case currently only updates status text. Add delivery logic:

#+begin_src typescript
case "tool_execution_end": {
  // Explicit file delivery from send_file
  if (!event.isError && event.toolName === "send_file") {
    await this.#deliverFile(event.result?.details);
  }
  // Auto-send generated images
  if (!event.isError && event.toolName === "generate_image" && this.#autoSendImages) {
    await this.#deliverGeneratedImages(event.result?.details);
  }
  // Existing status update
  const state = event.isError ? "Failed" : "Done";
  await this.#setToolStatus(`${state}: ${event.toolName}`);
  return;
}
#+end_src

** =deliverFile= method
- Extract =delivery= from =result.details=
- Validate =absolutePath= exists and is readable
- Determine whether to use =replyWithDocument= or =replyWithPhoto= based on =delivery.type=
- Read file from disk using =Bun.file()= / =fs.readFile()=
- Create grammy =InputFile(buffer, fileName)=
- Call =ctx.replyWithDocument()= or =ctx.replyWithPhoto()= with optional caption
- Catch errors and log warning (don't break the response flow)

** =deliverGeneratedImages= method
- Extract =imagePaths: string[]= from =result.details=
- For each path, read the image file
- Send via =ctx.replyWithPhoto(new InputFile(buffer, basename))=
- On error, log warning and skip individual images

** Config: =autoSendImages=
- Add =autoSendImages: boolean= (default =true=) to =TelegramChannelConfig=
- Parse =auto-send-images= boolean in =channels-parser.ts=
- Thread through =CommandContext= -> =createMessageHandler= -> =ResponseStreamer= constructor
- =ResponseStreamer= stores and checks =this.#autoSendImages= flag

** Type updates (=rpc/types.ts=)
Add =FileDelivery= interface to bridge types so the details shape is documented:
#+begin_src typescript
export interface FileDelivery {
  type: "document" | "photo";
  absolutePath: string;
  fileName: string;
  mimeType: string;

  fileSize: number;
}

* Edge Cases
- File deleted between tool execution and bridge delivery -> log warning, skip
- Telegram API rate limit / error -> log, don't crash response flow
- =generate_image= returns 0 images -> no-op (already handled by tool returning text-only result)
- Very large files approaching 50MB -> Telegram may reject; tool validates but Telegram upload can still fail
- Multiple images from one =generate_image= call -> send each as separate photo message

* Acceptance
- Agent calling =send_file= on a PDF results in the PDF appearing in the Telegram chat
- Agent calling =generate_image= results in the image appearing in the Telegram chat (when =auto-send-images= is true/default)
- Setting =auto-send-images false= in KDL suppresses auto-send of generated images
- File delivery errors are logged but don't break the text response flow
- =bun check:ts= passes
