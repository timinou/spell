* Narrative

Two tools let agents dynamically reshape the DAG at runtime:

*Handoff*: an agent says "I'm done, someone else continue from here." It writes a =HandoffRecord= to the blackboard, emits =swarm:handoff=, and calls =submit_result=. The scheduler creates a new =task://= node in the DAG with a dependency on the handoff source.

*Spawn successor*: an agent says "I need more work done in parallel or after me." It adds a new node to the live DAG without ending its own session. Unlike handoff, the spawner continues.

Both tools use =task://= URIs for the new nodes and =MutableDag.addNode()= for graph mutation. Both are only available in swarm execution mode.

* Design Decisions

1. =handoff= tool: params ={ targetAgent?, context, partialResult?, reason }=. Writes to blackboard. Emits event. Agent must call =submit_result= afterward.
2. =spawn_successor= tool: params ={ task, dependsOn?, agentType?, filesDeps?, metadata? }=. Adds node to DAG. Returns new node URI. Agent continues executing.
3. Default =dependsOn= for spawn_successor is =[currentAgentUri]= (successor waits for spawner).
4. Empty =dependsOn= (=[]=) means immediate start.
5. Both validate dependencies (exist in DAG, no cycle) before committing.
6. Both tools are =AgentTool= implementations injected into subagent tool sets when swarm mode is active.
