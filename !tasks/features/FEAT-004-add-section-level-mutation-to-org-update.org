* Scope
Add a ~section~ parameter to the org ~update~ command that targets a specific heading within an item's body. Uses Emacs org-element for robust heading navigation and manipulation.

** In-scope

* Implementation

** 1. Elisp: ~org-tasks-edit-section~ in ~packages/org/elisp/org-tasks.el~

New function using org-element APIs:

#+begin_src elisp
(defun org-tasks-edit-section (file custom-id section body mode)
  "Edit a section within item CUSTOM-ID in FILE.
SECTION is the heading title to match (case-sensitive, first match).
BODY is the new text. MODE is \"replace\" or \"append\".
Returns JSON with result."
  ...)
#+end_src

Algorithm using org-element:
1. ~org-find-property~ to locate item by CUSTOM_ID
2. Navigate into item subtree
3. Use ~org-element-map~ on the subtree to find child headline where ~:raw-value~ matches SECTION
4. Compute section body region: from after the section heading's property drawer (or heading end) to ~:contents-end~ of the section element (this naturally handles nested sub-headings as part of the section)
5. Replace or append within that region
6. ~save-buffer~ and return JSON result

Key org-element properties to use:
- ~:raw-value~ — heading title text (no TODO keyword, no tags)
- ~:contents-begin~ / ~:contents-end~ — byte range of heading contents
- ~:begin~ / ~:end~ — byte range of entire element including heading line
- ~org-element-map subtree 'headline~ — iterate child headings

For the section body region specifically:
- Section body starts after the heading line (and property drawer if present)
- Section body ends at ~:end~ of the headline element (includes all children)
- Use ~org-end-of-meta-data~ after positioning at the section heading to skip past any property drawer

* Edge Cases
- Heading matching: case-sensitive, exact match on ~:raw-value~ (trimmed)
- First-match semantics for duplicate heading titles
- Emacs not available: ~getOrgClient()~ throws — TS catches and returns error message directing user to ensure Emacs is available
- Section heading with tags: ~** Context :planning:~ — match on ~:raw-value~ which is "Context" (tags are separate in org-element)
- File-level items with sections: same logic — ~org-find-property~ finds the CUSTOM_ID, section search within that subtree
