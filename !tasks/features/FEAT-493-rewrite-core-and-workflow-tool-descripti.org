* Implementation
1. Rewrite every file above into the canonical declaration-of-being shape from `specs/prompt-declaration-of-being.md`:
   - one-line capability opening
   - tagged sections only
   - terse voice
   - no extra explanatory prose between the opening line and the first tag
2. Preserve factual runtime behavior. These are documentation rewrites, not semantic tool changes.
3. Replace stale source-code guidance with the current tool hierarchy:
   - `code` first for source-file reading/orientation/structural edits when tree-sitter is available
   - `lsp` for semantic questions
   - `ast_grep`/`ast_edit` for structural code search and codemods
   - `grep` for plain text/regex only
   - `read` as fallback for non-code files, URLs, images, PDFs, and directories
4. Remove duplicated enforcement where a single canonical reminder is enough. Specific hot spots:
   - `bash.md` currently reads like an enforcement wall; rewrite it as a capability with a concise fallback-role explanation and one compact critical section.
   - `read.md` and `grep.md` must stop duplicating bash restrictions and must describe their own boundaries clearly.
   - `task.md` and `todo-write.md` must be compressed without losing real semantics around auto-roster, blockers, gates, and verification protocol.
   - `write.md` and `fetch.md` must lead with what they are for before restrictions.
5. Keep syntax-heavy examples where they materially reduce failure risk (`ast-*`, `task`, `todo_write`, `exit_plan_mode`). Delete filler examples that merely restate obvious behavior.
6. Update any examples that still imply old-tool workflows, especially examples that steer source-code reading toward `read` or shell search when `code`, `lsp`, or `ast_grep` should be first.

* Edge Cases
- Do not erase important warning content for `task`, `todo_write`, or `exit_plan_mode`; compress repetition, not safety.
- Preserve template branches such as `autoRosterEnabled` and any conditional text in these prompt files.
- Avoid “terse” becoming ambiguous. The model still needs enough operational detail to use each tool correctly.
