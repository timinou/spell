* Initial Message

Look at the rust crates in this repo. What would a first-party integration with Clojure look like? Take your time to deeply provide Clojure's strengths and philosophy to the code tool

* Scope
In scope: add native parser and language-registry foundations required for first-party Clojure and EDN support in Spell's code tooling. This item covers `pi-code-engine` grammar generation/profile registration, `pi-natives` ast-grep language registration, and minimal TypeScript extension discovery fallback for semantic path detection. It establishes Clojure code extensions `.clj`, `.cljs`, `.cljc`, `.bb` and a separate EDN language identity for `.edn`.

Out of scope: Clojure namespace graph extraction, deps.edn/project.clj source-root discovery, code-tool UX hints, runtime/nREPL integration, and clj-kondo/clojure-lsp enrichment. Those are handled by dependent items. EDN graph support is explicitly out of scope; EDN is data, not code.

Rationale: current repo already has partial Clojure surface area in syntax highlighting and LSP detection, but native semantic support is missing from `pi-code-engine`, `pi-code-graph`, and `pi-natives` ast-grep. The foundation must be landed first so downstream code can query `code languages` and receive stable `clojure`/`edn` capabilities.

* Existing Patterns
- `crates/pi-code-engine/src/language/profile.rs`: `LanguageProfile` drives outline/read/navigate/resolve/edit/graph via `id`, `extensions`, `capabilities`, `declarations`, `imports`, `exports`, `references`, `separators`, `embedded_regions`, `procedures`, generated grammar rules, and `ts_language`.
- `crates/pi-code-engine/src/language/mod.rs`: `LanguageRegistry::with_builtins()` registers built-in profiles. Follow existing profile constructors and keep registration immutable after construction.
- `crates/pi-code-engine/build.rs`: grammar metadata generation pattern. Add `tree-sitter-clojure` to the grammar list so `generated::clojure::grammar()` is produced.
- `crates/pi-natives/src/language/parsers.rs`: parser factory pattern using `tree_sitter_LANG::LANGUAGE.into()`.
- `crates/pi-natives/src/language/mod.rs`: `impl_lang!` / `impl_lang_expando!`, `SupportLang`, `canonical_name()`, dispatch macro, and extension mapping for ast-grep support.
- `packages/coding-agent/src/tools/code-supported-files.ts`: fallback semantic extensions and `describeCodeToolSemanticFiles()` when native language discovery is unavailable.
- Repo rule: use Rust crate dependencies and generated metadata consistently; do not create shims or legacy aliases.

* Edge Cases
- Tree-sitter Clojure grammar may expose list forms without stable named fields. If so, profile extraction must be extended generically and tested against real parse trees, not guessed.
- `.cljc` reader conditionals are platform-dependent. Foundation only parses forms; semantic graph item decides platform-specific resolution.
- `.edn` must not be reported as graph-capable. EDN data lacks namespaces/vars and graph support would produce plausible but false code semantics.
- Ast-grep metavars must not collide with valid Clojure symbol syntax. Test `$foo`, symbols containing `?`, `!`, `*`, `-`, `/`.
- Native language registry must stay immutable and duplicate extension conflicts must fail clearly.
