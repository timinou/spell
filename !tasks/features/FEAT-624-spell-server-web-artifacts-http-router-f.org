* Intention & Purpose
Serve session artifacts over HTTP with two access modes: (1) bearer-auth direct fetch for headered XHR, (2) short-lived HMAC-signed URLs for embed contexts (PDF iframes, image src, video). Add a per-session fs.watch that surfaces newly-written artifact files as runtime events for FEAT-WEB-WS to broadcast. Subscribers may filter by file extension.

* Context & Narrative
Artifacts on disk follow ~<sessionRoot>/<agent>/<toolType>/<n>.<ext>~ with ~artifact://<sessionId>/<agent>/<tool>/<file>~ URIs. The web layer needs to translate ~sessionId~ + relative path back to a real file, content-type it, send with ~Content-Disposition: inline~. For ~<iframe src=>~ embeds, browsers cannot inject ~Authorization~ headers, so we mint a signed URL: ~/web/artifacts/<sessionId>/<agent>/<tool>/<file>?sig=<hmac>&exp=<unix>~. The HMAC key is derived from ~webhookSecret~ if present, otherwise from a deterministic value derived from ~web.tokens~ (server-only, never sent to client).

The fs watcher is the canonical artifact-creation event source: hook on ~Bun.file().writer()~ is awkward and ~ArtifactManager.saveArtifact~ is invoked from many sites; watching the directory is robust and tool-call-agnostic.

14. Watcher: ~stop()~ removes all watchers; subsequent file writes do not emit.

* Edge Cases
- Concurrent writes from two tools → fs.watch fires per file; ring debounce protects.
- Symlink in artifacts dir → router refuses (lstat then resolve check).
- Very large file (>1 GiB) → stream; no buffer; no Content-Length if size unknown (Bun.file gives size synchronously when known).
- ~ext~ subscription with ~"*"~ → all extensions match (documented helper behavior).
- ~ext~ entries case-mixed (~.PDF~ vs ~.pdf~) → normalize lowercased.
- Signed URL ~exp~ overflow (e.g. year 2038) → store as ~Number~; document Y2038 caveat for 32-bit systems (none in Bun targets).
