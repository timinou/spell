* Context

PLAN-173 introduced a typed =EventBus<TEventMap>= and a =SwarmEventMap= interface, but the implementation left two competing definitions and inconsistent typing at integration boundaries.

Current state:
- =utils/typed-event-map.ts= defines =SwarmEventMap= with 9 channels (canonical, complete)
- =swarm/types.ts= defines =SwarmEventMap= with 2 channels (=swarm:artifact=, =swarm:handoff= only)
- =blackboard.ts= imports from =swarm/types.ts= (the subset)
- =executor.ts= line 1086 uses an unsafe cast: =as EventBusType<SwarmEventMap>=
- =sdk.ts:676= and =loader.ts:300= instantiate =new EventBus()= without type argument

** Design Decisions

1. Delete =SwarmEventMap= from =swarm/types.ts=. The canonical definition lives in =utils/typed-event-map.ts=.
2. Update =blackboard.ts= to import =SwarmEventMap= from =../utils/typed-event-map=.
3. Remove the =as EventBusType<SwarmEventMap>= cast in =executor.ts= line 1086. The swarm tools receive the bus through =swarmContext=; the cast is unnecessary because the handoff tool's context already accepts an =EventBus<SwarmEventMap>=.
4. The shared session bus in =sdk.ts= stays =EventBus()= (untyped). Reason: it carries both swarm events and legacy events (=todo:change=, =bridge:outbound=, fluid events). Typing it with =SwarmEventMap= would restrict channels via the =EventChannel= conditional type and break existing callers. Add a JSDoc comment documenting this decision.
5. =loader.ts= stays untyped since extensions have their own event contracts.
