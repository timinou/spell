* Initial Message

Goal: simple frontend to spell server. a client can connect with a secret token to a fast websocket that can let you connect with the running sessions by that user on that instance (through spell autodiscovery, consolidate the feature by looking at existing usage of similar features).

On the frontend, you can start new plan sessions, you can request a url, etc. that lets you use both xterm.js and, for example, see the pdf generated from a typst requested by a task whose goal was to generate a report.

easy way to setup templates from the frontend, wiht a linear-like command bar. Template 'document', you run it, you get a nice card in your session list, and then it tells you when it has the artifact ready.

* Intention & Purpose
Build the Linear-style command bar (~cmdk~), the persistent session list in the sidebar, and the "template-as-card" UX. Running a template (e.g. ~document {topic: "memory"}~) yields a card that immediately appears in the list as ~status: spawning~ → ~running~ → ~ready~ when the watched-extension artifact arrives → ~done~ when the agent emits ~agent_end~.

* Context & Narrative
Templates are the entry point for non-interactive work. The user types ⌘K, picks ~document~, fills params with structured inputs, submits. Frontend issues ~POST /web/api/templates/:name/run~ which returns ~{ sessionId }~. The card subscribes to ~events~ and ~artifacts~ channels (with ext filter from the template's ~artifactWatch.ext~), updates state from incoming events, and surfaces the ready artifact as an inline preview on the card.

* Scope
In-scope:
- ~packages/spell-server/web/src/sidebar/SessionList.tsx~ — ordered list (spawned first by ~startedAt~ desc, then external). Each row = ~SessionCard~.
- ~packages/spell-server/web/src/sidebar/SessionCard.tsx~ — shows ~templateName~ or ~projectName~, ~ownedBy~ chip, status dot, latest artifact thumb (PDF first-page render via PDF.js or icon for non-image), one-line tail of last assistant text or last event_log entry.
- ~packages/spell-server/web/src/cmd/CommandBar.tsx~ — ~cmdk~ palette, opens with ~⌘K~/~Ctrl+K~. Items: list templates + raw "New session", session-targeted commands (jump to session, kill).
- ~packages/spell-server/web/src/cmd/TemplateRunner.tsx~ — modal-on-template-pick that renders param inputs based on ~ManifestTemplateParam[]~. ~string~ → text, ~number~ → number, ~boolean~ → switch, arrays → repeatable. Submit → ~POST /web/api/templates/:name/run~.
- ~packages/spell-server/web/src/state/sessions.ts~ — store using ~zustand~ (small, no boilerplate; pick this single dep). Subscribes to global WS messages ~session_added~/~_removed~/~_updated~. Per-session derived state (~status~, ~artifactReady?~, ~lastText?~).
- Status FSM: ~spawning~ (post-run, no rpc_event yet) → ~running~ (first ~agent_start~) → ~done~ (~agent_end~) → ~ready~ if ~artifact_created~ matched watch ext (overlay badge). Sticky terminal states: ~done~, ~error~.
- API client: ~packages/spell-server/web/src/api/client.ts~ — typed wrappers for all ~/web/api/*~ routes using ~fetch~ + bearer.

* Edge Cases
- Backend ~session_updated~ for fields the frontend doesn't render → ignored without warning.
- Spawn HTTP fails (e.g., 4xx unknown_template) → toast; no card created.
- Template with no params → modal still opens with a "Run" button (allows last-look prompt preview).
- ~artifact_created~ for an unsubscribed session (e.g. external) → ignored; no toast spam.
- WS reconnect → store is reset and re-listed; cards keep their per-session derived state via ~sessionId~ keys merging.
- Card preview for PDF artifact: first-page thumb via PDF.js worker; if PDF.js fails, fall back to a generic doc icon.
