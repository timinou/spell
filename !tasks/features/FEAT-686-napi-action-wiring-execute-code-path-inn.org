* Intention & Purpose
Wire the dead =command= and =actions= fields in =CodePathOptions= so
=executeCodePath({command:"edit", actions:[...]})= actually dispatches mutations
through the new =MutationResolver= traits delivered in PROJ-073/074/075.

* Context & Narrative
Today =execute_code_path_inner= ignores =opts.command= and =opts.actions=. With kernel
mutation surface ready, dispatch becomes:
- =command: "get"= (default) → query path (current behaviour)
- =command: "edit"= + =actions= → resolver-specific apply()
- =command: "manage"= + =manage= → existing manage commands — preserved

* Edge Cases
- Mixed target types in actions array — current scope: each action resolves its own target
- Cancellation mid-sequence — actions completed remain; pending actions skip with =CANCELLED=
- Idempotent flag: per-action =ActionParams.idempotent= takes precedence; batch-level
  flag could be a FUP
