* Scope
- In scope: make HTML a first-class `pi-code-engine` language with outline/read/resolve/navigate/edit-target semantics that feel as native as Markdown sections or Elixir modules, while keeping the substrate reusable by HEEx hosts.
- In scope: define how HTML symbols are named and resolved: semantic elements, component-like custom elements, stable anchors (`id`, named slots/landmarks where appropriate), and embedded `<style>` regions.
- In scope: expose host/guest region metadata so HEEx can later reuse HTML structural semantics while supplying its own expression/template rules.
- Out of scope: JavaScript semantics inside `<script>`, browser execution semantics, or framework-specific virtual-DOM abstractions.

* Existing Patterns
- `crates/pi-code-engine/src/language/mod.rs`
  - built-in profile registration pattern; HTML should join built-ins instead of piggybacking on text fallback.
- `crates/pi-code-engine/src/outline.rs`
  - section/class-like recursion in Markdown/Org is the closest existing precedent for nested DOM structure.
- `crates/pi-code-engine/src/resolve.rs`
  - dotted member resolution and ambiguity errors already exist; HTML naming/disambiguation should reuse this contract.
- `crates/pi-code-engine/src/navigate.rs`
  - parent/children/siblings/defun/reference navigation needs meaningful markup targets rather than raw nodes.
- `crates/pi-code-engine/src/line_target.rs`
  - line-based edits must respect owned node ranges; HTML closing tags/shared boundaries need explicit handling.
- `crates/pi-code-graph/src/language/elixir.rs`
  - current HEEx graph extractor is minimal; this item replaces one-off structural assumptions with a reusable HTML host substrate.

* Edge Cases
- Repeated anonymous siblings must either receive deterministic ordinal disambiguators or remain intentionally unresolvable; silent best-effort resolution is forbidden.
- Void elements and self-closing elements need different owned-range semantics from paired tags.
- Inline `style` attributes are not equivalent to `<style>` blocks; represent them distinctly so later CSS graph logic can reason about confidence.
- Malformed HTML recovery must degrade gracefully and preserve truthful navigation/edit warnings.
- Templating delimiters inside attribute values or text nodes must not corrupt host byte ranges for surrounding HTML nodes.

* Acceptance Criteria
- `.html` files become semantic-capable in `pi-code-engine` with meaningful outline/read/resolve/navigate/edit-target behavior.
- HTML symbol naming is deterministic, conservative, and documented well enough for HEEx reuse.
- Embedded `<style>` regions expose stable host/guest boundaries for downstream CSS analysis.
- The HTML fixture suite covers all workflows and required scenarios above, including malformed and templated inputs.
