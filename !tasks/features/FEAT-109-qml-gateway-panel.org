## Implementation
1. Create `packages/coding-agent/src/modes/qml/panels/GatewayPanel.qml`:
   - ListView model populated via bridge messages
   - Each delegate: alias label, target label, status badge, action buttons
   - Refresh button sends `gateway_list` message via bridge
   - Add button opens inline form (alias + target fields)
   - Remove button sends `gateway_deregister` message
   - Open button calls Qt.openUrlExternally(aliasUrl)
2. Register panel in shell.qml panel registry
3. In QML mode (qml-mode.ts): handle gateway_list/gateway_register/gateway_deregister bridge events, delegate to GatewayClient, send results back to QML
4. Follow existing ServicesPanel.qml pattern for layout and styling

## Edge Cases
- Gateway daemon not running: panel shows "Gateway not running" message with "Start" button
- Empty service list: show placeholder message
- Service status changes while panel is open: periodic refresh or event-driven update
- Long alias/target URLs: truncate with ellipsis, tooltip on hover
