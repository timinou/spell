* Scope
Extend the =ResponseStreamer= in =rpc-to-telegram.ts= to optionally send the agent's final text response as a voice message via Telegram's =sendVoice=, in addition to (or instead of) the text reply.

* Design

** Reply Mode Resolution
Resolve the effective reply mode for the current message. Inputs:
1. Global =voice.replyMode= from config (default: ="mirror"=)
2. Per-user =voice.replyMode= override from config
3. Per-session =/voice= toggle override (stored in =ChatSession=)
4. Whether the incoming message was a voice/audio/video_note (for "mirror" mode)

Resolution order: session toggle > per-user config > global config.

#+begin_src typescript
type VoiceReplyDecision = "voice" | "text";

function resolveVoiceReply(opts: {
  globalMode: VoiceReplyMode;
  userMode?: VoiceReplyMode;
  sessionOverride?: VoiceReplyMode;
  incomingWasVoice: boolean;
}): VoiceReplyDecision;
#+end_src

** Integration into ResponseStreamer

The =ResponseStreamer= needs two new inputs:
1. =ttsProvider: TtsProvider | null= -- null when TTS not configured
2. =voiceReplyDecision: VoiceReplyDecision= -- resolved before streamer creation

In =#finalize()=:
1. If =voiceReplyDecision === "text"= or =ttsProvider === null=: current behavior (text only)
2. If =voiceReplyDecision === "voice"=:
   a. Synthesize the final text via =ttsProvider.synthesize(text, { voice })=
   b. Send voice message: =ctx.replyWithVoice(new InputFile(audioBuffer, "voice.ogg"))=
   c. Still send the text reply as well (voice + text, so user has searchable text)
   d. If TTS fails: log error, fall back to text-only reply (never lose the response)

** Voice ID Resolution
Per-user =ttsVoice= overrides the global =tts.voice=. The =TtsProvider.synthesize()= accepts an optional =voice= override.

** Draft Header for Voice Input
When the incoming message was voice, the draft should start with a header line like:
#+begin_example
[Voice] <transcription text>

<agent response streaming...>
#+end_example

This is set by the caller (in =bot.ts=) by passing a =draftHeader= string to =ResponseStreamer=.

* Edge Cases
- TTS synthesis fails: fall back to text-only, log error
- Empty agent response: skip TTS (nothing to synthesize)
- Very long response: truncate to TTS provider's limit before synthesis, still send full text
- =ttsProvider= is null (not configured): always text reply, no error
