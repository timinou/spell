* Problem
The code tool's =edit=, =undo=, and =redo= commands modify an in-memory buffer but do not persist to disk. The agent must issue a separate =code save { file }= call. This wastes a tool call, and if the agent forgets, edits are lost on session end.

* Design Decisions
1. After successful =edit=, =undo=, or =redo= in =CodeTool.execute()=, automatically call =executeCodeBuffer({ command: "save", file })=.
2. If auto-save fails, return the ENTIRE tool call as an error using =createCodeToolError()=. Message: ="Edit succeeded but save to disk failed: {error}"=. The in-memory edit persists but the agent sees an error.
3. If auto-save succeeds, the original edit/undo/redo result is returned unchanged. Save is transparent.
4. Update the system prompt (=code.md=) to remove "Edits stay in-memory" and document auto-save behavior.
5. The =save= command remains available for manual use (no-op if buffer is clean).

* Implementation

Sequencing note: implementation must exist before tests because tests mock =executeCodeBuffer= — they need to mock the additional save call that auto-save introduces. The existing test pattern (=spyOn= on the native module) works directly. Test-first is not practical here because the auto-save call order depends on the implementation shape.

** Modify =packages/coding-agent/src/tools/code.ts=

In the =execute()= method, after the =executeCodeBuffer(options)= call succeeds (=!result.error=) and the command is a mutating command, add the auto-save:

#+begin_src typescript
const MUTATING_COMMANDS = new Set(["edit", "undo", "redo"]);

// After: const result = executeCodeBuffer(options);
// After: if (result.error) { ... return error ... }

if (MUTATING_COMMANDS.has(command) && options.file) {
    const saveResult = executeCodeBuffer({ command: "save", file: options.file });
    if (saveResult.error) {
        const details = createCodeToolError({
            command,
            file: options.file,
            cwd: sessionCwd,
            message: `Edit succeeded but save to disk failed: ${extractCodeToolErrorMessage(saveResult.output)}`,
        });
        return toolResult(details).text(formatCodeToolContent(details)).done();
    }
}

// Then: const details = normalizeCodeBufferSuccess(...);

* Edge Cases
- =undo= and =redo= that have no effect (empty history): These still succeed in the native engine (no error), so auto-save fires. This is harmless — the buffer content hasn't changed, so =fs::write= writes the same content.
- File with no disk path: All code tool operations require a =file= parameter, so =options.file= is always set for mutating commands. The guard =&& options.file= handles the theoretical case.
- Mode guard: =enforceModeWrite= already runs BEFORE the execute call for =edit= and =save= commands. We need to ensure it also covers the auto-save path. Since =enforceModeWrite= runs on entry for =edit=, the auto-save call (which is just =save= to the same file) is already authorized.
