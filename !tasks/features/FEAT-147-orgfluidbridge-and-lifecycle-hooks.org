* Implementation

** OrgFluidBridge class
:PROPERTIES:
:CUSTOM_ID: FEAT-017::bridge-class
:EFFORT: 2h
:END:
- File: =packages/coding-agent/src/orchestrators/fluid/org-fluid-bridge.ts= (new)
- Constructor: receives EventBus, org MCP client/tool access, plan metadata (PLAN CUSTOM_ID, mode info)
- Subscribes to FluidOrchestrator events on the =fluid:event= channel
- On =agent_state_change(running)=: call org update to transition item ITEM->DOING
- On =agent_state_change(completed)=: call org update to transition item DOING->DONE
- On =agent_state_change(failed)=: log warning, leave item in DOING state (coordinator handles recovery)
- Maps =agentId= to org CUSTOM_ID via =orgItemId= field on FluidAgentNode
- Idempotent: skips transition if item already in target state (handles re-runs)

** Post-execution lifecycle hooks
:PROPERTIES:
:CUSTOM_ID: FEAT-017::post-execution-hooks
:DEPENDS: FEAT-017::bridge-class
:EFFORT: 1.5h
:END:
- File: =packages/coding-agent/src/orchestrators/fluid/org-fluid-bridge.ts=
- On =execution_complete= event: run hook chain:
  1. Reconcile child org item states via =completePlanItem= from =org-plan.ts= (ITEM/ACTIVE->DONE, BLOCKED stays)
  2. Set audit state on session: =auto= for ultraplan, =suggest= for regular plan (extracted from current =#approvePlan=)
  3. Write design history entry if plan has design flavor (extracted from current =#approvePlan=)
  4. Set plan reference path on session (=setPlanReferencePath=, =markPlanReferenceSent=)
  5. Transition PLAN item DOING->DONE only if ALL children are DONE
- Error handling: individual hook failures logged but don't block other hooks
- Returns summary: =PostExecutionResult= with success/failure counts, deferred items, audit state

* Edge Cases
- Race condition: two coordinators completing near-simultaneously :: safe because org writer has per-file =KeyedMutex= (in-process, same event loop)
- Coordinator completes but org update MCP call fails (Emacs down) :: bridge logs error, does NOT block =execution_complete=. Item stays in stale state; operator can reconcile manually.
- Plan with items already in DONE state (re-run scenario) :: bridge skips transitions for already-DONE items (idempotent)
- Audit state when audit depth exceeds max :: set =pending: false= (matches current =interactive-mode.ts:1188= behavior)
- Post-execution hook throws :: caught per-hook, other hooks still run. Error reported in =PostExecutionResult=.
