* Initial Message

how would you move all of spell's config to spell.kdl config? What would it look like? Could you import bits inside other bits? would it be better to have blocks per mode?

* Reference
Read =specs/kdl-config-migration.md= Sections 4.11 and 4.9, and the mode blocks in Section 2.1.

* Context
Two peripheral config consumers need updating: (1) =KeybindingsManager= loads from =keybindings.json= — switch to KDL, (2) Mode discovery supports YAML frontmatter — add KDL frontmatter support. Also: remove YAML fallback from task-policies loading and domain.json fallback from detection.

* Design Decisions
- =KeybindingsManager.create()= reads from user + project =spell.kdl= keybindings blocks
- =KeybindingsManager.#loadFromFile()= (JSON-specific) deleted
- Modes defined in =spell.kdl= =mode= blocks are merged with MODE.md-discovered modes
- MODE.md files can use =---kdl ... ---= frontmatter OR =--- YAML ---= frontmatter (both supported)
- =task-policies.ts=: remove Step 3 YAML fallback (=.spell/task-policies.yml=)
- =detection.ts=: remove =domain.json= fallback

* Edge Cases
- Keybindings: kebab-case KDL names (=toggle-plan=) must convert to camelCase (=togglePlan=) for =KeybindingsConfig=
- Keybindings: =KeybindingsManager.inMemory()= bypasses file loading — unchanged
- Modes: if same mode name appears in both spell.kdl and MODE.md, spell.kdl takes precedence
- Task policies: projects with only =.spell/task-policies.yml= (no KDL) will lose their policies. The =spell migrate= command (separate item) handles this.
- Domain: projects with only =.spell/domain.json= lose domain detection. =spell migrate= handles this.
