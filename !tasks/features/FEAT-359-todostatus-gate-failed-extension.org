* Goal
Add =gate_failed= as a new =TodoStatus= literal. Update all status-dependent logic: =StatusEnum=, =isPhaseComplete=, =normalizeInProgressTask=, =hasUnresolvedBlockers=, =formatSummary=, =formatTodoLine= (TUI), and the =todo-write.md= prompt.

Also extend =TodoDelegationResult= with a =gateFailures= field to carry structured gate failure information.

* Design Decisions
- =gate_failed= is a *terminal, blocking* status. It means: "subagent completed, but required gates were not satisfied."
- =isPhaseComplete=: =gate_failed= does NOT count as complete (same as =failed=).
- =normalizeInProgressTask=: =gate_failed= stops auto-promotion (same as =failed=). Add it alongside the =hasFailedTask= check.
- =hasUnresolvedBlockers=: =gate_failed= does NOT count as resolved — dependents stay blocked (blocker must be =completed= or =abandoned=).
- =formatSummary=: new =--- Gate Failures ---= section listing each =gate_failed= task and its =gateFailures= detail.
- TUI: =gate_failed= renders in ="warning"= color with =[gate failed]= suffix (distinct from ="error"= used by =failed=).
- =gate_failed= is system-only: only =finalizeTodoRef= (in a later item) will set it. The LLM agent cannot set it directly via =todo_write= ops. However, the =StatusEnum= TypeBox schema must include it so the =update= op accepts it (the task dispatcher calls =todo_write= internally). Alternative: we could skip adding it to StatusEnum and have the task dispatcher bypass the schema, but that's worse. Include it in StatusEnum.
- Prompt =todo-write.md=: add =gate_failed= to the status table with description "Delegated work completed but required verification gates were not satisfied".
