* Context

Tinymist is the production LSP server for Typst, implemented in Rust. It provides semantic highlighting, code actions, formatting, document links, document symbols, hover, go-to-definition, references, and diagnostics. Both =typst= (v0.14.2) and =tinymist= binaries are already installed on the system.

The LSP defaults in =packages/coding-agent/src/lsp/defaults.json= contain configs for 20+ language servers but no entry for tinymist. Adding it enables all LSP operations (diagnostics, hover, definition, references, code_actions, rename, symbols) on .typ files automatically.

* Implementation

** File: packages/coding-agent/src/lsp/defaults.json
Add tinymist entry. Place it alphabetically among existing entries. Follow the existing JSON format exactly.

#+begin_src json
"tinymist": {
    "command": "tinymist",
    "args": ["lsp"],
    "fileTypes": [".typ"],
    "rootMarkers": ["typst.toml"],
    "initOptions": {
        "formatterMode": "typstyle"
    }
}
#+end_src

** Design rationale
- =command=: ="tinymist"= — the binary is at =/usr/bin/tinymist=, already on PATH
- =args=: =["lsp"]= — tinymist requires the =lsp= subcommand to start in LSP mode
- =fileTypes=: =[".typ"]= — standard Typst file extension
- =rootMarkers=: =["typst.toml"]= — Typst's project configuration file (equivalent to =Cargo.toml= or =package.json=). Even projects without =typst.toml= will work since LSP falls back to directory detection.
- =initOptions.formatterMode=: ="typstyle"= — tinymist supports both =typstfmt= and =typstyle= formatters; =typstyle= is the more modern option
- No =settings= needed — tinymist defaults are sensible
- No special =capabilities= needed — tinymist advertises its own capabilities via LSP initialization
