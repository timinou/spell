* Initial Message

do a deep, critical review of the work just done, and identify any sources of lag or undue TUI renders. the TUI stil feels a bit slow.

* Goal

Stop calling renderer.renderCall/renderResult at 12.5Hz to animate one character.

* Diagnosis

~spinnerFrame~ has exactly one consumer: ~formatStatusIcon()~, which returns a single character. So the only output difference per tick is one glyph. Current architecture re-runs the full renderer body (formatArgsInline, renderJsonTreeLines, replaceTabs, status-line construction) at 12.5Hz to swap that glyph.

* Approach: zero-width sentinel + TUI post-process

1. ~SPINNER_MARKER = "\x1b_pi:spin\x07"~ (APC, zero-width) in tui.ts alongside CURSOR_MARKER
2. ~formatStatusIcon~ for running status returns SPINNER_MARKER. spinnerFrame param ignored.
3. ~TUI~ accepts spinnerFrames; lazy-subscribes to spinnerClock on first marker observed.
4. ~TUI.#doRender~ post-process: replaceAll SPINNER_MARKER → currentGlyph after composite.
5. ~ToolExecutionComponent.#updateSpinnerAnimation~ → no-op (drop tick subscription + #updateDisplay).
