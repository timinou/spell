* Edge Cases
- HTML class attributes containing multiple tokens, duplicated tokens, or template/runtime holes must never cause cross-token widening.
- CSS selector lists such as `.btn, .link` must refuse token rename unless one exact token can be isolated without altering sibling selectors.
- Custom-property rename must not mutate lookalike identifiers inside comments, strings, or unrelated plain properties.
- Dead-style removal must account for existing style edges and confidence thresholds; absence of a proven consumer is not enough if the graph is stale or the host language is unsupported.
- Success-path edits must preserve surrounding formatting/ownership boundaries; a safe refusal is preferable to a plausibly-correct partial rewrite.

- HTML/CSS profiles register explicit proof-backed edit procedures instead of leaving `procedures` empty.
- Native edit execution can perform provable exact class/id/custom-property renames and proof-backed dead-style removal, while still refusing ambiguous cases.
- Generic `replace-body` is proven to work for a single resolved CSS rule symbol.
- Focused Rust/native tests lock both success and refusal paths for all workflows above.
- FEAT-563 can consume the proof metadata without requiring further Rust-side contract redesign.
