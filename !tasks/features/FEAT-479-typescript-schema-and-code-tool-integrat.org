* Initial Message

How would you make the edit experience with the code tool so ergonomic it's even more ergonomic than giving line diffs in the language?

* Context

The TypeScript layer needs to expose the new edit capabilities to the agent.
This involves schema changes (new fields in the tool definition), mapping
those fields to NAPI options, and updating the NAPI types.

* Design Decisions

1. New schema fields: =symbol=, =edits= (array), =patches= (array of ={find, replace}=)
2. The =target= object with =node_type= is kept in the schema but =node_type= is removed from the prompt examples and deprecated
3. =edits= array: each entry has the same shape as a single edit call (symbol, operation, content, patches, etc.)
4. The =content= field is reused for replace-body (body text), wrap (template), rename (new name), and replace (full content) — discriminated by =operation=
5. Remove =node_type= from =target= schema (breaking change — node_type was optional and agents should now use symbol instead)

Note: =symbol= serves double duty — for edit commands it targets a declaration;
for graph commands (context, impact, flow) it identifies a graph symbol. This is
fine because the command discriminates the usage.

* Execute Method Changes

In =CodeTool.execute()=, the options mapping must handle new fields:

#+begin_src typescript
// New fields for edit
if (params.symbol) options.symbol = params.symbol;
if (params.patches) options.patches = params.patches;  // pass through as JSON
if (params.edits) options.edits = params.edits;  // pass through as JSON

// Remove old target.node_type mapping
// Old: if (params.target?.node_type) options.node_type = params.target.node_type;
// Keep: if (params.target?.line) options.line = params.target.line;
#+end_src

The =edits= and =patches= arrays need to be serialized to the NAPI value format.
Since =executeCodeBuffer= accepts a =Value= (serde_json), the TypeScript objects
are automatically converted by the NAPI binding.
