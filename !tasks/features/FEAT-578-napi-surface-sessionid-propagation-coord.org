* Initial Message

show me how the pi code engine can be used to keep track of which session edited what file across code edit instances. some sort of auto-find and socket communication for editing processes. I don't want any more errors happening because another agent edited something. maybe it's time for loro crdt? think about this also within the scope of making undo/redo smarter and only undoing/redoing the actions of the agents/sessions but also knowing what the other agents/sessions modified.

Scenarios:

1. `session_id_required_on_mutating_edit`
   `executeCodeBuffer({ command: "edit", file, operations: [...] })` without `sessionId` returns `{ error: true, output: { code: "MISSING_SESSION_ID", ... } }`.

2. `session_id_accepted_on_mutating_edit`
   Same call with `sessionId: "test-s1"` succeeds; output carries `version` matching the new revision number.

3. `read_only_commands_do_not_require_session_id`
   `outline`, `read`, `navigate`, `symbols` work without `sessionId`.

4. `peer_conflict_surfaces_structured_error`
   Simulate a peer-commit via broker (use a broker test harness or a stubbed `CoordClient`). Mutation returns `{ error: true, output: { code: "PEER_CONFLICT", peerConflict: { sessionId: "peer", codePath: "...", peerRevision: 43, peerCommitTs: <n> } } }`.

5. `coord_status_returns_broker_state`
   `executeCodeBuffer({ command: "coord_status" })` → `{ brokerUp: boolean, peers: [...], socketPath: "..." }`. When broker up, contains at least the caller's own session entry.

6. `coord_peer_activity_returns_recent_edits_for_file`
   After a peer commit on file X, `executeCodeBuffer({ command: "coord_peer_activity", file: X })` returns `{ file, edits: [{ sessionId, revision, codePaths, ts }] }` with at least 1 entry.

7. `coord_journal_tail_returns_last_n_entries`
   After N commits, `executeCodeBuffer({ command: "coord_journal_tail", file: X, limit: 3 })` returns the most recent 3 entries in reverse chronological order.
