* Intention & Purpose
=ARTIFACT_THRESHOLD = 256 KiB= is hardcoded in =marshal.rs:10=. Content larger than this
is externalised to artifact URIs. Make it configurable via =CodePathOptions= so callers
can opt to inline larger content (e.g. when the model needs full context) or
externalise smaller (e.g. for streaming UX).

* Context & Narrative
Per audit (agent://35-Resolvers): =marshal.rs:10= defines threshold; applied in
=nodes_to_dtos=. No runtime override. Tools have no way to request "always inline"
or "always externalise".

* Scope
** In-scope
- Add =CodePathOptions.artifact_threshold: Option<u32>= (bytes) NAPI field
- Plumb through to =nodes_to_dtos=
- Default behaviour preserved (256 KiB) when option absent
- TS-side: =get= and =edit= and =manage= and =create= tool schemas accept optional
  =artifactThreshold=
- Tests
** Out-of-scope
- Per-resolver thresholds
- Auto-tuning based on model context budget

* Existing Patterns
- =crates/pi-natives/src/code_path/marshal.rs=
- =CodePathOptions= NAPI struct at =napi.rs:79-94=

* Tests
File: =crates/pi-natives/src/code_path/marshal_tests.rs= (extend)

Scenarios:
1. Default (no option) — content >256 KiB externalised, ≤ inlined
2. =artifactThreshold: 1024= — content >1 KiB externalised
3. =artifactThreshold: 0= — everything externalised
4. =artifactThreshold: u32::MAX= — nothing externalised (bounded by NAPI byte limits)
