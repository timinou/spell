* Scope

Add an =org delete= command that removes an org item file entirely. Currently the only way to "remove" an item is =org update state=CANCELLED=, which leaves the file on disk and causes validators to still traverse it via stale =[[id:...]]= links. A clean delete is simpler and avoids cascading validation issues from zombie items.

*In scope*:
- Add =org delete= command that deletes the org file for a given CUSTOM_ID
- Add the command to the tool schema, description, and execute switch
- Return ={ success: true, id, file, deleted: true }= on success
- Return NOT_FOUND error if item doesn't exist
- Safety: refuse to delete items in DOING or REVIEW state (active work)

*Out of scope*:
- Bulk delete
- Archive functionality (already exists as =org archive=)
- Cascading deletes (deleting a parent doesn't delete children)
- Undo/recycle bin

- =packages/org/src/tool.ts= — =cmdArchive()= finds items by state and lists them — similar pattern for locating item files
- =packages/org/src/tool.ts= — =cmdUpdate()= locates item file by scanning category directories — reuse for finding the file to delete
- File deletion: =node:fs/promises= =unlink()=
