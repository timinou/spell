* Intention & Purpose
Make long Anthropic reasoning visibly alive in the TUI. Increasing the watchdog helps, but users still need feedback during long silent gaps: when the provider has opened a thinking block and no new deltas arrive, Spell should show a local keepalive/status line rather than leaving the same generic ~Working…~ loader until success or failure.

* Context & Narrative
This item depends on the timeout configuration item because the status should align with the configured Anthropic timeout when available.

Current repo evidence:
- ~packages/coding-agent/src/modes/controllers/event-controller.ts~ owns interactive session event handling. On ~agent_start~ it calls ~ctx.ensureLoadingAnimation()~; on ~message_start~ it creates ~AssistantMessageComponent~ for assistant output; on ~message_update~ it updates streamed content and may derive working messages from tool-call intent or partial tool args; on ~message_end~ it finalizes the streaming component.
- ~packages/coding-agent/src/modes/interactive-mode.ts~ implements ~ensureLoadingAnimation()~, ~setWorkingMessage(message?: string)~, and ~applyPendingWorkingMessage()~. The default is currently ~Working… (esc to interrupt)~.
- ~packages/coding-agent/src/session/agent-session.ts~ forwards core agent events, including ~message_update~ with ~assistantMessageEvent.type === "thinking_delta"~ for thinking streams.
- ~packages/ai/src/providers/anthropic.ts~ emits ~thinking_start~, ~thinking_delta~, and ~thinking_end~ events for Anthropic thinking blocks.
- Existing TUI rendering rules require user-visible text to be sanitized/truncated via existing helpers when it can contain dynamic content. This status uses only generated text plus model/provider labels, so no raw file content is involved.

User-settled requirements:
- UX should be both a longer timeout and visible keepalive/status.
- Scope should focus on Anthropic thinking stalls, but implementation should not break text/tool streams.

Settled design decisions for this item:
1. Add a local TUI status timer; do not depend on provider heartbeat events because the failure mode is no provider events.
2. Track the last assistant stream event time in ~EventController~ and update the working loader every few seconds while an assistant message is streaming.
3. Prefer phase-specific labels: ~thinking~, ~response~, or ~tool call~ based on the latest assistant event type.
4. For Anthropic streams, include the configured timeout when available, e.g. ~Thinking for 62s; last token 14s ago; timeout 180s~. For non-Anthropic providers, use the same keepalive without promising a timeout unless a known timeout helper is available.
5. Stop and clear the timer on ~message_end~, ~agent_end~, abort/error finalization, and retry transitions so stale status cannot survive into the next turn.
6. Keep tool intent messages higher priority: if a tool call streams an explicit ~_i~ intent, do not overwrite it with generic keepalive until a later assistant stream starts.

* Edge Cases
- If the stream starts and fails before the first assistant message, do not start a stale keepalive timer.
- If an assistant message has thinking hidden by the user, still show generic keepalive because it does not reveal thinking content.
- If timeout is disabled, keepalive should say timeout disabled or omit timeout, not show ~0s timeout~.
- If a new user prompt begins immediately after a previous assistant ends, previous timer state must be cleared before the new turn.
- If retry starts after a stall, retry loader/status should own the UI and the keepalive timer must be stopped.
- If no model/provider is available on the context, use a provider-neutral message.

* Acceptance Criteria
- During a silent thinking gap, the terminal UI visibly changes from a static generic loader to a concise keepalive status.
- Keepalive status never includes raw thinking content.
- Timer stops after message end/agent end/retry cleanup; no stale status leaks across turns.
- Explicit tool intent remains higher priority than generic keepalive.
- Focused tests pass and TypeScript check passes for touched files.
