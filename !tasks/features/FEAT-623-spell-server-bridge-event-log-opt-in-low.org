* Intention & Purpose
Extend the existing JSONL session bridge protocol with one new client→server message type ~event_log~ that lets external interactive CLI sessions push *summary* progress lines (turn started, last assistant text, tool invoked, tool finished, plan approved) to the server. The server keeps the most recent N entries per session in the registry. Web clients then see a low-fi live feed of CLI sessions started outside the daemon — no full deltas, no PTY, no full agent stream. Emitting these events is opt-in (env var or config) on the CLI side so default privacy is preserved.

* Context & Narrative
Today the bridge carries blocking events (~plan_approval~, ~ask~, …) and heartbeats. Web "autodiscovery" needs more than a process card: humans expect to see what each external session is currently doing. We deliberately stop short of streaming full ~message_update~ deltas because (a) the bridge is JSONL on a Unix socket where chatty traffic regresses everything else and (b) external sessions are not attachable for prompt steering anyway. Summary lines are the right resolution.

* Edge Cases
- Burst of tool calls in a tight loop → ring buffer protects; emitter never blocks the agent loop (fire-and-forget on socket).
- Session disconnects (socket dropped) mid-turn → emitter swallows write errors; reconnect is the bridge client's existing concern.
- Privacy: assistant_text trimmed to 256 chars and only the LAST chunk per turn (not per delta) — gates leakage of full content.
- Event_log for a session that already has a blocking event pending → both coexist; web subscribers receive both streams independently.
- Concurrent producers (background tasks): same session may emit overlapping entries — entries are timestamped; consumer orders by ts asc.
