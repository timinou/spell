* Initial Message

the org get and search tools provide wrong ITEMs and not well ordered. PLease try the tool and tell me the querying improvements you'd make

* Problem
Queries can return 835+ items (after sub-heading fix) with no pagination.
The budget-based formatter caps LLM output at 80KB, but the backend still parses
all files. Adding limit/offset allows queries to short-circuit and enables
paginated exploration.

* Implementation

*** ITEM Add limit and offset to OrgQueryFilter
:PROPERTIES:
:EFFORT: 5m
:END:
In =packages/org/src/types.ts=, add to =OrgQueryFilter=:
#+begin_src typescript
/** Max items to return. */
limit?: number;
/** Skip first N items (applied after filter and sort). */
offset?: number;
#+end_src

*** ITEM Apply limit/offset after filter and sort in cmdQuery
:PROPERTIES:
:EFFORT: 10m
:END:
In =packages/org/src/tool.ts= =cmdQuery=, after filtering and sorting, apply:
#+begin_src typescript
const sliced = filtered.slice(filter.offset ?? 0, (filter.offset ?? 0) + (filter.limit ?? filtered.length));
return { items: sliced, total: filtered.length };
#+end_src
Note: =total= still reports the full count so the caller knows there are more.

*** ITEM Add limit/offset to tool schemas
:PROPERTIES:
:EFFORT: 5m
:END:
Add =limit= and =offset= parameters to both inner (=tool.ts=) and outer
(=packages/coding-agent/src/tools/org.ts=) schemas. Forward through execute dispatch.
