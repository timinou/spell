* Intention & Purpose
Make `clone(target:"file.ts::foo", content:"newName")` clone the `foo` declaration to a new symbol named `newName`. Currently `content` is silently ignored by the kernel; some other code path interprets it as a numeric line value, producing the misleading "line 3 is outside the target declaration span" error.

* Context & Narrative
`crates/pi-code-path/src/ast.rs::Action::Clone` doesn't have a `content` field. When TS sends `{kind:"clone", content:"newName"}`, serde silently drops `content`. Then `content` re-enters as a line number through coercion, leading to confusing error. Intended semantic: "duplicate the target declaration; if `content` given, rename the clone to that identifier". Matches `rename` action's API.
