* Intention & Purpose
Fix `insertBefore`/`insertAfter` actions which currently always reject with "missing field 'lines'". The TS-side action normalizer drops the `lines` field before sending to the kernel; the Rust Action enum requires it. Same defect affects positional anchors (`pos`, `end`) and patch (`diff`).

* Context & Narrative
`packages/coding-agent/src/tools/edit.ts::normalizeStructuralAction` (lines 105-118) copies a hand-listed subset of fields from the TS schema into the JSON sent to executeCodePath. The list misses `lines` (used by InsertBefore/InsertAfter/Append/Prepend/Splice replacement), `pos`/`end` (LINE#ID anchors), and `diff` (patch action). The kernel's `Action` enum in `crates/pi-code-path/src/ast.rs:390-395` declares `InsertBefore { lines: ActionContent }` and similar — when the JSON lacks the field, serde rejects with "missing field 'lines'".
