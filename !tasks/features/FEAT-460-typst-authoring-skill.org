*** Typst Language Reference (concise)
Cover these constructs with compact examples:
- *Modes*: markup (default), code (=#=), math (=$=)
- *Bindings*: =#let name = value=, =#let func(params) = body=
- *Imports*: =#import "path": *=, =#import "path": name1, name2=, =#import "@preview/pkg:version"=
- *Set rules*: =#set page(paper: "a4")=, =#set text(font: "Inter", size: 11pt)=
- *Show rules*: =#show heading: set text(fill: red)=, =#show heading.where(level: 1): it => text(...)[#it.body]=
- *Flow control*: =#if cond [content]=, =#for item in list [content]=, =#while cond [content]=
- *Content blocks*: =[inline content]=, =block(fill: color, inset: 12pt)[content]=
- *Functions*: =text()=, =grid()=, =table()=, =block()=, =box()=, =stack()=, =align()=, =pad()=, =place()=, =image()=, =line()=, =circle()=, =rect()=, =ellipse()=
- *Data access*: =dict.at("key", default: fallback)=, =array.map()=, =array.filter()=, =.join()=, =.flatten()=
- *Spacing*: =#v(12pt)=, =#h(6pt)=, =~= (non-breaking space), paragraph breaks via blank lines
- *Colors*: =rgb("#hex")=, =luma(percent)=, =color.lighten()=, =color.transparentize()=, =gradient.linear()=, =gradient.radial()=
- *Page setup*: =#set page(paper, margin, header, footer, fill, numbering)=
- *Document metadata*: =#set document(title, author)=

*** Component Design Patterns
Teach component authoring patterns drawn from the real codebase:
- Reusable components as =#let= functions accepting content or data
- Named optional parameters with defaults: =#let comp(required, optional: default) = ...=
- Nested grid/block composition for complex layouts
- Table patterns with header styling and alternating row fills
- Card/box patterns with fill, stroke, radius, inset
- SVG inline embedding via =image.decode(...)=

*** Brand Library Pattern
The pattern for brand-compliant documents:
1. Look for a brand library (=branding/*/lib.typ= or similar =lib.typ= aggregator)
2. Import it: =#import "../branding/brand-name/lib.typ": *=
3. Use named colors (=brand-primary=, =brand-dark=) instead of hex literals
4. Use brand components (section-header, stat-cell, callout-box, etc.)
5. Use brand typography (heading-font, body-font, font sizes)
6. Use brand layouts (report-page, cover-page)
7. NEVER use off-palette colors — if a color isn't in the brand library, add it there first

Example brand library structure:
#+begin_example
branding/spell-brand/
  lib.typ          — single import entrypoint
  colors.typ       — #let spell-purple = rgb("#7C3AED"), etc.
  typography.typ   — #let heading-font = ("Inter", ...)
  components.typ   — #let section-header(title) = ...
  layout.typ       — #let report-page(title) = { set page(...) ... }
#+end_example

*** Data-Driven Templates
Pattern for templates that accept external data:
#+begin_example
#let data = if sys.inputs.at("data", default: none) != none {
  yaml("data.yaml")  // or json("data.json")
} else {
  (key: "[Placeholder]", ...)
}
// Then use: data.at("key", default: "[Fallback]")
#+end_example

*** Document Type Recipes
Brief patterns for common document types:
- *Report/proposal*: A4, report-page layout, section-header + content + tables
- *Pitch deck/slides*: wide page (1280x720pt or 16:9), page-per-slide with =#page(fill: bg)[...]=, gradient orbs, stat-boxes
- *Academic/research*: numbered headings, bibliography, table of contents via =#outline()=

*** Compilation Workflow
#+begin_example
# Compile to PDF
typst compile input.typ output.pdf

# Compile with custom fonts directory
typst compile --font-path ./fonts input.typ output.pdf

# Compile with input data
typst compile --input data=data.yaml input.typ output.pdf
#+end_example
After compiling, use =send_file output.pdf= to show the user the result.

For iterative editing, compile after each significant change.

*** Quality Checklist
Before finalizing a Typst document:
1. All text uses =body-font= / =heading-font= variables (not hardcoded font names) when a brand library exists
2. All colors use named variables from the brand palette
3. Spacing is consistent (use =v()= and =h()= with consistent increments)
4. Tables have header styling and readable column widths
5. Document compiles without warnings
6. No orphaned pages or overflowing content
