* Edge Cases
- BLOCKER property with multiple space-separated IDs: =:BLOCKER: FEAT-001-xxx FEAT-002-yyy= -- already supported by org-depend parser
- BLOCKER referencing an item that doesn't exist yet: plan-mode creates items sequentially for deps, but IDs are auto-generated. The agent must create the blocker item first, get its CUSTOM_ID, then use it. This is inherent to the org system.
- Ultraplan parallel creation: items that are dependency targets must be created before dependent items. Items without cross-dependencies can be parallelized.
- Empty BLOCKER: items without dependencies should NOT have a BLOCKER property (don't set empty string)
- Plan-mode-approved execution: the agent reads the finalized plan and creates a TodoWrite list. The prompt guides it to wire deps, but ultimately the agent must do the mapping (plan item IDs to TodoWrite task IDs).
