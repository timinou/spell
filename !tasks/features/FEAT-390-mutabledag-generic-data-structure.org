* Narrative

The swarm scheduler needs a DAG that can mutate at runtime: agents spawn successors, handoffs inject new nodes, artifacts satisfy data dependencies dynamically. The existing =buildBatchGraph()= in =batch-scheduler.ts= builds an immutable graph once. The existing =splitIntoComponents()= in =orchestrators/fluid/dag.ts= operates on immutable =FluidPlan= structures.

This item creates a generic =MutableDag<T>= class that both the swarm scheduler and the refactored todo system will use. It is a pure data structure with no coupling to todos, events, or scheduling. The only domain concept it knows is "nodes with payloads connected by directed edges."

* Design Decisions

1. =MutableDag<T>= is parameterized by node payload type =T=.
2. Nodes are identified by string IDs (will be URI segments in practice, but the DAG doesn't care).
3. Mutations: =addNode(id, payload, deps?)=, =removeNode(id, mode)=, =addEdge(from, to)=, =removeEdge(from, to)=.
4. Every mutation runs cycle detection (Kahn's algorithm) before committing. If a mutation would create a cycle, it throws and the DAG is unchanged (transactional).
5. =getReady(completed, running)= returns nodes whose deps are all in =completed= and that are not in =running=. This is the core primitive the scheduler calls.
6. =splitComponents()= uses union-find (same algorithm as existing =splitIntoComponents= in =dag.ts=).
7. Optional file-dep overlap: =setFilesDeps(id, files)= and =hasFileOverlap(a, b)=. Stored separately from the graph topology. Used by the scheduler for isolation-gated concurrency.
8. The class is not thread-safe. Callers must serialize mutations (the scheduler owns the mutation lock).

*** addNode
- Empty DAG: =dag.addNode("a", {label: "A"})= => =dag.has("a") === true=, =dag.size === 1=, =dag.roots === ["a"]=
- With deps: =dag.addNode("b", {}, ["a"])= => =dag.getBlockers("b") === ["a"]=, =dag.getDependents("a") === ["b"]=
- Duplicate: =dag.addNode("a", {})= twice => throws ="Node a already exists"=
- Self-dep: =dag.addNode("b", {}, ["b"])= => throws ="Self-dependency: b"=
- Missing dep: =dag.addNode("b", {}, ["nonexistent"])= => throws ="Dependency nonexistent not found"=
- Diamond: a->{b,c}->d. =dag.addNode("d", {}, ["b","c"])= succeeds.

*** addEdge / cycle detection
- a->b->c exists. =dag.addEdge("c", "a")= => throws ="Cycle detected"=
- a->b exists. =dag.addEdge("a", "c")= where c exists => succeeds, =dag.getDependents("a")= includes both b and c

*** removeNode
- cascade: b depends on a. =dag.removeNode("a", "cascade")= => returns =["a", "b"]=, dag empty (or only other nodes)
- orphan: b depends on a. =dag.removeNode("a", "orphan")= => returns =["a"]=, =dag.getBlockers("b") === []=
- not found: =dag.removeNode("x", "cascade")= => throws ="Node x not found"=
- deep cascade: a->b->c->d. remove a cascade => returns ["a","b","c","d"]

*** getReady
- DAG: a(root), b(dep:a), c(root). completed={}, running={} => returns ["a","c"]
- completed={"a"}, running={} => returns ["b","c"]
- completed={"a"}, running={"c"} => returns ["b"] only
- All completed => returns []

*** splitComponents
- Two pairs: a->b, c->d => 2 components
- Single chain: a->b->c => 1 component
- Singleton: just a => 1 component with 1 node

*** topologicalOrder
- Diamond: a->{b,c}->d => starts with a, ends with d
- Verify determinism: same DAG produces same order on repeated calls

*** filesDeps overlap
- Same file: =setFilesDeps("a", ["src/x.ts"]); setFilesDeps("b", ["src/x.ts"])= => =hasFileOverlap("a","b") === true=
- Different files: => false
- Empty: =setFilesDeps("a", [])= => =hasFileOverlap("a","b") === false=
- Undefined: node without setFilesDeps => no overlap with anything
