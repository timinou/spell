* Narrative

Today, =todo_write= enforces a hard rule: at most one non-delegated direct task can be =in_progress= at any time (=normalizeInProgressTask()= in =todo-write.ts=, line ~445). This rule exists to prevent race conditions -- two agents editing the same workspace simultaneously would produce conflicts.

But isolation modes (worktree, fuse-overlay, fuse-projfs) already solve workspace conflicts by giving each agent its own filesystem snapshot. When isolation is active, the single-in_progress constraint is unnecessarily conservative: independent tasks that don't touch the same files could safely run in parallel.

The swarm architecture needs multiple agents executing simultaneously. The scheduler (FEAT-382) handles DAG-level parallelism, but =todo_write= -- the source of truth for task status -- must also relax its constraint. Otherwise, =normalizeInProgressTask()= will silently downgrade parallel tasks back to =pending=, defeating the scheduler.

This item makes the concurrency constraint *context-aware*:
- When isolation is OFF: existing behavior preserved exactly. One direct task at a time.
- When isolation is ON: multiple direct tasks allowed, subject to two safety checks:
  1. DAG independence: tasks must be in different connected components (no transitive dependency).
  2. File-dependency disjointness: tasks must not declare overlapping =filesDeps=.

The implementer should think of this as: "normalizeInProgressTask gains a second mode where, instead of keeping only the first in_progress task, it keeps ALL in_progress tasks that pass the safety checks."

* Design Decisions

1. New field =filesDeps?: string[]= on =TodoItem=. Lists file paths the task expects to modify. Populated by the parent agent, auto-roster, or self-reported by the subagent via =todo_write update=.
2. =normalizeInProgressTask(phases, isolationMode)= gains a boolean parameter. When =false=: existing logic unchanged. When =true=: allow multiple direct in_progress tasks if they pass safety checks.
3. New helper =hasFileDependencyOverlap(taskA: TodoItem, taskB: TodoItem): boolean=. Returns =true= if any path in =taskA.filesDeps= appears in =taskB.filesDeps=. Empty =filesDeps= is treated as "no constraint" (never overlaps with anything).
4. New helper =getRunningDirectTasks(phases: TodoPhase[]): TodoItem[]=. Returns all non-delegated tasks currently =in_progress=.
5. In isolation mode, =normalizeInProgressTask= checks each pending unblocked task against ALL currently running direct tasks for file overlap. If overlap found, the pending task stays =pending=.
6. The =splitIntoComponents= algorithm from =MutableDag= (FEAT-382) determines DAG independence. If FEAT-382 isn't available yet, a simpler heuristic is acceptable: tasks with no shared blockers in their transitive closure are independent.
7. The =todo-write.md= prompt must document the new =filesDeps= field and the conditional concurrency behavior clearly, with examples.

** 1. Write isolation-gated concurrency tests
File: =packages/coding-agent/test/tools/todo-write-isolation-concurrency.test.ts=

All tests use the =normalizeInProgressTask= function directly, constructing =TodoPhase[]= inputs and asserting the resulting status values.

*** Regression: isolation OFF preserves existing behavior
- Input: 2 phases, 4 tasks: task-1 (pending), task-2 (pending), task-3 (pending, blockers: [task-1]), task-4 (pending).
- Call =normalizeInProgressTask(phases, false)=.
- Assert: task-1 status === "in_progress", task-2/3/4 status === "pending". (Only first unblocked promoted.)

*** Isolation ON: independent tasks both promoted
- Input: task-1 (pending, filesDeps: ["src/a.ts"]), task-2 (pending, filesDeps: ["src/b.ts"]), no blockers between them.
- Call =normalizeInProgressTask(phases, true)=.
- Assert: task-1 status === "in_progress", task-2 status === "in_progress". (Both promoted.)

*** Isolation ON: file overlap prevents concurrent promotion
- Input: task-1 (pending, filesDeps: ["src/parser.ts"]), task-2 (pending, filesDeps: ["src/parser.ts"]).
- Call =normalizeInProgressTask(phases, true)=.
- Assert: task-1 status === "in_progress", task-2 status === "pending". (Overlap blocks task-2.)

*** Isolation ON: blocker still respected
- Input: task-1 (pending), task-2 (pending, blockers: ["task-1"], filesDeps: ["src/b.ts"]).
- Call =normalizeInProgressTask(phases, true)=.
- Assert: task-1 status === "in_progress", task-2 status === "pending". (Blocker prevents promotion regardless of isolation.)

*** Empty filesDeps treated as no constraint
- Input: task-1 (pending, filesDeps: []), task-2 (pending, filesDeps: ["src/a.ts"]).
- Call =normalizeInProgressTask(phases, true)=.
- Assert: both "in_progress". (Empty never overlaps.)

*** Undefined filesDeps treated as no constraint
- Input: task-1 (pending, filesDeps: undefined), task-2 (pending, filesDeps: undefined).
- Call =normalizeInProgressTask(phases, true)=.
- Assert: both "in_progress".

*** Mixed delegated + direct
- Input: task-1 (in_progress, delegated), task-2 (pending, filesDeps: ["src/a.ts"]), task-3 (pending, filesDeps: ["src/b.ts"]).
- Call =normalizeInProgressTask(phases, true)=.
- Assert: task-1 stays in_progress (delegated, untouched), task-2 and task-3 both promoted to in_progress.

*** hasFileDependencyOverlap unit tests
- =(["a.ts"], ["a.ts"])= => true
- =(["a.ts"], ["b.ts"])= => false
- =(["a.ts", "b.ts"], ["b.ts", "c.ts"])= => true (intersection: b.ts)
- =([], ["a.ts"])= => false
- =(undefined as any, ["a.ts"])= => false
