* Initial Message

Convert =executeOrg= from a synchronous NAPI function (blocks Node main
thread) to =task::Async<Value>= (runs on libuv worker pool, returns
=Promise= to JS). Fixes [[id:BUG-397-synchronous-executeorg-napi-freezes-node][BUG-397]] and unlocks live status-line
widget polling during memory recall, animated tool spinners, working
Ctrl-C cancellation, and concurrent agent tool calls.

* Edge Cases

- =peekMemoryProgress= is called from sync contexts (widget poll
  callback). After the cutover it becomes async; the poll callback
  wraps with =void= and the controller's =#lastStatus= dedup absorbs
  any out-of-order results.
- Two consecutive sync calls in source order (e.g.
  =executeOrg(opts1); executeOrg(opts2);=) now race on libuv. The
  daemon's =with_worker= mutex serializes wire-level access, so RPC
  stays ordered, but JS-side ordering assumptions must be reviewed.
  Grep for the pattern; none found in current repo.
- =AbortSignal= cancellation: =task::run_blocking= checks the cancel
  token at boundaries, but inside the closure we run
  =execute_org_catching= which doesn't currently expose cancel points.
  First cut: abort propagates back to JS, daemon may keep working.
  Acceptable per Scope/Out.
- Panic capture: =execute_org_catching= preserves the existing
  =catch_unwind=-based panic-to-error mapping. Verify it still works
  inside =task::blocking= (it should — the closure runs on a worker
  thread that catch_unwind covers).
- =result.error= shape unchanged: =OrgBufferResult= JSON layout doesn't
  change; only the wrapping =Promise= does. All result-shape tests
  remain valid.
