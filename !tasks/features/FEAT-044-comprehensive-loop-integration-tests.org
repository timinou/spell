*** Test 1: Multi-iteration loop lifecycle (start -> iterate x3 -> reflect -> iterate -> validate -> complete)
Contract: The full state machine produces correct transitions across a multi-iteration run.
- Start loop with maxIterations=5, reflectEvery=3, domains=[]
- Advance 3 iterations: verify iteration count, state=planning after each
- After iteration 3: verify state=reflecting (reflectEvery=3 triggers)
- Call kernel.done to transition reflecting -> planning
- Advance iteration 4
- Call markDone with forceValidate=true: verify state=validating
- Call markDone again: verify state=complete, completedAt set
- Assert persistence mock recorded all events (created, iterations, state changes)
- Assert dashboard panel registered on start, unregistered on complete

*** Test 2: Gate evaluation blocks iteration when command gate fails
Contract: When a command gate fires and fails, the gate decision is recorded with correct outcome.
- Start loop with a command gate config { id: "lint", type: "command", command: "false", trigger: { kind: "every-iteration" } }
- Run one iteration via runIteration()
- Assert gateResults contains { gateId: "lint", outcome: "fail" }
- Assert loop state reflects the gate failure in pendingGates/gateResults

*** Test 3: Human gate auto-approve via VirtualClock
Contract: When a human gate fires, auto-approve timer resolves the gate after configured timeout.
- Start loop with human gate { id: "review", type: "human", prompt: "Approve?", trigger: { kind: "every-iteration" }, autoApproveAfterMs: 100 }
- Use VirtualClock instead of RealClock (override in harness)
- Run iteration (will create pending human gate)
- Advance clock by 100ms
- Assert gate resolved with outcome=pass and reason containing "Auto-approved"

*** Test 4: Budget exceeded pauses the loop
Contract: When wall-clock budget is exceeded, safeguards pause the loop.
- Start loop with budgetLimits: { wallClockMs: 1000, maxTreeIterations: 200, maxIdleIterations: 5 }
- Use a LoopKernel with a custom now() that returns time beyond the budget
- Run iteration
- Assert loop state=paused with statusReason containing budget
- Verify the loop can be resumed and the budget status reflects elapsed time

*** Test 5: Runaway detection pauses the loop on idle iterations
Contract: When progress hash doesn't change across iterations, runaway detection fires.
- Start loop with maxIdleIterations=2
- Configure responder to return identical summary, changedFiles=[], findings=[] on every iteration
- Run 3 iterations
- Assert loop paused with reason containing "Runaway"
- Assert budgetStatus.idleIterations >= 2

*** Test 6: Child spawn, complete, and kill-tree

- Assert worktree cleanup was called for each (if worktreePath was set)
