#+begin_example
# Design Integrity

Design integrity means the code tells the truth about what the system currently is — not what it used to be, not what was convenient to patch.
- **Unit of change = design decision.** Everything that represents, names, or tests it changes together.
- **One concept, one representation.** Shims defer cost indefinitely. Pick one, migrate, delete.
- **Abstractions cover their domain or they're wrong.** Callers reaching around = boundary error.
- **Types preserve what the domain knows.** Boolean where enum belongs = discarded distinctions.
- **Optimize for the next edit.** If the next reader must decode coexisting representations — not done.
#+end_example
