* Intention & Purpose

Wire =pi-embedding-worker= into the recall pipeline as the embedding
execution path. The worker already exists for =pi-natives::code_graph=;
this FEAT exposes =embed_query= and =embed_batch= verbs callable from
=pi-org-recall=, plus an HNSW vector lane that consumes the resulting
vectors via the =hnswlib-rs= index from FEAT-633.

* Context & Narrative

Spec: =specs/org-graph-memory.md=, decision: subprocess via
=pi-embedding-worker= (memory isolation; cold-load amortized across
calls). The worker today serves the code-graph use case
(=crates/pi-natives/src/embedding_worker.rs=). The org recall pipeline
needs the same fastembed/jina-768-dim model. Reusing the worker avoids
a second model download and a second process.

A thin client in =pi-org-recall::embedder= wraps the existing JSON-RPC
or stdin/stdout transport. The client does:
1. lazy spawn (singleton per process)
2. =embed_query(text) -> Vec<f32>=
3. =embed_batch(texts) -> Vec<Vec<f32>>=
4. graceful shutdown on drop

The HNSW vector lane is built on the client + =pi-code-vectors::VectorIndex=
(from FEAT-633). Wraps it as =VecIndex= in =pi-org-recall= keyed by org
item ID rather than =node_index=.

* Edge Cases

- Worker fails to spawn (binary not found): =Error::WorkerSpawn= with hint to set =SPELL_EMBEDDING_WORKER_BIN=
- Worker stalls on first request (model download): timeout 60 s on first call; document
- Concurrent =embed_query= calls: client serializes via =Mutex<Child>= stdin/stdout; document the bottleneck and the future =embed_batch= mitigation
- Item ID collision (same string passed twice to =VecIndex::insert=): replace existing node_index in-place, or surface =Error::Duplicate=. Decision: replace (memory pipeline can re-embed after edit)
- Empty text: skip embed call; return zero-vector sentinel and skip insertion. Document and warn.
