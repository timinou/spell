* Scope

**In scope:**
- Auto-register slash commands from MODE.md ~command~ field during discovery
- Namespace collision detection: user mode commands cannot shadow builtin command names; error at load time with clear message
- Mode activation: custom slash command triggers mode entry using existing ~#enterPlanMode()~ with mode config attached to state
- Tool allow/deny lists per mode: resolve through extends chain, apply via ~setActiveToolsByName()~
- Todo phase templates: mode config ~todo.phases~ defines phase names used when agent creates task lists
- Starter task instantiation: mode config ~todo.phases[].tasks~ pre-populates todo on mode activation
- Gate presets: mode config ~todo.phases[].tasks[].gateCmd/gateLlm/gateArtifact/gateCommit~ pre-fill gate fields
- Wave-derived todo phases override mode config ~todo.phases~ when plan produces waves. Mode config phases are fallback for non-wave plans.

**Out of scope:**
- Prompt injection (FEAT: Mode Prompt Injection handles this)
- Lifecycle generalization / ActiveModeState (Phase 2)
- Canvas/QML (Phase 3)

**Boundary rationale:** This item covers the activation entry point (slash commands) and runtime behavior (tool filtering, todo templates). It uses the existing plan mode lifecycle (~enterPlanMode~) as the activation mechanism, attaching mode config as additional state. Full lifecycle generalization is Phase 2.

* Edge Cases
- Mode command name with/without leading ~/~ -> normalize: strip leading ~/~ if present
- Mode with both ~tools.allow~ AND ~tools.deny~ -> error at validation time (mutually exclusive)
- Mode activation while another mode is active -> exit current mode first (existing behavior)
- Session resume with mode that has custom command -> command must be re-registered from discovered modes
- Mode with tool restriction removing ~org~ tool but mode extends plan (which requires org) -> warn at load time
- Starter tasks with gate fields that reference tools not in mode's allow list -> warn, don't fail
- Empty ~tools.allow~ array -> no tools available except always-required (ask, exit_plan_mode)
- Mode with ~todo.phases~ AND wave-structured plan -> waves override, ~todo.phases~ discarded for that plan
