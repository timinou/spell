## Scope
**In scope:**
- Extend MCPServer interface: add ~gateway?: { expose?: boolean; alias?: string }~ field in =packages/coding-agent/src/capability/mcp.ts=
- Update MCPServer validation to accept the new field
- MCP manager integration: in =packages/coding-agent/src/mcp/manager.ts=, after connecting to HTTP MCP servers with ~gateway.expose = true~, auto-register them with the gateway daemon
- Lazy-start for HTTP MCPs: when gateway receives request to an MCP alias and the backing process isn't running, spawn it using the MCP config's command/args/env
- MCP config resolution: gateway reads MCP command/args from the registered service's managed config (populated during auto-registration)
- Auto-alias derivation: if ~gateway.alias~ not specified, derive from MCP server name (lowercase, hyphenated)
- Discovery integration: HTTP MCPs with gateway exposure get registered on ~discoverAndConnect()~
- Deregistration on MCP disconnect/session end

**Out of scope:**

- Non-MCP service management (PROJ-A, FEAT-B)

**Boundary rationale:** MCP-specific integration layer. Uses PROJ-A process manager for lazy-start, FEAT-B proxy for routing, FEAT-C client for registration.

** Implementation
1. Add ~gateway?: { expose?: boolean; alias?: string }~ to MCPServer in =packages/coding-agent/src/capability/mcp.ts=
2. Update validate function: gateway.expose only valid when command or url present
3. In =packages/coding-agent/src/mcp/manager.ts= connectServers():
   - After successful connection, check if config has gateway.expose = true
   - If yes and transport is http/sse: call gatewayClient.register({ alias, target: config.url, managed: { command, args, env }, persistent: false, sessionId })
   - Store gateway registration state on connection object
4. In MCPManager disconnect/dispose: deregister from gateway
5. In gateway daemon process-manager: when lazy-start is triggered for an MCP service, spawn the process, wait for HTTP health (GET /), then begin proxying
6. Write tests per plan

** Edge Cases
- MCP has url but no command: can proxy but can't lazy-start — register as external (unmanaged)
- MCP has command but no url: need to assign a port — use ephemeral port (0), detect via process output or health probe
- MCP server changes port on restart: re-register with new target
- Gateway not available: skip auto-registration, log warning, MCP works normally via direct connection
- Multiple sessions expose same MCP: first registration wins, subsequent sessions reuse alias
- MCP config env vars need expansion: env vars like ~${HOME}~ must be resolved before passing to process manager

** Acceptance Criteria
- HTTP MCPs with ~gateway.expose: true~ in mcp.json get .localhost aliases automatically
- Lazy-start works: cold MCP spawned on first request to alias
- MCP deregistered on session end
- Direct MCP connection still works when gateway unavailable
- All MCP gateway integration tests pass
- MCPServer type accepts new gateway field, ~bun check:ts~ passes
