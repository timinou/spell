* Context
=ModelRegistry= (=packages/coding-agent/src/config/model-registry.ts=) currently loads custom providers/models from =models.json= via =ConfigFile<ModelsConfig>= with TypeBox schema validation. This item replaces that loading path with KDL-parsed provider configs, while keeping the runtime API (=registerProvider()=, =getApiKey()=, =getAvailable()=) unchanged.

* Design Decisions
- =ModelRegistry= constructor changes: instead of =modelsPath?: string=, accepts =providerConfigs?: Record<string, KdlProviderConfig>=
- =ModelsConfigSchema= (TypeBox schema, ~200 lines) deleted
- =ModelsConfigFile= (=ConfigFile= instance) deleted
- =ModelsConfig= type deleted
- =validateProviderConfiguration()= stays (used by both KDL parser and =registerProvider()=)
- =buildCustomModel()= stays (same logic, receives parsed data from KDL instead of JSON)
- =#loadCustomModels()= simplified: reads from =this.#providerConfigs= instead of =ModelsConfigFile.load()=
- Discovery protocols (Ollama, LM Studio, llama.cpp) configs move from hardcoded defaults to KDL but the discovery RUNTIME stays unchanged (same API calls to detect models)
- =ProviderOverride=, =DiscoveryProviderConfig= interfaces stay
- =cacheDbPath= still derived from agentDir for SQLite model cache
- =ConfigFile= class in =config.ts= stays (used by other things) but models.json-specific usage removed

** Step 2: Simplify =#loadCustomModels()=
Current loads from ConfigFile, validates with TypeBox, parses models. New reads from =this.#providerConfigs= (already parsed and validated by KDL parser):

#+begin_src typescript
#loadCustomModels(): CustomModelsResult {
  const models: Model<Api>[] = [];
  const overrides: Map<string, ProviderOverride> = new Map();
  const discoveryProviders: DiscoveryProviderConfig[] = [];

  for (const [providerName, config] of Object.entries(this.#providerConfigs)) {
    // Handle provider overrides (baseUrl, headers, apiKey, compat without custom models)
    if (config.baseUrl || config.headers || config.apiKey || config.compat) {
      overrides.set(providerName, {
        baseUrl: config.baseUrl,
        headers: config.headers,
        apiKey: config.apiKey,
        compat: config.compat as Model<Api>["compat"],
      });
    }

    // Handle discovery
    if (config.discovery) {
      discoveryProviders.push({
        provider: providerName,
        api: config.api as Api,
        baseUrl: config.baseUrl,
        headers: config.headers,
        compat: config.compat as Model<Api>["compat"],
        discovery: config.discovery as ProviderDiscovery,
        optional: config.optional,
      });
    }

    // Handle custom models
    for (const modelDef of config.models ?? []) {
      models.push(buildCustomModel(
        providerName,
        config.baseUrl!,
        config.api as Api | undefined,
        modelDef.api as Api | undefined,
        modelDef,
        config.compat as Model<Api>["compat"],
      ));
    }
  }

  return { models, overrides, discoveryProviders };
}
#+end_src

* Edge Cases
- =ModelRegistry= with empty =providerConfigs= → only built-in models available (same as current behavior with no models.json)
- Discovery providers still need baseUrl for runtime API calls — validation catches missing baseUrl+discovery combos
- =registerProvider()= at runtime (from extensions) merges into the in-memory model list — unchanged
- API key resolution still goes through =AuthStorage.resolveApiKey()= which calls =resolveConfigValue()= — the =$ENV= and =!cmd= prefixes work because KDL stores them as literal strings, resolved at API call time
- Test files that use =writeModelsJson()= helper need equivalent =createProviderConfigs()= helper
