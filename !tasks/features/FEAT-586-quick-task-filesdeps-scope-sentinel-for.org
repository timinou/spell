Scenarios:

1. *task dispatch rejects quick_task without filesDeps* — call task tool with `agent: "quick_task"` and a batch where any task omits `filesDeps` → tool returns structured error `code: "QUICK_TASK_MISSING_FILESDEPS"` before spawning; no subagent started.

2. *empty filesDeps rejected* — `filesDeps: []` on a quick_task entry → same rejection.

3. *write inside scope allowed* — quick_task with `filesDeps: ["src/foo.ts"]` issues `write` to `src/foo.ts` → success.

4. *write outside scope blocked* — same agent issues `write` to `src/bar.ts` → tool returns `code: "OUT_OF_SCOPE_MUTATION"` naming the offending path and the declared scope.

5. *edit outside scope blocked* — text `edit` on non-allowlisted path → blocked.

6. *code edit outside scope blocked* — structural `code edit` (create/write/findAndReplace kinds) on non-allowlisted path → blocked.

7. *read outside scope allowed* — `read`, `grep`, `find` on any path → succeed. Scope is mutation-side only.

8. *directory-prefix scope* — `filesDeps: ["packages/natives/test/"]` (trailing slash) → any mutation under that prefix succeeds; sibling path blocked. Without trailing slash, `filesDeps` entry matches exact file only.

9. *task (full agent) unaffected* — same scenario as (4) but with `agent: "task"` → write succeeds (no scope enforcement on non-restricted agents).

* Edge Cases

- *Path normalization* — compare on resolved absolute paths; handle `./foo` vs `foo` vs `packages/coding-agent/./foo`.
- *Symlinks in filesDeps* — resolve both sides; treat matching real path as in-scope.
- *Newly created files inside allowed directory* — when `filesDeps` contains a directory (trailing slash), any descendant is allowed even if not yet existent at dispatch time.
- *Renames/moves* — if a mutating tool supports rename (e.g. edit tool `move`), both source and target must be in scope; else block.
- *Plan artifact paths* — `!tasks/plans/plan-artifacts/.../` is a valid write target; parent plan-mode enforcement already allows it. Do not conflict: scope enforcement runs AFTER plan-mode path check; both must pass.
- *Non-existent tool* — if a subagent has no access to a given mutating tool already, the wrapper noops for that tool.
- *Scope override via env / setting* — none. No escape hatch for quick_task; scope is a hard contract. If broader scope is needed, caller must use `agent: "task"` instead.
