* Goal

Replace the global =Mutex&lt;BufferRegistry&gt;= with per-buffer locking so operations
on different files don't block each other. This is prerequisite for the org tool
to share the buffer registry without blocking code operations.

Currently =crates/pi-natives/src/code_buffer.rs= has:
#+BEGIN_SRC rust
static BUFFER_REGISTRY: OnceLock<Mutex<BufferRegistry>> = OnceLock::new();
#+END_SRC

Every operation (outline, read, navigate, edit, save) acquires this single lock.
A slow tree-sitter parse on one file blocks ALL operations on ALL files.

* Architecture

** BufferRegistry changes (=crates/pi-code-engine/src/buffer.rs=)

Change internal storage from =HashMap&lt;PathBuf, CodeBuffer&gt;= to
=HashMap&lt;PathBuf, Arc&lt;parking_lot::Mutex&lt;CodeBuffer&gt;&gt;&gt;=.

#+BEGIN_SRC rust
pub struct BufferRegistry {
    buffers:  HashMap<PathBuf, Arc<Mutex<CodeBuffer>>>,
    registry: Arc<LanguageRegistry>,
}
#+END_SRC

New API:
- =open(&self, path) -> Result<Arc<Mutex<CodeBuffer>>>=  (takes =&self= not =&mut self=)
- =get(&self, path) -> Option<Arc<Mutex<CodeBuffer>>>=
- =close(&self, path)= — removes entry
- =list(&self) -> Vec<BufferInfo>= — locks each briefly to collect info

The registry itself needs a lightweight lock (=RwLock=) for the HashMap:
#+BEGIN_SRC rust
pub struct BufferRegistry {
    buffers:  RwLock<HashMap<PathBuf, Arc<Mutex<CodeBuffer>>>>,
    registry: Arc<LanguageRegistry>,
}
#+END_SRC

- =open=: write-lock registry briefly to insert, return =Arc<Mutex<CodeBuffer>>=
- =get=: read-lock registry to find entry, return clone of Arc
- Operations lock individual buffer via the Arc<Mutex>

** NAPI changes (=crates/pi-natives/src/code_buffer.rs=)

Change static from =OnceLock<Mutex<BufferRegistry>>= to =OnceLock<BufferRegistry>=
(registry itself uses internal RwLock now).

The dispatch pattern changes from:
#+BEGIN_SRC rust
let mut guard = registry().lock();
let buffer = guard.get_mut(&path).unwrap();
#+END_SRC
To:
#+BEGIN_SRC rust
let buf_arc = registry().get_or_open(&path)?;
let mut buffer = buf_arc.lock();
#+END_SRC

* Files to modify

- =crates/pi-natives/src/code_buffer.rs= — static registry type, all =registry().lock()= call sites

* Verification

- =cargo test -p pi-code-engine= passes (existing buffer registry tests)
- =cargo test -p pi-natives= passes if any
- =cargo check -p pi-natives= passes
- Verify =list()= doesn't deadlock (lock each buffer briefly, release)

* Edge cases

- =close()= while a buffer lock is held by another operation — the Arc ensures the buffer lives until the operation completes, then is dropped
- =open()= called concurrently for the same path — write-lock on registry HashMap serializes, second caller gets existing entry
- =list()= during active edits — must not hold registry read-lock while locking individual buffers (lock ordering: registry first, then buffer)
