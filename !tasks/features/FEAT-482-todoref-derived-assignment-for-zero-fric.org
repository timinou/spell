* Initial Message

I want tasks to be encouraged to use the sniper tool. make it so that the todo write, when used by subagents, uses the sniper tool (i.e. provides the exact context needed to efficiently do it then leave (no room for questions, terse). This is the level of the subtodos that should be shown in the UI. Explain how to make this a powerful tool that is used

* Context
Currently the ~task~ tool requires ~assignment~ as a required string field. When a task agent creates sniper todos via ~todo_write~ and wants to delegate them to ~quick_task~ agents, it must duplicate the sniper todo's content+details into the ~assignment~ field. This is wasteful and error-prone.

The fix: make ~assignment~ optional. When a task has ~todoRef~ but no ~assignment~, auto-construct the assignment from the linked todo item's ~content~ and ~details~.

This makes the sniper todo THE assignment — zero duplication, zero friction.

* Design Decisions
- ~assignment~ becomes optional in the TypeBox schema (it's already optional in the internal ~TaskItem~ TS interface at line 173 of types.ts)
- Resolution happens early in ~execute()~, before validation and dispatch
- The constructed assignment format: ~## Task: <content>

<details>~
- If ~todoRef~ is provided but the todo is not found OR has no details, fall through to the existing validation (which will error on missing assignment)
- The ~task.md~ tool prompt must document this: "When ~todoRef~ is set and ~assignment~ is omitted, the assignment is auto-derived from the linked todo's content and details."

#+begin_src typescript
#resolveTodoRefAssignments(tasks: TaskItem[]): TaskItem[] {
    const groups = this.session.getTodoGroups?.();
    if (!groups || groups.length === 0) return tasks;
    return tasks.map(task => {
        if (task.assignment?.trim() || !task.todoRef) return task;
        const todo = findTask(groups, task.todoRef);
        if (!todo) return task;
        const assignment = buildSniperAssignment(todo);
        return assignment ? { ...task, assignment } : task;
    });
}
#+end_src

Add a helper function (can be module-level or in template.ts):
#+begin_src typescript
export function buildSniperAssignment(todo: TodoItem): string | undefined {
    if (!todo.details && !todo.content) return undefined;
    const parts: string[] = [];
    parts.push(`## Task: ${todo.content}`);
    if (todo.details) {
        parts.push("");
        parts.push(todo.details);
    }
    return parts.join("
");
}
#+end_src

Call ~#resolveTodoRefAssignments~ in both ~execute()~ and ~#executeSync()~ right after extracting ~rawTasks~ from params but before any validation.

* Edge Cases
- If ~todoRef~ is set but the todo item doesn't exist: task proceeds with empty assignment, validation will catch it
- If todo item exists but has no ~details~: assignment is constructed from ~content~ alone (minimal but functional)
- If both ~assignment~ and ~todoRef~ are provided: explicit ~assignment~ takes precedence (no override)
- If the todo's details are very long: no truncation — the task tool already has payload size validation
