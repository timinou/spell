* Narrative

The =plan-mode-active.md= prompt already documents the =PARENT-ID::sub-slug= pattern for sub-outline items with =:DEPENDS:= properties. But plans are underusing it: many items have a =Sub-outline= section with prose dependency descriptions instead of structured =CUSTOM_ID= / =:DEPENDS:= properties. This means =org wave= cannot compute execution order from the dependency graph -- it requires manual wave assignment.

Additionally, the =:DEPENDS:= property and =blockers= mechanism in =todo_write= need hardening: there are no ERT tests for the org-side dependency graph algorithms (=org-fluid-plan=, =org wave=), and the TypeScript-side blocker resolution has gaps (dangling refs silently pruned, no cycle detection at the todo level).

This item has two parts:
1. *Prompt changes*: Strengthen plan-mode prompts to require =::= sub-outline items with =:DEPENDS:= properties. Make plan execution prompts consume =org wave= output.
2. *Testing*: Write comprehensive ERT tests for org graph algorithms AND TypeScript tests for blocker resolution edge cases.

* Design Decisions

1. Plan-mode-active prompt: every org item body MUST use =PARENT-ID::sub-slug= sub-headings with =:CUSTOM_ID:= and =:DEPENDS:= properties. Prose-only sub-outlines are prohibited.
2. Plan execution prompt: after plan approval, the executor reads =org wave= output to determine execution order instead of manually parsing wave headings.
3. =org wave= Elisp tool: must be tested with ERT for topological sort correctness, cycle detection, multi-component handling, and wave layer computation.
4. TypeScript blocker resolution: =hasUnresolvedBlockers= must detect and report dangling refs (currently silently pruned). =applyOps= must detect cycles in blocker graphs at the todo level.
5. The =todo_write= prompt must document that =blockers= are DAG edges and show examples of =::= sub-outline IDs as blocker references.
