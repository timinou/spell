Create =specs/prompt-surface-compression.md= with these sections:

*** Principles
1. Grammar is predictable; meaning is not → delete grammar
2. The model knows more than we teach → teach only what it can't derive
3. Schema-implied content → delete from description (parameter types, formats already in JSON Schema)
4. Non-obvious exemplar test: keep an example only if the model would get the pattern wrong without it
5. Handlebars conditionals → preserve exactly (structural, not content)
6. XML structural tags → preserve or consolidate (semantic meaning must survive)

*** Rules per content category
For each category (AGENTS.md, tool descriptions, overlays, agent prompts), specify:
- What constitutes "predictable grammar" in that category
- What constitutes "non-derivable meaning"
- Concrete before/after transform examples

*** AGENTS.md rules
- BAD/GOOD code pairs → delete unless pattern is genuinely non-obvious
- API tutorials → replace with constraint statements
- Table format for decision rules
- Example before: "**NEVER use named imports from `node:fs`** — always use namespace imports: // BAD: import { readdir } from 'node:fs/promises' // GOOD: import * as fs from 'node:fs/promises'"
- Example after: "- node:fs, node:path, node:os → =import * as= namespace only"

*** Tool description rules
- One capability sentence (first line, no positioning prose)
- =<instruction>= → constraint list only, no prose explanations
- =<examples>= → keep only if non-obvious exemplar test passes; JSON structure examples deleted
- =<critical>= → MUST/MUST NOT bullet list, no redundant restatement
- =<output>= → one-line summary
- Parameter prose → delete if schema covers it
- Verbose "avoid" sections → compress to anti-pattern list

*** Overlay/system prompt rules
- Process manual prose → decision tables + constraint lists
- Repeated constraint blocks → deduplicate (appears once)
- Workflow phases → notation (one line per phase, not paragraphs)
- Example flows → compress to minimal structural example

*** Agent prompt rules
- Already mostly exemplars — audit for consistency
- Role description → one sentence capability
- Instructions → constraint list

*** Validation criteria
- Each compressed file must pass: key constraints preserved (semantic anchor grep)
- Token count measured before/after
- No Handlebars conditional removed or altered
- All MUST/MUST NOT rules survive compression
