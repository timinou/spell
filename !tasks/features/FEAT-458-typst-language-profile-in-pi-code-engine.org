* Context

Typst is used across the codebase for professional documents — pitch decks, reports, brand libraries, client proposals. The Rust pi-code-engine currently supports 4 built-in languages (TypeScript, Rust, Python, Elixir). Typst must be added as a 5th built-in language so that =code outline=, =code read=, =code navigate=, and =code edit= work on .typ files.

Typst is Rust-native, and the =codebook-tree-sitter-typst= crate (v0.12.1) is the published crates.io version of uben0/tree-sitter-typst grammar.

The Emacs code layer is being deprecated; this MUST go into the Rust engine exclusively.

* Key Design Decisions

** Crate: codebook-tree-sitter-typst
Published on crates.io as =codebook-tree-sitter-typst= v0.12.1. Provides =LANGUAGE= constant for =tree_sitter::Language=.

** Tree-sitter-typst AST node types
Key named nodes in tree-sitter-typst (from uben0/tree-sitter-typst):
- =let= — fields: =pattern= (ident | call | assign), =value= (any expression). Represents =#let name = value= and =#let name(params) = body=.
- =import= — field: =import= (as | ident | string). Represents =#import "path": items=.
- =show= — fields: =pattern= (selector), =value= (transformation). Represents =#show selector: transform=.
- =set= — field: =condition= (optional), child: =call=. Represents =#set func(params)=.
- =heading= — no named fields (children are content nodes). Markup-level, not code-level.
- =ident= — leaf node for identifiers.
- =call= — field: =item= (ident | field | call | content). Function calls.
- =lambda= — fields: =pattern=, =value=. Anonymous functions.
- =comment= — line/block comments (=//= or =/* */=).
- =string= — string literals.

** Declaration patterns
Three declaration types:
1. =let= — kind "let", name_field "pattern", body_field "value". For =#let x = 5= the pattern is =ident("x")=. For =#let f(a, b) = body= the pattern is the call node =f(a, b)= — the text includes the signature, which is informative for outline.
2. =import= — kind "import", name_field "import", no body_field. The =import= field contains the path string.
3. =show= — kind "show", name_field "pattern", body_field "value". The pattern is the selector being styled (e.g., =heading=, =heading.where(level: 1)=).

=set= and =heading= are excluded from declarations — =set= is configuration (no stable name to extract), =heading= has no named fields and is content-level not code-level.

** Reference pattern
=ident= node, excluding parent types: =comment=, =string=.

** Separators
=","= only (Typst does not use =;= as a separator).

fn typst_profile() -> LanguageProfile {
    let gd = generated::typst::grammar();
    LanguageProfile {
        id:               LanguageId::new("typst"),
        extensions:       vec!["typ".into()],
        declarations:     vec![
            DeclarationPattern {
                node_types: vec!["let".into()],
                name_field: "pattern".into(),
                kind:       "let".into(),
                body_field: Some("value".into()),
                visibility: None,
            },
            DeclarationPattern {
                node_types: vec!["import".into()],
                name_field: "import".into(),
                kind:       "import".into(),
                body_field: None,
                visibility: None,
            },
            DeclarationPattern {
                node_types: vec!["show".into()],
                name_field: "pattern".into(),
                kind:       "show".into(),
                body_field: Some("value".into()),
                visibility: None,
            },
        ],
        class_like:       vec![],
        imports:          vec![ImportPattern {
            node_type:       "import".into(),
            specifier_field: "import".into(),
            is_type_only:    false,
        }],
        exports:          vec![],
        references:       vec![ReferencePattern {
            node_type:            "ident".into(),
            exclude_parent_types: vec!["comment".into(), "string".into()],
        }],
        separators:       vec![",".into()],
        production_rules: gd.production_rules,
        inverse_rules:    gd.inverse_rules,
        all_types:        gd.all_types,
        supertypes:       gd.supertypes,
        ts_language:      codebook_tree_sitter_typst::LANGUAGE.into(),
    }
}
