* Context: What This Replaces

Currently the Emacs daemon handles outline (=pi-outline.el=, 158 lines), resolution-aware read (=pi-resolution.el=, 120 lines), and navigate (=pi-edit.el= lines 102-218). Each call opens a fresh buffer over socat JSON-RPC, parses with tree-sitter, computes the result, kills the buffer. The navigate actions have known bugs: =references-local= ignores the =symbol= parameter, =node-at= and =defun-at= fail silently on whitespace, =parent= returns minimal information.

We're reimplementing all of these as Rust functions operating on =CodeBuffer=. They use the =LanguageProfile= declarations to extract names, kinds, and signatures. Navigate's references action integrates with the codegraph when available.

Canonical references:
- =specs/pi-code-engine-spec.md= section 7
- =packages/emacs/elisp/pi-outline.el= — existing outline logic to replicate
- =packages/emacs/elisp/pi-resolution.el= — existing resolution logic to replicate
- =packages/emacs/elisp/pi-edit.el= lines 102-218 — existing navigate logic (with known bugs to fix)

** Types

#+begin_src rust
#[derive(Debug, Clone, serde::Serialize)]
pub struct OutlineEntry {
    pub name: String,
    pub kind: String,         // "function", "class", "struct", "impl", etc.
    pub line: u32,            // 1-indexed start line
    pub end_line: u32,        // 1-indexed end line
    pub column: u32,          // 1-indexed column of the name
    pub exported: bool,
    pub signature: String,    // header without body, capped at 200 chars
    #[serde(skip_serializing_if = "Vec::is_empty")]
    pub children: Vec<OutlineEntry>,  // class/interface members
}
#+end_src

** Algorithm

1. Get tree root node from buffer
2. Iterate top-level children (named only) via =root.named_children()=
3. For nodes wrapped in =export_statement= (TypeScript): unwrap to get the inner declaration
4. For each child, try to match against =profile.declarations=:
   - Check if =node.kind()= is in any =DeclarationPattern.node_types=
   - If match: extract name via =node.child_by_field_name(pattern.name_field)=
   - Extract kind from =pattern.kind=
   - Compute signature: get node text, find body field (=pattern.body_field=), replace body with ="{ ... }"= (or ="..."= if no braces), cap at 200 chars
   - Check exported: is the node or its parent an =export_statement=?
   - Compute line/end_line/column from node positions (1-indexed)
5. For =profile.class_like= entries: if the node matches a class_like pattern, recurse into its body to extract member entries using the same declaration matching logic
6. For nodes that DON'T match any declaration pattern: skip them (don't include in outline)
7. Special cases per existing Elisp behavior:
   - =lexical_declaration= (TypeScript const/let/var): name is in =declarator.name=
   - =decorated_definition= (Python): unwrap to inner =definition= field
   - =impl_item= (Rust): name is in =type= field, not =name=
   - Markdown =atx_heading=: name is the heading text with level prefix (=h1: Title=)
   - YAML/JSON/TOML top-level keys: name is the key text
   - Elixir =call= nodes: check if target text is a def keyword

These special cases are encoded in the language profiles' =declarations= list. The implementer should check the existing Elisp in =pi-treesit.el= lines 193-320 (=pi-treesit-declaration-name=) and =pi-outline.el= lines 93-143 (=pi-outline--entry=) to ensure feature parity.

** Signature Stubbing

To create a signature (header without body):
1. Find the body child: =node.child_by_field_name(body_field)=
2. If body exists: return text from node.start_byte to body.start_byte (everything before the body), trimmed
3. If no body: return full node text
4. Cap at 200 characters

* Resolution-Aware Read

#+begin_src rust
/// Read a buffer at the specified resolution level.
///
/// - Resolution 0: names only (one name per line)
/// - Resolution 1: signatures (body stubbed to "{ ... }")
/// - Resolution 2: structure (class members visible, method bodies stubbed)
/// - Resolution 3: full source, optionally with line range
pub fn read(
    buffer: &CodeBuffer,
    profile: &LanguageProfile,
    resolution: u8,
    offset: Option<u32>,  // 1-indexed start line for resolution 3
    limit: Option<u32>,   // max lines for resolution 3
) -> String
#+end_src

- Resolution 0: call =outline()=, format as ="name (kind)"= per line
- Resolution 1: call =outline()=, format as signature per entry
- Resolution 2: call =outline()= with children, format signatures with children expanded (member signatures visible, their bodies stubbed)
- Resolution 3: return raw source from rope, optionally sliced by line range. If =offset= provided, start from that line (1-indexed). If =limit= provided, return at most that many lines.

** Main Function

#+begin_src rust
pub fn navigate(
    buffer: &CodeBuffer,
    profile: &LanguageProfile,
    action: NavigateAction,
    line: u32,            // 1-indexed
    column: Option<u32>,  // 1-indexed, optional
    symbol: Option<&str>, // for References action
    graph: Option<&dyn GraphLookup>,  // optional graph for cross-referencing
) -> NavigateResult
#+end_src

** Action: NodeAt

1. Convert (line, column) to byte offset. If no column, use start of line.
2. =tree.root_node().descendant_for_byte_range(offset, offset)= to get smallest node
3. If node is anonymous (not named), walk up to nearest named node via =.parent()=
4. Extract: type, text (first line, cap 80 chars), line, end_line
5. Also get parent info if parent exists

FIX vs Emacs: the current Elisp =node-at= fails when =treesit-node-at= returns on whitespace. We fix this by using =descendant_for_byte_range= which always returns a node, then walking up past anonymous nodes.

** Action: DefunAt

1. Convert line to byte offset (start of line)
2. Walk up from the node at that position looking for declaration nodes:
   - For each ancestor, check if =node.kind()= matches any =profile.declarations[].node_types=
3. If found: extract name (via =child_by_field_name(pattern.name_field)=), kind, line, end_line
4. If not found: return =NavigateResult::Error { message: "No enclosing function found" }=

FIX vs Emacs: the current Elisp =defun-at= relies on =treesit-defun-at-point= which requires =@function.outer= captures in the grammar. Our version walks the parent chain checking against the language profile's declarations — works for any language with a profile, no special grammar captures needed.

** Action: Parent

1. Find named node at (line, column)
2. Get its parent (=.parent()=)
3. If parent exists: extract name (via profile declarations), kind, line, end_line, and child_count (=parent.named_child_count()=)
4. If no parent: return error

FIX vs Emacs: current Elisp returns only type and line. We add name, kind, end_line, and child_count — making it actually useful.

** Action: Siblings

Same logic as current Elisp (which works well). Find named node, get parent, iterate parent's named children, mark which one is current.

** Action: Children

Same logic as current Elisp (which works well). Find node at line, walk up to a node that has a body (via profile's =body_field=), iterate body's named children.

** Action: References

This is the most changed action. Current Elisp =references-local= ignores the =symbol= parameter and does a brute-force text search including comments and strings.

New behavior:
1. Determine the symbol name:
   - If =symbol= parameter provided: use it directly
   - Else: find the node at (line, column), get its text
2. Walk the entire tree, collecting nodes whose text matches the symbol name AND whose type is NOT in =profile.references[].exclude_parent_types=. This filters out matches inside comments, strings, etc.
3. If =graph= is provided: cross-reference the file-local matches against graph edges. For each match, check if the graph has a References/Calls/Imports edge from a symbol in this file to/from the target symbol. Matches with graph edges get higher confidence. Include a note in the result like "Graph confirms 5/8 references".
4. If =graph= not available: include a warning "Graph not available, results are text-based only".

The =GraphLookup= trait:
#+begin_src rust
pub trait GraphLookup {
    /// Check if the graph has a reference from `from_file` to symbol `name`.
    fn has_reference(&self, from_file: &Path, name: &str) -> bool;
    /// Get all files that reference symbol `name`.
    fn references_to(&self, name: &str) -> Vec<PathBuf>;
}
#+end_src

This trait is implemented by pi-code-graph's =CodeGraph= (in a separate item). Navigate doesn't depend on pi-code-graph directly — it takes an =Option<&dyn GraphLookup>=.
