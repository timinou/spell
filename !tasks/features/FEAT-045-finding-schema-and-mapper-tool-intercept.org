- map() return type: *unchanged* — ~Record<string, unknown> | null~

Critical: map() must call super.map(event) for the normal tool_end emission in addition to the findings payload. Use a two-call pattern: emit findings_batch first, then return super.map(event) for the tool_end. Since map() can only return one value, the findings_batch must be sent via a separate channel — either emit it as a side-effect (store in a pending queue consumed by browse-mode.ts), or restructure map() to accept a callback for additional emissions. The cleanest approach: add an ~onAdditionalEvent~ callback to BrowseEventMapper that browse-mode.ts sets. The mapper calls ~this.onAdditionalEvent(findingsBatch)~ before returning ~super.map(event)~.
* Edge Cases
- web_search with 0 sources: emit empty batch, no findings
- web_search with error (result.details.error truthy): skip finding creation, emit normal tool_end
- fetch with aborted signal: no finding emitted
- tool_execution_start without matching tool_execution_end (orphaned): cleanup on next message_end or agent_end
- result.details is undefined or wrong shape: guard with runtime type checks, fall through to super.map()
- Multiple web_search calls: each gets its own batch with distinct toolCallId
- contentBody extraction: truncate to 10KB to avoid oversized bridge messages
