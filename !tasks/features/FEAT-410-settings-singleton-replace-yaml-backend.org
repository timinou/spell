* Reference
Read =specs/kdl-config-migration.md= Sections 4.8 and 3.1 for the complete design. This is the highest-risk item in the plan.

* Context
The Settings singleton (=packages/coding-agent/src/config/settings.ts=) manages all ~139 settings with a 3-tier merge (global + project + overrides). Currently it loads from =~/.spell/agent/config.yml= (YAML) and persists via =YAML.stringify=. This item replaces the YAML backend with KDL.

CRITICAL: This item changes ONLY the persistence layer. The =Settings.get()= / =Settings.set()= API, =SETTINGS_SCHEMA=, =SettingPath=, =SettingValue<P>=, and =SETTING_HOOKS= are all UNCHANGED. The ~67 files that import settings see no interface change.

* Design Decisions
- =Settings.set()= gains an optional =tier= parameter: =WriteTier = "session" | "project" | "user"=
- Default tier changes from "user" (current — writes to config.yml) to "session" (in-memory). See spec Section 4.8 for rationale.
- =#load()= reads =~/.spell/spell.kdl= (user) + =./spell.kdl= (project) instead of =config.yml=
- =#saveNow()= writes KDL via =writeKdlSettings()= instead of =YAML.stringify()=
- =Settings.#configPath= (string to config.yml) replaced by =Settings.#userKdlPath= and =Settings.#projectKdlPath=
- =YAML= import from ="bun"= removed
- =#loadYaml()= private method deleted
- Capability-based project settings loading (=.claude/settings.json= etc. via =loadCapability=) remains UNCHANGED — those are a separate project-settings overlay, not related to KDL
- =Settings.isolated()= continues to work with in-memory overrides (no KDL involved)
- =_resetSettingsForTest()= continues to work
- =flush()= method stays, now flushes KDL writes
- =AgentStorage= integration (=getStorage()=) stays unchanged

New =set()=:
#+begin_src typescript
set<P extends SettingPath>(path: P, value: SettingValue<P>, tier: WriteTier = "session"): void {
  const prev = this.get(path);
  const segments = parsePath(path);
  switch (tier) {
    case "session":
      setByPath(this.#overrides, segments, value);
      break;
    case "project":
      setByPath(this.#project, segments, value);
      this.#projectModified.add(path);
      this.#queueSave("project");
      break;
    case "user":
      setByPath(this.#global, segments, value);
      this.#globalModified.add(path);
      this.#queueSave("user");
      break;
  }
  this.#rebuildMerged();
  const hook = SETTING_HOOKS[path];
  if (hook) hook(value, prev);
}
#+end_src

** Step 4: Replace =#saveNow()=
Current writes YAML with file lock. New writes KDL:
#+begin_src typescript
async #saveNow(target: "user" | "project"): Promise<void> {
  const filePath = target === "user" ? this.#userKdlPath : this.#projectKdlPath;
  if (!filePath) return;
  
  const modified = target === "user" ? this.#globalModified : this.#projectModified;
  const source = target === "user" ? this.#global : this.#project;
  
  const changes = new Map<string, unknown>();
  for (const modPath of modified) {
    changes.set(modPath, getByPath(source, parsePath(modPath)));
  }
  modified.clear();
  
  await writeKdlSettings(filePath, changes);
}
#+end_src

** Step 6: Update =flush()=
#+begin_src typescript
async flush(): Promise<void> {
  // Clear timers
  if (this.#userSaveTimer) { clearTimeout(this.#userSaveTimer); this.#userSaveTimer = undefined; }
  if (this.#projectSaveTimer) { clearTimeout(this.#projectSaveTimer); this.#projectSaveTimer = undefined; }
  // Await pending saves
  if (this.#userSavePromise) await this.#userSavePromise;
  if (this.#projectSavePromise) await this.#projectSavePromise;
  // Flush remaining
  if (this.#globalModified.size > 0) await this.#saveNow("user");
  if (this.#projectModified.size > 0) await this.#saveNow("project");
}

* Edge Cases
- =Settings.isolated()= with =inMemory: true= sets both KDL paths to null → no file I/O, works exactly as before
- Constructor with custom =agentDir= → derive user KDL path from parent of agentDir (=path.dirname(agentDir)=)
- Concurrent =set()= calls to different tiers → each tier has independent debounce
- =flush()= must await BOTH user and project saves
- =set()= with default tier is now "session" (in-memory) instead of the old behavior that wrote to config.yml. This is intentional and documented in the spec. Callers that explicitly need persistence must pass "user" or "project".
- The =spell config set= CLI command (=config-cli.ts=) must be updated in a separate item to pass =tier: "user"= to maintain current behavior.
