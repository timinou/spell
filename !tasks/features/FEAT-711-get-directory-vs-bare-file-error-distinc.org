* Intention & Purpose
When `get(target:"./not-real")` fails, the error should distinguish (a) path doesn't exist, (b) path exists but is unreadable, and suggest a trailing slash if user might have meant a directory.

* Context & Narrative
`packages/coding-agent/src/tools/get.ts:88-102` calls `fs.stat(absCandidate)` to decide between bare-file (`#raw`) and bare-dir (`#listing`/`#tree`). On error, silently swallows; lets the kernel surface generic "Inaccessible: ENOENT". The TS layer has the most context (knows whether path probably exists, what user passed) and should produce the rich error.

* Scope
In-scope:
- `packages/coding-agent/src/tools/get.ts` — on stat ENOENT/EACCES, classify and emit explicit diagnostic before kernel
- New diagnostic codes: `PATH_NOT_FOUND`, `PATH_NOT_READABLE`
- Trailing-slash suggestion (deferred unless cheap)
Out-of-scope:
- Kernel changes
- Filesystem watching for path-changed scenarios

* Existing Patterns (MUST use)
- `prettifyDidYouMean` in `get.ts:51-66` — extend with PATH_NOT_FOUND prettification
- `toolResult` builder pattern
- `fs.stat` error code field

* Edge Cases
- Already-qualified target (e.g., `a.ts#raw`): stat probe runs but failures still reach kernel
- URI targets (jobs://, agent://): no fs probe (existing classifyBareTarget excludes)
- Read permission on file but no execute on parent: EACCES; classified
- Symlink to non-existent target: stat returns ENOENT for follow; PATH_NOT_FOUND
- Race: file deleted between probe and kernel — kernel surfaces own diagnostic
