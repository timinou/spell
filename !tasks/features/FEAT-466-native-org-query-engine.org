* Goal

Implement a native Rust query engine in =crates/pi-org-engine/= that replaces org-ql for filtering org items. This engine supports the keyword query syntax already used by the org tool (=todo:DOING tags:auth priority:>=B=) and extends it with date range, clocked time, effort, and property comparison operators.

* Design Decisions

- No raw org-ql sexp support — keyword query syntax covers all needed use cases
- The query engine operates on Vec<OrgItem> (output from the foundation crate's item extraction)
- Filter predicates are composable via AND/OR/NOT
- Date range queries compare item timestamps (SCHEDULED, DEADLINE, planning dates) against from/to bounds
- Clocked queries aggregate CLOCK entries and filter by date or total minutes
- Effort queries parse EFFORT property to minutes and compare with operators (<=, >, =)
- Property queries support string equality (=) and numeric comparison (<, >, <=, >=)
- Sort supports: priority, state/todo, id, category (matching current TS-side sort)
- Pagination via limit/offset applied after filtering and sorting

* Current System Reference

The current =requiresEmacs()= boundary in =packages/org/src/query-builder.ts= defines what goes to Emacs:
- dateRange, clocked, effort → requires Emacs
- loopStatus, loopBlocked, acceptanceFailed, dependencyChain, loopDepth → requires Emacs
- properties with op != "=" → requires Emacs
- Composite (and/or/not containing above) → requires Emacs

The native engine replaces ALL of these. After migration, =requiresEmacs()= always returns false and is deleted.

* Keyword Query Syntax Parser

Current implementation in =packages/org/src/query-builder.ts= function =parseKeywordQuery()=:
- =todo:DOING= → filter by TODO state
- =tags:auth,security= → filter by tags (comma-separated)
- =priority:>=B= → priority comparison
- =layer:infra= → property equality shorthand
- =effort:<=2h= → effort comparison
- Free text → body text search

The Rust implementation should parse the same syntax into OrgQlFilter.

** =crates/pi-org-engine/src/query/filter.rs=
- =OrgQlFilter= struct (above)
- =PriorityFilter=, =PropertyFilter=, =DateRangeFilter=, =ClockedFilter=, =EffortFilter= structs
- =matches(item: &OrgItem, filter: &OrgQlFilter) -> bool=: evaluate filter against single item
  - todo: item.state in filter.todo list
  - tags: all filter.tags present in item's tags
  - priority: compare item priority (A > B > C) with operator
  - properties: find property, compare value (string or numeric)
  - date_range: parse timestamps from body/planning, check if in range
  - clocked: parse CLOCK entries from body, check date or total
  - effort: parse EFFORT property, compare minutes
  - text: case-insensitive substring search in body
  - and: all sub-filters match
  - or: any sub-filter matches
  - not: sub-filter does not match
- =filter_items(items: &[OrgItem], filter: &OrgQlFilter) -> Vec<&OrgItem>=

* Edge Cases

- Priority "#A" vs "A" normalization (org format uses #A, internal comparison uses A)
- Effort "0h" matches effort:<=1h (0 <= 60)
- Empty tags list: matches nothing (not everything)
- Date parsing: "2024-01-15" bare date vs org timestamp format
- Property with no value: =:KEY:= (empty value) should match property existence check
- Unicode in text search
- Case sensitivity: tag matching is case-sensitive (org convention), text search is case-insensitive
