Final design decisions that this item must codify for downstream executors:
1. Full prompt-stack scope: system prompt, overlays, agent prompts, tool descriptions, inline tool strings, loop tool prompts, and base skills.
2. Acceptance bar is full cutover, not selective cleanup: every in-scope artifact must adopt the terse declaration-of-being style.
3. Canonical voice for tool docs is the `system-prompts` skill template style: one-line capability, then tagged sections only; no extra positioning prose between the capability line and the first tag.
4. Prompt content must teach the current tool landscape: `code` for source-file work, `ast_grep`/`ast_edit` for structural code work, `lsp` for semantic questions, `read`/`edit` only as fallback where appropriate.
5. Structural cleanup is required in the same initiative: misplaced, orphaned, deprecated, or duplicate prompt assets must be normalized or removed.
