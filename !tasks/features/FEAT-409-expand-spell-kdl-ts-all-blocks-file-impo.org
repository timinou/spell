* Initial Message

how would you move all of spell's config to spell.kdl config? What would it look like? Could you import bits inside other bits? would it be better to have blocks per mode?

* Reference
Read =specs/kdl-config-migration.md= Sections 3.1, 4.12, and the full grammar in Section 2.1.

* Context
Currently =spell-kdl.ts= handles only =domain=, =import= (built-in templates), =layer=, and =policy= nodes. After this item, it handles ALL node types from the grammar, resolves file-relative imports, and supports loading from both project (=./spell.kdl=) and user (=~/.spell/spell.kdl=) levels.

The =SpellProjectConfig= type expands to include all parsed config.

* Design Decisions
- =SpellProjectConfig= grows from ={domain, policies}= to include settings (RawSettings), providers, keybindings, modes, etc.
- File-relative imports (=import "./team.kdl"=) resolve against the directory containing the spell.kdl file
- Built-in template imports (=import "spell.coding.typescript"=) continue working (existing behavior)
- Import cycle detection via visited-set (prevents infinite loops)
- User-level loading: new =loadUserSpellKdl()= function that reads =~/.spell/spell.kdl=
- =loadSpellKdl= gains an optional =baseDir= parameter for import resolution
- Merge semantics for file imports: imported nodes are merged first, local nodes override

** Step 4: Add file-relative import resolution
Change the =import= handling:
#+begin_src typescript
case "import": {
  const ns = getStringArgument(node);
  if (!ns) break;
  
  if (ns.startsWith("./") || ns.startsWith("../")) {
    // File-relative import
    if (!baseDir) {
      logger.warn("spell-kdl: file imports not supported without baseDir");
      break;
    }
    const importPath = path.resolve(baseDir, ns);
    if (visited.has(importPath)) {
      logger.warn("spell-kdl: import cycle detected", { path: importPath });
      break;
    }
    visited.add(importPath);
    try {
      const content = await Bun.file(importPath).text();
      const importedConfig = parseSpellKdlInternal(content, path.dirname(importPath), visited);
      mergeConfigs(result, importedConfig);
    } catch (err) {
      if (!isEnoent(err)) {
        logger.warn("spell-kdl: failed to load import", { path: importPath, error: err });
      }
    }
  } else {
    // Built-in template (existing behavior)
    const templateContent = resolveTemplate(ns);
    // ... existing template logic ...
  }
}
#+end_src

** Step 5: Add =loadUserSpellKdl=
#+begin_src typescript
export async function loadUserSpellKdl(): Promise<SpellProjectConfig | undefined> {
  const userKdlPath = path.join(getConfigRootDir(), "spell.kdl");
  try {
    const content = await Bun.file(userKdlPath).text();
    return await parseSpellKdl(content, path.dirname(userKdlPath));
  } catch (err) {
    if (isEnoent(err)) return undefined;
    logger.warn("spell-kdl: failed to load user spell.kdl", { error: err });
    return undefined;
  }
}
#+end_src

Import =getConfigRootDir= from =@oh-my-pi/pi-utils=.

* Edge Cases
- =parseSpellKdl= must remain safe to call with content that has ONLY domain + policies (backward compat with existing spell.kdl files)
- File imports merge using same override semantics as template imports: local nodes win
- =import= nodes are processed in order — later imports override earlier ones
- The =visited= set prevents cycles but allows the same file to be imported from different paths (resolved to absolute)
- =baseDir= is =undefined= for =parseSpellKdl(content)= calls without a file context (e.g., from tests passing inline strings). File imports log a warning in this case.
