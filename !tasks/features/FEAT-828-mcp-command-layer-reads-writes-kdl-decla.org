* Problem

`/mcp reauth|unauth|test|enable|disable <name>` all funnel through `#findConfiguredServer` (packages/coding-agent/src/modes/controllers/mcp-command-controller.ts:629), which reads ONLY `mcp.json` files via `getMCPConfigPath("user"|"project")`. Servers declared in `spell.kdl` `mcp {}` blocks are invisible → "Server not found". This is the exact "Server notion not found" failure.

Persistence side: `#handleReauth` writes results via `updateMCPServer(filePath, …)` → mcp.json. Must instead write to the KDL settings tier.

* Fix

1. `#findConfiguredServer(name)` — resolve from settings tiers instead of (or in addition to) mcp.json:
   - Read `settings.getPerTier("mcp.servers")` → check `project` tier then `user` tier for `name`.
   - Return `{ scope: "user"|"project", config, tier }` shape the callers expect. Map tier→scope: project tier→"project", user tier→"user".
   - KEEP a legacy mcp.json read as a fallback (migration window) — but KDL/settings wins when both define the name (mirrors builtin.ts::loadMCPServers precedence + emits the same shadow warning semantics).

2. Persist path (`#handleReauth`, quick-add in `#handleAdd`, `#handleUnauth`, remove) — replace `updateMCPServer(...)` with:
   - Read current `settings.getPerTier("mcp.servers")[tier]` map (or {}).
   - Set/merge `map[name] = updatedConfig` (including the widened `auth {}` from BUG-491).
   - `settings.set("mcp.servers", map, tier)` where tier = user|project|local per `--scope`.
   - `await settings.flush()` (or the existing persistence await) so spell.kdl is written before reload.

3. `--scope` handling: user→user tier (~/.config/spell/spell.kdl), project→project tier (<cwd>/spell.kdl), (local→<cwd>/.local/spell.kdl if surfaced). Default scope = project per PLAN decision.

* Non-goals

- Don't remove mcp.json read yet (migration). Just make KDL the primary + writable source.
- Don't touch the runtime `#resolveAuthConfig` — it already consumes the config correctly once the config carries the fields.
