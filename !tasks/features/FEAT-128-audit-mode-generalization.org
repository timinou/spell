* Scope

**In scope:**
- Express ~AuditState~ as an ~ActiveModeState~ variant with ~type: 'audit'~
- Create an internal audit prompt definition (not in .spell/modes/, in ~packages/coding-agent/src/modes/definitions/audit.md~) that serves as the base for user ~extends: audit~ modes
- User modes with ~extends: audit~ inherit the audit lifecycle (pending -> active -> escalate/clean)
- Custom ~audit.focusAreas~ from mode config replaces/augments the default 5-item audit checklist in the prompt
- Custom ~audit.maxDepth~ from mode config overrides default (2)
- Custom ~audit.escalation~ from mode config overrides default ('auto' for ultraplan, 'suggest' for regular)
- Preserve ALL existing audit behavior: [AUDIT_CLEAN] marker detection, escalation to ultraplan, depth tracking, suggest callback

**Out of scope:**
- Full audit lifecycle rewrite (keep ~checkAuditPhase()~ and ~injectAuditPrompt()~ working as-is)
- Custom audit UI (Phase 3 canvas)
- Audit as a nested mode (FEAT: Mode Transitions handles nesting)

**Boundary rationale:** Audit generalization is scoped to making audit configurable through the mode system while preserving its unique lifecycle (which differs from plan mode). The audit lifecycle (pending/active/escalate) stays as-is; we're adding a configuration layer on top, not rewriting the state machine.
