* Initial Message

Implement these audit recommendations from org://AUD-060-audit-implementation:

- **What**: Atomic vector-cache writes still use a shared fixed temp filename instead of a per-write unique temp path  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `save_vector_cache()`  
  **Why**: `workspace-vectors.bin.tmp` is safe against partial writes from one process, but not against two concurrent semantic-index runs. Concurrent writers can clobber the same temp file or fail during rename, which reintroduces a race in the cache persistence path.  
  **Effort**: small

- **What**: Auto-degrade semantic search paths are untested  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `"search"` branch and `code_graph::tests`  
  **Why**: Current tests cover `semantic: true` hard failure with no vector cache and status reporting for a corrupt cache, but they do not verify the new auto mode behavior that should return BM25 results plus a degradation hint for stale/corrupt vectors or query-embedding failures. A regression here would silently revive the original “plausible results, hidden semantic failure” problem.  
  **Effort**: small

- **What**: The actual JS/N-API boundary for `semanticStatus` is still unverified  
  **Where**: `crates/pi-natives/src/code_graph.rs` export path and `packages/natives` / `packages/coding-agent/test/tools/code.test.ts`  
  **Why**: Rust tests call internal `run_code_graph()`, while TS tests mock `executeCodeGraph()`. That leaves the real N-API marshalling path untested, so a field-name/export mismatch on `semanticStatus` could ship without a failing test.  
  **Effort**: medium

- **What**: Tool docs mention `semantic?` for `search` but not for `index`  
  **Where**: `packages/coding-agent/src/prompts/tools/code.md`  
  **Why**: Users are now told, via runtime errors, to rebuild with `code index` and `semantic: true`, but the prompt surface does not document that `index` accepts the flag. That makes the new contract harder to discover and debug from the public interface alone.  
  **Effort**: trivial

- **What**: Semantic indexing derives dimensions from the first embedding but does not validate the rest of the batch  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `build_semantic_index()`  
  **Why**: This removes the hardcoded `768`, but it still assumes every returned vector matches the first. If fastembed or model configuration changes produce inconsistent dimensions, the cache can be built from malformed data and fail later in a less obvious place. Early validation would make indexing fail truthfully at the source.  
  **Effort**: small

* Problem

All Rust tests for the semantic search contract call the internal =run_code_graph()= function. All TS tests mock =executeCodeGraph()=. Neither verifies that =semanticStatus= survives the N-API marshalling boundary. A field-name or type mismatch between the =#[napi(object)]= struct and the TS =CodeGraphResult= interface would ship without a failing test.

=packages/natives/test/native.test.ts= already tests real native bindings (=grep=, =glob=, etc.) against temp fixtures — the pattern exists, it just has no =executeCodeGraph= coverage.

* Design Decisions

1. Add a new =describe("executeCodeGraph")= block in =packages/natives/test/native.test.ts=.
2. Tests call the real =executeCodeGraph= function (imported from =../src/index=) — not mocked.
3. Use a temp directory with two TS fixture files (reuse the existing =setupFixtures= pattern with =fs.mkdtemp=).
4. Three tests verify:
   - (a) =index= without =semantic= returns a result with =semanticStatus === undefined= and correct shape.
   - (b) =status= returns a result with =semanticStatus= as a string (type check, not exact value).
   - (c) =search= with =semantic: true= and no vector cache returns an error mentioning "Semantic search requested but unavailable".
5. Each test asserts the full =CodeGraphResult= shape: =output= (string), =cacheStatus= (string), =rebuilt= (boolean), =fileCount= (number), =symbolCount= (number), =edgeCount= (number), =semanticStatus= (string | undefined).

#+begin_src typescript
describe("executeCodeGraph", () => {
    beforeAll(async () => {
        await setupGraphFixtures();
        return async () => {
            await fs.rm(graphTestDir, { recursive: true, force: true });
        };
    });

    it("index returns correct result shape with semanticStatus undefined", async () => {
        const result = await executeCodeGraph({
            command: "index",
            root: graphTestDir,
        });
        expect(typeof result.output).toBe("string");
        expect(typeof result.cacheStatus).toBe("string");
        expect(typeof result.rebuilt).toBe("boolean");
        expect(typeof result.fileCount).toBe("number");
        expect(typeof result.symbolCount).toBe("number");
        expect(typeof result.edgeCount).toBe("number");
        expect(result.semanticStatus).toBeUndefined();
        expect(result.fileCount).toBeGreaterThanOrEqual(2);
        expect(result.symbolCount).toBeGreaterThanOrEqual(2);
    });

    it("status returns semanticStatus as string", async () => {
        const result = await executeCodeGraph({
            command: "status",
            root: graphTestDir,
        });
        expect(typeof result.output).toBe("string");
        expect(typeof result.semanticStatus).toBe("string");
        expect(result.output).toContain("Semantic:");
    });

    it("search with semantic: true errors without vector cache", async () => {
        await expect(
            executeCodeGraph({
                command: "search",
                root: graphTestDir,
                query: "limit",
                semantic: true,
            }),
        ).rejects.toThrow("Semantic search requested but unavailable");
    });
});
#+end_src
