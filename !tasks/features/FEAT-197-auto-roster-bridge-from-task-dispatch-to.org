* Implementation

** FEAT-197-auto-roster-bridge-from-task-dispatch-to::deterministic-mapping - Deterministic task-to-todo ID mapping
- DEPENDS: auto-create-logic
- Strategy: Create todo items in the same order as the ~tasks~ array. The internal ~todo_write add_phase~ call produces sequential IDs (~task-N~). Use the item creation order to build a stable index mapping: ~tasks[i] → created_todo_ids[i]~.
- Store the mapping in a ~Map<string, string>~ (task item ID → todo item ID) for ~todoRef~ assignment.
- If ~add_phase~ returns items in a different order (unlikely but defensive), fall back to content-matching by task description.
- Edge case: mixed batch with some existing ~todoRef~ — only unmapped tasks participate in the index mapping.

** FEAT-197-auto-roster-bridge-from-task-dispatch-to::partial-create-rollback - Partial creation failure handling
- DEPENDS: auto-create-logic
- If internal ~TodoWriteTool~ call fails (returns errors):
  - Log the error
  - Do NOT abort the dispatch — proceed without roster entries for the failed subset
  - The dispatch itself is more important than tracking; tracking failure is recoverable
- If the call partially succeeds (some items created, some failed):
  - Assign ~todoRef~ only to successfully created items
  - Log which items could not be tracked

* Edge Cases
- Concurrent auto-roster creation from multiple async batches: mutation lock prevents interleaving
- Auto-created items coexisting with manually-created ones: normalization treats auto-created as delegated (has delegation metadata from creation)
- Race between auto-create and user's manual ~todo_write~: serialized via mutation lock
- Very large batch (50+ tasks): single internal ~todo_write~ call with ~add_phase~ is atomic enough
- Nested task calls: child subagent's task dispatch should NOT auto-create in parent's roster (check ~taskDepth > 0~)
- Phase name collision: if phase with same name exists, append numeric suffix or create new phase
- Empty task description: use task ID as fallback content

* Acceptance Criteria

- Cancellation produces clean state (no orphan ~pending~ items)
- No interleaving with concurrent manual ~todo_write~ updates
- Normalization treats auto-created items as delegated (not direct)
