* Initial Message

looking at the typst and org integrations to pi-code-engine, what would you want to implement for your markdown usage to be a delight?

* Context

With the markdown profile from [[id:FEAT-520-markdown-language-profile-with-section-a]] and the procedure DSL transform layer from [[id:FEAT-522-procedure-dsl-transform-layer-with-decla]], this feature registers markdown-specific edit operations as named procedures on the markdown profile.

** Design Decisions

- ~promote~: decrease heading level of a section and all its descendant headings (~## → #~, ~### → ##~, etc.). Uses declarative ~Transform::TrimStart { count: 1 }~ on heading marker nodes
- ~demote~: increase heading level (~# → ##~, ~## → ###~). Uses declarative ~Transform::Prepend { text: "#" }~ on heading marker nodes
- ~replace-code-block~: replace the content of a specific fenced code block within a section. Uses ~Transform::Custom~ because it needs runtime parameters (which code block to target by index or language). Document why Custom is needed: the selection depends on runtime parameters, not static AST patterns
- These operations are invoked as: ~code edit { file, symbol: "Installation", operation: "promote" }~
- Promote/demote on h1 promote or h6 demote: promote on h1 is a no-op (can't go above h1); demote on h6 is a no-op (can't go below h6). Validate and return error
- replace-code-block uses ~content~ parameter for new code and an optional ~index~ or ~language~ parameter to select which code block

** Selector extension for descendant matching

The current ~Selector~ supports ~Target::Self_~, ~Target::Parent~, ~Target::Grandparent~ with ~ChildFilter~. For promote/demote, we need to select ALL descendant nodes of specific types within a resolved target's byte range — not just direct children.

*** Add ~Target::Descendants~ or a ~descendants()~ method on ~SelectorBuilder~

This collects all named nodes of the specified types within the target node, recursively. Implementation: walk the tree within the resolved byte range, collect nodes matching the type filter.

This is a necessary extension to the selector. Without it, promote/demote can only affect the section's direct children, not nested headings.

** ~replace-code-block~ Custom implementation

The Custom function receives the full section text and options JSON. It needs to:
1. Parse ~index~ (0-based) or ~language~ from options
2. Find the Nth fenced code block or the first with matching language
3. Extract the ~code_fence_content~ byte range within the code block
4. Return a replacement that preserves fence delimiters and info string but replaces content

Since ~Transform::Custom~ receives text and options but NOT the AST nodes, the implementation needs to either:
- Re-parse to find code block boundaries (undesirable)
- Extend Custom signature to receive ~&[MatchedNode]~ and the buffer

Consider extending ~Transform::Custom~ signature:

#+begin_src rust
Custom(Box<dyn Fn(&CodeBuffer, &[MatchedNode], &serde_json::Value) -> crate::Result<Vec<TextEdit>> + Send + Sync>)
#+end_src

This gives the Custom fn access to the buffer (for AST queries) and matched nodes (for context). The Custom fn returns ~Vec<TextEdit>~ directly instead of transformed text per node. Update ~apply_procedure_transform~ accordingly — when transform is Custom, call it directly and return its edits.

* Edge Cases

- Promote h1 section: return error ~"Cannot promote h1 heading — already at top level"~
- Demote h6 section: return error ~"Cannot demote h6 heading — already at deepest level"~
- Promote/demote with nested sections: ALL headings in the subtree shift. If promoting a section that contains h2→h3→h4, result is h1→h2→h3
- replace-code-block with no code blocks in section: return error ~"No code blocks found in section"~
- replace-code-block by language with no match: return error ~"No code block with language 'X' found"~
- replace-code-block by index out of range: return error with count of available blocks
- Code block with empty content: replacement works, just replaces empty with new content
- Code block with no info_string (no language): matchable only by index, not by language
