* Problem
The manifest parser correctly parses all KDL domain types (panels, layouts, syncCollections, stateSchemas, reviewPolicies, checkpoints, exportTargets, notificationRoutes) into =AutonomyManifest=. But =toManifestJson()= in =goals.ts= only serializes =name=, =version=, =setups=, =goals=. All 8 new domain type arrays are silently dropped. The frontend receives a gutted manifest.

* Approach
Extend =toManifestJson()= to include all manifest domain types. No data config loading — domain data is served from state stores (FEAT-292), not from KDL.

** Sub-outline
1. Extend =toManifestJson()= return type to include all 8 domain arrays
2. Serialize each domain type array (panels, layouts, syncCollections, stateSchemas, reviewPolicies, checkpoints, exportTargets, notificationRoutes)
3. Extend manifest parser test to verify =toManifestJson()= includes all domain types
4. =bun check:ts= passes

** Scope
- =packages/spell-server/src/http/routes/goals.ts= (=toManifestJson= extension)
- =packages/spell-server/test/manifest/parser.test.ts= (extended)
- Does NOT touch manifest parser or types (already correct)
- Does NOT add =/api/data= endpoint (removed — domain data comes from state stores via FEAT-292)
