* Intention & Purpose
Give callers an opt-in atomic mode: when any op in a multi-op edit fails, all prior file mutations are rolled back. Default behavior (best-effort, first-failure-abort) is preserved — strict mode is opt-in via `transaction:"strict"` field on CodePathOptions.

* Context & Narrative
`crates/pi-natives/src/code_path/napi.rs:296-326` applies edit actions sequentially. On failure, prior outcomes are returned but prior file writes remain on disk. Test `edit_first_failure_aborts_rest` (line 882) codifies this as intentional. Make atomic mode opt-in.

Snapshot strategy: before applying any op, scan action list to enumerate target files; for each, read into Vec<u8> snapshot keyed by absolute path (and noting "didn't exist" for create-target paths). On failure: restore each touched file (or remove if it didn't exist before).

* Edge Cases
- Snapshot fails (file too large): fall back to best-effort with diagnostic warning
- Restore fails (disk full, permission revoked): catastrophic; emit FATAL diagnostic listing what was lost
- Strict + already-failing first op: no snapshots to restore (no-op)
- Same file targeted by multiple ops: one snapshot per file (deduplicated)
- Symbol-target ops don't need snapshot beyond host file
