* Scope

Make a running terminal session accept a remotely-injected message and submit it as a real
user turn — identical to typing it in the terminal.

** SessionBridgeClient (=packages/coding-agent/src/session-bridge/client.ts=)
- Handle inbound =inject_input= in =#handleMessage=.
- Add =onInjectInput(handler: (msg: {injectId; text; deliverAs}) => Promise<{accepted; reason?}>)=
  registration; the client invokes it, then sends =inject_ack=.
- Guard: if no handler registered, ack =accepted:false, reason:"no_handler"=.

** Wiring (=packages/coding-agent/src/main.ts=  runInteractiveMode)
- After =new InteractiveMode(...)=, register =sessionBridge.onInjectInput= → call into the mode.

** InteractiveMode (=packages/coding-agent/src/modes/interactive-mode.ts=)
- Add =async injectRemoteInput(text: string, deliverAs: "steer"|"followUp"|"auto"): Promise<{accepted; reason?}>=.
- Behavior MUST reuse existing submit semantics (study =input-controller.ts= submit path):
  - if =session.isCompacting= → =queueCompactionMessage(text, deliverAs==="followUp"?"followUp":"steer")=, accepted.
  - else if =session.isStreaming= → =session.prompt(text,{streamingBehavior: deliverAs==="followUp"?"followUp":"steer"})=.
  - else (idle) → submit as a normal new user message (same as =onInputCallback= path / =session.prompt(text)=); render the user message in the transcript.
  - if a bash command is running and text would conflict → accepted:false, reason:"bash_running" (mirror the input-controller guard) — or just queue; choose the least-surprising parity with terminal.
- Add to session history like terminal submit so /up recall + persistence match.
- Trigger UI render + niri/status listener as the terminal submit does.

* Existing patterns

- =input-controller.ts= lines ~250-320 are the canonical submit semantics — DO NOT invent a new
  path; route through the same =session.prompt= calls and pending-submission rendering.
- =raceWithBridge= / =emitBlockingEvent= show the existing bridge round-trip style for acks.

* Edge cases

- Injection while idle vs streaming vs compacting (all three handled above).
- Disposed/disconnected mode: handler unregistered on =shutdown()=; ack accepted:false.
- Empty/whitespace text → accepted:false, reason:"empty".
- Multiple rapid injections → each goes through prompt() queueing; no dropping.
