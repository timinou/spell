* Initial Message

Think about it. the wave-based dependency ordering only makes sense for one DAG, but orchestration flows can be several DAGs. Can you leanly improve/change the decomposition steps of plans and ultraplans to fully support these? And then once the first DAG has been generated, Daedalus is generated with that DAG summary as the startying point, instead of the current way which has Daedalus generate the decomposition analysis before the DAG which makes no sense? That way we can unlock deep parallelism and the orchestration is way more more granular per subtask

Ask me many questions. Challenge me a lot.

* Edge Cases
- Elisp MCP unavailable (Emacs not running, MCP connection error) :: graceful fallback to PlanWave extraction + old prompt-based execution flow. Log warning.
- Plan with no org items (file-backed plan, org disabled) :: old =#approvePlan= flow preserved entirely. No FluidOrchestrator invocation.
- FluidOrchestrator throws during execution :: PLAN stays in DOING state, error surfaced to user via TUI. Bridge's =execution_complete= does NOT fire. Operator intervenes manually.
- User cancels execution (Ctrl+C) :: parent AbortController.abort() cascades to all coordinators. Org items stay in current state (DOING). User can re-enter plan mode to resume.
- Reentry on partially executed plan :: bridge detects items already in DOING/DONE state, skips already-completed work. Items in DOING are re-attempted.
- Momus review after initial approval :: Momus triggers re-entry into plan mode. Agent revises items. On second approval, FluidOrchestrator re-executes with updated plan.
