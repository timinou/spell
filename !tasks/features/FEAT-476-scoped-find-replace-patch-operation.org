* Initial Message

How would you make the edit experience with the code tool so ergonomic it's even more ergonomic than giving line diffs in the language?

* Context

The single biggest ergonomic gap in the code tool: to change one line in a 50-line
function, the agent must reproduce all 50 lines. The scoped find/replace patch
operation solves this — the agent specifies only what changes, within a named scope.

This is the core new capability that makes code edit more ergonomic than line diffs.

* Design Decisions
1. New module: =crates/pi-code-engine/src/edit/patch.rs=
2. Operation name: ="patch"=
3. Input: a =ResolvedSymbol= (from FEAT-475) byte range + a list of ={ find, replace }= pairs
4. *Indent-insensitive matching*: for each line in =find= text, strip leading whitespace before comparison. The matched region's indentation is preserved. Replacement text's indentation is adjusted to match the matched region's indent level.
5. *Ambiguity*: if =find= text matches multiple locations within the symbol scope, return error with all match positions (byte offsets and line numbers). The agent must provide more specific text.
6. *No buffer mutation inside =apply_patches=*: the function takes =&CodeBuffer= (immutable) and computes ALL =TextEdit= values against the *original* buffer text. It does NOT re-parse between patches. All =find= texts are matched against the same original scope text. If the user needs dependent patches (where patch 2 matches the output of patch 1), they must use multi-edit batching (two separate ="patch"= edits in the =edits= array at the NAPI layer, which applies and re-parses between each).
7. Returns =Vec<TextEdit>= like other edit operations — integrates with existing =edit_batch=.
8. *Non-overlapping enforcement*: since all patches match the same original text, their matched byte ranges must not overlap. If two patches produce overlapping TextEdits, return an error. The =edit_batch()= function in =buffer.rs= already sorts edits by start_byte descending before applying, so non-overlapping edits compose safely.

* API

#+begin_src rust
// crates/pi-code-engine/src/edit/patch.rs

pub struct Patch {
    pub find: String,
    pub replace: String,
}

/// Apply find/replace patches within a byte range of the buffer.
/// `scope_start` and `scope_end` define the byte range to search within.
/// Returns TextEdits for each matched patch.
///
/// Matching: each line of `find` has leading whitespace stripped for comparison.
/// The replacement inherits the indentation level of the matched region.
pub fn apply_patches(
    buffer: &CodeBuffer,
    scope_start: usize,
    scope_end: usize,
    patches: &[Patch],
) -> Result<Vec<TextEdit>>;
#+end_src

* Algorithm
All patches are computed against the *original* buffer text (no mutation between patches):

1. Extract the scope text: =buffer.source()[scope_start..scope_end]=
2. For each patch, find the match position in the *original* scope text:
   a. Normalize the =find= text: split into lines, strip leading whitespace from each, rejoin with =
=
   b. Scan the scope text with same normalization: for each possible byte position in scope, extract a region of the same byte length as =find=, normalize it, compare
   c. Record all match positions (absolute byte offsets within the buffer)
3. Validate each patch:
   - If 0 matches → error: ="Patch find text not found in scope. Scope content:
{first_20_lines}..."=
   - If >1 matches → error: ="Patch find text is ambiguous: found at N locations (lines X, Y, Z) within scope"=
4. For each patch with exactly 1 match:
   a. Determine the indent level of the matched region's first line
   b. Determine the indent level of the =find= text's first non-empty line  
   c. Compute indent delta
   d. Apply indent delta to each line of =replace= text using =adjust_indent= from =indent.rs=
   e. Create =TextEdit { start_byte: match_start, old_end_byte: match_end, new_text: adjusted_replace }=
5. Check for overlapping TextEdits — if any two edits overlap in byte range, return error
6. Return all TextEdits sorted by start_byte descending (=edit_batch= requires this order)

* Indent-Insensitive Matching Detail

Example:
#+begin_src
// Symbol scope (function body):
    if (err) {
        return null;
    }

// Agent provides find:
if (err) {
    return null;
}

// Normalization strips leading whitespace per line:
// scope normalized: "if (err) {
return null;
}"
// find normalized:  "if (err) {
return null;
}"
// → Match!

// Replacement: agent provides:
if (err) {
    logger.error(err);
    throw err;
}

// Replacement is re-indented to match the original scope indent (4 spaces):
    if (err) {
        logger.error(err);
        throw err;
    }
#+end_src

Indent adjustment reuses =crates/pi-code-engine/src/edit/indent.rs= (=adjust_indent= function).
