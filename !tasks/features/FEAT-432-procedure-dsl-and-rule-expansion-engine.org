* Context: What This Replaces and Why

Combobulate (an Elisp package bundled in the Emacs daemon) provides a procedure DSL for declaratively finding nodes in a tree-sitter parse tree. It uses this for all structural editing: splice finds which children to keep, drag finds which sibling to swap with, clone finds the node to duplicate. Without this system, structural edits would require hardcoded node-type matching per language per operation — thousands of lines of case-specific code.

Combobulate's procedure system has two phases:
1. *Activation*: "Is the cursor at a node that matches this pattern?" — checks node type, cursor position relative to node, parent/ancestor constraints, and field membership.
2. *Selection*: "Given a match, which children/siblings should I operate on?" — filters nodes by type, marks them as @match or @discard.

Combobulate's procedure DSL is embedded in Elisp, defined as nested plists. The rules reference "production rules" — a 2200-line generated database mapping each tree-sitter node type to its fields and valid children. These production rules are generated from the tree-sitter grammar's =node-types.json=.

We're reimplementing this in Rust with a builder pattern API. The production rules are already generated by =build.rs= in the foundation item (=PROJ-029=). This item implements the DSL evaluation engine.

* Goal

* Design Decisions (All Binding)

1. *Builder pattern*: Procedures are built in Rust code using a fluent builder. NOT loaded from YAML/Elisp. Procedures are too complex and language-specific for declarative config — they're code.

2. *Deterministic execution*: No interactive proffer (combobulate lets the user choose between multiple matches). First matching activation rule wins. All selected nodes returned.

3. *Rule expansion is eager*: When an activation rule says =rule("expression")=, it immediately expands to all concrete node types that are children of the "expression" production rule. Expansion happens at activation time, not lazily.

4. *Supertypes are expanded*: Abstract node types like "expression", "statement", "declaration" never appear in real parse trees. When they appear in rules, they're expanded to their concrete subtypes (listed in =supertypes= + production rules from build.rs).

5. *Position uses byte offset*: The =point= parameter is a byte offset into the source. Position::At means point == node.start_byte(). Position::In means node.start_byte() < point <= node.end_byte(). Position::Any means either.

6. *Short-circuit*: Activation rules are tried in order. First match wins and execution moves to the selection phase. This matches combobulate's behavior.

#+begin_src rust
/// A rule expression that resolves to a set of concrete node type strings.
#[derive(Debug, Clone)]
pub enum RuleExpr {
    /// Direct list of node type strings: types(&["identifier", "string"])
    Types(Vec<String>),

    /// Expand a production rule to its children.
    /// rule("expression") → all node types that are children of "expression" in the grammar.
    /// With fields: rule_field("pair", "key") → only the "key" field's child types.
    Rule { name: String, fields: Vec<String> },

    /// Inverse rule: irule("identifier") → all node types that HAVE "identifier" as a child.
    InverseRule(String),

    /// Regex against all known node type names.
    Regex(String),

    /// Regex match each type, then expand each matched type as a production rule.
    RuleRegex(String),

    /// Set difference: all types matching `include` except those matching `exclude`.
    Exclude { include: Box<RuleExpr>, exclude: Box<RuleExpr> },

    /// Match all known node types.
    All,
}
#+end_src

use crate::language::profile::{ProductionRules, InverseRules};
use std::collections::HashSet;

/// Expand a RuleExpr into concrete node type strings.
pub fn expand_rules(
    expr: &RuleExpr,
    production_rules: &ProductionRules,
    inverse_rules: &InverseRules,
    all_types: &[String],
) -> HashSet<String> {
    match expr {
        RuleExpr::Types(names) => names.iter().cloned().collect(),

        RuleExpr::Rule { name, fields } => {
            if let Some(rule) = production_rules.get(name) {
                if fields.is_empty() {
                    // All fields + unnamed children
                    let mut result: HashSet<String> = rule.unnamed_children.iter().cloned().collect();
                    for field_types in rule.fields.values() {
                        result.extend(field_types.iter().cloned());
                    }
                    result
                } else {
                    // Only specified fields
                    fields.iter()
                        .filter_map(|f| rule.fields.get(f))
                        .flat_map(|types| types.iter().cloned())
                        .collect()
                }
            } else {
                // Unknown rule name — maybe it's a supertype. Expand subtypes.
                // Check if any production rule has this as a child and recurse.
                HashSet::new()
            }
        }

        RuleExpr::InverseRule(name) => {
            inverse_rules.get(name)
                .map(|parents| parents.iter().cloned().collect())
                .unwrap_or_default()
        }

        RuleExpr::Regex(pattern) => {
            let re = regex::Regex::new(pattern).unwrap_or_else(|_| regex::Regex::new("^$").unwrap());
            all_types.iter().filter(|t| re.is_match(t)).cloned().collect()
        }

        RuleExpr::RuleRegex(pattern) => {
            let re = regex::Regex::new(pattern).unwrap_or_else(|_| regex::Regex::new("^$").unwrap());
            let matched: Vec<String> = all_types.iter().filter(|t| re.is_match(t)).cloned().collect();
            matched.iter()
                .flat_map(|t| expand_rules(
                    &RuleExpr::Rule { name: t.clone(), fields: vec![] },
                    production_rules, inverse_rules, all_types
                ))
                .collect()
        }

        RuleExpr::Exclude { include, exclude } => {
            let included = expand_rules(include, production_rules, inverse_rules, all_types);
            let excluded = expand_rules(exclude, production_rules, inverse_rules, all_types);
            included.difference(&excluded).cloned().collect()
        }

        RuleExpr::All => all_types.iter().cloned().collect(),
    }
}

** =apply_procedure= (mod.rs)

#+begin_src rust
/// Apply a procedure to find nodes at a given point in the tree.
///
/// `tree`: the parsed tree-sitter tree
/// `point`: byte offset of the cursor position
/// `profile`: the language profile (for production rules)
///
/// Returns None if no activation rule matches.
pub fn apply_procedure<'tree>(
    procedure: &Procedure,
    tree: &'tree tree_sitter::Tree,
    source: &str,
    point: usize,
    profile: &LanguageProfile,
) -> Option<ProcedureResult<'tree>> {
    // Find the smallest named node at `point`
    let root = tree.root_node();
    let node_at_point = find_named_node_at(root, point)?;

    // Phase 1: Try each activation rule
    for (idx, rule) in procedure.activation_nodes.iter().enumerate() {
        // Walk up from node_at_point, trying each ancestor
        let mut candidate = Some(node_at_point);
        while let Some(node) = candidate {
            if let Some(parent) = try_activation(rule, node, point, profile) {
                // Phase 2: Selection
                let matched_nodes = if let Some(selector) = &procedure.selector {
                    let chosen = match selector.choose {
                        SelectorTarget::Node => node,
                        SelectorTarget::Parent => parent.unwrap_or(node),
                    };
                    apply_selector(&selector.matcher, chosen, profile)
                } else {
                    vec![node]
                };

                return Some(ProcedureResult {
                    activation_rule_index: idx,
                    action_node: node,
                    parent_node: parent,
                    matched_nodes,
                });
            }
            candidate = node.parent();
        }
    }

    None
}

/// Find the smallest named node containing the given byte offset.
fn find_named_node_at(root: tree_sitter::Node, byte_offset: usize) -> Option<tree_sitter::Node> {
    let mut node = root.descendant_for_byte_range(byte_offset, byte_offset)?;
    // Walk up past anonymous nodes to nearest named node
    while !node.is_named() {
        node = node.parent()?;
    }
    Some(node)
}
#+end_src

** =try_activation= (activation.rs)

For a given candidate node and activation rule:
1. Expand =rule.nodes= → set of concrete type strings
2. Check =node.kind()= is in the set. If not → return None.
3. Check position constraint:
   - At: =point == node.start_byte()=
   - In: =node.start_byte() < point && point <= node.end_byte()=
   - Any: =node.start_byte() <= point && point <= node.end_byte()=
4. Check =has_fields=: if set, verify =node= is in one of those named fields of its parent. Use =node.parent()= then iterate parent's children to find which field =node= is in (via =parent.field_name_for_child(child_index)=).
5. Check =has_parent=: if set, expand rule, check =node.parent().kind()= is in the set. If match, return =Some(parent)=.
6. Check =has_ancestor=: if set, walk up parent chain checking each ancestor's type against expanded rule. If match, return =Some(ancestor)=.
7. If all checks pass, return =Some(matched_parent_or_none)=.

** =apply_selector= (selector.rs)

Given a chosen node and a =SelectorMatcher=:
- =MatchChildren=: iterate =chosen_node='s named children (or all children if =include_anonymous=). For each child, check against matcher:
  - If =match_rules= set and child.kind() matches → Mark::Match
  - If =discard_rules= set and child.kind() matches → Mark::Discard
  - Otherwise → =default_mark=
  - Return all Mark::Match children
- =MatchSiblings=: get =chosen_node='s parent, iterate parent's children, apply same marking logic
