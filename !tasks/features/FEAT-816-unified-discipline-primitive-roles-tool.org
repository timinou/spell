* What — the unified primitive
#+begin_src kdl
discipline "name" {
    on   manual | tool "generate_ui_screen" | layer "implementation" | auto   // trigger
    inject once|carry { context "…"  instructions "…" }                       // guidance + cadence
    verify { cmd "…" · review "…" · swarm 3 criteria="…" · commit }           // loop-closer (optional)
    tools { allow … deny … }   read-only #true                                 // optional constraints
}
#+end_src
- roles            = =on manual= + =inject carry=   → orchestrate/discover/challenge/design
- tool-disciplines = =on tool=   + =inject once=    → Mock-critique (moves OUT of tool description)
- layer policies   = =on layer=  + =verify=         → api-quality/ui-quality
One loader, one injection path (per-turn role seam + tool_result hook seam — both already wired), one =verify= vocab. =mode=/=policy= kept as desugaring ALIASES for back-compat.

* Sub-loops — =verify= as the closing half of a discipline
A sub-loop = a discipline's =activate → work → verify → (loop|exit)= cycle made observable. "Slightly structured" pays 3 audiences:
- AGENT: explicit close-condition → won't stop mid-loop, won't forget the review step (the 303× pain). instructions=loop body; verify=exit gate.
- RUNTIME: =verify{swarm N}= is a real gate — auto-dispatches N reviewers over the wave diff, blocks until pass (satisfiable-by-existing per B1). Loops nest (wave ⊃ review).
- TUI/TEAM CHAT: renders as a labeled collapsible unit — "▼ Wave 2 · orchestrate · spine→review→gate · 3 reviewers · 2 findings · [SLOW auto]". User sees active loop, pending gate, AND which model drives it (A3).
Kept simple: sub-loop = a todo node kind="loop" + verify{swarm}. REUSES the existing wave roster — no new tracker.
