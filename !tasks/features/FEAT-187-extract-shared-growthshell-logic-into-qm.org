Addresses audit finding 5.

* Problem

=iconFor()=, =loadWorkspacePanel()=, =Component.onCompleted= registry builder, and =panelRegistry= property are fully duplicated between =GrowthShell.qml= and =GrowthShellTestHarness.qml=. Any future change to panel loading or icon mapping must be applied in both files. The harness exists because ApplicationWindow cannot be nested, so it must duplicate the structure, but the JS logic does not need duplication.

* Approach

Create a QML JS library module at =domain/growth/src/qml/panels/GrowthShellLogic.js= with =.pragma library= at the top, exporting:

- =iconMap= (the icon name -> emoji map, as a module-level object)
- =iconFor(name)= — reads =iconMap[name]=
- =buildPanelRegistry(panels)= — takes the panels array, returns the registry object
- =resolveMainPanelSource(workspaces, currentWorkspaceId, panelRegistry)= — the panel resolution logic from =loadWorkspacePanel()=

Both =GrowthShell.qml= and =GrowthShellTestHarness.qml= import this:
#+begin_src qml
import "GrowthShellLogic.js" as Logic
#+end_src

Then:
- =function iconFor(name) { return Logic.iconFor(name) }=
- =Component.onCompleted: { panelRegistry = Logic.buildPanelRegistry(panels); loadWorkspacePanel() }=
- =function loadWorkspacePanel() { mainPanelLoader.source = Logic.resolveMainPanelSource(workspaces, currentWorkspaceId, panelRegistry) }=

Depends on BUG-062 and BUG-063 being done first so the logic being extracted is clean.

* Files
- =domain/growth/src/qml/panels/GrowthShellLogic.js= — new, shared logic
- =domain/growth/src/qml/panels/GrowthShell.qml= — import and delegate to Logic
- =domain/growth/src/qml/panels/GrowthShellTestHarness.qml= — same

* Acceptance Criteria
- =GrowthShell.qml= and =GrowthShellTestHarness.qml= contain no inline =iconFor= object literal or =loadWorkspacePanel= loop logic
- Both import =GrowthShellLogic.js= and delegate to shared functions
- =bun test domain/growth/test/panels/growth-shell.test.ts= passes
- =bun test domain/growth/test/panels/chat-drawer.test.ts= passes
