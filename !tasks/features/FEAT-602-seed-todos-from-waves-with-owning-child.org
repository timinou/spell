* Edge Cases

- `orgItemId` empty or missing parent in map → slicer returns `undefined`; materializer leaves existing details untouched.
- Sub-outline exists but body is empty (just properties + next heading) → slicer returns `undefined`; wave entry keeps original `entry.details`.
- Multiple wave entries point to the same sub-outline id → each gets its own copy (slicer is pure).
- `:PROPERTIES:` drawer inside the sub-outline body (nested drawer) → outer drawer ends at first `:END:`; inner-only drawers inside the sub-outline body are preserved as part of the sliced text.
- Fluid mode (`materializeFluidPlanToTodos(plan)`) → no opts passed; `childBodiesById` is undefined; slicer is not invoked; unchanged output.
- Byte cap lands mid-emoji → `safeTruncateUtf8` guarantees code-point boundary (tested by FEAT-601-inject-linked-child-org-bodies-into-appr::s3-tests T-3 and scenario 6 here).
- Details merge when slicer result equals existing details → still concatenated with separator; the duplicate is acceptable and visible to the agent. (Deduplication is not in scope.)
- `planItemId` absent → `TodoGroup.planItemId` is undefined; downstream behavior unchanged (matches current backcompat behavior).
