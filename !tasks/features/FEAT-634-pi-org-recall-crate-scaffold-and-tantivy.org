* Intention & Purpose

Stand up a new =pi-org-recall= crate with a Tantivy BM25 full-text index
keyed by org item ID. This is the first of three retrieval lanes that
FEAT-636 (hybrid recall) will fuse via RRF; the other two are HNSW
vector recall (FEAT-633) and graph-walk seed expansion (FEAT-632).

* Context & Narrative

Spec: =specs/org-graph-memory.md=. Tantivy is the production-grade
Rust BM25 engine — pure Rust, ~10 ms cold start, 2x Lucene speed.
Mature ecosystem (ParadeDB, Codanna, Memgraph). It does not own vector
search; that's HNSW's job (FEAT-633). They compose at the recall layer
(FEAT-636) via Reciprocal Rank Fusion.

The crate is positioned for org-specific concerns: schema mirrors org
fields (id, kind, title, body, tags, file), tokenizer is English
stemmer, index location is OS-cache (=~/.cache/spell/recall/<repo-hash>/fts/=)
so it stays out of the repo and out of the dotfile sync surface.

* Edge Cases

- =repo_root= not canonical: canonicalize first; if path doesn't exist, error =Error::RepoHash=
- Index dir corrupted (Tantivy says invalid segment): bubble up; caller can wipe and re-index
- Disk full: Tantivy commit fails → =Error::Io=; caller surfaces
- Reindex storm (1000 items in tight loop): writer commits batched per call; document a single =writer.commit()= guarantees atomicity
- Mixed-language stemming: snowball English only; non-English text falls through unstemmed (still lowercased + ascii-folded)
- Scope filter with unknown kind string: returns empty hits (not error)
