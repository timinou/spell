* Edge Cases

- A sub-outline with no CUSTOM_ID and no TODO keyword returns None from extract_section_item → correctly omitted from the flat list (pre-existing behavior preserved).
- Deep nesting (level 3+): all descendants flattened. Confirmed by scenario 6.
- Cycles in the filesystem are impossible (headings are a tree); no cycle protection needed for the flatten walk.
- include_body=true on flattened sub-outlines: each sub-outline's body is its own section bytes. Parent still reports its own body which includes the sub-outline bytes (pre-existing behavior — do not change parent body computation). Documented in scenario 8.
- byte_range for a sub-outline must be (sub_section.start_byte, sub_section.end_byte), independent of the parent. Confirmed by scenario 3.
- cmdQuery level=0 default must survive: this is the most-touched consumer and regressions here would break every query. Scenario 10 is the guard.
- Memory: flattening does not deep-clone children; we push the same OrgItem into the flat Vec and leave children empty on that copy if memory matters. Simpler: clone once. Cost is bounded by total heading count per file; acceptable.
- Serialization size: flattened items include all properties; not a concern because NAPI returns JSON once per call.
