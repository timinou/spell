Status widget polls `peekMemoryProgress` every 5s. Now that operations
are non-blocking (FEAT-780), the 5s cadence is the only reason the
progress bar lags behind warm transitions. During `warming` state,
drop to ~250ms so the user sees real-time progress (files indexed /
total). Fall back to 5s in `warm` / `idle` to avoid waste.

** Targets

- `packages/coding-agent/src/modes/controllers/memory-status-controller.ts`
  - introduce `#cadenceForStatus(status)` returning 250ms (warming) /
    5000ms (warm|idle|unavailable)
  - reschedule the next poll based on the *current* snapshot status
    (not a fixed `setInterval`)

** Constraints

- Replace `setInterval` with `setTimeout` recursive scheduling so the
  cadence can change per-tick.
- `#inFlight` guard from FEAT-780 still applies — never double-poll.
- Test: state transitions warming → warm flip the cadence back to 5s
  on the first warm tick.

** Acceptance

- Visible: cold session start, warming progress updates every ~250ms
  in the status line until completion, then quiesces.
- Existing controller tests still pass.
- Idle CPU cost in warm state unchanged (still ~1 peek per 5s).
