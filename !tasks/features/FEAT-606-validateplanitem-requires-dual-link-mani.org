* Edge Cases

- A PLAN linking a top-level child that has NO sub-outlines: validator must not flag missing-suboutline-link. Scenario 5.
- A PLAN linking only sub-outline IDs (forgetting top-level links entirely): validator reports missing-top-level-link for every inferred parent. Scenario 2.
- A PLAN listing a sub-outline that does not actually exist in the parent's body: missing-suboutline-declaration. Scenario 4.
- A PLAN linking a top-level child that DECLARES sub-outlines but the PLAN only cites the top-level link (zero sub-outline entries): manifest-missing-suboutlines. Scenario 3. Rationale: waves must be expressed at sub-outline granularity; a top-level-only link defeats the purpose.
- A sub-outline whose own LAYER differs from its parent's: exit-plan-mode's resolveLayerFromProperties must prefer the sub-outline's own LAYER when present, fall back to parent's. Existing logic in lines 188-193 already does this via the properties-by-id lookup; verify with scenario 9.
- Validator error ordering: categories are accumulated in fixed order (structural errors first, then namespace, then dependency). New categories slot in next to missing-linked-items. formatPlanValidationIssues already handles arbitrary categories via the map lookup.
- Backward compat: a PLAN that passes validation today (all top-level links, no sub-outlines) continues to pass if the linked children have no sub-outlines. If any linked child has sub-outlines, the PLAN now fails validation until the manifest is extended — intentional per decision 5.
