* Intention &amp; Purpose

Create ~streamBetterCcflare~ — a full Anthropic-compatible provider that reuses all Claude Code stealth behavior but sends NO auth header when ~ANTHROPIC_AUTH_TOKEN~ is unset (OAuth passthrough mode). The proxy at ~localhost:8080~ uses its own configured OAuth accounts.

* Context &amp; Narrative

The existing ~streamAnthropic~ in ~packages/ai/src/providers/anthropic.ts~ always sends an auth header (~x-api-key~ or ~Authorization: Bearer~). This breaks better-ccflare's OAuth passthrough mode, where the proxy expects NO client auth so it can use its own configured OAuth accounts.

The stealth mode (Claude Code headers, tool prefixing, billing header, cache control normalization) must be preserved — better-ccflare forwards requests to Anthropic, and Anthropic expects Claude CLI-formatted requests for proper rate limiting and feature access.

~streamBetterCcflare~ delegates to ~anthropic.ts~ exports for all shared behavior and only overrides auth header construction and base URL default.

* Scope

In-scope:
- New file ~packages/ai/src/providers/better-ccflare.ts~ exporting ~streamBetterCcflare~ and ~buildBetterCcflareHeaders~
- Auth behavior: if ~ANTHROPIC_AUTH_TOKEN~ is unset → NO ~x-api-key~ or ~Authorization~ header (OAuth passthrough). If set → ~x-api-key: <token>~ (API key auth).
- Base URL: default ~http://localhost:8080~ (from ~resolveAnthropicBaseUrl~ modified in FEAT-649)
- ALL stealth mode features preserved: Claude Code headers, ~proxy_~ tool prefix, billing header, user-agent spoofing, TLS fetch options, cache control, thinking budget, message conversion, stream retry, raw request dump
- Register ~streamBetterCcflare~ in ~packages/ai/src/stream.ts~ dispatch

Out-of-scope:
- Changes to ~anthropic.ts~ beyond what FEAT-649 already does (exporting ~resolveAnthropicBaseUrl~)
- Model discovery / catalog entries
- ~ANTHROPIC_BASE_URL~ env var handling (FEAT-649)

* Edge Cases

- ~ANTHROPIC_AUTH_TOKEN~ set but empty: treated as unset → OAuth passthrough
- ~ANTHROPIC_AUTH_TOKEN~ set to ~dummy-key~ (open access): sent as ~x-api-key: dummy-key~
- ~ANTHROPIC_AUTH_TOKEN~ set to ~btr-...~ (real key): sent as ~x-api-key: btr-...~
- Model with ~provider: "better-ccflare"~ but ~api: "openai-completions"~: should not happen; the dispatch only intercepts ~anthropic-messages~ API
- Thinking disabled models: should work correctly (no thinking params)
- Opus adaptive thinking: should work correctly (effort config)
- Tool choice forced: should disable thinking as anthropic provider does
- Streaming errors mid-response: retry logic preserved
- GitHub Copilot dynamic headers: NOT applicable for better-ccflare, but the code checks ~model.provider === "github-copilot"~ so it naturally skips
- Foundry mode: NOT applicable for better-ccflare, no interaction
