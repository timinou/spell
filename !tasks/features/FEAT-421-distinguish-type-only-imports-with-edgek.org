* Context
The TypeScript extractor parses =import type { Foo } from "./bar"= and correctly sets =ExtractedImport.is_type_only = true=. However, the indexer in =crates/pi-code-graph/src/indexer.rs= never reads =is_type_only= — it creates =EdgeKind::Imports= and =EdgeKind::References= edges identically for runtime and type-only imports. This means:
- =dead_code= counts type-only references as "used", keeping type-only-referenced symbols alive in the report
- =impact= and =deps= cannot distinguish runtime breakage from type-level breakage
- The field is dead data — a contract violation (the extractor promises information the pipeline discards)

* Design Decisions
1. Add =EdgeKind::TypeImports= variant to the =EdgeKind= enum in =model.rs=. This variant is used for both file-level type-only import edges and symbol-level type-only reference edges.
2. In the indexer's import-processing loop, check =import.is_type_only=. If true, use =EdgeKind::TypeImports= instead of =EdgeKind::Imports= for the file edge, and =EdgeKind::TypeImports= instead of =EdgeKind::References= for the symbol edges.
3. In =graph_dead_code()= in =query.rs=, exclude =EdgeKind::TypeImports= from the =has_inbound_usage= check. A symbol referenced only via type-only imports should be reported as dead (no runtime consumer).
4. In =graph_impact()= in =query.rs=, include =TypeImports= in the traversal edge set so type-level dependents still appear in blast-radius analysis.
5. =EdgeKind::TypeImports= must derive =Serialize= / =Deserialize= (it already does via the derive on the enum) and have a stable bincode representation. Since we're adding a variant, existing caches will fail to deserialize — this is acceptable; the graph will just rebuild.

* Files to Modify
- =crates/pi-code-graph/src/model.rs=: Add =TypeImports= to =EdgeKind= enum (after =Renders=)
- =crates/pi-code-graph/src/indexer.rs=: In the import-processing loop (~line 130-154), branch on =import.is_type_only=
- =crates/pi-code-graph/src/query.rs=: Update =graph_dead_code()= to exclude =TypeImports= from inbound usage; update =graph_impact()= edge set to include =TypeImports=
- =crates/pi-code-graph/src/model.rs=: Update =count_edges()= if needed (it's generic — no change needed)

** Implementation
1. *model.rs* — Add variant after =Renders=:
   #+begin_src rust
   #[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq, PartialOrd, Ord, Hash)]
   pub enum EdgeKind {
       Defines,
       Imports,
       Calls,
       References,
       Inherits,
       Renders,
       TypeImports,
   }
   #+end_src

2. *indexer.rs* — In the import-processing loop (inside =for import in imports=), change the edge creation:
   #+begin_src rust
   let file_edge = if import.is_type_only { EdgeKind::TypeImports } else { EdgeKind::Imports };
   let symbol_edge = if import.is_type_only { EdgeKind::TypeImports } else { EdgeKind::References };
   // ...
   graph.add_edge(from_index, to_index, file_edge);
   // ...
   graph.add_edge(from_index, symbol_index, symbol_edge);
   #+end_src

3. *query.rs* — In =graph_dead_code()=, the =has_inbound_usage= check currently matches =Calls | References | Inherits | Renders=. Do NOT add =TypeImports= to this list. This means type-only references don't count as usage — which is the desired behavior.

4. *query.rs* — In =graph_impact()=, the BFS edge set is currently =[EdgeKind::Calls, EdgeKind::References, EdgeKind::Inherits, EdgeKind::Imports]=. Add =EdgeKind::TypeImports= so type-level dependents appear in blast-radius:
   #+begin_src rust
   &[EdgeKind::Calls, EdgeKind::References, EdgeKind::Inherits, EdgeKind::Imports, EdgeKind::TypeImports]
   #+end_src

* Edge Cases
- Mixed imports: =import { type Foo, Bar } from "./baz"= — the TypeScript extractor currently checks if the entire import statement starts with ="import type"=. Inline =type= modifiers on individual specifiers (TS 4.5+) are NOT detected. This is a known limitation; the =is_type_only= field only captures statement-level type imports. Documenting this as a TODO comment in the extractor is sufficient for now.
- Cache invalidation: Adding a new =EdgeKind= variant changes the bincode schema. Existing =.spell/graph/workspace.bin= files will fail to deserialize. The cache loader returns =None= on deserialization error, triggering a rebuild. This is the correct degradation.
- =export type { Foo } from= re-exports: The extractor already sets =is_type_only= based on ="export type"= prefix (see =parse_export_statement=). These will correctly produce =TypeImports= edges.
