* Initial Message

I want tasks to be encouraged to use the sniper tool. make it so that the todo write, when used by subagents, uses the sniper tool (i.e. provides the exact context needed to efficiently do it then leave (no room for questions, terse). This is the level of the subtodos that should be shown in the UI. Explain how to make this a powerful tool that is used

* Context
Subagents currently receive weak guidance on todo_write usage ("You MAY use todo_write to plan complex work into steps"). The result is variable-quality child todos that don't communicate enough context for mechanical execution. We need to define and enforce the "sniper todo" pattern: tasks so precise that any agent can execute them without exploration or questions.

* Design Decisions
- Sniper todo format: ~content~ = ultra-terse verb+target (5-10 words); ~details~ = full execution spec
- MUST for ~task~ agents, SHOULD for ~explore~, ~plan~, and other agents
- The sniper pattern is defined once in ~todo-write.md~ and referenced from ~subagent-system-prompt.md~

#+begin_example
## Sniper Pattern

When creating tasks as a subagent, write *sniper todos*: each task must be precise enough to execute mechanically without exploration or questions.

### Sniper task fields:
- `content`: Ultra-terse label. Verb + target + what. (5-10 words)
  - Good: "Add null guard to parseConfig input"
  - Good: "Update 3 callers to use validate()"
  - Bad: "Fix the parser"
  - Bad: "Handle edge cases"
- `details`: The full execution spec (shown in TUI when active):
  - Exact file path(s) to modify
  - Exact change description (what to add/remove/modify and where)
  - Exact acceptance criteria (test command, observable behavior)
  - Edge cases or constraints that affect the change

### Example
```
{
  content: "Add retry with backoff to fetchUser",
  details: "File: src/api/user.ts, function fetchUser()
Change: Wrap fetch() in retry loop — max 3 attempts, exponential backoff 100/200/400ms
Preserve: AbortSignal passthrough, existing error types
Acceptance: bun test test/api/user.test.ts — new case for retry exhaustion + success-on-retry-2"
}
```

### Anti-pattern
```
{content: "Fix the API", details: "Look at the API and fix the issues"}
{content: "Update tests"}  // no details at all
```
#+end_example
