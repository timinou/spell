* Scope
- In scope: make CSS a first-class semantic language across `pi-code-engine` and `pi-code-graph`, including selectors, at-rules, custom properties, keyframes, and cross-file links from HTML consumers to CSS definitions.
- In scope: add graph/query semantics for cascade-sensitive reasoning: selector consumers, token definitions/usages, override chains, media/supports contexts, and dead-style analysis with explicit confidence.
- In scope: keep the model reusable for future HEEx/template hosts by consuming the HTML host/guest contract rather than teaching the graph Phoenix-specific rules.
- Out of scope: Tailwind/utility-class expansion, CSS-in-JS runtime extraction, and browser layout/render-tree simulation.

* Existing Patterns
- `crates/pi-code-graph/src/model.rs`
  - current symbol kinds and edge kinds are code-oriented; extend the canonical graph schema instead of overloading style semantics onto `References` everywhere.
- `crates/pi-code-graph/src/indexer.rs`
  - source-of-truth for graph assembly, import binding resolution, and edge creation.
- `crates/pi-code-graph/src/query.rs`
  - context/impact/flow/dead_code/clusters/symbol/file/search queries must learn style-aware summarization and confidence.
- `crates/pi-code-graph/src/language/generic.rs`
  - reusable engine-profile extractor path; CSS should use this where possible and specialize only where selector/token semantics require it.
- `crates/pi-code-graph/src/language/elixir.rs`
  - existing HEEx graph path is intentionally minimal; this item should replace brittle one-off component/tag extraction with HTML/CSS-backed semantics over time.
- `crates/pi-natives/src/code_graph.rs`
  - graph command surface and result formatting entrypoint; any new graph semantics must remain consumable from here.

* Edge Cases
- Dynamic class generation, templated class concatenation, and server-side conditional attributes must lower confidence instead of generating false dead-style claims.
- Selector matching must be token-aware and combinator-aware; substring matches are invalid.
- Override/cascade modeling must explain partial confidence when full browser specificity/layer order cannot be reconstructed from static inputs alone.
- Custom property cycles and fallbacks must be reported without infinite traversal.
- Inline style attributes should appear as high-specificity consumers, but not masquerade as stylesheet definitions.

* Acceptance Criteria
- CSS is semantic-capable locally and graph-aware across files.
- Style queries answer practical maintenance questions: who uses this selector/token, what breaks if it changes, what appears dead, and where overrides occur.
- Dead-style analysis is conservative and confidence-annotated rather than optimistic.
- The CSS/graph test suite covers all workflows and scenarios above, including mixed HTML/CSS/template fixtures.
