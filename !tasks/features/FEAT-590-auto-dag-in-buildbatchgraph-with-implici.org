* Change
- Depends on FEAT-589-subtree-aware-hasfileoverlap-with-path-n (subtree predicate shipping first).
- New pass in buildBatchGraph:
  1. Build a temporary MutableDag-like structure keyed by task id with filesDeps to invoke hasFileOverlap.
  2. For each (i, j) pair with i<j in declaration order where filesDeps overlap:
     - If j does not already list i in blockers: add an implicit edge i -> j.
     - Record { to: j.id, from: i.id, reason: first overlapping path or "filesDeps overlap" }.
  3. Merge implicit edges into blockersById; update dependentsById; re-run topological sort + cycle check.
- Return implicitBlockers as part of BatchGraph.
- scheduleBatch: forward implicitBlockers into the final result shape (see FEAT for result surface; this wave only extends the graph API).

* Edge Cases
- Explicit blocker already covers the overlap: do not duplicate; do not record as implicit.
- Overlap makes a cycle with an explicit blocker: report as scheduler error ("filesDeps overlap implies cycle"); this is a caller bug.
- Empty filesDeps on both sides: no implicit edge (policy flip).
- Transitive implicit edges: record only direct pairs; topological sort handles chains naturally.
