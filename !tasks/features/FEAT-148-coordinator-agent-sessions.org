* Implementation

** Coordinator prompt template
:PROPERTIES:
:CUSTOM_ID: FEAT-148::coordinator-prompt
:EFFORT: 1h
:END:
- File: =packages/coding-agent/src/prompts/agents/coordinator.md= (new)
- Handlebars template with variables: =subDagItems= (list of org items with CUSTOM_IDs, bodies, dependencies), =planId= (parent PLAN CUSTOM_ID), =isSimple= (boolean for 1-2 items)
- Simple variant: "Execute these org items in sequence. For each: transition ITEM->DOING, execute using task tool, verify, transition DOING->DONE, commit."
- Complex variant: "You are a coordinator managing {{subDagItems.length}} org items. Analyze dependencies. Parallelize independent items via task tool. For each item: transition ITEM->DOING, spawn task subagent, verify completion, transition DOING->DONE, commit transitional changes."
- Both variants include: org state transition instructions, verification requirements, transitional commit protocol
- Does NOT include plan-level completion (parent handles that)

** RunAgent implementation for coordinator nodes
:PROPERTIES:
:CUSTOM_ID: FEAT-148::run-coordinator
:DEPENDS: FEAT-148::coordinator-prompt
:EFFORT: 2h
:END:
- File: =packages/coding-agent/src/orchestrators/fluid/coordinator-runner.ts= (new)
- Exported function: =runCoordinator(node: FluidAgentNode, session: AgentSession, signal?: AbortSignal): Promise<SingleResult>=
- Receives FluidAgentNode with =isCoordinator: true= and =subPlan= containing the component's agents
- Builds coordinator prompt from Handlebars template + sub-DAG items (fetched via org get)
- Creates =AgentDefinition= with tools: =task=, =org=, =todo_write=, =read=, =grep=, =find=, =bash=, =lsp=, =ast_grep=, =edit=, =write=
- Calls =runSubprocess= (in-process via =createAgentSession=, NOT =Bun.spawn=)
- =todo_write= explicitly NOT in =parentOwnedToolNames= — coordinator gets its own instance
- Returns =SingleResult= to parent FluidOrchestrator for status tracking
- Passes abort signal through to the agent session

* Edge Cases
- Coordinator's agent session fails to start (model unavailable, auth error) :: coordinator marked =failed=, parent FluidOrchestrator continues other coordinators
- =todo_write= conflict :: each coordinator session has its own todo state. No collision because =runSubprocess/createAgentSession= creates isolated session state.
- Coordinator receives upstream results from parent :: not applicable — coordinators are root nodes with =dependsOn: []=. No upstream context passed.
- Very large sub-DAG (20+ items) :: coordinator prompt may be token-heavy. Recommendation: plan decomposition should aim for <15 items per component. Not enforced here.
- Coordinator transitional commits :: coordinator commits after each item completion. Parent handles final plan-level commit.
