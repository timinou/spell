* Implementation
1. Rewrite weak/stubby agents so each one declares what it is, what it sees, and how it decides.
2. Bring the whole catalog into the terse declaration-of-being style without flattening distinct roles into one generic worker voice.
3. Priority targets called out by the audit:
   - `task.md` needs a real executor voice
   - `canvas-orchestrator.md` needs scoped-assistant identity instead of pure restrictions
   - `fluid-planner.md` needs decomposer persona and sharper decomposition protocol
   - `fluid-plan-validator.md` needs evaluator voice
   - `init.md` needs documentarian/setup voice
4. Remove stale tool guidance inside agent prompts. Where agent examples or procedures mention tool choices, they must reflect the current hierarchy (`code`/`lsp`/`ast_grep`) rather than old read/grep/bash habits.
5. If the topology item determines that some current files are not real model-facing agent prompts, move them or rename them honestly instead of leaving fake prompt files in the catalog.
6. Preserve frontmatter metadata and schema expectations for spawned agents. If tool lists or descriptions are updated, keep them accurate.

* Edge Cases
- Do not homogenize specialized reviewers/critics into generic task executors. The point is consistent voice plus distinct faculties.
- If an agent intentionally remains narrow or callback-like, express that as a crisp declared function, not a placeholder.
- Keep output expectations and any structured-schema commitments intact.

* Acceptance
- Every real bundled agent prompt has a clear role, directives, procedure, and output contract in the new voice.
- Weak/stub files no longer read like template filler.
