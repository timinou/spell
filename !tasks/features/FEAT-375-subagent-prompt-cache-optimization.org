* Initial Message

is the cache control at the system level prompt? as in, is there a way to make the system prompt a cache checkpoint so that i re-use cache when I start a new session (or a new planning session for example)? do you understand me?

* Goal
Ensure subagent sessions benefit from the multi-block system prompt caching. Sibling subagents share the same stable system prompt prefix, so the first subagent's cache write benefits all subsequent siblings. The existing stagger delay (=task.cacheStaggerMs=, default 800ms) already spaces launches to allow cache warming.

* Design Decisions
- Subagent system prompt assembly in =executor.ts= wraps the base system prompt (already =SystemPromptBlock[]=) with subagent-specific overlays
- The subagent system prompt template (=subagent-system-prompt.md=) prepends the base prompt and appends Acting as / Job / Closure / Giving Up sections
- The base prompt's stable block should remain the first block, so the cached prefix is shared across siblings
- Subagent-specific content (agent override, worktree, outputSchema, contextFile) goes in a separate dynamic block
- The =systemPrompt= callback in =createAgentSession= must return =SystemPromptBlock[]= instead of a string

* Architecture

Current subagent prompt assembly (=executor.ts= line ~1098):
#+begin_src typescript
systemPrompt: defaultPrompt =>
  renderPromptTemplate(subagentSystemPromptTemplate, {
    base: defaultPrompt,
    agent: agent.systemPrompt,
    worktree: worktree ?? "",
    outputSchema: normalizedOutputSchema,
    contextFile: options.contextFile,
  }),
#+end_src

The =defaultPrompt= is the full default system prompt (from =rebuildSystemPrompt=). With the block changes, =defaultPrompt= will be =SystemPromptBlock[]= (or the joined string, depending on how the callback works).

The key insight: the subagent system prompt template takes the base prompt and wraps it:
#+begin_example
{{base}}

═══════════Acting as═══════════
{{agent}}

═══════════Job═══════════
...worktree, contextFile...

═══════════Closure═══════════
...submit_result requirements...

═══════════Giving Up═══════════
...
#+end_example

For caching, we want the FIRST block to be the stable prefix from the base prompt. Then the rest (Acting as, Job, Closure, subagent-specific) is a second dynamic block.

** =packages/coding-agent/src/task/executor.ts= — Update systemPrompt callback

The =systemPrompt= callback currently receives =defaultPrompt: string= and returns =string=. After FEAT-372, =rebuildSystemPrompt= returns =SystemPromptBlock[]=, so the callback signature needs updating.

Check how =createAgentSession= handles the systemPrompt callback in =packages/coding-agent/src/sdk.ts=. The callback receives the default prompt and returns the final prompt. With blocks:

#+begin_src typescript
// In executor.ts, the systemPrompt callback:
systemPrompt: (defaultBlocks: SystemPromptBlock[]) => {
  // Separate stable and dynamic blocks from the base prompt
  const stableBlocks = defaultBlocks.filter(b => b.stable !== false);
  const dynamicBlocks = defaultBlocks.filter(b => b.stable === false);

  // Render subagent-specific overlay
  const subagentOverlay = renderPromptTemplate(subagentSystemPromptTemplate, {
    base: "", // base is handled separately as blocks
    agent: agent.systemPrompt,
    worktree: worktree ?? "",
    outputSchema: normalizedOutputSchema,
    contextFile: options.contextFile,
  });

  // Return blocks: stable base prefix → dynamic base suffix + subagent overlay
  return [
    ...stableBlocks,
    {
      text: [
        ...dynamicBlocks.map(b => b.text),
        subagentOverlay,
      ].join("
"),
      stable: false,
    },
  ];
}
#+end_src

Wait — this changes the subagent template because =base= is no longer rendered inline. The template currently has ={{base}}= at the top. If we separate the base into blocks, we need to either:

**Option A**: Keep the template as-is, render with =base= as the joined text of all base blocks, then split the result. But this loses block boundaries.

**Option B**: Change the subagent template to NOT include ={{base}}=. Instead, the callback constructs the blocks array directly: base stable blocks first, then a dynamic block with the subagent-specific text.

**Choose Option B** — it's cleaner and preserves the stable/dynamic split:

*** Update =subagent-system-prompt.md= template
Remove ={{base}}= from the template. The template now renders ONLY the subagent-specific overlay:

{{/if}}

{{SECTION_SEPERATOR "Job"}}
You are operating on a delegated sub-task.

#+end_example

*** Update =executor.ts= callback
#+begin_src typescript
import type { SystemPromptBlock } from "@oh-my-pi/pi-ai";
import { systemPromptText } from "@oh-my-pi/pi-ai";

// In the systemPrompt callback:
systemPrompt: (defaultBlocks: SystemPromptBlock[]) => {
  // Render subagent overlay (without base — it's in the blocks)
  const overlay = renderPromptTemplate(subagentSystemPromptTemplate, {
    agent: agent.systemPrompt ?? "",
    worktree: worktree ?? "",
    outputSchema: normalizedOutputSchema,
    contextFile: options.contextFile,
  });

  // Stable base blocks stay as-is for cache reuse across siblings
  const stableBlocks = defaultBlocks.filter(b => b.stable !== false);

  // Dynamic = base dynamic blocks + subagent overlay
  const dynamicTexts = defaultBlocks
    .filter(b => b.stable === false)
    .map(b => b.text);
  dynamicTexts.push(overlay);

  const result: SystemPromptBlock[] = [...stableBlocks];
  if (dynamicTexts.length > 0) {
    result.push({ text: dynamicTexts.join("
"), stable: false });
  }
  return result;
}
#+end_src
