* Context

Skill frontmatter supports =globs= (e.g., =["**/*.typ"]=) and the discovery system parses them, but the extensibility =Skill= interface drops them during the =CapabilitySkill → Skill= mapping. The system prompt builder includes ALL discovered skills unconditionally. This means skills like the Typst skill waste prompt tokens in projects that have no =.typ= files.

No existing skills in =.spell/skills/= currently set =globs=, so adding conditional filtering is backward-compatible. The Typst skill (=.spell/skills/typst/SKILL.md=) is the first to use it.

** 3. Filter in system-prompt.ts

File: =packages/coding-agent/src/system-prompt.ts=. After skills are loaded (around line 471 where =skills= is assigned), filter them:

#+begin_src typescript
// Filter skills by globs: skills with globs only load when matching files exist
skills = skills.filter(skill => {
    if (!skill.globs || skill.globs.length === 0) return true;
    return skill.globs.some(pattern => {
        const scan = new Bun.Glob(pattern).scanSync({ cwd: resolvedCwd, onlyFiles: true });
        for (const _ of scan) return true;
        return false;
    });
});
#+end_src

This uses =Bun.Glob.scanSync= with lazy iteration — stops on first match for performance.

** 4. Filtering rules

- =globs= undefined or empty array → always include (backward compatible)
- =globs= non-empty → include only when at least one file in project cwd matches any pattern
- No separate =alwaysApply= handling needed — skills that want to always load should not set =globs=
