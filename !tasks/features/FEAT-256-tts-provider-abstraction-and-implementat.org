Create a TTS provider interface and two implementations: ElevenLabs and Deepgram Aura. These accept text and return audio bytes suitable for Telegram's =sendVoice= (OGG Opus preferred, MP3 fallback).

* Design

** Interface

interface TtsResult {
  audio: Buffer;
  mimeType: string;  // "audio/ogg" or "audio/mpeg"
  duration?: number; // seconds, if known
}

interface TtsProvider {
  /** Synthesize text to audio */
  synthesize(text: string, options?: {
    voice?: string;  // override default voice
  }): Promise<TtsResult>;
}

** ElevenLabs Implementation
- HTTP POST to =https://api.elevenlabs.io/v1/text-to-speech/{voice_id}=
- Headers: =xi-api-key: <api-key>=, =Content-Type: application/json=, =Accept: audio/mpeg=
- Body: ={"text": "...", "model_id": "<model>", "voice_settings": {"stability": 0.5, "similarity_boost": 0.75}}=
- Response: raw audio bytes (MP3 by default)
- Voice ID resolution: =config.voice= is the voice ID string (e.g. ="rachel"=, ="21m00Tcm4TlvDq8ikWAM"=)
- For OGG output: set =output_format=opus_48000= query parameter (ElevenLabs supports direct Opus)

** Deepgram Aura Implementation
- HTTP POST to =https://api.deepgram.com/v1/speak=
- Headers: =Authorization: Token <api-key>=, =Content-Type: application/json=
- Query params: =model= (e.g. =aura-asteria-en=)
- Body: ={"text": "..."}=
- Response: raw audio bytes
- Default output is MP3; for OGG Opus, add =encoding=opus= and =container=ogg= query params

** Audio Format Strategy
- Telegram's =sendVoice= prefers OGG Opus (displays as voice bubble)
- Both ElevenLabs and Deepgram Aura support direct Opus output
- Request OGG Opus from providers directly -- no ffmpeg conversion needed
- Fallback: if provider returns MP3, send as-is (Telegram accepts it but may display differently)

** Telegram Message Length Constraint
- Long agent responses should be truncated before TTS (providers have text limits)
- ElevenLabs: ~5000 chars per request
- Deepgram Aura: ~2000 chars per request
- Truncate with ellipsis if needed, log a warning
