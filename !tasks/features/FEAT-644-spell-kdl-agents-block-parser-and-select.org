* Scope
- In-scope:
  - Schema: `agents { rule "<selector>" [disabled=#true] { model "..."; thinking-level "..."; tools "a" "b" "c" } }`.
  - Selector forms: bare string. Auto-detect: contains `*` or `?` → glob; otherwise exact match.
  - Specificity ranking (highest → lowest): exact > prefix-only glob (`name*`) > suffix-only glob (`*name`) > infix (`*name*`) > catch-all (`*`).
  - Tie-breaking within the same specificity bucket: last declared wins. Conflicting same-bucket ties get a `logger.warn` and surface a `conflicts: AgentRuleConflict[]` field on the parsed config for TUI consumption (FEAT-647).
  - User and project spell.kdl both contribute rules; merging handled by FEAT-646. This item only parses one document and returns its rule list.
- Out-of-scope:
  - `spawns` overrides (security-sensitive, deferred to FUP).
  - `prepend-tools` / `append-tools` (deferred to FUP).
  - Per-parent context rules (`when explore spawns reviewer ...`) (deferred to FUP).
  - Wiring rules into `TaskTool.#executeSync` (FEAT-646).

* Edge Cases
- Selector `"*"` is wildcard, not infixGlob — handle separately.
- Empty `agents { }` block: parsed as zero rules, no conflicts, no warnings.
- Malformed rule (e.g. selector arg missing): skipped with warning, parsing continues.
- Same selector declared twice (e.g. two `rule "explore"`): both parsed, second wins via last-declared, recorded as conflict with `selectors: ["explore", "explore"]`.
- Conflicting overrides across user + project: handled in FEAT-646 by merging into one rule list before matching; same conflict detection applies.
- KDL-side `tools` with empty variadic args (`tools`) is treated as "explicit empty tool list" — distinct from omitted `tools` key. Document in DEVELOPMENT.md (FEAT-648).
- `thinking-level "invalid"` → `parseThinkingLevel` returns undefined → field omitted from rule, logger warning.
