* Intention & Purpose

Treat =~/.spell/personal/= as a second org root that lives alongside the
per-repo =.spell/memory/= store. Concepts, entities, and actors defined
in personal are referenceable from any repo via stable CUSTOM_IDs.
Recall scope unions personal + per-cwd by default. No daemon, no
namespacing, no cross-machine sync — that is the user's responsibility
(rsync, git in =~/.spell/personal/.git=, or none).

* Context & Narrative

Spec: =specs/org-graph-memory.md=. Layout:

- =~/.spell/personal/concepts/<slug>.org=
- =~/.spell/personal/entities/<kind>/<slug>.org=
- =~/.spell/personal/actors/<handle>.org=

Collision policy: per-cwd shadows personal if the same =CUSTOM_ID= exists
in both. This lets a repo override a personal concept when needed
without touching the personal source.

The id-resolver lives in =pi-org-engine::locate=. Today it indexes a
single root. This FEAT adds a second root and a precedence rule. Recall
fans out to both roots and unions hit lists before RRF fusion (each
lane is run per-root and combined; this preserves ranking semantics).

* Scope

In scope:
- =crates/pi-org-engine/src/locate.rs= — multi-root id index + precedence
- New helper =resolvePersonalRoot()= in TypeScript = =~/.spell/personal/=
- =crates/pi-org-recall/src/personal.rs= (new) — wraps two RecallContexts and unions hits
- =RecallQuery.include_personal= flag honored (default true; configurable via spell.kdl)
- =executeOrg::remember= writes concept items to =resolvePersonalRoot()/concepts/= when called with =scope: "personal"= argument
- Tests under =crates/pi-org-engine/tests/locate_personal.rs= and =crates/pi-org-recall/tests/personal.rs=

Out of scope:
- Cross-machine sync (out of v1; documented as user-responsibility)
- Personal store schema validation (entities can be schemaless)
- Migrating existing personal data (none exists; greenfield)

* Existing Patterns

- =locate.rs= already builds an id → file map per root. Generalize to =Vec<(RootScope, HashMap<ItemId, PathBuf>)>=.
- =RecallContext= from FEAT-636 takes a single items snapshot. Either make =RecallContext::personal: Option<Box<RecallContext>>= or build two contexts and run lanes over both. Choice: separate contexts, fuse at the RRF input layer (cleaner for tracing).
- Home dir resolution: =home::home_dir()= via the =home= crate (already a dep transitively via several places; verify).

* Edge Cases

- =~/.spell/personal/= does not exist: =DualContext.personal= is None; recall behaves as cwd-only
- Symlink loop in personal: locate must not follow into the same dir twice (canonicalize during scan)
- File in personal contains an id that also appears in cwd: lookup returns cwd; recall dedupes
- =remember(scope: "personal")= without write permission to ~/.spell/personal/: surface =RememberError::Permission= with hint
- Personal store on a different filesystem than cwd: blob references using relative paths break; v1 sticks to absolute paths and documents the limitation
- Performance: 2x recall lanes when personal exists; RRF fusion already linear; total stays well under the 200 ms budget for 10k+10k items
