* Initial Message

the /move command should also move where tools liek the Org tool save their files

* Problem
OrgTool captures ~session.cwd~ at construction time and passes it as ~projectRoot~ to ~createOrgTool()~. The inner ~OrgContext.projectRoot~ is a static string used by ~resolveCategories(config, projectRoot)~ to determine where ~.org~ files are saved. After ~/move~, org files continue saving to the old directory.

* Approach
OrgTool stores the session reference and tracks the ~projectRoot~ it was initialized with. On each ~execute()~, it compares ~session.cwd~ to the tracked root. If changed:
1. Dispose old inner tool (~#inner.dispose()~)
2. Reload org config via ~loadOrgConfig(session)~ (new project may have different settings)
3. Recreate ~#inner~ via ~createOrgTool(newRoot, newConfig, { emacsSessionManager: session.orgSessionManager, ... })~
4. Reuse the existing ~EmacsSessionManager~ (Emacs daemon is project-agnostic for org — it just runs org-mode Elisp commands on whatever files you point it to; ~resolveCategories~ in TypeScript determines the file paths)

#+begin_src typescript
#recreateForNewRoot(newRoot: string): void {
    // Dispose old inner tool (closes OrgClient if open)
    this.#inner.dispose?.();

    const config = loadOrgConfig(this.#session);
    const orgSessionManager = this.#session.orgSessionManager
        ?? createOrgSessionManager(
            this.#session.settings.get("org.emacsPath") as string | undefined || undefined,
            newRoot,
            this.#session.getSessionId?.() ?? "default",
        );

    this.#inner = createOrgTool(newRoot, config, {
        emacsSessionManager: orgSessionManager,
        ownsSessionManager: !this.#session.orgSessionManager,
        getSessionContext: () => buildSessionContext(this.#session),
    });
    this.#currentProjectRoot = newRoot;
    this.description = this.#inner.description;
}
#+end_src

*** Ensure dispose() is safe:
The existing ~dispose()~ calls ~this.#inner.dispose?.()~. After cwd change and recreation, the new ~#inner~ is the one disposed. The old one was already disposed in ~#recreateForNewRoot~. This is correct and idempotent.

* Edge Cases
- **Session without orgSessionManager**: When ~session.orgSessionManager~ is null, ~createOrgSessionManager~ is called with the new root. This creates a new Emacs daemon session manager for the new project. The old one was already disposed via ~#inner.dispose()~ (if ~ownsSessionManager~ was true).
- **Rapid /move calls without org execute**: No overhead — recreation only happens on next execute, not on every /move.
- **Org emacs not available**: ~createOrgTool~ handles this gracefully; the tool returns errors on execute if Emacs is unavailable.
- **Config differences**: ~loadOrgConfig(session)~ reads from session settings which are session-global; project-local org config would need separate handling (out of scope, tracked by existing org config infrastructure).
