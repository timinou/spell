#+begin_example
{{curly "#if waves"}}
## Wave-Based Execution

This plan uses wave-based decomposition for cross-item parallelism.

When initializing `todo_write`:
- Create one phase per wave, named after the wave
- Each wave entry becomes a task in that phase
- Set `orgItemId` on each task to the entry's orgItemId
- For cross-wave dependencies: if an org item appears in wave N and wave N-1, the wave N task MUST have a blocker on the wave N-1 task for the same orgItemId
- Tasks within the same wave are independent -- parallelize via `task` subagents with `todoRef`
- Read each child org item via `org get` to populate task details from the matching implementation step

### Waves
{{curly "#each waves"}}
#### {{curly "name"}}
{{curly "#each entries"}}
- `{{curly "orgItemId"}}` -- {{curly "step"}}
{{curly "/each"}}
{{curly "/each"}}
{{curly "/if"}}
#+end_example

Note: replace =curly= with actual Handlebars syntax (={{= / =}}=) during implementation. The example uses placeholder to avoid template processing.

* Edge Cases
- Plan with no waves: executor falls back to current 1-task-per-item behavior (Handlebars guard)
- Plan with single-entry waves: works but degenerates to current behavior with phases
- Asymmetric wave coverage (item A in all 3 waves, item B only in wave 1): blocker graph is correct -- item B task has no cross-wave blockers
- Wave with zero entries: skip phase creation (empty phases are noise)
