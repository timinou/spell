* Context

PLAN-173 delivered =SwarmScheduler= with 6 test cases, but three critical scenarios lack coverage: dynamic node mutation during an active pump cycle, multi-level failure cascade, and concurrent abort with active tasks. These are the scheduler's most novel contracts and the most likely to regress.

Current test cases in =packages/coding-agent/test/task/swarm-scheduler.test.ts=:
1. Static DAG pump
2. Multi-entry readiness + dynamic node mutation (but not DURING pump)
3. Data node satisfaction + single-level failure cascade
4. File overlap serialization
5. Opaque work serialization (no filesDeps)
6. Abort signal

** Design Decisions

1. Tests use the existing =NodeLike= interface and =SwarmScheduler= constructor from the test file.
2. For "during active pump" tests, use =Promise.withResolvers()= gates inside the =runNode= callback to hold tasks in-flight while mutations are applied externally.
3. Failure cascade test uses a 3-node chain: A→B→C. Fail A, assert B and C both receive =failed= status.
4. Dynamic removeNode test: while A is running, remove B (depends on A). After A completes, verify B's dependents (if any) were cascade-removed or orphaned.
5. Dynamic addNode test: while A is running, add D (depends on A). After A completes, verify D becomes ready and is dispatched.
