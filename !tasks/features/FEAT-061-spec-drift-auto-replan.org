* Initial Message

from what I understand, the loop mode of the coding agent should base itself off of specs directories and keep track of itself through successive planning/ultraplanning, and leverage org to know which tickets in the specs are done/taken/etc, and builds a manifest for the gates based off of the specs, with the ability to complete the manifest at loop creation before formally launching (like a plan but for the loop). Is that true? If not, what does it do currently, and what would it take to take it there?

Ask me as many questions as humanly/agentically possible

* Scope
Enhance spec drift detection to auto-pause, re-run manifest generation on changed specs, merge changes preserving completed tickets, and commit the replan.

** In-Scope
- Enhanced drift detection: compare current spec content hashes against snapshot (existing =git/drift.ts=)
- On drift detected:
  1. Pause the loop
  2. Re-parse changed spec files
  3. Merge into existing manifest:
     - Preserve DONE tickets (completed work is immutable)
     - Preserve DOING tickets (in-progress work continues)
     - Update ITEM/BLOCKED tickets if their spec changed
     - Add new tickets from new specs
     - Remove tickets whose specs were deleted (mark as HOLD with reason)
  4. Present diff to user for approval (if auto-approve is off) or auto-approve
  5. Stage and commit manifest with =\ud83d\udd04 loop(replan): manifest updated after spec drift= message
  6. Resume loop
- Manifest version increment on replan
- Event log: =manifest.replanned= event with added/removed/modified ticket counts
- Safeguard integration: drift check runs in =checkSafeguards()= pipeline (existing hook point)

** Out-of-Scope
- Drift detection for non-spec files (only spec org files are tracked)
- Manual manifest editing (user edits go through org tool during manifest_building)

* Tests
Test file: =packages/coding-agent/test/loop/spec-drift-replan.test.ts=

** Scenarios
1. No drift: all hashes match, no action taken
2. Spec modified: re-parse, merge, preserved DONE tickets, updated ITEM ticket
3. New spec added: new ticket added to manifest
4. Spec deleted: orphaned ticket marked HOLD
5. DOING ticket's spec changed: ticket stays DOING, findings updated
6. Manifest version incremented after replan
7. Git commit with correct emoji and message
8. Auto-approve off: loop stays paused until user approves replan

* Edge Cases
- Drift detected during manifest_building: re-parse but don't pause (we're already building)
- Spec file encoding changes but content identical: hash still matches, no drift
- Replan while child loop is active: pause parent and child, replan, resume
- Git not available: skip commit, still replan manifest in memory
