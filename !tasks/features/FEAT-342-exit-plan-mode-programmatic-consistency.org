* Problem

The current ~exit-plan-mode.ts~ validates:
1. Plan mode is active
2. Title is valid
3. Plan item exists (if org enabled)
4. Plan has at least one ~[[id:...]]~ child link
5. All linked child items exist

But it does NOT validate:
- Child items have non-empty bodies
- Dependency chains are acyclic and complete
- DEPENDS properties reference items that actually exist in the plan
- Child items have required properties (EFFORT, PRIORITY, LAYER)
- The Execution Manifest references all child items (no orphans)

In the observed session, the agent called exit_plan_mode with items that were stale, had wrong dependency chains, and missing required fields. The tool returned success, and the user had to manually catch the problems.

const childIdSet = new Set(childItemIds);
const brokenDeps: string[] = [];
for (const childItemId of childItemIds) {
    const childItem = await resolvePlanItem(this.session.settings, this.session.cwd, childItemId);
    if (!childItem) continue;
    const depends = childItem.properties.DEPENDS;
    if (!depends) continue;
    const depIds = depends.split(/\s+/).filter(Boolean);
    for (const depId of depIds) {
        if (!childIdSet.has(depId)) {
            brokenDeps.push(`${childItemId} depends on ${depId} which is not in this plan`);
        }

}

${brokenDeps.join("
")}
All DEPENDS must reference items linked in this plan.`
    );
}
