* Scope
Add a new top-level KDL node ~action-descriptor~ to the manifest parser so projects can declare action descriptors directly in autonomy.kdl (or imported KDL files) instead of requiring imperative TypeScript registration.

** Current state
- Action descriptors are defined in TypeScript via ~ActionDescriptor~ objects and registered via ~ActionRegistry.register()~
- ~ActionRegistry~ enforces ~source === "first-party"~ on all registrations
- ~createServerActionRegistry()~ in ~packages/spell-server/src/actions/index.ts~ hardcodes a call to ~registerGrowthActions()~ from ~@oh-my-pi/spell-growth~
- The manifest parser already knows how to parse ~action~ blocks inside goals (params, param-list, param-json, prompt, prompt-file)
- The validator already validates action params against the registry

** Design
Add a new top-level node ~action-descriptor~ to the manifest grammar:

#+begin_src kdl
action-descriptor "growth.discovery" source="project"
action-descriptor "growth.feed.send" source="project" {
    param "maxItems" type="number"
    param "dryRun" type="boolean"
    prompt-slot "context" required=#true
}
#+end_src

*** Parser changes
In ~parseManifestModuleDocument()~ (parser.ts), add a new branch for ~nodeName === "action-descriptor"~:
- Parse the action ID as the first string argument
- Parse ~source~ property (default ~"project"~)
- Parse child ~param~ nodes into ~ActionParameterDescriptor~ (type + required)
- Parse child ~prompt-slot~ nodes into ~ActionPromptSlotDescriptor~ (required)
- Store descriptors in a new ~actionDescriptors~ field on ~ParsedManifestModule~

*** Registry changes
- Widen ~ActionDescriptor.source~ type from ~"first-party"~ to ~"first-party" | "project"~
- ~ActionRegistry.register()~: accept both ~"first-party"~ and ~"project"~ source values
- Keep ~createBuiltinActionRegistry()~ unchanged (only built-in actions)
- Remove ~createServerActionRegistry()~ entirely (it was only for hardcoding growth)

*** Import resolver changes
In ~resolveManifestModule()~ (import-resolver.ts):
- After parsing the module, register any ~action-descriptor~ nodes into the ~context.registry~ before validating goals
- Imported modules can declare action descriptors that become available to the importing module's goals
- Prefix imported action descriptors with the import alias (e.g., ~growth.discovery~ from ~import "./growth.kdl" as="growth"~)

*** Config loader changes
In ~loadConfig()~ (config/loader.ts):
- Replace ~createServerActionRegistry()~ with ~createBuiltinActionRegistry()~
- The manifest loader now registers project-declared descriptors during parsing
