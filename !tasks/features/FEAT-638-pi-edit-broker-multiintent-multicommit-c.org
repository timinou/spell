* Intention & Purpose

Extend =pi-edit-broker= with cross-file atomic transactions:
=MultiIntent=, =MultiCommit=, =MultiIntentAck=, =MultiCommitAck=,
=MultiPeerCommitted=. All-or-nothing acquire on N files; staged commit
via .tmp paths + atomic renames; crash recovery via the existing
=pi-code-engine::coord::journal=. This unblocks =remember()= writes
that touch both an episode file and a concept file in one transaction.

* Context & Narrative

Spec: =specs/org-graph-memory.md=. The broker today (=protocol.rs=,
=server.rs=, =conn.rs=, =state.rs=) provides per-file =Intent=/=Commit=
with =IntentConflict= / =CommitConflict= peer awareness. Consumers in
=pi-code-engine::coord::socket= already use it. This FEAT layers a
transaction id on top so an N-file edit either fully lands and emits
=MultiPeerCommitted= or fully rolls back leaving no partial state.

The journal infrastructure exists at =pi-code-engine/src/coord/journal.rs=
(107 LOC). Extend it to record per-txn entries; the broker reaper
already runs as a sibling task and will be enhanced to detect
abandoned transactions.

* Existing Patterns

- =protocol.rs= NDJSON discriminated union with =#[serde(tag = "type", rename_all = "snake_case")]=. Add new variants in the same enum.
- =state.rs::BrokerState= already tracks =active_intents: HashMap<(SessionId, PathBuf, CodePath), IntentRecord>=. Extend with =active_txns: HashMap<TxnId, TxnState>=.
- =reaper.rs= owns the =broadcast::Sender<BrokerEvent>=; reuse to fire =MultiPeerRolledBack= on abandoned txns.
- =journal.rs= already serializes per-file commit log entries; add =JournalEntry::TxnStarted=, =TxnCommitted=, =TxnRolledBack= variants.
- Atomic rename: =std::fs::rename= is atomic on same filesystem; document the same-fs precondition. Bun-side writers must observe this.

* Edge Cases

- TxnId collision (client mints same ULID twice): broker rejects with =MultiIntentAck { granted:false, conflicts:[{code:"DUP_TXN"}] }=
- Cross-filesystem rename (.tmp on tmpfs, target on disk): document precondition; tooling stages .tmp in same directory as target
- Disk full during second-of-two renames: detect, restore first from backup, journal as RolledBack
- Broker crashes mid-rename: journal replays and matches actual fs state; if first rename succeeded, restore from hash backup
- Two clients each open MultiIntent overlapping files in opposite order: classic lock-order deadlock impossible because grant is atomic (acquire-all-or-none)
- TTL passes during commit: refuse commit, rollback; client must re-intent
