* Goal

Rewrite the org tool's TS adapter (=packages/coding-agent/src/tools/org.ts= and
=packages/org/src/tool.ts=) to call the new native buffer-backed org commands
instead of the TS =org-reader.ts= and =org-writer.ts=.

* Current architecture (to be replaced)

=tool.ts= dispatches 13 commands:
- Reads: =query=, =get=, =dashboard=, =validate=, =wave=, =graph=, =archive=
  - Use =org-reader.ts= (TS line-state-machine parser) for item extraction
  - Call native =executeOrg= only for graph/wave algorithms
- Writes: =create=, =update=, =note=, =set=
  - Use =org-writer.ts= (TS line-array mutator) for all file mutations
- Init: =init=
  - Creates directory structure and reference.org file

* New architecture

** Write commands

Replace =org-writer.ts= calls with native NAPI commands:

| TS function | Native command |
|---|---|
| =appendItemToFile()= | =executeOrg({command: \"createItem\", file, ...})= |
| =applyItemMutations()= | =executeOrg({command: \"updateItem\", file, id, state, title, body, append})= |
| =setPropertyInFile()= | =executeOrg({command: \"setProperty\", file, id, property, value})= |
| Note (via update) | =executeOrg({command: \"appendNote\", file, id, note})= |
| Section edit | =executeOrg({command: \"editSection\", file, id, section, body, mode})= |

The native commands handle: open buffer → locate item → produce TextEdits →
apply → save. The TS side just calls and handles the response.

** Read commands

Replace =org-reader.ts= calls with native parsing:

| TS function | Native replacement |
|---|---|
| =readOrgFile()= | =executeOrg({command: \"parse\", file, ...})= (already exists but takes source, change to accept file path) |
| =readCategory()= | Loop over =.org= files in category dir, call parse on each |
| =findItemById()= | =executeOrg({command: \"findItem\", id, dirs})= (new native command) |

** Category and ID logic stays in TS

=categories.ts= (resolveCategories, findCategory, findCategoryForId), =id-generator.ts=
(generateId), and directory scanning remain in TypeScript — they're filesystem/config
operations, not parsing.

* Migration sequence

1. Add file-path-based parsing to native =executeOrg= (instead of requiring source string)
2. Replace write operations one by one: create → update → set → note
3. Replace read operations: use native parse for item extraction
4. Remove =org-reader.ts= imports from =tool.ts=
5. Remove =org-writer.ts= imports from =tool.ts=
6. Verify all 13 commands still work
