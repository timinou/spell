* Initial Message

kk look online what code-specific vector embeddings do and how that could help with the `code search` task

* Goal
Integrate vector search from =pi-code-vectors= into =pi-code-graph='s search API.
When a vector index is available, =code search= uses hybrid BM25 + cosine similarity
with Reciprocal Rank Fusion (RRF) and graph-aware re-ranking.
When vectors are unavailable, search falls back to BM25-only (no regression).

* Background
=pi-code-graph/src/search.rs= currently implements BM25 over symbol qualified names and file paths.
The =SearchIndex= is built in-memory from =PersistedCodeGraph= when =CodeGraph::new()= is called.
=pi-code-graph/src/query.rs= has =GraphSearchMatch= as the output type for the =search= command.

The graph has rich structural edges: =Defines=, =Imports=, =Calls=, =References=, =Inherits=,
=Renders=, =TypeImports=, =TypeParameterOf=. These can boost search results — if a top vector
hit calls another function, that callee is likely relevant too.

* Design Decisions
- Hybrid scoring uses Reciprocal Rank Fusion (RRF): =score(d) = Σ 1/(k + rank_i(d))= with k=60
- RRF is the industry standard for merging heterogeneous rankers — simple, parameter-light, proven
- Graph re-ranking: after RRF, boost nodes that are direct neighbors (via =Calls=, =References=,
  =Imports=) of the top-5 results. Boost factor: 0.3 * max_rrf_score for direct callers/callees,
  0.1 * max_rrf_score for same-file siblings
- =pi-code-graph= gains an *optional* dependency on =pi-code-vectors= behind a cargo feature flag =semantic=
- =CodeGraph= struct gains an optional =VectorIndex= field
- The public API remains backward-compatible — =CodeGraph::new(persisted)= still works without vectors

*** Updated search API (in query.rs)
#+begin_src rust
impl CodeGraph {
    /// Search the graph. When `query_vector` is provided and a vector index is
    /// loaded, uses hybrid BM25 + cosine + graph re-ranking. Otherwise BM25-only.
    pub fn search(
        &self,
        query: &str,
        query_vector: Option<&[f32]>,
        limit: usize,
    ) -> Vec<GraphSearchMatch> {
        #[cfg(feature = "semantic")]
        if let (Some(vector_index), Some(qv)) = (&self.vector_index, query_vector) {
            return self.hybrid_search(query, qv, vector_index, limit);
        }
        // Fallback: BM25 only (existing behavior, ignores query_vector)
        self.bm25_search(query, limit)
    }
}
#+end_src

*** RRF fusion function

const RRF_K: f32 = 60.0;

fn reciprocal_rank_fusion(
    bm25_hits: &[SearchHit],
    vector_hits: &[VectorSearchHit],
    limit: usize,
) -> Vec<HybridSearchHit> {
    // 1. Build a map: node_index -> (bm25_rank, vector_rank)
    // 2. For each unique node_index, compute RRF score:
    //    score = 1/(RRF_K + bm25_rank) + 1/(RRF_K + vector_rank)
    //    where rank is None -> contribution is 0
    // 3. Sort by score descending, truncate to limit
}

*** Graph-aware re-ranking
#+begin_src rust
fn graph_rerank(
    hits: &mut Vec<HybridSearchHit>,
    graph: &StableGraph<GraphNode, EdgeKind>,
    top_k: usize,       // default: 5
    boost_factor: f32,   // default: 0.3

    // 1. Collect node indices of top-K hits as anchors
    // 2. For each anchor, find direct neighbors via Calls, References, Imports edges
    // 3. For hits that are neighbors of anchors: add boost_factor * max_score
    // 4. For hits in same file as anchor: add 0.1 * max_score
    // 5. Re-sort by updated score
}

* Edge Cases
- Vector index is None (not built yet) -> pure BM25, zero change from today
- Query matches BM25 but not vectors -> RRF still includes BM25-only hits (vector_rank = None)
- Query matches vectors but not BM25 -> RRF still includes vector-only hits (bm25_rank = None)
- Node index in vector results not found in graph (stale vectors) -> skip that entry
- Empty query -> return empty (as today)
