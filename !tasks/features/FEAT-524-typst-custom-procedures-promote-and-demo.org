* Initial Message

looking at the typst and org integrations to pi-code-engine, what would you want to implement for your markdown usage to be a delight?

* Context

This feature proves the procedure DSL extension point from [[id:FEAT-522-procedure-dsl-transform-layer-with-decla]] works across languages by registering promote/demote heading operations on the existing Typst profile.

Typst headings use ~=~ markers: ~= Title~ (h1), ~== Subtitle~ (h2), ~=== Section~ (h3), etc. Promotion removes one ~=~, demotion adds one.

** Design Decisions

- Typst headings are ~heading~ nodes containing a marker child (not a named field — the ~=~ characters are part of the heading node text)
- In tree-sitter-typst, the heading node type is ~heading~. The marker text is the leading ~=~ characters. There is no separate ~heading_marker~ node type — the equals signs are anonymous tokens
- Since there's no separate marker node to select, the procedure needs to target the ~heading~ node itself and transform its leading ~=~ characters
- Promote: ~Transform::Custom~ that strips one leading ~=~ from the heading node text. Custom needed because we must preserve everything after the markers
- Demote: ~Transform::Custom~ that prepends one ~=~ to the heading node text
- Alternative: use ~Transform::RegexReplace { pattern: "^(=+)", replacement: ... }~ — but regex doesn't easily express "remove one char from a capture group." Custom is cleaner here

NOTE: Verify the actual tree-sitter-typst AST structure for headings before implementing. The heading markers might be separate nodes or part of the text. Check ~crates/pi-code-engine/tests/fixtures/sources/hello.typ~ or create a test fixture.

* Scope

** ~crates/pi-code-engine/src/language/mod.rs~ — in ~typst_profile()~

*** Register ~promote~ procedure

#+begin_src rust
procedures.insert("promote".into(), Procedure::builder()
    .name("promote")
    .description("Decrease heading level in Typst (=== → ==)")
    .activate(|a| a.nodes(types(&["heading"])))
    .select(|s| /* select heading node itself or marker child */)
    .transform(Transform::Custom(Box::new(|text, _options| {
        // Remove one leading '=' if level > 1
        if text.starts_with("==") {
            Ok(text[1..].to_string())
        } else {
            Err(crate::CodeEngineError::Edit(
                "Cannot promote h1 heading".into()
            ))
        }
    })))
    .build()
);
#+end_src

*** Register ~demote~ procedure

#+begin_src rust
procedures.insert("demote".into(), Procedure::builder()
    .name("demote")
    .description("Increase heading level in Typst (== → ===)")
    .activate(|a| a.nodes(types(&["heading"])))
    .select(|s| /* select heading node itself or marker child */)
    .transform(Transform::Custom(Box::new(|text, _options| {
        // Add one leading '='
        // Typst has no hard limit on heading levels, but cap at 6 for sanity
        let level = text.chars().take_while(|c| *c == '=').count();
        if level >= 6 {
            Err(crate::CodeEngineError::Edit(
                "Cannot demote beyond h6".into()
            ))
        } else {
            Ok(format!("={text}"))
        }
    })))
    .build()
);
#+end_src

* Edge Cases

- Typst heading with content on same line: ~= Title~ — the ~=~ and title are part of the same node. Transformation must preserve the space and title text
- Headings in Typst can have inline content (bold, etc.): the transformation only affects the leading ~=~ characters
- Nested show/set rules under headings: these are not headings and should not be affected by promote/demote

* Acceptance Criteria

- ~code edit { symbol: "Section One", operation: "promote" }~ changes ~==~ to ~=~
- ~code edit { symbol: "Top Level", operation: "demote" }~ changes ~=~ to ~==~
- Boundary validation works (h1 promote, h6 demote)
- Existing Typst outline and edit tests unaffected
- This proves the procedure DSL is language-agnostic — same dispatch mechanism works for both markdown and typst
- ~cargo test -p pi-code-engine~ passes
