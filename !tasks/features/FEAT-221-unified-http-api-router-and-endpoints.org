* Scope
** In scope
- Single =Bun.serve()= router in =packages/spell-server/= that dispatches frontend index, goals API, trigger routes, and reused session log viewer routes
- Reuse log viewer renderer from =@oh-my-pi/telegram-bridge= for =/sessions/*= transcript pages instead of duplicating rendering logic
- Goals API endpoints: =GET /api/goals=, =GET /api/goals/:id=, =GET /api/goals/:id/runs=, =GET /api/goals/:id/logs=
- Trigger endpoints: =POST /trigger/:goal= for executor-driven manual or webhook activation
- Auth middleware for three cases: Basic Auth on API routes, HMAC signature verification for webhook trigger requests, per-goal bearer token support
- Local-dev response headers for API and trigger routes
** Out of scope
- Session restart endpoints (follow-up FUP)
- Pause/resume/delete management endpoints (follow-up FUP)
- WebSocket or SSE streaming
** Boundary
- HTTP API is the external interface for autonomy.
- Router reads state from scheduler and executor, and trigger routes call executor to start work.
- Dedup/conflict decisions remain owned by executor; the API surfaces executor truth as HTTP status codes.

* Edge Cases
- Request to unknown route returns JSON =404= response
- Malformed JSON body in trigger POST returns =400= with explicit error message
- Very large request body is rejected above 1MB before full buffering
- Concurrent triggers for same goal rely on executor dedup; API returns =409 Conflict=
- Missing auth header vs malformed auth header remain distinguishable to callers
- HMAC must use exact raw bytes received, not parsed/re-serialized JSON
- CORS is not required for production/internal use, but local-dev access-control headers should be present
