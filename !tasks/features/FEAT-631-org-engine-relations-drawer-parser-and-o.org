* Intention & Purpose

Add a first-class RELATIONS drawer to the org parser so org items can
declare typed edges (INVOLVED, ABOUT, PRODUCED, DISTILLED_FROM, MENTIONS,
SUPERSEDES, DERIVED_FROM, BLOCKS, ACTION) inline in the source file.
This is the foundation every other v1 FEAT depends on: typed-graph
traversal, hybrid recall, episode/concept memory writes, and live
subscription patches all read this field.

* Context & Narrative

Spec: =specs/org-graph-memory.md=. Existing parser
(=crates/pi-org-engine/src/buffer.rs=, =item.rs=) only surfaces
=properties= (key→string) and =body=. Edges today are encoded only via
the legacy =BLOCKERS: a b c= property and ad-hoc body =[[id:…]]= links;
neither is queryable as typed graph data. The renewed model encodes
edges as drawer lines with one =KIND: target-id= per line, terminated
by =:END:=, sitting next to the PROPERTIES drawer. Multiple lines with
the same kind = multiple targets. Targets are bare =CUSTOM_ID= strings
(no double-bracket id wrap).

* Scope

In scope:
- =crates/pi-org-engine/src/item.rs=: add =relations: Vec<(EdgeKind, ItemId)>= to =OrgItem=
- =crates/pi-org-engine/src/edge.rs= (new): =EdgeKind= enum + parser/Display
- =crates/pi-org-engine/src/buffer.rs=: extend drawer scanner to recognize the RELATIONS drawer alongside the existing PROPERTIES and LOGBOOK drawers
- Translate legacy =BLOCKERS= property into =EdgeKind::Blocks= edges at parse time so existing wave/DAG code keeps working without callsite changes
- Tests under =crates/pi-org-engine/tests/relations.rs=

Out of scope:
- Graph traversal (neighborhood, timeline, path) — that's FEAT-632
- Writing edges back to disk via editSection — that's FEAT-637 / FEAT-639
- Schema validation that target IDs exist (cross-file resolve) — FEAT-632 handles graph-time validation

* Existing Patterns

- Drawer parsing: =buffer.rs= already handles PROPERTIES and LOGBOOK via a state machine. Extend the same machine; do not introduce a parallel scanner.
- =OrgItem= field additions: precedent in =effort.rs=, =clock.rs= — both add typed fields without breaking serde or NAPI bindings. Mirror their =Default= and =Serialize= patterns.
- Tree-sitter grammar at =crates/tree-sitter-org/= already tokenizes generic drawers; the parser side classifies them by name.
- Reserve =EdgeKind::Other(String)= for forward-compat with unknown kinds; log-warn but don't fail.

* Edge Cases

- Drawer ordering: RELATIONS drawer before PROPERTIES drawer must also parse (do not hard-code order)
- Whitespace-only line inside drawer: skipped, no warning
- Duplicate =(kind, target)= relation: kept verbatim (deduplication is a graph-layer concern, not parser-layer); document in function doc-comment
- Extremely long relation list (>1000): no special handling; Vec scales linearly
- Mixed-case kind token: uppercased before =EdgeKind::parse=
- Target containing spaces: treated as one target string; spaces are not separators here (BLOCKERS legacy uses spaces, but RELATIONS uses one-target-per-line)
- Existing items consumed via =extract_items_from_buffer= must default =relations= to empty when drawer absent — verified by scenario 7
