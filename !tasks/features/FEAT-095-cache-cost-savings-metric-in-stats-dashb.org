* Initial Message

How does this coding harness manage token caching, especially with Anthropic Opus? Is there any room for improvement? Look at usage statistics if you can find them.

* Problem
The stats dashboard shows cache rate (%) and total cached tokens, but doesn't show the dollar amount saved by caching. For Opus at $15/MTok input vs $1.5/MTok cache read, users have no visibility into how much money caching saves them.

* Approach
Add a computed "Cache Savings" metric to ~buildAggregatedStats()~ and the dashboard:
- ~cacheSavings = totalCacheReadTokens * (model_input_cost - model_cache_read_cost) / 1_000_000~
- Since stats aggregate across models, use the per-message cost data already stored: ~cost_input~ and ~cost_cache_read~ per row
- ~cacheSavings = SUM(cache_read_tokens * ((cost_input / input_tokens) - (cost_cache_read / cache_read_tokens)))~ or more simply, sum the counterfactual: ~SUM(cache_read_tokens * cost_input_rate) - SUM(cost_cache_read)~

Actually simpler: the savings is ~totalCacheReadTokens~ priced at full input rate minus what was actually paid.
