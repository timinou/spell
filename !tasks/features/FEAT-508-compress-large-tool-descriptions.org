* Design Decisions

1. **code.md** — The 33-line =<instruction>= lookup table (intent → subcommand) is the primary value. Keep it but compress entries to one line each. The 5 JSON examples teach =code edit= patterns — keep 2 (patch + batch), delete 3 (the model knows JSON from the schema). =<operations>= list is schema duplication — compress to one line per group. =<critical>= — keep all constraints. =<output>= — keep.

2. **hashline.md** — The 6 examples are genuinely non-obvious (block boundary traveling rules). Keep 3: single-line replace, block body replace (shape a), and full block replace (shape b) with the bad/good contrast. Delete: delete-lines (trivial), shared boundary (explained in critical), insert-between (trivial). =<critical>= — keep ALL block boundary rules (these prevent real errors). The =<operations>= section explains pos/end/lines semantics — keep compressed.

3. **todo-write.md** — 10 examples for 4 operations. Keep 3: start+complete (basic lifecycle), gated-task (non-obvious protocol), wave-based-plan (complex pattern). Delete 7: initial-setup, skip, add_task, gated-completion, deferral, org-linked-task, sniper-todos-dispatch (derivable from schema + rules). The Sniper Pattern section — keep the contract, delete the example. Dependency Management — compress to constraint list. Verification Protocol — keep (non-obvious). Handlebars conditionals MUST be preserved exactly (=swarmEnabled=, =autoRosterEnabled=).

4. **task.md** — 3 examples. Keep 1 (rename+update callers — shows parallelization). Delete 2 (auto-roster, sniper dispatch — derivable from schema). The =<parallelization>= table — keep (decision table). =<templates>= — keep (structural contract). =<checklist>= — compress. =<scope>= — keep. Agent listing (={{#list agents}}=) — preserve exactly (Handlebars).

5. **bash.md** — The redirect/pipe prohibition table (=|Instead of|Use|=) — keep (prevents real tool misuse). =<instruction>= — compress. Handlebars conditionals (=asyncEnabled=, =hasAstGrep=, =hasAstEdit=) — preserve exactly.

* Existing Patterns
- =specs/prompt-surface-compression.md= (created by FEAT-506) — compression rules
- Tool descriptions follow: one-line capability → =<instruction>= → =<examples>= → =<output>= → =<critical>=
- =compactToolDescription()= in =packages/coding-agent/src/tools/index.ts= extracts first sentence for specialized tools
- First sentence MUST stand alone truthfully as the compacted version
