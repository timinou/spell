* Edge Cases
- YAML file with only ~layers~ and no ~policies~ is valid — layers still get injected into planning prompt
- Mode frontmatter with ~taskPolicies~ but no project-level file is valid
- Circular or contradictory policies (same name, different layers) — last definition wins silently
- ~layer~ field values are case-sensitive and must match exactly
- Missing ~match~ field on a policy → validation error, skip that policy with warning
- Sub-outline item with own LAYER overrides parent's LAYER — the sub-outline is the authoritative source
- ~resolveLayerFromOrgId~ with a ~::~ ID where parent doesn't exist → returns undefined
- ~layers~ declared in task-policies.yml extend the default ~VALID_LAYERS~ from pi-org, they don't replace them
