* Scope

In: new `org` subcommand that appends a structured implementation
sub-heading to an existing child item, with auto-prefixed `:CUSTOM_ID:` and
validated `:DEPENDS:` — eliminates the namespace-guessing failure class by
making the agent physically unable to produce a wrong prefix.

already handles wrong prefixes at rewrite time).

* Background

Even with N1's lenient rewrite, we want a first-class tool path. When the
agent writes the entire body at `org create` time and then iterates,
editing via `org update` with full body replacement is fragile and loses
other content. A dedicated append operation removes that footgun.

* Existing patterns

- `packages/org/src/tool.ts: cmdUpdate` (L523) — existing structured edit
  path; uses `executeOrg({ command: "editSection" })`.
- `packages/natives/src/org` / `pi-org-engine` `editSection` native
  operation.
- N1's shared `matchesParent` + rewrite helpers.

* Edge cases

- Parent has no PROPERTIES drawer yet: still works (we append a `**`
  section; existing parser requires per-heading PROPERTIES — we provide
  one).
- `body` contains a top-level `* heading` (breaks out of parent): reject
  with "body must not start a top-level heading; use N-star headings only"
  error.
- Concurrent add of the same slug: the `createCategoryMutex` primitive
  exists for file-level locking; reuse it (`withLock(parent.absPath,
  async () => {...})`).
- `depends` references a slug that will be added in a later call: strict
  mode rejects; `--defer-deps` could relax (not in this scope — document
  as a future FUP if needed).
