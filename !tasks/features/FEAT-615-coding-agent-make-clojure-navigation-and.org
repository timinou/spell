* Scope
In scope: make Clojure `code navigate children/siblings` return semantically useful forms instead of raw token-level nodes, and make graph context keep Clojure keywords while sectioning/collapsing them under “Data keywords” to reduce call-graph noise.

Out of scope: runtime nREPL/macro expansion, executing Clojure, or removing keyword extraction from the graph. Keywords are valuable data-flow signals and must remain available; they just must not crowd callers/callees/references.

* Existing Patterns
- Clojure profile: `crates/pi-code-engine/src/language/mod.rs`; Clojure uses `list_lit`, `sym_lit`, balanced-form helpers, and form procedures.
- Navigation: `crates/pi-code-engine/src/navigate.rs`; `children_result()` currently uses `class_member_nodes(profile, node, source)`, which is not meaningful for Clojure because Clojure has no class-like declarations. `siblings_result()` currently uses named children of the raw parent.
- Graph extraction: `crates/pi-code-graph/src/language/clojure.rs`; `extract_keywords()` creates `SymbolKind::Keyword`; `collect_references()` emits `EdgeKind::UsesKeyword`.
- Graph query/formatting: `crates/pi-code-graph/src/query.rs` and `crates/pi-natives/src/code_graph.rs`; `format_context()` currently sections Callers/Callees/References/Referenced by/Imports/Imported by/Inherits uniformly.
- TypeScript formatter: `packages/coding-agent/src/tools/code-result.ts` mostly returns graph `output` as native-formatted text.

* Tests
User workflows to cover first:
1. `code navigate {file: "x.clj", action:"children", line:<defn line>}` returns defn body forms, not `defn`/symbol/vector token noise.
2. Navigating children on a `let` form returns binding pairs and body forms with line ranges.
3. Navigating children on map/vector EDN-like Clojure forms returns map entries/vector elements at semantic granularity.
4. `siblings` around a form returns sibling forms in the same parent list/vector/map, not punctuation or leaf tokens.
5. `code context` on a Clojure var still shows callers/callees/references, but keyword refs are grouped under “Data keywords” and capped/collapsed separately.
6. `semantic:true` or an equivalent option may expand keyword detail if implemented, but default output must be quieter.
