* Scope

In scope:
- Add four focused test scenarios to close coverage gaps against PLAN-254 and PLAN-259 manual acceptance criteria that the unit suite does not currently encode.
- Scenarios:
  1. Two real =BufferRegistry= instances sharing one real =pi-edit-broker= instance; concurrent =edit_transaction= calls on disjoint =CodePath= targets in the same file both succeed, journal records both entries in order, each with the originating =sessionId=.
  2. Subagent sessionId attribution: parent session and subagent session each call =callCodeBuffer= with distinct =sessionId=; the journal entries recorded for the subagent edit carry the subagent =sessionId=, never the parent's.
  3. Peer-activity footer rendering: =appendPeerActivityFooter= in =packages/coding-agent/src/tools/code-result.ts= produces a stable truncated footer for a =CodeEditData= payload carrying up to 5 peer-activity entries across up to 3 files.
  4. Broker stale-socket recovery: =spawn_broker_if_absent= detects a stale socket file (no peer at the other end, e.g. =connect()= refused) and =unlink()=s + rebinds instead of failing.

Out of scope:
- Modifying production code for the covered scenarios except where a test uncovers a real bug (record as a NOTE; do not widen scope without returning to planning).
- End-to-end spawning two real =spell= CLI processes (tested at the engine/tool boundary, not the full CLI shell).
- Test-harness for BUG-267 patch-mode lifecycle; that is separate work.

* Edge Cases
- Broker socket path collisions across parallel cargo tests: use =tempfile::tempdir()= for isolation.
- Journal file race: assert ordering by =revision=, not by reading file timestamps.
- Subagent fallback: if neither parent nor subagent passes a sessionId, =tui-${pid}= fallback still applies; the test must not assert parent-vs-subagent distinction in that degenerate case.
- Peer-footer stability: TRUNCATE_LENGTHS constants may change; the test must reference the constant, not a hardcoded width, to prevent spurious failures when the constant is tuned.
- Stale-socket detection must not race a legitimate broker starting at the same moment; the test asserts the binary decision post-fact, not timing.

- If the stale-socket test reveals a real bug in =spawn_broker_if_absent=, the fix lands in the same change and the FEAT body is updated with a NOTE describing the fix.
