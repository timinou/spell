** SessionManager exposes sessionId early

- Verify =getSessionId()= is non-null at every point a mutating tool can fire. If a path exists where it's null (e.g., very early init before session id assigned), fall back to =tui-${process.pid}= (matching the pattern at =main.ts:129=).
- Add a runtime assertion in =callCodeBuffer=: throw if mutating command is requested and resolved sessionId is empty/null.
* Edge cases
- Subagent sessions: each subagent has its own sessionId via `sessionManager.getSessionId()`. Verify subagent edits attribute correctly (visible to parent via journal).
- `code edit` on a fresh file (not yet on disk) — `edit_transaction` creates the file; broker-commit still happens; sessionId still required.
- A single `code edit` with multiple `operations` targeting the same file: one `edit_transaction` call → one journal entry → one peer broadcast.
- A single `code edit` spanning multiple files: one `executeCodeBuffer` call but multiple transactions (one per file). Each file gets its own commit and journal entry.
- Tool retry budget: ensure `PeerConflictToolError` does not consume the agent's retry budget aggressively. Cap retries at 2 per call.
