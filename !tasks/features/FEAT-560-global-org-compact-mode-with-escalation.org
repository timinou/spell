* Scope
In scope:
- Make compact result mode the default for `org create`, `update`, `set`, `note`, `query`, `get`, `wave`, and `graph` in the coding-agent tool surface.
- Preserve agent auto-escalation to fuller output when the compact response is insufficient; no user confirmation step is required.
- Reduce repeated plan/query/wave churn by reusing prior compact summaries when the same org state is queried repeatedly and the underlying files have not changed.
- Keep the plan-mode and execution-mode contracts truthful: compact responses must still surface the exact IDs, state changes, and follow-up paths needed to continue the workflow.

Out of scope:
- Rewriting org file storage or native org-engine semantics.
- Changing the org item body standard itself.
- Replacing `org get` / `org query` with another tool; this item changes default result surfaces, not the domain model.

Rationale:
- `org:item mutation` is ~11.1% of sampled tokens with tiny char share: classic high-chatter, low-signal output.
- `org:lookup/query` and `org:planning graph` together contribute large visible outputs, especially repeated `wave` and query result bodies.
- The settled design decision is global compact default, not plan-mode-only compacting, because org tax appears both inside and outside strict planning flows.

* Tests
Workflows to enumerate and defend first:
1. Workflow 1 — create/update/set/note return compact success acks containing exactly the IDs, changed fields, and state/category facts needed for the next step.
2. Workflow 2 — query/get default to compact lists / summaries instead of dumping full item bodies unless escalation is warranted.
3. Workflow 3 — wave/graph default to compact rollups plus top blockers / ready items instead of emitting repeated huge item lists.
4. Workflow 4 — repeated query/wave calls against unchanged org state can reuse prior compact summaries safely.
5. Workflow 5 — when fuller output is genuinely needed, the compact response exposes the truthful auto-escalation path and the tool can still surface the full content.

* Edge Cases
- Compact mutation acks must still expose enough information for later `org set`, `org update`, and `exit_plan_mode` flows to work without ambiguity.
- `org get` sometimes needs the full item body for planning; the compact default must make escalation obvious and cheap.
- `wave` output can be legitimately large when many items are ready; compacting must not hide blockers or dependency facts that change the next action.
- Memoization must invalidate on create/update/delete/set/note operations touching relevant org files.
- Compact defaults must not break existing plan-mode tests that rely on stable anchor text or specific success cues.

* Acceptance Criteria
- Org mutation/query/wave traffic becomes compact by default while preserving truthful next-step guidance.
- Repeated unchanged query/wave calls can reuse prior compact summaries.
- Full output is still available through automatic escalation when genuinely needed.
- Focused org tests cover compact formatting, unchanged-state reuse, and compatibility with planning flows.
