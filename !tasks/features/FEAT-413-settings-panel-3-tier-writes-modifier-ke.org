* Context
With KDL-backed settings and the new =WriteTier= parameter on =Settings.set()=, the settings panel UI needs modifier key support: Enter = session (default), Shift+Enter = project, Ctrl+Shift+Enter = user. This changes flow through three layers: TUI SettingsList → coding-agent settings-selector → selector-controller.

* Design Decisions
- =SettingsList= (=packages/tui/src/components/settings-list.ts=) propagates modifier key info through its =onChange= callback
- =SettingsCallbacks.onChange= (=packages/coding-agent/src/modes/components/settings-selector.ts=) gains =tier?: WriteTier= parameter
- =SelectorController.handleSettingChange= (=packages/coding-agent/src/modes/controllers/selector-controller.ts=) passes tier to =settings.set()=
- Footer hint shows: "Enter: session | Shift+Enter: project | Ctrl+Shift+Enter: user"

* Implementation

** Part A: TUI SettingsList Modifier Support

File: =packages/tui/src/components/settings-list.ts=

The =onChange= callback currently has signature: =(id: string, value: string) => void=

Add a third parameter: =(id: string, value: string, modifier?: "shift" | "ctrl+shift") => void=

In =handleInput()=, when detecting Enter key:
#+begin_src typescript
// Current:
if (matchesKey(key, "return")) {
  this.#onSelect(item.id, selectedValue);
}

// New: detect Shift+Enter and Ctrl+Shift+Enter
if (matchesKey(key, "return")) {
  let modifier: "shift" | "ctrl+shift" | undefined;
  if (key.shift && key.ctrl) modifier = "ctrl+shift";
  else if (key.shift) modifier = "shift";
  this.#onSelect(item.id, selectedValue, modifier);
}
#+end_src

Check how =matchesKey= and the key event object work in =packages/tui/src/keys.ts=. The key event from stdin has =.shift= and =.ctrl= boolean fields. =matchesKey= checks the base key name; modifiers are separate properties.

** Part B: Settings Selector Callbacks

File: =packages/coding-agent/src/modes/components/settings-selector.ts=

Update =SettingsCallbacks= interface:
#+begin_src typescript
export interface SettingsCallbacks {
  onChange: (path: SettingPath, value: string, tier?: WriteTier) => void;
  // ... other callbacks unchanged
}
#+end_src

Import =WriteTier= from =../../config/settings=.

In the SettingsSelectorComponent where SettingsList onChange is wired:
#+begin_src typescript
// Map modifier to tier
const tier = modifier === "ctrl+shift" ? "user" : modifier === "shift" ? "project" : "session";
this.callbacks.onChange(settingPath, value, tier);
#+end_src

** Part C: Selector Controller

File: =packages/coding-agent/src/modes/controllers/selector-controller.ts=

Update =handleSettingChange=:
#+begin_src typescript
// BEFORE:
handleSettingChange(path: SettingPath, value: string): void {
  // ... parse value ...
  settings.set(path, parsedValue);
}

// AFTER:
handleSettingChange(path: SettingPath, value: string, tier?: WriteTier): void {
  // ... parse value (unchanged) ...
  settings.set(path, parsedValue, tier);
}
#+end_src

* Edge Cases
- Terminals that don't report shift/ctrl modifiers correctly → falls back to Enter (session tier), which is safe
- Some terminal emulators map Shift+Enter to plain Enter → same fallback
- Ctrl+Shift+Enter may not be reliably detected in all terminals → degrade gracefully to session tier
- The TUI =matchesKey= function handles raw key events — verify it exposes modifier booleans
