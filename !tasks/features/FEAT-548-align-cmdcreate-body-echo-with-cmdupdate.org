* Scope

=cmdCreate= currently echoes the locally rewritten body string in its response, while =cmdUpdate= (via =buildMutationResponse=) reads the final body back from disk via =fetchItem=. This asymmetry means the create response is technically showing what was *requested* rather than what was *persisted*. Although the native engine does not currently mutate body content during persist, aligning the behavior ensures the transparency contract holds if that changes.

*In scope*:
- Change =cmdCreate= to read body back from disk after persist (via =fetchItem=) instead of echoing the local =rewrittenBody= variable
- Reuse the =buildMutationResponse= pattern or equivalent

*Out of scope*:
- Changing =cmdUpdate= behavior (already correct)
- Changing the native engine's persist logic
- Changing =org create= response shape (=body=, =bodyLength= fields stay the same)
