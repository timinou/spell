* Intention & Purpose
Per audit (agent://36-Tests): all TS tests for the 4 generic tools mock
=executeCodePath=. NAPI Rust tests assert option marshalling, not full resolution. There
are zero "call NAPI with real fs + real code graph → assert returned nodes" tests.
This is exactly the gap that let PLAN-296's silent data-loss bugs ship to production.

This item adds an end-to-end test fixture + runner that exercises every promised
behaviour through the real NAPI binary against real source files.

* Context & Narrative
The current test architecture has 4 layers, none of which are e2e:
1. Kernel unit tests (parser/renderer/setops): pure Rust, no I/O
2. Dialect NameLexer tests: parse/render only, no AST
3. NAPI tests: tempdir + real fs but only assert option marshalling
4. TS tests: mock =executeCodePath= entirely

We need layer 5: build the native binary, drive it from a test harness, assert real
behaviour against real files. Captures regressions like "kernel ignores
=opts.actions= silently" or "qualifier returns 0..0".
