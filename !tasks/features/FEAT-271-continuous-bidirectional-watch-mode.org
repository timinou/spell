* Edge Cases
- =fs.watch= can emit multiple events for one save (tmp-file writes, rename bursts)
- Pull may run while the remote goal is actively writing SQLite state; backup step must preserve consistency
- Network disconnect during push can leave partial rsync output in transit
- Watch roots may include symlinked directories
- Very large change bursts (for example =git checkout= or =bun install=) must not schedule unbounded overlapping work
- Push-then-immediate-pull race: a local push must not immediately pull the same remote-side change back as noise

* Acceptance Criteria
- Local file changes trigger push within the configured debounce window
- Pull executes at the configured interval
- Push and pull never overlap
- Clean shutdown releases all watchers, timers, and pending abortable work
- SSH failures trigger reconnection behavior instead of leaving watch mode dead
