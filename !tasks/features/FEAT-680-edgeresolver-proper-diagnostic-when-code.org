* Intention & Purpose
When users issue an edge query (e.g. =foo.ts::Bar/ref→=) in a project where the code
graph hasn't been built/indexed yet, EdgeResolver currently surfaces =FileNotFound= or
similar misleading errors. This item makes the diagnostic explicit: "code graph not
initialised for this workspace; run =manage index= first" or equivalent.

* Context & Narrative
Per audit (agent://35-Resolvers risks): =EdgeResolverImpl= at
=crates/pi-natives/src/code_path/edge_resolver/mod.rs:18-250= depends on
=pi_code_graph::CodeGraph=. If graph isn't initialised, errors during =resolve= read as
generic =Diagnostic= without distinguishing "graph missing" vs "no edges found". Current
=executeCodePath= just propagates whatever error.

* Scope
** In-scope
- New diagnostic code =CODE_GRAPH_NOT_INITIALISED= surfaced when graph backend missing
- =EdgeResolverImpl::resolve= probes graph readiness before traversal; emits the
  diagnostic with remediation hint
- =manage index= command surfaces the build-graph entrypoint (verify it's already
  exposed; if not, this item adds it)
- TS-side ToolResult error formatter prints the diagnostic in a copy-pasteable format
  with the suggested next command
** Out-of-scope
- Auto-building the graph on demand (triggers data races + potentially expensive)

* Existing Patterns
- =crates/pi-natives/src/code_path/edge_resolver/mod.rs:18-250=
- =pi_code_graph::CodeGraph= initialisation API
- =crates/pi-code-path/src/types.rs::Diagnostic= structure

* Tests
