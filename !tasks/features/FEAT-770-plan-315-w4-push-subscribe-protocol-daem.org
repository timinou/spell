* Scope

Add subscription channel: daemon pushes =index_changed= events to long-lived clients when a repo's lane rebuilds. Enables /memory TUI live refresh + zero-staleness session views.

* Deliverables

** Wire protocol
- Connection upgrade: first message =Command::Subscribe { repo_handles: Vec<String>, lanes: Vec<Lane> }=. Daemon flips the connection from request-response to bidirectional streaming.
- Frame format: line-delimited JSON in both directions. Server frames:
  #+begin_src jsonc
  { "event": "index_changed", "repo_handle": "abc", "lane": "OrgMemory", "fingerprint": "..." }
  { "event": "warm_completed", "repo_handle": "abc", "lane": "CodeGraph", "ms": 4321 }
  { "event": "evicted",        "repo_handle": "abc", "reason": "idle_ttl" }
  { "event": "heartbeat",      "ts": "2026-..." }
  #+end_src
- Client may interleave queries on the same connection; replies are tagged with optional =request_id= correlator.

** Daemon side
- One =tokio= task per connection holds a =BroadcastReceiver<Event>=. Ingest watcher publishes on the broadcast channel under the per-lane write lock.
- Heartbeat every 30s; disconnect on missed.
- Backpressure: if client lags, drop oldest events (channel bound 256); send =event: "lag" { dropped: N }= on recovery.

** Client side
- New =pi-natives::knowledge_client::Subscription= handle. =memory= NAPI exposes =subscribe(repo, lanes, callback)= for TUI; non-TUI clients ignore.
- TUI =/memory= panel (W6) subscribes on open, unsubscribes on close.
