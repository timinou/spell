* Summary

SPELL PATCH-8 to the vendored ptc_runner: Clojure-shaped `(try body… (catch e
handler…) (finally cleanup…))` in PTC-Lisp, the `execute` tool's language. The
SEQUENTIAL analogue of PATCH-1's `psettled` (errors-as-values for parallel
fan-out): for a single fallible step or guaranteed cleanup.

Motivated by execute-tool ergonomics review: the ONE genuine capability gap
(vs discoverability gaps fixed by teaching apropos/doc in execute.md). Before
this, ANY error inside a sequential program aborted the whole run with no
in-language recovery.

* Semantics (faithful Clojure over BEAM try/rescue/catch/after)

- catch traps BOTH PTC error channels: the {:error, reason} RETURN TUPLE
  (apply.ex converts most raises: unbound var, arithmetic, type, arity), a
  raised ToolExecutionError (tool failure), AND the {:fail_signal, v} throw from
  (fail v) — binds the RAW v, not a string.
- (return v) is NOT trapped — bubbles to the enclosing return boundary; finally
  still runs as it passes through.
- finally runs on EVERY exit path (normal/caught/re-raised/return/fail); value
  discarded.
- catch var is handler-local (like let); closure_capture treats it as bound.
- both catch and finally optional, trailing (catch before finally).

* SAFETY invariant (load-bearing)

try can NEVER swallow a global safety limit. Heap/timeout/capacity kill
terminates the BEAM process before any rescue runs (uncatchable by
construction); the one catchable form — a nested ExecutionError with a stable
resource reason (:memory_exceeded/:timeout/:parallel_capacity_exceeded) — is
RE-RAISED past the handler (mirrors the psettled worker rescue +
stable_resource_error?). Dedicated test: heap-cap kill wrapped in (try … (catch
e "SWALLOWED")) asserts the run aborts :memory_exceeded, never the handler value.

* W4-write interaction

try is control-flow, NOT a transaction boundary. A caught error → program
SUCCEEDS → file writes COMMIT (the D3 transaction journal keys rollback on
program-level failure, execute.ts success vs catch path). An UNCAUGHT failure
still rolls back. Documented in prompts/tools/execute.md.
