* Intention & Purpose

Expose the new graph-and-memory primitives across the NAPI boundary by
extending =executeOrg= with =recall=, =remember=, =timeline=, =graph=,
and =link= ops. Mirrors the existing dispatch shape in
=crates/pi-natives/src/org_buffer.rs=. The TypeScript side
(=packages/org/src/tool.ts=) gains new cases that consume these ops via
the regenerated bindings.

* Context & Narrative

Spec: =specs/org-graph-memory.md=. The recall, graph, and edit-tx
primitives all live in Rust crates. NAPI is the single boundary for the
TS layer (memory pipeline, settings, tool surface) to use them. Today
=executeOrg= owns =parse=, =query=, =graph=, =computeWaves=, =nextWave=,
=editSection=, =toMarkdown=. This FEAT adds five verbs in the same
dispatch and keeps the contract that =executeOrg= is the only Rust→JS
surface for org operations.

The =subscribe= op is intentionally deferred to FEAT-639 alongside
broker routing so the live-event path lands as a unit.

* Edge Cases

- =remember= called outside a repo (no repo root resolvable): error clearly =RememberError::NoRepoRoot=
- =remember= when today's episodes file does not exist: create with file header (#+TITLE: Episodes <DATE>)
- =link= when source item has no CUSTOM_ID: error =LinkError::SourceMissingId=; suggest creating one first
- =link= when target item is in personal store and =include_personal=false=: still works — link is by id, recall scope is separate
- =recall= with malformed profile name (not in registry): warn + fall back to defaults
- Timeline with no episodes: empty Vec, no error
- Concurrent =remember= to the same day file: broker MultiIntent (FEAT-639) ensures atomicity once routed; until then v1 race-tolerates by writer-side retry on ETag mismatch in editSection
- TUI render: all op outputs pass through =replaceTabs= and =truncateToWidth= per AGENTS.md
