* Context

=hasUnresolvedBlockers()= and =isTaskBlocked()= in =todo-write.ts= hard-code a dummy context ={ currentSessionId: "current", currentAgentName: "main" }= instead of accepting the actual session/agent context. This means blocker refs that use session-scoped or agent-scoped URIs (e.g., =task://abc123/reviewer/task-1=) are evaluated against the wrong URI namespace, potentially making subagent tasks appear ready or blocked incorrectly.

Current signatures (post-rename, these will use =TodoGroup= after PROJ-028):
#+begin_src typescript
export function hasUnresolvedBlockers(task: TodoItem, allTasks: TodoItem[]): boolean {
    const context: ResolvedTodoContext = { currentSessionId: "current", currentAgentName: "main" };
    // ...
}
export function isTaskBlocked(task: TodoItem, allTasks: TodoItem[]): boolean {
    if (task.status !== "pending") return false;
    return hasUnresolvedBlockers(task, allTasks);
}
#+end_src

** Design Decisions

1. Add an optional third parameter =context?: ResolvedTodoContext= to both functions. Default to ={ currentSessionId: "current", currentAgentName: "main" }= for backward compatibility.
2. Update internal callers that already have a real context to pass it through:
   - =applyOps()= has =context: ResolvedTodoContext= param → pass to blocker check in update case
   - =promoteReadyTasks()= has =context= param → pass to blocker check
   - =collectBlockerGraphWarnings()= has =context= param → pass to blocker check
3. External callers that don't have session context keep using the default:
   - =formatSummary()= — rendering only, no session available
   - =TodoWriteTool.renderResult()= / =formatTodoLine()= — TUI rendering
   - =deriveAgentState()= in fluid-mode.ts — uses =hasUnresolvedBlockers= for state derivation
4. The =isTaskBlocked= function passes its context through to =hasUnresolvedBlockers=.

** Edge Cases
- When =context= is omitted, behavior is identical to current code. No external API breakage.
- A subagent with =agentName: "reviewer"= and blockers referencing =task://current/reviewer/define-contract= will now resolve correctly when context is provided, instead of falling back to the =main= namespace.
- The fallback lookup in =hasUnresolvedBlockers= (=allTasks.find(t => t.id === blockerRef || t.uri === blockerRef)=) remains as a safety net for refs that don't need URI resolution.
