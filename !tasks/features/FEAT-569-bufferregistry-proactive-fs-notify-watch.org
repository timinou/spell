* Scope

In: add a cross-platform `notify`-rs watcher owned by `BufferRegistry` that asynchronously marks cached buffers dirty when their source files change on disk. Supersedes BUG-279's reactive mtime-check as the primary invalidation mechanism; the reactive check remains as fallback for filesystems without usable watch (some network mounts).

Out: recursive workspace watching; content-diff replay; pushing invalidations to TS clients (later FUP).

* Background

BUG-279 adds `disk_mtime` and stat-on-every-`open`. That re-stat is O(number of opens). A watcher reduces this to O(number of changes) and makes the cache self-healing between tool calls without per-open stats.

Secondary benefit: the user's stated goal — "auto-discover and play well with the other code editing services running by any other spell service". A shared fs-watcher receives events from any writer (TUI, stats, external editors, git checkout, other spell subprocesses) uniformly.

** Integrate into BufferRegistry

- File: `crates/pi-code-engine/src/buffer.rs`
- `BufferRegistry` owns `Option<FileWatcher>`. `new()` attempts init; on failure logs and sets `None` (fallback to BUG-279 reactive path).
- `open(path)`:
  - If watcher is present AND `!watcher.is_stale(path)` AND cache hit → return cached Arc (no stat).
  - If watcher marks stale → drop cache, fall through to `CodeBuffer::open`, re-watch.
  - If watcher is absent → run BUG-279 mtime revalidation.
- `close(path)` unwatches.
- `save()` in `CodeBuffer` calls `registry.watcher.mark_self_write(path, new_mtime)` after write.

* Edge cases

- Network / virtualised FS without native event support: `notify::RecommendedWatcher::new` may return `Unsupported`. Catch and continue in fallback mode.
- Watcher event batching: debounce bursts to 50ms windows to avoid storms during large git operations.
- Self-write suppression keyed on `(path, expected_mtime)` with 1s TTL; if external write happens within the same millisecond, the mtime comparison in BUG-279 catches it.
- Symlinks: watch the canonicalised path (`fs::canonicalize(path)`) so reopening via different aliases converges.
- macOS case-insensitive HFS+: canonicalise case as above; document limitation.
- Very high file-count sessions (>10k buffers): each open registers a watch; on Linux this hits `fs.inotify.max_user_watches`. Document and add a soft cap (5000) with a warning log when exceeded.
