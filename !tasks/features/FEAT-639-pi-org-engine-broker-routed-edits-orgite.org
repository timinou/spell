* Intention & Purpose

Route org file edits through =pi-edit-broker= so every commit emits a
=PeerCommitted= event with an =OrgItemPatch= payload describing
which items changed and which fields/relations were touched. Add a
=subscribe= op to =executeOrg= that lets clients (QML, TUI agenda,
recall cache invalidator) register an =OrgQlFilter= and receive only
relevant patches via a NAPI =ThreadsafeFunction= callback. This is
what makes "LIVE SELECT-equivalent" real for org files.

* Context & Narrative

Spec: =specs/org-graph-memory.md=. =pi-edit-broker= already broadcasts
=PeerCommitted= per file commit. =pi-code-engine::coord::socket= is the
client today, but only =pi-natives::code_buffer= uses it.
=pi-natives::org_buffer= writes via =pi-org-engine::editSection=
directly, bypassing the broker. This FEAT adds the missing routing.

The =OrgItemPatch= diff is computed by parsing before- and after-state
items and comparing =(id, properties, relations, body_hash)= tuples.
Subscribers re-evaluate their filter only when the patch's
=touched_props ∪ touched_relations= intersects the filter's input
fields — keeps wake-ups proportional to relevance.

* Scope

In scope:
- =crates/pi-org-engine/src/diff.rs= (new) — =OrgItemPatch= computation
- =crates/pi-org-engine/src/coord.rs= (new) — broker client wrapper for org edits
- =crates/pi-natives/src/org_buffer.rs= — route =editSection=, =remember=, =link= through coord
- =crates/pi-edit-broker/src/protocol.rs= — extend =ServerMessage::PeerCommitted= and =MultiPeerCommitted= with =org_items: Option<Vec<OrgItemPatch>>=
- =executeOrg::subscribe= dispatch (NAPI =ThreadsafeFunction= callback)
- Subscription registry per-process: =SubscriptionRegistry { queries: HashMap<SubId, (OrgQlFilter, ThreadsafeFunction)> }=
- TS side: =packages/org/src/tool.ts= adds =subscribe= op; =packages/org/src/subscription.ts= (new) wraps the callback into an iterator
- Tests in =crates/pi-org-engine/tests/coord.rs= + =packages/org/test/subscribe.test.ts=

Out of scope:
- QML or TUI consumers of =subscribe= — that's UI work for a later iteration; this FEAT only ships the API
- Cross-process subscription (client A subscribes, client B edits): IT WORKS by design via broker broadcast — covered by integration test 5

* Existing Patterns

- =pi-edit-broker::protocol::ServerMessage::PeerCommitted= already includes =code_paths= and =diff_hash=. Add =org_items= as additive field; preserve wire-compat for non-org code commits (None).
- =pi-code-engine::coord::socket::SocketCoordClient= owns the connection lifecycle; reuse via =Arc<SocketCoordClient>= in =pi-org-engine::coord=.
- =OrgQlFilter= already has =requiresEmacs= and matcher logic in TS; for native subscribe-side filtering, port the simple cases (todo, tags, properties=, kind) into Rust. Defer Emacs cases (we no longer use Emacs — verified in =!architecture/org-native/=).
- =ThreadsafeFunction= NAPI helper precedent: =pi-natives::code_buffer= uses it for live edit notifications.

* Edge Cases

- Broker disconnect mid-stream: client retries with backoff; subscriptions persist on the client and replay via Welcome on reconnect
- Subscription leak (client crashes without unsubscribe): broker tracks per-session subscriptions and drops them on PeerLeft
- Patch with =Other= edge kind: serializes as ="OTHER:WHATEVER"=; TS consumers see opaque string
- Filter referencing inherited property: re-evaluate fully (cannot shortcut on touched_props)
- Edit removes the only item in a file: =OrgItemPatch { kind: Deleted }= with the id; subscribers compute correctly
- Patch dispatch latency target: <50 ms from commit to subscriber callback under no contention
