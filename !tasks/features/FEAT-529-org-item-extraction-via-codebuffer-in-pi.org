* Goal

Refactor =pi-org-engine= to depend on =pi-code-engine= and use =CodeBuffer= for parsing
instead of its own standalone =OrgBuffer=. This eliminates the duplicate parser and
makes org items accessible through the unified buffer system.

* Current state

=pi-org-engine/src/buffer.rs= has =OrgBuffer= which:
1. Creates its own =tree_sitter::Parser= and parses source
2. Walks the tree to extract =OrgItem= structs
3. Has no buffer management (re-parses every call)

=pi-code-engine= has =CodeBuffer= which:
1. Manages parser + rope + tree-sitter tree
2. Supports incremental re-parsing after edits
3. Has buffer registry with persistence

* Architecture change

=pi-org-engine= adds =pi-code-engine= as a dependency. =OrgBuffer= is replaced with
functions that operate on =&CodeBuffer= (or on =&str= source + =&Tree= for stateless ops).

** New API in pi-org-engine

#+BEGIN_SRC rust
// Stateless extraction from source text (for queries without buffer)
pub fn extract_items_from_source(
    source: &str,
    todo_keywords: &[&str],
    category: &str,
    dir: &str,
    file_path: &str,
    include_body: bool,
) -> Result<Vec<OrgItem>>;

// Extraction from a CodeBuffer (for buffered operations)
pub fn extract_items_from_buffer(
    buffer: &CodeBuffer,
    todo_keywords: &[&str],
    category: &str,
    dir: &str,
    include_body: bool,
) -> Vec<OrgItem>;
#+END_SRC

The tree-walking logic (=extract_headings=, =extract_section_item=, =parse_headline=,
=extract_properties=) stays in =pi-org-engine= — it just reads from =buffer.source()=
and =buffer.tree()= instead of its own fields.

** Backward compatibility

Keep a =parse_items= function that creates a temporary CodeBuffer from source text
for the NAPI =cmd_parse_items= path (stateless queries).
