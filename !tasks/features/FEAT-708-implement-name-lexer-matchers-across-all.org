* Intention & Purpose
Make `target:"file.ts::DemoConfig"` resolve to a TypeScript interface (and similarly for all dialects with stubbed name lexers). Currently `TsNameLexer.matches()` is a stub returning false; interfaces have no fallback path.

* Context & Narrative
`crates/pi-code-path/src/dialects/typescript.rs:66-72 TsNameLexer.matches()` returns false unconditionally. Walker `crates/pi-natives/src/code_path/code_resolver/walker.rs:241-275 head_matches` calls `dialect.name_lexer.matches()` first; on false, walks fallbacks (field name, text match) which work for some node kinds (function_declaration) but not others (interface_declaration, type_alias_declaration).

Each dialect's `NameLexer::matches()` consults the per-language `NameExtractor` (registered in `crates/pi-code-engine/src/language/mod.rs::with_builtins`) to extract the declared name from the node and compare to the requested name.

- Mangled names with dots (`a.b.c`): walker handles via step chain
