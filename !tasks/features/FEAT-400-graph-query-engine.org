* Context — Why This Exists
The graph engine ([[id:FEAT-397-core-graph-engine-and-trait-interfaces]]) builds and stores the code graph. This item provides the *query layer* — the algorithms that traverse the graph to answer questions the agent asks.

These queries are what the agent actually calls. When the agent runs =code impact { symbol: "UserService" }=, the code tool delegates to the NAPI bridge, which calls the Rust query engine, which runs a BFS traversal on the petgraph and returns depth-grouped results.

This item is *language-agnostic* — it operates purely on the =CodeGraph= data structure. It can be developed in parallel with [[id:FEAT-398-typescript-javascript-language-support]] and [[id:FEAT-399-elixir-and-heex-language-support]] since it only needs a populated graph (and we test with manually-constructed graphs).

** Queries To Implement
| Command | What It Does | Algorithm |
|---------+--------------+-----------|
| =context= | 360° view of a symbol: callers, callees, type refs, heritage, file | Incoming/outgoing edge traversal, 1-hop |
| =impact= | Blast radius if symbol changes, grouped by depth | BFS upstream through Calls/TypeRef edges, depth-limited |
| =deps= | Import graph for a file or module | Outgoing ResolvedImport + incoming ResolvedImport edges |
| =flow= | Execution flow from entry point to leaf | BFS downstream through Calls edges |
| =dead_code= | Unreachable symbols (no incoming Calls edges) | Filter symbols with zero incoming Calls, exclude entry points |
| =clusters= | Architectural community detection | Connected components on file-level import subgraph |
| =search= | Keyword/fuzzy search over symbol names | BM25 index lookup + trigram fuzzy fallback |

** Key Design Decision: Output Format
Query functions return structured Rust types, not formatted strings. The NAPI bridge serializes to JSON, and the TypeScript code tool formats for the TUI. This keeps the query engine pure — no presentation logic in Rust.

/// 360° symbol context
pub struct ContextResult {
    pub symbol: SymbolSummary,      // name, kind, file, span, signature
    pub callers: Vec<SymbolRef>,    // who calls this symbol
    pub callees: Vec<SymbolRef>,    // what this symbol calls
    pub type_refs: Vec<SymbolRef>,  // type references from this symbol
    pub heritage: Vec<HeritageRef>, // extends/implements relationships
    pub importers: Vec<PathBuf>,    // files that import this symbol's file
}

pub struct SymbolSummary {
    pub name: String,
    pub kind: SymbolKind,
    pub file: PathBuf,
    pub span: Span,
    pub signature: Option<String>,
    pub is_exported: bool,
}

pub struct SymbolRef {
    pub name: String,
    pub kind: SymbolKind,
    pub file: PathBuf,
    pub line: u32,
}

/// Blast radius grouped by depth
pub struct ImpactResult {
    pub target: SymbolSummary,
    pub layers: Vec<ImpactLayer>,
    pub total_affected: usize,
}

pub struct ImpactLayer {
    pub depth: u32,
    pub label: String,          // "Direct callers (will break)", "Indirect (may break)", "Transitive (review)"
    pub symbols: Vec<SymbolRef>,
}

/// File dependency view
pub struct DepsResult {
    pub file: PathBuf,
    pub imports: Vec<DepRef>,     // files this file imports
    pub importers: Vec<DepRef>,   // files that import this file
    pub external: Vec<String>,    // external packages imported
}

pub struct DepRef {
    pub file: PathBuf,
    pub specifiers: Vec<String>,  // import specifiers used
}

/// Execution flow trace
pub struct FlowResult {
    pub entry: SymbolSummary,
    pub steps: Vec<FlowStep>,
}

pub struct FlowStep {
    pub depth: u32,
    pub symbol: SymbolRef,
}

/// Dead code report
pub struct DeadCodeResult {
    pub unreachable_symbols: Vec<SymbolRef>,
    pub unreachable_files: Vec<PathBuf>,
    pub total_symbols: usize,
    pub dead_count: usize,
}

/// Architectural clusters
pub struct ClustersResult {
    pub clusters: Vec<Cluster>,
}

pub struct Cluster {
    pub id: usize,
    pub files: Vec<PathBuf>,
    pub key_symbols: Vec<String>,   // most-connected symbols in cluster
}

/// Search results
pub struct SearchResult {
    pub matches: Vec<SearchMatch>,
}

pub struct SearchMatch {
    pub symbol: SymbolRef,
    pub score: f32,
}

** 4. Context query implementation
- Resolve symbol name to NodeIndex via =symbol_index=
- If ambiguous (multiple indices), prefer exported, then most-connected
- Incoming Calls edges → callers
- Outgoing Calls edges → callees
- Outgoing TypeRef edges → type references
- Outgoing Extends/Implements edges → heritage
- File node → incoming ResolvedImport edges → importers

* Error Handling
- Symbol not found → return descriptive error with "did you mean?" suggestions (closest names by edit distance)
- Ambiguous symbol (multiple with same name) → return all candidates with file paths
- Empty graph → return empty results, not error
- Cycles → BFS visited set prevents infinite loops
