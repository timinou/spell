* Scope
Extend =telegram-to-rpc.ts= to handle three new Telegram message types: voice messages, video notes (round circles), and audio file documents. Download media, extract audio if needed, transcribe via STT, and pass text to the agent.

* Message Types

** Voice Messages (=message.voice=)
- Telegram type: =Voice= object with =file_id=, =duration=, =mime_type= (=audio/ogg=), =file_size=
- Download via =getFile= → raw OGG Opus bytes
- Send directly to STT provider (all providers accept OGG)

** Video Notes (=message.video_note=)
- Telegram type: =VideoNote= object with =file_id=, =length= (diameter), =duration=, =file_size=
- Download via =getFile= → MP4 video file
- Extract audio track with ffmpeg: =ffmpeg -i input.mp4 -vn -acodec libopus -f ogg pipe:1=
- Send extracted audio to STT provider
- Requires ffmpeg on the server (check at startup, log warning if missing)

** Audio Documents (=message.audio=)
- Telegram type: =Audio= object with =file_id=, =duration=, =performer=, =title=, =mime_type=, =file_size=
- Download via =getFile= → raw audio bytes (MP3, M4A, OGG, etc.)
- Send directly to STT (providers accept common formats)
- Also applies to audio files sent as documents (=message.document= with audio MIME type)

** Transcription Flow in =handleTelegramMessage=

#+begin_src
1. Check if message has voice/video_note/audio
2. If voice config has no STT configured → reply "Voice messages require STT configuration. Add a voice { stt-provider ... } block to channels.kdl"
3. Download media bytes
4. If video_note → extractAudioFromVideo()
5. Call sttProvider.transcribe(audioBytes, { mimeType, language })
6. If transcription empty → reply "Could not transcribe voice message"
7. Prepend transcription to prompt text (transparent to agent)
8. Pass to rpcClient.prompt() as normal text
