* Intention & Purpose
Translate a ~template~ manifest entry plus parameter values into a live spawned RPC session: validate params, render the prompt with Handlebars, resolve the setup reference into ~RpcSpawnOptions~, call ~WebSessionHub.spawn~, then fire the rendered prompt as the first ~prompt~ RPC command. Returns the new ~sessionId~ to the caller (WS or REST).

* Edge Cases
- Empty params object on a template with no required params → fine, render with empty context.
- Handlebars syntax error in stored template prompt (manifest already loaded but invalid) → logger.error with template name and details; throws ~PromptRenderError~. UI surfaces as toast.
- Race: two ~runTemplate~ calls for same template — both return distinct ~sessionId~ (templates are not singletons).
- Setup that defines ~tools.deny~ excluding all default tools → spawn proceeds; agent will be limited (correct behavior).
- ~mode~ on template = ~"rpc"~ is a no-op pass-through (only mode in v1); kept for forward compat.
- ~initialPrompt~ failure (rpc client not ready yet) → retry once with 200ms backoff.
