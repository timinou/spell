Can you leanly improve/change the decomposition steps of plans and ultraplans to fully support these? And then once the first DAG has been generated, Daedalus is generated with that DAG summary as the startying point, instead of the current way which has Daedalus generate the decomposition analysis before the DAG which makes no sense? * Edge Cases
- Daedalus advisory finds critical issue (e.g., cycle in dependencies) :: agent has discretion to fix via =org update= or note the issue and proceed. The cycle would also be caught by =org-fluid-plan= Elisp tool at exit-plan-mode time.
- Agent creates malformed org items (missing EFFORT, bad CUSTOM_ID) :: =exit-plan-mode= validation catches these (existing validation in =ExitPlanModeTool.execute=). This is not a prompt concern.
- Metis identifies gaps AFTER agent has already created some items :: agent can update existing items via =org update= (section-scoped updates). No need to delete and recreate.
- Agent skips Daedalus entirely (it's advisory) :: acceptable. Plan quality relies on Org Item Body Standard + exit-plan-mode validation + Momus in approval UI.
- Regular plan mode agent tries to run Daedalus :: Daedalus section only renders in ultraplan mode (={{#if ultraplan}}=). Not available in regular plan mode.
