* Problem
Running =fastembed= (ONNX Runtime) inside the Bun process via NAPI causes segfaults. The ONNX Runtime creates its own thread pool, does memory-mapped I/O, and runs SIMD operations that collide with Bun's internals. This manifests as ~Segmentation fault at address 0x983E7000~ after ~17 minutes of session runtime. Documented Bun issue: https://github.com/oven-sh/bun/issues/19802

* Solution
Create a standalone Rust binary =pi-embedding-worker= that encapsulates all fastembed/ONNX Runtime operations in a separate process. The binary communicates via stdin/stdout JSONL protocol.

* Design Decisions
- Binary crate at =crates/pi-embedding-worker/=
- Links against =pi-code-vectors= (which depends on fastembed + ort)
- Single-threaded: reads JSON commands from stdin, processes, writes JSON responses to stdout
- Stays alive between calls (long-lived subprocess for session reuse)
- Model download (~500MB jina-embeddings-v2-base-code) happens in this process, not Bun
- Progress output goes to stderr (not stdout, which is for protocol messages)

* JSONL Protocol
#+begin_example
# Initialize (triggers model download on first run)
stdin:  {"cmd":"init","show_progress":true}
stdout: {"ok":true}

# Batch embed documents
stdin:  {"cmd":"embed_batch","texts":["fn hello()...","class Foo..."],"batch_size":null}
stdout: {"ok":true,"vectors":[[0.1,0.2,...],[0.3,0.4,...]]}

# Single query embed
stdin:  {"cmd":"embed_query","text":"find rate limiting"}
stdout: {"ok":true,"vector":[0.1,0.2,...]}

# Error response
stdout: {"ok":false,"error":"Failed to load model: ..."}
#+end_example

** main.rs structure
#+begin_src rust
use std::io::{self, BufRead, Write};
use pi_code_vectors::EmbeddingEngine;
use serde::{Deserialize, Serialize};

#[derive(Deserialize)]
#[serde(tag = "cmd")]
enum Command {
    #[serde(rename = "init")]
    Init { show_progress: Option<bool> },
    #[serde(rename = "embed_batch")]
    EmbedBatch { texts: Vec<String>, batch_size: Option<usize> },
    #[serde(rename = "embed_query")]
    EmbedQuery { text: String },
}

#[derive(Serialize)]
#[serde(untagged)]
enum Response {
    Ok(OkResponse),
    Err(ErrResponse),
}

#[derive(Serialize)]
struct OkResponse { ok: bool, #[serde(flatten)] payload: Payload }

#[derive(Serialize)]
struct ErrResponse { ok: bool, error: String }

#[derive(Serialize)]
#[serde(untagged)]
enum Payload {
    Empty,
    Vectors { vectors: Vec<Vec<f32>> },
    Vector { vector: Vec<f32> },
}
#+end_src

** Read loop
- Read one JSON line from stdin per iteration
- Parse into Command enum
- Lazily initialize EmbeddingEngine on first embed call (or explicit init)
- Write JSON response line to stdout
- Flush stdout after each response
- Exit cleanly on stdin EOF or parse error

** Error handling
- All panics caught via =std::panic::catch_unwind= on the main loop
- ONNX Runtime errors converted to error responses, not panics
- If engine init fails, return error and allow retry on next command

* Acceptance Criteria
- =cargo build -p pi-embedding-worker= produces a binary
- Binary reads JSONL from stdin, writes JSONL to stdout
- =init= command succeeds if model is cached, returns error message if download fails
- =embed_batch= returns correct number of 768-dim vectors
- =embed_query= returns single 768-dim vector
- Invalid JSON input returns error response (does not crash)
- Binary exits cleanly on stdin EOF

* Testing
