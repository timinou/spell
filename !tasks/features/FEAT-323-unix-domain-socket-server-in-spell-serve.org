Implement a Unix domain socket server in spell-server that accepts connections from local coding-agent sessions. The server maintains a session registry and routes blocking events to the notification system.

* Architecture

** Socket Server (=src/socket/server.ts=)

- Listen on configurable path (default: =~/.spell/server.sock=)
- On startup: remove stale socket file if exists (check PID liveness or just unlink)
- Accept connections, each connection is one coding-agent session
- Parse JSON lines from each connection using the protocol types from FEAT-322
- On =register=: add session to registry, respond with =registered=
- On =blocking_event=: forward to registered event handlers (the Telegram notification layer will subscribe)
- On =deregister= or connection close: remove session from registry
- On =heartbeat=: update last-seen timestamp in registry
- Graceful shutdown: close all connections, remove socket file

** Session Registry (=src/socket/session-registry.ts=)

- In-memory =Map<sessionId, SessionRegistryEntry>= tracking:
  - Session metadata (pid, cwd, mode, project, startedAt)
  - Connection handle (for sending responses back)
  - Last heartbeat timestamp
  - Current blocking event (if any)
- Methods:
  - =register(sessionId, metadata, connection)=
  - =deregister(sessionId)=
  - =getActive(): SessionRegistryEntry[]=
  - =getBlocked(): SessionRegistryEntry[]= — sessions with pending blocking events
  - =resolveEvent(sessionId, eventId, response)= — send response back to session
  - =cancelEvent(sessionId, eventId)= — send cancellation back
- Stale session cleanup: periodic sweep removing entries where PID is no longer running (=process.kill(pid, 0)= check)
- Event emitter pattern: =onBlockingEvent(handler)= / =onSessionChange(handler)= so Telegram can subscribe

** Integration with spell-server

- Initialize socket server in =src/server.ts= =startSpellServer()=
- Pass session registry to Telegram service (for =/sessions= and notifications)
- Shut down socket server in the =stop()= method
- Socket path from server config (parsed from =server.kdl=)

* Edge Cases

- Socket file left behind from crashed server: unlink before bind, with PID-liveness check to avoid stomping a running server
- Client sends malformed JSON: log warning, ignore the line, don't close connection
- Client disconnects without =deregister=: connection close event handles cleanup
- Multiple sessions from same PID (e.g., nested task agents): each has unique sessionId, all tracked independently
- Socket dir (=~/.spell/=) doesn't exist: create it
