* Initial Message

the org get and search tools provide wrong ITEMs and not well ordered. PLease try the tool and tell me the querying improvements you'd make

* Problem
Query results come back in =fs.readdir= order x =Promise.all= resolution order —
effectively random. There is no sort parameter exposed, no default ordering, and
no way for the LLM to request sorted output. The org-ql-query MCP tool already
accepts a =sort= parameter but the TS code never passes it.

* Design
Two layers of sort support:

1. *TS-side default sort*: After =applyFilter=, sort by priority (#A > #B > #C > none),
   then by state (DOING > REVIEW > ITEM > BLOCKED > DONE > INIT), then by ID
   (natural sort so PLAN-087 > PLAN-001). This applies to simple TS-path queries.

2. *org-ql sort forwarding*: When queries route to Emacs (=ql= or advanced keyword
   queries), pass the =sort= param through to =org-ql-query= MCP tool.

3. *Elisp multi-key sort*: Enhance =org-ql-query.el= to accept space-separated sort
   keys (e.g. =priority todo=) and pass them as a list to =org-ql-select :sort=.
