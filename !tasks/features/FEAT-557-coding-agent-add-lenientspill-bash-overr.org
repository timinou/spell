* Scope
In scope:
- Add an explicit per-call bash parameter named `lenientSpill` that reverts that one bash invocation to the legacy lenient spill behavior instead of the new low-spill default.
- Keep the override off by default, non-sticky, and visible: the tool result and renderer must warn when lenient spill is active so transcript readers know the call intentionally widened inline output.
- Reuse the existing artifact workflow (`artifact://` references resolved back into subsequent bash commands) rather than inventing a second mechanism for shell follow-up analysis.
- Update bash tool documentation and tests so agents learn the intended behavior: default to tight spill budgets, opt into `lenientSpill` only when broader inline stderr/stdout is truly necessary.

Out of scope:
- Adding a session-level or settings-level sticky override.
- Extending the lenient override to `python`, `ssh`, `fetch`, or other tools in this change.
- Changing `read`/`grep`/`org` contracts; those are handled by the shared spill-policy project item.

Rationale: the user wants a sharp default that pushes agents toward artifact-based follow-up analysis while still leaving an escape hatch for debugging sessions where a slightly fatter inline tail materially speeds iteration. A per-call parameter is explicit, auditable, and less dangerous than a sticky setting.

* Edge Cases
- `lenientSpill` must not mask non-zero exit codes or convert failing commands into plausible success summaries.
- The override must interact correctly with `head`, `tail`, `pty`, and `async` paths.
- Follow-up commands using `artifact://` must keep working whether the original call used default or lenient spill.
- The warning must be visible enough to discourage silent overuse but not so noisy that every bash result becomes cluttered.

* Acceptance Criteria
- Bash defaults to the low-spill artifact-first behavior from the shared policy item.

- Documentation makes the artifact-first workflow explicit and treats `lenientSpill` as an exception.
- Tests prove default behavior, override behavior, truthful failure semantics, and preserved artifact follow-up workflows.
