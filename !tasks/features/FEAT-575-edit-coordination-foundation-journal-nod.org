* Tests (write before implementation)
Test file: =crates/pi-code-engine/tests/coord_foundation.rs=

Scenarios (all must initially fail against `main`):

1. `history_records_session_id_and_code_paths`
   Given a buffer with session id `"s1"`, after one `edit_with_attribution(edit, vec!["src/a.ts::Foo.bar#body"])`, the recorded `Revision` has `session_id == "s1"` and `code_paths == ["src/a.ts::Foo.bar#body"]`.

2. `undo_scoped_skips_peer_revisions`
   History has revisions from s1, s2, s1, s2 in order. `undo_scoped("s1")` walks back to the nearest revision belonging to s1, records 1 skipped s2 revision in the returned summary, and applies only s1's inverse. Redo is symmetric.

3. `undo_scoped_own_chain_only_succeeds_when_no_peer_present`
   Same as today's `undo()` behavior when every revision has the same session id. Regression guard.

4. `journal_writer_appends_jsonl_atomically`
   Given a tmpdir journal root, `JournalWriter::append(entry)` produces one newline-terminated JSON line. Two concurrent appends from different threads produce two complete lines (use fs advisory lock); no torn line, no interleave.

5. `journal_replay_last_n_returns_recent_entries_in_reverse`
   Given 10 appended entries, `JournalReader::tail(path, 5)` returns the last 5 in reverse chronological order, parsed.

6. `journal_path_derivation_is_stable_per_repo_and_file`
   `journal_path_for(repo_root, file_path)` returns `~/.spell/edit-journal/<blake3[0..16] of canonicalize(repo_root)>/<blake3[0..16] of canonicalize(file_path)>.jsonl`. Verify hash is stable across calls.

7. `null_coord_client_is_silent_no_op`
   `NullCoordClient::intent / commit / recent_peer_edits / peer_state / on_open / on_close` all return immediately with `Granted` / `Ok` / empty vecs / empty state. No side effects.

8. `node_ref_extracts_code_path_from_named_ts_method`
   Parse `class Server { handle() {} }`, derive CodePath for the method node's byte range, assert it equals `"::Server.handle"` (file prefix supplied by caller).

9. `node_ref_falls_back_to_whole_file_for_unnamed_edit`
   An edit spanning two top-level functions has no single named ancestor; `derive_code_paths(edit, tree)` returns `vec!["::*"]` whole-file marker.

10. `revision_parent_revision_is_recorded`
    On edit, `Revision::parent_revision` equals the previous revision's numeric revision id (monotonic u64 within one buffer's history).

* Edge cases
- History truncation on divergent edit path: the existing `record_batch` truncates forward revisions past `current`. `undo_scoped` must handle a history where every revision after root is peer-authored — returns `ScopedUndoResult { applied: None, skipped: [...] }` gracefully.
- CodePath extractor must not panic on `edit.start_byte == edit.old_end_byte == 0` (insertion at start of empty buffer) — return whole-file marker.
- Journal append: if `~/.spell/edit-journal/` is unwritable, log once via the engine's existing error path and continue silently; tests assert no panic.
- Blake3 hash is not cryptographic for our purposes — used only as a short stable key. Do not expose as a security primitive.
- Concurrent `JournalWriter::append` from two threads in one process: `with_exclusive_lock` on the journal file path (same `fd_lock` helper) serializes them.
