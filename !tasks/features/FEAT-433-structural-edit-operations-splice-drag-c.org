* Context: What This Replaces

Combobulate (Emacs Lisp, ~1686 lines in =combobulate-manipulation.el=) provides structural editing operations that work on tree-sitter nodes: splice (unwrap a node keeping selected children), drag (swap sibling nodes), clone (duplicate a node), and transpose (swap adjacent sexp-like nodes). These are backed by combobulate's procedure DSL for finding the right nodes.

In the current Spell code tool, these operations are routed through the Emacs daemon: the TypeScript tool sends JSON-RPC to Emacs, which activates combobulate-mode, positions the cursor, calls the combobulate function, and returns the result. This has latency (socat round-trip), requires the Emacs daemon, and the interactive aspects (proffer choices, overlay preview) are unused by the headless agent.

We're reimplementing these in Rust as pure functions on =CodeBuffer=. Each operation uses the procedure DSL (=FEAT-432=) to find target nodes, then performs text mutations on the buffer. No interactive UI. Deterministic: first match wins.

Research documents:
- =specs/combobulate_analysis.md= — Part II covers all 4 operations with algorithms and pseudocode
- =specs/pi-code-engine-spec.md= section 6 — Rust API design

* Goal

Implement all structural edit operations in =crates/pi-code-engine/src/edit/=. Each operation takes a =CodeBuffer= reference, finds the relevant node(s) using the procedure DSL, and returns a list of =TextEdit= values to apply.

The operations also include simple edits (replace, insert-before, insert-after, kill) which don't need the procedure DSL — they just need a node at a given line.

* Design Decisions

1. *Operations return =Vec<TextEdit>=, not mutate directly*. The caller decides whether to apply them (via =buffer.edit_batch()=). This enables preview/diff before applying.
2. *High-to-low ordering*: =edit_batch= sorts edits by start_byte descending automatically. Operations don't need to worry about position shifts.
3. *Indentation*: Each operation handles indentation adjustment for its specific case. General strategy: measure the indent of the source node, measure the indent of the target position, compute delta, apply to all lines of the moved/cloned text. First line gets absolute indent, subsequent lines get relative shift.
4. *Separator detection*: Clone appends a separator (comma, semicolon) if the node's next sibling is an anonymous separator node whose text matches the language profile's =separators= list.
5. *Error on syntax-error trees*: If the tree has ERROR nodes in the region being operated on, return an error rather than producing garbage. Check =node.has_error()=.

* Operation: Splice (splice.rs)

** What it does
Removes a node's parent/container, keeping selected parts of the node based on =SpliceMode=. Example: splicing up an if-statement's body keeps the body statements but removes the if-condition and braces.

** Algorithm
1. Find node at line using tree-sitter: =tree.root_node().descendant_for_point_range(...)=
2. Walk up to nearest named node if anonymous
3. Apply the sibling procedure to find all siblings (using the language's registered sibling procedure, or a default: "match all named children of parent")
4. Partition siblings by position relative to the target node:
   - =Before=: siblings that start before the target node
   - =Self=: the target node itself
   - =After=: siblings that start after the target node
   - =Around=: nodes that contain the target (larger than it)
5. Filter by mode:
   - =Up=: keep Self + After + Around
   - =Self_=: keep only Self
   - =Down=: keep Self + Before + Around
6. Get the range extent (min start_byte, max end_byte) of all kept nodes
7. Find the splice parent: walk up from the target node, find the first ancestor whose type is in the language's production rules for the current node type's parent
8. Build =TextEdit=: delete the parent node's range, insert the kept text at the parent's start position
9. Adjust indentation: the kept text's first line gets the parent's column, subsequent lines shift by (parent_column - original_column)

** Edge Cases
- No valid splice parent found: return error "No valid splice target"
- Target node IS the root: return error "Cannot splice root"
- ERROR node in tree: return error "Cannot splice: syntax error in region"
- Single child (nothing to partition): splice up/down equivalent to self

* Operation: Drag (drag.rs)

** What it does
Swaps a node with its adjacent sibling in the given direction. Example: dragging a function parameter up swaps it with the previous parameter.

** Algorithm
1. Find named node at line
2. Get the node's parent
3. Find the node's index among parent's named children
4. For DragDirection::Up: get the previous named sibling (index - 1). For Down: next (index + 1).
5. If no sibling in that direction: return error "No sibling to swap with"
6. Build two =TextEdit= values: one replaces the node's range with the sibling's text, the other replaces the sibling's range with the node's text. Process high-to-low.

** Edge Cases
- Node is first child and direction is Up: error
- Node is last child and direction is Down: error
- Separators between nodes (commas): the swap must preserve them. Strategy: swap only the node text, NOT including trailing separators. Separators are anonymous nodes between the named children — they stay in place.

* Operation: Clone (clone.rs)

** What it does
Duplicates a node, inserting the copy adjacent to the original. Example: cloning an array element duplicates it in the array.

** Algorithm
1. Find named node at line
2. Get the node's text from the buffer source
3. Detect separator: check the next sibling. If it's anonymous and its text is in =profile.separators=, capture it.
4. Determine insertion mode:
   - If the line before the node's start position is blank or only whitespace: newline mode (clone on new line)
   - Otherwise: inline mode (clone inline with separator)
5. For newline mode:
   - Calculate node's indentation (column of first non-whitespace on its start line)
   - Build text: newline + indent + node_text + separator
   - Insert at =node.end_byte()=
6. For inline mode:
   - Build text: separator + " " + node_text
   - Insert at =node.end_byte()=

* Operation: Transpose (transpose.rs)

** What it does
Swaps two adjacent sexp-like nodes around a given position. Simpler than drag — it doesn't use procedures. It finds the node before point and the node after point, then swaps them.

** Algorithm
1. Convert (line, column) to byte offset
2. Find the named node ending just before or at the byte offset (backward node)
3. Find the named node starting just after or at the byte offset (forward node)
4. If either not found: return error
5. Swap their text regions (same as drag's swap)
