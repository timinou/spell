* Edge Cases

- PLAN body has no [[id:...]] links → return warning "no linked child items; manifest not written" and wrote_to_plan=false. Scenario 7.
- PLAN has both top-level and sub-outline links mixed: both are accepted; sub-outline links imply their parent but the parent is not required to be linked separately (the manifest only needs to list sub-outline items). However, for discovery the validator (separate FEAT) will require parent links too — here we simply do not fail on missing top-level links.
- Linked child file not found: the offending ID is added to warnings; other children proceed. wrote_to_plan still true if any waves computed.
- editSection mode replace fails when the section does not exist: catch the NOT_FOUND error and fall through to mode: append. Scenarios 3 and 4.
- Concurrent mutation of the PLAN file: editSection is atomic at the native layer (single edit_batch). No explicit locking needed beyond the existing createCategoryMutex which is not required here because editSection already serializes through the buffer.
- Circular DEPENDS across sub-outlines: engine already reports cycles in warnings; manifest is still written with items excluded from waves. Scenario 8 variant: add warning assertion.
- A DEPENDS value that references an ID not in the aggregated set: engine emits a warning; manifest still writes. Scenario: verify warning surfaces in the returned envelope.
- Pathological huge wave counts: no hard limit; manifest text can grow. Acceptable — PLAN body should not be truncated.
- doneStates=["DONE"] is fixed here; no support for custom lifecycle yet. Future extension.
