* Context
=collect_heritage_references()= in =crates/pi-code-graph/src/language/typescript.rs= walks extends/implements clauses and collects ALL identifiers recursively via =collect_identifier_names()=. This means =class Foo extends Bar&lt;Baz&gt;= produces =Inherits= edges to both =Bar= (correct) and =Baz= (incorrect — =Baz= is a type parameter, not a base class).

This was observed in practice: =CodeTool= appeared to "inherit" =codeSchema= because the generic parameter =typeof schema= included =codeSchema= as an identifier.

The fix: add a new =EdgeKind::TypeParameterOf= variant. Rewrite =collect_heritage_references()= to produce =Inherits= edges only for the direct type references in extends/implements clauses, and =TypeParameterOf= edges for identifiers found inside =type_arguments= / =type_parameters= subtrees.

* Design Decisions
1. Add =EdgeKind::TypeParameterOf= variant to the =EdgeKind= enum in =model.rs= (after =TypeImports= which is added by the dependency item FEAT-421).
2. Rewrite =collect_heritage_references()= to walk the heritage clause children structurally:
   - For each direct child of an extends/implements clause that is a type reference (=type_identifier=, =identifier=, =nested_type_identifier=, =generic_type=), collect the top-level type name as =Inherits=.
   - For identifiers found inside =type_arguments= subtrees of those generic types, collect as =TypeParameterOf=.
3. =graph_dead_code()= should NOT count =TypeParameterOf= as "usage" (same treatment as =TypeImports=).
4. =graph_impact()= should include =TypeParameterOf= in the traversal set for completeness.
5. Adding a variant changes bincode schema — acceptable (cache rebuilds on deserialization failure).

* Dependency
This item depends on [[id:FEAT-421-distinguish-type-only-imports-with-edgek]] because both add new variants to the =EdgeKind= enum in =model.rs=. Sequential execution avoids merge conflicts on the same enum.

2. *typescript.rs* — Rewrite =collect_heritage_references()=. The current implementation:
   #+begin_src rust
   fn collect_heritage_references(node: Node<'_>, source: &str) -> Vec<ExtractedReference> {
       let mut refs = Vec::new();
       visit_named(node, &mut |child| {
           if matches!(child.kind(), "extends_clause" | "implements_clause" | "extends_type_clause") {
               for name in collect_identifier_names(child, source) {

   }
   #+end_src

   Replace with a two-phase approach:
   #+begin_src rust
   fn collect_heritage_references(node: Node<'_>, source: &str) -> Vec<ExtractedReference> {
       let mut refs = Vec::new();
       visit_named(node, &mut |child| {
           if !matches!(child.kind(), "extends_clause" | "implements_clause" | "extends_type_clause") {
               return;
           }
           // Walk direct value/type children of the clause
           let mut clause_cursor = child.walk();
           for clause_child in child.named_children(&mut clause_cursor) {
               collect_heritage_from_type(clause_child, source, &mut refs);
           }
       });
       dedupe_references(refs)
   }

   fn collect_heritage_from_type(node: Node<'_>, source: &str, refs: &mut Vec<ExtractedReference>) {
       match node.kind() {
           "type_identifier" | "identifier" => {
               refs.push(ExtractedReference {
                   target_name: node_text(node, source),
                   edge_kind: EdgeKind::Inherits,
               });
           }
           "nested_type_identifier" => {
               // e.g., Foo.Bar — collect the whole dotted name as Inherits
               refs.push(ExtractedReference {
                   target_name: node_text(node, source),
                   edge_kind: EdgeKind::Inherits,
               });
           }
           "generic_type" => {
               // e.g., Bar<Baz> — the first child is the type name (Inherits),
               // the type_arguments child contains type params (TypeParameterOf)
               let mut cursor = node.walk();
               for child in node.named_children(&mut cursor) {
                   if child.kind() == "type_arguments" {
                       for name in collect_identifier_names(child, source) {
                           refs.push(ExtractedReference {
                               target_name: name,
                               edge_kind: EdgeKind::TypeParameterOf,
                           });
                       }
                   } else {
                       collect_heritage_from_type(child, source, refs);
                   }
               }
           }
           _ => {}
       }
   }
   #+end_src

* Edge Cases
- =class Foo extends Bar {}= (no generics): Should produce one =Inherits= edge to =Bar=, no =TypeParameterOf=.
- =class Foo extends Bar&lt;Baz, Qux&lt;T&gt;&gt;= (nested generics): =Inherits= to =Bar=. =TypeParameterOf= to =Baz=, =Qux=, and =T=. The recursive =collect_identifier_names= inside type_arguments handles nesting.
- =implements A & B= (intersection types): Both =A= and =B= are direct children of the implements clause. They're not inside =type_arguments=, so both get =Inherits=. This is correct.
- =extends_type_clause= (interface extends): Same structure as =extends_clause=. The =type= field children are the extended types.
