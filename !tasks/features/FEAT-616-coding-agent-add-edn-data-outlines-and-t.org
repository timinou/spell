* Scope
In scope: make `.edn` files ergonomically useful in the code tool by adding data outlines keyed by top-level map keys/vector indexes and target IDs like `test/fixtures/golden_books.edn::[:books 0 :title]`. EDN remains data-only: read/navigate/edit can target data forms; graph/code symbol semantics stay off.

Out of scope: treating EDN as Clojure code, resolving namespaces/vars, evaluating tagged literals, or adding graph edges from EDN to Clojure vars. No runtime evaluation.

* Existing Patterns
- EDN profile: `crates/pi-code-engine/src/language/mod.rs`; `edn_profile()` uses tree-sitter-clojure grammar, `data_capabilities()`, no declarations, no graph.
- Outline implementation: `crates/pi-code-engine/src/outline.rs`; currently only declaration patterns produce outline entries, so EDN returns 0 top-level entries.
- Navigation: `crates/pi-code-engine/src/navigate.rs`; raw tree-sitter navigation exists but is not data-path oriented.
- Native target IDs: `crates/pi-natives/src/code_buffer.rs`; `parse_target_id()` splits `<file>::<symbol>`, `resolve_target_id()` assumes symbol names. EDN target paths must coexist with normal symbols and with `::` separator.
- TS output normalization: `packages/coding-agent/src/tools/code-result.ts`; outline entries already include `targetId`, name, kind, line ranges.

* Tests
User workflows to cover first:
1. `code outline test/fixtures/golden_books.edn` returns top-level map keys (`:books`, `:metadata`, etc.) with line ranges and target IDs.
2. Nested data outline can expose vector indexes and map keys enough to target `file::[:books 0 :title]`.
3. `code read` or `code navigate` on an EDN data target returns the exact balanced data form/value.
4. `code edit` can replace an EDN targeted value with balanced EDN content and reject unbalanced/invalid content.
5. EDN graph commands remain unavailable/empty with clear data-only messaging.
6. Target path parser handles spaces/strings/numeric indexes safely and rejects malformed paths truthfully.

Test files:
- `packages/natives/test/code-buffer.test.ts`: EDN fixture outline/read/edit target path scenarios.
- `crates/pi-code-engine/src/outline.rs` or new EDN data outline module: unit tests for maps/vectors/nested paths.
- `packages/coding-agent/test/tools/code.test.ts`: result formatting if target ID display changes.
