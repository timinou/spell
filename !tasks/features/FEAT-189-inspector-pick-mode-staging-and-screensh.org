Decouple element pick from Tidewave resolution in the Phoenix inspector QML.

* Problem
When the user clicks an element in pick mode, the QML immediately:
1. Disables pick mode
2. Calls ~resolveSelectionContext()~ which fires ~bridge.send()~ for Tidewave lookups
3. These bridge events flow through the extension event loop, potentially triggering agent turns

The user wants to type their prompt BEFORE any resolution/send happens.

* Changes

** inspector.qml — Staged pick mode
- On click: capture ~selectedElement~ data, show element preview, but do NOT call ~resolveSelectionContext()~
- Keep pick mode active (or add a "re-pick" toggle that stays visible)
- Add a "Confirm & Resolve" button that triggers Tidewave resolution
- Alternatively: defer resolution to the "Send" / "Quick fix" button press

** inspector.qml — Screenshot toggle
- Add a boolean property ~sendScreenshot~ (default: true)
- Add a toggle button in the action bar: "Include screenshot"
- When enabled, capture a screenshot of the selected element's bounding rect using WebEngineView's ~grabToImage~ or ~runJavaScript~ to get a base64 PNG of the element
- Include the screenshot data in the context sent to the task/agent

* Acceptance
- Clicking an element in pick mode shows element info but does NOT trigger Tidewave bridge events
- A "Resolve" or "Send" action triggers the full resolution flow
- Screenshot toggle captures the element region and includes it in the dispatch payload
- Existing "Send to agent" flow still works after resolution
