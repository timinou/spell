* Edge Cases
- Empty content is valid: replacing the full file with an empty string should behave as a deliberate truncate, not as a no-op
- Existing declaration/line replace precedence must stay stable when `symbol` or `line` is present
- Missing file must still fail on `replace` so callers do not accidentally bypass explicit create validation
- Binary / unsupported files remain governed by existing code-buffer language detection and supported-extension checks
- Formatting should continue to run through the current post-edit path; a whole-file replace must not skip formatter/save orchestration already used by `edit`
- Diff rendering should remain truthful even when the entire file changes
