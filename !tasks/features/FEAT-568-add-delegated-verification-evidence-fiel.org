* Scope

In scope:
- Add a new explicit task/org field for optional delegated verification evidence artifacts. Recommended naming for implementation: `verificationArtifact` in TypeScript-facing task/todo structures and `VERIFICATION_ARTIFACT` for org properties.
- Preserve structured verification evidence in delegated todo results even when no dedicated artifact is requested.
- When a task explicitly opts in, persist a durable evidence artifact that captures the verification summary for later inspection.
- Thread the new field through the todo/task lifecycle, dashboard/serialization surfaces, and delegated result persistence without overloading `gateArtifact`.
- Keep the evidence model compatible with the runtime proof contract from sibling item `BUG-277-reject-delegated-success-without-observe`.

Out of scope:
- Making evidence artifacts mandatory for every delegated task.
- Reusing `gateArtifact` as a proxy for verification evidence. `gateArtifact` remains the deliverable artifact gate; this item adds a distinct proof trail.
- Changing the core meaning of `verifyCmd`, `gateCmd`, or `gateLlm`.
- Implementing screenshots/manual QA capture for unrelated UI tasks.

Rationale: the user asked for durable verification evidence and an audit trail, but only optionally depending on task. The system needs one canonical place for structured proof (`delegation.result`) and one explicit opt-in path for a persisted evidence file.

* Existing Patterns

- `packages/coding-agent/src/tools/todo-write.ts` is the canonical task/todo schema and already persists gate fields, delegation metadata, result summaries, and gate failures.
- `packages/coding-agent/src/task/index.ts::{#finalizeTodoRef,#verifyTaskGates,#verifyChildTodoGates}` already computes delegated completion status and merges `delegation.result` into todo state.
- `packages/coding-agent/src/tools/todo-dashboard-bridge.ts` controls which task fields round-trip through the dashboard bridge; new explicit task fields must be added there intentionally.
- `packages/coding-agent/src/loop/ingestion/org-depend.ts` is the org-property ingestion path for task metadata; org-facing field support belongs there.
- Existing serialization / lifecycle tests already cover adjacent behavior in `packages/coding-agent/test/tools/todo-write-serialization.test.ts`, `packages/coding-agent/test/tools/todo-dashboard-bridge.test.ts`, `packages/coding-agent/test/task/todo-ref-lifecycle.test.ts`, `packages/coding-agent/test/task/gate-enforcement.test.ts`, and `packages/coding-agent/test/tools/todo-write-delegation.test.ts`.
- Prior art for durable verification artifacts exists in plan items and notes across `!tasks/plans/`, but delegated task evidence today is not modeled as an explicit first-class field.

* Edge Cases

- Tasks without `verificationArtifact` must not fail just because no extra artifact file was written.
- The new field must not collide semantically with `gateArtifact`; one is deliverable evidence, the other is verification audit evidence.
- Delegated failure paths (`failed`, `gate_failed`) must record evidence honestly rather than only on success.
- Parent delegated summaries must not lose child evidence metadata when child groups are merged into `delegation.result`.
- If org ingestion sees `VERIFICATION_ARTIFACT` on a child/sub-outline item, the field must survive through task creation the same way other explicit task metadata does.
- Optional artifact paths must resolve relative to the same cwd/worktree rules already used for delegated task artifacts; do not invent a parallel path base.

- A new explicit optional field exists for delegated verification evidence artifacts and round-trips through org/task/todo/dashboard surfaces.

- When `verificationArtifact` is configured, the delegated task writes the evidence artifact and the summary links/reference data remain durable.
- Failed and gate_failed delegated outcomes preserve honest evidence summaries and, when configured, honest evidence artifacts.
- Existing gate propagation and delegated todo lifecycle behavior remain intact.
