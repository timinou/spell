* Context: Why This Exists

The current Emacs-backed code tool opens a fresh buffer for every read operation (=pi-treesit-open-file=), kills it after. For edits, it uses =pi-buffer.el= — a hash-table registry mapping file paths to Emacs buffers with =find-file-noselect=. Diff is =diff-no-select= between buffer content and disk. All of this goes through socat + JSON-RPC with a 30-second timeout per call.

We're replacing this with a Rust-native =CodeBuffer= that is faster (no IPC), persistent (buffers survive across calls), supports multi-agent concurrent editing (via CRDT), and provides tree-based undo/redo per agent.

The canonical design document is =specs/pi-code-engine-spec.md= section 3. Read it before implementing.

This item depends on =PROJ-029-create-pi-code-engine-crate-foundation= (the crate must exist with =LanguageProfile= and =LanguageRegistry= types).

* Goal

Implement =CodeBuffer=, =BufferSnapshot=, =BufferRegistry=, and the tree-based =History= system in =crates/pi-code-engine/src/buffer.rs=. This is the core data structure that outline, navigate, and all edit operations work on.

After this item, you can: open a file → edit it → undo → redo → take snapshots → diff → save. Multiple agents can edit the same buffer concurrently with automatic merge.

* Design Decisions (All Binding)

1. *Rope*: =ropey= crate. O(log N) insert/delete. Arc-based cheap snapshots (=rope.clone()= shares internal nodes). Line-aware (=rope.line()=, =rope.line_to_byte()=).

2. *Tree-sitter incremental parsing*: After each rope mutation, compute an =InputEdit= (byte offsets of the change), call =tree.edit(&input_edit)=, then =parser.parse_with(callback, Some(&old_tree))= where the callback reads from the rope (zero-copy via chunk iteration). This gives sub-millisecond re-parse for typical edits.

3. *CRDT*: =loro= crate. Each buffer owns a =LoroDoc=. Each editing agent has a unique =PeerId=.
   - Edits go through loro's text type: =doc.get_text("content").insert(pos, text)= / =.delete(pos, len)=
   - Loro uses the Fugue algorithm which prevents text interleaving anomalies (the failure mode where two agents insert at the same position and their text gets character-interleaved)
   - =UndoManager::new(&doc)= provides per-agent undo: each agent can undo only their own edits
   - =doc.fork()= creates an independent branch (speculative editing). =doc.merge(&fork)= integrates it.

4. *Undo*: Tree-based history modeled after Helix editor. Each edit creates a =Revision= with a parent pointer and a =Transaction= (the edits) plus its inverse. Undo walks to parent, redo walks to last_child. Jump-to-revision computes LCA and applies inverse/forward transactions.

5. *Edit flow*: =buffer.edit(TextEdit)= → loro records op → rope mutated → =InputEdit= computed → tree incrementally re-parsed → history records revision → version incremented → =EditResult= returned.

6. *BufferRegistry*: =HashMap<PathBuf, CodeBuffer>= managed by a single owner (the NAPI binding thread). NOT thread-safe — all access is from the same NAPI task thread. Holds an =Arc<LanguageRegistry>= for language lookup.

7. *Diff*: Two kinds: (a) =diff_from(snapshot)= compares current rope against a =BufferSnapshot= (for showing what changed since a checkpoint), (b) =diff_from_disk()= compares current rope against the file on disk (for showing unsaved changes). Use =difftastic= for structural diff where available, fall back to line-based diff (=imara-diff= or similar) for the initial implementation.

** Constructor: =CodeBuffer::open=

1. Read file bytes from disk: =std::fs::read_to_string(path)=
2. Match path against =LanguageRegistry= to get =LanguageProfile=
3. Create =Parser=, set language to =profile.ts_language=
4. Parse source → get initial =Tree=
5. Create =Rope::from_str(&source)=
6. Create =LoroDoc::new()=, insert source text into =doc.get_text("content")=
7. Create empty =History= with initial revision
8. Return =CodeBuffer= with version=0, dirty=false

** Constructor: =CodeBuffer::from_str=

Same as =open= but takes source string and =LanguageId= directly. No file path. Used in tests.

** Method: =edit(&mut self, edit: &TextEdit) -> Result<EditResult>=

Step by step:
1. Validate: =edit.start_byte <= edit.old_end_byte=, =edit.old_end_byte <= self.rope.len_bytes()=
2. Apply to CRDT: =self.crdt.get_text("content").delete(start, old_end - start)= then =.insert(start, &edit.new_text)=
3. Apply to rope: =self.rope.remove(byte_range)= then =self.rope.insert(start_char_idx, &edit.new_text)=
   - CAUTION: rope uses char indices, not byte indices. Convert: =self.rope.byte_to_char(edit.start_byte)=
4. Compute =InputEdit=:
   #+begin_src rust
   let input_edit = tree_sitter::InputEdit {
       start_byte: edit.start_byte,
       old_end_byte: edit.old_end_byte,
       new_end_byte: edit.start_byte + edit.new_text.len(),
       start_position: byte_to_point(&self.rope, edit.start_byte),
       old_end_position: byte_to_point(&old_rope, edit.old_end_byte),
       new_end_position: byte_to_point(&self.rope, edit.start_byte + edit.new_text.len()),
   };
   #+end_src
5. Apply to tree: =self.tree.edit(&input_edit)=
6. Re-parse: =let new_tree = self.parser.parse_with(&mut rope_callback, Some(&self.tree))?=
7. =changed_ranges = old_tree.changed_ranges(&new_tree)=
8. Record in history: store =(edit, inverse_edit)= as a new =Revision=
9. =self.tree = new_tree=
10. =self.version += 1=, =self.dirty = true=
11. Return =EditResult=

The =rope_callback= is a closure that reads bytes from the rope. Tree-sitter's =parse_with= takes a callback =|byte_offset, _position| -> &[u8]= that returns the text at the given byte offset. For ropey, iterate rope chunks starting from the byte offset.

** Method: =edit_batch(&mut self, edits: &[TextEdit]) -> Result<Vec<EditResult>>=

Sort edits by =start_byte= descending (highest first). Apply each in order. This prevents earlier edits from shifting positions of later ones.

** Method: =undo(&mut self) -> Result<Option<TextEdit>>=

1. If =history.current == 0= (at root): return =Ok(None)=
2. Get inverse transaction from current revision
3. Apply inverse edits to rope + tree (same flow as =edit()= but skip history recording)
4. Move =history.current= to parent
5. Return the inverse edit

** Method: =redo(&mut self) -> Result<Option<TextEdit>>=

1. Get =last_child= of current revision. If None: return =Ok(None)=
2. Apply forward transaction from child revision
3. Move =history.current= to child
4. Return the forward edit

** Type: =History=

#+begin_src rust
struct History {
    revisions: Vec<Revision>,
    current: usize,  // index into revisions
}

struct Revision {
    parent: usize,
    last_child: Option<usize>,
    forward: TextEdit,   // the edit that was applied
    inverse: TextEdit,   // the edit that undoes it
}

impl History {
    fn new() -> Self {
        // Create root revision (dummy, represents initial state)
        Self {
            revisions: vec![Revision { parent: 0, last_child: None, forward: TextEdit::empty(), inverse: TextEdit::empty() }],
            current: 0,
        }
    }

    fn record(&mut self, forward: TextEdit, inverse: TextEdit) {
        let new_idx = self.revisions.len();
        let parent = self.current;
        self.revisions.push(Revision { parent, last_child: None, forward, inverse });
        self.revisions[parent].last_child = Some(new_idx);
        self.current = new_idx;
    }
}
#+end_src

fn byte_to_point(rope: &Rope, byte_offset: usize) -> tree_sitter::Point {
    let line = rope.byte_to_line(byte_offset);
    let line_start_byte = rope.line_to_byte(line);
    let col = byte_offset - line_start_byte;
    tree_sitter::Point::new(line, col)
}

* Edge Cases (Must Handle)

1. *Byte vs char indices*: Rope uses char indices for insert/remove. Tree-sitter uses byte offsets. Always convert: =rope.byte_to_char(byte_offset)= before rope mutations, =rope.char_to_byte(char_idx)= when going back. Multi-byte UTF-8 characters (emoji, CJK) make these differ.

2. *Empty file*: =CodeBuffer::open= on an empty file should produce a valid buffer with an empty rope and a parsed (trivial) tree.

3. *Binary file*: Before opening, check first 8192 bytes for null bytes (=\0=). If found, return =CodeEngineError::Buffer("binary file detected")=.

4. *File >100MB*: Return error rather than OOMing. Check =std::fs::metadata(path)?.len()=.

5. *Unknown language*: If =registry.match_path(path)= returns None, return =CodeEngineError::LanguageNotFound=.

6. *Parse timeout*: Set =parser.set_timeout_micros(5_000_000)= (5 seconds). If parse returns None after timeout, return error.

7. *Undo past root*: =undo()= at root returns =Ok(None)=, not an error.

8. *Redo with no children*: =redo()= with no =last_child= returns =Ok(None)=.

9. *edit_batch with overlapping edits*: If two edits in the batch overlap in byte range, return error. Don't silently corrupt.

10. *Save without path*: =save()= on a buffer created with =from_str()= (no path) returns error.

* Sequencing Note

Implement in this order:
