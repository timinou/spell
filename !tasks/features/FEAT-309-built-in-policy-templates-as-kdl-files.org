* Initial Message

I want to set up task policies in kdl with a command when I enter a new repository. like some sort of onboarding thing. what could that look like? finish with your completed summary

Ship static KDL template files that provide default layers and policies for common project types. These are the targets of =import "spell.coding.typescript"= references in =spell.kdl=.

* Template Catalog

| Namespace                  | Domain  | Description                          |
|----------------------------+---------+--------------------------------------|
| =spell.coding.typescript=  | coding  | TS/JS: core, api, ui, data layers   |
| =spell.coding.rust=        | coding  | Rust: core, api, cli layers         |
| =spell.coding.python=      | coding  | Python: core, api, data layers      |
| =spell.coding.go=          | coding  | Go: core, api, cmd layers           |
| =spell.growth.default=     | growth  | Growth: content, analytics, outreach |

* File Location

=packages/coding-agent/src/templates/= with filenames matching the dot-namespace: =spell.coding.typescript.kdl=, etc. Loaded at runtime via =import ... with { type: "text" }= (Bun static text import).

* Example: spell.coding.typescript.kdl

#+begin_src kdl
// Base template for TypeScript projects
// Imported via: import "spell.coding.typescript"

layer "core" description="Core business logic and shared types"
layer "api" description="API endpoints, routes, and middleware"
layer "ui" description="Frontend components and pages"
layer "data" description="Database models, migrations, and queries"

policy "core-quality" layer="core" {
    gate-commit true
}

policy "api-quality" layer="api" {
    gate-commit true
    gate-cmd "bun test"
}

policy "ui-quality" layer="ui" {
    gate-commit true
    gate-cmd "bun test"
}

policy "data-safety" layer="data" {
    gate-commit true
    gate-llm "Verify migration safety and reversibility"
}
#+end_src

* Sub-outline

** create template directory and index
Create =packages/coding-agent/src/templates/= directory with all 5 KDL files plus an =index.ts= barrel that maps dot-namespace strings to their text content:
#+begin_src typescript
const TEMPLATES: Record<string, string> = {
    "spell.coding.typescript": typescriptTemplate,
    "spell.coding.rust": rustTemplate,
    // ...
};
export function resolveTemplate(namespace: string): string | undefined {
    return TEMPLATES[namespace];
}
#+end_src

** write tests for template resolution
Test in =packages/coding-agent/test/config/template-resolution.test.ts=:
- Each namespace resolves to non-empty string
- Unknown namespace returns undefined
- Resolved content parses as valid KDL via =parseTaskPoliciesKdl=

* Verification
- All 5 template files exist under =packages/coding-agent/src/templates/=
- =resolveTemplate("spell.coding.typescript")= returns parseable KDL
