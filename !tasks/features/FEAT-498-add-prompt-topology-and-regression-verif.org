* Context
This initiative changes a large amount of model-facing text. Without targeted regression tests, the next edit can silently reintroduce stale old-tool guidance, broken template placement, or low-quality compact summaries.

Current test patterns to build on:
- `packages/coding-agent/test/system-prompt-templates.test.ts` compiles every system template and asserts semantic anchors/conditionals.
- `packages/coding-agent/test/tools/index.test.ts` verifies tool tiers and `compactToolDescription()` semantics.
- `packages/coding-agent/test/prompts/auto-roster-prompts.test.ts` checks prompt branches by semantic content instead of snapshots.
- `packages/coding-agent/test/plan-mode/plan-mode-approved-prompt.test.ts` and `packages/coding-agent/test/caveman.test.ts` verify important overlay behavior.

This item should harden coverage around the rewrite without adding fragile giant snapshots.

* Implementation
1. Add tool-prompt compilation coverage for actual canonical tool prompt assets after the topology cleanup. This should fail if non-tool templates creep back into the tool directory or if a live tool prompt stops compiling.
2. Add agent-prompt compilation coverage for actual canonical agent prompt assets after topology normalization.
3. Extend existing tool tests to assert the post-rewrite contracts that matter:
   - specialized-tool first sentences remain compact-worthy and truthful
   - moved prompt files are no longer imported from legacy/orphaned paths
   - canonical description sources exist for inline/hidden tools normalized by the topology item
4. Extend existing system-prompt tests to assert the new tool-era guidance where it matters:
   - relevant prompts prefer `code` for source-file work
   - stale old-tool examples no longer appear in the system layer
   - plan-mode overlays and caveman/terseThinking branches still render truthfully
5. If skill content needs direct regression checks, keep them semantic and narrow. Prefer verifying the specific stale examples are gone rather than snapshotting entire SKILL files.
6. Final verification must include focused prompt tests plus `bun check:ts` because topology cleanup may move prompt imports and descriptions across TypeScript files.

* Edge Cases
- Do not write tests that only prove a file exists. Each assertion must protect a contract: compileability, canonical source-of-truth, absence of stale guidance, or compact-summary behavior.
- Avoid brittle exact-string tests unless downstream behavior depends on exact bytes.
- Keep verification focused on changed surfaces; do not add package-wide smoke tests that say little.

* Acceptance
- New or updated tests fail if legacy prompt topology or stale old-tool guidance is reintroduced.
- The rewritten prompt stack compiles/renders under focused test coverage.
- `bun check:ts` passes after the prompt and topology changes land.
