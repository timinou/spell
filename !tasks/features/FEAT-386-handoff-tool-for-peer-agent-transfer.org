* Narrative

In the current system, agent control flow is strictly hierarchical: a parent agent dispatches subagents via the =task= tool, and subagents return results to the parent via =submit_result=. There is no way for a running subagent to say "I've done what I can; agent X should take over from here with this context."

This matters for swarms because agents discover things at runtime that change what should happen next:
- A code analysis agent finds that the fix requires database schema changes. It cannot do that work, but it has assembled the exact context a schema-migration agent would need.
- A test-writing agent finishes writing tests and wants to hand off to an implementation agent with the test file paths and failing assertions as structured input.
- An agent hits an unexpected API boundary and needs to hand off to a specialist (e.g., from a TypeScript agent to a Rust agent for crate changes).

The handoff tool lets a running agent transfer control to another agent (or a scheduler-selected agent) by writing a structured =HandoffRecord= to the blackboard and signaling the scheduler via the event bus. The current agent's session ends (it calls =submit_result= with the handoff details), and the scheduler creates a new task node in the live DAG for the receiving agent.

This is distinct from =spawn_successor= (FEAT-387): handoff *replaces* the current agent (it's done), while spawn_successor *extends* the DAG (the current agent continues).

* Design Decisions

1. The handoff tool is a new =AgentTool= available to subagents in swarm mode. Name: =handoff=.
2. Parameters:
   - =targetAgent?: string= -- suggested agent type. Scheduler may override. If omitted, scheduler picks.
   - =context: string= -- structured context for the receiving agent (what was done, what needs doing, key files).
   - =partialResult?: string= -- any intermediate output the receiving agent should have.
   - =reason: string= -- why the handoff is happening (for audit/blackboard).
3. When a subagent calls =handoff=:
   a. A =HandoffRecord= is written to the blackboard (=SwarmBlackboard.write= with type=handoff).
   b. A =SwarmHandoffEvent= is enqueued on =SWARM_HANDOFF_CHANNEL=.
   c. The tool returns a success message, and the agent MUST call =submit_result= immediately after.
   d. The scheduler receives the event and creates a new node in the =MutableDag= with a dependency on the current agent and the handoff context injected into the assignment.
4. If =targetAgent= is specified and the agent type exists, the scheduler uses it. Otherwise, the scheduler selects based on the handoff context (or asks the parent agent to decide).
5. The receiving agent's assignment includes the handoff context, the partial result, and a reference to the blackboard entry (for querying additional state).
6. Handoff is optional: agents that don't need it simply call =submit_result= as usual. The tool is only available in swarm execution mode.

** =packages/coding-agent/src/task/swarm-scheduler.ts=
Subscribe to =SWARM_HANDOFF_CHANNEL=. On handoff event:
1. Resolve target agent type (from event or auto-select).
2. Create new =MutableDag= node with dependency on the handoff source agent.
3. Set the new node's assignment to include handoff context + partial result.
4. Node enters the ready queue once the source agent completes.

** =packages/coding-agent/src/swarm/blackboard.ts=
No structural changes needed -- =write()= with =type=handoff= already supported. Just verify =HandoffRecord= fields are stored correctly.
