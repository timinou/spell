* Context — Why This Exists
We are adding cross-file code intelligence to the Spell coding agent. Today the agent has:
- =code= tool (Emacs treesit): single-file AST operations (read, outline, navigate, edit)
- =lsp= tool: 1-hop cross-file semantics (references, definitions)
- =ast_grep=: pattern-based structural search

What's missing: transitive call graphs, impact analysis ("change X → what breaks?"), cross-file dependency maps, dead code detection, execution flow tracing, architectural clustering. These require a *code graph* — a persistent, queryable representation of how symbols and files relate across the entire codebase.

This item builds the Rust foundation crate that everything else depends on.

** Prior Art Studied
- *GitNexus* (26k★): PolyForm Noncommercial license, can't use. Architecture: tree-sitter → LadybugDB graph → MCP tools.
- *Axon* (653★): Python, KuzuDB. No license. Architecture: tree-sitter → graph DB → MCP.
- *code-graph-cli* (5★, MIT): Rust, petgraph + tree-sitter + oxc_resolver. Good reference architecture. https://github.com/MonsieurBarti/code-graph-ai
- *tree-sitter-stack-graphs*: Abandoned by GitHub. Overkill for our needs.
- All converge on: tree-sitter parsing → petgraph/graph-DB → typed edges → BFS traversal queries.

** Key Design Decisions
1. New workspace crate =crates/pi-code-graph= (lib, not cdylib). pi-natives depends on it for NAPI exposure.
2. =petgraph::stable_graph::StableGraph<GraphNode, EdgeKind, Directed>= — StableGraph keeps NodeIndex stable across removals (needed for incremental updates).
3. O(1) lookup indexes: =HashMap<PathBuf, NodeIndex>= (files), =HashMap<String, Vec<NodeIndex>>= (symbols by name).
4. Bincode serialization to =.spell/graph/= for persistence. BM25 search index is transient (rebuilt after deserialization).
5. Concurrency: =Arc<CodeGraph>= snapshot via =arc-swap= crate. Readers get immutable snapshot, writer builds new graph and atomically swaps.
6. Two-trait language interface: =LanguageExtractor= (per-file, stateless AST extraction) + =ImportResolver= (project-level, holds config state). Adding a language = implement both traits + register.
7. Indexing pipeline: Walk (=ignore= crate, respects .gitignore) → Parse (rayon parallel) → Resolve (per-language resolvers) → Build graph → Cache.

** Existing Codebase Patterns To Follow
- Workspace root: =Cargo.toml= at repo root lists =members=. Add =crates/pi-code-graph= to members.
- pi-natives =Cargo.toml= already depends on =tree-sitter = "0.25"=, =rayon = "1"=, =ignore = "0.4"=. Match versions.
- pi-natives uses =napi= / =napi-derive= for NAPI bindings. pi-code-graph does NOT have NAPI — it's a pure Rust lib.
- Rust style: no =pub(crate)= unless necessary, use =pub= for crate API, private for internals.

#[test]
fn add_symbol_creates_contains_edge_from_file() {
    let mut g = CodeGraph::new();
    let file_idx = g.add_file(PathBuf::from("src/main.ts"), "typescript");
    let sym = SymbolDef { name: "greet".into(), kind: SymbolKind::Function, ..Default::default() };
    let sym_idx = g.add_symbol(file_idx, sym);
    // Verify Contains edge exists from file to symbol
    assert!(g.graph.edges(file_idx).any(|e| e.target() == sym_idx && matches!(e.weight(), EdgeKind::Contains)));

#[test]
fn add_child_symbol_creates_child_of_edge() {
    let mut g = CodeGraph::new();
    let file_idx = g.add_file(PathBuf::from("src/main.ts"), "typescript");
    let class_sym = SymbolDef { name: "User".into(), kind: SymbolKind::Class, ..Default::default() };
    let class_idx = g.add_symbol(file_idx, class_sym);
    let method_sym = SymbolDef { name: "validate".into(), kind: SymbolKind::Method, parent: Some("User".into()), ..Default::default() };
    let method_idx = g.add_child_symbol(class_idx, method_sym);
    // ChildOf edge goes from child → parent
    assert!(g.graph.edges(method_idx).any(|e| e.target() == class_idx && matches!(e.weight(), EdgeKind::ChildOf)));
}

#[test]
fn symbol_index_allows_multiple_symbols_with_same_name() {
    let mut g = CodeGraph::new();
    let f1 = g.add_file(PathBuf::from("a.ts"), "typescript");
    let f2 = g.add_file(PathBuf::from("b.ts"), "typescript");
    g.add_symbol(f1, SymbolDef { name: "Config".into(), kind: SymbolKind::Interface, ..Default::default() });
    g.add_symbol(f2, SymbolDef { name: "Config".into(), kind: SymbolKind::Class, ..Default::default() });
    assert_eq!(g.symbol_index.get("Config").unwrap().len(), 2);
}

#[test]
fn remove_file_cleans_up_symbols_and_edges() {
    let mut g = CodeGraph::new();
    let file_idx = g.add_file(PathBuf::from("src/main.ts"), "typescript");
    let sym = SymbolDef { name: "foo".into(), kind: SymbolKind::Function, ..Default::default() };
    g.add_symbol(file_idx, sym);
    assert_eq!(g.file_count(), 1);
    assert_eq!(g.symbol_index.get("foo").unwrap().len(), 1);
    g.remove_file(Path::new("src/main.ts"));
    assert_eq!(g.file_count(), 0);
    assert!(g.symbol_index.get("foo").map_or(true, |v| v.is_empty()));
}

* Error Handling
- Tree-sitter parse returns =None= for malformed files → skip file, log warning, continue
- File read errors → skip file, log warning
- Resolver init fails (e.g., invalid tsconfig) → log error, resolver returns =Unresolved= for all specifiers
- Bincode deserialization fails (corrupt cache) → rebuild from scratch
- Empty project (no supported files) → return empty graph, not error
