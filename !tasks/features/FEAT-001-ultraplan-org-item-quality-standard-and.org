** Change 2: Add Org Item Body Standard
Insert a new subsection between Phase 4 (Daedalus) and Phase 5 (Create Org Items). This subsection defines the mandatory sections for every child item body:

=* Scope= — What is in, what is explicitly out, why this boundary.
=* Implementation= — Specific file paths, module/function names, type signatures (code snippets for non-trivial interfaces), step-by-step instructions. Not vague descriptions.
=* Tests= — Per-item test specifications. Each item carries its own test requirements:
  - Unit test file paths with specific test case descriptions
  - Integration test scenarios where the item participates

=* Edge Cases= — What can go wrong, error codes, degradation behavior, race conditions.
=* Acceptance Criteria= — Concrete, manually checkable conditions. Not "it works" — specific observable outcomes. Example: "POST /api/webhooks/whatsapp with valid HMAC returns 200 and creates a Message record" not "webhook ingestion works".

The subsection should also note:
- Acceptance criteria must be falsifiable — another engineer can check each one independently
- Public APIs must include full type signatures
- File paths must be explicit (=lib/myapp/foo/bar.ex=), not vague ("a module in the foo directory")
- Dependencies on other items must name the specific artifact needed (e.g., "requires Conversation schema from PROJ-A" not just "depends: PROJ-A")
