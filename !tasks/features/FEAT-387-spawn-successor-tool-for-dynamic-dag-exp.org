* Narrative

In the current system, the shape of the task DAG is fixed at dispatch time. When the parent agent calls the =task= tool, it declares all tasks and their blockers upfront. If a subagent discovers mid-execution that additional work is needed -- a new module to create, a discovered dependency to investigate, a test suite to write for code it just generated -- it has no way to express this. It can only include the finding in its =submit_result= output and hope the parent agent reads it and dispatches a follow-up.

This is the "closed world" problem: the DAG assumes all required work is known in advance. Real-world coding tasks are inherently open-ended -- agents discover scope during execution.

=spawn_successor= lets a running agent dynamically add a new node to the live DAG. Unlike =handoff= (which ends the current agent), =spawn_successor= extends the graph: the current agent continues working while the new node waits for its dependencies to be satisfied. The current agent can declare itself as a dependency (meaning the successor waits for it to finish) or declare other agents as dependencies (meaning the successor starts as soon as those agents complete, potentially before the spawner finishes).

This is the dual mechanism to handoff: handoff is "I'm done, someone else continue." Spawn_successor is "I need more work done in parallel or after me."

* Design Decisions

1. The spawn_successor tool is a new =AgentTool= available to subagents in swarm mode. Name: =spawn_successor=.
2. Parameters:
   - =task: string= -- the assignment for the new agent (what it should do).
   - =dependsOn?: string[]= -- agent IDs the successor depends on. Defaults to =[currentAgentId]= (waits for spawner to complete).
   - =agentType?: string= -- suggested agent type. Defaults to same type as spawner.
   - =filesDeps?: string[]= -- file paths the successor will modify (for overlap detection).
   - =metadata?: Record<string, unknown>= -- arbitrary structured data passed to the successor's context.
3. When a subagent calls =spawn_successor=:
   a. The tool validates dependencies (all referenced agents must exist in the DAG).
   b. A new =FluidAgentNode= is created with a generated ID: =<spawnerAgentId>-successor-<n>=.
   c. The node is added to the =MutableDag= via =dag.addNode()=. Cycle detection runs.
   d. An =ArtifactRecord= is optionally written to the blackboard documenting the spawned task.
   e. The tool returns the new node's ID to the spawning agent (so it can reference it in subsequent calls or its =submit_result=).
   f. The scheduler's pump loop picks up the new node once its dependencies are satisfied.
4. The spawner agent does NOT stop -- it continues executing. The successor is a new, independent task.
5. If =dependsOn= is empty (=[]=), the successor starts immediately if concurrency allows (useful for parallel work).
6. The successor's assignment includes: the =task= text, any =metadata= as structured context, and predecessor results from its dependencies (via existing =resolvePredecessorResultsContext= mechanism).
7. The tool is only available in swarm execution mode. Calling it outside swarm mode returns an error.

- Assert: new node has deps=["agent-b", "agent-c"] (NOT agent-a).

*** Spawn with empty deps (immediate start)
- =spawn_successor({ task: "...", dependsOn: [] })=.
- Assert: new node has no deps, enters ready queue immediately.

*** Spawn with invalid dep (missing agent)
- =spawn_successor({ task: "...", dependsOn: ["nonexistent"] })=.
- Assert: returns error "Dependency nonexistent not found in DAG".

*** Spawn creating cycle
- Agent "agent-a" depends on "agent-b". Agent "b" calls =spawn_successor({ task: "...", dependsOn: ["agent-a"] })=.
- This would create a->b->successor->a cycle. Assert: error "Cycle detected".
  (Actually: successor depends on agent-a which depends on agent-b which is the spawner. The cycle is: if successor also had agent-b as a dep. The test should construct the exact scenario.)

*** Spawn with filesDeps
- =spawn_successor({ task: "...", filesDeps: ["src/parser.ts"] })=.
- Assert: new node in DAG has filesDeps set.

*** Spawn with metadata
- =spawn_successor({ task: "...", metadata: { testFiles: ["test/parser.test.ts"], failingAssertions: 3 } })=.
- Assert: new node's assignment includes metadata as structured context.

*** Spawn outside swarm mode
- Returns error: "spawn_successor is only available in swarm execution mode."
