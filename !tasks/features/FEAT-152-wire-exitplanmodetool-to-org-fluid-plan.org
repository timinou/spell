* Scope

ExitPlanModeTool.execute() resolves PLAN items and child refs but never calls org-fluid-plan MCP. The ~fluidPlan~ field in ExitPlanModeDetails is always undefined, so the FluidOrchestrator path in interactive-mode.ts #approvePlan is never triggered.

** In
- Add OrgClient access to ExitPlanModeTool (via ToolSession.emacsSessionManager or by exposing org tool's internal client)
- Call ~org-fluid-plan~ MCP with ~{plan_id: itemId}~ after child ID validation passes
- Parse response into FluidPlanWithComponents, set on details.fluidPlan
- Handle MCP failure gracefully: log warning, fall back to wave-based execution (fluidPlan stays undefined)

** Out
- No changes to interactive-mode.ts (already consumes fluidPlan)
- No changes to FluidOrchestrator

* Approach

Expose a ~getOrgClient()~ method on ToolSession (or add it alongside existing ~emacsSessionManager~). The OrgClient is created lazily from the Emacs MCP socket. ExitPlanModeTool calls ~client.callTool("org-fluid-plan", {plan_id})~, parses JSON result into FluidPlanWithComponents.

Alternative: have ExitPlanModeTool invoke the org tool internally via ~session.executeTool("org", {command: "fluid_plan", ...})~. This requires adding a fluid_plan subcommand to the org tool, which is more invasive.

Preferred: direct OrgClient access via ToolSession.
