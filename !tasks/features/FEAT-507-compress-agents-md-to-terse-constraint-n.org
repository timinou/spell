* Initial Message

Look at PLAN 181 and PLAN 207. With the same freedom, can you tell me how you could express yourself even more by applying the terse thinking mode to the whole surface of what is sent to the llm?

* Scope
Compress =AGENTS.md= from ~5,500 tokens of developer tutorial prose to ~1,800 tokens of terse constraint notation. This is the single highest-impact compression target.

** In scope
- Rewrite =AGENTS.md= to terse constraint notation
- Preserve all constraints and rules (MUST/MUST NOT)
- Preserve all project-specific information the model cannot derive

** Out of scope
- System prompt template (=system-prompt.md=) — separate item
- Tool descriptions — separate items
- Adding new rules or changing existing rules (content-preserving rewrite only)

* Existing Patterns
- =specs/prompt-surface-compression.md= (created by FEAT-506) — defines the compression rules
- =specs/system-prompt-architecture.md= — documents AGENTS.md boundary: "AGENTS.md encodes how THIS project works"
- Current AGENTS.md structure: Package Structure, Org Logic, Code Quality, Bun Over Node, Logging, TUI Rendering, Commands, Testing, GitHub Issues, Style, Changelog, Releasing

* Design Decisions
1. Compress in place — the file itself becomes terse. Developers read constraint notation.
2. No BAD/GOOD code pairs unless the pattern is genuinely non-obvious (the model knows what namespace imports look like)
3. Tables for decision rules (e.g., "Where Bun Wins" table stays but shrinks)
4. Package Structure table: keep as-is (already concise)
5. Commands table: keep as-is (already concise)
6. Code Quality section: each rule becomes one bullet, no code examples
7. Bun Over Node section: biggest opportunity — ~2,000 words of tutorials → ~400 words of constraint lists
8. Testing Guidance: already reasonably terse, light compression
9. Preserve Handlebars-consumable markdown format (the file is injected raw into prompts)

* Edge Cases
- AGENTS.md is consumed raw by the prompt system (no rendering pipeline). The file IS the prompt content.
- Some AGENTS.md rules reference specific function names (=replaceTabs()=, =shortenPath()=, =readStream()=) — these MUST survive compression.
- The file is also read by human developers — constraint notation must be unambiguous.
- Some code examples in the Bun section are genuinely helpful for developers new to Bun APIs. But the LLM knows Bun. Favor LLM efficiency over developer onboarding.
