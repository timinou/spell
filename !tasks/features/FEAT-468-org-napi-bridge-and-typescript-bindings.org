* Goal

Expose =pi-org-engine= through NAPI bindings in =crates/pi-natives/= and provide TypeScript wrapper types in =packages/natives/=. This follows the exact pattern of =executeCodeBuffer= / =executeCodeGraph= for the code tool.

* Design Decisions

- Single NAPI entry point: =executeOrg(options: Value) -> Value= (synchronous, matching code_buffer.rs pattern)
- Command dispatch via =options.command= string field
- Results wrapped in ={"output": ..., "error": bool}= envelope (matching code tool pattern)
- OrgBufferRegistry uses =OnceLock<Mutex<OrgBufferRegistry>>= for thread safety (matching code_buffer.rs)
- TypeScript types mirror the Rust OrgItem struct

* Reference Pattern: =crates/pi-natives/src/code_buffer.rs=

The code_buffer.rs pattern to follow:
1. Static registry with OnceLock + Mutex
2. Helper functions: =engine_err()=, =json_err()=, =json_response()=, =to_json()=
3. Single =#[napi]= function with match on command string
4. Each command extracts params from serde_json::Value, calls engine, returns json_response

* Commands to Implement

| Command | Description | Input | Output |
|---------|-------------|-------|--------|
| parse | Parse org file, return all items | file path | Vec<OrgItem> as JSON |
| get | Get single item by ID | file path, custom_id | OrgItem as JSON |
| query | Filter items with keyword syntax | files[], query string, sort, limit, offset | Vec<OrgItem> as JSON |
| graph | Build dependency graph | files[] | { nodes, edges, cycles } |
| wave | Next wave of eligible items | files[], cap | { wave, items, total } |
| waves | Compute all waves (Kahn's) | files[] | [{ number, items }] |
| components | Connected components | files[] | [{ root_id, member_ids, waves }] |
| section_range | Find byte range of named section | file, custom_id, section | { start, end } |
| to_markdown | Convert org to markdown | file path or text | markdown string |
| validate | Validate items against schema | files[] | { valid, errors, warnings } |

* Edge Cases

- Large org files (>1MB): should not crash, may return error for files exceeding size limit
- Concurrent access: OrgBufferRegistry is Mutex-protected, safe from multiple threads
- Invalid JSON in options: descriptive error message
- Missing required fields: specific error message naming the missing field
