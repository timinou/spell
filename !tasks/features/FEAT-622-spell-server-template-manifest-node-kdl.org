* Initial Message

Goal: simple frontend to spell server. a client can connect with a secret token to a fast websocket that can let you connect with the running sessions by that user on that instance (through spell autodiscovery, consolidate the feature by looking at existing usage of similar features).

On the frontend, you can start new plan sessions, you can request a url, etc. that lets you use both xterm.js and, for example, see the pdf generated from a typst requested by a task whose goal was to generate a report.

easy way to setup templates from the frontend, wiht a linear-like command bar. Template 'document', you run it, you get a nice card in your session list, and then it tells you when it has the artifact ready.

* Intention & Purpose
Introduce a new top-level ~template "<name>" { … }~ node alongside ~goal~ and ~setup~ in ~autonomy.kdl~. A template is a lightweight, schedule-less, ad-hoc-runnable preset: name + description + setup ref + initial prompt (Handlebars-renderable) + typed params + optional artifact-watch hint. Templates feed the web frontend's command-bar.

* Context & Narrative
Goals carry too much weight (cron schedule, hooks, retry, escalation). Templates fill the missing slot: a manifest-declared, parameterized one-shot the human invokes from the cmd-K palette. The grammar deliberately reuses the existing ~param~/~prompt-slot~ machinery already used by ~action-descriptor~ so the manifest layer evolves coherently. Validation runs alongside ~validateManifest~.

This item only adds parsing/types/serialization/validation. Spawning is owned by FEAT-WEB-TEMPLATE-RUN.
