* Edge Cases

- Heading lines that contain CUSTOM_ID inside a code block or quoted text: not an issue because the rewrite pass scans line-by-line, not AST-aware. Documentation prose that mentions CUSTOM_ID values inside body paragraphs would be rewritten too; guarded by the regex requiring leading whitespace plus exact property shape. Prose won't match.
- Triple-star grand-child sub-outlines: out-of-scope for ITEM injection. Only two-star sub-outlines are injected. Matches the Body Standard's "second-level" model.
- Multi-line headings are not an org concept; single-line guarantee.
- A bare-title heading followed immediately by another heading (no PROPERTIES drawer): no CUSTOM_ID found so no injection. Safe default.
- Whitespace before stars tolerated.
- Existing ITEM-prefixed heading passed through rewrite: the keyword check sees ITEM as first word, skips injection. Idempotent.
- Empty body passed to update: skip all work, return empty string.
- rewriteSubOutlineIds callers that destructure rewrites: the returned map still reflects CUSTOM_ID changes; ITEM injection is silent (no entry added).
