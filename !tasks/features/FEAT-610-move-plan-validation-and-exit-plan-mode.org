* Scope

In scope:
- Move the expensive plan-validation and plan-item resolution work from repeated TypeScript category rescans into native org-index-backed commands.
- Cut over `validatePlanItem`, `resolvePlanItem`, `approvePlanItem`, `completePlanItem`, and `exit_plan_mode` child/property hydration to consume native indexed results.
- Preserve existing validation categories and dual-link/sub-outline semantics unless a documented truthfulness bug requires a change.
- Keep TypeScript responsible only for formatting user-facing validation hints and plan-approval payload assembly.

Out of scope:
- General org read-surface cutover for `query` / `dashboard` / `archive` (handled by FEAT-609).
- Shared cache extraction and mutation freshness foundations (handled by PROJ-057 and FEAT-608).
- Rewriting wave computation itself; this item targets lookup/validation/orchestration cost, not the graph algorithm.

Rationale:
- `packages/coding-agent/src/plan-mode/plan-validation.ts` and `packages/coding-agent/src/tools/exit-plan-mode.ts` currently repeat the same expensive lookup/parsing work across validation, approval payload building, and child-layer hydration. The Rust org index should become the single source of truth for plan resolution and validation structure.

* Existing Patterns

- `packages/coding-agent/src/plan-mode/plan-validation.ts` — current validation issue categories, sub-outline normalization, and resolved-children contract are the behavior to preserve while moving computation native.
- `packages/coding-agent/src/plan-mode/org-plan.ts` — `resolvePlanItem`, `approvePlanItem`, and `completePlanItem` show every plan-mode lookup path that currently depends on `findItemById` rescans.
- `packages/coding-agent/src/tools/exit-plan-mode.ts` — validation gate + child item injection + wave layer hydration identify the exact approval-time hot path to cut over.
- `packages/coding-agent/src/loop/ingestion/org-depend.ts` — `parseOrgDependProperties(...)` documents the current sub-outline dependency extraction behavior that native validation must match or subsume.
- Existing regression tests: `packages/coding-agent/test/plan-mode/plan-validation-suboutline.test.ts`, `packages/coding-agent/test/plan-mode/exit-plan-layer-resolution.test.ts`, and `packages/coding-agent/test/tools/exit-plan-mode-waves.test.ts`.

* Tests

User workflows to defend first:
1. Workflow 1 — `org validate-plan <PLAN-ID>` on a dual-link manifest returns the same valid/invalid outcomes and issue categories as today, but through native indexed validation.
2. Workflow 2 — `exit_plan_mode` approval payload loads linked child items and wave layers without repeated per-child rescans.
3. Workflow 3 — `approvePlanItem` and `completePlanItem` resolve plan/child items through the index and remain truthful after recent writes.
4. Workflow 4 — missing linked items, phantom sub-outline links, broken DEPENDS, and manifest-missing-suboutlines still surface with the same semantics.

Concrete test files / scenarios:

* Edge Cases

- Duplicate CUSTOM_ID conflicts must surface truthfully; native validation must not silently pick one child and proceed as though the plan were unambiguous.
- Sub-outline IDs that inherit parent LAYER must still resolve correctly in `exit_plan_mode` payloads.
- Recent in-session mutations must be visible to validation and approval flows without manual cache rebuilds.
- Very large plans with many linked children must avoid N×category rescans and N×body reparse loops.
- Validation output ordering should stay deterministic so existing tests and human diagnostics remain stable.

* Acceptance Criteria

- `validatePlanItem` / `org validate-plan` / `exit_plan_mode` rely on native indexed validation/lookup for their steady-state path.
- Existing dual-link validation semantics and issue categories are preserved.
- `packages/coding-agent/src/plan-mode/{plan-validation.ts,org-plan.ts}` no longer perform whole-category rescans as the normal way to resolve plan/child items.
- Focused coding-agent tests prove parity for validation issues, approval payloads, and child-layer resolution.
