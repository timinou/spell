Out-of-scope:

- Changes to `task.isolation.mode` default.
- Any change to top-level (depth=0) task dispatch; main-session `task` calls stay explicit-opt-in.

Rationale: the incident session had no isolation because:
1. `task.isolation.mode` is non-default per workstation settings.
2. Main session dispatched `agent: task`; that task agent then delegated to `agent: quick_task` without `isolated: true`.
3. Children's destructive edits landed directly on the live workspace.

Isolation-on-nested-dispatch is a cheap safety net: the parent task agent is already a contained execution; its children's patches should go through the parent before merging into the real tree.

Scenarios:

1. *depth=0 no auto-coerce* — top-level task dispatch with `isolated` absent → isolation not engaged regardless of agent or file scope.

2. *depth=1, task.isolation.mode="none"* — no auto-coerce; existing "Task isolation is disabled" path unreachable because no coercion happened.

3. *depth=1, mode=worktree, single non-code file* — batch of one task mutating `docs/README.md` only → no auto-coerce (threshold not met).

4. *depth=1, mode=worktree, batch>1* — two tasks → auto-coerce to `isolated: true` even if each task is single-file.

5. *depth=1, mode=worktree, any code-supported file* — one task with `filesDeps: ["src/foo.ts"]` → auto-coerce triggered by code-file heuristic.

6. *depth=1, mode=worktree, explicit isolated:false* — caller passed `isolated: false` → respected; no auto-coerce override.

7. *depth=1, mode=worktree, explicit isolated:true* — behaves like today; auto-coerce is a no-op.

8. *render surface* — auto-coerced call shows `[isolated:auto]` indicator in task render output.

* Edge Cases

- *Auto-coerce with no isolation infra* — if `isolationMode === "none"` we never coerce; users must opt in by configuring the mode.
- *Performance overhead* — worktree/fuse-overlay modes add startup cost. At depth >= 1 the extra cost is bounded and small vs. risk of destructive edits.
- *Subagent wants to run a shell command that affects state* — isolation only protects files; processes spawned by subagent still run on host. Acceptable for this FEAT; future work can sandbox exec.
- *Nested nested tasks* — depth=2 inherits the same rule. Coercion is cheap and idempotent.
- *Merge conflicts on patch apply* — existing worktree merge already handles; no new failure modes.
- *Settings drift* — if user changed `task.isolation.mode` to `"none"` deliberately, we respect that. No error, just no coercion.
