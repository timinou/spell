* Scope

Add two new subcommands to the emacs_code tool: =languages= (list installed/available tree-sitter grammars and their status) and =install_grammar= (install a tree-sitter grammar by language name or from a URL). These fill the introspection and management gaps — today there is no way to see what languages are available or install new ones at runtime.

** In-scope
- Elisp MCP tool registration for =code-languages= and =code-install-grammar=
- TypeScript wiring: client method, tool.ts switch case, schema params
- =languages= returns: lang name, installed (bool), grammar URL, file extensions, compilation error (if any)
- =install_grammar= accepts: lang name (uses recipe URL) OR explicit URL; compiles and loads the grammar
** Out-of-scope
- Grammar removal/uninstall
- Mode configuration
- Changes to the recipe data structure (handled by FEAT-335)

* Implementation

** Elisp: packages/emacs/elisp/pi-emacs-tools.el

*** code-languages tool
Handler: iterate =pi-treesit-recipes=, for each recipe check =(treesit-language-available-p lang)= and =(pi-prelude-grammar-unavailable-p lang)=. Return JSON array of objects:

#+begin_src json
[
  {"lang": "typescript", "installed": true, "url": "...", "extensions": ["ts"], "mode": "typescript-ts-mode"},
  {"lang": "elixir", "installed": false, "url": "...", "extensions": ["ex", "exs"], "error": "compilation failed: ..."},
]
#+end_src

Also include project-local grammars from =pi-treesit--project-lang-map=.

Schema: no required params. Optional =installed_only= boolean filter.

*** code-install-grammar tool
Handler: accepts =lang= (string, e.g. "elixir") and optional =url= / =revision= / =source_dir= overrides. When only =lang= is given, looks up recipe. Calls =treesit-install-language-grammar= into =pi-prelude--managed-dir=. Returns success/error status with compilation output.

Schema: =lang= required. =url=, =revision=, =source_dir= optional.
