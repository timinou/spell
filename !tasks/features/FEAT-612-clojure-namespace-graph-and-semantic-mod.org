* Scope
In scope: implement first-party static Clojure semantic indexing in `pi-code-graph`, including dedicated namespace/var extraction, dependency-root discovery from `deps.edn` and `project.clj`, source-root-aware namespace resolution, aliases, `:refer`, protocols, records/types, multimethods, tests, macro uncertainty markers, and keyword indexing/search. This item depends on `[[id:FEAT-611-clojure-and-edn-native-grammar-foundatio]]` because it needs the native parser/profile foundation and stable language IDs.

Out of scope: EDN graph semantics, runtime/nREPL execution, full macro expansion, JAR/classpath indexing, and editor UX hints. Runtime and external analyzer enrichment are deferred to a follow-up item. EDN is intentionally excluded from graph-capable semantics because EDN is data rather than code.

Rationale: Clojure graph correctness is mostly namespace correctness. A generic declaration extractor can find `defn`, but it cannot faithfully model `(ns ... (:require [foo.bar :as fb :refer [x]]))`, Clojure file path conventions, `.cljc` source roots, tests, or qualified keywords. First-party support should prefer truthful partial static analysis over plausible false certainty.

* Existing Patterns
- `crates/pi-code-graph/src/language.rs`: implement `LanguageExtractor` and `ImportResolver`; `ExtractedFile` returns `symbols` and `imports`; registry pairs extractor/resolver.
- `crates/pi-code-graph/src/language/typescript.rs`: example of dedicated parser-backed extractor and resolver.
- `crates/pi-code-graph/src/language/elixir.rs`: pragmatic extractor/resolver reference for macro-heavy language and module-name-to-path resolution.
- `crates/pi-code-graph/src/language/generic.rs`: generic engine-profile extraction; use as fallback/reference, but Clojure graph should be dedicated due namespace alias/refer complexity.
- `crates/pi-code-graph/src/indexer.rs`: `CodeGraphBuilder` walks project files, calls `registered.extractor.extract()`, resolves imports, and adds `GraphNode` + `EdgeKind` edges.
- `crates/pi-code-graph/src/model.rs`: extend `SymbolKind` and `EdgeKind` to preserve Clojure-specific distinctions requested for first-party support.
- Reference spec: `specs/clojure-code-tool-first-party-integration.md` captures decisions and desired user-facing semantics.

* Tests
User workflows to cover first:
1. `code index` on a deps.edn project indexes `src` and `test` Clojure files but excludes unrelated directories.
2. `code deps src/app/core.clj` shows required namespaces and files that require `app.core`.
3. `code context app.core/normalize-name` shows the defining file, callers, aliases, tests, and keyword references.
4. `(require '[clojure.string :as str])` resolves `str/trim` as an alias-qualified reference.
5. `(require '[app.db :refer [connect!]])` resolves unqualified `connect!` to `app.db/connect!`.
6. Namespace `foo.bar-baz` resolves to file path `foo/bar_baz.clj`, `.cljc`, or `.cljs` under discovered source roots.
7. `defprotocol`, `defrecord`, and `deftype` produce protocol/record/type symbols and implementation edges.
8. `defmulti` and `defmethod` produce multimethod and dispatch edges.
9. `deftest` in `test/app/core_test.clj` is linked to `app.core` where statically inferable.
10. Keywords such as `:user/id`, `::user/id`, and `::id` are indexed for search/impact but are not exposed as structural edit targets.
11. Macro declarations and known macro call sites are marked; macro-generated internals remain unresolved/uncertain rather than guessed.
12. `.cljc` reader conditionals parse without panics and produce conservative edges when platform is ambiguous.

* Edge Cases
- Reader conditionals in `.cljc` may produce platform-specific requires. Static graph should include conservative edges and mark ambiguity where renderers can show it.
- Clojure macros can define vars and generate calls. Static extractor must not invent generated symbols; it should index macro declarations and known call sites only.
- `:refer :all` cannot be fully resolved statically without loading target namespace or complete source indexing. Represent as namespace-level `Refers` or unresolved wildcard rather than linking every possible symbol.
- External dependencies in Maven/JAR classpath are out of scope. Show them as unresolved external namespace imports rather than errors.
- Namespace aliases and auto-resolved keywords may conflict. Resolution must prefer explicit alias data from current namespace.
- `deps.edn`/`project.clj` parser is intentionally shallow. If parsing fails, degrade to conventional roots `src`, `test`, `dev`, `resources` with a warning/diagnostic in tests if exposed.

* Acceptance Criteria
- `code index` includes Clojure files from discovered `deps.edn`/`project.clj` roots and excludes EDN from graph indexing.
- Graph queries distinguish Clojure namespaces, vars, protocols, records, multimethods, tests, aliases, refers, and keywords via explicit symbol/edge kinds.
- Alias-qualified and `:refer` references resolve for local source files.
- Macro-generated refs are not fabricated; uncertainty is represented or conservatively omitted.
- `bun check:rs` passes and Clojure graph fixture tests pass.
