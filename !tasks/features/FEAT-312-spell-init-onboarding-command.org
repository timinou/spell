* Initial Message

I want to set up task policies in kdl with a command when I enter a new repository. like some sort of onboarding thing. what could that look like? finish with your completed summary

The =spell init= command — the entry point when you enter a new repository. Detects the project, picks the right template, generates =spell.kdl= with smart defaults, and scaffolds =.spell/AGENTS.md=.

* User Experience

#+begin_example
$ cd ~/my-saas-app
$ spell init

  Detected: TypeScript (Next.js, Prisma)
  Test:     bun test
  Check:    tsgo
  Lint:     biome

  Created: spell.kdl
    domain "coding"
    import "spell.coding.typescript"
    + 3 project-specific policies with detected toolchain

  Created: .spell/AGENTS.md
    Project context stub — edit to add conventions

  Run `spell` to start a session with policies active.
#+end_example

For a growth project (no coding toolchain detected, or user specifies):
#+begin_example
$ spell init --domain growth

  Created: spell.kdl
    domain "growth"
    import "spell.growth.default"

  Created: .spell/AGENTS.md
#+end_example

* What Gets Generated

** spell.kdl (project root)

For a detected TypeScript/Next.js project with =bun test= and =tsgo=:

#+begin_src kdl
// Spell project configuration
// Docs: https://github.com/can1357/oh-my-pi

domain "coding"
import "spell.coding.typescript"

// Project-specific policy overrides
// The imported template provides base layers and policies.
// Layers and policies declared here override the template by name.

policy "api-quality" layer="api" {
    gate-commit true
    gate-cmd "bun test"
    verify-cmd "tsgo"
}

policy "ui-quality" layer="ui" {
    gate-commit true
    gate-cmd "bun test"
}
#+end_src

Key: the =gate-cmd= values come from project detection, not canned strings. If detection finds =bun test= in scripts.test, that's what goes in the policy.

For a Rust project:
#+begin_src kdl
domain "coding"
import "spell.coding.rust"

policy "core-quality" layer="core" {
    gate-commit true
    gate-cmd "cargo test"
    verify-cmd "cargo clippy -- -D warnings"
}
#+end_src

* CLI Interface

#+begin_src
spell init [--force] [--domain <name>]
#+end_src

| Flag       | Description                                      |
|------------+--------------------------------------------------|
| =--force=  | Overwrite existing spell.kdl and AGENTS.md       |
| =--domain= | Override detected domain (e.g. =growth=)         |

* Behavior

1. Check if =spell.kdl= exists at project root
   - If exists and no =--force=: print message, exit
2. Run project detection via =detectProject(cwd)=
3. Select template namespace based on detection:
   - TypeScript/JavaScript → =spell.coding.typescript=
   - Rust → =spell.coding.rust=
   - Python → =spell.coding.python=
   - Go → =spell.coding.go=
   - If =--domain growth= → =spell.growth.default=
   - Unknown → no import, just =domain "coding"= with empty layers
4. Generate =spell.kdl= with domain, import, and project-specific policy overrides using detected toolchain commands
5. Generate =.spell/AGENTS.md= stub with detected project info
6. Print colored summary
