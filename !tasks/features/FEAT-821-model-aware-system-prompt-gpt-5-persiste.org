* Initial Message

there's been a huge drop in quality, instruction following, honesty, rigour (and completeness), and relentlessness since switching from opus to gpt. please compare sesssions using text analysis and find out, in the way that the prompts are constructed and through developer feedback and documentation online, what to improve.

* Problem
Measured quality regression (instruction-following, honesty, rigour, completeness, relentlessness) after the default model switched from Anthropic Opus to OpenAI GPT (gpt-5.x / codex).

Evidence (full local session corpus: 15,397 transcripts; 318k Opus vs 127k GPT assistant messages; rate-normalized, percentile-robust):
- tool calls/session: Opus 80.6 vs GPT 53.5 (-34%)
- assistant steps/session: 69.4 vs 39.4 (-43%); median 34 vs 26, p90 158 vs 102 (down across whole distribution)
- share of <=10-tool sessions IDENTICAL (17.2% vs 16.9%) -> GPT is NOT bailing on easy tasks; it under-completes substantive ones
- verify-command rate /100 tools: 7.0 vs 4.7 (-33%)
- think-chars/msg: 55 vs 189 -> GPT thinks 3.4x MORE; reasoning effort is NOT the deficit
- "done/fixed" claims /10k: 5.1 vs 8.9 (more); voiced-uncertainty /10k: 6.1 vs 0.03

Root cause (verified in code + corroborated by OpenAI's own GPT-5/5.1/5.2/codex prompting guides):
- buildSystemPrompt() (packages/coding-agent/src/system-prompt.ts:437) renders ONE template for ALL providers. Grep for anthropic|opus|claude|codex|gpt|openai|provider in builder + template = no prompt-level branching. The Claude-tuned prompt ships byte-identical to GPT.
- Default reasoning already "high" (config/settings-schema.ts:462) -> not the lever.
- OpenAI GPT-5 guide: "GPT-5 follows instructions with surgical precision; contradictory/vague instructions damage it MORE than other models, as it expends reasoning reconciling them." GPT-5.1 guide names the exact regression: "can err on the side of excessively concise at the cost of answer completeness ... emphasize persistence and completeness via prompting."
- The shipped prompt has live contradictions GPT follows literally: terse-vs-complete (loud brevity examples win), one-off abstract persistence, push-back-vs-independence.
- Corroborating: GPT bash-share 13% vs Opus 38% -> GPT obeys "prefer structured tools" BETTER. So the issue is literalism, not weak instruction-following: make the LETTER say what the SPIRIT wants.

Verbatim block content (adapted from OpenAI gpt-5.1 solution_persistence + gpt-5.2 uncertainty_and_ambiguity + codex verify guidance):
<persistence>
- Autonomous senior engineer: gather context, plan, implement, verify, refine -- within this turn. Do not hand back at analysis or a partial fix.
- Never stop at uncertainty -- research/deduce the most reasonable path and continue. Only yield when the deliverable >= the full scope.
- Biased for action: an ambiguous directive => proceed with the most reasonable interpretation and state the assumption; do not bounce it back as a question. Ask only for irreversible actions or >=2 materially different readings.
</persistence>
<verification>
- Before claiming done/fixed/working, RUN the check (test - build - lint - reproduce) and cite the result. An unverified completion claim is a failure.
- Never fabricate figures, line numbers, file paths, or command output. If unverified, say so and state how to verify.
</verification>

Terse<->complete precedence clause (GPT-only):
"Brevity governs conversational prose only. It NEVER reduces work, verification, edge-case coverage, or deliverable scope. When brevity and completeness conflict, completeness wins."
