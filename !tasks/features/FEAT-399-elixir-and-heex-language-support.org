* Context — Why This Exists
Elixir is one of two Phase 1 languages (alongside TypeScript) for the pi-code-graph engine. The user specifically requested Elixir as first priority with full HEEx template parsing.

This item implements =LanguageExtractor= and =ImportResolver= for Elixir (.ex, .exs) and HEEx (.heex) files, as defined by the trait interfaces in [[id:FEAT-397-core-graph-engine-and-trait-interfaces]].

** What This Enables
After this item, running =code index= on a Phoenix/Elixir project produces a graph with:
- Every module, function (def/defp), macro (defmacro), struct, protocol, behaviour as symbol nodes
- =alias=, =import=, =use=, =require= directives resolved to target modules
- Function call edges between modules (=UserService.find_user(query)= → edge to =UserService.find_user=)
- HEEx template component references (=<.button>=, =<Components.Modal.show>=) linked to defining modules
- Phoenix LiveView associations (LiveView module ↔ HEEx template)

** Elixir Module Resolution Rules
Elixir modules are globally namespaced. Resolution is convention-based:
1. Module =MyApp.Users.User= → file =lib/my_app/users/user.ex= (CamelCase module → snake_case path under =lib/=)
2. Test modules → =test/= directory with =_test.exs= suffix
3. Project name comes from =mix.exs= → =project()= function → =:app= key
4. Dependencies live in =deps/= — treat as =ExternalPackage= nodes
5. Elixir/Erlang standard library (=Enum=, =Map=, =GenServer=, etc.) → =Builtin= nodes
6. No path aliases like tsconfig — module names ARE the canonical identifiers

** Elixir Dependency Directives
- =alias MyApp.Users.User= → creates a shorthand. Edge type: =Uses= (alias reference)
- =alias MyApp.Users.{User, Admin}= → multi-alias expansion. One edge per aliased module.
- =import Enum, only: [map: 2]= → imports functions into scope. Edge type: =Uses= (import)
- =use GenServer= → invokes =__using__/1= macro. Edge type: =Uses= (use). Opaque — treat as strong dependency.
- =require Logger= → compile-time dependency for macros. Edge type: =Uses= (require)

** HEEx Template Rules
HEEx templates are Elixir's HTML template engine, used in Phoenix LiveView:
- =<.button>= → function component from the same module (=button/1= function)
- =<.button />= → same, self-closing
- =<Components.Modal.show>= → cross-module function component reference
- ={@assign_name}= → references a LiveView assign (useful for data flow tracking)
- ={Module.function(args)}= → Elixir expression, creates a =Calls= edge
- HEEx files are typically co-located: =lib/my_app_web/live/user_live.html.heex= is owned by =UserLive= module

** Key Design Decisions
1. Elixir grammar: =tree-sitter-elixir = "0.3"= (already in pi-natives dependencies)
2. HEEx grammar: =tree-sitter-heex = "0.8"= (https://github.com/phoenixframework/tree-sitter-heex, MIT, 26k downloads). This is the official Phoenix grammar with proper AST node types for components, expressions, slots, and directives. Do NOT use =tree-sitter-html= — HEEx has its own grammar.
3. Module-to-file mapping: parse =mix.exs= for project name, then CamelCase → snake_case conversion
4. Standard library detection: maintain a static list of known Elixir/Erlang stdlib modules (=Enum=, =Map=, =String=, =GenServer=, =Supervisor=, =Agent=, =Task=, etc.)
5. Phoenix conventions: detect =use Phoenix.LiveView=, =use Phoenix.Component= to classify modules
** Reference: Elixir tree-sitter Node Types
Key tree-sitter-elixir node types for extraction:
- =call= with target =defmodule= → module definition
- =call= with target =def=, =defp= → function definition (pub/private)
- =call= with target =defmacro=, =defmacrop= → macro definition
- =call= with target =defstruct= → struct definition
- =call= with target =defprotocol= → protocol
- =call= with target =defimpl= → protocol implementation
- =call= with target =alias=, =import=, =use=, =require= → dependency directives
- =call= with target =@behaviour= → behaviour declaration
- =call= with dot notation =Module.function()= → cross-module call

** 9. HEEx extraction implementation
Parse HEEx files using =tree-sitter-heex= (NOT =tree-sitter-html=). The HEEx grammar provides proper AST node types:

*** tree-sitter-heex Node Types Reference
- =fragment= — root node
- =component= → contains =start_component= / =self_closing_component= / =end_component=
  - =component_name= → children: =module= (optional) + =function=
    - =<.button>= → =component_name= has only =function= child (text: "button")
    - =<MyApp.Modal.show>= → =component_name= has =module= (text: "MyApp.Modal") + =function= (text: "show")
- =expression= → contains =expression_value= (the Elixir code between ={= and =}=)
  - ={@users}= → =expression_value= text: "@users"
  - ={Module.func()}= → =expression_value= text: "Module.func()"
- =slot= → =<:col>...</:col>= named slots
- =directive= → ={#if}=, ={/if}=, ={#for}= control flow
- =tag= → regular HTML tags (=<div>=, =<p>=, etc.)

*** Extraction Logic
- Walk all =component= nodes in the tree:
  - Get =component_name= → check for =module= + =function= children
  - If =function= only (no =module=) → local component ref (e.g., "header", "button", "table")
  - If =module= + =function= → cross-module ref (e.g., "MyAppWeb.Components.Modal.show")
  - Create =Relationship { from_symbol: "<heex-file>", to_symbol: component_name, kind: Calls }=
- Walk all =expression= nodes:
  - Extract =expression_value= text
  - If starts with =@= → assign reference (e.g., "@users", "@user")
  - If matches =ModuleName.function(= pattern → cross-module call
  - Store as relationships on the HEEx file node

*** HEEx ↔ LiveView Association
- HEEx file =user_live.html.heex= → find companion =user_live.ex= in same directory
- Create a =Contains= edge from the LiveView module's file node to the HEEx file node
- Local component refs (=<.button>=) resolve to functions in the LiveView's module or its imported component module

** 11. Mix resolver implementation
=MixResolver= struct:
- =init(project_root)=: parse =mix.exs= to extract app name, detect umbrella vs flat project, build module prefix → lib path mapping
- =resolve(specifier, from_file)=:
  1. Check stdlib list → =Builtin=
  2. Check if module prefix matches project app → compute snake_case path under =lib/=
  3. Check known Phoenix/Ecto deps → =ExternalPackage=
  4. Otherwise → =Unresolved=

CamelCase → snake_case conversion:
- =MyApp= → =my_app=
- =UserLive= → =user_live=
- =HTMLParser= → =html_parser= (consecutive caps: split before last cap of a run)
- Algorithm: insert =_= before each uppercase letter that follows a lowercase, then lowercase all

* Error Handling
- =mix.exs= not found → fall back to inferring project structure from directory layout
- Malformed Elixir files → tree-sitter produces partial tree, extract what's possible
- HEEx files without owning LiveView module → still extract component refs, mark as orphaned
- Multi-line alias blocks → handle =alias MyApp.{Sub1, Sub2}= correctly
- Elixir metaprogramming (=unquote=, =quote=) → can't resolve statically, skip
- Umbrella projects → detect =apps/= directory structure, resolve per-app
