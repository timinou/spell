* Narrative

In the current system, the only mechanism for inter-agent data flow is the =resolvePredecessorResultsContext= function (=task/template.ts=): when a task has blockers via =todoRef=, the completed blocker's =delegation.result.output= is injected into the dependent task's assignment at launch time. This is *post-hoc*: the dependent task cannot start processing until the predecessor finishes entirely.

For interconnected swarms, agents need *live* communication:
- Agent A writes an artifact (e.g., a type definition file). Agent B, running concurrently, needs to know the artifact exists so it can read and use it -- without waiting for A to fully complete.
- Agent C discovers a constraint that affects Agent D's approach. C publishes a "finding" to the blackboard. D (already running) should receive a notification and adapt.
- The scheduler needs to know when artifacts are available so it can unblock artifact-dependent tasks (not just task-completion-dependent).

The EventBus (=utils/event-bus.ts=) already provides prioritized async event dispatch. Subagent progress events already flow through it (=TASK_SUBAGENT_EVENT_CHANNEL=). This item extends the EventBus with swarm-specific channels and introduces an artifact notification system that bridges file-system events and the blackboard.

* Design Decisions

1. New EventBus channels:
   - =swarm:artifact= -- fired when an agent writes an artifact (file or blackboard entry). Payload: ={ agentId, artifactPath?, entryId?, type, metadata }=
   - =swarm:finding= -- fired when an agent publishes a finding to the blackboard. Payload: ={ agentId, entryId, title, summary }=
   - =swarm:handoff= -- fired when an agent initiates a handoff. Payload: ={ fromAgent, toAgent?, context, reason }=
   - =swarm:progress= -- fired when an agent reports structured progress. Payload: ={ agentId, progress: number, total: number, label: string }=
2. Artifact notifications are triggered by =SwarmBlackboard.write()= when =type === "artifact"=. The blackboard write method enqueues an event on =swarm:artifact= after the org item is created.
3. For file-based artifacts (outside the blackboard), a =SwarmArtifactWatcher= watches the swarm artifacts directory (=artifacts/<run-id>/=) and fires =swarm:artifact= events when files appear or change.
4. The scheduler subscribes to =swarm:artifact= to check if any pending tasks have artifact-based readiness triggers (new field on =SwarmNode=: =artifactDeps?: string[]=).
5. Typed objects on the event bus: events carry structured JSON payloads (not just strings). The existing =EventBus= already supports =unknown= payloads; we add TypeScript interfaces for each channel's payload shape.
6. Agents receive notifications by subscribing to channels. In practice, the scheduler is the primary subscriber; agents receive notifications indirectly via injected context or blackboard queries.

export const SWARM_ARTIFACT_CHANNEL = "swarm:artifact";
export const SWARM_FINDING_CHANNEL = "swarm:finding";
export const SWARM_HANDOFF_CHANNEL = "swarm:handoff";
export const SWARM_PROGRESS_CHANNEL = "swarm:progress";

export interface SwarmArtifactEvent {
  agentId: string;
  artifactPath?: string;
  entryId?: string;
  type: "file" | "blackboard";
  metadata?: Record<string, unknown>;
}

export interface SwarmFindingEvent {
  agentId: string;
  entryId: string;
  title: string;
  summary: string;
}

export interface SwarmHandoffEvent {
  fromAgent: string;
  toAgent?: string;
  context: string;
  reason: string;
}

export interface SwarmProgressEvent {
  agentId: string;
  progress: number;
  total: number;
  label: string;
}
#+end_src
