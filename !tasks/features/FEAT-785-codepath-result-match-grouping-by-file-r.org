* Initial Message

How would you improve the Get, Find, and Create tools'
1. TUI? I want to see the CodePath and other useful information
2. Output to the LLM? right now it seems like file paths are getting rewritten at every line hit

* Problem
`codepath-result.ts#renderMatchLine` emits the full file path on *every* grep
hit (`path:line:  content`). N matches in one file → N path repetitions. On wide
results the repeated 40–60 char repo path dominates token cost and hurts
readability for the model.

`buildNodeList` already sorts match-shape §line nodes by `(path, line)` and
batches them contiguously — the grouping structure exists but isn't exploited.

* Goal
Adopt ripgrep `--heading` shape: emit each file path once as a heading, then
indented line-numbered hits beneath it.

#+begin_src
src/a.ts
  2:  todo two
  7:  todo seven

src/b.ts
  3:  todo
#+end_src

* Contract decisions
- *Pure grouping* (not hybrid): single-hit files also get a heading. One shape =
  one parse rule for the model. Cost is +1 line per single-hit file; trivial vs
  the path-noise win and worth the consistency.
- Row form: `  <line>:  <content>` (2-space indent + line + `:` + 2 spaces +
  verbatim content). Body whitespace preserved as today.
- Line number stays machine-parsable (`^\s*(\d+):`) so the model can recompose
  `path::§line[N]` for edit. Path lives in the heading.
- Blocks separated by blank line; heading is a bare path line (`^\S`).
- Non-match §line nodes (ordinal `§line[N]`, slice `shape:"slice"`) keep their
  existing LINE#ID / single-body rendering — only `shape:"match"` nodes regroup.

* Scope
- `packages/coding-agent/src/tools/codepath-result.ts`: rewrite the match flush
  in `buildNodeList` (`flushMatches`) to group sorted matchBuf by path; replace
  `renderMatchLine` per-row path with heading + indented rows.
