** Existing Architecture To Integrate With
- =packages/coding-agent/src/tools/code.ts= — the =CodeTool= class, wraps =CodeToolDefinition= from =@oh-my-pi/pi-emacs=
- =packages/emacs/src/tool.ts= — =createCodeTool()= factory, routes commands to Emacs via JSON-RPC
- =packages/natives/= — the NPM package wrapping pi-natives Rust NAPI bindings
- =packages/coding-agent/src/prompts/tools/code.md= — the tool description (prompt engineering)

Currently: =CodeTool.execute()= → =this.#inner.execute(args)= → Emacs daemon via JSON-RPC.
After: =CodeTool.execute()= routes file-scoped commands to Emacs, codebase-scoped commands to NAPI graph bridge.

** Key Design Decisions
1. Add pi-code-graph as dependency of pi-natives (Rust side). NAPI functions exposed from =crates/pi-natives/src/code_graph.rs=.
2. The =packages/natives= package re-exports graph functions alongside existing ast/grep functions.
3. =CodeTool= gains a =GraphBackend= that holds the =GraphStore= (via NAPI). Initialized lazily on first graph command.
4. File-scoped commands (read, outline, edit, navigate, etc.) → Emacs (unchanged).
5. Graph commands (index, context, impact, deps, flow, dead_code, clusters, search, status) → NAPI.
6. Graph results formatted as structured text for agent consumption. Agent-optimized: compact, depth-grouped, with "Next:" hints.
7. TUI rendering: graph results use =renderCodeCell= with language "text" for now. Future: custom renderer.

** 6. Prompt doc update
File: =packages/coding-agent/src/prompts/tools/code.md=

Add to the =<operations>= section:
#+begin_example
- `context`: 360° view of a symbol — callers, callees, type refs, heritage, importing files
  - `symbol` (required): Symbol name to inspect
  - Use to understand how a symbol is connected before making changes
- `impact`: Transitive blast radius of changing a symbol, grouped by depth
  - `symbol` (required): Symbol to analyze
  - `depth` (optional, default 3): Max traversal depth (1-10)
  - Use before modifying any function, type, or class to understand what breaks
- `deps`: Import dependency graph for a file
  - `file` (required): File path to analyze
  - Shows what the file imports and what imports it
- `flow`: Execution flow trace from an entry point
  - `symbol` (required): Entry point symbol name
  - Traces downstream through call chain to leaf functions
- `dead_code`: Find unreachable symbols across the codebase
  - No arguments — scans entire indexed graph
- `clusters`: Discover architectural communities in the codebase
  - No arguments — analyzes file-level import graph
- `search`: Search symbols by name across the codebase
  - `query` (required): Search term (supports fuzzy matching)
- `index`: Build or rebuild the code graph index
  - Run explicitly when codebase has changed significantly
  - Auto-runs on first graph query if stale
- `status`: Check code graph index freshness and stats
#+end_example

Add to =<instruction>= section:
#+begin_example
- Before modifying a symbol → `code { command: "impact", symbol: "name" }` to see blast radius
- Understanding connections → `code { command: "context", symbol: "name" }` for 360° view
- Exploring architecture → `code { command: "clusters" }` then `code { command: "deps", file: "..." }`
#+end_example
