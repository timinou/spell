* Intention & Purpose

When `get` returns "Did you mean: lib/agentmaker/admin/workbench" for a target like `apps/agentmaker/lib/agentmaker/admin/workbench`, the agent doesn't understand that the session CWD is `apps/agentmaker` — so it repeats the same wrong path prefix across multiple calls. Add CWD context to the diagnostic so the agent can correct its paths.

Evidence: session `14d54f5d0e274ba8` lines 7-11 — agent made 4 consecutive `get` calls with `apps/agentmaker/...` prefix, each returning `[§not-found]` with suggestions that dropped the prefix. Agent never realized it should use paths relative to CWD.

* Context & Narrative

The suffix fallback in `FsResolver` strips the `apps/agentmaker/` prefix when generating "Did you mean" suggestions because it resolves paths relative to the workspace root. The suggestions are correct relative paths — but the agent doesn't know the workspace root or session CWD.

Fix: include the session CWD in the suggestion text, e.g.:
```
Did you mean: lib/agentmaker/admin/workbench, lib/agentmaker_web/components/workbench
Note: session CWD is apps/agentmaker — try paths relative to CWD
```

Or, shorter: annotate each suggestion with the CWD note.

* Scope

In scope:
- Thread session CWD from NAPI layer into `ZeroMatches` suggestion text
- Add CWD note to "Did you mean" output in `formatForTool`
- CWD sourced from `FetchOpts` which already carries `cwd: Option<PathBuf>`

Out of scope:
- Auto-resolving paths relative to CWD (behavior change, not just diagnostic)
- Changing the suffix fallback algorithm
- Showing workspace root (less useful than CWD)

* Existing Patterns

`FetchOpts` in `napi.rs` already carries `cwd`:
```rust
pub struct FetchOpts {
    pub cwd: Option<PathBuf>,
    pub kind: Option<String>,
    // ...
}
```

`FsResolver::resolve()` receives `fetch_opts: &FetchOpts` — can extract `cwd` from it.

Current suffix_fallback signature in `fs/suffix_fallback.rs`:
```rust
pub fn suffix_fallback(
    locator: &FsLocator,
    workspace_root: &Path,
    fetch_opts: &FetchOpts,
) -> Option<String>
```
