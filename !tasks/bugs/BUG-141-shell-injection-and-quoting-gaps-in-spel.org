## Audit Findings

### 1. Duplicated `buildQuotedPath` and `executeRsync` helpers
- **What**: Identical implementations of `buildQuotedPath()` and `executeRsync()` exist in both `push.ts` and `pull.ts`
- **Where**: `packages/spell-deploy/src/sync/push.ts:5-19` and `packages/spell-deploy/src/sync/pull.ts:5-19`
- **Why**: Violates DRY-at-2 rule from AGENTS.md. When one copy gets fixed (e.g., a bug in quoting or error reporting), the other stays broken. Extract to a shared `sync/utils.ts`.
- **Effort**: `trivial`

### 2. Barrel uses `export type { ... } from` instead of `export *`
- **What**: `src/index.ts` uses `export type { DeployContext } from "./cli/types"` and named re-exports from `./sync/types`, violating AGENTS.md star re-export rule
- **Where**: `packages/spell-deploy/src/index.ts:6,22-30`
- **Why**: The named re-export exists to avoid a `CommandResult` name collision between `cli/types.ts` and `sync/types.ts`. The fix is to remove the dead `CommandResult` from `cli/types.ts` (it's unused), then use `export *` for both modules.
- **Effort**: `trivial`

### 3. Dead `CommandResult` interface in `cli/types.ts`
- **What**: `CommandResult` is defined in `cli/types.ts` but never imported or used anywhere
- **Where**: `packages/spell-deploy/src/cli/types.ts:10-13`
- **Why**: Dead code that caused the barrel to use named re-exports to avoid collision. Delete it.
- **Effort**: `trivial`

### 4. `execSsh` is `async` but uses `Bun.spawnSync`
- **What**: Function is declared `async` and returns `Promise<CommandResult>` but only uses synchronous `Bun.spawnSync`. The `async` keyword is misleading.
- **Where**: `packages/spell-deploy/src/sync/ssh.ts:40`
- **Why**: Contract confusion — callers `await` a function that never yields. Either drop `async`/`Promise` (if intentional sync) or switch to `Bun.spawn` with `await proc.exited` (if truly async is desired). Currently both `push.ts` and `pull.ts` call `executeRsync` (which is sync) but then `await execSsh` for swap commands — the mixture is inconsistent.
- **Effort**: `small`

### 5. Shell injection in `initCommand` — unquoted `projectRoot`
- **What**: `initCommand` interpolates `target.projectRoot` directly into a remote shell command without quoting: `mkdir -p ${target.projectRoot} ...`
- **Where**: `packages/spell-deploy/src/cli/commands.ts:138`
- **Why**: If `projectRoot` contains spaces or shell metacharacters, the command breaks or executes unintended code. The push/pull modules use `buildQuotedPath` for this exact reason, but the init command skips it.
- **Effort**: `small`

### 6. Shell injection in `buildSecretPushCommand` — unquoted `remotePath`
- **What**: `remotePath` and `remoteTmp` are interpolated into a remote shell command without quoting: `cat > ${remoteTmp} && chmod 600 ${remoteTmp} && mv ...`
- **Where**: `packages/spell-deploy/src/secrets/push.ts:10-11`
- **Why**: Same quoting issue as finding 5. Paths with spaces would break the remote command.
- **Effort**: `small`

### 7. Unsanitized `unitName` in `lifecycle.ts` remote commands
- **What**: `buildServiceCommand` and `buildInstallUnitCommand` interpolate `unitName` into shell strings without sanitization, while `systemd.ts` has a `sanitizeUnitName` function that only runs in the unit generator
- **Where**: `packages/spell-deploy/src/service/lifecycle.ts:7,27`
- **Why**: A unit name from config containing shell metacharacters would be injected into `sudo systemctl ${action} ${unitName}` and `sudo tee ${remotePath}`. Since values come from user-controlled `sync.kdl`, this is a defense-in-depth gap. Apply `sanitizeUnitName` at the boundary or when building the command.
- **Effort**: `small`

### 8. `BundleUploadOptions` type is exported but never used
- **What**: `BundleUploadOptions` interface exists in `bundle/types.ts` but no function signature references it
- **Where**: `packages/spell-deploy/src/bundle/types.ts:20-24`
- **Why**: Dead type. `buildUploadCommands` uses an inline opts type instead. Either use the exported type or delete it.
- **Effort**: `trivial`

### 9. SSH key path with spaces breaks rsync `-e` transport
- **What**: `buildRsyncSshTransport` interpolates `sshOptions.sshKey` into a single string passed as rsync's `-e` flag. If the key path contains spaces, the resulting ssh command becomes malformed because rsync parses the `-e` value with shell word splitting.
- **Where**: `packages/spell-deploy/src/sync/rsync.ts:4`
- **Why**: Paths like `~/.ssh/my key` would produce `-e "ssh -p 22 -i /home/user/.ssh/my key ..."` where `key` becomes a separate argument. Should quote the key path.
- **Effort**: `small`

### 10. `shouldExclude` is too broad — matches prefix rather than path segments
- **What**: `shouldExclude("node_modules_backup/foo", ["node_modules/"])` returns `true` because the check `filePath.startsWith(normalized)` matches `node_modules` as a prefix of `node_modules_backup`. The `||` branch `filePath.startsWith(normalized)` subsumes and weakens the segment-aware `filePath.startsWith(normalized + "/")` branch.
- **Where**: `packages/spell-deploy/src/sync/watcher.ts:17`
- **Why**: False-positive exclusions — files in directories whose names begin with an excluded prefix are silently skipped from sync.
- **Effort**: `small`
