* Problem
The =zai= provider is intended to represent the Z.AI GLM Coding Plan, but current provider wiring uses the Anthropic-compatible Coding Plan descriptor/path instead of the OpenCode-style OpenAI-compatible Coding Plan endpoint.

Observed failures include repeated retryable =overloaded_error= 500 surfaces from Z.AI with nested =java.lang.StackOverflowError=, likely amplified by protocol/endpoint mismatch through Z.AI's Anthropic compatibility layer.

* Source of truth
- User confirmed: =zai= is intended as the Coding Plan provider.
- OpenCode / models.dev use =@ai-sdk/openai-compatible= with endpoint =https://api.z.ai/api/coding/paas/v4=.
- Z.AI docs warn Coding Plan should use the dedicated Coding API endpoint, not the general API.
- GLM 5.2 has 1M context and should become the default Coding Plan model.

* Desired behavior
- =zai= uses OpenAI Chat Completions protocol via =https://api.z.ai/api/coding/paas/v4=.
- Default =zai= model is =glm-5.2= with 1,000,000 context.
- Existing Z.AI thinking support remains =thinking: { type: enabled|disabled }=.
- Prefer =ZHIPU_API_KEY= while retaining =ZAI_API_KEY= compatibility.
- Spoof OpenCode only if low-risk/token-light; otherwise avoid unnecessary headers.
