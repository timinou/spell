Why are org files like this getting the initial message as the initial prompt? which pathway led to them being created that way? do org files created in subtasks lead to this issue? how would you fix it? explain and show the tradeoffs

* Problem
When =org create= is called from a subtask (taskDepth > 0), ~buildSessionContext()~ in
=packages/coding-agent/src/tools/org.ts= reads ~session.getFirstUserMessage()~ which returns
the subtask's assignment/context blob — not the user's original message. This gets written
as =* Initial Message= in the org file, polluting every subtask-created item with kilobytes
of orchestration context.

* Root Cause
~buildSessionContext()~ (org.ts line 196-202) does not check ~session.taskDepth~. In subtask
sessions, the first user message IS the parent's assignment.

* Fix
In ~buildSessionContext()~, gate ~initialMessage~ on ~taskDepth === 0~:

#+begin_src typescript
function buildSessionContext(session: ToolSession): OrgSessionContext {
    return {
        sessionId: session.getSessionId?.() ?? undefined,
        transcriptPath: session.getSessionFile() ?? undefined,
        initialMessage: (session.taskDepth ?? 0) > 0
            ? undefined
            : (session.getFirstUserMessage?.() ?? undefined),
    };
}
#+end_src
