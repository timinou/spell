**6. `formatWaveManifest` padding arithmetic is off by 2**
- **Where**: `packages/org/src/tool.ts` line 634
- **What**: `50 - 10 - String(wave.number).length` uses `10` as the prefix length, but `** wave-` is 8 characters, so the `:wave:` tag starts 2 columns earlier than intended.
- **Why**: Cosmetic only. The org heading is still valid and the tag is parsed correctly by `extractPlanWaves`.
- **Effort**: `trivial`

* Scope
** In-scope
- =packages/org/src/tool.ts= — =formatWaveManifest= function, line 634

** Out-of-scope
- Wave computation logic
- extractPlanWaves parser (handles any whitespace)

* Problem
Line 634:
#+begin_src typescript
lines.push(`** wave-${wave.number}${" ".repeat(Math.max(1, 50 - 10 - String(wave.number).length))}${tag}`);
#+end_src

The =10= is meant to be the length of =** wave-= but that string is 8 characters. The =:wave:= tag starts 2 columns earlier than the intended column 50.

* Fix
Change =10= to =8=:
#+begin_src typescript
const prefix = `** wave-${wave.number}`;
lines.push(`${prefix}${" ".repeat(Math.max(1, 50 - prefix.length))}${tag}`);
#+end_src

This computes the actual prefix length instead of hardcoding, preventing future drift if the format changes.

* Tests
No automated test — cosmetic formatting. Verify manually that generated manifest headings align =:wave:= tag at column 50.

* Acceptance Criteria
- =:wave:= tag is right-aligned at column 50 in generated manifest output
