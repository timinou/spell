* BUG: warm-load embed runs as one giant batch → progress marker stuck at 0 for the whole embed, no cancellation

** Symptom
TUI warm-progress marker shows =phase:embed done:0 total:11805= for the entire (multi-minute) embed wall-time, then jumps to done. Reads as "hung at 0 forever."

** Root cause
=lane_org.rs::build_vec_index_with= calls =embedder.embed_batch(&refs)= over ALL items in a single call, THEN loops =progress.bump_done()= afterward. So =done= is 0 for ~100% of the embed, and the snapshot the =stats= RPC returns to the TUI never advances mid-embed. Progress is decorative, not real. The single =embed= call is also uninterruptible — no chunk boundary to check a shutdown flag.

** Fix
Chunk the embed into batches (~256 items): for each chunk call =embed_batch=, upsert, then =progress.done.fetch_add(chunk_len)=. Between chunks, check the daemon SHUTDOWN flag and bail cleanly (persisting partial progress once BUG (cache) lands). Keep =total= = items.len(); =done= now climbs smoothly.

** Acceptance
- During a cold embed of the live corpus, =stats= snapshots show =done= strictly increasing across multiple polls (not 0 → total).
- Chunk size tunable via =KNOWLEDGE_EMBED_CHUNK= (default 256).
- A SIGTERM mid-embed exits within the drain grace without finishing the whole corpus.

NOTE [2026-06-14]: Fixed in commit 69cbeade8. build_vec_index_with now embeds in chunks of KNOWLEDGE_EMBED_CHUNK (default 256), bumping progress.done per chunk so the marker climbs in real time; engine lock released between chunks (also helps BUG-478 interleave). Embedder failure mid-build stops cleanly and skips cache persist.
