* Scope

In scope:
- Delegated task execution in `packages/coding-agent/src/task/executor.ts`, specifically the path that currently accepts `submit_result` success without proving required gates from observed runtime evidence.
- Runtime ownership of a single retry when proof is missing. The delegated subagent, not the parent finalizer, must be the component that gets one forced opportunity to repair missing proof before success is accepted.
- Reuse of canonical verification logic from `packages/coding-agent/src/task/gate-verification.ts` rather than inventing a parallel proof matcher.
- Honest failure semantics when proof is still missing after the single retry. The task must not be surfaced as completed.
- Preservation of existing behavior for ungated delegated tasks and for explicit aborted/error `submit_result` payloads.

Out of scope:
- Code-tool target ambiguity, structural-edit ergonomics, or any change to the `code` tool.
- Direct `todo_write` completion behavior for non-delegated work.
- Adding a parent-side second retry. The parent may consume runtime results, but it must not own the retry loop for this item.
- Redefining what `gateArtifact` or `verifyCmd` means.

Rationale: the observed failure was not just missing UI polish; it was a truthfulness bug. A subagent claimed verified completion without observed proof. The fix belongs in the delegated execution contract itself.

* Edge Cases

- Gate command evidence may appear through normalized wrappers (`cd`, `env`, `bash -lc`). Matching must continue to use canonical normalization, not raw string equality.
- A delegated task may call `submit_result` success, then later run the gate. Runtime must only accept the terminal success after evidence exists; ordering matters.
- A delegated task may emit multiple `submit_result` attempts. The runtime must treat the last accepted success attempt as authoritative, not the first malformed one.
- Missing proof after the single retry must produce an honest failure path, not a misleading completed state with a warning.
- Explicit `submit_result` aborted/error payloads must still terminate immediately without proof retry.
