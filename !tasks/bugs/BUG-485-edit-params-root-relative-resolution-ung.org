* Initial Message

Found during the path-surface audit for the cross-project leak (BUG-481). edit.ts computed effectiveCwd with raw nodePath.resolve(sessionCwd, params.root) for a relative root. effectiveCwd is the BASE every per-op target then resolves against, so a duplicated/wrong relative root bakes the nesting in BEFORE the per-op resolveCwdRelativePath guard runs — the per-op guard (relative to the already-doubled base) can never see it.

* Repro

#+begin_src
cwd = /proj/apps/foo
edit { root: "apps/foo", operations: [{ target: "lib/x.ts", ... }] }
OLD: effectiveCwd = path.resolve(cwd, "apps/foo") = /proj/apps/foo/apps/foo
   → target lib/x.ts resolves under the doubled dir
   → real file /proj/apps/foo/lib/x.ts untouched; edit lands in/forms wrong tree
#+end_src

This was the last raw path.resolve on a WRITE anchor (all per-op targets + create/send-file/browser already route through resolveCwdRelativePath; reads via get/find/image-input/mode-guard are not leak vectors since a wrong path is ENOENT, not a created file).

* Fix (commit pending)

Route a relative params.root through resolveCwdRelativePath(sessionCwd, root, { mode:"dir", projectRoot: getRepoRoot() }) before it becomes effectiveCwd. The project-root walk-up resolves a duplicated root back to the real directory; a degenerate root (root == cwd-tail) falls back to sessionCwd; any coalesce/sibling warning is surfaced via a new #appendWarning on both the single-op and aggregate result paths. Absolute root unchanged.
