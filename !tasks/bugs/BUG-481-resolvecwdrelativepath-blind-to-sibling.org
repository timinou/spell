Root cause is the BUG-029/358/360/361 family: unanchored relative paths resolve against session.cwd, not the agent's mental git-root anchor.

* Root cause (structural)

The write-path guard =resolveCwdRelativePath= (packages/coding-agent/src/tools/path-resolution.ts) only detects ONE shape — the cwd-TAIL DUPLICATION pattern (cwd=/x/apps/foo + input=apps/foo/bar → double-prefix). It is BLIND to the *sibling / new-top-level* shape that hit verse:

#+begin_src
cwd  = /code/ora/verse            (== git root)
write  rv/data/todos.json          (a DIFFERENT project's file)
→ detectCwdPrefixDuplication returns null (first seg `rv` ≠ cwd tail)
→ resolveFromProjectRoot walks up, finds nothing (brand-new path)
→ falls through to decision:"no-overlap", path.resolve(cwd, p)
→ silently creates /code/ora/verse/rv/data/todos.json
→ success message echoes the INPUT string; agent gets NO feedback signal
#+end_src

The existing design philosophy (BUG-360/361) is "don't block, but always emit a feedback signal so the agent self-corrects." That signal exists for the cwd-tail case and is MISSING for the new-top-level/sibling case. Closing that signal gap is the structural completion of the existing guard.

* Secondary bug: type drift

=CwdResolutionDecision= union = "no-overlap" | "kept-nested" | "coalesced" | "degenerate" but =resolveCwdRelativePath= already returns decision:"project-root" (L161). The union is missing it → TS narrowing is unsound on that arm.

* Fix

1. Add "project-root" and "unanchored-new" to the =CwdResolutionDecision= union (type-truth).
2. In the =!dup= branch, AFTER =resolveFromProjectRoot= returns null, detect the leak shape: a brand-new write (target + parent dir absent) whose FIRST path segment does not exist under cwd ⇒ return decision:"unanchored-new" with a warning naming the new top-level dir, the absolute resolved path, and the absolute/dot-anchored alternatives. SOFT warning (writes still proceed) — matches the no-block design. Uses only the injected =exists= predicate (no git spawn in the hot per-op path).
3. All write tools (create, edit, send-file, browser screenshot, transaction) already surface =resolved.warning=, so they inherit the new signal with zero per-tool churn.
