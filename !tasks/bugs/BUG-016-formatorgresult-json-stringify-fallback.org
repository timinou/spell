* Problem
In =packages/coding-agent/src/tools/org.ts=, the =formatOrgResult= function has a fallback
path (line 337):

#+begin_src typescript
return JSON.stringify(result, null, 2);
#+end_src

This serializes create/update/set/note results as JSON. The JSON output contains =\n= escapes
for any newlines in string values, which the LLM may echo back in subsequent tool calls.

While not the primary cause of the =\n= bug (that's the prompt example), this reinforces the
pattern: the LLM sees =\n= in tool results and uses the same pattern in its responses.

** Steps
Add a new branch before the =JSON.stringify= fallback that handles mutation results:

#+begin_src typescript
// Mutation results (create, update, set, note)
if (typeof result === "object" && result !== null && "success" in result) {
  const r = result as Record<string, unknown>;
  const parts: string[] = [];
  if (r.id) parts.push(`id: ${r.id}`);
  if (r.success) parts.push("success: true");
  if (Array.isArray(r.updated)) parts.push(`updated: ${r.updated.join(", ")}`);
  if (typeof r.file === "string") parts.push(`file: ${r.file}`);
  if (typeof r.section === "string") parts.push(`section: ${r.section}`);
  if (typeof r.note === "string") parts.push(`note: ${r.note}`);
  return parts.join("\n");
}

// Error results
if (typeof result === "object" && result !== null && "error" in result) {
  const r = result as Record<string, unknown>;
  return `error: ${r.message ?? "unknown"}${r.code ? ` (${r.code})` : ""}`;
}
#+end_src

Keep the =JSON.stringify= fallback only for truly unknown shapes.
