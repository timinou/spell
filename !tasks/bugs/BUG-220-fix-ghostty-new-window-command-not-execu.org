* Problem

~spell recover~ spawns Ghostty windows via IPC (~ghostty +new-window~), but the ~-e spell -r <sessionId>~ command is not executed inside the new window. The window opens with the user's default shell prompt instead of the recovered spell session. This affects Ghostty 1.3.0 and is likely caused by multi-argument forwarding bugs in the ~+new-window~ IPC path.

The current command format:
#+begin_example
ghostty +new-window --working-directory=<cwd> -e spell -r <sessionId>
#+end_example

Uses ~-e~ with multiple subsequent arguments (~spell~, ~-r~, ~<sessionId>~) as separate argv entries. Ghostty's IPC protocol must serialize these and deserialize them in the receiving instance. The multi-arg parsing is buggy in 1.3.0.

* Design Decisions

1. Switch from ~-e <args...>~ (multi-arg) to ~--command=<full command>~ (single key-value pair). Ghostty docs confirm ~--command~ is supported for ~+new-window~. A single k=v pair is more robust for IPC serialization.
2. Add ~--title=<project: session>~ to windows for identification.
3. Add ~--direct~ flag to bypass ~+new-window~ IPC entirely and launch standalone ~ghostty~ processes. This is a guaranteed workaround for any IPC bugs. When ~--direct~ is set, spawn ~ghostty --working-directory=<cwd> -e spell -r <id>~ (no IPC, new process per window).
4. Always print manual fallback commands after recovery so users have a backup.

** Add direct mode variant

Add a ~formatDirectSpawnCommand~ and ~spawnRecoveredSessionDirect~ that bypass IPC:

#+begin_src typescript
function formatDirectSpawnCommand(session: RecoverableStatusSession): string {
    return `ghostty --working-directory=${shellQuote(session.cwd)} --title=${shellQuote(formatSessionLabel(session))} -e spell -r ${shellQuote(session.sessionId)}`;
}

async function spawnRecoveredSessionDirect(session: RecoverableStatusSession): Promise<boolean> {
    try {
        Bun.spawn(
            ["ghostty", `--working-directory=${session.cwd}`, `--title=${formatSessionLabel(session)}`, "-e", "spell", "-r", session.sessionId],
            { stdin: "ignore", stdout: "ignore", stderr: "ignore" },
        );
        // Direct launch stays alive as a child process — detach by not awaiting
        return true;
    } catch {
        return false;
    }
}
#+end_src

Note: direct mode uses ~-e~ with standalone ghostty (no IPC), which works reliably. ~Bun.spawn~ without awaiting ~proc.exited~ lets the process run independently.
