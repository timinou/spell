* Scope
In scope: tighten `resolveDefaultConfigDir` in `packages/coding-agent/src/commands/server.ts` so the `~/.spell` fallback only commits when it actually contains a spell-server config, and produce a useful error otherwise. Update the unit test that mocks the fallback path so it still describes the intended behavior.

Out of scope: removing the `~/.spell` global-config UX (intentional, has integration test coverage), changing `packages/spell-server/src/main.ts` cwd-only default, or refactoring `loadConfig`'s error messages in `packages/spell-server/src/config/loader.ts`.

* Reproduction
1. Run `spell server` from a directory that has no `./.spell/` (e.g., a fresh project).
2. Have `~/.spell/` already populated by the coding-agent (`~/.spell/spell.kdl` etc.), but NO `~/.spell/server.kdl`.
3. Observe: error `Missing required config file: /home/<user>/.spell/server.kdl`. The user has no obvious way to know the resolver silently chose `~/.spell/` — they typically expect the failure to reference `./.spell/`.

* Root Cause
`resolveDefaultConfigDir` (`packages/coding-agent/src/commands/server.ts:60`) commits to `~/.spell` whenever `./.spell/` is not a directory. The fallback dir is shared with `coding-agent` (which stores `~/.spell/spell.kdl`, an unrelated config), so the existence probe succeeds on a dir that will never satisfy spell-server's `readRequiredConfigFile(..., "server.kdl")` (`packages/spell-server/src/config/loader.ts:148`).

The two config namespaces — coding-agent (`spell.kdl`) and spell-server (`server.kdl`, `channels.kdl`, `autonomy.kdl`) — share the directory but not the file set. The resolver doesn't notice that and produces a misleading error path.

* Existing Patterns
- Cwd-first resolution from `packages/spell-server/src/main.ts:7-17` (`resolveConfigDir`). The legacy entrypoint uses cwd-only (`cwd/.spell`) with no home fallback — which would have produced the more honest error `Missing required config file: ./.spell/server.kdl`.
- Config-file existence probing from `loader.ts:148` (`readRequiredConfigFile`) — uses `Bun.file(...).text()` and `isEnoent` from `@oh-my-pi/pi-utils`.
- Multi-candidate resolution pattern from `packages/coding-agent/src/commands/server.ts:60-72` (the function in scope).

* Tests
- T1 — `resolveDefaultConfigDir` returns `cwd/.spell` when that dir exists, regardless of `~/.spell` state.
- T2 — when `cwd/.spell` is missing AND `~/.spell/server.kdl` exists, returns `~/.spell` (preserves the existing global-config integration test).
- T3 — when `cwd/.spell` is missing AND `~/.spell/server.kdl` does not exist, throws an error whose message names both candidate paths and recommends `--config-dir`.
- T4 — non-ENOENT errors from probing `cwd/.spell` still propagate unchanged.
