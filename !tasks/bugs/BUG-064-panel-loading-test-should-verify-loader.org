* Problem

The "switching workspace loads the main panel via Loader" test in =growth-shell.test.ts= (lines 88-101) verifies:
- =currentWorkspaceId= changed to "strategy"
- =panelRegistry['dashboard']= contains "GrowthDashboard.qml"

But it never checks that =mainPanelLoader.source= was actually set. The core contract tested by this suite is "Loader loads content when workspace is selected". A regression that breaks the =mainPanelLoader.source = panelPath= assignment would pass this test.

* Fix

In =domain/growth/test/panels/growth-shell.test.ts=, in the "switching workspace loads the main panel via Loader" test, after the existing assertions add:

#+begin_src typescript
// Verify the Loader source was actually set to the dashboard panel path
const loaderSource = await harness.evaluate<string>(
  "JSON.stringify(root.contentItem.children[0].children[1].children[0].children[0].source)"
);
// ... or use a named approach:
const source = await harness.evaluate<string>(
  "(function(){ var items = root.contentItem.children;" +
  "for(var i=0;i<items.length;i++){for(var j=0;j<items[i].children.length;j++){" +
  "var c=items[i].children[j];for(var k=0;k<c.children.length;k++){" +
  "var l=c.children[k]; if(l.objectName==='mainPanelLoader' || (l.source !== undefined && l.source !== '')) return String(l.source);}}} return '';})()"
);
expect(source).toContain("GrowthDashboard.qml");
#+end_src

A cleaner approach: give mainPanelLoader an =objectName: "mainPanelLoader"= in both GrowthShell.qml and the test harness, then use =findItems({ objectName: "mainPanelLoader" }, { properties: ["source"] })= to read it. This is more robust than tree traversal.
