* Problem

=build_semantic_index()= in =crates/pi-natives/src/code_graph.rs= derives the embedding dimension from the first vector: =vectors.first().map_or(768, Vec::len)=. It then builds the =VectorIndex= using that dimension. But it never validates that all other vectors in the batch match. If fastembed or a future model change produces inconsistent dimensions, the cache gets built from malformed data, and search later silently returns empty results (=VectorIndex::search= returns =Vec::new()= on dimension mismatch, which is correct but opaque).

The fix is to validate immediately after the batch returns and before building the index.

* Design Decision

After deriving =dimensions= from the first vector, check that all vectors match. This is a single pass over the batch — acceptable cost since we just completed an O(n * 768) embedding operation.

Use an early-return error with a clear message naming the offending index and length, so the user can diagnose whether the model configuration changed.
