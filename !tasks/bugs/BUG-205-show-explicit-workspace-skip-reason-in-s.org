* Goal

When ~spell recover --dry-run~ omits workspace restoration commands, print an explicit line explaining why (niri not found vs ~--no-workspace~ flag).

* Context

Currently the dry-run output silently skips ~niri msg action focus-workspace~ commands when either niri is unavailable or ~--no-workspace~ is set. The user cannot tell from the output alone whether workspaces are being skipped intentionally, due to missing niri, or for another reason. This makes post-crash troubleshooting harder.

* Implementation

** File: ~packages/coding-agent/src/commands/recover.ts~

In the dry-run branch (around line 152), after writing the ~spawnMode~ header and before iterating groups, add:

#+begin_src typescript
if (flags["no-workspace"]) {
    process.stdout.write("(--no-workspace: workspace commands omitted)
");
} else if (!niriAvailable) {
    process.stdout.write("(niri not found: workspace commands omitted)
");
}
#+end_src

This goes between line 156 (~process.stdout.write(`Dry run — showing ${spawnMode}:
`)~) and line 157 (~for (const group of groups)~).
