Two compounding issues make the niri overview show phases/tasks as blocked when they are not:

* Stale snapshot source
The niri controller reads =ctx.todoPhases= which is the interactive mode's cached
field. That field is updated by the event controller's async =tool_result= handler
(=setTodos()=). But the session's =#emit()= does not await async listeners, so the
niri controller's subscription fires before the event controller updates the cache.
Meanwhile, the session's internal =#todoPhases= (via =setTodoPhases()=) was already
updated synchronously by the todo-write tool before the event was emitted.

*Fix*: Change the niri context's =todoPhases= getter from =ctx.todoPhases= (stale
cache) to =ctx.session.getTodoPhases()= (authoritative source).

* Missing blocker refs treated as blocking
In =controller.ts#buildSnapshot()=, the blocker resolution logic uses:
#+begin_src typescript
return !dep || (dep.status !== "completed" && dep.status !== "abandoned");
#+end_src
When =dep= is undefined (blocker task auto-cleared/missing), =!dep= is true,
treating it as blocking. The canonical =hasUnresolvedBlockers= in =todo-write.ts=
does the opposite: =if (!blocker) return false= (missing = resolved).

After a blocker task is auto-cleared from the session data, all dependent tasks
flip to "blocked" in the niri overview.

*Fix*: Change to =return !!dep && dep.status !== "completed" && dep.status !== "abandoned"=.
Apply the same fix to =blockerLabels= filter.
