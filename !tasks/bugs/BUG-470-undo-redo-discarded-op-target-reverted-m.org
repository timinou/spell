* Root cause (three compounding bugs)
Traced both undo ops in the source session. Each reverted a DIFFERENT file than
its target:
- undo#1 target=packages/djinn_calendar/.../mock.ex → reverted apps/agentmaker/!docs/DJINN-CALENDAR-C4-C6-BRIEF.md (235 lines → 0)
- undo#2 target=packages/djinn_integrations/.../registry.ex → reverted apps/agentmaker/.../meetings_live.ex

1. TARGET DISCARDED (primary). edit.ts:194 hardcoded `target: ""` in the manage
   bridge → op.target never reached the kernel. Every undo degraded to
   target-less "revert most-recent".
2. PER-SHARD HISTORY. lib.rs:74 records each edit into
   workspace_root_for(file)/.spell/edit-history.jsonl. A monorepo splits one
   session across N logs. Target-less undo probes only the session-cwd shard →
   the packages/… corruption lived in a different log, invisible; the
   most-recent entry in the visible shard was the long-committed brief.
3. NO COMMIT AWARENESS. EditEntry.commit hardcoded None (lib.rs:85); nothing
   reconciles external `git commit`s → revert() happily rewrote committed work.

* Fix shipped (this session)
- Fix A: edit.ts threads op.target + root to manage undo/redo → revert scopes to
  the named file.
- Operation-aware grouping: one editGroupId per `edit` invocation (NAPI option →
  thread-local EditGroupGuard in napi.rs → stamped on every EditEntry via the
  lib.rs recorder). revert/reapply in edit_history.rs operate on the whole group
  atomically (intra-group rollback = all-or-nothing on disk) so a cross-file
  rename never half-reverts. group_id is `#[serde(default)]` → legacy logs read
  as singletons.
- manage.rs handle_undo/handle_redo: honour target (file_glob scope), render
  multi-file payload (files[], fileCount, per-file diff body).
- Docs: verb-schema.ts undo/redo descriptions now state target scopes the revert.
