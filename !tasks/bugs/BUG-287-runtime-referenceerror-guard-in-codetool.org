* Root Cause Context
When the agent edits its own source (code.ts) via sequential =code edit= calls, intermediate
saves leave the file in states where variables are referenced but not declared. New spell
sessions starting during this window load broken source and get ReferenceErrors. The running
process is unaffected (module already loaded), but the catch block surfaces an opaque
"X is not defined" error that doesn't help the user understand what happened.

Log evidence:
- ="editFile is not defined"= (8 occurrences, pid 3942455, command: edit)
- ="editHasManagedMissingBuffer is not defined"= (1 occurrence, pid 3954585, command: read)
Both occurred during the transition from commit 004f68eb3 to 0d64d00af.
