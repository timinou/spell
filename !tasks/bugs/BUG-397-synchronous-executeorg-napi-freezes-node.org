* Initial Message

Captured during PLAN-316 verification. User-visible symptom of the structural defect that FEAT-async-executeOrg fixes.

* Reproduction

1. Kill any running =pi-knowledge-worker= daemon and remove =/run/user/$UID/spell/{embed.pid,knowledge.sock}=.
2. Start a fresh =spell= session in a repo with a populated =.spell/memory= corpus (≥1000 .org files).
3. Issue =memory.search= via the agent surface.

Observed:
- One =📚 indexing org memory… 0/N (scan)= status line lands.
- TUI freezes for the duration of bge-m3 init + cold corpus embed (~30 s – 4 min depending on corpus size).
- Tool-call spinner glyph (=⠋⠙⠹…=) stops animating.
- Keyboard input is buffered but not processed; Ctrl-C does not interrupt.
- =MemoryStatusController= 2 s poll callbacks never fire during the wait.
- Status line is stuck on whatever was rendered immediately before the call.

Expected:
- TUI stays responsive throughout the recall.
- Status-line widget updates every 2 s with current =org_lane= progress.
- Tool-call spinner animates.
- Ctrl-C reaches the abort handler.

* Root Cause

=executeOrg= is declared as a synchronous NAPI function at
=crates/pi-natives/src/org_buffer.rs:1477=:

#+begin_src rust
#[napi(js_name = "executeOrg")]
pub fn execute_org(options: Value) -> Result<Value> {
    Ok(execute_org_catching(&options, execute_org_inner))
}
#+end_src

NAPI registers this as a sync JS function. The native body runs on the
Node main thread, so during the ~4 min cold recall the event loop is
fully blocked: no timer callbacks, no I/O, no render frames, no signal
handlers.

Every other heavy NAPI surface in =pi-natives= already uses
=task::run_blocking= (libuv worker pool) and returns =task::Async<T>=:
=grep=, =ast_grep=, =fuzzy_find=, =glob=, =read_image_from_clipboard=,
=execute_code_path=, =execute_code_graph=, =html=, =image=. =executeOrg=
is the outlier.

PLAN-316 mitigates the *startup* path (=peekMemoryProgress= now never
forces =init=), but the underlying freeze surface remains for any real
=recall= / =query= / =remember= call that actually waits on the daemon.
