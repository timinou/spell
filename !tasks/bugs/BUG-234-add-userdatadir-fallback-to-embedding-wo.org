* Problem
The TypeScript native addon loader (=packages/natives/src/native.ts=) searches =userDataDir= as a fallback path for compiled binaries:
- Linux/macOS: =~/.local/bin=
- Windows: =%LOCALAPPDATA%/spell= (fallback: =~/AppData/Local/spell=)

The Rust embedding worker discovery (=crates/pi-natives/src/embedding_worker.rs=, =worker_candidates()=) does NOT search this directory. If the addon loads from =userDataDir=, the worker binary at the same location is invisible, breaking semantic features.

* Change
** Add a =user_data_dir()= helper function matching =native.ts= lines 43-46:
#+begin_src rust
fn user_data_dir() -> Option<PathBuf> {
    #[cfg(windows)]
    {
        let base = env::var_os("LOCALAPPDATA")
            .map(PathBuf::from)
            .unwrap_or_else(|| home_dir().map(|h| h.join("AppData/Local")).unwrap_or_default());
        Some(base.join("spell"))
    }
    #[cfg(not(windows))]
    {
        home_dir().map(|h| h.join(".local/bin"))
    }
}
#+end_src
** Add =user_data_dir()= as a candidate in =worker_candidates()= after the =versioned_native_dir= candidate:

if let Some(user_dir) = user_data_dir() {
    push(user_dir.join(WORKER_BINARY_NAME));

#+end_src
