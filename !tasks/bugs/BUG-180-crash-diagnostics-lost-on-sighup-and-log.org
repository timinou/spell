* Problem
Three gaps in crash diagnostics cause 0-byte log files and no crash report when the process dies:

1. *SIGHUP/SIGTERM don't write crash reports*: ~writeCrashReport()~ is only called for ~uncaughtException~ and ~unhandledRejection~. When the terminal dies (SIGHUP), no crash report JSON is written to ~~/.spell/reports/~.

2. *Logger never flushes before exit*: Winston uses async file transport. The postmortem handler calls ~logger.error()~ then ~process.exit()~ — buffered log entries are lost. The logger has no ~flush()~ or ~close()~ method exposed.

3. *No session crash marker*: When the agent dies mid-turn, the session JSONL ends with a tool result and no assistant response. There's no entry to distinguish "crashed" from "still generating." The existing ~postmortem.register("session-manager-flush", ...)~ callback only flushes pending writes but doesn't write a crash marker.

* Design Decisions
1. *Crash reports for all fatal signals*: Extend ~writeCrashReport~ to accept signal reasons (SIGHUP, SIGTERM, SIGINT). Create a synthetic ~Error("Process received SIGHUP")~ to keep one crash report format. Call ~writeCrashReport~ in the SIGHUP, SIGTERM, and SIGINT handlers.

2. *Logger flush via ~winstonLogger.close()~*: Add a ~close()~ export to the logger module that calls ~winstonLogger.close()~ (returns a Promise). Call it in the postmortem ~runCleanup~ chain with a 2-second timeout. After close, the logger is unusable — this is fine since we're about to ~process.exit()~.

3. *Session crash marker entry*: Add a new ~CrashMarkerEntry~ type to session-manager. Extend the existing ~"session-manager-flush"~ cleanup callback in ~interactive-mode.ts~ to write a crash marker entry before flushing, but only for crash reasons (not normal EXIT). The marker is: ~{ type: "crash", id: <snowflake>, parentId: <lastLeafId>, timestamp: <iso>, reason: "sighup" | "sigterm" | "uncaught_exception" | "unhandled_rejection" }~.

* Edge Cases
- Logger ~close()~ called when logger was never used: winstonLogger.end() is idempotent
- ~close()~ called twice: should be idempotent (winstonLogger.end() is safe to call multiple times)
- ~appendCrashMarker~ called when session manager is closed: check ~this.#closed~ and no-op if true
- ~appendCrashMarker~ called when no session file exists: _persist will no-op (checks ~this.persist && this.#sessionFile~)
- SIGINT during normal exit (user presses Ctrl+C): writes a crash report and marker, which is slightly noisy but not harmful. The marker is informational.
- ~writeCrashReport~ failure: already wrapped in try/catch, no change needed
- Session file already has entries from the current turn: crash marker should have parentId pointing to the last entry written
