* Initial Message

make sure the spill threshold does not affect the get tool, and that the get tool can access all artifacts.

* Symptom
=get= on any file > ~1KB returns =[Showing lines X-Y of Z (1.0KB limit)]= with body redirected to =artifact://…=. The follow-up =get= on that artifact ALSO spills to a new artifact → infinite indirection. Agent cannot read mid-size source files in a single call.

* Root Cause
- =packages/coding-agent/src/tools/output-meta.ts::spillLargeResultToArtifact= wraps every tool result through =resolveToolSpillPolicy()=.
- =packages/coding-agent/src/session/spill-policy.ts::PRECISION_SPILL_EXEMPT_TOOLS= = ={ read, grep, org, find, code, lsp, ast_grep, ast_edit }= → ="get"= is missing despite being the canonical replacement for read/grep/find/ast_grep per Tool Precedence in =AGENTS.md=.
- Fallthrough policy = =getLowSpillPolicy=: 50-line trigger / settings-driven byte trigger (default ≈1KB) clamps =get= output and re-spills artifact reads.

* Impact
- Cannot read files > 50 lines or > spill-threshold KB in one call.
- =artifact://= reads via =get= are useless (recursive spill).
- Forces agent to use bash =sed=/=head= fallbacks → violates =get over bash= guidance from =AGENTS.md= and triggers the same 1KB clamp anyway.

* Fix
Closed by [[id:FEAT-A-tools-get-spill-threshold]].

* Verification
- =get= on 10_000-line file → full content, no =artifact://= notice.
- =get= on =artifact://…= for 100KB blob → identical content, no re-spill.
- =packages/coding-agent/test/tools/output-meta-spill-policy.test.ts=: add =get= case mirroring read case.
