* Context

After the Emacs-to-native migration (PLAN-183), the =CodeTool= in =packages/coding-agent/src/tools/code.ts= has four contract violations identified by audit AUD-057:

1. *Error envelope flattening*: When =executeCodeBuffer= returns ={ error: true, output: "..." }=, the tool serializes only =result.output= as content text. The LLM sees a bare string (e.g. ="Unknown command: bogus"=) without any error marker. Compare with the catch block which wraps errors as ={ error: true, message: ... }=.

2. *Missing mode forwarding*: The native engine's =splice= operation reads a =mode= field (="self" | "up" | "down"=) from the options object (see =edit_operation()= in =crates/pi-natives/src/code_buffer.rs= ~line 103). But the TypeBox schema has no =mode= field, and the option-building code doesn't forward it. Agents cannot express splice direction.

3. *Depth silently discarded*: =params.depth= is forwarded to the native buffer engine (line ~140) but NO file-local command reads it. The outline handler in Rust takes =(buffer, &profile)= with no depth parameter. The depth field exists in the schema for graph commands (forwarded separately via =#executeGraphCommand=). Forwarding it to file-local commands is a contract violation: input accepted and discarded.

4. *Relative paths not resolved*: File-local commands pass =params.file= directly to the native engine. The Rust =required_path()= converts it to a =PathBuf= relative to the process CWD. If =session.cwd= differs from process CWD (e.g. subagent with different working directory), the wrong file is opened. Graph commands already resolve against =session.cwd= (line ~174).

* Design Decisions

- When =result.error= is true, serialize content as =JSON.stringify({ error: true, message: ... })= matching the catch-block format
- Add =mode= field to TypeBox schema: =Type.Optional(Type.String({ description: "Splice mode: self | up | down (default: self)" }))=
- Forward =mode= to NAPI options alongside =operation=
- Remove =depth= forwarding from file-local option building (line =if (params.depth !== undefined) options.depth = params.depth;=). Do NOT remove =depth= from the schema — graph commands need it.
- Resolve relative file paths using =path.resolve(session.cwd ?? getProjectDir(), params.file)= when =!path.isAbsolute(params.file)=. Import: =import * as path from "node:path"= (per AGENTS.md namespace import rule).
- Apply path resolution only to the file-local code path, not the graph path (which already passes =root=).

* Edge Cases

- =result.output= can be a string or an object depending on the command. For error cases, it is typically a string. The =typeof result.output === "string"= check handles both.
- =path.resolve= with an absolute path returns the absolute path unchanged — the =isAbsolute= check is an optimization, not a requirement.
- =mode= defaults to ="self"= in the Rust engine when not provided. The TypeBox schema should NOT set a default — let the engine handle it.
- The =save= command also needs path resolution (it writes to disk). The file option forwarding is shared code, so the fix covers all file-local commands.
