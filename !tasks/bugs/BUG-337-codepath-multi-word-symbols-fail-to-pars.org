* Symptoms

Targets like =foo.ts::export * from "./json"= produce ="unexpected trailing input"=. Quoted/spaced/non-identifier names cannot be addressed at all.

* Root cause

- =crates/pi-code-path/src/dialects/typescript.rs:146-160= TsNameLexer.parse_segment accepts only =[A-Za-z0-9_$]=. First non-ID char terminates the segment.
- =crates/pi-code-path/src/parser.rs:39-60= top-level returns "unexpected trailing input" diagnostic with no remediation hint.
- =crates/pi-code-path/src/ast.rs= NamePayload has only =Raw(String)=; no =Quoted= variant. Even if backticks parsed, the matcher would compare against tree-sitter =name= field (which doesn't exist for re-exports).
- =crates/pi-natives/src/code_path/code_resolver/walker.rs= NameLexer.matches() compares only against =name= field of declarations.

* Fix contract (D: Quoted variant + walker text-match)

** AST extension
- Add =NamePayload::Quoted(String)= alongside =Raw(String)= in =crates/pi-code-path/src/ast.rs=.
- Update serde derives, render(), and Hash/PartialEq.

** Parser
- =crates/pi-code-path/src/dialects/typescript.rs::parse_segment=: when input starts with =`=, consume verbatim until matching =`=, emit =Quoted(payload)=. Reject unterminated.
- Also Python/Rust/Haskell name lexers — backtick path same shape.
- =crates/pi-code-path/src/parser.rs::parse_code_path_inner=: when the trailing-input diagnostic fires AND the unconsumed input contains space or asterisk after first identifier, append a DidYouMean hint suggesting =§export_statement[text~"…"]= or appropriate axis.

** Walker matcher
- =crates/pi-natives/src/code_path/code_resolver/walker.rs= and =crates/pi-code-path/src/dialects/typescript.rs::matches=: for =Quoted=, compare against the candidate node's source text after whitespace normalization (collapse =\s+= → one space, trim ends).
- Scope: match only against statement-level node kinds (export_statement, import_statement, return_statement, expression_statement, call_expression). Bounds walker cost.
- Equality after normalization. Anchor predicate =[~=]= for contains can be added in a follow-up.

** Schema/prompts
- Update tool descriptions in =packages/coding-agent/src/tools/codepath-types.ts= editSchema and getSchema to document backtick-quoting.
