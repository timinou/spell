Found + FIXED during PLAN-321 verb-surface test-drive.

The `undo` verb is documented as "dispatched alone; target ignored" (edit.md + verb-schema.ts), and edit.ts routes it via `manage undo` with `target: ""`. But `manage::handle_undo` had a hard guard rejecting empty target ("manage undo requires a file target"), so EVERY undo failed:
```
edit { operations: [{ target: "", action: { kind: "undo" } }] }
→ [missing_target] manage undo requires a file target
```
Even passing a file target failed because the guard fired before the engine ran.

Root cause: artificial guard. The underlying `JsonlHistory::revert` treats `file_glob` as OPTIONAL (None → revert most-recent uncommitted edit in session, any file), and `history_for("")` already falls back to `workspace_root_for(root)`. So target-less undo was fully supported by the engine; only the guard blocked it.

Fix (crates/pi-natives/src/code_path/manage.rs::handle_undo): drop the empty-target rejection; pass `file_glob` only when a file is supplied (narrows the revert), else revert session-wide most-recent. Matches the verb contract.

NB: `redo` remains a stub ("redo not yet implemented; re-apply manually") — separate, pre-existing, out of scope here.
