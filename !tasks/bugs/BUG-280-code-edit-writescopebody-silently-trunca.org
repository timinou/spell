* Scope

In: detect and refuse `write{scope:"body"}` executions that would silently delete sibling declarations; add a structural-loss safety guard and a clear error variant in `pi_code_engine::edit::body::replace_body` and the single_action dispatcher in `crates/pi-natives/src/code_buffer.rs`.

Out: fixing tree-sitter Elixir grammar itself; changing the declarative API of other actions (findAndReplace, wrap, rename).

* Background

Observed failure (PLAN-248 wave-1 subagent): a `quick_task` subagent invoked `code edit { targetId: "lib/collections_section.ex::Foo.bar", actions: [{ kind: "write", scope: "body", content: [...] }] }` on `collections_section.ex`. The action silently truncated the file at line 72, deleting 213 lines of EEx-template content inside the surrounding module. Recovery required `git checkout`.

Likely mechanism (to confirm during implementation):
- `build_resolved` (`crates/pi-code-engine/src/resolve.rs:95-120`) returns `body_start_byte`/`body_end_byte` from tree-sitter's `body` field of the decl node. For Elixir `defmodule Mod do ... end`, the `do_block` body includes ALL sibling `def`s. If the caller targeted `Mod` (the module) with `scope:"body"` but intended an inner `def`, `replace_body` happily replaces the entire block with the short content.
- The current dispatcher (`single_action` at `crates/pi-natives/src/code_buffer.rs:380-409`) has no structural check.

Impact: silent data loss. Worse than the staleness class (BUG-279) because even with a fresh cache, the edit destroys content deterministically.

** Structural-loss guard in replace_body
:PROPERTIES:
:CUSTOM_ID: BUG-280-code-edit-writescopebody-silently-trunca::size-guard
:DEPENDS: BUG-280-code-edit-writescopebody-silently-trunca::decl-count BUG-280-code-edit-writescopebody-silently-trunca::error-variant
:END:

- File: `crates/pi-code-engine/src/edit/body.rs`
- Extend signature: `pub fn replace_body(buffer, resolved, content, policy: ReplacePolicy)` where `ReplacePolicy { allow_sibling_delete: bool }`.
- Before returning the `TextEdit`:
  - `original_decls = collect_top_level_decls_in_range(buffer, body_start, body_end)`.
  - Parse `adjusted` into a temporary tree-sitter tree of the same language; collect `new_decls` analogously.
  - If `original_decls.len() >= 2 AND new_decls.len() < original_decls.len() AND !policy.allow_sibling_delete`, compute `lost_decls = original_decls - new_decls (set diff)` and return `Err(CodeEngineError::UnsafeScopeWrite { ... })`.
- Keep a non-policy convenience wrapper `replace_body_safe(buffer, resolved, content) = replace_body(buffer, resolved, content, ReplacePolicy::default())` for the >90% call path.

* Edge cases

- Languages without `declaration` queries (plain text, Typst prose): guard does not fire; preserve current behavior.
- Single-decl body (e.g., one-line TS function): `original_decls.len() == 1` → guard does not fire; matches the common case.
- Nested classes: counts direct-child top-level decls only; nested methods removed intentionally are not triggered.
- Parse failure on replacement content: if tree-sitter rejects `adjusted`, return `Err(CodeEngineError::Edit("content does not parse"))` BEFORE applying — no silent acceptance.
- Tree-sitter timeout: replacement re-parse uses `PARSE_TIMEOUT_MICROS` (already 200ms); on timeout, accept the edit but include a warning in the returned `EditResult.warnings` vector.
- Whole-file `write` (no `scope`, no `targetId`): unchanged; guard explicitly scoped to `scope:"body"` branch.
- Renamed-only-but-otherwise-equivalent decls: if the agent's replacement renames a `def` while keeping its body, the lost-decls set diff would mark the old name as lost. Acceptable: the agent must opt in via `allowSiblingDelete` for renames inside bodies — surfaces the rename intent explicitly.
