** Problem

The Anthropic SDK throws ~AnthropicError("Unexpected event order, got message_start before receiving \"message_stop\"")~ when its internal ~MessageStream._accumulateMessage()~ receives a second ~message_start~ SSE event before the first message's ~message_stop~. This indicates a corrupted/overlapping server-side stream.

The error is caught by our retry loop in ~streamAnthropic~ but is *not* recognized as retryable:
- ~isTransientStreamParseError~ only matches JSON parse errors
- ~isProviderRetryableError~ doesn't match this message pattern
- Since ~firstTokenTime~ is already set (content was streaming), the non-transient path throws immediately

The partial response is unusable (the stream was interrupted mid-flight), so this *should* be classified as transient — eligible for retry even after content has started.

Source: ~node_modules/@anthropic-ai/sdk/lib/MessageStream.mjs:435~
Thrown as ~AnthropicError~ (extends ~Error~, not ~APIError~).

** Fix

Add ~unexpected event order~ to the regex in ~isTransientStreamParseError()~ in ~packages/ai/src/providers/anthropic.ts~:

#+begin_src typescript
function isTransientStreamParseError(error: unknown): boolean {
    if (!(error instanceof Error)) return false;
    return /json parse error|unterminated string|unexpected end of json input|unexpected event order/i.test(error.message);
}
#+end_src

This classifies it as transient, so the retry loop:
1. Retries even after ~firstTokenTime~ is set (partial response is unusable anyway)
2. Resets ~output.content~, ~stopReason~, ~firstTokenTime~, and ~started~ for a clean retry
3. Respects ~PROVIDER_MAX_RETRIES~ (3) with exponential backoff (2s, 4s, 8s)
