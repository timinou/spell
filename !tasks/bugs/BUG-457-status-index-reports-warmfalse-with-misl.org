## Symptom
`status index` (manage://index) returns `"warm": false` with reason "no edge query has triggered build yet" even when `.spell/graph/workspace.bin` holds a fully-built, up-to-date graph on disk. After one edge query it flips to `warm:true` with full stats. The "warm" signal only reflects whether the **in-process `code_graph_cache` DashMap** is populated — it is blind to the persisted cache that BUG-456 now warm-loads from.

## Why it's confusing
An operator checking readiness sees `warm:false` and concludes the graph isn't built, when in fact a fast warm-load is available. The message actively suggests running an edge query "to trigger build" when no build is needed — only an in-process load.

## Fix
Make `status index` distinguish three states:
- `warm` (in-process Arc present),
- `cached` (persisted `.bin` fresh on disk, load pending — sub-second to serve),
- `cold` (no cache; full build needed).
Report `cached` instead of `warm:false` when `cache_status==Fresh`, with a message reflecting load-not-build.
