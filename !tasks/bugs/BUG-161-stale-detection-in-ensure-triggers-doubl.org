* Initial Message

When ~ensure()~ detects a stale socket (no data for 90s), it calls ~this.#socket.destroy()~ and falls through to ~#doEnsure()~. The socket ~close~ event fires asynchronously and, since ~#stopping~ is false, triggers ~#autoReconnect~. This creates two concurrent reconnection paths racing to establish a new socket.

* Problem
~ensure()~ at line 108-112:
#+begin_src typescript
if (Date.now() - this.#lastDataReceived > HEARTBEAT_TIMEOUT_MS) {
    this.#socket.destroy();  // triggers close handler → autoReconnect
    this.#socket = null;
    // falls through to #doEnsure → also reconnects
}
#+end_src

The close handler at line 340 checks ~!this.#stopping~ which is still false (stale detection is not a shutdown). So it dispatches ~socket_disconnected~ and starts ~#autoReconnect~. Meanwhile ~ensure()~ falls through to ~#doEnsure()~ which also calls ~#connectSocket()~.

The ~#connectingPromise~ guard in ~ensure()~ does NOT protect here because the first ~ensure()~ call has already entered ~#doEnsure~ by the time ~#autoReconnect~ fires.

* Fix
Add a ~#staleDisconnecting~ flag. Set it to ~true~ before calling ~destroy()~ in the stale path. Check it in the close handler alongside ~#stopping~. Clear it after the close event fires or in ~#doEnsure~ entry.

Simpler alternative: just abort any existing auto-reconnect before entering ~#doEnsure~:
#+begin_src typescript
// In ensure(), stale path:
this.#reconnectAbort?.abort();
this.#socket.destroy();
this.#socket = null;
#+end_src

This kills any in-flight auto-reconnect. When the close handler fires, ~wasUnexpected~ is true, so it starts a new auto-reconnect. But ~#doEnsure~ is already running. If ~#autoReconnect~ tries ~#connectSocket~, it races with ~#doEnsure~'s ~#connectSocket~. Both would succeed or one would fail.

Best approach: set ~this.#stopping = true~ temporarily in the stale path, then restore it after ~destroy()~ fires:
#+begin_src typescript
if (Date.now() - this.#lastDataReceived > HEARTBEAT_TIMEOUT_MS) {
    logger.warn("Socket appears stale (no data for 90s), forcing reconnect");
    // Suppress close handler's auto-reconnect — we'll reconnect via #doEnsure.
    this.#stopping = true;
    this.#socket.destroy();
    this.#socket = null;
    this.#stopping = false;
    // Fall through to reconnect logic below
}
#+end_src

The close handler fires asynchronously (after current microtask), so ~#stopping~ is false when it runs. That doesn't work either.

Correct approach: use a dedicated flag:
#+begin_src typescript
#intentionalDisconnect = false;
// ...
// In stale path:
this.#intentionalDisconnect = true;
this.#socket.destroy();
this.#socket = null;

// In close handler:
const wasUnexpected = !this.#stopping && !this.#intentionalDisconnect;
this.#intentionalDisconnect = false;
#+end_src
