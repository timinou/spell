## Symptom

`packages/coding-agent/src/tools/edit.ts::#executeLineId` handles these kinds TS-locally:
- `lineReplace`, `lineAppend`, `linePrepend`
- `lineInsert` (with `at` field)
- `fileAppend`/`filePrepend` (no anchor — missing-file create branch)

It calls `applyHashlineEdits()` which uses `fs.writeFile` directly. BYPASSES executeCodePath, edit_transaction, broker.

## Why this is wrong post-PLAN-309

The kernel has Op variants for ALL of these:
- `Op::LineReplace { target, span, content }` at `crates/pi-code-path/src/op.rs`
- `Op::LineInsert { target, at, content }`
- `Op::LineAppend / LinePrepend { target, at, content }`
- `Op::FileAppend / FilePrepend { target, content }` (no anchor case)

All implemented via `crates/pi-code-path/src/dialects/text/mutation.rs::apply_to_text` and routed through edit_transaction in napi.rs. Full broker + journal + transaction semantics.

The TS-local dispatch was a historical optimization back when the kernel didn't support these ops cleanly. PLAN-309 made the kernel canonical; the TS bypass is now legacy behavior.

## Same consequences as BUG-B

- ❌ No broker (concurrent peer edits silently race)
- ❌ No journal
- ❌ No session_id
- ❌ No buffer registry invalidation
- ❌ No edit_transaction snapshot/rollback
- ✓ TS-local has its own hash-line verification

## Severity

P1 — same as BUG-B (filePatch bypass). Working but not canonical.

## Fix scope

Replace `#executeLineId` body with a call to `#executeStructural` for each line-op kind. Delete the applyHashlineEdits dependency from edit.ts (the patch/hashline module may still be used elsewhere for diff preview; check).

Edge case: missing-file `fileAppend`/`filePrepend` (create-if-missing). Kernel Op::FileAppend currently requires file to exist. Either:
- Add a `create:true` flag to FileAppend/FilePrepend so missing-file creates the file
- Migrate the missing-file branch to dispatch `fileCreate` instead
- Keep a thin TS-side "create-if-missing" precheck that synthesizes a fileCreate

Tests need parity verification.
