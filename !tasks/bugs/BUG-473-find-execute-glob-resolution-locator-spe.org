## Root cause: locator spelling is not invariant
A target addressing the SAME file resolves differently by spelling. Two layers:

### Kernel `walk()` — crates/pi-code-path/src/dialects/fs/walker.rs
`walk()` matches each entry via `rel = path.strip_prefix(root)` then `glob.is_match(rel)`. The glob comes from `fs_locator_to_glob(loc)` built literally from segments, special-casing only `.`/`./`. Therefore:
- ABSOLUTE locator (`/root/crates/*`) → glob has leading `/`, never matches root-relative `rel` → 0.
- `..` locator → literal `..` segment, never matches → 0.
- TRAILING-SLASH dir-glob (`crates/*/`) → globset `crates/*/` doesn't match `crates/pi-code-path` → 0.
No diagnostic emitted; looks like "no results".

### TS `get.ts` — effectiveRootFor + relativize gate
Patches ABSOLUTE targets (re-roots at prefix dir; `makeRelativeToRoot` incidentally strips trailing slash via path.relative). Two holes:
1. `..`-relative targets: `extractAbsolutePrefix` returns null → entire relativize block skipped → raw `../...` hits kernel with root=cwd → 0. (THE USER REPRO.)
2. qualified-absolute-under-cwd (`/cwd/sub/x#raw`): relativize gate `rootEqual || !under-cwd || hasQuery` misses it → absolute glob under non-matching root → empty-content.
