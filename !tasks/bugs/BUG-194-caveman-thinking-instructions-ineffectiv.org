* Problem

PhD-caveman thinking notation instructions (symbol vocabulary, structural markers, domain
abbreviations) are placed at the absolute end of the system prompt via =appendPrompt= in
=system-prompt.md=. After hundreds of lines of tools, rules, and procedures, the thinking
instructions have minimal salience. The model's extended thinking blocks remain verbose
despite =caveman.thinkingMode= being set to ="caveman"=.

* Root Cause

In =system-prompt.ts=, the caveman prompt is rendered separately and appended via:
#+begin_src typescript
const appendPromptParts = [resolvedAppendPrompt, cavemanPrompt].filter(...);
#+end_src

This lands at the very end of =system-prompt.md=:
#+begin_src handlebars
{{#if appendPrompt}}
{{appendPrompt}}
{{/if}}
#+end_src

The thinking instructions share this position with communication style instructions,
placing them after =CACHE_BOUNDARY= in the dynamic section — the weakest possible position
for influencing extended thinking behavior.

* Fix

Two-pronged fix: (1) reposition thinking instructions to high-salience location, (2) rewrite
prompt with stronger compliance framing, negative examples, and multiple domain-specific
examples.

** Key design decisions
- Thinking instructions move from =caveman.md= (rendered into =appendPrompt= at end of
  system prompt) to =system-prompt.md= right after =</behavior>= in a =<thinking-mode>=
  XML tag — the highest salience position for reasoning-style instructions
- Communication style instructions (lite/full/ultra/wenyan level descriptions) remain in
  =caveman.md= and render via =appendPrompt= at the end — no change
- No duplication — the =={{#if cavemanThinking}}...{{/if}}== block is removed from =caveman.md=
- No changes to =system-prompt.ts= — =cavemanThinking= already flows to the main template
  via =...cavemanPromptData= spread
- =custom-system-prompt.md= is unchanged — its =appendPrompt= is already near the top
- This goes before =CACHE_BOUNDARY=, so caveman-on and caveman-off sessions have different
  cache keys. Acceptable because level is constant within a session.

** Prompt improvements over current version
1. *Visibility accountability*: "Your thinking blocks are visible to the user" — creates
   social pressure for compliance
2. *Negative example first*: show verbose thinking marked as BAD
3. *Multiple domain-specific examples*: architecture decision, code investigation, debugging
4. *Trimmed symbol table*: inline the most-used symbols in compact format instead of a
   large table the model skims over
5. *Stronger imperative*: "EVERY thinking block MUST" not just "your thinking blocks"
