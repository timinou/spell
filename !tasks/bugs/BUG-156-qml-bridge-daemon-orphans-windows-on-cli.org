When a client disconnects from the daemon, its windows keep their old ~owner~ pointer (now a dangling ~QLocalSocket*~). On reconnect, ~getWindowStates(newClient)~ returns empty because the new client pointer doesn't match the dead owner. Windows are alive but unreachable.

* Problem
- ~SocketServer::onClientDisconnected()~ removes the client from ~m_clients~ but does NOT notify ~WindowManager~ to orphan the windows.
- ~WindowManager::getWindowStates(client)~ filters by ~it->owner != client~ — so a reconnecting client gets an empty state snapshot.
- Events emitted by orphaned windows route to the dead owner pointer (no-op via ~writeEvent~ null guard), silently lost.
- Systray/hotkey signal lambdas (windowmanager.cpp:107-119, 134-140) capture ~client~ by value. After disconnect + ~deleteLater()~, the pointer dangles — undefined behavior on next systray/hotkey event.
- When a user closes an orphaned window via WM (X button), ~QQuickWindow::closing~ lambda captures ~owner~ (nullptr for orphans) and calls ~writeEvent(nullptr, ev)~ — silently dropped. After reconnect, state snapshot still reports the window as alive.

* Tests
All tests in ~packages/qml/test/reconnect.test.ts~:
1. "orphaned windows appear in reconnect state snapshot" — fake daemon tracks connection order, first client gets windows, disconnect, second connect receives state with orphaned windows.
2. "multi-session orphan arbitration: only matching window IDs are claimed" — two clients connect, client A owns window X, client A disconnects, client B (which had window Y) reconnects, state snapshot for B includes orphaned X with ~orphaned: true~ flag. B's QmlBridge only claims X if it was in B's #windows map.
3. "WM-close of orphaned window removes it from state" — fake daemon tracks window removal, orphaned window closed by WM, next reconnect state snapshot excludes it.
4. Existing multi-client isolation tests must still pass.

* Edge Cases
- *Dangling pointer UB*: ~orphanWindows~ must be called BEFORE ~deleteLater()~ to avoid accessing freed memory.
- *Multi-session orphan claim*: TS-side QmlBridge only re-adds windows from state snapshot if ~win.id~ is in its existing ~#windows~ map OR if the window is orphaned and no other client has claimed it. The ~orphaned: true~ flag enables this.
- *Rapid reconnect*: A client disconnects and reconnects within the same Qt event loop iteration. ~orphanWindows~ runs synchronously in ~onClientDisconnected~, so the orphaning happens before the reconnect callback.
- *WM-close during disconnect*: The closing lambda fires while owner is nullptr. Window is removed from ~m_windows~. No event routed. State snapshot on reconnect excludes it.
