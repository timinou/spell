* Initial Message

the org get and search tools provide wrong ITEMs and not well ordered. PLease try the tool and tell me the querying improvements you'd make

* Problem
=readCategory= in =packages/org/src/org-reader.ts= returns ALL parsed items from
every .org file: file-level (level 0) AND heading-level children (level > 0).
=cmdQuery= and =cmdDashboard= in =packages/org/src/tool.ts= pass these through
without level filtering. Result:

- 50.3% of query results are sub-heading noise (846 of 1681 items)
- When querying =todo:ITEM=, 91.5% of results are sub-headings (842 of 920)
- Dashboard DOING list includes child headings with empty IDs
- Many sub-headings have empty CUSTOM_IDs (=id: \"\"=), providing no useful reference

The Emacs-side =org-tasks--collect-heading-items-from-file= correctly filters
items to only those WITH a CUSTOM_ID (line 186: =when custom-id=), but the TS
reader does not.

:PROPERTIES:
:EFFORT: 5m
:END:

#+begin_src typescript
/** Filter by heading level. 0 = file-level items only. */
