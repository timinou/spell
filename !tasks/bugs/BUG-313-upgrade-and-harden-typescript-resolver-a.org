What happened?

* Scope

In:
- Upgrade =oxc_resolver= for =crates/pi-code-graph= from the current =1.12= line to the current stable 11.x line and refresh =Cargo.lock=.
- Add local panic containment inside =crates/pi-code-graph/src/language/typescript.rs= so =TypeScriptImportResolver.resolve()= cannot abort the Spell process if the upstream resolver panics again.
- Preserve the existing resolution contract: successful resolutions still return project-relative paths, ordinary misses still fall through to =fallback_relative_path()= or =None=, and valid graphs continue indexing normally.
- Add Rust regression coverage that proves both the direct resolver path and the builder path used by native code-graph commands stay alive under the panic class reported by the user.

Out:
- Broad dependency refresh across unrelated Rust crates.
- Changing the =ImportResolver= trait contract or introducing a new user-visible resolver error for normal misses.
- Reworking grep / code tool UI formatting unless the implementation session discovers a truthful-surfacing gap after the Rust fix.
- Removing semantic/code-graph functionality; the system must keep working, not degrade by feature removal.

Rationale:
- Repo evidence shows =crates/pi-code-graph/Cargo.toml= still pins =oxc_resolver = "1.12"=.
- =crates/pi-code-graph/src/language/typescript.rs= currently calls =resolver.resolve(from_dir, request.specifier).ok()= directly with no panic containment.
- =crates/pi-code-graph/src/indexer.rs= runs that resolver for every extracted import during =CodeGraphBuilder.build()=.
- =crates/pi-natives/src/code_graph.rs= and =crates/pi-natives/src/code_buffer.rs= host that builder in runtime NAPI paths, so an uncaught resolver panic aborts the Spell session instead of producing a truthful failure.

* Existing Patterns

- =crates/pi-code-graph/src/language/typescript.rs=
  - =fallback_relative_path(project_root, from_file, specifier)= and =resolve_candidate()= already define the local fallback contract after resolver misses. The panic guard must preserve these paths rather than inventing a parallel recovery branch.
- =crates/pi-code-graph/src/indexer.rs=
  - =CodeGraphBuilder.build()= canonicalizes the root once, extracts imports, then resolves each import through the language resolver. Regression coverage must hit this builder path, not only a unit helper, because this is the runtime boundary used by Spell.
- =crates/pi-embedding-worker/src/main.rs=
  - =panic::catch_unwind(AssertUnwindSafe(...))= is an in-repo precedent for containing internal Rust panics and converting them into ordinary control flow instead of process abort.
- =crates/pi-natives/src/code_graph.rs=
  - =run_code_graph()= / =ensure_graph()= are the native call path that exercises =CodeGraphBuilder=. After Rust changes, implementation must rebuild the native addon before manual repro so Spell actually runs the updated resolver path.
