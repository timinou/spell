* Scope
In scope: fix the root cause of `code edit` insertion boundary corruption by unifying safe insertion semantics for symbol-target and line-target `insertBefore` / `insertAfter`, then audit adjacent sibling-structure actions (`splice`, `move`, `clone`, `transpose`) for the same boundary/indentation invariant violations. The implementation area is primarily `crates/pi-natives/src/code_buffer.rs` plus the structural edit modules under `crates/pi-code-engine/src/edit/`.

Required behavior: safe symbol-target insertion should auto-normalize boundary newlines/indentation when the target boundary is unambiguous, but still reject shared-boundary or otherwise unsafe splices. The same conceptual operation must not behave one way for line targets and another way for symbol targets.

Out of scope: broad API redesign, interactive previews, unrelated write-scope/body bugs, or semantic rename/delete behavior outside the insertion/sibling-operation family.


Any broader API redesign or usability work discovered during this hardening pass must be captured in [[id:FUP-059-code-edit-api-ergonomics-and-audit-follo]] instead of expanding this bug item.
* Existing Patterns
- Reuse the explicit safety discipline already present in `crates/pi-code-engine/src/edit/replace.rs`:
  - `insert_before(buffer, line, node_type, content, within)`
  - `insert_after(buffer, line, node_type, content, within)`
  - separator guards in `ensure_insert_before_separator` / `ensure_insert_after_separator`
- Reuse indentation helpers instead of ad-hoc spacing logic:
  - `crates/pi-code-engine/src/edit/indent.rs::{node_indent, adjust_indent}`
- Follow transactional edit application in `crates/pi-natives/src/code_buffer.rs`:
  - `single_action(...)`
  - `apply_operations_transactionally(...)`
- Use existing sibling-safety precedent from `replace_body_safe` in `crates/pi-code-engine/src/edit/body.rs`: reject unsafe structural changes rather than silently corrupting neighbors.

* Tests
Workflows to cover before implementation:
- T1 — symbol-target `insertBefore` at a top-level declaration inserts a clean sibling with correct indentation and no stripping of the following declaration’s leading whitespace.
- T2 — symbol-target `insertAfter` inserts at the right sibling boundary without producing a leading empty-string artifact, double blank line, or malformed import/declaration adjacency.
- T3 — unsafe shared-boundary insertions still fail with an explicit refusal/error rather than being auto-corrected into a possibly wrong structure.
- T4 — equivalent safe symbol-target and line-target insertions produce the same file shape.
- T5 — adjacent sibling operations (`splice`, `move`, `clone`, `transpose`) either preserve boundaries/indentation or reject unsafe cases under the same invariant family.
- T6 — failed structural edits remain atomic; a follow-up edit on the same file still succeeds without stale dirty state.

* Edge Cases
- Top-level imports, adjacent declarations, and nested declaration targets must not gain or lose indentation on neighboring lines.
- Auto-normalization must not silently cross shared boundary lines such as `} else {`, `}),`, or similar multi-owner delimiters.
- Any refusal path must leave the buffer transaction clean so a later valid edit works immediately.
- Hardening must preserve existing successful operations that already produce stable structure.
