* Intention &amp; Purpose

Add ANTHROPIC_API_KEY as fallback env var for better-ccflare provider so users with existing Anthropic keys can route through the proxy without setting ANTHROPIC_AUTH_TOKEN.

* Context &amp; Narrative

PLAN-293's serviceProviderMap entry only resolves ANTHROPIC_AUTH_TOKEN:
  better-ccflare: () => $pickenv("ANTHROPIC_AUTH_TOKEN")

When this is unset (common case — user hasn't generated a btr- key), the provider sends no auth header. better-ccflare instances with API keys configured reject requests with:
  {"type":"authentication_error","message":"x-api-key header is required"}

better-ccflare's API auth is OPTIONAL per docs. When no API keys exist, the proxy is wide open. When keys are configured (this user's instance), a valid btr- key is required. But users may also want to route their standard Anthropic key through better-ccflare for analytics/load-balancing even without a btr key.

The fix: fall back to ANTHROPIC_API_KEY (the user's existing Anthropic key). This matches how the user's pre-PLAN-293 setup worked — routing anthropic models through better-ccflare with their Anthropic key as x-api-key.

Auth priority: ANTHROPIC_AUTH_TOKEN (btr- key) → ANTHROPIC_API_KEY (standard Anthropic key) → "" (keyless mode for instances without API keys)
