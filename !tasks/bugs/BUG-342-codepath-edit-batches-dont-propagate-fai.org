* Root cause

- =packages/coding-agent/src/tools/edit.ts:166-188= iterates ops, pushes results, no early return on failure.
- Line 201: ~_hasError = results.some(r => r.isError === true)~ computed but **prefixed with underscore = unused**. Aggregate result returns success.
- No transaction concept at the TS API surface. Kernel FEAT-712 ~transaction:"strict"~ wraps the *actions array within ONE op*, not the *operations array of the batch*.

* Fix contract (C: fail-fast default + opt-in atomic restore)

** A. Fail-fast (default)
- After each ~results.push(...)~, check ~r.isError~. If true:
  - Mark remaining ops as ~status: "skipped"~ in aggregate result
  - Set ~result.isError = true~
  - ~text~ summary names the failed op index and reason
  - ~return~ early — do not run subsequent ops

** B. Strict transaction (opt-in)
- Add ~transaction~ field to editSchema:
  - ~"best-effort"~ (default) — fail-fast (A) but applied ops stay applied
  - ~"strict"~ — snapshot all ~targetPath~ files before loop; on any failure, restore snapshots; return aggregate isError with rollback summary
- Snapshot model: read each unique targetPath once before loop. Restore via ~fs.writeFile(targetPath, snapshot)~ for files that existed; ~fs.unlink~ for files that didn't.
- Mirrors kernel ~transaction:"strict"~ at the TS layer (similar shape, different scope).

** Schema/prompts
- =packages/coding-agent/src/tools/codepath-types.ts=: add ~transaction~ field doc:
  "transaction: 'best-effort' (default) | 'strict'. Strict snapshots all target files before any op and restores on failure."
- =packages/coding-agent/src/tools/edit.ts editDescription=: one example showing transaction:"strict" usage.
