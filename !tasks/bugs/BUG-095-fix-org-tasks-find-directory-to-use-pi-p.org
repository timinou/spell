* Problem

~org-tasks--find-directory~ looks for ~@tasks~ via ~locate-dominating-file~, but the actual directory is ~!tasks~. The function also doesn't use ~pi-project-root~ which is set by the daemon launcher.

Currently this is masked because the TypeScript layer always passes explicit file paths to Emacs MCP tools. But any Elisp code that falls back to ~org-tasks--all-org-files~ will fail to find items.

* Fix

Update ~org-tasks--find-directory~ to:
1. Check ~org-tasks-directory~ (existing, unchanged)
2. Check ~(expand-file-name "!tasks" pi-project-root)~ when ~pi-project-root~ is bound
3. Fall back to ~locate-dominating-file~ for ~!tasks~ (not ~@tasks~)
4. Final fallback to git root + ~!tasks~

#+begin_src elisp
(defun org-tasks--find-directory ()
  "Find the tasks directory."
  (or org-tasks-directory
      (when (and (boundp 'pi-project-root) pi-project-root)
        (let ((dir (expand-file-name "!tasks" pi-project-root)))
          (when (file-directory-p dir) dir)))
      (when-let ((current (or buffer-file-name default-directory)))
        (when-let ((parent (locate-dominating-file current "!tasks")))
          (expand-file-name "!tasks" parent)))
      (let ((git-root (locate-dominating-file default-directory ".git")))
        (when git-root
          (expand-file-name "!tasks" git-root)))))
#+end_src
