* Context

The =lsp status= action in =LspTool.execute()= reports =Object.keys(config.servers)= as "Active language servers". This shows configured-but-not-yet-started servers as "active". After adding =.git= to Tinymist =rootMarkers=, this now reports =tinymist= as active in any git repo before any =.typ= file has been opened.

The =getActiveClients()= function in =client.ts= correctly returns only instantiated clients from the global =clients= Map, but status doesn't use it.

Replace with:
#+begin_src typescript
if (action === "status") {
    const activeClients = getActiveClients();
    const activeNames = activeClients.map(c => c.name);
    const configuredNames = Object.keys(config.servers);
    const idleNames = configuredNames.filter(name => !activeNames.includes(name));
    // ... lspmux detection ...

    const lines: string[] = [];
    if (activeNames.length > 0) {
        lines.push(`Active language servers: ${activeNames.join(", ")}`);
    }
    if (idleNames.length > 0) {
        lines.push(`Configured (not started): ${idleNames.join(", ")}`);
    }
    if (lines.length === 0) {
        lines.push("No language servers configured for this project");
    }
    const serverStatus = lines.join("
");
    // ... rest unchanged ...
}
#+end_src

Note: =getActiveClients= is already imported in =index.ts= (line 15). The =getActiveClients= return shape is ={ name, status, fileTypes }[]=, where =name= is =client.config.command= (e.g., "tinymist", "rust-analyzer").

** Edge case: name matching

=getActiveClients()= returns =client.config.command= as =name=, while =config.servers= keys are server identifiers (e.g., "tinymist", "rust-analyzer"). These may differ if the command name differs from the config key. To handle this, compare using the config key stored on the client, not the command name.

Check =client.ts= line 20 — the =clients= Map key. If the key is the config key (server name), use =Array.from(clients.keys())= for active names instead of =getActiveClients().map(c => c.name)=.

If the Map key is something else (e.g., resolved command path), an additional mapping step is needed. Inspect and adapt accordingly.
