**Intention & Purpose**
When a user has logged in via OAuth (e.g., `/login anthropic`) and the OAuth token can no longer be refreshed, `getApiKey()` silently falls back to the `.env` `ANTHROPIC_API_KEY` instead of returning `undefined`. This masks the OAuth session expiry and uses a potentially stale or low-credit key. The user sees errors like "credit balance too low" from the .env key rather than being prompted to re-login.

**Context & Narrative**
The `getApiKey()` method in `AuthStorage` (auth-storage.ts:1981-2005) has this priority chain:
1. Runtime override (CLI --api-key)
2. Stored api_key credential
3. OAuth token (refreshed if expired)
4. Environment variable (.env)
5. Custom resolver (models.json)

When the user runs `/login anthropic`, credentials are stored as `type: "oauth"` (line 972). Step 2 is always skipped (no `api_key` type). Step 3 attempts OAuth resolution — if the token is expired and refresh fails (e.g., network error, revoked token), `#resolveOAuthApiKey` returns `undefined`. The code then falls through to step 4 and picks up `ANTHROPIC_API_KEY` from `.env`.

The user never sees that their OAuth session expired. They get cryptic errors from the .env key instead.

**Scope**
In scope:
- `packages/ai/src/auth-storage.ts` `getApiKey()` method (lines 1994-2001): After OAuth returns undefined, check if the provider has any OAuth credentials. If yes, return undefined immediately (skip .env fallback)
- `packages/ai/test/auth-storage-anthropic-invalid-token.test.ts`: Add test verifying .env is NOT used as fallback when OAuth credentials exist but fail

Out of scope:
- Changing how OAuth tokens are refreshed
- Changing how `/login` stores credentials
- Adding a warning log (returning undefined already triggers the existing "No API key" error path in sdk.ts:1658)
- Changes to `peekApiKey` or `getCredentialSync` — those have different use cases and keeping .env fallback there is acceptable for model discovery

**Existing Patterns**
- `#getCredentialsForProvider(provider)` returns all stored credentials for a provider
- `hasOAuth(provider)` at line 700-701: `this.#getCredentialsForProvider(provider).some(credential => credential.type === "oauth")`
- Test pattern in `packages/ai/test/auth-storage-anthropic-invalid-token.test.ts`: creates temp DB, instantiates `AuthStorage`, uses `vi.spyOn` for mocking
- Error message in sdk.ts line 1658: `throw new Error(`No API key found for provider "${provider}"`);`

**Tests**
File: `packages/ai/test/auth-storage-anthropic-invalid-token.test.ts`
- Test: When OAuth credentials exist for a provider and refresh fails, `getApiKey()` does NOT fall back to the environment variable
- Test: When OAuth credentials exist and are valid, `getApiKey()` still returns the OAuth token (no regression)
- Test: When NO credentials exist for a provider (neither OAuth nor api_key), `getApiKey()` still falls back to environment variable (existing behavior preserved for env-only users)

**Implementation**
1. **Write failing test** (TDD): Add the test scenarios above to the existing test file
2. **Add OAuth credential check in `getApiKey`**: After line 1997 (`return oauthKey;` returns undefined), add:
   ```typescript
   // If the provider has OAuth credentials that failed to resolve, don't fall back to env.
   // The user explicitly logged in — they should re-login rather than silently using a stale .env key.
   if (this.#getCredentialsForProvider(provider).some(c => c.type === "oauth")) {
       return undefined;
   }
   ```
   This goes BEFORE the `// Fall back to environment variable` comment at line 1999.
3. **Verify tests pass**: Run `bun test packages/ai/test/auth-storage-anthropic-invalid-token.test.ts`
4. **Run full test suite**: `bun run --workspaces --if-present --parallel test`

**Edge Cases**
- Provider has BOTH api_key and OAuth credentials: api_key wins at step 2, OAuth step never reached → no change
- Provider has OAuth credentials but user set `--api-key` runtime override: runtime override wins at step 1 → no change
- Provider has NO credentials at all (env-only user): still falls back to .env → existing behavior preserved
- Multiple OAuth credentials for same provider: all must be unresolvable for the check to trigger. If any resolves, it's returned normally

**Acceptance Criteria**
- User who `/login anthropic` and has `ANTHROPIC_API_KEY` in .env gets "No API key found for provider" error when OAuth refresh fails (not "credit balance too low" from the .env key)
- User with NO stored credentials and only .env still works (env fallback preserved)
- Existing auth-storage tests pass
- `bun run --parallel check:ts check:rs` passes
- `bun run --workspaces --if-present --parallel test` passes
