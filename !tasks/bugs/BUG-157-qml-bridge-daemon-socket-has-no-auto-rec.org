When the daemon socket closes unexpectedly, ~QmlProcess~ sets ~#socket = null~ and logs a warning but makes no attempt to reconnect. In-flight ~waitForEvent~ calls hang until their 10-minute timeout. The canvas event loop catches the resulting error silently and terminates — windows become unreachable.

* Scope
** In scope
- ~protocol.ts~: Add ~socket_disconnected~ to ~BridgeEvent~ union
- ~qml-process.ts~: Synthetic event dispatch on socket close, auto-reconnect with backoff, ~#connectingPromise~ concurrency guard
- ~qml-bridge.ts~: Handle ~socket_disconnected~ (route before window lookup), wake ~waitForEvent~, trigger reconnect
- ~canvas.ts~: Event loop retry on reconnect, max-retry guard
- Tests for all TS changes
** Out of scope
- Heartbeat protocol type + filtering (FEAT-315)
- C++ daemon changes (BUG-156)
- Spawn lock (BUG-158)
- ~ping~ BridgeCommand (removed — no consumer, dead protocol per GAP-08)

* Problem
- ~qml-process.ts~ line 244-249: socket ~close~ handler only nulls the socket. No synthetic event dispatched to listeners. No reconnect attempt.
- ~qml-bridge.ts~ ~waitForEvent~: listener waits for ~event~ or ~closed~ types. Socket death doesn't produce either — the promise hangs until the 600s timeout.
- ~qml-bridge.ts~ ~#handleEvent~: routes events through window lookup (~this.#windows.get(event.id)~). A ~socket_disconnected~ event with system ID would fail the window lookup and be silently dropped. Must handle BEFORE the window lookup, same layer as stderr/state/hotkey checks (GAP-02).
- Canvas tool event loop (~canvas.ts~ line 466): catches the eventual error and terminates silently. No recovery path.
- ~qml-process.ts~ ~ensure()~: no async lock — multiple concurrent callers can race into ~#connectSocket~ or ~#spawnDaemon~ simultaneously (GAP-06).

* Edge Cases
- *Concurrent ensure() during reconnect*: ~#connectingPromise~ serializes all callers. Second caller gets the same promise.
- *Auto-reconnect during dispose*: ~#stopping~ flag prevents reconnect after intentional shutdown.
- *Rapid disconnect-reconnect*: socket_disconnected fires, auto-reconnect starts, new connection established, state event arrives, QmlBridge rebuilds window map. If another disconnect happens during reconnect, the backoff timer is reset.
- *Daemon truly dead*: after 5 reconnect attempts fail, ~#autoReconnect~ gives up. ~ensure()~ on next tool call tries ~#spawnDaemon~. Canvas event loop breaks after 3 retries.
- *In-flight waitFor during disconnect*: ~waitFor~ (not ~waitForEvent~) callers (e.g., ~launch~, ~close~, ~screenshot~) have a 10s timeout. They'll fail and propagate the error to the tool call. The tool can retry.
- *Event loop re-entry after reconnect*: The canvas event loop's ~while (!signal.aborted)~ naturally re-enters ~waitForEvent~ after processing the disconnect event. ~getBridge()~ calls ~ensure()~ which either returns the auto-reconnected socket or triggers a new connection.

* Acceptance Criteria
- Socket closes during idle session → auto-reconnect within 5s, event loops resume transparently.
- ~waitForEvent~ callers resolve promptly on socket death (not hang > 5s).
- Windows are NOT marked as closed during disconnect — they survive for reconnect.
- All existing tests pass: ~bun test packages/qml/test/reconnect.test.ts~
- New tests cover: socket_disconnected dispatch, auto-reconnect, waitForEvent wake, full cycle, concurrent ensure, canvas loop recovery.
- ~bun check:ts~ passes with new protocol types.
