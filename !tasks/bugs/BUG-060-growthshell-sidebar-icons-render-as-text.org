Workspace =icon= fields contain semantic names ("home", "search", "lightbulb", "edit", "chart", "rocket") but =GrowthShell.qml= line 70 renders them as =Label { text: modelData.icon }= — plain text, no icon font, no mapping.

* Root Cause

The workspace definitions in =manifest.ts= use semantic icon names. The default =shell.qml= avoids this problem by using literal Unicode symbols ("●", "■"). The Growth shell adopted semantic names but never implemented a resolver.

There is no icon font loaded (Material Icons, etc.) and no name→Unicode mapping function.

* Fix

Add a JS icon resolver function in =GrowthShell.qml=:

#+begin_src javascript
function iconFor(name) {
    var icons = {
        "home": "🏠", "search": "🔍", "lightbulb": "💡",
        "edit": "✏️", "chart": "📊", "rocket": "🚀",
        "briefcase": "💼", "kanban": "📋"
    };
    return icons[name] || "●";
}
#+end_src

Then change the icon label from:
=text: modelData.icon || ""=
to:
=text: iconFor(modelData.icon)=

Alternatively, change the manifest workspace definitions to use Unicode directly — simpler, no runtime mapping needed. The =ComponentPalette.qml= already uses emoji in this codebase, so it's an established pattern.
