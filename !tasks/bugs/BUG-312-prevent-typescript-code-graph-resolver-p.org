What happened?

* Scope

In:
- Stop TypeScript import resolution inside =pi-code-graph= from aborting the host process when =oxc_resolver= panics.
- Upgrade the resolver dependency from the current =1.12= line to the current stable =11.x= line in =crates/pi-code-graph/Cargo.toml= and refresh =Cargo.lock= accordingly.
- Add a local panic guard around =TypeScriptImportResolver.resolve()= so the code graph degrades to the existing fallback / unresolved path behavior instead of crossing the N-API worker boundary and killing Spell.
- Add regression coverage proving both the direct resolver path and the builder path no longer abort on resolver failure.

Out:
- Broad dependency refreshes outside =oxc_resolver= and any unrelated =Cargo.toml= cleanup.
- Redesigning the TypeScript import-resolution contract; resolution misses should remain non-fatal.
- UI/TUI wording changes unless the runtime contract forces a new surfaced error.
- Generic panic handling across every graph path; focus on the TypeScript resolver boundary reproduced by the user crash.

Rationale:
- Repo evidence shows =crates/pi-code-graph/Cargo.toml= still pins =oxc_resolver = "1.12"=.
- Repo evidence shows =crates/pi-code-graph/src/language/typescript.rs= calls =resolver.resolve(from_dir, request.specifier)= directly inside =TypeScriptImportResolver.resolve()=.
- Repo evidence shows =crates/pi-code-graph/src/indexer.rs= calls each language resolver during =CodeGraphBuilder.build()=, and =crates/pi-natives/src/code_graph.rs= routes runtime graph commands through that builder in Spell.
- Upstream evidence shows the path-prefix assertion class was fixed after 1.12, but the local runtime must still not let third-party panics abort the host process.

* Existing Patterns

- =crates/pi-code-graph/src/language/typescript.rs=
  - =TypeScriptImportResolver.resolve()= already treats resolver failures as non-fatal via =.ok()= and falls back through =fallback_relative_path(...)=.
  - Preserve that contract: a defensive panic guard must degrade into the same fallback / =None= path, not invent a second error surface.
- =crates/pi-code-graph/src/indexer.rs=
  - =CodeGraphBuilder.build()= canonicalizes the workspace root before walking files and delegates import resolution through =registered.resolver.resolve(ResolveRequest { ... })=.
  - Keep the fix at the resolver boundary so every code-graph caller benefits without parallel call-site patches.
- =crates/pi-embedding-worker/src/main.rs=
  - =panic::catch_unwind(AssertUnwindSafe(...))= is an existing repo precedent for containing native-side panics and surfacing a truthful degraded result instead of process termination.
  - Reuse this containment style rather than inventing a new panic-handling convention.
- =crates/pi-natives/src/code_graph.rs=
  - =execute_code_graph()= runs on a blocking N-API worker thread; any uncaught panic below this layer aborts the Spell process.
  - The resolver fix must therefore be complete before the panic could cross the worker boundary.
