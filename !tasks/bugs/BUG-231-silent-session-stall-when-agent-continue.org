* Problem
When the Anthropic API call following a tool result silently fails to stream any
events, the session hangs permanently. No error, no timeout, no log entry, no recovery.

Confirmed in two sessions with transcript evidence:

1. Session =14b79dc662a38caa= (hotelcomm): 90,635 tokens context on claude-opus-4-6.
   Tool results returned at 10:40:57 (grep, code outline x2, find). 25 min hang.

2. Session =14b79aec8fda64f1= (spell): 210,160 tokens context on claude-opus-4-6.
   =code outline= returned in 2ms at 11:47:41.015. Transcript ends there — 18 min hang,
   zero log activity from the PID during that time.

In both cases the tool itself worked fine (returned instantly). The hang occurs in
=streamAssistantResponse()= in the agent loop — the =for await= on the Anthropic SSE
stream blocks forever because the API connection stalls without sending any events.

The correlation with =code outline= / =code edit= is incidental — these tools are used
deep into exploration sessions when context is already enormous (90K-210K tokens). The
real trigger is the large context causing the API to stall during stream establishment.

** Root Cause

=packages/ai/src/providers/anthropic.ts= line ~650:

#+begin_src typescript
for await (const event of anthropicStream) { ... }
#+end_src

This bare =for await= has **no idle timeout**. Compare with every OpenAI-family provider,
which all wrap their streams in =iterateWithIdleTimeout= (45s default):

#+begin_src typescript
for await (const chunk of iterateWithIdleTimeout(openaiStream, {
    idleTimeoutMs: getOpenAIStreamIdleTimeoutMs(),
    errorMessage: "OpenAI responses stream stalled while waiting for the next event",
    onIdle: () => requestAbortController.abort(),
})) { ... }
#+end_src

When the Anthropic API opens a connection but stops sending events (transient network
issue, API overload on large context, connection silently dropped), the =for await=
blocks forever. The agent loop never progresses, no =agent_end= event fires.

** Secondary Issue: Silent Error Swallowing

~#scheduleAgentContinue~ (agent-session.ts line 1037-1041) and ~#trackPostPromptTask~
(line 988) also swallow errors silently. Defense-in-depth — the primary fix is the
missing timeout, but silent error swallowing in other paths should also be fixed.

* Edge Cases

- =PI_ANTHROPIC_STREAM_IDLE_TIMEOUT_MS=0= disables the timeout (matches OpenAI pattern)
- Anthropic's own SDK may have internal keepalive pings that reset the idle timer —
  this is fine, the timeout only fires when NO events arrive
- The timeout error message should be caught by the existing retry mechanism (it matches
  =stream stall= in =isRetryableErrorMessage=, line ~4835 of agent-session.ts)
- On abort, the SDK should clean up its HTTP connection — verify no resource leak

describe("Anthropic stream idle timeout", () => {
    it("throws after idle timeout when stream stalls", async () => {
        // Create a mock async iterable that never yields

            await new Promise(() => {}); // never resolves

            idleTimeoutMs: 100, // short for testing
            errorMessage: "Anthropic messages stream stalled",
        });

        await expect(async () => {
            for await (const _event of wrapped) {
                // should never reach here
            }
        }).toThrow("Anthropic messages stream stalled");
    });

    it("passes through events normally when stream is active", async () => {
        async function* activeStream() {
            yield { type: "event1" };
            yield { type: "event2" };

        const events = [];

            idleTimeoutMs: 1000,
            errorMessage: "stalled",
        })) {
            events.push(event);
        }

        expect(events).toHaveLength(2);
    });
