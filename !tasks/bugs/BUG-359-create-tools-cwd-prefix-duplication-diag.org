When the BUG-358 guard fires in =packages/coding-agent/src/tools/create.ts=, the returned =AgentToolResult= has =isError: undefined=. The diagnostic text is present, but the model receives it as informational content, not as a failure signal.

=edit.ts= already sets =result.isError = true= after =toolResult(...).done()=. =create.ts= does not.

* Why it matters

Models batch-process tool results. Many use =isError= as the primary "should I retry/correct?" signal. Without it, the diagnostic may be skimmed and the agent moves on, never re-issuing the call.

* Fix
