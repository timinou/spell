* Problem

In =crates/pi-code-engine/src/navigate.rs= line 65-66, =node_at()= allocates the entire rope to a String (=buffer.source()=) solely to call =.lines().count()= for line validation:

#+begin_src rust
let source = buffer.source();  // allocates entire file as String
let total_lines = source.lines().count() as u32;
#+end_src

This is wasteful: the String is not used for anything else (the byte offset comes from =buffer.rope().line_to_byte_idx()= on the next line).

Additionally, =str::lines().count()= and =rope.len_lines()= can disagree by 1 for files ending with a trailing newline:
- =str::lines()= on ="a
b
"= yields =["a", "b"]= -> count 2
- =rope.len_lines(LF_CR)= on ="a
b
"= returns 3

=buffer.info().line_count= uses =rope.len_lines()=, so navigate and info disagree on the total line count for such files. This is a latent off-by-one that would only manifest as an unreachable-last-line bug for files ending with a newline.

* Fix

** File: =crates/pi-code-engine/src/navigate.rs=

Replace the allocation-based count with a rope-based count. Since =rope.len_lines()= includes a trailing empty "line" for files ending with =
=, subtract 1 when the rope ends with a line terminator to maintain correct 1-indexed semantics:

#+begin_src rust
fn node_at(buffer: &CodeBuffer, line: u32, column: Option<u32>) -> Result<Node<'_>> {
    let rope = buffer.rope();
    let raw_lines = rope.len_lines(ropey::LineType::LF_CR);
    // Ropey counts the trailing empty segment after a final newline as a line;
    // adjust so total_lines matches the number of content lines (1-indexed).
    let total_lines = if raw_lines > 1 {
        let last = rope.byte(rope.len_bytes() - 1);
        if last == b'
' || last == b'\r' {
            raw_lines - 1
        } else {
            raw_lines
        }
    } else {
        raw_lines
    } as u32;
    if line == 0 || line > total_lines {
        return Err(CodeEngineError::Buffer("line out of range".into()));
    }
    let byte = rope
        .line_to_byte_idx((line - 1) as usize, ropey::LineType::LF_CR)
        + column.unwrap_or(0) as usize;
    // ... rest unchanged
}
#+end_src

#[test]
fn test_navigate_node_at_last_line_trailing_newline() {
    // hello.ts ends with a newline; verify last content line is reachable
    let buf = buffer("hello.ts", "typescript");
    let p = profile("typescript");
    let source = buf.source();
    let last_content_line = source.lines().count() as u32;
    // Navigate to last content line should succeed
    assert!(navigate(&buf, &p, NavigateAction::NodeAt, last_content_line, Some(1), None).is_ok());
    // One past last content line should fail
    assert!(navigate(&buf, &p, NavigateAction::NodeAt, last_content_line + 1, Some(1), None).is_err());
}
