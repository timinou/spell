1. **What:** Quick Fix captures screenshots, but the backend discards them.
   **Where:** `.spell/extensions/phoenix-inspector/inspector.qml` in `dispatchQuickFix()` and `.spell/extensions/phoenix-inspector/index.ts` in `runQuickFixTask()`.

2. **What:** The new quick-fix backend depends on a non-contract `pi.pi.runSubprocess` API.
   **Where:** `.spell/extensions/phoenix-inspector/index.ts` in `runQuickFixTask()` / task-tier handling.
   **Why:** The focused tests pass because the harness stubs this method, but a real launch can fail if the host does not inject that exact runtime hook. That makes Quick Fix brittle outside the test harness.
   **Effort:** medium

3. **What:** Quick-fix error handling is not regression-tested.
   **Where:** `.spell/extensions/phoenix-inspector/index.test.ts`, the new `dispatches canonical quick-fix tasks...` case only covers success.
   **Why:** A failed task result could regress to stale or incorrect UI messaging without any test catching it.
   **Effort:** small

* Context
The quick-fix dispatch test added in PLAN-099 covers only the success path (~exitCode === 0~, not aborted). The error branch (~exitCode !== 0~ or ~runSubprocess~ throws) and the agent handoff error branch (no active model) have no regression coverage. A change to the error reply shape would regress silently.

The test harness already supports ~piOverrides.runSubprocess~ for injecting custom behavior and ~ctxOverrides~ for removing the model, so adding error-path coverage is low-friction.

* Implementation
** Test: task failure sends ~task_result~ with ~ok: false~
   Use ~piOverrides.runSubprocess~ to return ~{ exitCode: 1, error: "Build failed", stderr: "compilation error", ... }~. Assert the bridge reply is ~{ action: "task_result", ok: false, error: "Build failed" }~.

** Test: task dispatch exception sends ~task_result~ with ~ok: false~
   Use ~piOverrides.runSubprocess~ that throws ~new Error("Runtime unavailable")~. Assert the bridge reply is ~{ action: "task_result", ok: false, error: "Runtime unavailable" }~ and a UI notification is emitted.

** Test: agent handoff without a model sends ~agent_handoff_result~ with ~ok: false~
   Use ~ctxOverrides: { model: undefined }~. Emit an agent-tier payload. Assert the bridge reply is ~{ action: "agent_handoff_result", ok: false, error: /no active model/i }~.
