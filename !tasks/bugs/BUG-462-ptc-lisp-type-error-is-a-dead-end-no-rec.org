* Symptom

Calling a real builtin with wrong-typed args produces a type_error that names
the types but NOT what to use instead — a dead end. Contrast the unbound_var
path, which always suggests ("Did you mean: …").

Live repro (execute tool):
#+begin_src
(contains? "hello" "ell")
;; → PtcRuntime error (type_error): contains?: invalid argument types: string, string
#+end_src

`contains?` is collections-only (map/set/list); the string analogue is
`(includes? s sub)` or `(index-of s sub)` (>= 0). The error doesn't say so, so
the caller is stuck. This is the residual half of the execute-ergonomics
friction class (the other half — discoverability — was fixed by teaching
apropos/doc in FEAT-812's execute.md pass).

* Root cause

`beam/ptc_runner-vendored/lib/ptc_runner/lisp/eval/helpers.ex`:
- `type_error_for_args/2` tries `specific_type_error/2` (an EXTENSIBLE
  pattern-match table of helpful messages — e.g. sort-by arg-order, update-vals
  thread-direction, get/get-in collection-first) and falls back to
  `generic_type_error/2` (line 109) which only joins `describe_type` of each
  arg → "invalid argument types: string, string". No suggestion.

The affordance to fix this ALREADY EXISTS: `specific_type_error/2` is the right
home. The fix is additive — a new clause, not a new mechanism.

* Fix

Add `specific_type_error/2` clauses for the high-traffic string-vs-collection
collisions, pointing at the right builtin:
- `(contains? <string> <string>)` → "contains? is for collections (map/set/list).
  For strings use (includes? s sub) or (index-of s sub) (>= 0 when present)."
- consider `(conj <string> …)`, and any other collection fn called on a string
  where a string analogue exists.

Keep it curated (a few real collisions), not a blanket type-inference engine —
mirrors how the existing specific clauses are hand-picked for common mistakes.

Also: reinforce in `packages/coding-agent/src/prompts/tools/execute.md` the
concrete `(get (tool/find …) "text")` → nil trap (tool/find is a LIST; use
`(get (first …) "text")` or `get!`), since that is the sibling discoverability
nudge.

* Acceptance

- `(contains? "s" "sub")` error text names `includes?`/`index-of`.
- New ExUnit test in the vendored runner (or ptc_runtime) asserting the message.
- Full ptc_runtime suite stays green.
- Build/test prefixed `NK_TARGET_DIAMOND=0` (numkong/GCC16 ISA workaround).
