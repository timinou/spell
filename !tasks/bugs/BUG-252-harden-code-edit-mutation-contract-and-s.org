* Existing Patterns
- `CodeTool.execute(...)` (`packages/coding-agent/src/tools/code.ts`) currently validates create payloads, executes native buffer ops, formats, then saves.
- `normalizeCodeBufferSuccess(...)` and `formatCodeToolContent(...)` (`packages/coding-agent/src/tools/code-result.ts`) determine user-facing `Edited/Created` + `Changes: +N -M` text.
- Hashline/patch summaries are compacted via `buildCompactHashlineDiffPreview(...)` in `packages/coding-agent/src/patch/hashline.ts` and consumed by result rendering.
- Current tests in `packages/coding-agent/test/tools/code.test.ts` already assert create validation and save behavior and should remain the canonical contract suite.

* Tests
User workflows to lock first as failing tests:
1. Non-idempotent mutating edit returns no semantic diff -> tool returns hard error, not success text.
2. Explicit idempotent mutating edit returns no semantic diff -> tool succeeds with explicit no-op/applied metadata.
3. Mutating edit with real diff still succeeds and keeps formatting/save behavior.
4. Stale buffer detected before mutation -> deterministic stale-buffer error with corrective next steps.
5. In-sync buffer path remains unblocked.
6. Cross-tool transcript fixture validates classification path (`Edited` + `Changes: +0 -0`) is treated as failure for non-idempotent mutation.

* Edge Cases
- Formatting-only churn that nets zero semantic change still follows strict no-op contract unless idempotent is explicit.
- Idempotent override is per-call only; no global silent bypass.
- Stale-buffer guard must avoid false positives on clean synchronized state.
- Error surfaces must remain truthful (no fabricated symbols/hunks).
