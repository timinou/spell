* Problem

After the KDL settings cutover, =discovery/builtin.ts:786-810= still reads =<cwd>/.spell/agent/config.yml= and feeds it into the =settings= capability. =settings.ts:438= then merges that overlay on top of values read from =spell.kdl=.

∴ Two valid project-config files. Whichever provider runs last in the merge order wins — *not* whichever file the user edited most recently. Users editing =spell.kdl= via =/settings= can have their changes silently shadowed by a stale =config.yml=.

Remove the YAML overlay branch from the =settings= capability provider. KDL-only inputs for Spell-owned config.
