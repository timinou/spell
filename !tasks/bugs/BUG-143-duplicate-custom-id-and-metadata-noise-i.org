* Problem
=renderItemOrg= in =packages/coding-agent/src/tools/org-format.ts= always emits
=:CUSTOM_ID: ${item.id}= as the first property, then iterates =item.properties=
which ALSO contains CUSTOM_ID (the TS reader puts it there from frontmatter).
The filter only excludes "TAGS", so CUSTOM_ID appears twice in every rendered item.

Additionally, SESSION_ID and TRANSCRIPT_PATH from frontmatter appear as properties
in the rendered output, wasting LLM context tokens on internal metadata.

** Root Cause
Line 41: =.filter(([k]) => k !== "TAGS")= should also exclude CUSTOM_ID and
metadata keys (SESSION_ID, TRANSCRIPT_PATH).

* Implementation

*** ITEM Write test proving CUSTOM_ID deduplication
:PROPERTIES:
:EFFORT: 10m
:END:

with =properties: { CUSTOM_ID: "PROJ-042-auth", EFFORT: "2h" }= and asserts that
the rendered output contains exactly ONE =:CUSTOM_ID:= line, not two.
Also add a test with SESSION_ID/TRANSCRIPT_PATH in properties and assert they are
excluded from the rendered output.

*** ITEM Fix renderItemOrg property filtering
:PROPERTIES:
:EFFORT: 10m
:END:
