* Scope
** In scope
- Make the manifest parser handle ~param-json~ child nodes that carry structured JSON values.
- Make the serializer emit ~param-json~ for object-typed parameter values instead of stringifying them into scalar ~param~ nodes.
- Alternatively, remove ~"json"~ from ~ActionParameterType~ if the contract should not support it yet (simpler, but changes the public type).
** Out of scope
- Complex nested KDL structures. JSON params are serialized as single JSON string arguments.
** Decision
The recommended approach is to support ~param-json~ in the parser and serializer so the type contract is honored. The parser reads ~param-json "name" "{ ... }"~ and calls ~JSON.parse~. The serializer emits ~param-json "name" "{ ... }"~ via ~JSON.stringify~. This preserves round-trip fidelity.
