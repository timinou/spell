* Problem
The code tool accepts any file path and passes it to the native NAPI engine. When the file has an unsupported extension (e.g. =.md=, =.json=, =.yaml=, =.toml=, =.txt=), the Rust engine returns =LanguageNotFound=. The error propagates correctly but:
1. Wastes a round-trip into native code for a predictable failure
2. The error message ("language not found for path: ...") gives the model no guidance on what to do instead
3. The model often retries or stalls instead of falling back to the =read= tool

* Design Decisions
1. Add a =SUPPORTED_EXTENSIONS= constant in =code.ts= listing all file extensions supported by the native engine: =ts, tsx, js, jsx, mjs, cjs, mts, cts, rs, py, pyi, typ, ex, exs=
2. For file-requiring commands (=outline=, =read=, =navigate=, =edit=, =undo=, =redo=, =diff=, =save=), check the file extension before calling =timedCodeBuffer=
3. Return a structured error via =createCodeToolError= with a message that explicitly tells the model to use the =read= tool instead
4. Commands that don't require a file (=buffers=, =languages=, =list=) and graph commands skip this check
5. The =SUPPORTED_EXTENSIONS= set is the source of truth in TypeScript — if a new language is added to the Rust engine, this set must be updated. This is acceptable because language additions are rare and involve coordinated changes across layers anyway.

* Implementation

** Modify =packages/coding-agent/src/tools/code.ts=

*** Add constant after existing =MUTATING_COMMANDS= set

#+begin_src typescript
const SUPPORTED_EXTENSIONS = new Set([
    "ts", "tsx", "js", "jsx", "mjs", "cjs", "mts", "cts",
    "rs",
    "py", "pyi",
    "typ",
    "ex", "exs",
]);

const FILE_COMMANDS = new Set([
    "outline", "read", "navigate", "edit", "undo", "redo", "diff", "save", "open", "close",
]);
#+end_src

*** Add guard in =execute()= after file resolution, before NAPI call

After the line =if (params.file) options.file = resolveFile(params.file);= and after all other option assignments, before =const result = timedCodeBuffer(options);=, add:

#+begin_src typescript
if (FILE_COMMANDS.has(nativeCommand) && options.file) {
    const ext = path.extname(options.file).slice(1).toLowerCase();
    if (ext && !SUPPORTED_EXTENSIONS.has(ext)) {
        const details = createCodeToolError({
            command,
            file: options.file,
            cwd: sessionCwd,
            message: `Unsupported file type .${ext}. Use the read tool for non-code files.`,
        });
        return toolResult(details).text(formatCodeToolContent(details)).done();
    }
}
#+end_src

Note: the check uses =ext && !SUPPORTED_EXTENSIONS.has(ext)= — if there's no extension, let NAPI handle it (extensionless files like =Makefile= are rejected at the Rust level anyway, and the error envelope from BUG-238 will handle it cleanly).
