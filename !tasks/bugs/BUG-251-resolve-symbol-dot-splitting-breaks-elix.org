* Problem

=resolve_symbol()= in =crates/pi-code-engine/src/resolve.rs= (line 40) hardcodes =.= as a Container.member separator with a 2-level maximum:

#+begin_src rust
let parts: Vec<&str> = symbol.split('.').collect();
if parts.is_empty() || parts.len() > 2 {
    return Err(...)  // "at most 2 levels"
}
#+end_src

Elixir module names are naturally dotted (=MyApp.Greeter=, =Agentmaker.AgentConfig.PipelineMaterializer=). This makes it impossible to:
1. Target a module: =symbol: "MyApp.Greeter"= splits into =["MyApp", "Greeter"]= → interpreted as Container.member, fails because no top-level =MyApp=
2. Target a member function: =symbol: "MyApp.Greeter.greet"= → 3 parts → rejected by 2-level limit
3. Target by short name: =symbol: "PipelineMaterializer"= → no top-level match (stored name is full dotted path)

Side effect: deeply nested markdown sections (=h1.h2.h3.h4=) are also blocked by the 2-level limit (documented as a known limitation in FEAT-520).

Agents that encounter this fall back from =code edit= to =sed=, bypassing safety.

Replace the current splitting logic with:

#+begin_src rust
pub fn resolve_symbol(
    buffer: &CodeBuffer,
    profile: &LanguageProfile,
    symbol: &str,
) -> Result<ResolvedSymbol> {
    let source = buffer.source();
    let root = buffer.tree().root_node();

    // Step 1: Try full string as a top-level declaration name.
    // This handles Elixir dotted module names (MyApp.Greeter) and simple names.
    let mut cursor = root.walk();
    let mut top_matches: Vec<Node<'_>> = Vec::new();
    for child in root.named_children(&mut cursor) {
        if let Some(node) = match_declaration(child, profile, symbol, &source) {
            top_matches.push(node);
        }
    }

    if top_matches.len() == 1 {
        return Ok(build_resolved(top_matches[0], profile, &source));
    }
    if top_matches.len() > 1 {
        let lines: Vec<String> = top_matches
            .iter()
            .map(|n| (n.start_position().row + 1).to_string())
            .collect();
        return Err(CodeEngineError::Edit(format!(
            "Ambiguous symbol '{}': found at lines {}",
            symbol,
            lines.join(", ")
        )));
    }

    // Step 2: If the full string wasn't found and contains dots,
    // split at the last dot: prefix is the container, suffix is the member.
    if let Some(last_dot) = symbol.rfind('.') {
        let container_name = &symbol[..last_dot];
        let member_name = &symbol[last_dot + 1..];
        if !member_name.is_empty() {
            // Find container as top-level
            let mut cursor = root.walk();
            let mut container_matches: Vec<Node<'_>> = Vec::new();
            for child in root.named_children(&mut cursor) {
                if let Some(node) = match_declaration(child, profile, container_name, &source) {
                    container_matches.push(node);
                }
            }
            if container_matches.len() == 1 {
                return resolve_member(
                    container_matches[0], profile, &source,
                    container_name, member_name,
                );
            }
            if container_matches.len() > 1 {
                let lines: Vec<String> = container_matches
                    .iter()
                    .map(|n| (n.start_position().row + 1).to_string())
                    .collect();
                return Err(CodeEngineError::Edit(format!(
                    "Ambiguous symbol '{}': found at lines {}",
                    container_name,
                    lines.join(", ")
                )));
            }
        }
    }

    // Step 3: Nothing matched — report error with available names
    let available = collect_top_level_names(root, profile, &source);
    Err(CodeEngineError::Edit(format!(
        "Symbol '{}' not found. Available: [{}]",
        symbol,
        available.join(", ")
    )))
}
#+end_src

Key changes from current code:
1. Remove =symbol.split('.')= and the =parts.len() > 2= guard
2. Try full string match first (handles dotted Elixir names)
3. Use =rfind('.')= for last-dot split (handles =A.B.C.D= → container =A.B.C=, member =D=)
4. Same =match_declaration= / =build_resolved= / =resolve_member= helpers — no changes needed

This is backwards compatible because for TypeScript =Foo.bar=:
- Step 1 tries =Foo.bar= as top-level → not found (no declaration named =Foo.bar=)
- Step 2 splits at last dot: container =Foo=, member =bar= → works identically to current behavior

* Edge Cases

1. =MyApp.Greeter= (full dotted module name as top-level): Step 1 matches directly
2. =MyApp.Greeter.greet= (dotted container + member): Step 1 fails, Step 2 splits at last dot → =MyApp.Greeter= + =greet=
3. =Foo.bar= (TypeScript class.method): Step 1 fails (no top-level =Foo.bar=), Step 2 splits → =Foo= + =bar= (identical to current)
4. =greet= (simple non-dotted name): Step 1 matches (no dots involved)
5. =NonExistent.thing= (container not found): Step 1 fails, Step 2 fails → error with available names
6. =MyApp.Greeter.nonexistent= (container found, member not): Step 2 → =resolve_member= → error "not found in 'MyApp.Greeter'"
7. Name collision: both a module =Foo.bar= AND a class =Foo= with member =bar= — Step 1 finds =Foo.bar= module first. This is correct: prefer the more-specific full-string match.
8. Deeply nested markdown =A.B.C= (3+ levels): Step 1 tries =A.B.C= (not a section name), Step 2: =A.B= container + =C= member → works if =A.B= is a valid dotted section name via class_like nesting
9. Empty member (trailing dot =MyApp.=): =rfind= finds dot, member is empty → skip step 2, fall to error
10. No dots: Step 1 handles it (current single-name behavior)
