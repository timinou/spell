* Problem
The current line-target path is split across multiple implementations:
- =crates/pi-code-engine/src/navigate.rs= reports raw parse nodes from =node_at=
- =crates/pi-code-engine/src/edit/replace.rs= resolves edit targets with separate ancestor/unwrap logic
- =crates/pi-natives/src/code_buffer.rs= duplicates a second fallback resolver for line-based edit operations
This split is why Typst can report raw =let= / =set= in navigation while edit only succeeds when callers guess =code=. It also explains the comment-line bug: =navigate::node_at= climbs away from extra nodes, so a comment can degrade to =source_file=.

* Target
Files to create/modify:
- =crates/pi-code-engine/src/navigate.rs=
- =crates/pi-code-engine/src/edit/replace.rs=
- =crates/pi-code-engine/src/edit/mod.rs= and/or a new shared helper module under =crates/pi-code-engine/src/edit/=
- =crates/pi-natives/src/code_buffer.rs=

If a cleaner shared helper belongs outside =src/edit/=, create it there instead, but keep one canonical resolver.

* Change
1. Introduce one shared line-target resolver in Rust that returns both:
   - the raw node found at the requested line/column
   - the canonical editable scope/container for that location
2. Use that shared resolver from both navigation and line-target edit paths. Do not keep parallel Typst-specific ancestor walks in =replace.rs= and =code_buffer.rs=.
3. Preserve raw navigation truth:
   - =nodeType= remains the concrete parse node kind
   - add additive editable metadata named =editableScopeNodeType=
   - add matching editable scope range metadata (line + end line at minimum) so callers can round-trip the exact container they should edit
4. Comment handling:
   - comment lines must resolve to comment nodes instead of collapsing to =source_file=
   - comments are editable in this design, so their editable scope should remain the comment node unless a larger shared editable container is the true owner
5. Typst behavior:
   - line-target edit operations must accept concrete Typst raw kinds reported by navigation (=set=, =let=, multiline helper =let=)
   - callers may also use the canonical editable scope kind returned by navigation, and both forms must succeed for the same location
6. Non-Typst behavior:
   - preserve existing raw =nodeType= behavior for current languages
   - the new editable-scope metadata is additive only; do not silently rewrite old fields or normalize them in the TypeScript wrapper
7. Native bridge:
   - =crates/pi-natives/src/code_buffer.rs= must serialize the new editable-scope metadata so tool callers see it without wrapper-side special casing
   - line-target pseudo-resolution in the native bridge must use the shared resolver instead of its current hand-rolled parent walk

* Design Constraints
- Fix the invariant where it breaks: in the Rust engine/native bridge, not in =packages/coding-agent/src/tools/code.ts=.
- No Typst-only shim in the TS layer.
- No compatibility alias that leaves two different target-resolution systems reachable.
- The implementation item depends on the test-first regression item and should satisfy it directly.
