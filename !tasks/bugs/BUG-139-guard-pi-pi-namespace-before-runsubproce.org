The quick-fix runtime guard now covers a missing pi.pi namespace as well as a missing runSubprocess method.

* Initial Message

Implement these audit recommendations from org://AUD-030-audit-implementation:

- **What:** `runQuickFixTask()` still dereferences `pi.pi` before the runtime guard, so a missing `pi.pi` namespace throws a raw TypeError instead of the intended descriptive failure.
  **Where:** `.spell/extensions/phoenix-inspector/index.ts`, `runQuickFixTask()` around the `const runtime = pi.pi as ...` / `runtime.runSubprocess` guard.
  **Why:** The hardening only covers a missing `runSubprocess` method, not a missing `pi.pi` object. If the host runtime shape regresses further, Quick Fix will fail cryptically again and bypass the user-facing error path.
  **Effort:** small

* Problem
~runQuickFixTask()~ in ~index.ts~ line 213-214 does:
#+begin_src typescript
const runtime = pi.pi as QmlRuntime & { runSubprocess?: ... };
if (typeof runtime.runSubprocess !== "function") {
#+end_src

The type cast on line 213 is safe (just aliasing), but line 214 dereferences ~runtime.runSubprocess~. If ~pi.pi~ is ~undefined~ or ~null~, this throws a raw ~TypeError: Cannot read properties of undefined (reading 'runSubprocess')~ instead of the descriptive guard message.

~getQmlRuntime(pi)~ validates ~pi.pi~ at extension init, so this only fires if ~pi.pi~ regresses after initialization. Unlikely but the whole point of the guard was to prevent cryptic failures.

* Implementation
** Add null guard to the existing condition
In ~runQuickFixTask()~, change line 214 from:
#+begin_src typescript
if (typeof runtime.runSubprocess !== "function") {
#+end_src
to:
#+begin_src typescript
if (!runtime || typeof runtime.runSubprocess !== "function") {
#+end_src

This makes the guard cover both a missing namespace and a missing method in a single condition. The error message remains the same.

No other callers or downstream code are affected — the function signature, return type, and error shape are unchanged.
