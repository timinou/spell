* Root cause
`packages/coding-agent/src/thinking.ts::toReasoningEffort` maps `ThinkingLevel.Off` to `undefined`. Smol utility code passes that into `completeSimple`:
- `packages/coding-agent/src/utils/intention-summarizer.ts`
- `packages/coding-agent/src/utils/title-generator.ts`

For OpenAI Codex Responses, the provider transform currently does:
- if `options.reasoningEffort !== undefined`, include `body.reasoning`
- else delete `body.reasoning`

For Codex, omitted reasoning means provider default reasoning, not no reasoning. The explicit off state is lost before provider serialization.

* Required behavior
When a caller explicitly configures a role as `:off`, Codex requests must send explicit no-reasoning semantics (`reasoning.effort = "none"`, and no reasoning summary if applicable), instead of omitting the field.

* Acceptance
- Add regression coverage proving smol `:off` utility calls send Codex no-reasoning rather than omit reasoning.
- Existing supported-effort validation must still reject unsupported non-off efforts for Codex.
- Run targeted tests and commit fix.
