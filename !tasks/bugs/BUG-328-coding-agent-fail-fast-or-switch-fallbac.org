* Intention & Purpose
Prevent delegated subagents from sleeping for 30 minutes after provider usage-limit/quota failures. When a subagent hits a usage limit, Spell should first rotate credentials if possible, then switch to a configured fallback model role if possible, and otherwise fail fast for quota/billing-cycle exhaustion instead of blocking the coordinator's =await= for a long hidden sleep.

This directly addresses session =14cc69946fb52683=:
- Root coordinator launched wave-5 child tasks at 19:24 and awaited them.
- Child logs =37-W5ToolKbProofsDock.jsonl= and =38-W5DeleteDeadRuntime.jsonl= recorded Kimi =429 rate_limit_error= around 19:35/19:36.
- Earlier wave-2 logs show the behavior: attempts at ~15:09 then ~15:39, proving the current path sleeps 30m before the next retry.

* Context & Narrative
Current retry path:
- =packages/coding-agent/src/session/agent-session.ts= imports =parseRateLimitReason= and =calculateRateLimitBackoffMs=.
- =AgentSession.#isRetryableErrorMessage= treats =usage limit=, =rate limit=, =429=, and related errors as retryable.
- =AgentSession.#handleRetryableError= increments =#retryAttempt=, computes exponential backoff, and for usage-limit messages calls:
  - =#parseRetryAfterMsFromError(baseErrorMessage) ?? calculateRateLimitBackoffMs(parseRateLimitReason(baseErrorMessage))=.
  - =this.#modelRegistry.authStorage.markUsageLimitReached(...)= to block/rotate credential.
  - If no credential switch occurs and =retryAfterMs > delayMs=, it sleeps =retryAfterMs=.
- =createAgentSession(options)= receives =taskDepth= for subagents but =AgentSession= does not currently store that depth.
- =AgentSession.setModelTemporary(model)= already exists and switches models without persisting settings.
- =AgentSession.resolveRoleModel(role)= / private =#resolveRoleModel= already resolve configured model roles.
- =packages/coding-agent/src/config/model-registry.ts= defines roles =default=, =smol=, =slow=, =task=, =subtask=, etc.

Desired runtime policy:
1. Mark the current provider credential as usage-limited, preserving real retry/reset duration for auth storage.
2. If another credential for the same provider is available, keep current behavior: switch credential and retry immediately.
3. Else, if the current session is a subagent and a configured fallback model role resolves to a different model with an API key, switch to it temporarily and retry immediately.
4. Else, for subagent quota/billing-cycle/unknown exhaustion, fail fast with a clear final error; do not sleep 30m.
5. Else, for subagent transient rate-limit/model-capacity/server retry reasons, cap sleep to a short setting (default 60s).
6. Interactive top-level sessions may keep long sleeps unless the new settings explicitly cap them later; this item is scoped to subagent safety.

* Edge Cases
- A fallback role may be unset; skip silently with debug-level logging only.
- A fallback role may resolve to the same model as the current one; skip to avoid retrying the blocked credential/model pair.
- A fallback role may resolve to a model with no API key; skip and try the next role.
- Credential rotation may succeed for the same provider; in that case do not switch model.
- If a provider sends real =retry-after= for a transient rate limit in a subagent and it exceeds 60s, cap to the configured max.
- If a provider sends real reset time for quota exhaustion, still pass it to =markUsageLimitReached= for credential blocking, but do not sleep it in subagents.
- Abort during any short sleep must preserve existing retry cancellation behavior.
- Do not leak API keys in errors, events, or logs.

* Acceptance Criteria
- No subagent can sleep for 30 minutes solely because of a usage-limit/quota error.
- Kimi-like 429 =rate_limit_error= in subagents becomes short retry or fallback, not 30m sleep.
- Kimi-like billing-cycle/quota exhaustion in subagents rotates credential, then fallback model, then fails fast if neither is available.
- Fallback model selection is role-based and configurable, not arbitrary.
- Top-level interactive sessions preserve existing long-wait behavior unless a future setting changes it.
- Focused tests pass and final =bun check:ts= passes.
