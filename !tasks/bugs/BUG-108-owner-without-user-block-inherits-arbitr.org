* Problem

When an owner ID appears in =config.owners= but has no matching =user= block, the auth middleware resolves their =userConfig= via =resolveFallbackUserConfig()=, which returns =Object.values(config.users)[0]=. This makes the owner's =defaultMode=, =modes=, =projects=, and =idleTimeout= depend on an unrelated non-owner user's insertion order in the =users= map.

The existing test asserts =isOwner= for this case but does not assert the resolved =userConfig=, so the distortion is invisible to regression coverage.

- =packages/spell-server/test/telegram/auth.test.ts= — the "allows owner IDs from the owners list" test case

** Change
1. Introduce a =resolveOwnerDefaultConfig()= helper (or inline) that returns a stable owner-appropriate config with full tool access: =modes: [DEFAULT_GUEST_MODE, "telegram-full"]=, =defaultMode: DEFAULT_GUEST_MODE=, no project restriction, no idle timeout.
2. In the owner branch (=configuredUser ?? ...=), when =isOwner= is true and =configuredUser= is absent, use the owner default config instead of the guest fallback.
