The merged Telegram auth middleware determines =isOwner= by checking =config.users[userId]=, treating every configured user as an owner. In the new KDL schema, =owners= is a separate list (numeric Telegram IDs for notification recipients and =/unlock= access), while =users= is the map of all authorized users.

The auth middleware must distinguish:
- Owner: userId is in =config.owners= array (can =/unlock=, receives notifications)
- Authorized user: userId is in =config.users= map (can interact with bot, permissions defined by UserConfig)
- Guest: valid token claim (fallback config, =isOwner: false=)

* Scope
File: =packages/spell-server/src/telegram/bot/auth.ts=

** Current (wrong)
#+begin_src typescript
const ownerConfig = config.users[userId];
if (ownerConfig) {
  applyAuthState(ctx, { userId, isOwner: true, userConfig: ownerConfig });
  await next();
  return;
}
#+end_src

** Correct
#+begin_src typescript
const userConfig = config.users[userId];
const isOwner = config.owners.includes(Number(userId));

if (userConfig) {
  applyAuthState(ctx, { userId, isOwner, userConfig });
  await next();
  return;
}

// Owner who is not in users map — grant with guest-level config
if (isOwner) {
  applyAuthState(ctx, { userId, isOwner: true, userConfig: resolveGuestConfig(config) });
  await next();
  return;
}
#+end_src

This means:
1. A user in =users= map gets their configured permissions; =isOwner= is true only if also in =owners= array
2. An owner not in =users= map still gets access with guest-level config
3. Token-based guests remain =isOwner: false=
