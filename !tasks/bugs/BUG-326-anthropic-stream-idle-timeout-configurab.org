* Initial Message

Error: Assistant response stalled while streaming thinking content. Idle timeout: 45000ms.



^^^^ I get way too many of these during long thinking sessions and Anthropic. Maybe increase the timeout? Try to see what is happening?

* Intention & Purpose
Fix false-positive Anthropic streaming stalls during long reasoning/thinking gaps. The current watchdog aborts after 45,000ms without provider events, producing user-visible failures like:

#+begin_example
Assistant response stalled while streaming thinking content. Idle timeout: 45000ms.
#+end_example

The goal is not to hide real dead streams; it is to make the watchdog fit Anthropic long-thinking behavior and give users a persistent override path.

* Context & Narrative
Current repo evidence:
- ~packages/ai/src/utils/idle-iterator.ts~ defines ~DEFAULT_ANTHROPIC_STREAM_IDLE_TIMEOUT_MS = 45_000~ and reads ~PI_ANTHROPIC_STREAM_IDLE_TIMEOUT_MS~ via ~getAnthropicStreamIdleTimeoutMs()~. ~0~ disables the watchdog through ~normalizeIdleTimeoutMs()~.
- ~packages/ai/src/providers/anthropic.ts~ calls ~getAnthropicStreamIdleTimeoutMs()~ once before wrapping ~client.messages.stream(...)~ in ~iterateWithIdleTimeout(...)~. On idle, the provider aborts the request and classifies the partial assistant message via ~classifyAssistantStreamInterruption(...)~.
- ~packages/ai/src/utils/tool-call-diagnostics.ts~ maps the diagnostic state ~stalled_during_thinking~ to the exact user error string.
- ~packages/ai/test/providers/anthropic-idle-timeout.test.ts~ already exercises idle timeout behavior with a mocked Anthropic stream.
- ~packages/coding-agent/src/config/settings-schema.ts~ is the typed settings schema. Existing provider settings live under ~providers.*~ and expose UI metadata on the Providers tab.
- ~packages/coding-agent/src/sdk.ts~ initializes provider preferences from settings near ~providers.webSearch~, ~providers.codeSearch~, ~providers.image~, and ~providers.openaiWebsockets~.

User-settled requirements:
- Scope: add a config knob plus Anthropic-specific safer default.
- UX: use both a longer timeout and visible keepalive/status in the TUI (the visible status is planned in the dependent UI item).
- Config: expose both config and environment setting with safer default.

Settled design decisions for this item:
1. Anthropic default stream idle timeout becomes ~180_000ms~.
2. Existing env var ~PI_ANTHROPIC_STREAM_IDLE_TIMEOUT_MS~ remains supported and takes precedence over coding-agent config.
3. ~0~ disables the watchdog; invalid/non-finite values fall back to the safer default/configured fallback.
4. Other providers keep their current defaults; do not broaden this change to OpenAI, Bedrock, or tool-argument idle timeout.
5. Coding-agent exposes ~providers.anthropicStreamIdleTimeoutMs~ with default ~180000~ on the Providers settings tab.
6. Coding-agent must wire this setting into ~@oh-my-pi/pi-ai~ through a small public runtime override API rather than mutating ~Bun.env~ as hidden configuration state.

* Edge Cases
- Env var set to ~0~ must disable even when config is positive.
- Env var set to invalid text must not disable accidentally; it should fall back.
- Runtime override ~undefined~ must restore env/default behavior for tests and fresh isolated sessions.
- If ~providers.anthropicStreamIdleTimeoutMs~ is negative, non-finite, or not a number because of malformed YAML, normalize rather than throwing in production startup.
- Tool argument streaming must continue to use the larger of base timeout and ~DEFAULT_TOOL_ARGUMENT_STREAM_IDLE_TIMEOUT_MS~ unless explicitly overridden by ~PI_TOOL_ARGUMENT_STREAM_IDLE_TIMEOUT_MS~.
- Existing retry diagnostics should still include the timeout that actually fired.

* Acceptance Criteria
- A default Anthropic thinking stall no longer aborts at 45s; default diagnostic timeout is 180,000ms when the watchdog fires.
- Users can set ~PI_ANTHROPIC_STREAM_IDLE_TIMEOUT_MS=0~ or config ~providers.anthropicStreamIdleTimeoutMs: 0~ to disable the watchdog.
- Env var precedence is documented in schema description and proven by tests.
- Other provider defaults are unchanged.
- Focused tests pass and TypeScript check passes for touched packages.
