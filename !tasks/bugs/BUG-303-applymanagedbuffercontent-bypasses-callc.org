* Scope
Two tests in test/tools/managed-code-buffer-errors.test.ts fail with:
#+BEGIN_EXAMPLE
Managed code buffer update failed for .../lib.rs: Mutating code buffer commands require a non-empty sessionId
#+END_EXAMPLE

- "includes the native per-file error message in the thrown error" \u2014 expects "structurally invalid" in the error. The sessionId guard fires first.
- "does not throw on successful writes (parseable replacement)" \u2014 expects no throw.

Root cause: `src/session/edit-coordinator.ts::callCodeBuffer` (line 28-37) enforces non-empty sessionId on mutating commands, with a fallback (`tui-${process.pid}`) when the session's `getSessionId` returns empty. `src/tools/managed-code-buffer.ts::applyManagedBufferContent` (line 81-105) calls `executeCodeBuffer` **directly** from `@oh-my-pi/pi-natives`, not through `callCodeBuffer`. The native now enforces the sessionId requirement, so this path fails when `options.sessionId` is undefined.

Three call sites feed `applyManagedBufferContent`:
- `src/patch/index.ts:593` (EditTool.execute)
- `src/patch/index.ts:697`
- `src/patch/index.ts:915`
- `src/tools/write.ts:142` (WriteTool.execute)

All of them have `this.session` (a `ToolSession`) available.

In scope: route `applyManagedBufferContent` through `callCodeBuffer` using a `SessionIdSource`; update 4 call sites to pass `session`.
Out of scope: changing native sessionId policy; introducing new session storage. One concept, one representation (Principle 2).
