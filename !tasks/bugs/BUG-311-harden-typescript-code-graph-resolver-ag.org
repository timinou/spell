What happened?

* Scope

In:
- Stop TypeScript/JavaScript code-graph indexing from aborting Spell when `oxc_resolver` panics during module resolution.
- Land the user-selected fix scope as one cut:
  - bump `oxc_resolver` from `1.12` to current stable `11.x`,
  - add a local panic guard around `TypeScriptImportResolver.resolve()`,
  - preserve truthful fallback behavior and add regression coverage.
- Cover the native code-graph paths that invoke the resolver through `CodeGraphBuilder.build()` and currently surface as process aborts in `executeCodeGraph()` / semantic grep.

Out:
- Broad code-graph architecture changes unrelated to resolver safety.
- A general dependency refresh across other Rust crates.
- Reworking semantic grep or code-tool UX beyond what is needed to prevent process abort and keep output truthful.
- Canonicalization experiments or path rewriting unless the upgraded resolver + local guard still leave a proven gap.

Rationale:
- Repo evidence: `crates/pi-code-graph/Cargo.toml` pins `oxc_resolver = "1.12"`; `crates/pi-code-graph/src/language/typescript.rs` calls `resolver.resolve(from_dir, request.specifier)` directly; `crates/pi-natives/src/code_graph.rs` executes the graph builder inside a NAPI blocking task, so an uncaught resolver panic aborts the host process.
- Upstream evidence already collected in-session: crates.io now publishes `oxc_resolver 11.19.1`, and upstream PR #1481 fixed this package.json path-prefix assertion class. The local guard remains required because native graph code must degrade to a truthful failure path instead of taking down Spell if upstream or future path shapes panic again.

* Existing Patterns

- `crates/pi-code-graph/src/language/typescript.rs`
  - `TypeScriptImportResolver.resolve()` is the only TypeScript import-resolution entry point.
  - `fallback_relative_path(project_root, from_file, specifier)` already defines the current degraded-success path for unresolved relative imports; preserve it after guarded resolver failure.
- `crates/pi-code-graph/src/indexer.rs`
  - `CodeGraphBuilder.build()` calls `registered.resolver.resolve(ResolveRequest { ... })` for every extracted import. The fix must preserve this contract and keep valid edge construction unchanged.
- `crates/pi-natives/src/code_graph.rs`
  - `run_code_graph()` constructs `CodeGraphBuilder` and is the user-visible native entry point that currently aborts when the resolver panic escapes.
- `crates/pi-embedding-worker/src/main.rs`
  - `panic::catch_unwind(AssertUnwindSafe(...))` is an existing repo pattern for containing native-side panics and surfacing truthful errors instead of crashing the host.
- `crates/pi-code-graph/src/language/elixir.rs` and `crates/pi-code-graph/src/language/generic.rs`
  - Existing resolver tests create temp workspaces and call resolver/builder entry points directly. Reuse this style for new TypeScript resolver regression coverage rather than inventing a new harness.
