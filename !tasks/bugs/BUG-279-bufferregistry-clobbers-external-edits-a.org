* Scope

In: make `pi_code_engine::buffer::BufferRegistry` detect external file
modifications and (a) reload the rope before serving `open()` when disk is
newer, (b) refuse `save()` when disk was mutated externally between open
and save.

Out: file-watcher infrastructure; multi-process coordination; content-hash
based invalidation (stick with mtime for v1).

* Background

Process-wide singleton `buffer_registry()` caches a `HashMap<PathBuf,
Arc<Mutex<CodeBuffer>>>`. `BufferRegistry::open()` returns the cached
`Arc` on hit with no disk check. Every subsequent `executeOrg` /
`executeCodeBuffer` command operates on the cached rope. `CodeBuffer::
save()` overwrites disk with the cached rope.

Consequence (demonstrated during planning of PLAN-248):

1. `org create FEAT-564 …` — engine caches rope v1.
2. External `fs.writeFile(path, fixed)` changes the disk contents.
3. `org note FEAT-564 "x"` — operates on cached rope v1, `save()`
   re-writes v1+note to disk, clobbering the external edit.
4. Every subsequent `executeOrg("parse" | "query" | "validate")` returns
   results based on rope v1 forever, regardless of actual disk state.

Impact:
- Any tool that mixes engine writes with non-engine writes silently loses
  data.
- `validatePlanItem` sees stale bodies; users cannot recover except by
  re-opening the whole process.

* Implementation

** Track mtime on CodeBuffer
:PROPERTIES:
:CUSTOM_ID: BUG-279-bufferregistry-clobbers-external-edits-a::mtime-field
:END:

- File: `crates/pi-code-engine/src/buffer.rs`
- Add `disk_mtime: Option<std::time::SystemTime>` to `CodeBuffer`.
- Populate in `CodeBuffer::open` from `metadata.modified()?`.
- On `save()`, stat the file first; record the new mtime post-write.

** Revalidate in BufferRegistry::open
:PROPERTIES:
:CUSTOM_ID: BUG-279-bufferregistry-clobbers-external-edits-a::registry-revalidate
:DEPENDS: BUG-279-bufferregistry-clobbers-external-edits-a::mtime-field
:END:

- File: `crates/pi-code-engine/src/buffer.rs`
- In `BufferRegistry::open`, after `self.get(path)` hit:
  - Stat path. If `err.kind() == NotFound` → drop cache entry, fall
    through to normal open (which will error).
  - If `metadata.modified()? > buffer.lock().disk_mtime.unwrap_or(
    UNIX_EPOCH)`, drop the cache entry (write-lock map) and fall
    through to `CodeBuffer::open`, re-insert, return.
  - Else return cached Arc.
- Add `BufferRegistry::reload_if_stale(path)` helper surfaced publicly.

* Edge cases

- Filesystems with 1s mtime granularity (ext4 without extended
  timestamps): two writes in the same second look identical. Guard:
  on save(), after write, explicitly stamp mtime via
  `filetime::set_file_mtime(now + 1ns)` OR stash a content hash
  alongside mtime. For v1 accept the 1s race — document in the error
  path.
- Concurrent engine writes to the same path from two threads: already
  serialized by `Arc<Mutex<CodeBuffer>>`. No change.
- File deleted externally: `open()` stat fails → drop cache entry →
  caller receives the underlying IO error (NotFound). Matches fresh
  open behavior.
- Very large files: revalidate path must NOT re-read until we confirm
  mtime bumped. Stat is cheap; read is only on stale.
