* Edge Cases

- An Elixir file whose root has a single `defmodule` whose first argument is a non-alias expression (e.g. `defmodule __MODULE__ do` or `defmodule :"elixir_compound_module" do`). The resolver MUST NOT crash; it MAY return `Available: []` with the improved diagnostic. No code change is required unless such files surface in test corpora.
- Multiple top-level `defmodule` declarations in one file (the tree-sitter-elixir AST permits this). Dotted-name resolution MUST still pick the correct module by its full name; ambiguity detection already handled by `ambiguous_symbol_error` (resolve.rs:199). Add a regression test if not already covered.
- A `defmodule` nested inside a `quote do ... end` block (e.g. inside a macro body). Not a top-level declaration; MUST NOT resolve as one. The existing single-level root walk already enforces this; preserve that behavior.
- Tree-sitter-elixir version drift: if the grammar changes node type or field names across versions, the resolver fix MUST NOT hard-code version-specific quirks beyond what `language/mod.rs` already encodes. Profile-level config first; code changes second.
- If the fix requires a rebuild of the native binary, implementation session MUST rebuild (`bun run dev:native`) and then re-run the NAPI-level tests, per the memory summary's "Pin native binary rebuild" pitfall.
