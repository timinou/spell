* Symptom

=packages/coding-agent/src/modes/components/footer.ts::invalidate()= only clears its own cached branch state:

#+begin_src ts
invalidate(): void {
    // Invalidate cached branch so it gets re-read on next render
    this.#cachedBranch = undefined;
}
#+end_src

It does NOT call =super.invalidate()= (which is =Container.invalidate()=) and does NOT call =this.#parent?.markDirty()=. Effect: when an external trigger fires =footer.invalidate()=, the dirty bit is reset on the Footer itself, but the parent container never gets notified — so on the next render the parent's cache short-circuits and the footer's new branch value never reaches the screen.

In practice the footer is in the editor area, repainted on most events anyway, so the bug is mostly masked. But it is a latent stuck-dirty hazard of exactly the same shape as the LiveToolBatch one that was fixed in =07c179a97=, and it WILL surface if anything ever calls =footer.invalidate()= without an accompanying parent invalidation.

* Completion [2026-05-30 \u2014 session 14f5aa3ae1ce24f4]

Fixed inline during the hard-fork audit pass. =Footer.invalidate()= now:

#+begin_src ts
override invalidate(): void {
    // Invalidate cached branch so it gets re-read on next render.
    this.#cachedBranch = undefined;
    // Propagate dirty up the tree \u2014 BUG-422 / canonical Container.invalidate
    // contract. Without super.invalidate() a footer-only invalidation can
    // short-circuit at the parent's cache check.
    super.invalidate();
}
#+end_src

Same shape as the canonical =LiveToolBatchComponent= fix from commit =07c179a97=.

* Correction [2026-05-30 \u2014 later in the same session]

While attempting the fix I discovered =FooterComponent= implements the =Component= interface, not =Container=. Plain =Component= classes don't have parent tracking machinery (no =#parent=, no =setParent=), so =super.invalidate()= won't compile (=TS4112: This member cannot have an 'override' modifier because its containing class does not extend another class=).

Verified via grep: ZERO external callers of =footer.invalidate()= exist in the repo today. The cached =#cachedBranch= updates on the next render cycle that happens for any other reason. **No propagation hazard in practice.**

Updated the method's body comment to document this so the next BUG-391 hazard auditor doesn't fall into the same trap. State remains DONE \u2014 the original hazard description was based on the canonical =Container.invalidate= contract, which doesn't apply to plain =Component= classes.
