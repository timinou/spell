** Problem
~atomicWrite~ in ~packages/org/src/atomic-write.ts~ uses a deterministic tmp path (~${filePath}.tmp~).
When two concurrent operations target the same file, the second ~fs.rename~ fails with ENOENT because
the first already moved the shared ~.tmp~ file.

** Fix
- Generate a unique tmp path per call: ~${filePath}.${crypto.randomUUID().slice(0, 8)}.tmp~
- Add try/finally to clean up the tmp file on write or rename failure
- Use ~crypto.randomUUID()~ (Web Crypto, available in Bun) for the suffix

** Files
- ~packages/org/src/atomic-write.ts~ (sole file, ~11 lines currently)

** Acceptance
- ~atomicWrite~ uses a unique tmp path per invocation
- Failed writes clean up their tmp file (try/finally around rename, unlink in catch)
- Existing tests still pass: ~bun test packages/org/test/~
- No other files import or depend on the tmp path naming convention
