* Problem
=packages/ai/src/providers/azure-openai-responses.ts= has the same two caching bugs as the Codex provider:
1. =prompt_cache_key= is set unconditionally to =options?.sessionId= (line 255) — ignores =cacheRetention === "none"=
2. =prompt_cache_retention= is never set

* Fix

** File: =packages/ai/src/providers/azure-openai-responses.ts=
In =buildParams= function (line ~243):

1. Add import at top of file:
#+begin_src typescript
import { resolveOpenAICacheParams } from "../utils";
#+end_src

2. Replace the raw =prompt_cache_key= assignment in the params object (line 255):

Before:
#+begin_src typescript
const params: AzureOpenAIResponsesSamplingParams = {
    model: deploymentName,
    input: messages,
    stream: true,
    prompt_cache_key: options?.sessionId,
};
#+end_src

After:
#+begin_src typescript
const params: AzureOpenAIResponsesSamplingParams = {
    model: deploymentName,
    input: messages,
    stream: true,
    ...resolveOpenAICacheParams(options?.cacheRetention, options?.sessionId),
};
#+end_src

3. Verify that =AzureOpenAIResponsesSamplingParams= type can accept =prompt_cache_retention=. Check the type definition — it likely extends =ResponseCreateParamsStreaming= or has an index signature. If it does not include =prompt_cache_retention=, add it:
#+begin_src typescript
prompt_cache_retention?: "in_memory" | "24h";
#+end_src

- Azure may or may not support extended retention server-side; the parameter is safe to send (server ignores unsupported params).
