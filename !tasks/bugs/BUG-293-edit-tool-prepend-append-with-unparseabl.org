* Root Cause

=resolveEditAnchors()= in =packages/coding-agent/src/patch/index.ts= L212-243 resolves user-supplied =pos= / =end= strings into =Anchor= objects via =tryParseTag()=. When the string is not a valid hashline tag (e.g. raw source text like ="export interface CodeBufferResult { ... }"=), =tryParseTag()= returns =undefined=.

For =replace= (L222-230), this correctly throws: ="Replace requires at least one anchor"=.

For =append= (L232-234) and =prepend= (L236-238), undefined is silently accepted:
#+begin_src typescript
case "append": {
    result.push({ op: "append", pos: tag ?? end, lines });
    // pos becomes undefined → append at EOF
    break;
}
case "prepend": {
    result.push({ op: "prepend", pos: end ?? tag, lines });
    // pos becomes undefined → prepend at BOF
    break;
}
#+end_src

Downstream in =applyHashlineEdits()= (=packages/coding-agent/src/patch/hashline.ts= L694-716):
- =prepend= with no =pos= → =fileLines.splice(0, 0, ...inserted)= → BOF insert
- =append= with no =pos= → =fileLines.splice(fileLines.length, 0, ...inserted)= → EOF insert

The original content at the intended anchor location is untouched → duplication.
