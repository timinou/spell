* Scope

The plan-mode-active.md prompt hardcodes =state: "INIT"= for PLAN item creation, but the project's org config may not include =INIT= as a valid TODO keyword. This causes =org create= to fail with =Unknown state: "INIT". Valid: ITEM, DOING, DONE, BLOCKED, CANCELLED, REVIEW=. The agent then has to retry with =state: "ITEM"=, wasting a tool call.

*In scope*:
- Fix =packages/coding-agent/src/prompts/system/plan-mode-active.md= to use =state: "ITEM"= instead of =state: "INIT"= for PLAN creation (ITEM is universally valid)
- OR: make the prompt template inject the correct initial state dynamically from the project's org config

*Out of scope*:
- Changing the default TODO keywords
- Changing the org engine's state validation logic
- Changing how other org commands work

* Existing Patterns
- =packages/coding-agent/src/prompts/system/plan-mode-active.md= — Handlebars template with ={{planCategory}}=, ={{exitToolName}}= etc.
- The prompt currently hardcodes =state: "INIT"= in 5 places (lines 41, 104, 109, 184, 261)
- =packages/coding-agent/src/modes/plan-mode.ts= or wherever the template context is built — could inject ={{planInitState}}= as a Handlebars variable
- =packages/org/src/schema/defaults.ts= — =DEFAULT_TODO_KEYWORDS= includes INIT but project configs can override

Decision: Use a Handlebars variable ={{planInitState}}= that defaults to the first TODO keyword from the project's org config. This way the prompt adapts to whatever the project has configured.

- Scenario 1: Project with default config (includes INIT) → prompt says =state: "INIT"=
- Scenario 2: Project with custom config (no INIT) → prompt says =state: "ITEM"= (or whatever the first keyword is)
