## Audit Findings

### 1. Markdown outline will not work: `section` node missing from unwrap list
- **What**: `pi-treesit--top-level-nodes-children` unwraps `document`, `stream`, `block_mapping`, `object` — but tree-sitter-markdown wraps `atx_heading` inside `section` nodes. Without `section` in the unwrap list, heading nodes are never reached by the outline function.
- **Where**: `packages/emacs/elisp/pi-treesit.el` ~line 155
- **Why**: Markdown outline (`code outline` on .md files) will return empty results. The feature's primary use case doesn't work. The test is gated by `skip-unless` AND has a nesting bug that prevents execution, so this was never caught.
- **Effort**: `trivial` — add `"section"` to the unwrap list at line 155.

### 2. Elisp test nesting bug: `test-outline-markdown-headings` is inside `test-outline-line-numbers`
- **What**: `test-outline-line-numbers` (line 56-64) is missing one closing paren. The next test (`test-outline-markdown-headings`) is nested inside it. The paren I added at line 77 compensated the total count but didn't fix the structural nesting.
- **Where**: `packages/emacs/test/elisp/test-outline.el` line 64 (needs one more `)`) and line 77 (has one extra `)`)
- **Why**: The markdown test is never registered as an ERT test (confirmed: `ert-test-unbound`). If/when grammars become available, these tests silently don't run.
- **Effort**: `trivial` — add `)` at line 64, remove one from line 77.

### 3. Core tier test missing `"code"` assertion
- **What**: The core tier test at `test/tools/index.test.ts` line 261 asserts core tier for `["grep", "find", "bash", "lsp", "task", "ask"]` but omits `"code"`.
- **Where**: `packages/coding-agent/test/tools/index.test.ts` line 261
- **Why**: The most important assertion of this plan — that `code` is core tier — is not tested. The test would still pass if someone accidentally moved `code` to standard.
- **Effort**: `trivial` — add `"code"` to the array.

### 4. TOML `table` name returns full node text including all children
- **What**: The `table` case in `pi-treesit-declaration-name` (line 283-284) returns `(string-trim (treesit-node-text node t))` which includes the entire table content (`[table]\nitem = "value"\nother = 1`), not just the header `[table]`.
- **Where**: `packages/emacs/elisp/pi-treesit.el` line 284
- **Why**: TOML table outline entries will have multi-line names containing all key-value pairs under the table. The test asserts `(member "[table]" names)` but the actual name would be the full table text. When TOML grammar becomes available, this test will fail.
- **Effort**: `small` — extract just the table header line, or use the first child node (the `[table]` bracket header).

### 5. `pair` clause crashes on nil grandparent-type
- **What**: In the TOML path of the `pair` handler (line 277), `(not (string= grandparent-type "table"))` calls `string=` on potentially nil `grandparent-type`, which signals a wrong-type-argument error in Elisp.
- **Where**: `packages/emacs/elisp/pi-treesit.el` line 277
- **Why**: If a `pair` node's grandparent is nil (unlikely but possible for malformed documents), this crashes. Fix: use `(not (equal grandparent-type "table"))` or guard with `(and grandparent-type ...)`.
- **Effort**: `trivial`

- **Where**: `packages/coding-agent/src/tools/code.ts` lines 139-171
- **Why**: Minor perf waste (parse twice) and double-sanitization (cosmetic). Not a correctness bug.
- **Effort**: `trivial` — single try-catch parse; remove `safeText` and use `toRender(text)` directly.
