* Scope
Seven task/executor tests crash when the subagent mock session lacks `refreshBaseSystemPrompt`:
- test/task/tool-budget.test.ts (5 tests)
- test/task/model-fallback.test.ts (2 tests)

Root cause is in `src/task/executor.ts:1329-1333`:
#+BEGIN_SRC typescript
const actualTodoWrite = session.getActiveToolNames().includes("todo_write");
if (actualTodoWrite !== todoWriteAvailable) {
    todoWriteAvailable = actualTodoWrite;
    await session.refreshBaseSystemPrompt();
}
#+END_SRC

`todoWriteAvailable` initializes to `subagentSettings.get("todo.enabled") && (toolNames === undefined || toolNames.includes("todo_write"))`. Tests use `baseAgent` without a `tools` field, so `toolNames === undefined` and `todoWriteAvailable` becomes `true`. The mock session's `getActiveToolNames` returns `["read","submit_result"]`, so `actualTodoWrite === false`. The mismatch triggers `refreshBaseSystemPrompt()`, which does not exist on the mocks.

In tool-budget this throws synchronously before `prompt()` runs, so `prompts.length === 0` and every assertion about prompt content or `result.output` fails. In model-fallback it replaces the expected "401 Invalid bearer token" with a TypeError.

In scope: test-mock changes only. No production change.
Out of scope: hardening `executor.ts` with optional chaining; real sessions have the method, so relaxing the call would hide genuine future regressions.
