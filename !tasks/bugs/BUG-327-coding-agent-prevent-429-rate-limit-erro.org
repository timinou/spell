* Intention & Purpose
Stop provider 429 responses with structured =rate_limit_error= / =rate_limit_exceeded= semantics from being classified as long quota exhaustion. The concrete incident is session =14cc69946fb52683=: wave-5 child logs =37-W5ToolKbProofsDock.jsonl= and =38-W5DeleteDeadRuntime.jsonl= recorded Kimi =429 rate_limit_error= usage-limit responses, while earlier wave-2 child logs show attempt 1 around 15:09 and attempt 2 around 15:39. The current classifier let those errors enter the 30 minute quota path.

Purpose: make the reason classifier precise enough that transient/per-period 429s use short retry semantics, while true quota/billing-cycle messages remain quota exhaustion for credential blocking and fail-fast handling by the coding-agent layer.

* Context & Narrative
Current evidence:
- =packages/ai/src/rate-limit-utils.ts= defines =parseRateLimitReason(errorMessage: string): RateLimitReason= and =calculateRateLimitBackoffMs(reason: RateLimitReason): number=.
- The parser currently detects =rate limit= with a literal space but not =rate_limit_error= or =rate_limit_exceeded=.
- The parser then sees =quota= in provider prose like “Your quota will be refreshed...” and classifies the whole response as =QUOTA_EXHAUSTED=.
- =calculateRateLimitBackoffMs("QUOTA_EXHAUSTED")= returns =30 * 60 * 1000=.
- Tests already exist in =packages/ai/test/rate-limit-utils.test.ts= for quota, too-many-requests, per-minute, model capacity, server error, and unknown.

This item defines the lower-level classification contract. It does not decide whether subagents should sleep, switch model, or fail fast; that runtime policy is handled by the dependent coding-agent item.

* Scope

- Preserve true quota exhaustion classification for billing-cycle/usage-quota phrases that do not carry an explicit rate-limit error code.
- Add tests for Kimi-like 429 payload strings and for billing-cycle 403 permission errors.
- Keep existing backoff constants unchanged: =QUOTA_EXHAUSTED= remains 30m for callers that intentionally use it; =RATE_LIMIT_EXCEEDED= remains 30s.

Out of scope:
