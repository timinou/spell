Introduced in PLAN-141 (commit 134d9eeaf). In the async batch path (~task/index.ts~), ~return undefined!~ violates the ~() => Promise<string>~ callback contract of ~AsyncJobManager.register~. The job manager stores ~undefined~ as ~resultText~ (typed ~string~) and passes it through ~#enqueueDelivery~ to ~formatAsyncResultForFollowUp(result: string)~ in ~sdk.ts~, which calls ~result.length~ — a runtime TypeError on ~undefined~.

In practice, this only fires when ~runSignal.aborted~ is true after stagger sleep. The abort path in the job manager checks ~job.status === \"cancelled\"~ first (line 125), so the ~undefined~ is stored but not delivered. However, this is fragile — any change to cancellation ordering surfaces the bug.
