* Symptom

For *any* absolute target whose resolved filesystem path equals
the walker's root (with or without trailing =/= or =#qualifier=),
=get= and =find= return =[§no-results]= even though =ls= /
=cat= on the same path work.

#+begin_example
find { target: "/home/user/code/ora/concept/#tree" }   → [§no-results]
get  { target: "/home/user/code/ora/concept/" }         → [§no-results]
get  { target: "/home/user/code/ora/concept" }          → [§no-results]
#+end_example

This is reproducible after the BUG-379 fix; this bug exposes a
residual hole in =makeRelativeToRoot=.

* Root Cause

=packages/coding-agent/src/tools/get.ts::makeRelativeToRoot=:

#+begin_src ts
const rel = path.relative(rootDir, base);
if (rel === "") return target;   // ← target IS root → return absolute → kernel chokes
if (!rel.startsWith("..") && !path.isAbsolute(rel)) return rel + suffix;
return target;
#+end_src

When the absolute target resolves to the walker root itself,
=path.relative= returns =""=. The early-return passes the absolute
target back to the kernel. The kernel walker treats =target= as a
path /inside/ =root=, so =root=, =target=/=root/=, =target=/=root/=,
or =target=/=root/#tree=, =target= all resolve to "find an entry
named =<root>= inside =<root>=" → empty.

The correct mapping when =rel === ""= is =.= (or =suffix= alone if
suffix already begins with =#=/=:=) so the walker resolves to the
root entry itself.

* Acceptance

** Behaviour
- =get { target: "/abs/root" }= where =/abs/root= equals the
  computed walker root → returns the directory listing.
- =get { target: "/abs/root/" }= → same.
- =get { target: "/abs/root#tree" }= → returns the tree.
- =get { target: "/abs/root#listing" }= → returns one-level listing.
- =find { target: "/abs/root/#tree" }= from a session rooted at
  =/abs/root= → returns the tree (regression of the original repro).
- Existing FEAT-816 tests still pass (no regression in
  out-of-cwd handling).

** Mechanism
In =makeRelativeToRoot=, replace the =if (rel === "") return target=
branch with =if (rel === "") return "." + suffix= (suffix carries
the qualifier/symbol-query verbatim, so =.#tree=, =.#listing=,
=.::§line[...]= all work).

* Edge Cases

- =suffix === ""= (bare path equal to root) → =target = "."=.
  Kernel must accept =.= as the entire target. If not, fallback to
  =buildDirQualifier(".",  params)= attaching =#listing= — but the
  bare-plain branch in =execute()= already does this for relative
  =.=, so we should be re-using that path. Verify in a test.
- Trailing-slash variation: =/abs/root/= and =/abs/root= must yield
  the same answer.
- Qualifier with embedded =/=: =/abs/root/file#raw= where the
  prefix is also =/abs/root= — =base= is =/abs/root/file=,
  =rel = "file"=, =rel + "#raw"= → unchanged. No regression.
- =root: "/other"= override with target =/abs/root= where
  =/abs/root= sits under =/other=: =rel= becomes non-empty, no
  change. Already covered.

NOTE [2026-05-16]: Fixed TDD-style. Root cause: `makeRelativeToRoot` returned the original absolute target when `path.relative === ""`, but the kernel can't resolve `<root>` inside `<root>` for some root paths (incl. spell's own cwd) and returns []. Compounded by a cwd-skip optimization that bypassed the conversion for all in-cwd absolute paths. Fix: (1) when `rel === ""`, return `.` + suffix (special-case `#listing` → bare `.` because kernel rejects `.#listing`); (2) hoist a `rootEqual` escape past the cwd-skip so root-equal targets always convert. 4 new BUG-380 tests + 10 wire-format updates to existing T1.* tests (the old assertions locked in the broken `<abs>#qual` wire format). 75/75 in get.test.ts; 89/89 across get/negative/get-image. Smoke test on the original spell cwd repro returns content correctly.
