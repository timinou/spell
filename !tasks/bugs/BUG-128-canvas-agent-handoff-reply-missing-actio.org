The =CANVAS_AGENT_CHANNEL= subscriber in =sdk.ts= sends reply payloads that lack the =action: "agent_handoff_result"= field. The Phoenix Inspector QML (and any future canvas QML using the agent handoff protocol) gates reply processing on =payload.action === "agent_handoff_result"=. Without it, replies are silently dropped and the UI stays permanently stuck at "Sending selection to the agent..."

** Affected Code
- File: =packages/coding-agent/src/sdk.ts= (lines 2124-2145)
- The =CANVAS_AGENT_CHANNEL= event subscriber

** Current Behavior
Success reply sends:
#+begin_src typescript
payload.reply?.({
    ok: true,
    status: "submitted",
    message: "Submitted the Phoenix inspector request to the active agent session.",
});
#+end_src

Error replies send:
#+begin_src typescript
payload.reply?.({ error: "Canvas agent request failed: no active session." });
// or
payload.reply?.({ error: error.message });
#+end_src

The =reply= callback in =canvas.ts= wraps this as ={ _rid: rid, ...result }=. The QML receives ={ _rid, ok, status, message }= but no =action= field.

** Expected Behavior
The =reply= callback should include the =action= field the QML expects, matching the extension path's =buildAgentHandoffReply()= / =buildAgentHandoffReplyFailure()= contract:

Success: =action: "agent_handoff_result", ok: true, status: "submitted"|"queued", message: "..."=
Error: =action: "agent_handoff_result", ok: false, error: "..."=

** Fix
In =packages/coding-agent/src/sdk.ts=, update the =CANVAS_AGENT_CHANNEL= subscriber:

1. Success reply (line 2135): add =action: "agent_handoff_result"=
2. No-session error (line 2127): add =action: "agent_handoff_result", ok: false=
3. Catch error (line 2141): add =action: "agent_handoff_result", ok: false=

The existing helpers =buildAgentHandoffReply= and =buildAgentHandoffReplyFailure= from the inspector extension's =helpers.ts= define the exact shape. The SDK should match it. Alternatively, the SDK can inline the same shape since importing from a project extension is not appropriate.
