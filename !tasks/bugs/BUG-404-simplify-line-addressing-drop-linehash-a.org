* Symptom

=lineReplace= / =lineInsert= / =lineAppend= / =linePrepend= fail 12/14 in
the corpus (86% error rate). Top error:
=Edit 1: replace requires at least one anchor (pos or end).=

Agents pass =span= in any of these shapes — all rejected:

#+begin_example
"span": [48, 68]                                          (array of numbers)
"span": "603-603"                                         (string)
"span": "351..422"                                        (CodePath slice)
"span": {"start":{"line":1030,"column":1},"end":{...}}    (LSP-style)
#+end_example

What the schema *requires*: =LINE#HASH= base32 anchor strings copied
from a prior =find/get= output (=lineAnchorSchema.pattern = "^\\d+#.+$"=).

* Root cause

FEAT-705 added 2-char content-hash anchors to every emitted line and
required them on every line-targeted edit, so that drifted line numbers
fail loudly via =AnchorMismatch=. In practice:

1. Agents see =LINE#XY= in =find= output but mentally throw away the =#XY=
   suffix because line numbers feel natural.
2. The schema description ("LINE#HASH anchor copied from get output")
   is too terse — agents don't connect "anchor" with the suffix.
3. The error message "replace requires at least one anchor" does not
   explain the expected format — agents iterate randomly.
4. Net: line-targeted ops are effectively unusable; agents fall back to
   =fileFindReplace= (good) or =bash + sed/python= (bad — 12 fallback
   chains in the corpus).

The staleness protection LINE#HASH provides is *not justified by use*:
in 945 edit calls, no successful =lineReplace= depended on the hash for
correctness — every working case would have worked with a raw line
number too.

* Decision

Drop LINE#HASH anchors entirely. =lineSpanSchema=, =lineAnchorSchema=,
=lineAtSchema= become raw 1-indexed line numbers.

#+begin_src ts
// after
export const lineAnchorSchema = Type.Number({ minimum: 1, description: "1-indexed line number" });
export const lineSpanSchema = Type.Object({
  start: Type.Number({ minimum: 1, description: "1-indexed start line" }),
  end:   Type.Optional(Type.Number({ minimum: 1, description: "1-indexed end line (inclusive)" })),
});
export const lineAtSchema = Type.Object({
  side: Type.Union([Type.Literal("before"), Type.Literal("after")]),
  line: Type.Number({ minimum: 1 }),
});
#+end_src

Staleness: optimistic. If users want guarded edits, they use symbol
targets (which are content-addressed) or =fileFindReplace= (which is
content-addressed by =find=).
