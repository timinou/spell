- =crates/pi-code-engine/src/buffer.rs:1302-1350= ~save()~/~save_with_watcher()~ formally deprecated; edit goes through ~edit_transaction~ which auto-persists and closes the buffer.

- After auto-commit, no buffer is left dirty → manage diff/undo/save have nothing to operate on.

* Reframed goal (per user direction)

Even when edits auto-save (which is correct default), the agent should be able to:
1. ~edit~ a file → it persists to disk
2. ~manage diff~ → see what THIS agent session changed (vs disk-prior)
3. ~manage undo~ → revert THIS session's changes; sibling agents' overlapping changes survive
4. ~manage context~ → enumerate edits by agent/session/commit (initial scope: uncommitted; future: cross-commit)

This is a per-session edit-history tracker, not a managed-buffer revival. Building blocks already exist (edit_transaction, watcher, sessionId).

* Fix contract (small, simple, extensible trait)

** New module: ~crates/pi-natives/src/code_path/edit_history.rs~

- Trait ~EditHistory~ with builder methods:
  #+begin_src rust
  pub trait EditHistory {
      fn record(&self, entry: EditEntry);
      fn query(&self, q: HistoryQuery) -> Vec<EditEntry>;
      fn revert(&self, q: HistoryQuery) -> RevertOutcome;
  }

  pub struct EditEntry {
      pub id: String,           // monotonic
      pub session_id: String,
      pub agent_label: String,  // optional, e.g. "task-09-explorer"
      pub file: PathBuf,
      pub before: String,       // pre-edit content (for revert)
      pub after: String,        // post-edit content
      pub diff: String,         // unified diff
      pub timestamp: SystemTime,
      pub commit: Option<String>,  // git commit if known; None=uncommitted
  }

  pub struct HistoryQuery {
      pub session_id: Option<String>,
      pub agent_label: Option<String>,
      pub file_glob: Option<String>,
      pub since: Option<SystemTime>,
      pub uncommitted_only: bool,  // initial default
  }
  #+end_src

** Storage (initial)
- File-backed JSONL log at =<root>/.spell/edit-history.jsonl=, append-only.
- One record per ~edit_transaction~ commit. The ~before~ is the rope content at edit-start; ~after~ is the persisted result.
- Reverting overwrites the file with the recorded ~before~ content. Reverting a chain replays in reverse.

** Wiring
- =crates/pi-code-engine/src/buffer.rs= ~edit_transaction~: emit one ~EditEntry~ on success. Take a sessionId/agentLabel from request payload (already plumbed through code_buffer JSON).
- =crates/pi-natives/src/code_path/manage.rs= handlers:
  - ~handle_diff(file, root, sessionId)~: query history for sessionId, file → join all diffs.
  - ~handle_undo(file, root, sessionId)~: query history for sessionId, file → revert most-recent entry.
  - ~handle_redo(file, root, sessionId)~: track reverted entries, replay.
  - ~handle_context(root, sessionId, opts)~: query history with builder filters; render summary.
  - ~handle_save~: deprecate to a no-op + diagnostic "edits auto-persist; use manage diff to inspect or manage undo to revert".
- All file params validated: empty string → ~missing_target~ diagnostic (mirror existing diff guard).
- =crates/pi-natives/src/code_path/napi.rs= dispatch: add ~"context"~ branch.
