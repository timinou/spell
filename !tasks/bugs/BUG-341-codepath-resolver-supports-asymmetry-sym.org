* Symptoms

Latent data-loss vector. Currently masked by FsResolver winning the dispatch race; if order ever changes, symbol resolvers silently corrupt files.

#+begin_example
edit { target: "foo.ts", action: { kind: "delete" }}
              ^^^ bare path, no qualifier

Expected: fs::remove_file → file unlinked
Actual today: FsResolver wins → unlinked ✓
But: CodeResolver.supports() ALSO claims this Delete action.
     If FsResolver were down/disabled/reordered → CodeResolver
     dispatches → kill_node clears bytes → file becomes 0-byte
     but survives.

Same asymmetry: TextResolver claims Insert/Replace/Patch on
qualified paths it cannot safely handle.
#+end_example

* Root cause

PLAN-300 fixed FsResolver to gate by path structure:
#+begin_src rust
// crates/pi-code-path/src/dialects/fs/mutation.rs:53-62
fn supports(&self, path: &CodePath, kind: ActionKind) -> bool {
    if !matches!(kind, Create | Write | Delete) { return false; }
    path.query.is_none() && path.qualifier.is_none()  // ← path-aware ✓
}
#+end_src

But CodeResolver and TextResolver still gate on action kind alone:
#+begin_src rust
// crates/pi-natives/src/code_path/code_resolver/mutation.rs:114-135
fn supports(&self, _path: &CodePath, kind: ActionKind) -> bool {  // ← _path ignored
    matches!(kind, Rename | Wrap | … | Delete | …)
}

// crates/pi-code-path/src/dialects/text/mutation.rs:131-144
fn supports(&self, _path: &CodePath, kind: ActionKind) -> bool {  // ← _path ignored
    matches!(kind, Append | Prepend | Insert | Replace | Patch)
}
#+end_src

* Fix contract (C: full structural alignment)

** A. CodeResolver
- Symbol-scoped kinds (Rename/Wrap/FindAndReplace/RawTextReplace/Splice/Move/Clone/Transpose/InsertBefore/InsertAfter/Delete/RenameClassToken/RenameIdToken/RenameCustomProperty/ReplaceCodeBlock/RemoveDeadStyle/Promote/Demote) require ~path.query.is_some() || path.qualifier.is_some()~.
- Without a query/qualifier, return false → not this resolver's job.

** B. Zero-byte guard in code_buffer kill_node
- =crates/pi-natives/src/code_buffer.rs= delete handler: after computing edits, if applying them would leave the file at 0 bytes AND the original CodePath had no qualifier, return diagnostic ~zero_byte_delete_blocked~ with hint "use bare path target to delete the file".
- Belt-and-braces against future regression of (A).

** C. TextResolver
- Insert/Replace require ~path.qualifier.is_some()~ (text qualifiers like #raw, #lines) — currently TextResolver "rewrites the whole file" per its own comment, which is wrong for symbol-targeted text ops.
- Append/Prepend on bare paths are OK (they append/prepend to the whole file).
- Patch is bare-path — keep claimed.
- Audit each kind:
  - Append: claim ↔ bare path only
  - Prepend: claim ↔ bare path only
  - Insert (line-anchored): claim ↔ bare path or text qualifier
  - Replace (line-anchored): claim ↔ bare path or text qualifier
  - Patch: claim ↔ bare path only

** Common helper
- Add ~CodePath::has_target_query()~ inherent helper to avoid duplicating ~path.query.is_some() || path.qualifier.is_some()~ across resolvers.
