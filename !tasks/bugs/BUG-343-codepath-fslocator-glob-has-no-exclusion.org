* Symptoms

#+begin_example
get { target: "dist/*.ts" }
→ matches dist/foo.ts, dist/foo.d.ts, dist/foo.ts.map (technically not .ts)
→ user has no way to exclude generated .d.ts and source-map files
#+end_example

* Root cause

- =crates/pi-code-path/src/parser.rs:265-338= ~tokenise_segment~ supports glob primitives Star/DoubleStar/CharClass/Brace but no NEGATION.
- Brace ~{a,b}~ is positive matching only; users naturally try ~{ts,!d.ts}~ and it gets parsed as a literal ~!d.ts~.

* Fix contract (A: extend brace grammar with `!` exclusion)

** Grammar
- ~{a,b,!c,!d}~ matches anything in {a,b} that does NOT match {c,d}.
- Inclusion items first, exclusion items prefixed with ~!~.
- Pure-exclusion ~{!c}~ is a parse error (must have at least one positive).

** Implementation
- =crates/pi-code-path/src/parser.rs::tokenise_segment= (around line 311):
  - When parsing brace contents, split items on ~,~
  - Items starting with ~!~ go into ~exclusions: Vec<String>~
  - Other items stay as ~items: Vec<String>~
  - Emit a new ~FsSegment::Brace { items, exclusions }~ variant (or extend existing Brace tuple)

** AST
- =crates/pi-code-path/src/ast.rs= ~FsSegment::Brace(Vec<String>)~ → ~FsSegment::Brace { items: Vec<String>, exclusions: Vec<String> }~. Update all call sites; existing serialization may need a #[serde(rename)] migration.

** Walker
- =crates/pi-code-path/src/dialects/fs/mod.rs= matcher: a name matches a Brace if (any item matches) AND (no exclusion matches).
- Items and exclusions follow the same suffix-/prefix-/exact-match rules.

** Tests in parser
- ~tokenise_segment("foo.{ts,!d.ts}")~ → Brace { items: ["ts"], exclusions: ["d.ts"] }
- ~tokenise_segment("foo.{!d.ts}")~ → parse error (no positive item)
- ~tokenise_segment("foo.{ts}")~ → Brace { items: ["ts"], exclusions: [] } (back-compat)
