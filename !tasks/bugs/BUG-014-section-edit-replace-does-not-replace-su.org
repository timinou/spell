* Problem
The Emacs =org-tasks--edit-section-headline= function in replace mode only deletes text
before the first sub-heading, then inserts the new body. If the new body contains sub-headings
(e.g. =** Problem=, =** Approach=), they are inserted before the existing sub-headings,
creating duplication.

Example: replacing =* Context= section body that has =** Problem= / =** Approach= sub-headings:
1. Function deletes text between =* Context= heading and =** Problem= sub-heading
2. Inserts new body (which includes =** Problem= content)
3. Existing =** Problem= sub-heading remains
4. Result: duplicated sub-headings

This compounds with [[id:BUG-013-literal-n-in-org-body-from-llm-tool-call]] because when the
body has literal =\n= instead of real newlines, the sub-headings in the body are not recognized
as headings — the entire body becomes a single line, making the duplication appear as a long
line with =\n= text followed by the original sub-headings.

* Implementation
** Target file
=packages/org/elisp/org-tasks.el= — function =org-tasks--edit-section-headline= (line ~626)

** Steps
In replace mode, change =body-end= to use =section-contents-end= instead of stopping at the
first sub-heading. This makes replace mode replace the ENTIRE section content (body text +
sub-headings), not just the text before the first sub-heading.

Current code (line ~636):
#+begin_src elisp
(body-end
  (save-excursion
    (goto-char body-start)
    (if (re-search-forward subheading-regexp section-contents-end t)
        (match-beginning 0)
      section-contents-end)))
#+end_src

Fix: compute body-end based on mode:
#+begin_src elisp
(body-end
  (if (string= mode "replace")
      section-contents-end
    (save-excursion
      (goto-char body-start)
      (if (re-search-forward subheading-regexp section-contents-end t)
          (match-beginning 0)
        section-contents-end))))
#+end_src

For append mode, keep the current behavior (append after body text, before sub-headings).

** Edge cases
- Section with no sub-headings: =section-contents-end= is already the fallback — no change
- Section with sub-headings where you only want to edit the text before them: this change
  makes that impossible in replace mode. Accept this: callers use replace to replace the full
  section content.
- Empty new body in replace mode: the delete-region call already handles this
