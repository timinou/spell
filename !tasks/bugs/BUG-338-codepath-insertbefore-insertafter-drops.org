* Symptoms

The LINE#ID anchor is silently dropped through 4 layers; kernel falls back to line=0.

* Root cause (4-layer drop)

1. =packages/coding-agent/src/tools/edit.ts:55= ~isLineIdAction~ returns true only for replace/append/prepend; insertBefore/insertAfter route through ~#executeStructural~ which forwards =pos= raw to kernel.
2. =crates/pi-code-path/src/ast.rs:394-399= ~Action::InsertBefore { lines }~ has NO pos/line field. Serde silently drops =pos= during deserialization (separate variant from ~Action::Insert { pos, line, lines }~).
3. =crates/pi-natives/src/code_path/code_resolver/mutation.rs:79= ~action_to_value~ re-serializes after the drop.
4. =crates/pi-natives/src/code_buffer.rs:763-771= ~action_line()~ reads only ~action.get("line")~; with line absent, returns 0 via ~unwrap_or(0)~.

Then =insert_before(buf, 0, ...)=:
- =crates/pi-code-engine/src/edit/replace.rs:21-31= rejects "Unsafe line-target insert-before at line 0" if content lacks newline.
- =crates/pi-code-engine/src/line_target.rs:25= rejects =line == 0= as "line out of range".

* Fix contract (D: structural collapse)

Collapse the AST asymmetry. ~Action::Insert~ and ~Action::InsertBefore~ become ONE variant family with optional anchor.

** AST
- =crates/pi-code-path/src/ast.rs=: change ~Action::InsertBefore { lines }~ to ~Action::InsertBefore { #[serde(default)] pos: Option<String>, #[serde(default)] line: Option<u32>, lines: ActionContent }~. Same for ~InsertAfter~.
- ~Action::Insert~ already has pos/line/lines — keep for backward compat OR remove if no callers depend on the unique kind="insert" tag (audit needed).
- Update ~ActionKind~ enum + ~kind()~ impl.

** Kernel dispatch
- =crates/pi-natives/src/code_buffer.rs:763= ~action_line()~: when ~action.line~ absent, parse ~action.pos~ as ="<n>#<id>"=, return n. Hash validation occurs in TS path, kernel just trusts the line component (or optionally re-validates).
- =crates/pi-code-path/src/dialects/text/anchor.rs= already has the line+hash parser; reuse it.

** TS dispatch
- =packages/coding-agent/src/tools/edit.ts:55= ~isLineIdAction~: include ~insertBefore~, ~insertAfter~, ~splice~. The dedicated ~#executeLineId~ path validates the anchor via ~parseTag~ and ~applyHashlineEdits~ before delegating; this is the preferred route.
- ~#executeLineId~ may need extension to support insertBefore/insertAfter semantics (insert N lines at byte offset of line start; verify hash before write).

** Schema + prompts
- =packages/coding-agent/src/tools/codepath-types.ts= editSchema description: explicitly document =pos= as supported on =insertBefore=/=insertAfter=/=splice=, format ="<line>#<id>"=.
- =packages/coding-agent/src/tools/edit.ts editDescription= (the prompt): show one example of insertBefore-with-LINE#ID.
