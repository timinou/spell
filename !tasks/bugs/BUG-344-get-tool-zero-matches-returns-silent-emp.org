* Intention & Purpose

When `get` resolves a target and finds zero matches, the `formatForTool` output must always include a human-readable diagnostic explaining what happened. Currently, when suffix fallback also finds nothing, a `§not-found` node is created with no `ZeroMatches` diagnostic — `formatForTool` renders empty string. Agent sees silence, abandons tool.

Evidence: session `14d54f5d0e274ba8` — `get` with glob `apps/agentmaker/**/*workbench*` returned `""`. Agent switched to `bash` for all subsequent file reading.

* Context & Narrative

The resolution chain:
1. `FsResolver::resolve()` calls `resolve_path_content()` → returns empty vec
2. `suffix_fallback()` tries fuzzy match → returns `None` (no candidates)
3. Currently: `diagnostics` stays empty, `§not-found` node is pushed with no `ZeroMatches` diagnostic
4. `formatForTool` in TS: checks `diagnostics.find(d => d.kind === 'zeroMatches')?.suggestion` → undefined → no "Did you mean" line → only renders the `§not-found` kind label which collapses to empty

Fix: always emit a `ZeroMatches` diagnostic, with a message that always renders. The `suggestion` field stays optional for the "Did you mean" rendering, but a `message` field provides the fallback text.

* Scope

In scope:
- `FsResolver::resolve()` in `fs/mod.rs`: always emit `ZeroMatches` diagnostic when nodes are empty
- `formatForTool` / `formatCodePathItem` in `codepath-result.ts`: render `diagnostic.message` as fallback when `suggestion` is absent
- Unit test: empty glob produces visible diagnostic text

Out of scope:
- Changing suffix_fallback algorithm
- CWD context (separate bug)
- Empty-string guard at the tool handler level (separate bug)

```rust
if nodes.is_empty() {
    if let Some(suggestion) = suffix_fallback(&locator, &self.workspace_root, fetch_opts) {
        diagnostics.push(Diagnostic {
            kind: DiagnosticKind::ZeroMatches { suggestion: Some(suggestion) },
            ..
        });
    }
    nodes.push(resolved_node(ResolvedNode {
        kind: "§not-found".into(),

        ..

}
```

```typescript

    const diagnostics = item.diagnostics || [];
```
