* Initial Message

When a tool-arg stream stalls, the diagnostic stored in the transcript carries =rawPartialJsonArtifact.uri= but the user-visible / assistant-visible error message doesn't surface it. The agent has no way to read what it had partially streamed and recover (e.g., split the write into pieces).

In the example session the user manually told the assistant: "if it's not, write the document in several pieces than concatenate them. Keep the same scope and the exact same content that you were about to write." That instruction would be unnecessary if the assistant could read =artifact://<session>/main/tool-call-diagnostic/<n>.json= directly.

* Cause

=packages/ai/src/utils/tool-call-diagnostics.ts::formatToolCallStreamDiagnosticMessage= concatenates state + idle timeout + retries, but never includes =diagnostic.rawPartialJsonArtifact.uri= even though the field exists on =ToolCallStreamDiagnostic= and is already populated.

* Fix

Append the artifact URI to the formatted message when present, e.g.:

#+begin_src
Tool call create stalled while streaming incomplete tool arguments. Parsed keys: _i, path. Idle timeout: 180000ms. Retry attempts: 3. Partial arguments saved to artifact://14d6b8621f4e3f90/main/tool-call-diagnostic/238.json (115 bytes) — read it with the get tool to recover and continue.
#+end_src

* Acceptance

- =formatToolCallStreamDiagnosticMessage= includes the artifact URI and byte size when =rawPartialJsonArtifact= is set
- Existing test in =packages/coding-agent/test/session/tool-call-diagnostics.test.ts= updated for new format

* Resolution [2026-05-06]
=formatToolCallStreamDiagnosticMessage= now appends "Partial arguments saved to <uri> (<bytes> bytes) — read it with the get tool to recover." when =rawPartialJsonArtifact.uri= is present. Test in =tool-call-diagnostics.test.ts= asserts the URI is surfaced.
