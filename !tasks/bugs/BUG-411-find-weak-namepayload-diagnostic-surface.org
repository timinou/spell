* Initial Message

* Initial Message

=find { target: "**/*.md::§line[text~=\"LINE#HASH\"]" }= returns valid results plus:

#+begin_example
...results...

Diagnostics:
[unsupported_operation] weak NamePayload parse: glob FS prefix uses generic DotLexer
#+end_example

Agents read "unsupported_operation" as a hard error and fall back to bash grep — exactly the anti-pattern PLAN-317 was supposed to eliminate.

* Root Cause

=crates/pi-natives/src/code_path/napi.rs:360-369= emits this diagnostic whenever an FS prefix contains glob magic before =::=. The diagnostic is *informational* (fallback to generic name lexer is correct), but its variant (=UnsupportedOperation=) and wording read as error. It is also redundant when the query head is =NodeKind=, =FieldName=, or =AnchorName= — the name lexer is never used in those cases.

* Scope

In:
- =crates/pi-natives/src/code_path/napi.rs= — reword + demote variant + suppress when the head doesn't use the name lexer.
- New =DiagnosticVariant::Informational= in =crates/pi-code-path/src/types.rs=.
- Renderer in =packages/coding-agent/src/tools/codepath-result.ts= — suppress =Informational= when nodes ≠ []; surface on zero results.

Out:
- Changing the lexer fallback behavior.
- Reworking the parser's glob/predicate boundary (covered by BUG-405).
