* Initial Message

User report: "submit_result hangs and then it fails". The visible "hang" is a 9-32s window between submit_result returning and the subagent process actually exiting.

* Cause

Two combined effects in =packages/coding-agent/src/task/executor.ts=:

1. =verifyGates(...)= is awaited synchronously inside the =tool_execution_end= handler. This blocks the rest of the event pipeline (subsequent events from the subagent JSONL queue up). Git operations on a large repo add seconds of wall-clock.

2. =requestAbort("terminate")= calls =activeSession.abort()= which cancels in-flight provider streams, but does NOT prevent the agent loop from kicking off the NEXT assistant turn after submit_result's tool result is delivered. Evidence from session =14d6907eb0fbe7f4=:
   - 0-Feat722RustHandlers: submit_result returned 20:21:13.601, next assistant turn at 20:21:45.395 (32s of pointless "task complete" thinking)
   - 4-Feat727PromptUpdate: submit_result returned 20:59:49.019, next assistant turn at 20:59:58.510 (9s)

The subagent burns tokens, holds resources, and the user sees the agent as "still working" even though it's done.

Side effect: if the next turn races with the abort signal, =finally= block at =executor.ts:1638-1646= sets =exitCode = 1=. Combined with BUG-354, this can manifest as failed status.

* Fix

1. Add a =terminating= flag to the subagent session loop. When =requestAbort("terminate")= fires due to a successful submit_result, set =terminating = true= BEFORE calling abort. The agent loop checks this flag before issuing the next =session.prompt(...)= and refuses to start a new turn.
2. Move =verifyGates(...)= off the event-handling hot path. Run it in a deferred Promise: optimistically terminate on submit_result(success), then await gates; if gates fail, un-terminate and inject the reminder. Net latency on the success path drops from "verify+terminate" to "terminate; verify in background".

- Subagent that calls submit_result(success) with passing gates exits within 1s of the tool result being recorded (no extra assistant turn)
- No regression: gate-failed path still triggers the reminder loop and gives the agent a chance to repair
- Test: success-path subagent transcript ends with the submit_result toolResult message (no trailing assistant message)

* Resolution [2026-05-06]
Introduced =terminating= flag in the agent loop scope. When =shouldTerminate= fires from a successful =submit_result=, the flag is set BEFORE =requestAbort("terminate")=.
