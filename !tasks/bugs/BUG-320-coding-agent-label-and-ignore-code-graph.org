* Scope
In scope: make `.spell/graph` generated artifacts unsurprising. Keep project-local graph artifacts, but ensure they are ignored, status-labeled, and documented in code-tool output. Primary observation: graph ops created `.spell/graph/workspace.bin`; vector cache `.spell/graph/workspace-vectors.bin` is also possible and currently not fully surfaced.

Out of scope: moving graph artifacts out of the repo, making graph indexing ephemeral, or changing org cache behavior except where shared cache status helpers make it unavoidable.

* Existing Patterns
- Graph cache creation: `crates/pi-natives/src/code_graph.rs`; `run_code_graph()` creates `CacheStore::new(root.join(".spell/graph"))` with `CACHE_NAME = "workspace"` and `VECTORS_CACHE_NAME = "workspace-vectors"`.
- Cache abstraction: `crates/pi-workspace-cache/src/lib.rs`; `CacheStore::entry_path(name)` persists `<name>.bin`.
- Status output: `crates/pi-natives/src/code_graph.rs`; `render_status()` computes graph `cache_status`, vector `semantic_status`, and `format_status()` prints graph status. Current output does not clearly identify artifact paths or gitignore expectation.
- TS formatting: `packages/coding-agent/src/tools/code-result.ts`; `CodeGraphDetails` stores `cacheStatus`, `rebuilt`, `semanticStatus`, but graph content mostly returns native `details.output`.
- `.gitignore` already contains an entry for graph `workspace.bin`; `workspace-vectors.bin` must be added if missing.

* Tests
User workflows to cover first:
1. Running `code status` after graph indexing tells the user graph cache path, cache freshness, vector cache status, and whether rebuild happened.
2. `.spell/graph/workspace.bin` and `.spell/graph/workspace-vectors.bin` are ignored by default.
3. If vector cache is missing/stale/corrupt, status labels it without failing graph status.
4. Graph context/impact output can include a concise cache status hint when rebuild occurs, but should not bury semantic results.
5. No tracked source changes appear solely because graph cache was created.

- `packages/coding-agent/test/tools/code.test.ts`: if TS formatter adds status labels around graph output.
- `.gitignore`: static verification by test or checklist.
