* Context
The Phoenix Inspector ~dispatchQuickFix()~ in QML captures element screenshots and sends them in the ~images~ field of the ~_tier: "task"~ payload. The TypeScript backend (~runQuickFixTask~ in ~index.ts~) ignores this field entirely. The task agent never learns a screenshot was captured, making the "Include screenshot" checkbox misleading.

Additionally, ~runQuickFixTask~ calls ~pi.pi.runSubprocess(...)~ without a runtime guard. While this IS a public contract (the ~pi.pi~ namespace is ~typeof piCodingAgent~), a defensive check with a clear error message prevents cryptic failures if the runtime shape changes.

* Implementation
** Extract images from the task payload in ~runQuickFixTask()~
   Parse the ~images~ field from the bridge payload using a new ~payloadImageArray()~ helper or inline extraction.

** Append image metadata to the assignment text
   Match the ~canvas-task-manager.ts~ pattern (line 176-178): when images are present, append ~"

N screenshot(s) attached."~ to the assignment text. This is the canonical framework pattern; structural image forwarding is tracked by [[id:FUP-035-thread-images-through-executoroptions-to]].

** Add a runtime guard before calling ~pi.pi.runSubprocess~
   Check ~typeof (pi.pi as Record<string, unknown>).runSubprocess === "function"~ before the call. On failure, throw a descriptive error: ~"Quick Fix task dispatch requires pi.pi.runSubprocess, which is not available in this runtime."~
