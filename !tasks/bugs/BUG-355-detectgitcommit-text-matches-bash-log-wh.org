* Initial Message

Subagents that genuinely commit hit "gateCommit not satisfied: expected =git commit=; No git commit execution was detected." See session =14d6907eb0fbe7f4= where multiple subagents fired the reminder loop despite committing.

* Cause

=packages/coding-agent/src/task/gate-verification.ts:detectGitCommit=:

#+begin_src ts
export function detectGitCommit(executions: TrackedBashExecution[]): boolean {
  return executions.some(execution => /\bgit\s+commit\b/.test(execution.command));
}
#+end_src

This is text-matching against the bash event's =args.command= string. False-negative paths:

1. Subagent runs the commit through =bash -c '... git commit ...'= or a heredoc / multi-line script where the text isn't matched by the regex (=unwrapTransparentCommand= covers some shells but not all wrappers).
2. Subagent uses a tool wrapper (e.g. async dispatch, chained commands) where the stored =args.command= doesn't include the verb.
3. Out-of-order events: bash event arrives after =submit_result= was already evaluated.
4. =progress.extractedToolData.bash= is empty for any race/filtering reason.

The worktree branch =detectGitCommitInWorktree= is robust (=git rev-parse HEAD != baseline=) but only fires when BOTH =worktreeDir= AND =baselineHeadCommit= are set. For non-worktree tasks with a known baseline, this evidence is ignored.

* Fix

1. Whenever a =baselineHeadCommit= is captured (whether or not a worktree is active), use =git rev-parse HEAD= against the relevant cwd as the primary signal. Fall back to bash text matching only when no baseline exists.
2. Improve =extractCommandPreamble= to peek into single-arg =bash -c "..."= / =sh -c "..."= and recursively look for =git commit= inside the inner string.
3. Add a unit test for: heredoc-wrapped =git commit=, =bash -c '...git commit...'=, baseline-advanced HEAD with NO bash entry.

* Acceptance

- A subagent that commits via =bash -c "...git commit..."= passes gateCommit
- A subagent in a non-worktree task with baselineHeadCommit captured + HEAD advanced passes gateCommit even if no bash entry mentions git
- Existing positive/negative tests still pass
