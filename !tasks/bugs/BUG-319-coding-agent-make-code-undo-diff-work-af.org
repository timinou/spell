* Scope
In scope: make `code undo`, `code redo`, and `code diff` observable and useful after the `CodeTool` auto-saves edits to disk. User contract: `code diff` shows unsaved buffer-vs-disk hunks when dirty plus uncommitted git working-tree diff for code-tool-edited files from journal/history, tagged by the editing agent/session. `code undo`/`code redo` must work after auto-save within the live managed buffer session.

Out of scope: cross-restart persistent undo/redo containing full source contents. The existing journal stores attribution metadata, not full inverse patches; this plan must not silently introduce a source-content journal without an explicit privacy/security design. Cross-session attribution for diff labels is in scope via existing journal metadata.

* Existing Patterns
- TypeScript finalization: `packages/coding-agent/src/tools/code.ts`; `#finalizeEditExecution()` performs staged native edit, optional formatter, then `save`.
- Native buffer save/edit: `crates/pi-natives/src/code_buffer.rs`; `execute_edit_command()` supports `saveMode: staged|auto`; `save` currently persists through `BufferRegistry::edit_transaction`.
- Engine history: `crates/pi-code-engine/src/buffer.rs`; `History` tracks forwards/inverses, `saved_revision`, and session attribution; `CodeBuffer::save_with_watcher()` preserves history and marks saved, while `BufferRegistry::edit_transaction()` commits and closes the buffer.
- Journal attribution: `crates/pi-code-engine/src/coord/journal.rs`; `JournalEntry` has `session_id`, `revision`, `parent_revision`, `code_paths`, `diff_hash`, `byte_len`.
- Result formatting: `packages/coding-agent/src/tools/code-result.ts`; diff currently renders only “Unsaved diff ... (N hunks)” and undo/redo renders “had no effect” when native returns no entries.

* Tests
User workflows to cover first:
1. `code edit` auto-saves a file; immediate `code undo` on that file changes the file back and reports applied entries.
2. Immediate `code redo` reapplies the auto-saved edit and reports applied entries.
3. `code diff` after auto-save no longer misleadingly says only `0 hunks`; it reports clean unsaved state and, when git working tree differs, shows persisted working-tree diff tagged with the last journal agent/session.
4. If buffer is dirty from an unsaved operation, `code diff` shows unsaved hunks first and still includes persisted journal/git attribution separately.
5. Undo/redo remain session-scoped: revisions from peer sessions are skipped according to existing `undo_scoped` design.
6. If git is unavailable, diff still reports unsaved state and journal attribution without failing the command.

* Implementation
1. First fix native/engine save semantics so undo/redo after CodeTool auto-save has real state to operate on.
2. Add journal-aware diff attribution without storing source contents in journal.
3. Update result formatting to avoid plausible lies: `0 unsaved hunks` is acceptable only when persisted diff/attribution is shown separately.

* Edge Cases
- Save failure after staged edit must still surface as failure and leave mutation state truthful.
- Formatting before save may add an extra revision; undo should revert the whole user-visible code edit transaction or clearly show multiple entries.
- Peer session edits must not be undone by the current session.
- Deleted or newly-created files need diff/undo behavior defined in tests.

* Acceptance Criteria
- The Clojure trial sequence `code edit` → `code undo` visibly reverts the saved change.
- `code redo` reapplies it.
- `code diff` after auto-save shows persisted working-tree diff and agent/session attribution when git has uncommitted changes.
- No source-content journal is introduced without explicit design.
