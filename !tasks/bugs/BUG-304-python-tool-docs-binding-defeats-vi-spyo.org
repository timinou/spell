* Scope
Test: test/tools/python.test.ts "renders dynamic helper docs" fails because the tool description does not reflect the mocked prelude docs.

Root cause: `src/tools/python.ts:11` uses a destructured named import:
#+BEGIN_SRC typescript
import { executePython, getPreludeDocs, type PythonExecutorOptions } from "../ipy/executor";
#+END_SRC

`getPythonToolDescription` calls the directly bound `getPreludeDocs` reference. The test does:
#+BEGIN_SRC typescript
vi.spyOn(pythonExecutor, "getPreludeDocs").mockReturnValue(docs);
#+END_SRC
`spyOn` rewrites the property on the module namespace, but `python.ts` already holds the original reference via the destructured import. The mock never takes effect.

Settled design: switch to namespace import in `python.ts` so `spyOn` works. Memory note already records this pattern: "Bun module mocks leak \u2014 use spyOn/injection".

In scope: change the import form; update the one call site.
Out of scope: introduce DI for doc providers (considered and declined).
