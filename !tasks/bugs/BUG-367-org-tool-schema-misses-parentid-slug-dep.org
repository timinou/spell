* Symptom
Calling org suboutline-add with parentId + slug + title from a coding-agent
session fails with:
    {"error":true,"message":"GenericFailure, Missing required field: id"}

Root cause: the agent-facing JSON schema does not declare parentId, slug,
depends, or layer as accepted fields. The agent SDK strips unknown fields
before forwarding, so by the time the dispatcher reads args.parentId it is
undefined. The error message is misleading -- it surfaces an internal
"id required" check rather than naming the actually-missing field.

* Drift surfaces (two of them)

** packages/coding-agent/src/tools/org.ts:27 (the LLM-facing schema)
orgSchema TypeBox object declares:
  command, title, category, state, properties, body, append, manifest,
  planItemId, section, file, dir, priority, layer, agent, query, ql,
  includeBody, sort, limit, offset, id, note, property, value
MISSING: parentId, slug, depends

The "command" description string lists only:
  init | create | query | get | update | delete | note | set | validate
  | validate-plan | dashboard | wave | graph | archive
MISSING from docs: suboutline-add, recall, remember, timeline, subgraph, link
(all 6 subcommands exist in the dispatcher at packages/org/src/tool.ts:1354+)

** packages/org/src/tool.ts:1233 (the tool's own parameters schema)
Declares ONLY `command` as a property. Every other field the dispatcher
reads (id, title, body, parentId, slug, ...) is undocumented. This is
"loose JSON schema by intent" -- works because callers know the shape --
but it's fragile and any agent SDK that schema-validates strictly will
break the same way.

* Fix shape (proposed)

A) Update orgSchema in coding-agent/src/tools/org.ts:
   - Add parentId: Type.Optional(Type.String({...}))
   - Add slug:     Type.Optional(Type.String({...}))
   - Add depends:  Type.Optional(Type.Array(Type.String(), {...}))
   - Expand "command" description to enumerate ALL 20 subcommands
   - Add explicit per-command "required fields" hints

B) Update packages/org/src/tool.ts:1233:
   - Replace the {command-only} parameters schema with the full set
   - Better: derive both schemas from a single shared SoT module
     `packages/org/src/tool-schema.ts` exporting the JTD shape; both
     tool.ts (internal) and coding-agent/tools/org.ts (LLM-facing)
     import it.

C) Improve the error message:
   When suboutline-add dispatcher receives args without parentId, return
   { code: "MISSING_PARENT_ID", message: "suboutline-add requires parentId" }
   instead of the generic "Missing required field: id" stemming from
   downstream updateItem.
