* Goal

Replace silent ~.catch(() => {})~ error swallowing on status-file write and cleanup paths with ~logger.warn()~ calls so that write failures are observable in spell logs.

* Context

~StatusFileWriter.writeIfChanged()~ persists the recovery snapshot that ~spell recover~ depends on. The current ~Bun.write(filePath, ...).catch(() => {})~ silently discards all write failures (permissions, disk full, shutdown timing). When recovery metadata fails to persist, the user sees missing or stale sessions in ~spell recover~ with no explanation.

The method must stay synchronous (fire-and-forget) because callers invoke it on every session state change from a synchronous context. The fix is to log failures, not to make the method async.

* Design Decision

- Replace ~.catch(() => {})~ with ~.catch(err => logger.warn("StatusFileWriter: write failed", { path: filePath, err: String(err) }))~ on the ~Bun.write~ call in ~writeIfChanged()~.
- Replace ~.catch(() => {})~ with ~.catch(err => logger.warn("StatusFileWriter: cleanup failed", { path: filePath, err: String(err) }))~ on the ~fs.rm~ call in ~cleanup()~.
- The ~logger~ import already exists in ~status-file.ts~ (used by ~StatusFileReader~).
