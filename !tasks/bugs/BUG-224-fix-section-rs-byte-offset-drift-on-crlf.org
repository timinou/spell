The `str.lines()` iterator in Rust returns lines without the terminator. For a file ending with `\n`, the last yielded line has `line.len()` not counting the `\n`. The `offset = line_end + 1` works correctly because `line_end` is the byte position of the last char of the line (exclusive of `\n`), and `+1` skips the `\n`.

And for `\r\n` files, `str.lines()` strips `\r` from the yielded text, so `line.len()` is shorter than the actual bytes between line separators, making `offset` drift out of sync. The comment says `(approx — handles \n)` which acknowledges the issue.

This is a correctness issue for `\r\n` files. However, org files are typically `\n`-only (created by the TS writer which uses `\n`), so the practical impact is low.

### 1. Silent data loss when deserializing TS items in NAPI bridge
- **What**: `parse_items_from_options` in `org_buffer.rs` silently drops items that fail serde deserialization via `filter_map(|v| serde_json::from_value(v.clone()).ok())`. TS `OrgItem` objects lack `byte_range` (a required field with no `#[serde(default)]`), so ALL items will fail to deserialize, producing an empty vec.

- **Why**: `cmdWave` and `cmdGraph` in tool.ts pass TS-constructed items to `executeOrg({ command: "computeWaves", items })`. * Problem

=find_section= in =crates/pi-org-engine/src/section.rs= uses =str.lines()= to iterate over lines and manually tracks byte offsets with =offset = line_end + 1=. This has two correctness issues:

1. **CRLF drift**: =str.lines()= strips =\\r= from line text, so =line.len()= is one byte too short for =\\r\
= files. Each line adds 1 byte of drift, compounding over the file. After N lines, the offset is off by N bytes.

2. **Last line without trailing newline**: For files not ending in =\
=, the last line's =offset = line_end + 1= points 1 byte past the actual content end. This can cause off-by-one in section boundary detection.

Both issues produce silently corrupted section edits (wrong byte ranges → wrong content replaced or appended at wrong location).

Risk is LOW because the TS org-writer produces =\
= files. But org files from external sources (git clones on Windows, copy-paste from editors) can have =\\r\
=.

#+begin_src rust
pub fn find_section(
    source: &str,
    item_start: usize,
    item_end: usize,
    section_name: &str,
) -> Option<(usize, usize, usize)> {
    let region = source.get(item_start..item_end)?;
    let bytes = region.as_bytes();
    let mut pos = 0usize;
    let mut found_heading_level = 0usize;
    let mut body_start = 0usize;

    while pos < bytes.len() {
        // Find end of current line
        let line_start = pos;
        let line_end = memchr_or_end(bytes, b'\
', pos);
        // Trim \\r if present
        let text_end = if line_end > line_start && bytes[line_end - 1] == b'\\r' {
            line_end - 1
        } else {
            line_end
        };
        let line = &region[line_start..text_end];

        if let Some(level) = heading_level(line) {
            let heading_text = extract_heading_text(line, level);
            if found_heading_level > 0 && level <= found_heading_level {
                return Some((
                    item_start + body_start,
                    item_start + body_start,
                    item_start + line_start,
                ));
            }
            if heading_text.eq_ignore_ascii_case(section_name) {
                found_heading_level = level;
                body_start = if line_end < bytes.len() { line_end + 1 } else { line_end };
            }
        }

        // Advance past the newline (or to end)
        pos = if line_end < bytes.len() { line_end + 1 } else { bytes.len() };
    }

    if found_heading_level > 0 {
        return Some((item_start + body_start, item_start + body_start, item_end));
    }
    None
}

fn memchr_or_end(bytes: &[u8], needle: u8, start: usize) -> usize {
    bytes[start..].iter().position(|&b| b == needle).map_or(bytes.len(), |p| start + p)
}
#+end_src

Also add a guard in =find_section= for =item_start..item_end= being out of bounds (use =source.get()= which returns =None= instead of panicking on invalid ranges).

#[test]
fn find_section_crlf() {
    let src = \"** Context\\r\
Old content.\\r\
\\r\
** Implementation\\r\
Code here.\\r\
\";
    let result = find_section(src, 0, src.len(), \"Context\");
    assert!(result.is_some());
    let (_, start, end) = result.unwrap();
    let body = &src[start..end];
    assert!(body.contains(\"Old content.\"));
    assert!(!body.contains(\"** Implementation\"));
}

fn find_section_no_trailing_newline() {
