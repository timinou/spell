* Intention &amp; Purpose

Fix streamBetterCcflare constructing `http://localhost:8080/v1/v1/messages` (double /v1/) which causes better-ccflare proxy to return 404.

* Context &amp; Narrative

PLAN-293 implemented a better-ccflare provider. The first user test returned:
  Error: 404 {"type":"error","error":{"type":"not_found_error","message":"Not found"}}

better-ccflare's own request log shows the root cause:
  "path": "/v1/v1/messages"
  "statusCode": 404

The Anthropic JS SDK internally prefixes all routes with /v1/. streamBetterCcflare was also appending /v1/ to baseURL, creating a double prefix. streamAnthropic does not append /v1/ — it passes the base URL directly and lets the SDK handle routing.

Confirmed via curl:
  /v1/messages     → 503 (correct path, SDK adds /v1/ internally)
  /v1/v1/messages  → 404 (current bug)
