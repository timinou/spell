* Problem

=save_vector_cache()= in =crates/pi-natives/src/code_graph.rs= writes to a deterministic temp path =workspace-vectors.bin.tmp=. Two concurrent semantic-index runs (e.g., parallel agent sessions on the same workspace) can clobber the same temp file or fail during rename, reintroducing a race in the cache persistence path that PLAN-190 was supposed to eliminate.

* Design Decision

Include the process ID in the temp filename: =format!("{VECTORS_CACHE_NAME}.{}.bin.tmp", std::process::id())=.

- PID uniqueness is sufficient for same-machine concurrency (the typical scenario).
- No external crate dependency needed.
- The rename still targets the same final path, so the atomicity guarantee is preserved.
- On failure, the PID-scoped temp file is left behind but does not interfere with the final path or other processes.
