* Root Cause

In =packages/coding-agent/src/tools/create.ts=:

#+begin_src ts
const sessionCwd = this.session.cwd;
const resolvedPath = path.isAbsolute(params.path)
  ? params.path
  : path.resolve(sessionCwd, params.path);
#+end_src

And success render:
#+begin_src ts
.text(`Created ${params.path} (${stat.size} bytes)`)
#+end_src

Three compounding factors:
1. *Naive resolve* — =path.resolve(sessionCwd, params.path)= silently double-prefixes when =params.path= already starts with the cwd's tail segment.
2. *Misleading echo* — success message returns =params.path= (relative-as-given), not the resolved path. Agent has no feedback signal to detect mis-placement on the next turn.
3. *cwd ≠ namespace root* — agents read AGENTS.md, plan org items, specs, code-review notes that all address files as =apps/hotelcomm/lib/...= from the monorepo root. The harness session cwd is =/monorepo/apps/hotelcomm=. Agent's mental model and tool's resolution root disagree silently.

Recurrence across 3 agents → not a model slip; deterministic for any agent that takes the monorepo-root view (the natural reading).

* Scope

In scope:
- =packages/coding-agent/src/tools/create.ts= — duplication guard + resolved-path echo
- =packages/coding-agent/src/tools/edit.ts= — same guard for =kind: "create"= / =kind: "write"= when the target is a new file path
- =packages/coding-agent/src/prompts/tools/create.md= — document cwd resolution
- system prompt boot — surface cwd vs git-toplevel asymmetry when they differ

Out of scope:
- Changing the resolution root (sessionCwd stays correct semantics)
- Auto-correcting the duplication silently (we reject + diagnose)

* Implementation

** A. Duplication guard

In =CreateTool.execute=, after computing =resolvedPath= for relative paths:

#+begin_src ts
if (!path.isAbsolute(params.path)) {
  const cwdSegments = sessionCwd.split(path.sep).filter(Boolean);
  const pathSegments = params.path.split(path.sep).filter(Boolean);
  const overlap = longestSuffixPrefixOverlap(cwdSegments, pathSegments);
  if (overlap > 0) {
    const stripped = pathSegments.slice(overlap).join(path.sep);
    return toolResult({ path: params.path, error: "cwd_prefix_duplication" })
      .text(`Path "${params.path}" appears to include the cwd prefix `
          + `"${cwdSegments.slice(-overlap).join(path.sep)}". `
          + `Session cwd is ${sessionCwd}. `
          + `Pass "${stripped}" (relative to cwd) or an absolute path.`)
      .done();
  }
}
#+end_src

Where =longestSuffixPrefixOverlap= returns the longest k such that =cwd.endsWith(path[0..k])= matches. Handles =apps/hotelcomm= + =apps/hotelcomm/...= and deeper duplications.

Apply the same guard in =EditTool= for =kind: "create"= and =kind: "write"= on new-file paths.

** B. Echo resolved path in success message

#+begin_src ts
const relFromCwd = path.relative(sessionCwd, resolvedPath);
.text(`Created ${relFromCwd} (${stat.size} bytes)
   → ${resolvedPath}`)
#+end_src

The relative-to-cwd echo gives the agent immediate, unambiguous feedback. The absolute path lets the agent disambiguate cwd assumptions on first inspection.

** C. Update =prompts/tools/create.md=

Add to top of doc:
- "Paths resolve from session cwd, NOT from project / git root."
- "Pass paths relative to cwd, or use absolute paths."
- "If you'd write =apps/hotelcomm/lib/...= in a spec and cwd is =apps/hotelcomm=, pass =lib/...=."

** D. Surface cwd asymmetry in system prompt

Where the agent system prompt renders cwd, also detect git-toplevel and warn when they differ:

#+begin_src
cwd: /home/user/code/ora/monorepo/apps/hotelcomm
(git root: /home/user/code/ora/monorepo — paths resolve from cwd, not git root)
#+end_src

Renders only when =cwd !== git-toplevel=. No noise for sessions at repo root.

* Edge Cases

- Duplication overlap of length k where k > path-segment-count: clamp to min(cwd-segs, path-segs).
- Symlinks in cwd: resolve once, then compare segments — don't realpath, as it would change other semantics.
- Case-insensitive filesystems: leave case-sensitive; cwd is normally lowercased and false positives from case skew are rare and recoverable.
- Whitelist absolute path inputs: do not run the guard for absolute paths.
