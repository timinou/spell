* Initial Message

The =get= tool already emits a structured =OUT_OF_PROJECT_ROOT=
diagnostic when an absolute *file* path sits outside the walker
root (BUG-348). The same condition for an absolute *directory*,
*glob*, or *qualified* target silently degrades to
=[§no-results] empty-result=.

In a session whose cwd was =/home/user/code/ora/cais= the user
saw three failures (BUG-371, BUG-372 cover the first two). The
third — =get { target: "." }= → =empty-result= — looked like the
listing tool was broken, when the actual cause is the same
out-of-root scoping that BUG-348 already diagnoses for files.

User direction: =let it walk outside by default=. Until that
default flips (tracked in FUP-086), the immediate fix is to make
the failure mode honest — same =OUT_OF_PROJECT_ROOT= diagnostic
for directories, globs, and qualified absolute paths.

* Symptom
1. =get { target: "/home/user/code/ora/cais" }= run from a
   spell session rooted at =/home/user/code/ora/spell= →
   =[§no-results] empty-result= (no =OUT_OF_PROJECT_ROOT=).
2. =get { target: "/some/abs/path/*" }= same.
3. =get { target: "/some/abs/path/#tree" }= same.
4. =get { target: "/some/abs/path/file.txt" }= correctly emits
   =OUT_OF_PROJECT_ROOT=. The asymmetry is the bug.

* Root Cause
=packages/coding-agent/src/tools/get.ts= guards out-of-root paths
only inside =classifyBareTarget(target) === "bare-plain"= and
only when =stat()= reports =isFile()=. Three branches drop out:

#+begin_example
if (params.content !== false && !looksLikeRegex
    && classifyBareTarget(target) === "bare-plain") {
    …
    if (stat.isFile()) {
        if (!inRoot) {  // ← only place OUT_OF_PROJECT_ROOT is raised
            …
        }
    } else if (stat.isDirectory()) {
        target = buildDirQualifier(normalized, params); // no root check
    }
}
#+end_example

- Directories: stat probe attaches =#listing= and hands off; the
  walker silently returns =[]=.
- Globs: =classifyBareTarget= returns ="other"=; the probe is
  skipped entirely.
- Qualified targets (=path#tree=, =path#stat=, …):
  =classifyBareTarget= returns ="qualified"=; probe skipped.

The kernel walker has no notion of "you asked for an absolute
path outside my root" — it just returns =[]=. The user-facing
result is indistinguishable from "exists but everything is
gitignored", which is the exact confusion BUG-348 was supposed to
end.

* Acceptance
- For every absolute target whose resolved path is outside the
  walker root (file, dir, glob, qualified, or with shorthand
  slice), =get= emits a single structured =OUT_OF_PROJECT_ROOT=
  diagnostic with =project root=, =resolved=, and the same
  =gitignore: false= / =root:= hint already used for files.
- =gitignore: false= continues to short-circuit file reads
  (BUG-348). For dirs/globs/qualifiers, the diagnostic explains
  that =gitignore: false= alone won't reach the path and points at
  the =root:= override.
- The check happens *before* the kernel call so the diagnostic is
  unambiguous; we do not first run the walker and then guess.

* Edge Cases
- Relative paths are unchanged (resolved against =cwd= → always
  in-root by construction).
- =memory://=, =artifact://=, =skill://=, =rule://=, =agent://=
  URIs are unaffected (routed before the FS check).
- Symlinks pointing outside root: treated as out-of-root.
- The session's =root= override (=root: "/other/path"=) shifts the
  comparison anchor as expected.
