What happened? What does it mean?

* Problem

~tree-selector.ts~ renders session entries via ~#getEntryDisplayText~ and ~#applyFilter~.
Four ~SessionEntry~ types are unhandled in both the display switch and the settings filter:

- ~mode_change~ — plan mode transitions
- ~service_tier_change~ — API tier changes
- ~session_init~ — subagent debug entries
- ~ttsr_injection~ — time-traveling rule injections

These entries:
1. Pass through the default filter (shown to user in default view)
2. Get ~result = ""~ from the ~default~ switch branch
3. During streaming partial updates, tool call metadata may be ~undefined~ at interpolation time, producing the literal string ~[undefined] undefined~

The ~#getSearchableText~ method has the same gap — missing handlers for these four types.

* Affected file

~packages/coding-agent/src/modes/components/tree-selector.ts~

Three methods need changes:
- ~#getEntryDisplayText~ — add case handlers for each missing type
- ~#getSearchableText~ — add case handlers for search indexing
- ~#applyFilter~ — add ~service_tier_change~, ~mode_change~, ~session_init~, ~ttsr_injection~ to ~isSettingsEntry~

Write a focused unit test that exercises ~#getEntryDisplayText~ (and the related filter) by constructing minimal ~SessionTreeNode[]~ arrays containing entries of every type, instantiating ~TreeList~, and asserting:
