The kernel artifact.rs profile uses ProjectRoot with rel=.spell/sessions and PathLayout::Direct. The TS ArtifactProtocolHandler uses getSessionsDir() which is ~/.spell/agent/sessions/ (UserRoot, NOT ProjectRoot), AND does cross-project session lookup via a regex-suffix index on dir names matching SESSION_ROOT_NAME_RE = /_([0-9a-f]+)$/i.

Two parity gaps:

1. Wrong root: ProjectRoot vs UserRoot. Quick fix: change RootTemplate to UserRoot { rel: ".spell/agent/sessions" }.

2. Cross-session lookup. Given artifact://<sessionId>/<agent>/<tool>/<file>, kernel must scan <sessions>/<project>/ to find a dir whose name suffix matches sessionId. Requires an IndexLookup impl.

Implementation:
1. Update artifact.rs:
   - RootTemplate::UserRoot { rel: ".spell/agent/sessions" }
   - Replace ContentLoader::FsRead with ContentLoader::Indexed
   - PathLayout::Indexed (body opaque to layout, lookup handles parsing)
2. Add crates/pi-natives/src/code_path/uri/artifact_index.rs implementing IndexLookup. Logic:
   - Parse body as <sessionId>/<agent>/<tool>/<file>
   - Read sessions root, iterate project dirs
   - For each project dir, iterate child dirs looking for name matching /_<sessionId>$/i
   - On match, return path: <project>/<match>/<agent>/<tool>/<file>
   - With small mtime-cached index for repeat lookups
