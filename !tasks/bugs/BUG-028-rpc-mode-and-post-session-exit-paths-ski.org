* Initial Message

Yo bro are emacs sessions properly disposed of at the end of all spell sessions regardless of the exist mode?

Several exit paths call =process.exit()= after the session has been created but without calling =session.dispose()= first.

* RPC mode (=packages/coding-agent/src/modes/rpc/rpc-mode.ts=)
- Line 672: =checkShutdownRequested()= → =process.exit(0)= (no dispose)
- Line 701: stdin closed → =process.exit(0)= (no dispose)

* Main command (=packages/coding-agent/src/main.ts=)
- Line 729: no model available → =process.exit(1)= (session already created at line 681)

These exits leak the Emacs daemon because =toolSession.dispose()= (which calls =emacsSessionManager.dispose()=) is never invoked.

After BUG-025 (postmortem registration), the signal-based cleanup path covers these if =postmortem.quit()= is used instead of bare =process.exit()=. But the correct fix is explicit cleanup.

* Fix
1. RPC mode: call =session.dispose()= before both =process.exit(0)= calls, or replace with =postmortem.quit(0)=
2. Main.ts line 729: call =session.dispose()= before =process.exit(1)=, or replace with =postmortem.quit(1)=
3. Audit: grep for any other =process.exit()= calls after session creation that skip dispose
