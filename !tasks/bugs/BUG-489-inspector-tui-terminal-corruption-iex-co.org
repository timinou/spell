* Defects

** D1 — terminal corruption + doubled composer (HIGH)
Symptom (user screenshots): the bordered "prompt" composer box renders TWICE at
different vertical offsets, and garbage/scrollback bleeds above the TUI frame.

Root cause (reasoned from source — a real TTY could not be driven in the agent
sandbox to observe directly, so labeled a strong hypothesis, not a confirmed
repro): `SpellAgent.tui/0` calls `App.start_link` and RETURNS immediately to the
iex shell. ExRatatui's local Server then runs in the alternate screen + raw mode
polling stdin on the DirtyIo scheduler, WHILE the iex shell process keeps doing
its own `IO.gets` on stdin and printing `iex>` prompts to stdout. Two concurrent
readers of stdin and two writers of stdout on the same TTY ⇒ frames land at
drifting cursor offsets (the doubled composer) and the shell's output bleeds
through (the garbage band). Confirmed in deps: native `init_terminal` does
`enable_raw_mode` + `EnterAlternateScreen` (terminal.rs:92-94), so a clean
FOREGROUND run would not corrupt — the corruption is the iex co-tenancy.

Fix: the TUI must own the TTY exclusively. Provide a foreground entrypoint that
BLOCKS until the app stops (a `mix spell.tui` task and/or `tui/0` that monitors
the server pid and waits), instead of returning to a live iex shell. Update the
README to stop recommending `SpellAgent.tui()` from inside iex.

** D2 — final answer never shown (HIGH, confirmed)
Confirmed in lib/spell_agent/tui/app.ex: the mission runs in a Task; its result
arrives as `handle_info({ref, _result}, state)` but `_result` (the `{:ok,
answer}` / `{:error, reason}` from `Session.run/1`) is DISCARDED — the handler
only sets `running?: false`. So the user watches the whole run but never sees the
model's final answer.

Fix: capture the Task result and surface it — a dedicated result line/area
showing the final answer (or error), styled prominently.

** D3 — low readability (MEDIUM)
The span-tree pane is the only output; no run status summary, no result line,
rows are terse and uncoloured beyond status glyph. The user explicitly asked for
output "that's easier for me".

Fix: add a header/status line (running… / done in Nms, turns, tool count) and a
result line; keep the tree but make the active run obvious. Optionally print a
plain final summary to stdout on quit.
