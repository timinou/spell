`tests/memory-loop.test.ts` (PLAN-310 W10) writes into the real
fixture tree `tests/fixtures/memory-corpus/.spell/memory/{concepts,episodes}/`
during execution. No `afterAll` cleanup. Concretely, files left behind
between runs include:

- `concepts/since-test.org`
- `concepts/test-concept--a-test-concept-body-for-in.org`
- `episodes/EP-2026-05-15-auth-discovery.org`
- `episodes/2026-05-{today}.org`

** Consequences

1. First clean checkout: `bun test tests/memory-loop.test.ts` →
   tests have known-good baseline, some pass.
2. Second run (state leaked): subset of assertions now collide with
   pre-existing state; failure mode differs run-to-run.
3. `git stash` cycles fail with "files would be overwritten by merge"
   because the leaked files are untracked.
4. CI is presumably immune (fresh checkout each time), so this hides.

** Targets

- `tests/memory-loop.test.ts`
  - per-test temp dir, OR a global beforeAll/afterAll that cleans the
    leaked filenames
- Prefer temp dir: each test gets its own corpus root passed via the
  memory tool's `repoRoot` parameter (already supported).

** Acceptance

- `bun test tests/memory-loop.test.ts` twice in a row → identical
  pass/fail counts.
- `git status` after a test run shows zero new files under
  `tests/fixtures/memory-corpus/.spell/memory/`.
- The shared corpus tree (`CON-auth-flow`, `CON-jwt`,
  `CON-token-expiry`, `CON-vendor-coordination`) remains intact — only
  test-generated content gets cleaned.

** Difficulty

~1h. Soft because:
- memory tool already supports per-call `repoRoot`
- `bun:test` has standard `afterAll` hook
- the fixture root is small and well-bounded

Sharp edges:
- T10.4-style tests that exercise the warm-cache fast path may need
  warm pre-seeding to be moved into beforeAll for the temp corpus.
