Yo bro are emacs sessions properly disposed of at the end of all spell sessions regardless of the exist mode?

The =EmacsSessionManager= (=packages/emacs=) is never registered with the postmortem cleanup system. When signals (SIGINT from outside, SIGTERM, SIGHUP) hit the process, postmortem runs registered callbacks, but Emacs cleanup is absent. The daemon survives as an orphan.

SSH and Python cleanups are registered at sdk.ts:432-440. Emacs needs the same treatment.

* Affected files
- =packages/coding-agent/src/sdk.ts= — add =postmortem.register("emacs-cleanup", ...)=

The registration must return a cancel function; store it and call it in =toolSession.dispose()= to avoid double-dispose.
