* Scope
In scope: make file-scoped `code` commands accept both local declaration IDs and graph/workspace fully-qualified IDs while continuing to display local IDs in file-local output. Primary regression: Clojure workspace lookup can return `src/clojend/ga/admission.clj::clojend.ga.admission/admit-candidate`, but `code edit` currently resolves only `src/clojend/ga/admission.clj::admit-candidate` and reports `Symbol 'clojend.ga.admission/admit-candidate' not found. Available: [...]`.

Out of scope: changing graph target IDs, changing user-visible outline IDs to fully-qualified forms, adding compatibility shims that preserve two canonical representations. The chosen representation remains local display + permissive command input.

* Existing Patterns
- TypeScript tool entry: `packages/coding-agent/src/tools/code.ts`; `parseTargetId(targetId)` splits `<file>::<symbol>`, `normalizeOperations()` forwards target IDs to native buffer, file commands route through `executeCodeBuffer`.
- Native file commands: `crates/pi-natives/src/code_buffer.rs`; `parse_target_id()`, `resolve_target_id()`, `file_target_id_for_path()`, `symbol_target_id()`.
- Symbol resolver: `crates/pi-code-engine/src/resolve.rs`; `resolve_symbol(buffer, profile, symbol)` currently matches declaration names and dotted members, then errors with available local names.
- Clojure profile: `crates/pi-code-engine/src/language/mod.rs`; Clojure declarations are local names extracted from list forms (`defn`, `ns`, etc.). Graph qualified names are produced separately in `crates/pi-code-graph/src/language/clojure.rs`.

* Tests
User workflows to cover first:
1. Agent copies a workspace symbol result `src/app/core.clj::app.core/normalize-name` into `code edit`; edit succeeds and target summary displays local `src/app/core.clj::normalize-name` or otherwise makes accepted alias obvious.

5. Invalid qualified symbols still fail truthfully with available local names plus an alias hint, not a silent fallback.
