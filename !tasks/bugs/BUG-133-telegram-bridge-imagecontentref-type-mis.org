* Problem
The =ImageContentRef= type in =spell-server= does not match the =ImageContent= type from =@oh-my-pi/pi-ai= that =coding-agent= expects. Two fields diverge:
- =type= discriminant: ="base64"= vs ="image"=
- mime type field name: =media_type= vs =mimeType=

When Telegram sends a photo, the bridge creates an =ImageContentRef= with the wrong shape. The coding-agent RPC mode passes =command.images= directly to =session.prompt()= without transformation. The Anthropic provider reads =block.mimeType= (undefined) and sends the API request missing =media_type=, causing a 400 error.
