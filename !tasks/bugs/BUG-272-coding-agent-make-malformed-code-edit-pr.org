* Scope
- In scope: make `code` results and previews tell the truth when an edit is malformed, formatter-altered, or rejected by the structural invariants from `BUG-270-coding-agent-harden-code-edit-target-res`.
- In scope: expose enough before/after context and exact target metadata that a maintainer can see why an edit was unsafe, instead of only seeing a compact diff summary like the malformed previews in transcript `14be281c6474c15d`.
- In scope: preserve that truthfulness through TUI preview, final tool result rendering, and transcript rebuild paths.
- Out of scope: changing prompt wording or native target-resolution semantics. Those are handled by sibling items `BUG-271-coding-agent-align-code-edit-prompts-exa` and `BUG-270-coding-agent-harden-code-edit-target-res`.

* Tests
- Workflow 1: malformed or structurally rejected edits render as errors, not `Edited …`, and clearly state whether the failure happened at payload validation, target resolution, unsafe boundary detection, or post-apply structural validation.
- Workflow 2: applied edits show exact enough context to reveal token concatenation or formatter-induced cleanup; compact output must not hide the only corrupted line.
- Workflow 3: result details preserve exact target/path metadata needed for transcript rebuild and TUI preview so live output and rebuilt transcript tell the same story.
- Workflow 4: no-op, applied, preview-pending, discarded, and failed edit states remain distinct and truthful after formatter activity.

* Edge Cases
- Formatter output can differ from the immediate edit diff; the renderer must not imply that formatter success proved the original mutation was safe.
- Large diffs may be truncated, but the preserved context must still include the corruption/failure line rather than arbitrary first hunks.
- A failed edit after preview must not share the same headline/body as a no-op or discarded preview.
- Truthfulness must survive transcript rebuild, not only the live TUI path.

* Acceptance Criteria
- Malformed/rejected edits are visibly failures, not successful edits with cryptic diff previews.
- Applied edit output preserves enough exact context to diagnose boundary-splice problems.
- Live preview and rebuilt transcript show the same failure/apply story.
- Focused renderer/tool tests lock the user-visible contract for failed, applied, previewed, and no-op code edits.
