* Symptom
Anthropic 400: `messages.N.content.M: unexpected tool_use_id found in tool_result blocks: toolu_…. Each tool_result block must have a corresponding tool_use block in the previous message.`

* Root cause
Two =tool_result= blocks emitted for one =tool_use= id (=proxy_ask=, =toolu_012TiT…=), the second orphaned by an intervening user message:

#+begin_example
msg[316] assistant : tool_use    toolu_012TiT (proxy_ask)
msg[317] user      : tool_result toolu_012TiT err=true  "No result provided"  ← synthetic
msg[318] user      : text        "DID:… STUCK:…"                              ← user steering
msg[319] user      : tool_result toolu_012TiT err=false [real ask answer]     ← real, late
#+end_example

Sequence:
1. assistant calls =proxy_ask= → turn pending
2. user steers with a NEW text message instead of answering; real ask-result lands later in history
3. =transformMessages= 2nd pass sees the user-text interrupt the pending call → injects synthetic "No result provided" before the user msg, marks the id =Resolved=
4. the real result arrives later → current code only skips =Aborted=, not =Resolved= → pushed too
5. Anthropic merges the user turns; result 319's preceding message is user text (318), not an assistant tool_use → 400

* Fix
=packages/ai/src/providers/transform-messages.ts= toolResult branch: a =tool_use= takes exactly one result. Skip a duplicate when the id is already =Resolved= (not just =Aborted=). Keep-first → the kept result stays adjacent to its tool_use; the late orphan is dropped.

* Scope
- packages/ai/src/providers/transform-messages.ts (one-result-per-tool_use dedup guard)
- packages/ai/test/duplicate-tool-results.test.ts (regression: assistant(toolCall) → user(text) → real toolResult ⇒ exactly 1 result, adjacency preserved)
