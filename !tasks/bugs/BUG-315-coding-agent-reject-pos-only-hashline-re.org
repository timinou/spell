- Prompt/schema guidance: rewrite `pos` and `end` descriptions in `hashlineEditSchema` and the instruction/critical sections of `packages/coding-agent/src/prompts/tools/hashline.md` to state explicitly that `pos` alone replaces exactly one line, `lines` length has no effect on span, and multi-line ranges require `end`. Add one worked counterexample to the examples section.
- Focused regression tests at the runtime layer (`test/core/hashline.test.ts`) and the tool contract layer (`test/tools.test.ts`).

* Edge Cases

- `op: "replace"` with both `pos` and `end` supplied but identical (same `LINE#ID`): unchanged existing behavior — range collapses to single-line replace, `lines` may be any length. The new span check does NOT apply when both anchors are present.
- `op: "replace"` with `pos` only and `lines: []`: existing delete-one-line idiom, still accepted. Span check skips the empty case explicitly.
- `op: "replace"` with `pos` only and `lines: [""]`: length 1, still accepted (inserts a blank line in place of the source line). Span check only triggers for `length > 1`.
