* Symptom
`restructure move` on a decorated/attributed declaration stranded its decorations. E.g. moving an attributed Rust fn down produced:
#+begin_example
#[inline]
#[inline]

fn alpha() {...}      ← bare fn moved, BOTH attributes left behind
fn beta() {...}
#+end_example
Latent: tree-sitter models Rust `attribute_item` and TS/JS/Python `decorator` as *siblings* of the declaration, not children. The pre-PLAN-332 line-leaf drag resolved the bare `function_item` and swapped only its span; the new span-anchored resolver did too — both stranded attributes.

* Surfaced by
PLAN-332 Thesis A reviewer swarm (P1). The unified resolver made the gap visible; investigation showed it pre-existed (Rust attributed move never worked).

* Root cause + Fix (crates/pi-code-engine/src/edit/drag.rs)
The move swapped *bare declaration node* spans. Now it swaps whole *statement units*:
- `is_decoration_sibling(node)` — true for `attribute_item` | `decorator`.
- `sibling_pair` skips decoration siblings when finding the adjacent declaration to swap with (a decoration belongs to the decl that follows it).
- `statement_unit_span(node)` — extends the moved span backward over immediately-preceding decoration siblings.
- `drag_node` swaps the two unit spans (decoration-inclusive), and runs the shared-boundary guard on the unit span.

* Tests
- `drag_rust_attributed_item_down_does_not_error` (attributes travel with the fn).
- Existing TS method + top-level + boundary tests unchanged (7 drag tests green).
