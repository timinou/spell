Why do subagents return aborted even though the message in the chat is that it's completed?

* Problem
When a subagent completes its work but fails to call ~submit_result~ (e.g., model doesn't support forced tool choice, hits context limits, or confuses the tool name), the executor marks the result as ~aborted~ even though the agent produced valid output. The user sees "⏹ aborted" in the TUI while the agent's output text clearly shows completed work.

Confirmed from session data: ~gpt-5.3-codex~ model via ~openai-codex-responses~ API failed to call ~submit_result~ after 3 reminders (on the 3rd attempt, it called ~fetch~ with URL ~https://submit_result://complete~).

* Root Cause
In ~packages/coding-agent/src/task/executor.ts~ lines 1121-1126:
#+begin_src typescript
if (!submitResultCalled && !abortSignal.aborted) {
    aborted = true;        // <-- problem
    exitCode = 1;          // <-- problem
    abortReasonText ??= SUBAGENT_WARNING_MISSING_SUBMIT_RESULT;
    error ??= SUBAGENT_WARNING_MISSING_SUBMIT_RESULT;
}
#+end_src

Setting ~aborted = true~ and ~exitCode = 1~ creates a circular dependency:
1. ~done.aborted = true~ → ~doneAborted = true~ in ~finalizeSubprocessOutput~
2. ~allowFallback = exitCode === 0 && !doneAborted~ → ~false~
3. Fallback path (raw output acceptance) is blocked
4. ~wasAborted = !hasSubmitResult && done.aborted~ → ~true~
5. ~progress.status = "aborted"~

* Fix
Remove ~aborted = true~ and ~exitCode = 1~ from the missing-submit-result block. Keep only the error message for diagnostics:
#+begin_src typescript
if (!submitResultCalled && !abortSignal.aborted) {
    error ??= SUBAGENT_WARNING_MISSING_SUBMIT_RESULT;
}
#+end_src

This lets ~finalizeSubprocessOutput~ handle the fallback correctly:
- ~doneAborted = false~ → ~allowFallback = true~
- ~resolveFallbackCompletion~ tries to parse raw output as structured data
- If no schema: raw output accepted, ~exitCode = 0~ → "completed"
- If schema but can't parse: warning prepended, ~exitCode = 0~ → "completed" (with warning)
- Genuine aborts (signal, explicit abort via submit_result) still correctly show "aborted"
