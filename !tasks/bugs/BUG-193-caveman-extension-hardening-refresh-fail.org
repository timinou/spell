* Context
Audit AUD-049 found three issues in ~packages/coding-agent/src/extensibility/extensions/caveman.ts~:
1. ~/caveman~ reports success even when prompt refresh fails
2. Fire animation timer runs in non-interactive sessions (print mode, RPC, subagents)
3. Config dialog uses global ~theme~ import instead of the theme passed by ~ui.custom()~

All fixes are in the same file, non-overlapping, and small.

* Acceptance Criteria
- When ~refreshBaseSystemPrompt()~ throws, ~/caveman~ notifies the user of the degraded state instead of reporting success
- ~syncStatus()~ short-circuits when ~ctx.hasUI === false~, preventing ~setInterval()~ in non-interactive contexts
- ~CavemanSettingsDialog~ receives the active theme from the ~ui.custom()~ factory callback, not the global import
- ~bun check:ts~ passes
- The focused caveman test (sibling item) covers all three paths

* Implementation

** 1. Propagate refresh failure from ~refreshPrompt()~
File: ~packages/coding-agent/src/extensibility/extensions/caveman.ts~

Change ~refreshPrompt~ to return ~boolean~:
#+BEGIN_SRC typescript
const refreshPrompt = async (ctx: ExtensionContext): Promise<boolean> => {
  try {
    await ctx.refreshBaseSystemPrompt();
    return true;
  } catch (error) {
    logger.warn("Failed to refresh caveman system prompt", {
      error: error instanceof Error ? error.message : String(error),
    });
    return false;
  }
};
#+END_SRC

In ~applyRuntimeLevel~, check the return:
#+BEGIN_SRC typescript
const applyRuntimeLevel = async (nextLevel: CavemanLevel, ctx: ExtensionCommandContext): Promise<void> => {
  settings.override("caveman.defaultLevel", nextLevel);
  level = nextLevel;
  api.appendEntry("caveman-level", { level: nextLevel });
  syncStatus(ctx);
  const ok = await refreshPrompt(ctx);
  if (!ok) {
    ctx.ui.notify("Caveman mode set but prompt refresh failed — may not take effect until next turn", "warning");
  }
};
#+END_SRC

In ~restoreFromSession~, keep silent on failure (background restore, no user action). Already logs via ~refreshPrompt~.

In ~updatePersistedSetting~, the call is ~void refreshPrompt(ctx)~ — keep fire-and-forget but add a catch notification:
