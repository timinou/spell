## Symptom

`packages/coding-agent/src/tools/edit.ts::#executePatch` routes `kind: "filePatch"` actions to `applyPatch()` (from `patch/applicator.ts`) which writes via `SimpleFileSystem` → `fs.writeFile`. This BYPASSES executeCodePath entirely.

Consequences:
- ❌ No broker coordination (peer can race-overwrite)
- ❌ No journal append (.spell/edit-history.jsonl)
- ❌ No session_id attribution
- ❌ No buffer registry invalidation (open buffers go stale)
- ❌ No edit_transaction atomicity (no snapshot-restore on failure)
- ✓ Has its own structural validation

## Why this is wrong post-PLAN-309

The kernel has `Op::FilePatch { target, diff }` fully implemented at `crates/pi-code-path/src/dialects/text/mutation.rs:174`. It's wired through dispatch_op, goes through buf.edit_batch, gets full broker + journal + transaction semantics. The TS-side bypass is now legacy behavior.

## Severity

P1 — works correctly in isolation but breaks the "one canonical edit path" invariant PLAN-309 established. Concurrent agents could race-overwrite each other's patch edits without broker detecting.

## Fix scope

Replace `#executePatch` with a dispatch to `#executeStructural` with `kind: "filePatch", diff: ...`. Delete the SimpleFileSystem class. Delete the applyPatch import in edit.ts (other consumers may need it; check).

Tests need verification — some TS-local patch tests may exercise the SimpleFileSystem code path; migrate them to verify kernel-side behavior.
