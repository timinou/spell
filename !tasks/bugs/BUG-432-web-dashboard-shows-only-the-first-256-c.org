* Initial Message

1. why do sessions not show their history when I connect with them on the server?
2. why are the open sessions showing only the beginning of sessions? [Image #1]

* Initial Message

On the spell-server web dashboard, each session shows only the *beginning* of
assistant content — a few wrapped lines, then a =[HH:MM:SS] · end= footer. The
footer is the =turn_end= log entry, NOT a truncation marker; the real loss is
upstream: assistant text is hard-clipped before it leaves the CLI.

* Root Cause (verified)

External (terminal) CLI sessions mirror activity to the dashboard via the
low-fi =event_log= summary channel. Assistant messages are emitted as a single
=assistant_text= entry that is clipped at the source:

- =packages/coding-agent/src/session-bridge/client.ts:15= —
  =const EVENT_LOG_TEXT_MAX = 256;=
- =packages/coding-agent/src/session-bridge/client.ts:184= —
  clip applied: =entry.text.length > EVENT_LOG_TEXT_MAX ? slice(0, MAX) : entry=
- Emitted from =packages/coding-agent/src/modes/interactive-mode.ts:1503= on
  =message_end= via =bridge.emitEventLog({ kind: "assistant_text", ts, text })=.

256 chars is roughly 3 wrapped terminal lines — exactly what the screenshot
shows before =· end=. The remainder is discarded at the CLI; the dashboard
never receives it.

NB: spawned sessions stream full text via the *unclipped* =rpc_event= path
(=message_update= / =text_delta=), so this defect is specific to the external
=event_log= summary path.

* Scope

In:
- Make assistant (and user) message content reach the dashboard un-truncated
  for external sessions.
- Preferred approach: stream assistant text for external sessions through the
  same chunked, unclipped channel spawned sessions use (text deltas / a
  dedicated full-text event), rather than a single clipped summary line.
- If the chunked route is out of reach for the bridge transport, raise/remove
  =EVENT_LOG_TEXT_MAX= for =assistant_text=/=user_message= kinds specifically,
  with a sane upper bound and chunking so a single frame cannot be unbounded.
- Keep the tool_call/tool_result/turn markers as compact summaries (they are
  intentionally low-fi and not affected).

Out:
- The "no history on connect" backfill defect (tracked separately).
- Reworking the blocking-event / inject protocol.
- Spawned-session rendering (already unclipped).

Rationale:
- Repo evidence: the clip is unconditional for any =entry.text= over 256 chars,
  applied to =assistant_text= the same as a one-line tool intent.
- Repo evidence: spawned sessions already prove an unclipped streaming path
  exists end-to-end (=StreamRenderer.renderRpcEvent= handles =text_delta=).

* Existing Patterns

- =packages/spell-server/web/src/detail/StreamRenderer.ts= — =renderRpcEvent=
  already renders streaming =text_delta= for spawned sessions with no clip;
  =renderEventLogEntry= renders the clipped external summary. Converge external
  assistant text onto the richer path or feed it full text.
- =packages/coding-agent/src/session-bridge/client.ts= — =emitEventLog= is the
  single clip site; any kind-specific exemption or chunking lands here.
- =packages/coding-agent/src/modes/interactive-mode.ts= =#setupBridgeEventLog=
  — the =message_end= to =assistant_text= mapping is where a chunked emit would
  be produced if we split long messages.
- =packages/spell-server/src/socket/session-registry.ts= — ring-buffer entries
  must stay bounded in memory; a chunking strategy keeps per-frame size sane
  without one giant string.

* Edge Cases

- A very long single message must not produce one unbounded WS frame — chunk it.
- Ring-buffer memory: chunked entries must still respect the bounded ring; do
  not let one message evict the entire backfill window unintentionally.
- Mixed content (assistant text + tool calls in one turn): ordering preserved.
- Non-text/attachment messages: =extractMessageText= empty so still no emit.
- Backward compatibility: an older CLI still clipping must not break the newer
  renderer (treat absent chunks as a single entry).

* Acceptance Criteria

- Assistant and user messages render in full on the dashboard for external
  sessions, regardless of length.
- No single WS frame exceeds the documented cap; chunking preserves order.
- Compact tool/turn summaries remain low-fi and bounded.
- Spawned-session rendering is unchanged.
