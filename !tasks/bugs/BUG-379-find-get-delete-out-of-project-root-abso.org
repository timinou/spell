Find the root cause of this issue; this is a confusing surface for the get/find tools....

* Initial Message

User direction (2026-05-16): "what is most ergonomic? please
explain simply and comprehensively" → conclusion: =OUT_OF_PROJECT_ROOT=
should not exist. An absolute target carries its own scope; the
project-root guard exists to protect *relative* targets from
escaping the session cwd, not to deny absolute targets the kernel
can otherwise read.

This supersedes FUP-086 (KDL =fs.walk-mode= scheme): no new
config knob, no allowlist/denylist, no three-mode toggle. Just
delete the wall.

* Symptom

In a spell session rooted at =/home/user/code/ora/spell=, the user
tried to read tantivy source from the cargo registry:

#+begin_example
get { target: "/home/user/.cargo/.../tantivy-0.26.1/src/directory" }
  → [§no-results] empty-result (silent; BUG-373 escape hatch did not fire
                                because the file is a *directory*, not
                                a file path going through the bare-plain
                                short-circuit's isFile() branch)

find { target: ".../tantivy-0.26.1/src/**/*lock*" }
  → OUT_OF_PROJECT_ROOT
    hint: "pass gitignore: false to read this file directly"
  ↑ misleading: find has *no* gitignore parameter (findSchema is one-field).

get { target: ".../src/", gitignore: false }
  → [§no-results] empty-result
  ↑ broken: gitignore:false short-circuit only handles isFile(); for
    directories the bare-plain branch silently re-falls-through to the
    kernel walker.
#+end_example

The error class is artificial. The kernel can walk arbitrary
absolute paths when given the right =root=. The TS surface was
fighting that capability.

* Root Cause

=packages/coding-agent/src/tools/get.ts= treats =isInsideRoot(prefix, cwd)=
as a hard wall and forces the caller to pass an escape hatch
(=gitignore: false= for files; =root: "..."= for everything else).
But:

1. The =gitignore: false= escape only works for *files* (the
   =stat.isFile()= branch at L220). Directories, globs, and
   qualified targets silently degrade to =empty-result= because
   the bare-plain =isDirectory()= branch never checks =inRoot=.

2. The =root:= override works for both =get= and =find=, but
   =findSchema= does not expose =root= or =gitignore=, so the
   diagnostic's hint is unreachable from =find=.

3. The pre-check at L170 is skipped whenever =gitignore === false=,
   which silences the only diagnostic dirs/globs would have gotten,
   producing the silent =empty-result= the user saw.

The underlying truth: an absolute target like =/abs/dir/= is
self-scoping. The session's project root is only meaningful for
*relative* paths (`src/foo.ts`, `**/*.rs`) where the walker must
choose a base. For absolute targets the walker simply needs the
right base — which we already have, embedded in the target.

* Acceptance

** Behaviour
- =get { target: "/abs/file.rs" }= → reads the file.
- =get { target: "/abs/dir/" }= → lists the directory.
- =get { target: "/abs/dir/#tree" }= → tree.
- =get { target: "/abs/dir/**/*.rs" }= → walks under =/abs/dir/=.
- =get { target: "/abs/file.rs::§line[text~='TODO']" }= → grep.
- =find { target: "/abs/..." }= → identical (no schema changes).
- =get { target: "src/foo.rs" }= → unchanged (resolves against session cwd).
- =get { target: "**/*.rs" }= → unchanged (scoped to session cwd).
- =get { target: "../../etc/passwd" }= → unchanged (still resolves against cwd, still scoped).

** Surface
- =OUT_OF_PROJECT_ROOT= error class deleted from =get.ts= and from
  =GetToolResultDetails.error= contract.
- =isInsideRoot= helper deleted (no other consumers).
- =gitignore: false= remains as the escape hatch for *in-root*
  gitignored files. Out-of-root semantics no longer depend on it.
- =findSchema= unchanged (still single =target= field).
- Diagnostic hint =(hint: pass gitignore: false …)= deleted.

** Mechanism
=get.ts= computes an =effectiveRoot= by extracting the longest
absolute directory prefix from =target= (stripping qualifier,
symbol query, and glob tail). When the caller passes =root:=
explicitly, that wins. When the target is relative, =sessionCwd=
wins. The result is threaded through both the bare-plain stat
probe and =executeCodePath({ root })=.

* Edge Cases

- Symbolic links: pass through to kernel; permission/cycle handling
  remains kernel's responsibility.
- Symlink that points outside the chosen root: same as today.
  Kernel walker rules apply.
- =~/foo= shorthand: not currently expanded by =get= (out of scope).
- Absolute glob with no fixed prefix (=/**/foo=): degenerate;
  prefix becomes =/=, walker root =/=. Same behaviour as kernel
  invoked with =root: "/"=. Accept and let kernel decide.
- =canonicalize= is NOT applied: the user gave an absolute path,
  honour it lexically. Symlink-escape protection was never offered
  by the previous code either.
- =gitignore: false= for an in-root file: unchanged.
- =gitignore: false= for an out-of-root file: no longer special — the
  file is reachable through the auto-root, gitignore semantics still
  apply within that root.
