* Scope

The link-extraction regex in =packages/org/src/id-links.ts:7= and the matching =parseSubOutlineId= contract reject sub-outline IDs whose suffix contains uppercase letters. Concrete failure: =[[id:PROJ-052-pi-code-path-crate-codepath-v3-parser-as::proj-ast-types]]= does not parse because the sub-slug regex is =[a-z0-9-]+= but the repo's actual sub-outline naming convention uses uppercase-prefixed slugs (=proj-ast-types=, =feat-sigil-grammar=, =proj-cutover-tool-deletion=).

Effect: =org validate-plan= reports =manifest-missing-suboutlines= for every linked child whose declared sub-outlines use uppercase prefixes — *including* multiple in-flight plans (PLAN-255, presumably others). The plan engine itself works fine (different parser); only the pre-flight validator fails.
