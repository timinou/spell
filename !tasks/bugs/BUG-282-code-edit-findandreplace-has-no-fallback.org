* Scope

* Background

Observed failure (planner self-report, PLAN-248): `findAndReplace` with a snippet that appeared twice in scope (two adjacent `VectorRetriever.search(..., visibility: visibility)` lines) returns `Err("Patch 1: find text is ambiguous, found at 2 locations (lines 71, 73)")` with no way to select the intended occurrence. Forces the caller to pivot to much larger edits.

Current native impl (`crates/pi-code-engine/src/edit/patch.rs:46-61`) hard-errors on `matches.len() > 1`. The N positions are already computed; selection is a 5-line addition. This is a contract gap, not a semantic bug.

** Rewrite apply_patches selection logic
:PROPERTIES:
:CUSTOM_ID: BUG-282-code-edit-findandreplace-has-no-fallback::selector
:DEPENDS: BUG-282-code-edit-findandreplace-has-no-fallback::enum

- File: `crates/pi-code-engine/src/edit/patch.rs`
- In the match-loop:
  - `matches.is_empty()` → existing error.
  - Select:
    - `Unique`: keep current ambiguous error, with hint text updated.
    - `First`: take `matches[0]`.
    - `Last`: take `matches[matches.len() - 1]`.
    - `Index(n)`: 1-indexed; out-of-range error.
    - `All`: iterate all matches, emit N edits; the existing overlap guard already protects.
- Error message for ambiguous `Unique` case updated to hint about the selector.

- File: `crates/pi-natives/src/code_buffer.rs` (`findAndReplace` dispatcher).

* Edge cases

- `All` with overlapping replacements: caught by the existing overlap guard (`apply_patches` lines 82-88).
- `Index(0)`: reject as out-of-range (1-indexed).
- Empty `find` string: existing `needle_lines.is_empty()` short-circuit → no-op; keep behavior.
- Multi-patch action array: each patch carries its own `occurrence`.
- Scope-zero matches under `All`: returns success with zero edits (no-op); document as idempotent.
