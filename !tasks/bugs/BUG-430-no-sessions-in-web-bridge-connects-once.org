Reported by user: "I see no running sessions in the web thing." Two distinct root causes.

* Cause A — bridge connected only once (FIXED, commit be2980703)

=SessionBridgeClient= connected a single time at TUI startup; the only reconnect path
(=socket.on("close")= → =#attemptReconnect=) fired solely after an ESTABLISHED connection
dropped, capped at 3 attempts. So:
- a =spell= TUI started BEFORE the server never registered;
- after a server restart, every session permanently dropped after ~7s.

Fix: added a persistent supervisor (=start()= + =#scheduleSupervise=) that (re)connects forever
with capped backoff (500ms..15s) until =dispose=, re-registering on every connect. =main.ts= now
keeps the bridge regardless of initial reachability. Covered by =test/session-bridge/supervisor.test.ts=.
