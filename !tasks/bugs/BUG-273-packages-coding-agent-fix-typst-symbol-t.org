* Scope
- In scope:
  - Fix `code edit` symbol-target resolution for Typst callable `#let` bindings such as `#let section-block(num, title, body) = ...`.
  - Make missing-symbol diagnostics truthful for Typst code wrappers so `Available: [...]` lists actual top-level names instead of `[]`.
  - Align the code-graph extractor used by `code symbols` with the native resolver so the canonical target name for callable Typst lets is the base binding name (`section-block`), not the full pattern text.
  - Keep display/signature context available for humans while making machine-targeted symbol identity stable.
- Out of scope:
  - General line-target semantics for Typst `code` wrappers. The current `raw node 'let' expands to editable scope 'code'` refusal is conservative and correct unless a separate design says line edits should auto-pick `let`.
  - Arbitrary Typst pattern destructuring beyond callable/simple let bindings.
  - Broad multi-language audits; handled by [[id:BUG-274-packages-coding-agent-audit-wrapper-and]].

* Existing Patterns
- `packages/coding-agent/src/tools/code.ts`
  - `GRAPH_COMMANDS` routes `symbols` through graph search, while `edit` goes through native file-buffer execution.
  - This split is the first source of drift to eliminate or explicitly cover with tests.
- `crates/pi-natives/src/code_buffer.rs`
  - `resolve_target()` is the native entry point for symbol-targeted edits.
  - Any bug visible in `code edit` must be reproduced here, not patched in the TUI layer.
- `crates/pi-code-engine/src/resolve.rs`
  - `resolve_symbol()` → `find_symbol_node()` performs exact symbol matching.
  - `collect_top_level_names()` currently builds the `Available: [...]` list and must use the same wrapper-unwrapping rules as actual resolution.
- `crates/pi-code-engine/src/outline.rs`
  - `declaration_name_resolution()` / `resolution_from_node()` currently derive local declaration names.
  - This logic is duplicated conceptually in graph extraction and is the likely invariant boundary to centralize.
- `crates/pi-code-engine/src/language/mod.rs`
  - Typst declarations use `DeclarationPattern { node_types: ["let"], name: NameExtractor::Field { name: "pattern" }, ... }`.
  - Callable Typst lets currently surface full pattern text (`section-block(num, title, body)`) instead of stable binding names.
- `crates/pi-code-graph/src/language/generic.rs`
  - `resolve_name_for_extractor()` mirrors declaration-name extraction for graph indexing.
  - `collect_symbol_entry()` writes `ExtractedSymbol.name`; this must match the native resolver’s canonical symbol identity.
- `crates/pi-code-graph/src/query.rs`
  - `exact_symbol_matches()` matches on `symbol.name` / `symbol.qualified_name`; fixing canonical names here improves `code symbols` exact-match behavior without UI hacks.
- `packages/coding-agent/src/prompts/tools/code-hint-typst.md`
  - Update only if needed after behavior is settled; avoid promising syntax the resolver still does not support.
