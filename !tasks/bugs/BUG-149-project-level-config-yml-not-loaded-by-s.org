* Root Cause

The builtin settings discovery provider (=packages/coding-agent/src/discovery/builtin.ts=, =loadSettings()= at line 763) only looks for =settings.json= in directories returned by =getConfigDirs()=. For the native provider, =getConfigDirs()= returns:
1. =<cwd>/.spell/= (project level) — looks for =.spell/settings.json=
2. =~/.spell/agent/= (user level) — looks for =settings.json=

The =Settings= class loads global config from =~/.spell/agent/config.yml= via =#loadYaml()=, which works. But there is no equivalent project-level YAML path. Users who place =.spell/agent/config.yml= in their project directory (mirroring the global convention) get a dead file that nothing reads.

The =Settings.#loadProjectSettings()= method calls =loadCapability(settingsCapability.id)= and filters for =level === "project"=. Since the builtin provider never produces a project-level YAML item, project YAML settings are invisible.
