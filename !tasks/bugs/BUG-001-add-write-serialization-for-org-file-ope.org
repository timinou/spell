** Problem
Even with unique tmp paths (BUG-001), concurrent read-then-write cycles on the same org file
cause silent data loss. Two operations read the same content, compute independent mutations,
and the second write overwrites the first's changes.

Affected functions in ~packages/org/src/org-writer.ts~:
- ~appendItemToFile~ (read file -> serialize -> atomicWrite)
- ~applyItemMutations~ (read file -> mutate lines -> atomicWrite)
- ~setPropertyInFile~ (read file -> set property -> atomicWrite)

Additionally, ~cmdCreate~ in ~packages/org/src/tool.ts~ calls ~generateId~ (scans files for max sequence)
then ~appendItemToFile~. Two concurrent creates in the same category can generate duplicate sequence numbers.

** Approach: In-process KeyedMutex
Create a ~KeyedMutex~ class — a ~Map<string, AsyncMutex>~ that lazily creates per-key mutexes.
This is sufficient because the org tool runs in a single process.

~AsyncMutex~ implementation (simple Promise-chain lock):
#+begin_src typescript
class AsyncMutex {
  #tail = Promise.resolve();
  async acquire(): Promise<() => void> {
    const { promise, resolve } = Promise.withResolvers<void>();
    const prev = this.#tail;
    this.#tail = promise;
    await prev;
    return resolve;
  }
}
#+end_src
