* Tests
- Workflow 1: `code edit { operation: "create" }` rejects stray `resolution` / `offset` / `line` / `edits` before any native call.
- Workflow 2: line-target `insert-after` into a TypeScript import or interface member with multi-line content fails with an explicit error unless the edit targets a safe enclosing declaration/sibling boundary.
- Workflow 3: symbol/line replacement must not duplicate `export`/modifier text or partially splice declaration tokens when raw-node and editable-scope targets diverge.
- Workflow 4: mixed edit batches are atomic; one invalid edit entry prevents all mutations and keeps undo history unchanged.
- Workflow 5: parse-invalid post-edit results fail before save/format, so formatter success cannot mask a structurally bad mutation.

* Edge Cases
- Formatter cleanup can make a malformed import insertion look valid after save; validation must happen before formatter success is considered proof.
- Empty `node_type` line-target edits currently resolve to the editable scope; that fallback must stop being silently permissive when it changes the target shape.
- Multi-line content arrays joined without a leading newline are valid text but not valid sibling insertions at many node boundaries.
- `create` remains top-level only; tightening edit validation must not weaken existing `create` restrictions.

* Acceptance Criteria
- Unsafe line-target edits fail before disk mutation with a truthful, specific error.
- Raw-node vs editable-scope ambiguity no longer produces silent partial declaration edits.
- Mixed edit batches are atomic and reject malformed entries before save/format.
- Focused TypeScript/native/Rust tests cover the transcript-shaped regressions and keep them fixed.
