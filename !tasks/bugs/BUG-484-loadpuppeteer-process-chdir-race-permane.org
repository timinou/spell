* Initial Message

Discovered while hardening the cross-project file leak (BUG-481/482). browser.ts loadPuppeteer() temporarily process.chdir()s into a safe dir to import puppeteer (cosmiconfig probe safety), restoring the previous cwd in finally. It memoizes the resolved MODULE but not the in-flight LOAD.

* Root cause (persistent corruption, not transient)

In the shared-process model (interactive CLI/TUI runs many sessions + ALL subagents in ONE process), two concurrent first-callers race:

#+begin_src
Call A: puppeteerModule undefined → prev = A.cwd (real project) → chdir(safeDir) → await import…
Call B (concurrent): puppeteerModule STILL undefined → prev = process.cwd() = safeDir (!!) → chdir(safeDir) → await…
A.finally: chdir(A.cwd)   ✓ restores real cwd
B.finally: chdir(safeDir) ✗ pins process.cwd() to ~/.spell/puppeteer PERMANENTLY
#+end_src

B captured `prev` AFTER A had already chdir'd, so B's restore sets cwd to safeDir for the rest of the process lifetime. Every subsequent cwd-relative write process-wide then lands in ~/.spell/puppeteer — a cross-project corruption vector distinct from BUG-482 (which was Chrome's own profile dir).

* Fix (commit a9c85a7e7 / amend)

Singleflight: memoize the in-flight Promise, not just the resolved module, so the chdir/restore pair runs EXACTLY ONCE regardless of concurrency. Clear the memo on failure so a later call can retry the import. A transient cwd window during the single first-load remains (inherent to process.chdir) but is bounded to one load, never a permanent pin.

* Acceptance

- Concurrent first-callers share one promise; only one chdir/restore pair executes.
- Failed import clears the memo (retryable).
- tsgo clean on browser.ts; browser tests green (3/3).
