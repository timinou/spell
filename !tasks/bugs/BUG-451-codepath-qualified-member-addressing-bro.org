## Summary
Adversarial test-drive of `find`/`edit` across a TS+Rust+Python corpus surfaced that **qualified member addressing** (`Container::member` / `Container.member`) was broken on multiple axes. Two distinct resolvers are involved — the read-side CodePath walker and the edit-side `CodeBuffer`/`resolve_symbol` — and each had gaps.

## Findings & fixes

### 1. Rust read-side: `Type::method` resolved to ZERO nodes
`RustNameLexer::matches` was a stub returning `false` for every payload. The walker's text fallback then compared the FULL rendered path (`Widget::label`) against the bare name field (`label`) → never matched. Only bare `label` worked (fragile across multiple impls).
**Fix** (`crates/pi-code-path/src/dialects/rust.rs`): implement `matches` via `matches_rust_leaf` — take the leaf `::` segment and compare to the node's `name` field for Rust declaration kinds (parity with the TS dialect's leaf-matching; handles `r#` raw idents + turbofish).

### 2. Edit-side: Rust `::` separator never split
`find_symbol_node` only split container/member on `.` (`symbol.rfind('.')`). Rust members use `::`, so `Widget::label` was treated as one unresolvable name.
**Fix** (`crates/pi-code-engine/src/resolve.rs`): `split_container_member` tries `::` then `.`.

### 3. Edit-side: container name ambiguity (struct + impl blocks)
A Rust type and its `impl` block(s) share a name → `find_symbol_node("Widget")` errored as ambiguous BEFORE member lookup.
**Fix**: on ambiguity, gather every top-level container candidate via `find_top_level_matches` and try the member in each; non-member-bearing nodes (the struct) yield no match. Single success → resolve; multiple → ambiguous.

### 4. Edit-side: decorated/exported containers (all langs)
`@dataclass class Point` (Python `decorated_definition` wrapper) and `@sealed export class Server` (TS `export_statement` whose first child is the `decorator`) were not member-addressable.
**Fix**: `unwrap_to_class_like` descends a wrapper to the class-like node before the member node_type check; `unwrap_export` skips leading `decorator` siblings.

### 5. Edit-side: `@property` member body
A decorated member (`@property def magnitude`) is itself a `decorated_definition` with no body field → "has no body to replace".
**Fix**: `unwrap_decorated_member` returns the inner definition for #body/#sig span extraction.
