* Scope

In: enforce that positional `insertBefore`/`insertAfter`/`delete`/`splice`/`move`/`clone`/`transpose` actions with a `line:` anchor resolve inside the span of the `targetId` declaration when one is specified, and that they fail with a clear error instead of silently landing at file top.

Out: generalised sibling-aware movement heuristics beyond the declaration span; changes to symbol-mode (resolved) dispatch branches.

* Background

Observed failure (planner self-report, PLAN-248 authoring): `code edit { targetId: "src/file.ex::Module.fn", actions: [{ kind: "insertBefore", line: 52, content: "...
" }] }` inserted the block at file-top (outside the module) because tree-sitter's `descendant_for_byte_range` found the outermost sibling at the given raw byte. Resulted in a compile error; required manual cleanup.

Mechanism: `single_action` (`crates/pi-natives/src/code_buffer.rs:486-508`) branches on `resolved: Option<ResolvedSymbol>`. When the action has both a declaration `targetId` AND a positional `line:`, the dispatcher takes the symbol branch — fine. But when the caller passes a positional `line:` expecting it to be scoped to the targetId container, the line-resolution path in `crates/pi-code-engine/src/line_target.rs:33` walks from the raw byte with no ancestor constraint, so the chosen node may sit outside the `targetId` span entirely.

Failure mode: caller believes line-target is scoped to the targetId container; engine treats positional line as file-global; content lands outside the intended ancestor.

* Existing patterns

- `crates/pi-code-engine/src/line_target.rs:15-44` — `resolve_line_target`, `resolve_edit_target`.
- `crates/pi-code-engine/src/line_target.rs:66-94` — `editable_scope_for_node` ancestor walk.

- Existing sibling-safety precedent in `crates/pi-code-engine/src/edit/replace.rs:12-34` — separator checks that refuse unsafe positional inserts.

* Implementation

** Add ancestor constraint to line_target API
:PROPERTIES:
:CUSTOM_ID: BUG-281-code-edit-insertbefore-insertafter-escap::api-constraint
:END:

- File: `crates/pi-code-engine/src/line_target.rs`
- Extend: `pub fn resolve_edit_target<'a>(buffer, line, node_type, within: Option<(usize, usize)>)`; when `Some((start, end))`, compute byte, and if `byte < start || byte >= end`, return `Err(CodeEngineError::LineOutOfTargetScope { line, target_start, target_end })`.
- Add error variant `CodeEngineError::LineOutOfTargetScope { line: usize, target_start: usize, target_end: usize }` in `crates/pi-code-engine/src/error.rs`.
- Adjust `raw_node_at_byte` and `editable_scope_for_node` to never walk above a supplied ancestor.

** Plumb ancestor span through dispatcher

* Edge cases

- Symbol target is a single-line declaration: ancestor span may be < 1 line; line anchoring should still succeed when line is the declaration's line. Compute span inclusively.
- `targetId: "file.ext"` (file-scope, no symbol): no ancestor constraint; positional ops resolve against file as today.
- `line` exactly equal to the decl header line: treated as inside (boundary at `target_start` inclusive).
- Markdown / non-AST languages where tree-sitter's parse-tree is sparse: ancestor span still enforced; resolution may fall back to file-global with a warning if `within` span is zero-length.
- Unicode-heavy lines: byte boundaries vs codepoints already handled by `ropey::LineType::LF_CR`.
