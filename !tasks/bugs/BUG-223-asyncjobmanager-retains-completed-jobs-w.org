* Problem
In =packages/coding-agent/src/async/job-manager.ts=, the =AsyncJobManager= stores all completed jobs in =#jobs Map= until eviction timers fire. If =retentionMs= is short but many jobs complete rapidly, the map can grow large. The =#deliveries= array also grows if delivery callbacks fail.

* Solution
Add a hard cap on retained completed jobs. When the cap is exceeded, evict oldest completed jobs immediately (without waiting for the timer).

* Design Decisions
- Max 100 retained completed jobs (generous for any realistic session)
- When a new job completes and completed count > 100, evict oldest completed job immediately
- =#deliveries= array capped at 200 entries (drop oldest if exceeded)
- These are safety limits for pathological cases, not expected to trigger in normal use

* Files to Modify
- =packages/coding-agent/src/async/job-manager.ts= — Add max retention cap

* Specific Change
Read the file to find where jobs are marked complete (likely a =complete()= or status update method). After adding a completed job, check total completed count and evict if over limit.

#+begin_src typescript
const MAX_RETAINED_JOBS = 100;
const MAX_PENDING_DELIVERIES = 200;

// After marking a job complete:
private pruneCompletedJobs(): void {
    const completed = [...this.#jobs.entries()]
        .filter(([, job]) => job.status === "completed" || job.status === "failed");
    if (completed.length > MAX_RETAINED_JOBS) {
        // Sort by completion time, evict oldest
        const toEvict = completed.slice(0, completed.length - MAX_RETAINED_JOBS);
        for (const [id] of toEvict) {
            this.#jobs.delete(id);
            const timer = this.#evictionTimers.get(id);
            if (timer) { clearTimeout(timer); this.#evictionTimers.delete(id); }
        }
    }
    // Cap deliveries
    if (this.#deliveries.length > MAX_PENDING_DELIVERIES) {
        this.#deliveries.splice(0, this.#deliveries.length - MAX_PENDING_DELIVERIES);
    }
}
