* Problem

=GrowthShell.qml= has a single =Connections= block for =bridge.onMessageReceived= that only handles =workspace_layout=. All other bridge messages — =message_start=, =message_update=, =message_end=, =tool_start/update/end=, =agent_busy=, =user_message=, =dashboard_update= — are silently dropped.

The working =shell.qml= (=packages/coding-agent/src/modes/qml/shell.qml= lines 337-371) routes every bridge message to the active panel via =forwardToActivePanel(payload)=, which calls =item.handleMessage(payload)= on the loaded panel's root item. This is how ChatPanel receives message events and renders chat history.

GrowthShell loads ChatPanel.qml via the Loader (for the =general= workspace), but ChatPanel never receives any events because no forwarding exists.

* Root Cause

=domain/growth/src/qml/panels/GrowthShell.qml= lines 189-198: the =Connections= block only handles =workspace_layout=.

* Fix

Add message forwarding in GrowthShell that routes bridge payloads to both the main and secondary panel Loaders (secondary Loader is added by [[id:BUG-066-growthshell-only-loads-main-position-pan]]):

#+begin_src qml
function forwardToPanel(loader, payload) {
    if (loader.item && typeof loader.item.handleMessage === "function") {
        loader.item.handleMessage(payload)
    }
}

Connections {
    target: bridge
    function onMessageReceived(payload) {
        if (payload.type === 'workspace_layout') {
            // existing handling
        }
        // Forward to both panels so each processes what it understands
        forwardToPanel(mainPanelLoader, payload)
        forwardToPanel(secondaryPanelLoader, payload)
    }
}
#+end_src

Mirror in =GrowthShellTestHarness.qml=.
