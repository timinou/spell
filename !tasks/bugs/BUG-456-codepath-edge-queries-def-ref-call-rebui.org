## Symptom
The first graph-edge query (`def→`/`ref→`/`call→`/`import→`) in any fresh process blocks **~78 seconds** (measured: 77423ms on this 5556-file workspace). Subsequent edge queries are ~367ms (warm). `find "X def→"` appears to hang.

## Root cause
`crates/pi-natives/src/code_graph_cache.rs::get_or_build_graph` only memoises in a process-local `DashMap`. On a cold process (miss) it calls `CodeGraphBuilder::build()`, which **unconditionally re-parses every file** via `ignore::WalkBuilder` (`crates/pi-code-graph/src/indexer.rs::build`). It never consults the persisted `.spell/graph/workspace.bin` (21MB, written by the same build).

Meanwhile the `status index` path (`code_graph.rs::ensure_graph`) DOES warm-load: it checks `builder.cache_status(root)` and, when `CacheStatus::Fresh`, calls `cache.load::<GraphCacheEntry>(CACHE_NAME)` — a fast deserialize. That's why `status index` returns instantly while edge queries stall.

∴ two graph-construction paths diverged: the observability path warm-loads, the edge-query path rebuilds cold.

## Fix
Make `get_or_build_graph` replicate `ensure_graph`'s warm-load: build a `CodeGraphBuilder`, check `cache_status`; if `Fresh`, `load::<GraphCacheEntry>("workspace")` and wrap in Arc; else `build()` (which persists for next time). Memoise the Arc in the DashMap as today.
