* Scope

In:
- Bump the TypeScript import resolver dependency in `crates/pi-code-graph/Cargo.toml` from `oxc_resolver = "1.12"` to current stable `11.x`, updating the workspace `Cargo.lock` in the same change.

- Preserve the current resolver contract used by `CodeGraphBuilder.build()` in `crates/pi-code-graph/src/indexer.rs`: success stays `Ok(Some(...))`, misses stay `Ok(None)`, and `fallback_relative_path()` remains the non-panicking fallback path.

Out:
- Broad code-graph query changes unrelated to import resolution safety.
- Reworking `ImportResolver` trait contracts or changing resolver misses into new user-visible error types.
- General `oxc_resolver` feature adoption beyond what is required to remove the panic and keep existing import-resolution behavior truthful.
- TypeScript tool-surface redesign in `packages/coding-agent`; only touch TS/bridge code if the Rust change forces it.

Rationale:
- Repo evidence shows `crates/pi-code-graph/Cargo.toml` still pins `oxc_resolver = "1.12"`.
- `crates/pi-code-graph/src/language/typescript.rs` calls `resolver.resolve(from_dir, request.specifier).ok()` directly, so an upstream panic crosses the native async-work boundary and aborts the host.
- `crates/pi-code-graph/src/indexer.rs` routes every import edge through `registered.resolver.resolve(...)`, and `crates/pi-natives/src/code_graph.rs` / `code_buffer.rs` build live graphs through `CodeGraphBuilder`, so one resolver panic can take down semantic grep, code graph indexing, and related user flows.

* Existing Patterns

- `crates/pi-code-graph/src/language/typescript.rs`
  - Existing TypeScript resolver shape is: build `ResolveOptions` → `Resolver::new(options)` → `resolver.resolve(...).ok()` → `fallback_relative_path(...)` → strip to project-relative path.
  - Keep this outside-in contract intact; the hardening should change crash behavior, not successful-resolution semantics.
- `crates/pi-code-graph/src/indexer.rs`
  - `CodeGraphBuilder.build()` canonicalizes the workspace root, walks files, and resolves imports through the language resolver registry.
  - Resolver failures that are equivalent to “unresolved import” already degrade to `None`; the panic guard should preserve that truth instead of inventing a new parallel error path.
- `crates/pi-embedding-worker/src/main.rs`
  - `panic::catch_unwind(AssertUnwindSafe(...))` is an in-repo precedent for containing panicable third-party/native work and converting it into a truthful non-aborting failure.
  - Reuse that pattern rather than inventing ad-hoc panic plumbing.
- `crates/pi-natives/src/code_graph.rs`
  - `run_code_graph()` is the runtime consumer path that makes this bug user-visible.
  - Success payload shapes from this path should remain unchanged for well-formed workspaces.
- `crates/pi-natives/src/code_buffer.rs`
  - Additional code-buffer graph helpers also build through `CodeGraphBuilder`; the resolver hardening must not regress those paths.
