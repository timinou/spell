* Symptoms

#+begin_example
edit { target: "foo.ts::ERGO_V2",
       action: { kind: "wrap", content: ["try { $BODY } catch (e) {}"] }}

before:  export const ERGO_V2 = 42;
after:   export try { const ERGO_V2 = 42; } catch (e) {}
                 ^^^ export dangling, semantically broken
#+end_example

Same hazard for ~export default function~, ~export class~, ~export interface~, ~export async function~, decorated declarations, and any leading-modifier construct.

* Root cause

- =crates/pi-code-engine/src/resolve.rs:156-180= ~match_declaration~ unwraps =export_statement= to extract the inner declaration's name (correct for rename — we want to compare against ~variable_declarator.name~).
- =crates/pi-code-engine/src/resolve.rs:195-219= ~build_resolved~ creates ~ResolvedSymbol.{start_byte, end_byte}~ from the unwrapped inner node.
- =crates/pi-code-engine/src/edit/wrap.rs:17-35= ~wrap_node~ uses that range — leaves the =export= keyword outside.
- =crates/pi-natives/src/code_buffer.rs:936-943= dispatcher passes resolved as-is; no action-aware escalation.

* Structural cause

ResolvedSymbol carries ONE range used by THREE different consumers with different semantic needs:
- rename → wants identifier-only sub-range
- splice / clone / wrap → wants statement-level range (including modifiers/decorators)
- find / get → wants declaration range (no statement keywords)

The pipeline silently picks one (the unwrapped declaration), and downstream actions inherit the wrong range.

* Fix contract (C: structural multi-range)

** Type extension
- =crates/pi-code-engine/src/resolve.rs= ~ResolvedSymbol~: extend with three explicit byte ranges:
  - ~identifier_range~: the bare name token (for rename)
  - ~declaration_range~: the unwrapped declaration body (current default; for find/get)
  - ~statement_range~: smallest enclosing statement that includes modifiers, decorators, leading export — ascends until a node kind whose parent is module/program/class_body/etc.

- ~build_resolved~ computes all three. Identifier from name field; declaration from unwrapped node; statement by walking up while parent kind ∈ {export_statement, export_default_declaration, decorator, modifier, etc.}.

** Action handler selection
- =crates/pi-natives/src/code_buffer.rs=: each kind dispatches with the appropriate range:
  - rename → uses identifier_range
  - wrap, splice, move, clone → uses statement_range
  - default (other ops) → uses declaration_range
- Helper: ~range_for_action(kind, resolved) -> Range~.

** Wrap implementation
- =crates/pi-code-engine/src/edit/wrap.rs:17-35= unchanged; receives the right range from the dispatcher.

** Other dialects
- Python: enclosing statement may include decorators (~@property def x~) — escalation walks decorator parents.
- Rust: ~pub fn~ — pub modifier and attributes (~#[derive]~) get included.
- Implement statement_range escalation per dialect via a NameLexer/Profile method ~enclosing_statement_kinds() -> &[&str]~.
