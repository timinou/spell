* Initial Message

BUG-358 shipped a hard-reject guard. =proxy_create_nested_path_bug.md= explicitly recommends going further:

#+begin_quote
*Better still*: emit a warning + auto-coalesce (strip the prefix) for the common case where the agent meant a monorepo-root path. Agents will keep doing this because their dispatch contexts naturally reference monorepo-root paths.
#+end_quote

* Why hard-reject is wrong here

1. Dispatch contexts (task tool =assignment=, plan body, AGENTS.md) phrase work in *monorepo-root paths*. The session cwd is one level deeper. The agent faithfully passes what's in its context.
2. Hard-reject burns a turn: agent receives diagnostic, retries with the stripped path. Net: 2x latency + 2x tokens for an entirely-correctable input.
3. The bug doc says agents hit this *6+ times across ~10 days*. Even with a clean rejection, the agent has to re-call. The right tool behaviour is to do the right thing on the *first* call and *teach* via a warning.

* Disambiguation

Auto-coalesce should preserve legitimate nested directories. The disambiguator is *parent-directory existence on disk*:

| nested parent exists? | stripped parent exists? | action |
|---|---|---|
| yes | -- | use nested (legit; no coalesce); silent or info note |
| no | yes | *coalesce*; warn loudly |
| no | no | coalesce (best guess; this is the bug case); warn loudly |

* Behaviour

- =create.ts=: always pre-resolve via this logic before mode/sandbox/exists checks.
- =edit.ts=: same; for non-=create= ops, the disambiguator is *target-file existence*, not just dir existence (modifying a file requires it to exist).
- Result text shows both the supplied path AND the resolved absolute path on a second line so the agent sees what happened.
