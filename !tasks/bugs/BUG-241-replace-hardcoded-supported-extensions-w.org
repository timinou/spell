* Problem
Two issues from PLAN-213 audit:

1. =SUPPORTED_EXTENSIONS= in =packages/coding-agent/src/tools/code.ts= is a hardcoded duplicate of the native engine's language registry. When a language is added to the Rust engine, the TypeScript guard silently rejects files the engine supports. The native =languages= command already exposes extensions at runtime but the guard doesn't use it.

2. The guard error message says "Use the read tool for non-code files" but fires for ALL unsupported extensions, including unsupported code languages (Go, Java, etc.). This misleads the model about the actual limitation.

* Design Decisions
1. Replace hardcoded =SUPPORTED_EXTENSIONS= with a lazy =getSupportedExtensions()= function that queries the native =languages= command on first call.
2. Cache the result in a module-level variable (=_supportedExtensions=). The native language registry is static during a session.
3. Keep a =FALLBACK_EXTENSIONS= constant (same 14 values) as defensive fallback when the native engine is unavailable or returns an empty set.
4. Export =_resetSupportedExtensionsForTest(override?: Set<string>)= for test cache management.
5. Change guard message from =Unsupported file type .${ext}. Use the read tool for non-code files.= to =Unsupported file type .${ext}. The code tool supports TypeScript, Rust, Python, Typst, and Elixir. Use the read tool instead.=
6. Do NOT cache the fallback — if the native query fails, retry on next call.

const FALLBACK_EXTENSIONS = new Set([
    "ts", "tsx", "js", "jsx", "mjs", "cjs", "mts", "cts",
    "rs",
    "py", "pyi",
    "typ",
    "ex", "exs",
]);

let _supportedExtensions: Set<string> | undefined;

function getSupportedExtensions(): Set<string> {
    if (_supportedExtensions) return _supportedExtensions;
    try {
        const result = executeCodeBuffer({ command: "languages" });
        if (!result.error) {
            const output = result.output as { languages: Array<{ extensions: string[] }> };
            const exts = new Set<string>();
            for (const lang of output.languages ?? []) {
                for (const ext of lang.extensions ?? []) {
                    exts.add(ext);
                }
            }
            if (exts.size > 0) {
                _supportedExtensions = exts;
                return exts;
            }
        }
    } catch {
        // Native engine unavailable — use fallback
    }
    return FALLBACK_EXTENSIONS;
}

/** @internal Reset cached extensions — test-only. */
export function _resetSupportedExtensionsForTest(override?: Set<string>): void {
    _supportedExtensions = override;
}
#+end_src

Key behaviors:
- First production call queries native, caches result, subsequent calls use cache
- If native query fails (throws, returns error, returns empty), returns =FALLBACK_EXTENSIONS= without caching (retries next call)
- =_resetSupportedExtensionsForTest(set)= pre-populates cache; =_resetSupportedExtensionsForTest()= clears it
- =_resetSupportedExtensionsForTest= is exported via the tools barrel (already exports from =code.ts=)
