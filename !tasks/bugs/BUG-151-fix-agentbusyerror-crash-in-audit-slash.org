* Problem
~handleAuditCommand()~ in ~interactive-mode.ts~ calls ~session.prompt(prompt, { synthetic: true })~ without a ~streamingBehavior~ option. When the agent is already streaming (e.g. processing a previous prompt), ~prompt()~ throws ~AgentBusyError~ which is unhandled, crashing the process.

Compounding issue: the method mutates audit state (~setAuditState~, ~showAuditOverlay~) *before* the prompt call. So the crash leaves audit state corrupted:
- Overlay shows but no audit runs
- Re-running ~/audit~ says "Audit already in progress" because ~active~ is ~true~

* Fix
Add a streaming guard at the top of ~handleAuditCommand()~ (after plan mode and active-audit checks), *before* any state mutation.

** Target
~packages/coding-agent/src/modes/interactive-mode.ts~ — ~handleAuditCommand()~ method (line ~735).

** Change
Insert after the ~getAuditState().active~ guard:
#+begin_src typescript
if (this.session.isStreaming) {
    this.showWarning("Cannot audit while agent is processing.");
    return;
}
#+end_src

** Design rationale
- *Warn-and-bail over followUp queueing*: The ~followUp~ path hardcodes ~role: "user"~ / ~attribution: "user"~, but audit prompts require ~synthetic: true~ (→ ~role: "developer"~, ~attribution: "agent"~). Queueing via followUp would misrepresent the prompt.
- *Guard before state mutation*: The streaming check must precede ~setAuditState~ and ~showAuditOverlay~ to avoid corrupted state on early return.
- Consistent with codebase pattern: ~input-controller.ts~ checks ~session.isStreaming~ before calling ~prompt()~.
