* Scope
This item hardens the managed-buffer-backed create/write lifecycle used by `write` and the migrated text/edit patch flows.

In scope:
- Failed managed-buffer-backed create/write on supported files (`.ts`, `.rs`, `.py`, `.md`, `.org`, etc.) must preserve the disk contract:
  - if the target file did not exist before the attempt, an error leaves no file behind
  - if the target file existed before the attempt, an error leaves the exact prior bytes on disk
- Distinguish pre-save failure from post-save cleanup failure. If bytes are already persisted and only managed-buffer invalidation/close fails afterward, the tool must report persisted success plus a warning, not a failed write.
- Cover all callers that reuse `packages/coding-agent/src/tools/managed-code-buffer.ts`: `packages/coding-agent/src/tools/write.ts` and `packages/coding-agent/src/patch/index.ts`.
- Add/extend native contract tests in `packages/natives/test/code-buffer.test.ts` for missing-file invalid-create and existing-file invalid-overwrite behavior.
- Add/extend coding-agent regression tests for helper + tool behavior, including the motivating `specs/subagent-envelope-v2.md` style missing-file Markdown write case.

Out of scope:
- Multi-file atomicity.
- Non-managed non-code writethrough paths.
- Changing `force: true` semantics beyond keeping result classification truthful.
- Reworking `code edit` public API shape.

Rationale: current code explicitly allows a surfaced error after disk persistence (`"Edit succeeded on disk, but failed to invalidate the managed code buffer ..."` in `packages/coding-agent/src/tools/managed-code-buffer.ts`). The user-selected contract is stricter: errors mean no disk mutation; persisted writes must be reported as success with warning. Existing tests pin existing-file invalid-edit rollback, but missing-file invalid-create and post-save invalidation truthfulness are not yet covered.

* Existing Patterns
- `packages/coding-agent/src/tools/managed-code-buffer.ts`
  - `applyManagedBufferContent(file, content, options)` is the single choke point for managed-buffer-backed whole-file persistence.
  - `invalidateManagedCodeBuffersForPaths(paths)` currently throws after persistence if `close` fails; this is the truthfulness bug to remove.
- `packages/coding-agent/src/tools/write.ts::WriteTool.execute(...)`
  - current managed-buffer branch already routes supported-file writes through `applyManagedBufferContent(...)` and adds compatibility notices/diagnostics.
  - current `force: true` path falls back to `Bun.write(...)` after invalidation and must keep truthful result classification.
- `packages/coding-agent/src/patch/index.ts::EditTool.execute(...)`
  - replace/hashline/final-write paths also call `applyManagedBufferContent(...)`; the same persistence contract must hold there.
- `packages/natives/test/code-buffer.test.ts`
  - already proves existing-file invalid edit is rejected before save and existing bytes remain unchanged.
  - already proves missing supported files can be created through `edit` + `save`.
  - extend this file rather than inventing a new native test style.
- `crates/pi-code-engine/src/buffer.rs::BufferRegistry.open_or_create(...)`
  - existing test `test_buffer_registry_open_or_create_missing_file` shows missing-file create starts as an in-memory empty buffer; this is the lowest-layer contract to preserve when a create attempt later fails.
- `packages/coding-agent/src/session/edit-coordinator.ts::callCodeBuffer(...)`
  - BUG-303 is the prerequisite sessionId fix for mutating helper calls. Reuse its session plumbing rather than introducing a second mutation path.

* Tests
User workflows to cover first:
1. Missing-file Markdown create with structurally invalid content (the motivating `specs/subagent-envelope-v2.md` class): tool/helper errors, and the path does not exist after failure.
2. Existing-file supported-source overwrite with structurally invalid content: tool/helper errors, and disk bytes match the exact pre-write content.
3. Existing-file supported-source overwrite blocked by `WRITE_PARSE_REGRESSION` or `WRITE_SHRINK_BLOCKED`: disk bytes remain unchanged and no orphan temp/blank file appears.
4. Successful missing-file create on supported files still persists exact bytes and does not require any cleanup shim.
5. Post-save managed-buffer close/invalidation failure is surfaced as persisted success with an explicit warning/meta note, not as a failed write.
6. The shared helper contract holds for both `write.ts` and `patch/index.ts` callers.

* Edge Cases
- Existing broken files: `WRITE_PARSE_REGRESSION` guard already skips when original content is broken; preserve that behavior while keeping byte-restoration truth.
- Session plumbing: do not add a second sessionId path; BUG-303 remains the only session-propagation fix.
- Force fallback: if `force: true` intentionally bypasses guards and bytes persist, any later cleanup failure is still success-with-warning, not failure.
- Missing-parent-directory create failure must remain truthful if the underlying engine/kernel cannot materialize the path.
- No blank/orphan artifact should remain after any surfaced failure on the managed-buffer create path.

* Acceptance Criteria
- Missing-file managed-buffer-backed failure leaves no file on disk.
- Existing-file managed-buffer-backed failure leaves exact prior bytes on disk.
- Any surfaced failure from `write` / migrated patch persistence implies no disk mutation.
- Persisted writes with post-save invalidation problems surface as success plus warning/meta note.
- Native + coding-agent regression tests above pass without weakening FEAT-585 shrink/parse guards.
