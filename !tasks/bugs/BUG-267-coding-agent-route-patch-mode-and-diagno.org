* Scope
- In scope: remove the remaining persistence-model split inside `packages/coding-agent/src/patch/index.ts` so patch mode, replace mode, and hashline mode all use the managed code-buffer lifecycle for non-binary text writes.
- In scope: restore immediate diagnostics/meta parity for migrated replace/hashline writes so LSP writethrough diagnostics are not silently dropped after PLAN-235.
- In scope: preserve stale-buffer detection, preview/resolve correctness, undo/redo interoperability, and native text fallback behavior.

* Tests
- Workflow 1: patch-mode `edit` on a semantic-capable file writes through the managed code buffer, then `code undo` / `code redo` observe the same history with no stale-buffer false positive.
- Workflow 2: patch-mode `edit` on fallback text (`.txt`, `.toml`, `.kdl`, etc.) uses the same lifecycle and does not fail with `language not found`.
- Workflow 3: replace/hashline migrated writes still surface immediate diagnostics/meta when LSP writethrough is enabled.
- Workflow 4: stale-buffer drift blocks patch-mode mutation before disk changes, matching the replace/hashline managed-buffer contract.
- Workflow 5: preview/apply/discard flows remain correct after the persistence-path change; no orphaned pending-action state and no hidden buffer invalidation bugs.
- Workflow 6: semantic-capable patch-mode edits still preserve truthful user-visible result text and diff previews unless the contract is intentionally updated in the same change.
