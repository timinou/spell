* Problem

Two bugs in ~packages/emacs/elisp/pi-treesit.el~ prevent Elixir outline from working:

1. *Paren mismatch in ~pi-treesit-declaration-kind~* (lines 353-367): The outer =cond='s
   catch-all ~(t type)~ is inside the =call= clause body instead of being a separate clause.
   When the =call= branch matches, Emacs evaluates ~(t type)~ as a function call, crashing
   with =Symbol's function definition is void: t=.

2. *Arguments field lookup in ~pi-treesit-declaration-name~* (line ~300): Uses
   ~(treesit-node-child-by-field-name node "arguments")~ but tree-sitter-elixir does NOT
   assign the field name ="arguments"= to the arguments child (it has =field=nil=). This
   causes ~declaration-name~ to return ~nil~ for all Elixir nodes, producing empty outlines.

A related gap exists in ~pi-outline--declaration-name-node~ in
~packages/emacs/elisp/pi-outline.el~ — it has no Elixir =call= branch, so outline entries
for Elixir nodes lack the =column= field.

* Tree-sitter-elixir Node Structure

A =call= node (e.g. ~defmodule MyApp.HelloController do ... end~) has:
- child 0: type=identifier, field="target", text="defmodule"
- child 1: type=arguments, field=nil (NOT field="arguments"!), text="MyApp.HelloController"
- child 2: type=do_block, field=nil

A =def= call (e.g. ~def index(conn, _params) do ... end~) has:
- child 0: type=identifier, field="target", text="def"
- child 1: type=arguments, field=nil — first child is type=call, text="index(conn, _params)"
- child 2: type=do_block, field=nil

* Fix 2: Arguments lookup in pi-treesit-declaration-name

File: ~packages/emacs/elisp/pi-treesit.el~, function ~pi-treesit-declaration-name~,
Elixir =call= branch (around line 292-307).

Replace the field-name lookup ~(treesit-node-child-by-field-name node "arguments")~ with a
type-based search. Use ~treesit-search-subtree~ with depth 1 to find the =arguments= child
by node type:

#+begin_src elisp
(let ((args-node (treesit-search-subtree node "arguments" nil nil 1)))
  (when args-node
    (let ((first-arg (treesit-node-child args-node 0)))
      (when first-arg
        (if (string= (treesit-node-type first-arg) "call")
            (let ((fn-name (treesit-node-child first-arg 0)))
              (when fn-name (treesit-node-text fn-name t)))
          (treesit-node-text first-arg t))))))
#+end_src

Note: ~treesit-search-subtree~ with depth 1 searches direct children matching the given
node type string. This is safe because =call= nodes always have at most one =arguments=
child node.

* Fix 3: Add Elixir branch to pi-outline--declaration-name-node

File: ~packages/emacs/elisp/pi-outline.el~, function ~pi-outline--declaration-name-node~
(around line 35-76).

Add a =call= branch before the final =(t nil)= catch-all, mirroring the logic from
~pi-treesit-declaration-name~ but returning the *node* instead of text:

#+begin_src elisp
     ;; Elixir call nodes
     ((string= type "call")
      (let ((args-node (treesit-search-subtree node "arguments" nil nil 1)))
        (when args-node
          (let ((first-arg (treesit-node-child args-node 0)))
            (when first-arg
              (if (string= (treesit-node-type first-arg) "call")
                  (treesit-node-child first-arg 0)
                first-arg))))))
#+end_src

This enables the =column= field in outline entries for Elixir declarations.
