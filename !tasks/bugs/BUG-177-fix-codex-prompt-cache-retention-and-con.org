* Problem
=packages/ai/src/providers/openai-codex-responses.ts= has two caching bugs:
1. =prompt_cache_key= is set unconditionally to =options?.sessionId= — ignores =cacheRetention === "none"=
2. =prompt_cache_retention= is never set despite the =RequestBody= interface supporting it (=request-transformer.ts= line 48)

Per OpenAI docs, Codex models (gpt-5.1-codex, gpt-5.1-codex-mini, gpt-5.1-codex-max, gpt-5-codex) all support extended 24h prompt cache retention. This is entirely unused.

* Fix

** File: =packages/ai/src/providers/openai-codex-responses.ts=
In =buildTransformedCodexRequestBody= (line ~463):

1. Add import at top of file:
#+begin_src typescript
import { resolveOpenAICacheParams } from "../utils";
#+end_src

2. Replace the raw =prompt_cache_key= assignment (line 472):

Before:
#+begin_src typescript
const params: RequestBody = {
    model: model.id,
    input: [...convertMessages(model, context)],
    stream: true,
    prompt_cache_key: options?.sessionId,
};
#+end_src

After:
#+begin_src typescript
const params: RequestBody = {
    model: model.id,
    input: [...convertMessages(model, context)],
    stream: true,
    ...resolveOpenAICacheParams(options?.cacheRetention, options?.sessionId),
};
#+end_src

** No changes to =request-transformer.ts=
The =RequestBody= interface already has =prompt_cache_retention?: "in_memory" | "24h"= at line 48. No type changes needed.

** Key decisions
- No hostname gating: Codex base URL is =chatgpt.com/backend-api= but extended retention is supported per OpenAI docs.
- =resolveOpenAICacheParams= handles the ="none"= check, ="long"= → ="24h"= mapping, and missing sessionId case.
