* Scope
In scope: complete the user-facing `code edit` contract for duplicate `findAndReplace` matches by exposing `occurrence` all the way from the TypeScript tool schema to the native bridge and prompt docs. This item covers `packages/coding-agent/src/tools/code.ts`, `packages/natives/src/code-buffer/types.ts`, `packages/coding-agent/src/prompts/tools/code.md`, and regression coverage in `packages/natives/test/code-buffer.test.ts` plus relevant coding-agent prompt/tool tests.

Out of scope: redesigning `findAndReplace` into a new DSL, changing patch matching semantics beyond the already-implemented native `Occurrence` model, or adding preview-driven interactive disambiguation. Those are deferred because the current engine already has a sufficient structural model; the bug is that the outer contract fails to expose it.


Deferred design work for interactive previews or richer disambiguation UX belongs to [[id:FUP-059-code-edit-api-ergonomics-and-audit-follo]].

- T6 — prompt/tool contract docs mention the supported selector values so the agent can reliably use them.

* Edge Cases
- Numeric `occurrence` must be positive and 1-indexed; `0`, negatives, and non-integers must not be silently coerced into a different meaning.
- `occurrence: "all"` must remain scoped to the resolved target span, not the whole file unless the target itself is the file.
- Ambiguity errors must still list enough information to debug the failure when `occurrence` is omitted.
- String/array normalization for `find` and `content` must not accidentally erase `occurrence` when actions are rebuilt.
