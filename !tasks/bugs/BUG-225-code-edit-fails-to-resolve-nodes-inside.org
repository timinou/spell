* Problem

~code edit~ (replace, kill, insert-before, insert-after) fails with "No node
found at line X" on Typst files, even though ~code navigate node-at~ finds
nodes successfully at the same line.

Root cause: ~find_ancestor~ in ~edit/replace.rs~ only walks UP from the
initially-resolved node. In Typst (and any grammar with wrapper nodes), the
line starts with ~#~ which belongs to a ~code~ wrapper node. The target ~let~
node is a CHILD of ~code~, not an ancestor — so the upward search fails.

This is not Typst-specific. Any grammar where declarations nest inside wrapper
nodes triggers the same bug (e.g., TypeScript ~export_statement~ wrapping
~function_declaration~ when editing from column 0).

* Reproduction

1. ~code read~ a ~.typ~ file (loads buffer)
2. ~code navigate node-at~ on a ~#let~ line → returns ~{ nodeType: "let", parentType: "code" }~
3. ~code edit replace~ with ~target: { line: N, node_type: "let" }~ → "No node found at line N"

* Design Decisions

1. Fix in ~find_ancestor~ (rename to ~find_target~): after ancestor walk-up fails, try a
   sole-named-child descent. This matches the existing pattern in ~outline.rs::entry_for_node~
   where ~sole_named_child()~ is used to unwrap ~code~ → ~let~.
2. The descent uses the sole-named-child heuristic: only recurse into a child if it is the
   ONLY named child. This prevents false matches in nodes with multiple children.
3. The fix is language-agnostic — no Typst-specific logic needed.

#+begin_src rust
fn find_target<'a>(
    node: tree_sitter::Node<'a>,
    node_type: &str,
) -> Option<tree_sitter::Node<'a>> {
    // Walk up ancestors (existing logic)
    let mut current = node;
    loop {
        if current.kind() == node_type {
            return Some(current);
        }
        match current.parent() {
            Some(p) => current = p,
            None => break,
        }
    }
    // Unwrap sole-named-child chains downward.
    // Handles grammars where declarations nest inside wrapper nodes
    // (e.g., Typst `code` → `let`, TS `export_statement` → `function_declaration`).
    // Mirrors the pattern in outline.rs::entry_for_node.
    unwrap_to(node, node_type)
}

fn unwrap_to<'a>(
    node: tree_sitter::Node<'a>,
    node_type: &str,
) -> Option<tree_sitter::Node<'a>> {
    let mut cursor = node.walk();
    let mut children = node.named_children(&mut cursor);
    let child = children.next()?;
    if children.next().is_some() {
        return None; // Multiple named children — don't guess
    }
    if child.kind() == node_type {
        return Some(child);
    }
    unwrap_to(child, node_type)
}
#+end_src
