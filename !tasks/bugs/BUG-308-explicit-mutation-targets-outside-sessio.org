* Scope
In scope:
- Preserve the parent session cwd / subagent cwd default exactly as-is.
- Remove the failure mode where a delegated agent aborts solely because an explicitly targeted mutation path sits outside that cwd (for example, session cwd rooted at ~apps/agentmaker~ while the requested file lives in a sibling ~packages/djinn~ tree).
- Fix the problem at the mutation boundary, not by re-rooting the whole session: code-edit root derivation, path normalization, and any task-level preflight assumptions that still treat outside-cwd explicit targets as invalid.
- Add regression coverage for monorepo sibling-package targets.

Out of scope:
- Changing ~runSubprocess()~ / ~createAgentSession()~ to start subagents at repo root by default.
- Broadening semantic grep / workspace-wide indexing rules for read-only tools.
- Relaxing sandbox policy for implicit or unspecified paths.
- Solving unrelated isolation/worktree behavior beyond what is necessary for explicit file-targeted mutations.

Rationale: the user explicitly wants to keep parent-session context, but an explicit file target outside that cwd must still be writable when the assignment asks for it.

* Existing Patterns
- Task-level file scope is resolved relative to ~session.cwd~ in ~packages/coding-agent/src/task/index.ts:748-755~ and ~1170-1175~. This is correct for relative path resolution and should remain the parent-context basis.
- Nested isolation already discovers repo root separately via ~packages/coding-agent/src/task/worktree.ts::getRepoRoot~; do not conflate that with subagent session cwd.
- Code edit currently hardcodes ~options.root = params.root ? resolveFile(params.root) : sessionCwd~ in ~packages/coding-agent/src/tools/code.ts:702-745~. This is the most likely root-scoping choke point when explicit edit targets escape ~sessionCwd~.
- The code tool already resolves absolute file targets, collects all edit files up front, and routes through a single native edit call. Existing tests live in ~packages/coding-agent/test/tools/code.test.ts~.
- ~packages/coding-agent/src/tools/path-utils.ts::findCommonBasePath~ already computes a minimal common ancestor for multiple paths. Reuse an existing helper or an equivalent local helper; do not invent a second incompatible base-path algorithm.
- Existing task isolation tests in ~packages/coding-agent/test/task/nested-isolation-default.test.ts~ show where task/root decisions are already covered.

* Tests
User workflows to defend:
1. From a parent session rooted at a subdirectory of a monorepo, an explicit code edit targeting a sibling package file succeeds without requiring the session cwd to change.
2. Relative explicit targets that traverse upward (for example ~../packages/djinn/src/foo.ts~) resolve correctly and do not trigger root-scope aborts.
3. In-cwd edits still use the narrow session cwd root; the fix must not widen every code edit to repo root unnecessarily.
4. Task-level delegation preserves parent-session context while still allowing explicit outside-cwd mutation targets to flow through successfully.
5. If explicit targets span unrelated roots such that no meaningful shared workspace root exists, the tool should fail truthfully with a precise instruction (for example: split the edit or pass explicit ~root~), not with a misleading scope abort.

Concrete test files / scenarios:
