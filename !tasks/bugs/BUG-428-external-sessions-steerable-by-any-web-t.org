* Problem

Any authenticated web identity can =injectMessage= / answer blocking events for ANY external
(terminal) session, because external sessions carry no =ownedBy= (only spawned sessions do).
=WebSubsystem.#dispatchExternalRpc= and =answer_blocking_event= check the web token but not which
identity owns the session.

* Why it's acceptable for now

The user explicitly deferred auth/permissions to the network layer (Firezone local network) for
this milestone: "don't think about permissions and auth". Single-operator local use → no real
exposure. Filed so it is not forgotten once multi-user access matters.

* Fix (when picked up)

- Stamp external sessions with an owner identity at register time (the bridge could send the
  logged-in OS user / a per-machine token), OR
- Make steering authz a policy: tokens may be scoped to projects/cwd prefixes.
- Apply the same check to =answer_blocking_event= and =rpc prompt= for external sessions.

* Acceptance

- A web token can only steer sessions it is authorized for, once ownership exists.
- Pre-existing model (token = full access) documented until then.
