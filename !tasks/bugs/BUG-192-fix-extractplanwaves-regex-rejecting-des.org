* Problem

=extractPlanWaves= in =exit-plan-mode.ts= silently drops wave entries whose
links use the org description form =[[id:TARGET][DESCRIPTION]]=. A PLAN
that uses description-style links in its =* Execution Manifest= passes the
child-reference validation gate (PLAN-164 fixed =extractIdLinks= to accept
description links), but the wave-based todo auto-init then produces phases
with zero entries. User symptom: plan is accepted, execution starts, but
the todo roster has hollow wave phases.

Flagged by audit AUD-048-audit-implementation as findings #1 and #2:
- #1: =extractPlanWaves= has the same root-cause bug PLAN-164 fixed in two
  other extractors; it was missed.
- #2: =exit-plan-mode-waves.test.ts= has no description-form coverage, so
  the bug went undetected and has no regression guard.

* Root cause

=packages/coding-agent/src/tools/exit-plan-mode.ts= line 65 currently reads:

#+begin_src typescript
const entryRe = /^\s*-\s+\[\[id:([^\]]+)\]\]\s+(.+)$/;
#+end_src

This regex requires =\]\]= (two close brackets) immediately after the
captured target, so an entry like
=- [[id:FEAT-072-webhook][FEAT-072]] Webhook health= never matches. The
capture shape (group 1 = orgItemId, group 2 = step text AFTER the link)
is correct and MUST be preserved.

This is the same class of bug PLAN-164 fixed in
=packages/org/src/id-links.ts= (line 7) and
=packages/coding-agent/src/loop/ingestion/parser.ts= (line 35).

* Fix

Extend the regex with an optional non-capturing description segment
between the target's closing bracket and the link's final bracket. The
capture groups stay identical in shape:

#+begin_src typescript
const entryRe = /^\s*-\s+\[\[id:([^\]]+)\](?:\[[^\]]*\])?\]\s+(.+)$/;
#+end_src

Trace against =- [[id:FEAT-072-webhook][FEAT-072]] Webhook health=:
- =^\s*-\s+= matches =- =
- =\[\[id:= matches =[[id:=
- =([^\]]+)= captures =FEAT-072-webhook=
- =\]= matches the first =]= after the target
- =(?:\[[^\]]*\])?= matches =[FEAT-072]=
- =\]= matches the link's final =]=
- =\s+= matches = =
- =(.+)$= captures =Webhook health=

Description text is intentionally NOT captured. Only =orgItemId= and
=step= (text after the full link) matter for wave materialization.
