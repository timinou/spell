* Context

** Problem
spell-deploy currently syncs SQLite databases using a two-step approach:
1. On pull: SSH into remote, run =sqlite3 .backup= for each =data/*.sqlite= (full copy), then plain rsync the directories (including the SQLite files).
2. On push: SQLite files are excluded via target config (=*.sqlite=, =*.sqlite-wal= in exclude list).

This has several issues:
- Full backup copy every pull, even if only a few pages changed — wasteful bandwidth
- =.backup= creates timestamped copies on remote, accumulating disk usage
- Plain rsync of live SQLite databases can produce corrupt copies if writes happen during sync
- Push excludes SQLite entirely, making bidirectional SQLite sync impossible
- The =sqlite-backup= config boolean is a crude on/off with no file-level control

** Approach: sqlite3-rsync with auto-discovery
=sqlite3-rsync= is SQLite's official remote-copy tool (stable since SQLite 3.50.0, May 2025). It:
- Syncs SQLite databases page-by-page with hash-based diffing (~0.01% bandwidth for similar DBs)
- Works over SSH natively (=sqlite3-rsync user@host:remote.db local.db=)
- Is WAL-aware and safe against concurrent writers on both sides
- Supports both pull and push directions
- Available via Homebrew (=sqlite-rsync= v3.51.3) and Nixpkgs (=pkgs.sqlite.out=)
- Supports =--ssh PATH= flag for custom SSH program (handles non-standard port/key)

SQLite files are *auto-discovered* — any =*.sqlite= file found in a synced directory is
automatically handled via =sqlite3-rsync=. No per-file config needed. Discovery uses
SSH =find= on the remote (for pull) and local fs scanning (for push).

** Alternatives considered
- *SQLite Backup API via Bun's =node:sqlite=*: Not incremental (full DB copy), no remote support, equivalent to current =.backup= approach. Rejected.
- *Litestream*: Continuous WAL streaming replication. Requires background daemon, different operational model. Overkill for periodic sync. Rejected.
- *Custom VFS over SSH*: Maximum control but enormous complexity for no benefit over sqlite3-rsync. Rejected.

** Key decisions
1. *Require sqlite3-rsync* — error if not found. No fallback to backup+rsync.
2. *Both directions* — push and pull SQLite files via sqlite3-rsync.
3. *Auto-discovery* — any =*.sqlite= in synced dirs is handled automatically. No config field needed.
4. *Remove =sqlite-backup= config* — the boolean and its =normalizeKdlBooleans= hack are deleted.
5. *SSH wrapper script* — generate temp script for non-standard port/key, pass via =--ssh= flag.
6. *Don't touch NixOS module* — the =spell-backup-*= systemd timer is independent.
