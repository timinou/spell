* Problem

Forensic on 945 =edit= calls across 120 recent sessions:

| op kind         | err rate | dominant cause                           |
|-----------------+----------+------------------------------------------|
| =lineReplace=     | 86%      | =span= shape ≠ =LINE#HASH= anchors           |
| =replace= legacy  | 78%      | missing =pos/end= anchors                  |
| =fileFindReplace= | 0.5%     | empty Scope preview hiding missing file  |

The empty-Scope-preview chain (BUG-401 → BUG-402) caused the worst
documented regression in the corpus: =FixBug373= sub-agent burnt 60+
=bash + python3 -c= calls and introduced two syntax bugs after 4
consecutive edit failures on a non-existent path.

The =LINE#HASH= anchor mechanism (FEAT-705) is unused — agents pass raw
line numbers, get a useless error, and either fall back to
=fileFindReplace= (best case) or =bash heredocs= (regression case).

* Goal

Fail loud, accept what agents naturally write, delete the unused
machinery.

1. =edit { root }= honoured end-to-end.
2. Empty-scope error explains the actual cause.
3. Missing-file fast-fail before kernel dispatch.
4. =lineReplace/lineInsert/lineAppend/linePrepend= take raw line numbers.
5. All =LINE#HASH= anchor code, schema, prompts, tests deleted.

* Non-goals

- *No new staleness mechanism.* Optimistic edits are acceptable.
- *No back-compat for =LINE#HASH= strings.* Schema rejects them cleanly.
- *No kernel buffer-registry changes.* Existing =edit_transaction= flow
  preserved.
- *No prompt rewrite beyond removing LINE#HASH guidance.*
- *No FEAT-705 audit / reasoning preservation.* The mechanism existed,
  it's deleted, that's the record.
