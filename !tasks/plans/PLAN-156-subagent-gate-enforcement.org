Why did the GraphRAGModules fail?

* Context

Subagents dispatched via the =task= tool can complete (exitCode 0) without actually satisfying their gate requirements (=gateCmd=, =gateCommit=, =gateArtifact=). The current system injects gate instructions as advisory text into the subagent's assignment, but =finalizeTodoRef= determines status solely from =exitCode=. There is no enforcement.

This was observed in a real failure: GraphRAG subagents yielded code that compiled with warnings, hallucinated APIs, and incorrect Elixir patterns — all because the subagent ignored =gateCmd= (=mix compile --warnings-as-errors=) and no enforcement existed.

** Approach
1. Register a =SubprocessToolHandler= for the ="bash"= tool to track all bash commands executed by subagents (command string + exit code).
2. Implement pure gate verification functions: normalized command matching, git commit detection, artifact file existence.
3. Add =gate_failed= as a new =TodoStatus= — distinct from =failed= (which means the subagent itself errored). =gate_failed= means "subagent completed but didn't satisfy gates."
4. Wire gate verification into =#finalizeTodoRef=: after subagent succeeds, check gates before marking =completed=. If any gate fails, mark =gate_failed= and populate =gateFailures= on the delegation result.

** Key Decisions
- =gate_failed= is a new =TodoStatus= literal (not a flag on =failed=).
- =gate_failed= is terminal and blocking — dependents cannot proceed, phase is not complete.
- Command matching is normalized: strip =cd DIR &&= prefixes, trim whitespace, substring match.
- Gate checks only run when subagent exitCode is 0 (no point checking gates on a crashed subagent).
- =gateCmd=: verified via normalized substring match against bash history (only successful commands count).
- =gateCommit=: verified by detecting =git commit= in any bash command.
- =gateArtifact=: verified by checking file existence at the specified path.
- All work is fully TDD — tests written before implementation for every item.
