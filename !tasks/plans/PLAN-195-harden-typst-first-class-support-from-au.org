* Initial Message

Implement these audit recommendations from org://AUD-059-audit-implementation:

- **What**: Skill `globs` are parsed but dropped before prompt-building, so the new Typst skill cannot actually auto-activate based on `.typ` file presence.
  - **Where**: `packages/coding-agent/src/extensibility/skills.ts` around the `CapabilitySkill -> Skill` mapping (`loadSkillsFromDir` and `loadSkills` result assembly); downstream consumers in `packages/coding-agent/src/sdk.ts` / `packages/coding-agent/src/system-prompt.ts`
  - **Why**: This leaves a core plan contract only partially met: the Typst skill exists, but current runtime skill loading cannot use `globs: ["**/*.typ"]` to load it conditionally. The frontmatter is effectively decorative for the execution path that builds prompts.
  - **Effort**: `medium`

- **What**: `lsp status` reports configured servers as “Active language servers,” even when no client has been started.
  - **Where**: `packages/coding-agent/src/lsp/index.ts` around the `action === "status"` branch
  - **Why**: After adding `.git` to Typst root markers, this can now report `tinymist` as active before any Typst file has actually initialized a client. That is a contract violation in the operator-facing surface: callers cannot distinguish “configured” from “running.”
  - **Effort**: `trivial`

- **What**: There is no automated regression test for the `.git`-based Tinymist activation path.
  - **Where**: `packages/coding-agent/test/` LSP test coverage; specifically no test around `loadConfig()` / `getServerForFile()` for `.typ` files in a repo without `typst.toml`
  - **Why**: Current Typst LSP support depends on a deliberate deviation from the original plan (`rootMarkers: ["typst.toml", ".git"]`). Without a test, a future cleanup could silently remove `.git` and break Typst LSP in ordinary repos.
  - **Effort**: `small`

- **What**: Grammar generation still resolves Typst node-types by the first matching cargo-registry prefix, not the dependency version Cargo actually selected.
  - **Where**: `crates/pi-code-engine/build.rs`, `GRAMMARS` Typst entry and `find_node_types_json()`
  - **Why**: If multiple `codebook-tree-sitter-typst-*` versions exist in the cargo cache, generated rules can drift from the linked parser crate. That creates a non-deterministic failure mode that depends on machine state, not source state.
  - **Effort**: `medium`

- **What**: There is no TypeScript-side smoke test that the `code` tool surface handles a real `.typ` file end-to-end.
  - **Where**: `packages/coding-agent/test/tools/code.test.ts`
  - **Why**: Rust tests prove native Typst outline/navigation behavior, but they do not protect the user-facing `code` tool boundary. A future wiring/rendering regression in `packages/coding-agent` could break Typst support while `pi-code-engine` tests still pass.
  - **Effort**: `small`

* Context

Audit AUD-059 identified five hardening gaps in the PLAN-189 Typst first-class support implementation. This plan addresses all five findings: skill glob-based conditional loading, LSP status truthfulness, tinymist config regression test, build.rs version-aware grammar resolution, and TypeScript-side Typst code tool smoke test.

** Key decisions

1. Skill globs are carried through the =CapabilitySkill → extensibility Skill= mapping and used for conditional prompt inclusion in =system-prompt.ts=. Skills without globs remain always-loaded (backward compatible). No existing skills use globs, so this is safe.
2. LSP status distinguishes "Active" (running clients via =getActiveClients()=) from "Configured (not started)" (in =config.servers= but no client instantiated).
3. Tinymist config test uses existing =TempDir= pattern in =lsp-regressions.test.ts=, covers =.git=-based activation and absence without root markers.
4. =build.rs= reads =Cargo.toml= to extract dependency version specs and prefers registry directories matching the declared version. Falls back to first match for graceful degradation. No new build dependencies.
5. Code tool smoke test follows existing =spyOn(nativesModule, "executeCodeBuffer")= pattern, mocks real Typst outline shape, asserts formatting.
