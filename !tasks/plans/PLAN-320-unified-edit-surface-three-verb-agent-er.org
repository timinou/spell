* Initial Message

dude. look at the ast-grep and ast-edit tools, if they still exist, then review the Rust ecosystem for tools that are natively integrated to tree-sitter for these kinds of needs, on top of analysing the way that pi-code-graph works and is integrated to pi-edit-broker to enable advanced and fast AST edits. How would you implement it and how would you create a foolproof TDD integration and how would you surface these as natural extensions to the CodePath find/get/edit/create tools?

Design doc: [[file:specs/code-graph/unified-edit-surface.md]]

Replace the 30-variant OpKind taxonomy with a 3-verb agent surface (replace, rename, delete) that maps intent to mechanism through the target CodePath shape. Absorb ast-grep's pattern→rewrite into a natural find/replace paradigm with positional template variables ($1, $BODY, $NAME) instead of meta-programming capture syntax.

See design doc for full rationale, multi-language test matrix (9 languages, 72+ tests), Elixir multi-clause dispatch coverage, dollar-sign literal handling, and error hint templates.

* Wave 1: Template Expansion Engine
** Target
- crates/pi-code-path/src/template.rs
- Template parser: $1, $2, $LAST, $BODY, $NAME, $SIG, $DECL, $MATCH
- Escape rules: $$ → literal $, $non-uppercase → literal, ${ → pass-through
- Node-based variable resolution: extract body, name field, signature from tree-sitter node
- Language-appropriate body extraction: {} for C-like, do/end for Elixir, indented for Python
** Tests
- All template variables resolve correctly per language
- $ in source never captured incorrectly
- Unknown template variable → diagnostic with suggestions
- $BODY on non-declaration node → diagnostic

* Wave 2: Unified Action → Op Dispatch
** Target
- crates/pi-code-path/src/unified.rs — unified_op_from_action()
- TargetShape enum derived from CodePath query
- Every target shape × action kind mapped to correct internal Op variant
- The 30-variant OpKind taxonomy becomes implementation detail
** Tests
- Every target shape has dispatcher for replace/rename/delete
- Mismatched action/target → diagnostic with hint
- Adding new OpKind without updating dispatch → compile error (exhaustive match)
