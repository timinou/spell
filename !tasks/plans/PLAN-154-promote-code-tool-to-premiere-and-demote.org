* Context
Promote the =emacs_code= tool to be the premiere way to read and edit source code, renamed to =code=. Demote =read=, =edit=, =write= tools from core tier to standard tier — they become fallback tools for non-code resources, text-based edits, and new file creation.

** Key Design Decisions
1. *Hybrid scope*: Code owns reading + editing source files via AST. Write stays for new file creation. Read stays for internal URLs, images, PDFs, directory listings.
2. *AST-only editing*: Code uses tree-sitter targeting exclusively. Edit tool stays for text-based changes (old_text/new_text, hashline anchors).
3. *Mode guard*: Code's edit operations enforce =enforceModeWrite()= same as edit/write tools.
4. *Full rename*: =emacs_code= → =code= everywhere (tool name, class name, exports, tests).
5. *Tier changes*: Code stays =core=; Read, Edit, Write move to =standard=.
6. *Grammar expansion*: Add markdown-inline, LaTeX, SCSS, Svelte, Jinja2, Just grammars.
7. *Non-code language support*: Outline/read support for Markdown headings, YAML keys, TOML tables, JSON keys.

** Architecture
The Code tool wraps an Emacs daemon running tree-sitter + combobulate via MCP protocol over Unix socket. It provides:
- Resolution-aware reading (0=names, 1=signatures, 2=structure, 3=full source)
- Structural outline extraction
- AST-aware editing (9 operations including combobulate splice/drag/envelope)
- In-file navigation
- Grammar management

Fallback path: When a file has no tree-sitter grammar, the agent falls back to =read= + =edit= tools.
