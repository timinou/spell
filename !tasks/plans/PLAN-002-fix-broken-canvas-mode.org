* Problem

~spell --canvas~ hangs at "Planning..." for 18+ minutes. A previous agent added several features to fluid mode but never tested them end-to-end. The canvas mode is completely non-functional.

Screenshot shows the planner subprocess stuck cycling through submit_result attempts, with messages like "Checking submit tool availability", "Attempting mandated submit path", "Finalizing before submit_result" visible in the QML shell.

* Root Cause Analysis

** PRIMARY: Semantic validation + retry flow doubles planning time with no timeout

The previous agent added ~validateAndRefinePlan()~ which runs: plan -> structural validate -> *semantic validate (LLM call via completeSimple, NO timeout)* -> [if invalid: run planner AGAIN -> validate AGAIN]. Worst case = 2 full planner subprocess runs + 2 LLM API calls = 10-19 minutes.

~validatePlanSemantic~ calls ~completeSimple~ with only the parent AbortSignal (user cancellation only), no built-in timeout. If the semantic validator returns ~{ valid: false }~, it triggers a FULL second planner run with exploration tools (read, grep, find, lsp).

The ~fastPlan~ setting defaults to ~false~, so every user hits this slow path.

** CONTRIBUTING: Top-level await in code-highlight.ts blocks module import

Line 38: ~const highlighter = await createFluidCodeHighlighter()~ at module scope. Import chain: ~fluid-mode.ts -> index.ts -> event-router.ts -> code-highlight.ts~. Shiki loads WASM + 20 TextMate grammars at import time, adding 2-5 seconds startup penalty to every ~--canvas~ invocation. Could hang longer if WASM loading fails.

** CONTRIBUTING: outputSchema renders as "unknown" in subagent system prompt (pre-existing)

~jtdToTypeScript(fluidPlanSchema)~ produces ~"unknown"~ because ~fluidPlanSchema~ is TypeBox (JSON Schema), not JTD. The subagent system prompt tells the planner: "Your result MUST match this TypeScript interface: unknown". Pre-existing, not a regression, but contributes to agent confusion. Not addressed in this plan (separate fix).

With fire-and-forget background initialization:

** ITEM Simplify validateAndRefinePlan to structural-only validation
:PROPERTIES:
:EFFORT: 30m
:END:

File: ~packages/coding-agent/src/modes/fluid-mode.ts~

The current ~validateAndRefinePlan~ calls ~assessPlanCandidate~ which chains structural + semantic validation. Replace with structural-only:

1. Remove the ~assessPlanCandidate~ function entirely
2. Simplify ~validateAndRefinePlan~ to:
   - Call ~validatePlan(initialPlan)~ (structural, synchronous, fast)
   - If valid: return plan (log warnings if any)

The retry for structural failures is cheap and useful (the planner just re-runs with the error as feedback, no extra LLM validation call). Semantic validation is removed from the main flow.
