* Context
Problem: the `code` tool emits verbose file-local payloads that are cheap for machines but expensive for language models. In `packages/coding-agent/src/tools/code.ts`, file-local commands currently send pretty-printed raw JSON into model-visible `content`. Native output from `crates/pi-natives/src/code_buffer.rs` includes low-level editor primitives like `changedRanges`, `inputEdit.startByte`, and diff hunk arrays. This produces noisy context such as the pasted `Code [...]` dumps that are neither token-efficient nor pleasant for an LLM to reason over.

Recommended approach: full cutover for new sessions only. Replace the ad-hoc raw-JSON file-local payload path with a canonical code-tool result contract and a compact model-facing formatter. Preserve all information in structured `details`; make `content` compact, semantic, and task-oriented. Keep graph commands compact. Update transcript/TUI/session consumers to rely on the normalized contract instead of reparsing arbitrary JSON text.

Key decisions
1. No backward-compatibility shims for old code-tool schemas. New sessions/transcripts only.
2. Use a hybrid boundary: Rust may rename/regroup especially noisy low-level fields where it meaningfully improves semantics, but TypeScript owns the final normalized contract and model-visible phrasing.
3. Introduce one canonical contract file, `packages/coding-agent/src/tools/code-result.ts`, with discriminated result types plus one LLM-facing formatter.
4. Follow existing compact-content/rich-details patterns already used by `search_tool_bm25`, `code_search`, `gemini-image`, and `python`.
5. Keep the invariant from `packages/coding-agent/src/session/messages.ts`: `toolResult.content` is model-visible; `details` is not. Therefore the fix must happen at the code-tool content contract, not in caller-side workarounds.
6. Treat live streaming and rebuilt transcript as one design surface. `packages/coding-agent/src/modes/controllers/event-controller.ts`, `packages/coding-agent/src/modes/utils/ui-helpers.ts`, and `packages/coding-agent/src/modes/components/tool-execution.ts` must remain in sync.
7. Verification must include at least one end-to-end/session-level proof that an agent turn now receives cleaner code-tool context during planning/execution.
