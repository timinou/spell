propose improvements to make the get tool more ergonomic overall

* Context

The =get= tool's most common discovery use case (browsing a directory) is broken end-to-end:

- =get { target: "dirname" }= returns =dirname  [§dir]= — a single useless marker
- =get { target: "dirname/" }= returns empty output
- =get { target: "/abs/path" }= returns the same single marker
- =get { target: "dirname#stat" }= renders nothing (metadata is collected by walker but lost in TS formatter)

The native side ships =#listing=, =#tree[depth=N]=, and =#stat= qualifiers that work correctly. The leak is in the TS wrapper (=packages/coding-agent/src/tools/get.ts=) and the formatter (=packages/coding-agent/src/tools/codepath-result.ts=). The prompt =get.md= claims bare path → "directory listing" but only files actually list.

This plan fixes the four leaks together:
1. Bare-path-on-directory auto-attaches =#listing= (mirrors existing =#raw= for files).
2. New =recursive=/=depth= top-level params build =#tree[depth=N]= internally; qualifier remains escape hatch.
3. Format default auto-promotes to fs-listing layout (path + size, =path/=) when all results are fs nodes.
4. Prompt rewritten to match behavior, examples added.

Scope: TS-layer only. Zero =crates/= changes (native qualifiers already correct).
