* Initial Message

Implement these audit recommendations from org://AUD-060-audit-implementation:

- **What**: Atomic vector-cache writes still use a shared fixed temp filename instead of a per-write unique temp path  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `save_vector_cache()`  
  **Why**: `workspace-vectors.bin.tmp` is safe against partial writes from one process, but not against two concurrent semantic-index runs. Concurrent writers can clobber the same temp file or fail during rename, which reintroduces a race in the cache persistence path.  
  **Effort**: small

- **What**: Auto-degrade semantic search paths are untested  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `"search"` branch and `code_graph::tests`  
  **Why**: Current tests cover `semantic: true` hard failure with no vector cache and status reporting for a corrupt cache, but they do not verify the new auto mode behavior that should return BM25 results plus a degradation hint for stale/corrupt vectors or query-embedding failures. A regression here would silently revive the original “plausible results, hidden semantic failure” problem.  
  **Effort**: small

- **What**: The actual JS/N-API boundary for `semanticStatus` is still unverified  
  **Where**: `crates/pi-natives/src/code_graph.rs` export path and `packages/natives` / `packages/coding-agent/test/tools/code.test.ts`  
  **Why**: Rust tests call internal `run_code_graph()`, while TS tests mock `executeCodeGraph()`. That leaves the real N-API marshalling path untested, so a field-name/export mismatch on `semanticStatus` could ship without a failing test.  
  **Effort**: medium

- **What**: Tool docs mention `semantic?` for `search` but not for `index`  
  **Where**: `packages/coding-agent/src/prompts/tools/code.md`  
  **Why**: Users are now told, via runtime errors, to rebuild with `code index` and `semantic: true`, but the prompt surface does not document that `index` accepts the flag. That makes the new contract harder to discover and debug from the public interface alone.  
  **Effort**: trivial

- **What**: Semantic indexing derives dimensions from the first embedding but does not validate the rest of the batch  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `build_semantic_index()`  
  **Why**: This removes the hardcoded `768`, but it still assumes every returned vector matches the first. If fastembed or model configuration changes produce inconsistent dimensions, the cache can be built from malformed data and fail later in a less obvious place. Early validation would make indexing fail truthfully at the source.  
  **Effort**: small

* Context

** Problem

Post-implementation audit of PLAN-190 found five remaining gaps in the semantic search hardening: a race condition in cache writes, missing test coverage for the auto-degrade search path, no N-API boundary verification for the new =semanticStatus= field, incomplete tool documentation, and unvalidated embedding dimensions.

** Approach

Five surgical fixes, most parallelizable. One dependency chain: the temp-filename fix should land before the auto-degrade tests (since those tests exercise the same code path and the fix ensures their temp files don't collide). The N-API test depends on the auto-degrade tests being present so it can verify the same contract. Everything else is independent.

** Key Decisions

1. Unique temp path uses PID: =format!("{VECTORS_CACHE_NAME}.{}.bin.tmp", std::process::id())=. No =tempfile= crate.
2. Auto-degrade tests cover stale and corrupt vector caches with =semantic: None= (auto-detect mode).
3. N-API boundary test lives in =packages/natives/test/native.test.ts= alongside existing native integration tests, calling real =executeCodeGraph= against temp fixtures.
4. Prompt docs add =semantic?= to both the =index= instruction line and operations list.
5. Dimension validation uses =.find()= to check all vectors match the first, returns descriptive error early.
