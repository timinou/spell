* Initial Message

the org get and search tools provide wrong ITEMs and not well ordered. PLease try the tool and tell me the querying improvements you'd make

* Context
The org tool's query and get commands have 7 correctness and usability issues
that compound to make results unreliable:

1. *Sub-heading pollution* (#A): =readCategory= returns ALL items from .org files
   including child sub-headings (=*** ITEM= inside plan bodies). 50.3% of query
   results are sub-heading noise. When querying =todo:ITEM=, 91.5% are noise.
2. *No sorting* (#A): Results come back in filesystem/promise-resolution order.
   No default ordering, no sort parameter exposed.
3. *Duplicate CUSTOM_ID* (#B): =renderItemOrg= emits CUSTOM_ID twice — once
   explicitly and once from the properties dict. SESSION_ID and TRANSCRIPT_PATH
   metadata also leak into output.
4. *org-ql directory paths* (#B): The ql passthrough passes directory paths
   to =org-ql-query= which expects file paths. org-ql-select tries
   =find-file-noselect= on directories and fails silently.
5. *Get full-scan* (#B): =cmdGet= parses 838 files for a point lookup.
   =findCategoryForId= exists but is unused. File naming convention (={ID}.org=)
   has 98.6% compliance, enabling O(1) direct path derivation.
6. *No limit/offset* (#C): Queries return all matching items with no pagination.
7. *Stale DOING items* (data): ~75 zombie PLAN-001/PLAN-002/AUD items stuck in
   DOING, representing ~60% of DOING items.

** Approach
Fix in two waves: Wave 1 handles the 3 bugs (independent, parallelizable).
Wave 2 adds the 3 features (sort depends on level filter being in place,
limit/offset depends on sort). Stale items cleanup is a follow-up.

** Key Decisions
- *TS-side level filtering, not org-ql delegation*: File-level items use
  =#+CUSTOM_ID= frontmatter which is invisible to org-ql (only sees headings).
  Level filtering must happen in the TS reader. org-ql's =(level N)= predicate
  only works for heading levels, not frontmatter items.
- *Default to level=0*: Queries default to file-level items only. The LLM can
  opt-in to sub-headings via explicit =level= parameter.
- *TS-side sorting with org-ql forwarding*: Simple queries sort in TS
  (priority > state > id). Advanced org-ql queries forward the sort param
  to the Emacs side, with multi-key sort support.
- *Keep TS dashboard*: The Emacs =org-dashboard= MCP tool doesn't handle
  file-level (frontmatter) items. Keep the TS implementation but add level
  filtering.
- *Direct path get*: Derive file from ID prefix + convention. Fall back to
  scan on the 1.4% (12 of 835) that don't follow naming convention.
- *org-ql-query.el multi-key sort*: Enhance handler to accept space-separated
  sort keys (=priority todo=) converted to a list for =:sort=.
