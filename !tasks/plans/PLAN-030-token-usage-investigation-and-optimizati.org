Token usage has spiked dramatically in recent sessions, particularly for the djinn project (=/home/user/code/ora/hotelcomm/ecosystem/djinn=). Investigation of logs, session files, and configuration reveals the following root causes, ranked by impact:

| March 28  |             9 | 2.2M                         |

| March 30  |             8 | 6.1M                         |

On March 30, six djinn memory consolidations fired within 8 minutes (09:14-09:21), each consuming 300K-2.3M tokens. The memory system has no staleness check, no cooldown, and no token budget cap.

*** #2: Session Proliferation
48 djinn sessions in 3 days (1, 14, 29, 4 per day). Each session triggers a full memory phase1 + context reload. Many sessions are short (new session per task instead of using =/compact=).

*** #3: Model + Thinking Level
Default model =claude-opus-4-6:xhigh= = 32,768 thinking output tokens per turn (the maximum). Even the =task= role uses Opus at =:low=. Title generation correctly uses Haiku, but all substantive work uses Opus with expensive thinking.

*** #4: Context Payload
