** The tool dispatch seam (THE hook for homoiconicity)
- LLM only ever calls ONE native tool: `lisp_eval`. Everything else is `(tool/name …)`
  INSIDE a PTC-Lisp program. The agent writes Lisp; Lisp calls tools.
  (`beam/ptc_runner-vendored/lib/ptc_runner/sub_agent/loop/ptc_tool_call.ex`)
- `(tool/name args)` → `{:tool_call, name, arg_asts}` → `EvalContext.tool_exec :: (name, args) -> result`.
  tool_exec is a SINGLE host callback (`eval.ex:723`, `record_tool_call` at :996).
  ⇒ `define-tool` = route tool_exec through a runtime registry checked BEFORE native tools.
  ONE seam, no evaluator surgery. This is the strong foundation.
- `SubAgent.run(agent, llm: cb, tools: %{"name" => fn})` — tools is a plain map of
  name→callable; `tool_exec` is built from it. Adding a registry-backed resolver is additive.

** Subscription auth is FULLY portable — no Rust HTTP layer, no req_llm dependency required
