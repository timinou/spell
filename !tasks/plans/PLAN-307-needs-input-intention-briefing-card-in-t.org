* Initial Message

generate a small summary of the intention of a session when it transitions to needs_input, shown in the TUI chat window as a modal-like inline card. design must keep team-chat fan-out as a trivial follow-up.

* Intention & Purpose

When a coding-agent session transitions from a working state (running / streaming) into a "needs the user" state (needs_input / pending_approval), generate a compact "briefing" of what was done, what is stuck, and what is being asked — and render it as a prominent inline card in the TUI chat scroll just before the input editor. The briefing is a first-class session message so it persists across resume and so fan-out to spell-team-chat and Telegram becomes a render-side addition rather than a new pipeline.

* Context & Narrative

Today the user sees the agent's last assistant text, then an editor cursor. The "what am I being asked to decide?" cue is buried in chat scroll. Existing affordances:
- ~SessionManager.setSessionName~ + ~generateSessionTitle~ (utils/title-generator.ts) — proves the smol-model 1-liner pattern.
- ~deriveAgentStatus~ (packages/desktop-common) — the state precedence used to compute ~AgentStatus~.
- ~CompactionSummaryMessageComponent~, ~BranchSummaryMessageComponent~ — established inline "boxed callout" pattern in chat scroll; both backed by a first-class session message kind.
- ~packages/coding-agent/src/session/messages.ts~ — declaration-merging hub for custom session message kinds.
- ~packages/coding-agent/src/modes/utils/ui-helpers.ts~ — message → component dispatch table.

The fan-out target (later, separate work):
- ~EventLogEntryKind~ in ~packages/coding-agent/src/session-bridge/types.ts~ — already plumbs message-shaped events to spell-server registry → spell-team-chat + Telegram.

* Scope
** In-scope (this PLAN)
- A new ~IntentionSummaryMessage~ session message kind (role: "intentionSummary") with fields ~did~, ~stuck?~, ~ask~, ~trigger~, ~eventId?~, ~timestamp~.
- A new ~intention-summarizer.ts~ utility paralleling ~title-generator.ts~: smol-model call returning the three-line DID/STUCK/ASK shape, with current-model fallback when smol unavailable.
- A new ~IntentionSummaryMessageComponent~ rendered as a bordered card with collapsed (3 lines) and expanded (~ctrl+o~) states, accent-coloured to read as "awaiting you", placed at chat tail.
- A new ~IntentionController~ subscribing to status-change in interactive-mode; rising-edge detector into BRIEFING_STATES (needs_input, pending_approval); single in-flight generation with AbortController; placeholder "summarizing…" card swap-on-resolve; debounce/cancel on falling edge.
- Resume: the persisted IntentionSummaryMessage rehydrates the card; no regeneration on startup.
- Tests at three layers: pure transition logic (controller unit), summarizer prompt shape (mock model), component render snapshot.

** Out-of-scope (filed as FUP)
- spell-team-chat bubble + protocol propagation.
- Telegram session-notifications caption prepend.
- ~session-bridge/types.ts~ EventLogEntryKind extension.
- Theme token additions for a dedicated intentionMode accent (uses existing planMode/warning tokens for now).
- Multi-question / multi-event briefing aggregation (the current design emits one card per transition, superseding the previous via ~eventId~).

* Tests
- Workflow 1: session transitions running → needs_input → ~IntentionSummaryMessage~ appended to sessionManager, rendered as boxed card with DID/STUCK/ASK lines.
- Workflow 2: running → needs_input → user submits (running again) before generation resolves → AbortController fires, placeholder dropped, no card persisted.
- Workflow 3: needs_input → user_paused → needs_input → no second briefing; only the first persists.
- Workflow 4: pending_approval with planSummary populated → briefing card includes the plan title in ASK and expanded view shows full planSummary.
- Workflow 5: resume from disk into needs_input with a persisted IntentionSummaryMessage → card renders without re-generation; latest card marked "live" (◆).
- Workflow 6: smol model unavailable + current-model fallback succeeds → card renders with generated text.
- Workflow 7: both smol and fallback fail → minimal card with BlockingEvent.title as ASK, empty DID/STUCK.

* Risks
- *Generation latency dominates UX.* Smol model can be 1-3s. Mitigation: placeholder card emitted synchronously on transition; swap content when generation resolves; AbortController on retransition.
- *Re-render thrash on rapid status flicker.* Mitigation: rising-edge detector with ~#lastBriefedStatus~ guard; user_paused does not count as fresh entry.
- *Persisted card drift after resume.* Mitigation: card carries ~eventId~; on resume, controller reads sessionManager tail and only re-renders the latest card as "live" if the current ~currentBlockingEvent~ matches.
- *Smol model absent in tests.* Mitigation: summarizer accepts an injected ~complete~ fn; default uses ~completeSimple~ but tests pass a stub.
