* Context
Goal: fix the repeated `Anthropic messages stream stalled while waiting for the next event` failure mode without pretending the provider succeeded, and make repeated retry/error attempts understandable in the transcript/TUI.

Repo-grounded findings:
- `packages/ai/src/providers/anthropic.ts` throws the exact idle-stall error via `iterateWithIdleTimeout(...)` after Anthropic stops emitting stream events.
- Current provider behavior already recovers two safe tool-call cases: incomplete tool arguments and completed tool call missing trailing stop.
- Current session behavior (`packages/coding-agent/src/session/agent-session.ts`) treats generic `stream stall` messages as retryable and retries the whole turn.
- Current UI behavior (`packages/coding-agent/src/modes/controllers/event-controller.ts` plus `packages/coding-agent/src/session/tool-call-diagnostics.ts`) keeps retries/errors visible, but repeated stalls can surface as indistinguishable generic failures.
- The referenced failing session (`/home/user/.spell/agent/sessions/-code-ora-monorepo-infra-beam/2026-04-17T10-09-12-579Z_14be07f3e0ede200.jsonl`) showed exactly that pattern: repeated Anthropic idle stalls with little/no differentiating context.

Settled decisions:
1. Scope = two-layer fix: Anthropic provider improvements plus generic session/UI retry-context improvements.
2. Provider work is Anthropic-specific; do not silently change OpenAI/Bedrock behavior in the same change.
3. Session/UI work is generic across providers, but must consume richer provider diagnostics when available.
4. Keep every retry/error event visible for debugging; do not collapse them away.
5. Improve labels/context so repeated attempts are understandable (attempt number, intermediate vs final failure, classified stall context).
6. Preserve successful Anthropic recovery for `stalled_incomplete_tool_args` and `completed_tool_call_missing_trailing_stop`.
7. Do not fake success for thinking/text stalls merely to suppress the error.

Recommended approach:
- First make Anthropic provider stall handling more truthful and classifiable in `packages/ai`, with focused regression coverage.
- Then wire that context through the coding-agent session/TUI so repeated stall attempts remain visible but no longer read like opaque duplicates.
