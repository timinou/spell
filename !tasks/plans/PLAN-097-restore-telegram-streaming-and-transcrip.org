* Context
** Problem
- The Telegram bridge currently handles only a narrow subset of RPC events in =packages/spell-server/src/telegram/bridge/rpc-to-telegram.ts=. Intermediate tool progress is dropped because =packages/spell-server/src/rpc/types.ts= does not model everything the coding-agent RPC stream can emit, especially =tool_execution_update=.
- =packages/spell-server/src/telegram/log-viewer/renderer.ts= already expects a JSONL event timeline, but spell-server does not currently persist that event stream for new Telegram sessions. =packages/spell-server/src/telegram/process-manager.ts= only carries =sessionPath= for resumed sessions, so the log viewer has infrastructure without a default transcript source.
- =packages/utils/src/logger.ts= writes debug logs to rotating files only, and =packages/coding-agent/src/commands/server.ts= has no explicit terminal-debug sink for =spell server --debug=.

** Recommended Approach
Use a spell-server-owned per-chat JSONL event transcript as the canonical record for Telegram conversations. Feed Telegram streaming behavior and the log viewer from the same event vocabulary.

This is the recommended approach because reusing coding-agent session files would not satisfy the requirement: those files preserve finalized conversation state, not the full =message_update=/=tool_execution_update= streaming history the user wants restored and persisted.
