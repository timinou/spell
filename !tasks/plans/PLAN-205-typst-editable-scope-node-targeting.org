* Context
The code tool's Typst line-target behavior is internally inconsistent. Current repo evidence shows Typst declarations are modeled on raw parse kinds (=let=, =import=, =show=) in =crates/pi-code-engine/src/language/mod.rs=, while line-target edit and native fallback resolution live in separate code paths (=crates/pi-code-engine/src/edit/replace.rs= and =crates/pi-natives/src/code_buffer.rs=). Navigation reports raw parse nodes, but edit success currently depends on the caller guessing the enclosing editable container. Comment lines are additionally broken because =crates/pi-code-engine/src/navigate.rs= climbs away from extra nodes, allowing comments to collapse to =source_file=.

Recommended approach: preserve raw =nodeType= for AST truth, add additive editable-scope metadata named =editableScopeNodeType= plus matching editable-scope line/range fields, and unify navigate/edit/native line-target resolution behind one Rust resolver. The fix stays in the engine/native layer; no Typst-only wrapper logic in TypeScript.

Key decisions:
1. Keep raw =nodeType= unchanged.
2. Add additive editable-scope metadata named =editableScopeNodeType=.
3. Include editable scope line/range metadata so callers can round-trip the exact container deterministically.
4. For non-directly-editable lines, expose the nearest editable parent/container.
5. Comments are editable here and must stop resolving to =source_file=.
6. Edit must accept both raw Typst node kinds reported by navigation and the returned editable-scope kind.
7. Regression coverage must include =set=, single-line =let=, multiline helper =let=, comments, and additive compatibility controls for non-Typst languages.
