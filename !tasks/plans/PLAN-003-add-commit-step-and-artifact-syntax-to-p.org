* Context

** Problem
The plan-mode completion protocol instructs the agent to verify, write a completion report, and close org lifecycle — but never to commit. The user must manually request a commit after every plan execution. This is a gap: the commit should be part of the completion sequence.

Two additional issues compound this:
1. Artifacts (screenshots saved under ~plan-artifacts/~) are referenced as plain text paths in completion reports. They should use org-mode file link syntax (~[[file:path/to/image.png]]~) so they render inline when the org file is viewed.
2. Org-mode item files (~!tasks/bugs/~, ~!tasks/features/~, ~!tasks/plans/~) that describe the work are not committed with the code changes. They should be staged together for traceability.

** Approach
Modify ~packages/coding-agent/src/prompts/system/plan-mode-approved.md~ completion protocol to:
1. Add a commit step (step 5) after org lifecycle closure (step 4), before the "if verification fails" guardrail (becomes step 6).
2. Add guidance in the artifacts subsection to use ~[[file:{{orgItemArtifactsDir}}/name.png]]~ syntax for image/artifact references.
3. The commit step explicitly requires staging corresponding ~!tasks/~ org files alongside code changes.

Update the test to verify the new content renders correctly.

** Key decisions
- Commit is step 5 (after org closure, before failure guardrail) — org items should be in their final state before committing.
- The commit message should follow conventional commit format, matching project convention.
- Unrelated workspace changes must not be staged — the commit covers only plan-execution changes plus their org items.
- The ~[[file:...]]~ syntax is standard org-mode for inline file/image links and already used for ~TRANSCRIPT_PATH~ properties across existing org items.
