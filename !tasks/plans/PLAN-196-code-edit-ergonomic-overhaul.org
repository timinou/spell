* Initial Message

How would you make the edit experience with the code tool so ergonomic it's even more ergonomic than giving line diffs in the language?

* Context

The code tool's edit operations are less ergonomic than line-diff editing for
content changes. To change one line in a 50-line function, the agent must
reproduce all 50 lines as =content= in a =replace= operation. The agent must
also know tree-sitter node type names and run =navigate node-at= before editing.

This plan overhauls the code edit UX with three core capabilities:

1. *Symbol targeting*: Address declarations by name (=symbol: "handleRequest"= or
   =symbol: "MyClass.method"=) instead of =line + node_type=.

2. *Scoped find/replace patches*: The agent specifies only what changes. =find= text
   is matched within the symbol's scope (indent-insensitive), and =replace= text
   inherits the matched region's indentation. If =find= is ambiguous (multiple matches),
   the operation errors — the agent must provide more specific text.

3. *Multi-edit batching*: An =edits= array in a single tool call replaces multiple
   sequential calls.

Plus: =replace-body= (keep signature), =wrap= (template with =$BODY=), =rename=
(in-file), and annotated diff response (=@@ symbolName @@= headers).

** Key Design Decisions

1. Symbol resolution via tree-sitter tree walk + =declaration_for()= from outline.rs
2. =node_type= field removed from content operations (replace, insert, kill)
3. =line= retained only for positional operations (drag, splice, clone, transpose)
4. Indent-insensitive matching: leading whitespace stripped per line for comparison
5. Ambiguous match → error with all match positions (no replace-all, no occurrence field)
6. Annotated diff with =@@ symbolName @@= context headers in response
7. Full stack: Rust engine + NAPI + TypeScript schema + prompt
