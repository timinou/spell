* Context

User feedback identifies a contract breach in the `code` tool:
- `packages/coding-agent/src/prompts/tools/code-hint-semantic.md` advertises `code symbols { query }`.
- `packages/coding-agent/src/tools/code.ts` currently rejects `command: "symbols"` via `REMOVED_SEARCH_COMMANDS` and redirects to grep.
- `crates/pi-natives/src/code_graph.rs` still has a native `"symbols"` branch, but it fails with `symbols requires \`query\``.

Settled design decisions:
1. Restore a real `code symbols` command on the `code` tool; do not leave it as grep-only.
2. Contract matches `lsp symbols` structurally:
   - `file` => file-local symbols.
   - no `file` + `query` => workspace symbol lookup.
3. Bare `code symbols` must not error. It returns a concise workspace summary with refinement hints so the command answers “what is symbols about?” truthfully.
4. File mode uses existing code-buffer outline machinery, not LSP.
5. Workspace mode remains native graph-backed; non-empty query semantics stay `exact` / `ambiguous` / `ranked` / `none`.
6. Scope stays narrow: restore `symbols` only. `code files` and `code search` remain removed and continue steering to grep.
7. If both `file` and `query` are provided, file mode wins.

Recommended approach:
- TS surface restoration in `packages/coding-agent/src/tools/code.ts` and `code-result.ts`.
- Native optional-query support for workspace symbols in `crates/pi-code-graph/src/query.rs` and `crates/pi-natives/src/code_graph.rs`.
- Prompt/test cutover so docs and runtime agree in the same change.
