* Initial Message

* Context

After a power loss or crash, spell sessions persist as JSONL files on disk but there is no mechanism to discover and resume them en masse. Status files (~/.spell/status/<windowId>.json~) survive crashes but lack session identification data (ID, file path, cwd) and are actively deleted by ~StatusFileReader.readAll()~. Niri workspace layouts are entirely ephemeral — lost on compositor restart.

This plan adds:
1. Recovery metadata to status files (session ID, file path, cwd, workspace name)
2. A ~spell recover~ command that detects crashed sessions and restores them into ghostty windows across niri workspaces
3. Auto-detection of crashed sessions on normal ~spell~ launch

** Key Decisions
- Status files are the primary crash detection signal: clean exits remove them, crashes leave them with dead PIDs
- ~StatusFileReader.readCrashed()~ reads dead-PID entries without deleting (unlike ~readAll()~ which cleans up)
- Workspace names are captured from niri IPC at session init and stored in status files
- Recovery spawns ghostty windows: ~ghostty +new-window --working-directory=<cwd> -e spell -r <sessionId>~
- Niri workspaces are recreated by name: ~niri msg action focus-workspace <name>~
- Graceful degradation: no niri → skip workspaces; no ghostty → print resume commands
- Auto-detect is notification only (stderr), never blocks startup
