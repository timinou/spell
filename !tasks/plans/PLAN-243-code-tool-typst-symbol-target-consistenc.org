  - `crates/pi-natives/src/code_buffer.rs::resolve_target()` calls `crates/pi-code-engine/src/resolve.rs::resolve_symbol()` for symbol-targeted edits.

  - `crates/pi-code-engine/src/resolve.rs::collect_top_level_names()` does not unwrap `code` wrappers when building `Available: [...]`, which explains the misleading empty list.
- Interpreted error sequence:
  - `section-block` failed because the current canonical name is effectively `section-block(num, title, body)`.
  - `Available: []` was a diagnostic bug, not proof that the symbol was absent.
  - The line-target ambiguity was expected conservative behavior once the symbol path had already failed.

** Settled design decisions
1. Canonical symbol identity for callable Typst `#let` bindings is the base binding name (`section-block`), not the full callable signature.
2. Full callable signatures remain display/detail material for humans, but not the machine-targeted identity used by `code edit`, exact graph symbol lookup, or missing-symbol suggestions.
3. The fix should not be Typst-only string trimming in one call path; native resolve and graph extraction must share one canonical declaration-name rule.
4. The existing line-target refusal for raw `let` vs editable `code` remains unchanged in this plan; users must still specify `node_type` when they line-target Typst code wrappers.
5. After landing the Typst fix, audit other wrapper/name-resolution paths and repair only proven mismatches with regression tests.
