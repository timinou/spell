* Context
Two compounding bugs cause sessions to become permanently stuck with no recovery path.

** Bug 1: Anthropic SSE stream has no idle timeout

After a tool result returns, the agent loop calls =streamAssistantResponse()= to make the
next API call. When the Anthropic API connection stalls (no SSE events arrive), the
=for await= at =packages/ai/src/providers/anthropic.ts= line ~650 blocks forever.
Every OpenAI-family provider wraps its stream in =iterateWithIdleTimeout= (45s default),
but the Anthropic provider does a bare =for await= with no stall protection.

Transcript evidence from two sessions:

1. Session =14b79dc662a38caa=: 90,635 tokens on claude-opus-4-6. Tool results returned
   at 10:40:57. Transcript ends there — 25 min hang, zero log activity.

2. Session =14b79aec8fda64f1=: 210,160 tokens on claude-opus-4-6. =code outline= returned
   in 2ms at 11:47:41.015. Transcript ends at line 343 — 18 min hang, zero log activity.

In both cases, tools worked correctly. The correlation with =code outline= / =code edit= is
incidental — these tools are used deep into exploration sessions when context is enormous.
The real trigger is the Anthropic API silently stalling on large-context stream connections.

Secondary defense-in-depth: =agent-session.ts= has two silent error catch sites
(=#scheduleAgentContinue= line 1037, =#trackPostPromptTask= line 988) that should log
instead of silently dropping.

** Bug 2: Audit hijacks resume

When a user tries to recover from a stall by typing "continue", the plan-mode audit check
fires on the model's first non-tool-use response. If audit state is =pending: "auto"=
(set when plan mode activated), the audit prompt is injected instead of letting the model
resume work. Fix: clear pending audit state on explicit (non-synthetic) user prompts.

** Key Decisions

1. Wrap Anthropic SSE stream in =iterateWithIdleTimeout= (same pattern as all OpenAI providers)
2. Add =PI_ANTHROPIC_STREAM_IDLE_TIMEOUT_MS= env var (default 45s, 0 to disable)
3. Create a =requestAbortController= to cleanly abort the SDK stream on idle timeout
4. The timeout error ("stream stalled") already matches the retry regex in =isRetryableErrorMessage=
5. Add =logger.error()= in =#scheduleAgentContinue= and =#trackPostPromptTask= catch blocks
6. Clear pending audit state in =prompt()= for non-synthetic user messages
