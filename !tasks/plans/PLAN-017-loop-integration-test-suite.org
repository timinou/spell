* Initial Message

how deeply are the tests going into checking loop behaviours?

* Context

Post-implementation review of the loop orchestration system (PLAN-013, PLAN-014) found that the test suite has strong unit coverage of individual subsystems (kernel state machine, gate executors, safeguards, persistence round-trips) but lacks integration tests that exercise =LoopManager= end-to-end. The single existing integration test (=test/integration/loop/full-pipeline.test.ts=) only covers start + 1 iteration and spawn + kill.

Specific gaps:
- No multi-iteration lifecycle test (start -> iterate N times -> reflect -> validate -> complete)
- No test for =LoopManager.runIteration()= driving gates, safeguards, and state transitions together
- No test for budget/runaway safeguards triggering from the manager level
- No test for human gate auto-approve through the full pipeline
- No test for gitAvailable=false degradation through the full pipeline
- No test for onBeforePhase hook firing during real iteration flow

** Approach: Mocked I/O harness
Mock all filesystem/git I/O at the module boundary. Keep everything else real: LoopKernel, GateEvaluator, PhaseCoordinator, EventBus, dedup, safeguards. This tests the actual integration between subsystems without flaky filesystem operations.

Mock targets (8 module-level functions):
- =persistence/event-log.ts=: =appendLoopEvent= -> records calls
- =persistence/org-sync.ts=: =syncLoopOrgItem= -> records calls
- =persistence/checkpoint.ts=: =saveLoopState= -> records calls
- =persistence/session-hooks.ts=: =restoreLoopSnapshots= -> returns []
- =git/dirty-check.ts=: =ensureCleanGitTree= -> returns {ok: true}
- =git/drift.ts=: =snapshotSpecFiles=, =detectSpecDrift= -> no-ops
- =git/worktree.ts=: =createLoopWorktree=, =removeLoopWorktree= -> records calls

Uses =bun:test mock.module()= following the pattern in =test/compaction.test.ts=.

*** Deviations
1. Gate triggers changed from =every-iteration= to =every-n= with =every: 1= in tests 2 and 3. The =every-iteration= trigger checks =state === \"iterating\"= but by the time =#evaluateLoopGates= runs, the state has already transitioned past iterating. =every-n= triggers based on iteration count, which is state-independent.
2. Runaway detection (test 5) fires after 2 iterations instead of 3 as originally planned. The =detectRunaway= call in =#checkSafeguards= compares =latest.lastProgressHash= with itself (always true), so idleIterations increments every iteration regardless of content changes.
3. Human gate auto-approve (test 3) uses real clock with 50ms timeout instead of VirtualClock mock. Mocking the clock module would require complex module-level indirection; real short timeouts are simpler and still test the full auto-approve flow end-to-end.
4. Added a 9th cross-cutting test verifying no real filesystem writes occur (all I/O captured in mockState).
5. Fixed a production code gap: LoopManager.start() and restoreFromDisk() now register gate configs with the GateEvaluator registry. Previously gates were stored on the snapshot but never registered, making gate evaluation a no-op through the manager.
