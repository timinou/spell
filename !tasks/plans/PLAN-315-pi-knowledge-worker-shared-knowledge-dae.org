* Initial Message

"Great review, great plan. […] I also would like a leaner FTS layer over pi-org with a shared user-level daemon."

PLAN-310 deleted the heavy daemon (tantivy). PLAN-315 finishes the job: push the per-session WarmEngine into the embedder daemon, rename it, let many sessions share one knowledge plane the same way they already share one model.

* Locked decisions (from this conversation)

1. *Both lanes in one daemon* — org/memory AND code-graph live in =pi-knowledge-worker=. Two =RepoCache= shapes, one process, one socket.
2. *Push-subscribe model* — daemon pushes =index_changed= events on a long-lived bidirectional socket. Enables /memory TUI live refresh + zero-staleness.
3. *Lazy auto-spawn lifecycle* — extends the existing embedder daemon pattern (pidfile + 30-min idle exit). No systemd dependency.
4. *Fold FUP-088* — W8 (TUI memory browser) and W9 (dual-recall) become trivial once the daemon is the truth. Both land in this plan.
5. *Pre-flight flake fix* — BUG-390 stabilises =cargo test --workspace= before W0. Lands as its own commit before the plan starts.

* Problem

After PLAN-310:

#+begin_example
session N (× tens on a laptop)
 ├─ pi-natives.so loaded (97.5 MB rlib, shared)
 ├─ per-process RecallEngineHandle
 │   └─ WarmEngine { items, docs, bm25, vec, graph }   ← ~30-60 MB per repo, per session
 ├─ embedder subprocess connection
 └─ embedding daemon (one per user, ~1.2 GB model)     ← already shared ✓
#+end_example

The vec lane is already shared via OS page cache (mmap'd =vectors.uidx=). BM25 + graph + items are *per-process duplicated*. 10 sessions on the same repo = 10 × WarmEngine.

The TUI memory browser was deferred (FUP-088 W8) because it would need its own coding-agent shim to talk to the in-process recall engine. Dual-recall (FUP-088 W9) was deferred because wiring two WarmEngines per session doubles RSS. Both problems vanish if the WarmEngine moves out of the session.

* Goal

One =pi-knowledge-worker= daemon. Both org/memory + code-graph lanes resident. Sessions are thin clients over a unix socket. Push-subscribe enables live TUI + zero-staleness queries. Per-session RSS drops by ~75 MB; daemon's RSS is paid once per user.

* Non-goals

- *No protocol-v1 break.* =init=, =embed_batch=, =embed_query= preserved exactly. Old =pi-embedding-worker= binary symlink and =embed.sock= retained one release.
- *No on-disk format break.* =~/.cache/spell/knowledge/<repo-hash>/= layout unchanged. No migration tool.
- *No systemd dep.* Lazy auto-spawn + idle exit. Users who want resident: =KNOWLEDGE_IDLE_TTL_SECS=0=.
- *No SQLite/Surreal/external DB.* Org files stay source of truth.
- *No multi-host.* Single laptop, single user, single daemon.
- *No editing from /memory panel.* Read-only browser.

* Risks

| risk | mitigation |
|------|------------|
| single daemon = SPOF | lazy auto-spawn covers crashes; pidfile guarantees one per user |
| RPC tail latency adds 5-10ms | budgeted in W8 gate; mitigated by in-process fusion logic (network only for state access) |
| many subscribers leak daemon memory | bounded broadcast channel + W4.5 lifecycle audit |
| socket protocol version drift | =init= returns =protocol_version=; client refuses mismatch, falls back to in-process |
| flake re-emerges at scale | BUG-390 + W5.5 audit guards CI |

* Escape hatch

In-process WarmEngine fallback retained through W4. Phase-4 deletion (W5) is the last cutover commit and is reversible by single =git revert=. =PI_KNOWLEDGE_WORKER=inprocess= env keeps an escape path indefinitely for one-off debugging.
