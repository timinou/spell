* Initial Message

How does this coding harness manage token caching, especially with Anthropic Opus? Is there any room for improvement? Look at usage statistics if you can find them.

* Context
** Current state
Spell's token caching is already highly effective. Analysis of 20 recent sessions (1,290 turns total) shows:
- *99.9% average cache hit rate* across sessions
- Cache write/read ratio of ~4.8% (writes are small, incremental deltas)
- Post-compaction cache recovery is fast (system+tools cache breakpoints survive)
- The Anthropic direct API provider uses a well-designed 4-breakpoint strategy: tools → system → penultimate user → last user

The implementation lives primarily in ~packages/ai/src/providers/anthropic.ts~ (~applyPromptCaching~, ~getCacheControl~, ~buildAnthropicSystemBlocks~) with the ~prompt-caching-scope-2026-01-05~ beta enabled for scoped caching.

** Key findings
1. *Bedrock caching is under-optimized*: Only 2 cache points (system + last user) vs 4 on direct API. Missing: tool definitions and penultimate user message. For Bedrock Opus ($15/MTok input), this means tool definitions (~2-4k tokens) are re-processed every turn at full cost.

2. *Cache retention default is conservative*: Defaults to "short" (5-min TTL). The 1h TTL (~"long"~) is free on Anthropic's direct API and costs nothing extra. Users who pause >5 minutes pay a full cache re-write ($18.75/MTok for Opus). Most users don't know about ~PI_CACHE_RETENTION=long~.

3. *Proxy URL gate blocks 1h TTL*: ~getCacheControl()~ only enables 1h TTL when ~baseUrl.includes("api.anthropic.com")~. Custom proxies never get extended caching even when ~PI_CACHE_RETENTION=long~ is set. Decision: remove this gate entirely — proxies forward cache_control as-is, and the user explicitly opted in.

4. *OpenRouter gets 1 breakpoint*: ~maybeAddOpenRouterAnthropicCacheControl()~ only places one breakpoint on the last message. System and tool caches are wasted.

5. *No cost-savings visibility*: Dashboard shows cache rate (%) but not dollar savings. For Opus, the difference between cached ($1.5/MTok) and uncached ($15/MTok) is 10x.

** Approach
Incremental improvements to providers and defaults. Each item is independent and can be shipped separately. Ordered by cost-impact x effort ratio.

** Key decisions
- Default cache retention changed from ~"short"~ to ~"long"~ globally
- ~api.anthropic.com~ base URL gate for 1h TTL removed — applies to all Anthropic-messages endpoints including custom proxies
- ~PI_CACHE_RETENTION=short~ and ~PI_CACHE_RETENTION=none~ remain as explicit overrides

** Cost model reference (Anthropic Opus 4)
| Token Type     | Cost/MTok |
|----------------+-----------|
| Input          | $15.00    |
| Cache Read     | $1.50     |
| Cache Write    | $18.75    |
| Output         | $75.00    |

Cache reads are 10x cheaper than uncached input. Cache writes are 1.25x more expensive than input but amortized across all subsequent turns in the cache window.
