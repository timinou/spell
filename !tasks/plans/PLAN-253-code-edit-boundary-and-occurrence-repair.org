* Context
User request: audit the broader `code edit` scope behind the reported behavior table and session transcript, separate structural-now work from follow-up work, then produce an execution handoff that a fresh session can implement without prior context.

Settled design decisions:
1. Full-cutover `findAndReplace.occurrence` is structural-now work, not follow-up. The native engine already supports `Occurrence::{Unique, First, Last, Index, All}` in `crates/pi-code-engine/src/edit/patch.rs`, and the native bridge already parses it in `crates/pi-natives/src/code_buffer.rs`; the missing layer is the public TypeScript code-tool contract and prompt/docs.
2. `insertBefore` / `insertAfter` must stop having split semantics. Today line-target insertion is guarded in `crates/pi-code-engine/src/edit/replace.rs`, while symbol-target insertion in `crates/pi-natives/src/code_buffer.rs` is a raw byte splice. The plan adopts auto-normalization for safe symbol-target cases, with rejection of shared-boundary or otherwise unsafe insertions.
3. The current execution slice includes adjacent hardening for `splice`, `move`, `clone`, and `transpose`, but only for violations in the same boundary/indentation invariant family. Larger API redesign remains deferred.
4. Broader UX/API redesign, preview-driven disambiguation, and transcript/debug ergonomics are follow-up work only after the structural fixes land.

Critical evidence from the repo:
- `crates/pi-code-engine/src/edit/patch.rs` already implements ambiguity selection and errors that mention `occurrence`.
- `packages/natives/src/code-buffer/types.ts` and `packages/coding-agent/src/tools/code.ts` do not currently expose `occurrence`.
- `crates/pi-natives/src/code_buffer.rs::single_action` currently routes symbol-target `insertBefore` / `insertAfter` through raw `TextEdit` insertion instead of the guarded helpers used by line targets.
- `crates/pi-code-engine/src/edit/splice.rs`, `drag.rs`, `clone.rs`, and `transpose.rs` are the adjacent structural action family that must be audited under the same invariant.
