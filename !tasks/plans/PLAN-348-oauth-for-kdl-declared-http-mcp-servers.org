First start with the mcp connection

* Problem

Hosted OAuth MCP servers (Notion `https://mcp.notion.com/mcp`, Linear, GitHub, Sentry…) cannot be authenticated when declared in `spell.kdl`. A `mcp { server X type=http { url … } }` block loads at startup, hits the endpoint, receives `HTTP 401 invalid_token`, and dies silently with `MCP tool load failed`. There is no path to run the OAuth browser flow for a KDL-declared server.

** Root cause — the RUNTIME is already complete

`MCPManager.#resolveAuthConfig` (manager.ts:935) already: proactively refreshes tokens (5-min buffer), injects `Authorization: Bearer <access>` for http/sse, and `connectServers` wires `onAuthError` so a 401 forces a refresh. This all works — *for a server that carries an* `auth { type=oauth credentialId=… }` *block*.

The break is entirely in the CONFIG + COMMAND plane. Three defects:

*** GAP 1 — KDL `auth {}` round-trip is lossy

`McpServerKdlEntry.auth` (config/kdl-compatibility.ts:308) = `{ type, credentialId }` ONLY. The runtime `MCPAuthConfig` (mcp/types.ts:47) needs `tokenUrl`, `clientId`, `clientSecret` for token refresh. `readMcpServers` (:391) and `writeMcpServers` (:445) both drop those three fields. ∴ even a hand-authored/programmatically-written `auth {}` block cannot refresh → dies at first token expiry.

*** GAP 2 — no OAuth trigger for KDL servers

`/mcp reauth` → `#findConfiguredServer` (mcp-command-controller.ts:629) reads ONLY `mcp.json` via `getMCPConfigPath`. A kdl-declared server → "Server not found". No command path runs the browser OAuth flow → `credentialId` is never minted → the `auth {}` block GAP 1 would carry never comes into existence. This is the "Server notion not found" error we hit.

*** GAP 3 — startup 401 is terminal, not actionable

`connectServers` catches the 401 and logs `MCP tool load failed`. For a server whose `WWW-Authenticate` advertises OAuth and which has no stored credential, nothing surfaces a "needs auth — run /mcp login X" prompt. Silent dead-end.

* Token storage model (DECIDED)

- Secrets (`access`, `refresh`, `expires` tokens) → `~/.spell/agent/agent.db` SQLite `AuthStorage` (machine-local, gitignored), keyed by `credentialId`. Path via `getAgentDbPath(agentDir)` → `discoverAuthStorage` (sdk.ts:297).
- Non-secret coordinates (`type`, `credentialId`, `tokenUrl`, `clientId`) → project `spell.kdl` `auth {}` block. Safe to commit.
- `clientSecret` (rare; not needed for PKCE-public clients like Notion) → env-var indirection only: KDL stores an env-var NAME, resolved via `resolveConfigValue` (already applied to headers/env in `#resolveAuthConfig`). NEVER a literal secret in versioned config.

* Design decisions

- D1: keep the KDL-declares / agent.db-holds-secrets split. It is correct and deliberate.
- D2: redirect the `/mcp` command layer (`#findConfiguredServer`) to read settings tiers (`settings.getPerTier("mcp.servers")`) — the same primary source `builtin.ts::loadMCPServers` uses — instead of raw `mcp.json`. One redirect fixes reauth/unauth/test/enable/disable uniformly.
- D3: persist OAuth result back to KDL via `settings.set("mcp.servers", map, tier)`, not `updateMCPServer` (mcp.json). Scope→tier: `--scope user`→user (`~/.config/spell/spell.kdl`), `--scope project`→project (`<cwd>/spell.kdl`).
- D4: convert the terminal startup 401 into an actionable, non-fatal "OAuth required — run /mcp login X" status + a thin `/mcp login <name>` subcommand.
- D5: GAP-1 widening = three edits that MUST move together (interface + reader + writer), invariant = symmetric round-trip.
