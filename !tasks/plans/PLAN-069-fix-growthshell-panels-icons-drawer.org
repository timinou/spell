* Context

The =spell growth= command launches a QML shell (=GrowthShell.qml=) that is currently non-functional. Three bugs make it unusable:

1. **Panel loading broken**: The main content area always shows "Select a workspace to begin" because =mainPanelLoader= never has its =source= set. The panel registry (=bridge.props.panels=) with resolved QML paths is completely ignored. Workspace selection triggers a round-trip to TS (=workspace_switch= → =workspace_layout=), but the returned panel slot data is stored in =currentPanels= and never used to load anything.

2. **Icons render as text**: Workspace icon names ("home", "search", "lightbulb") display as literal strings instead of emoji/symbols. No icon font or name→glyph mapping exists.

3. **ChatDrawer invisible/non-functional**: The 56px collapsed bar blends into the background. The drawer's =chat_message= event type is not handled by =qml-mode.ts= (which only processes ="prompt"=, ="abort"=, ="steer"=, ="workspace_switch"=, ="restart"=). Agent tab updates are never sent.

** Key Architecture Context

=qml-mode.ts= launches the shell with =bridge.props= containing:
- =panels=: Array of ={ id, title, icon, path }= where =path= is an absolute filesystem path to the QML file (resolved by =resolveDomainPanels=)
- =workspaces=: Array of ={ id, name, icon, panels: [{ panelId, position }] }= where =panelId= references the =panels= array by =id=

The default =shell.qml= works because it uses =bridge.props.panels= directly with a =Repeater= + =Loader= pattern driven by =panelsModel=. GrowthShell ignored this architecture.

** Approach

Fix all three in =GrowthShell.qml= as a single coherent change:
- Build a panel registry (=panelId= → QML path) from =bridge.props.panels= on startup
- Wire workspace selection to load the main panel via the registry
- Add icon resolver function for sidebar
- Route =chat_message= events to =session.prompt()= in =qml-mode.ts=
- Improve ChatDrawer collapsed-state visibility
