* Initial Message

the telegram pdf upload to the user does not work my man. it should. I want it to work. is it registered through a tool call? how does the telegram bridge handle giving ht eability to send tool calls?

* Context
The Telegram bridge currently handles only text responses. When the agent generates files (PDFs, images, CSVs) or uses =generate_image=, the user sees only a text summary — the actual file never reaches them.

The root cause: =ResponseStreamer= in =rpc-to-telegram.ts= only builds text/HTML and calls =ctx.reply()=. It never extracts file/image data from =tool_execution_end= events, despite the RPC protocol already carrying full =details= payloads (including =imagePaths= and =images= for =generate_image=).

** Approach
Two delivery mechanisms:
1. *Explicit*: New =send_file= builtin tool lets the agent explicitly send any file. Tool validates the file (exists, <=50MB), returns path-based metadata in =details=. Bridge intercepts =tool_execution_end= for this tool, reads the file from disk, sends via grammy =replyWithDocument()= / =replyWithPhoto()=.
2. *Auto*: Bridge intercepts =generate_image= results and auto-sends images via =replyWithPhoto()=. Controlled by =auto-send-images= KDL config (default: true).

** Key Decisions
- *Path-based delivery* (not base64): Both processes run on the same machine. Sending absolute paths through RPC avoids 50MB+ base64 payloads through the JSON pipe. Bridge reads files directly from disk.
- *Two-layer approach*: Explicit tool for general files + auto-intercept for images. Agent keeps explicit control for documents; images from =generate_image= are always visual and always intended for the user.
- *Graceful degradation*: File delivery errors are logged but never break the text response flow. The agent's text response still arrives even if file delivery fails.
- *Tool works outside Telegram*: =send_file= returns delivery metadata regardless of context. Only the bridge acts on it. In non-Telegram modes the tool is simply not available (not in =MODE_TOOLS=).

** Architecture
#+begin_example
Agent calls send_file("report.pdf")
  -> Tool validates file, returns { details: { delivery: { absolutePath, mimeType, ... } } }
  -> RPC event: tool_execution_end { toolName: "send_file", result: { details: ... } }
  -> Bridge ResponseStreamer intercepts event
  -> Reads file from absolutePath via Bun.file()
  -> Sends via ctx.replyWithDocument(new InputFile(buffer, filename))

Agent calls generate_image(...)
  -> Tool generates image, saves to /tmp, returns { details: { imagePaths: [...] } }
  -> RPC event: tool_execution_end { toolName: "generate_image", result: { details: ... } }
  -> Bridge ResponseStreamer intercepts event (if autoSendImages=true)
  -> Reads each image from imagePaths
  -> Sends via ctx.replyWithPhoto(new InputFile(buffer, basename))
#+end_example
