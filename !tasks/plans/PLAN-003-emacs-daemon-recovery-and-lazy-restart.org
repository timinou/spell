* Context

The emacs_code tool returns \"Emacs daemon unavailable\" when toolSession.emacsSession is null/undefined. The daemon lifecycle has a fundamental gap: startup is one-shot (warmupEmacs runs once during session init), getSession() is a pure property reader with no retry, and the health timer detects crashes but never triggers recovery.

The Emacs PGTK build on Wayland is known to exit when the display connection drops (screen lock, monitor unplug), making runtime daemon death a real operational scenario, not theoretical.

** Problem
- packages/emacs/src/tool.ts:37 checks !session (null/undefined) but NOT isAlive()
- getSession() in packages/coding-agent/src/tools/emacs.ts:69 is () => Promise.resolve(session.emacsSession ?? null) — a dead-end property read
- No code path exists to restart the daemon after it dies or if warmup was skipped
- The health timer in daemon.ts evicts dead sessions from cache but nobody re-creates them

** Approach
Introduce EmacsSessionManager (new class in packages/emacs/src/session-manager.ts) that wraps getSession() with lazy-init + circuit breaker retry. Wire it through sdk.ts and EmacsTool, replacing the bare emacsSession property.

** Key decisions
- TDD: write all tests first, then implement
- Circuit breaker: 3 consecutive failures = 60s cooldown before retrying
- Concurrent calls coalesce into one startup attempt (pending promise lock)
- Preserve existing warmup-at-init fast path via setSession() injection
- detection failures trip the breaker permanently (no point retrying if emacs isn't installed)
