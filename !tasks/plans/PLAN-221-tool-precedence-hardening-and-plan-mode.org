* Context

The agent's system prompt has three problems that reduce execution quality:

1. **Tool precedence**: `edit` and `write` are presented as general-purpose tools, but `code edit` should be the unambiguous default for source file modifications. The tool descriptions (patch.md, write.md) don't mention `code edit` at all — a model reading them in isolation doesn't know a better option exists.

2. **Task delegation**: The `eagerTasks` setting that promotes delegation defaults to `false`. Most sessions don't see the "delegate by default" instruction, leading agents to do multi-file work manually instead of dispatching subagents.

3. **Plan mode sub-outlines**: Standard plan mode items have unstructured bodies. The ultraplan body standard (required sections, `PARENT-ID::sub-slug` CUSTOM_IDs, `:DEPENDS:` on sub-headings) only appears in ultraplan mode. Standard plans can't use `org wave` because items lack the structured sub-outline format.

4. **DEPENDS validation gap**: `exit-plan-mode.ts` validates top-level `:DEPENDS:` references but not sub-outline `::` IDs. Broken sub-outline dependencies, duplicates, and cycles pass validation silently and only surface at execution time.

** Decisions

1. Change `task.eager` default from `false` to `true`
2. Strengthen precedence wording: edit is "ONLY non-code", write is "new files only"
3. Add `code edit` operation list to system prompt
4. Add anti-patterns to patch.md and write.md directing to `code edit`
5. Port full ultraplan Org Item Body Standard to shared section (both modes)
6. Add `org wave` instruction to standard plan mode workflow
7. Extend exit-plan-mode validation: sub-outline ID collection, cross-reference validation, cycle detection
