* Context

PLAN-056 implemented the FluidOrchestrator infrastructure (types, DAG, scheduler, bridge, coordinator, prompts) but left critical wiring gaps. The ~fluidPlan~ field in ExitPlanModeDetails is never populated, deferred nodes aren't detected, coordinator prompts lack item body context, sub-plans skip validation, and there's no concurrency cap across coordinators. These gaps must be closed before any real plan can execute via the FluidOrchestrator path.

** Approach
Six focused features, mostly independent. The MCP wiring (FEAT-152) is the critical path — everything else can proceed in parallel after it lands. Implementation is test-first where practical: ERT tests for Elisp changes, TS tests for scheduler/orchestrator changes.

** Key Decisions
1. OrgClient access: expose via ToolSession rather than adding an org subcommand. Direct callTool is simpler and avoids the org tool dispatch overhead.
2. Deferred detection: FUP- prefix on CUSTOM_ID. Simple, matches existing convention, no configuration needed.
3. Concurrency: shared semaphore across coordinators rather than per-coordinator limits. Prevents runaway API calls.
4. Sub-outline resolution: verify org-element-map first, implement fallback only if needed. Prefer not adding complexity if the existing code works.
