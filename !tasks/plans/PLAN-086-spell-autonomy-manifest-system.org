* Context
** Problem
Non-technical cofounders need to set up recurring automated workflows (test suites, security reviews, deployments) that run unattended on a remote server. Today, Spell is interactive-only with no scheduling, unattended execution, or declarative workflow specification. The Telegram bridge (PLAN-080, FEAT-204-208) provides the RPC session management foundation but has no autonomy capability.

** Approach
Build a unified =packages/spell-server/= daemon that imports =packages/telegram-bridge/= as a library and adds autonomy scheduling, execution, and observability. The daemon runs as a foreground process managed by systemd/supervisor on the remote server. It loads three KDL config files, optionally starts the Telegram bot, schedules goals via cron, accepts webhook triggers, and exposes an HTTP dashboard.

** Key Decisions (all settled)
*** Architecture
- One unified daemon: =packages/spell-server/= imports =packages/telegram-bridge/= as library
- telegram-bridge exports: RpcClient, ProcessManager, bot setup, message bridge, log viewer renderer
- Telegram fully optional -- daemon works autonomy-only, telegram-only, or both
- CLI: =spell server start= foreground process, managed by systemd on remote box

*** Config (3 files, all KDL via @bgotink/kdl)
- =.spell/server.kdl= -- deployment-specific (HTTP port, auth credentials)
- =.spell/channels.kdl= -- notification channels (Telegram config, future Slack/Discord)
- =.spell/autonomy.kdl= -- repo-checked-in manifest (setups, goals) -- syncs to server via git pull webhook

*** Manifest Hierarchy
Reusable =setups= (domain, mode, skills, tools, sandbox, timeout, cost) crossed with =goals= (setup ref, schedule, prompt, state, hooks, retry). Full KDL schema documented in FEAT-224.

*** SessionManager
Generic =SessionManager<K>= with pluggable lifecycle strategies. Telegram instantiates with chatId key + idle timeout. Autonomy instantiates with goalName key + completion-based lifecycle. Both use RpcClient from telegram-bridge.

*** Sandbox Enforcement
- CLI flag: =--sandbox-policy /tmp/spell-sandbox-XXXX.json= (daemon writes temp file, child loads at startup)
- Enforces: path write restrictions + bash allow/deny regex
- paths_read enforcement deferred to FUP-022

*** Hooks
- NotificationSender interface: direct ref, no-op when Telegram unconfigured
- Three executors: WebhookHookExecutor, TelegramHookExecutor, OrgHookExecutor
- Failure escalation: retry N with backoff -> Telegram + auto-create BUG org item -> goal paused

*** State
- Per-goal SQLite: daemon metadata table + agent KV store + optional typed schema
- =autonomy_state= hidden builtin tool, activated via =--tools=
- DB path via =SPELL_AUTONOMY_STATE_DB= env var

*** Scheduling
- croner library for cron with timezone/jitter
- Webhook triggers via =POST /trigger/:goal= with HMAC or bearer auth

*** Frontend
- Preact/HTM (no build step, ESM imports from esm.sh CDN)
- Dashboard: goals list with status, run history, manifest viewer, trigger buttons, live polling
