* Context

Add a builtin "explore" mode — the simplest possible mode. It keeps the regular system prompt and enforces read-only file access. No plan-mode templates, no audit lifecycle, no tool filtering. Just the normal agent experience with file writes blocked.

** Key Design Decisions
- Standalone user mode (no ~extends~ — does not extend plan or audit)
- ~readOnly: true~ in frontmatter — leverages existing ~enforceModeWrite~ in ~mode-guard.ts~
- All tools remain available — read-only enforcement happens at the tool execution layer (write/edit/ast_edit/notebook throw ~ToolError~), not by removing tools from the active set
- Activated via ~/explore~ slash command (via ~command: /explore~ in frontmatter)
- Lives in a new ~src/modes/builtins/~ directory to separate builtin modes from base/example definitions
- Builtin mode directory uses same structure as user modes (~<name>/MODE.md~), scanned by existing ~scanModesDir~

** Architecture
- The mode system already supports standalone user modes via ~UserModeState~ with ~readOnly: true~
- ~enforceModeWrite~ in ~tools/mode-guard.ts~ already checks ~isUserMode(state) && state.readOnly~ and throws ~ToolError~
- ~handleModeCommand~ in ~interactive-mode.ts~ already creates ~UserModeState~ for non-plan, non-audit modes
- Mode slash commands are registered from ~frontmatter.command~ via ~registerModeCommands~ in ~builtin-registry.ts~
- The only missing piece: mode discovery (~discovery/builtin.ts~) only scans ~.spell/modes/~ directories, not package builtins
