*** What Aphrodite evaluates

*Visual Identity & Distinctiveness*
- Would this design be mistaken for generic AI output? Run the "which AI made this?" test.
- Does the aesthetic direction have genuine personality, or is it playing it safe?
- Are typography choices distinctive? (Flag Inter, Roboto, Arial, system fonts)
- Is the color strategy bold enough? (Flag purple-on-white, evenly-distributed palettes, gray-on-gray)
- Are there unexpected visual details that create delight? (gradient meshes, noise textures, geometric patterns, custom cursors, grain overlays — when appropriate to the direction)

*Visual Coherence*
- Does every decision reinforce the stated aesthetic direction?
- Are there conflicting visual signals? (e.g., brutalist typography with soft pastel colors)
- Is the visual hierarchy clear — can you tell what's most important without reading?
- Does the spatial composition have rhythm, or is everything evenly spaced?

*Memorability*
- Is the stated "one memorable thing" actually memorable?
- Would someone screenshot this? Would a designer ask "how was this made?"
- Does it have a clear point-of-view, or is it committee-designed?

*Anti-convergence*
- Does this repeat patterns from recent design-history.jsonl entries?
- Are there enough differences from previous designs in this project?

*Accessibility through a visual lens*
- Will the color choices meet contrast requirements while still being beautiful?
- Can focus states be styled distinctively within the aesthetic direction?
- Will the chosen typography be legible at the planned sizes?

- RISKS: aesthetic choices that will collapse into AI slop during implementation

** ITEM Create Athena agent prompt
:PROPERTIES:
:EFFORT: 30m

File: =packages/coding-agent/src/prompts/agents/athena.md=

Athena is the UX strategist — she sees flows, states, interactions, information architecture. She's the one who knows whether a beautiful interface actually WORKS: whether users can navigate it, whether error states are handled, whether the interaction model is learnable.

Frontmatter: =model: pi/slow=, =thinking-level: high=, =blocking: true=, =tools: read, grep, find=. Post-planning gate (triggered from approval UI, like Momus).

*** What Athena evaluates

*Interaction Design*
- Are ALL interaction states planned? (default, hover, focus, active, disabled, loading, error, empty)
- Do interactive elements have appropriate feedback? (button press: 100-150ms, loading states after 300ms)
- Is touch target sizing planned? (44x44px min, 8px spacing between targets)
- Are there hover-only interactions that would fail on mobile?
- Do animations convey meaning, or are they decoration? (Every animation must express cause-effect)
- Is motion interruptible? Can users tap/gesture to cancel in-progress animations?

*Information Architecture*
- Is the content hierarchy clear? What's primary, secondary, tertiary?
- Does progressive disclosure work? (Summary → detail on demand, don't overwhelm upfront)
- Are navigation patterns appropriate for the depth? (3-6 sections: top nav; 10+: sidebar; deep: breadcrumbs)
- Is the primary CTA obvious? (One primary per viewport, secondary actions visually subordinate)

*State Coverage*
- Empty states: do they guide the user toward action, or just say "nothing here"?
- Error states: do error messages state cause + how to fix? (Not just "Invalid input")
- Loading states: skeleton/shimmer vs spinner? (Skeletons for >1s operations)
- Confirmation flows: destructive actions require explicit confirmation?

*Flow Logic*
- Can the user always go back? Is back-navigation predictable?
- Are there dead ends? Can the user always reach primary navigation?
- Multi-step flows: is there a progress indicator? Can you go back?
- Form validation: on blur, not keystroke? Error placement near field?

*Responsive Strategy*
- Is there a mobile-first approach with clear breakpoint behavior?
- Does content priority shift appropriately on mobile? (Core content first, fold secondary)
- Are there layout decisions that would cause horizontal scroll on mobile?

*Accessibility through a UX lens*
- Is tab order logical?
- Do forms have visible labels (not placeholder-only)?
- Are screen reader announcements planned for dynamic content?
- Does the plan respect =prefers-reduced-motion=?
