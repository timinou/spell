* Context

The spell-server's Telegram bot (code now in =packages/spell-server/src/telegram/= and =packages/spell-server/src/rpc/=, merged from the former =telegram-bridge= package) replies with "Assistant completed without a text response" when the agent encounters any error. Two distinct issues cause this:

** Issue 1: No model slug passed to the RPC process

The RPC client (=packages/spell-server/src/rpc/rpc-client.ts=) spawns =spell --mode rpc= without a =--model= flag. The spawned process relies on whatever model the user has in =~/.spell/agent.db=. If none is configured, =session.prompt()= throws "No model selected" instantly and the user gets a meaningless error.

Fix: add a required =default-model= field to the telegram block in =channels.kdl=. Validate at config load (fail startup if missing). Pass as =--model <slug>= to the spawned process.

** Issue 2: Errors are silently swallowed by ResponseStreamer

Even when the LLM is configured, runtime errors (auth failure, rate limit, =stopReason=error=) produce no text events. =ResponseStreamer= (=packages/spell-server/src/telegram/bridge/rpc-to-telegram.ts=) only collects text from =text_delta= / =text_end=. Error info in =message_end= payload and ={type: response, success: false}= events is ignored. Additionally, a failed prompt-command response doesn't resolve =promptCompletion= in =rpc-client.ts=, causing a 5-minute hang.

Fix: widen =RpcEvent= types, handle error responses in =rpc-client=, surface errors in =ResponseStreamer=.

- =src/config/types.ts= — =TelegramChannelConfig= type
