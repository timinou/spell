* Context
Audit AUD-067 identified four hardening gaps in the preview/apply mutation path implemented by PLAN-228:

1. =applyPendingAction()= throws after persist succeeds when buffer invalidation fails → caller loses the resolution, state is ambiguous
2. =PendingAction.files?= is optional → persisted mutations with empty file lists silently skip buffer invalidation, reintroducing stale-buffer divergence
3. =isPendingActionResolution()= type guard uses only ="result" in value= → fragile, could misidentify future =AgentToolResult= shapes
4. Resolve TUI renderer hides the new =mutationState=/=persisted= provenance fields already computed

Approach: BUG-258 fixes the contract substrate (invalidation failure → degraded result, opt-in invalidation flag, tighter guard). BUG-259 layers renderer provenance display on top.

Key design decisions:
- Invalidation failure returns =bufferInvalidationError= string on the resolution instead of throwing — callers always get a truthful resolution
- =invalidateManagedCodeBuffers?: boolean= opt-in flag on =PendingAction= — only AST edit preview sets it, safe default for unknown future producers
- Tighter =isPendingActionResolution= checks =mutationState=, =persisted=, =files=, and =result= (not just =result=)
- Resolve renderer adds persistence status indicator line below header
- =ResolveToolDetails= gains optional =bufferInvalidationError= field

Executor notes:
- Use =Edit=/=Write= tools for source mutations (code tool itself is the subject of these changes)
- Do NOT use =code edit= for any test or source file in this plan
- All test spying uses =spyOn(nativesModule, "executeCodeBuffer")= to simulate close failures
