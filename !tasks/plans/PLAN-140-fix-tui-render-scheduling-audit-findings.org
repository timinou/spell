* Context

Post-implementation audit of PLAN-138 (TUI input starvation fix) found a critical bug and several test quality issues.

** Critical bug
=requestRender(force=true)= is silently dropped when a throttle timer is pending. The =force= block clears the timer but doesn't reset =#renderRequested=, so the guard =if (this.#renderRequested) return= fires and no render is scheduled. This causes screen corruption on resize during subagent execution (the exact scenario PLAN-138 aimed to fix).

** Test issues
- =render-scheduling.test.ts=: settle uses =Bun.sleep(20)= default instead of =setImmediate=; unnecessary =as unknown as TUIConstructor= cast; fragile stop test viewport comparison
- =container-dirty.test.ts=: unnecessary =DirtyContainer= type cast (=markDirty()= is public)
- Missing test for force=true while throttle timer is pending (would have caught the bug)

** Dead caching (deferred)
=markTreeDirty()= in =#executeRender= marks all Containers dirty every frame, making the caching infrastructure dead code. This requires a design decision (remove vs enable via leaf signaling) and is tracked as [[id:FUP-039-container-dirty-tracking-caching-is-dead]].
