* Context

Phase A of PLAN-296 (CodePath v3 cutover) shipped the 4 generic tools and patched
silent-data-loss bugs in =create.ts= and =edit.ts= structural ops. Subsequent audit
revealed the underlying kernel =pi-code-path= ships with its full read-side grammar +
parser + 8 NameLexers + FS / Text / Code / Edge / URI resolvers, but with several
spec-promised features that are stubbed, mis-routed, or never wired into the NAPI
boundary.

Audit summary (sources: =memory://root=, =agent://33-Spec=, =agent://34-Parser=,
=agent://35-Resolvers=, =agent://36-Tests=):

** Critical gaps
- *G2* NAPI uses generic =DotLexer= for ALL languages — 8 NameLexers exist but never
  selected by file extension. Symbol queries weakly parsed.
- *G3* All qualifier resolvers (=#body=/=#name=/=#sig=/etc.) are =StubResolver=
  returning 0..0 byte ranges. Spec §3.4 promises broken.
- *G4* Anchor matchers per dialect exist; =CodeResolver.evaluate_query= never invokes
  them. =[¶name]= predicates silently no-op.
- *G5* =is_text_query= routing miss: symbol queries on md/org/html/css fall through
  to =FsResolver= and return file nodes instead of symbol nodes.

** High-priority UX
- *G6* EdgeResolver no-graph diagnostic is generic, not actionable.
- *G7* =#image=/=#thumbnail= return placeholder Content::Image, no bytes flow.
- *G8* =jobs://= + =mcp://= scheme handlers stub instead of erroring.
- *G9* Suffix-fallback ambiguity returns =None= instead of "did you mean".
- *G10* =ARTIFACT_THRESHOLD = 256 KiB= hardcoded.
- *G16* All 8 dialects use =EdgeKindSet::default()= — language-specific edges parse but
  don't resolve.

** Test coverage
- *G11* Zero dialect AST tests. NameLexer tested in isolation; qualifier/anchor
  resolution untested. Addressed inside each per-dialect FEAT in this plan.
- *G12* No NAPI end-to-end tests. All TS tests mock =executeCodePath=. The exact gap
  that let PLAN-296 silent-data-loss ship.

** Architectural unification
- *G1* Kernel is read-only. =opts.command/.actions/.manage= are dead API. Two NAPI
  surfaces (=executeCodePath= for query, =executeCodeBuffer= for mutation) — should
  unify so tools talk to one boundary.
