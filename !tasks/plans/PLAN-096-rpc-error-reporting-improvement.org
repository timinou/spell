* Initial Message

Failed to process message: Error: RPC stdout closed

in ../growth under spell server.

What's up?

* Context

When a spell RPC child process dies, the parent (spell-server) surfaces the
opaque message "RPC stdout closed" to callers (Telegram bot, goal executor).
The actual cause — exit code and stderr output — is available but lost:

- stderr is logged at debug level and discarded
- stdout close is detected before =child.exited= resolves, so the exit code
  message from the exit handler never fires (=#markDead= guard short-circuits)

Concrete recent failure: Telegram user got "Failed to process message: Error:
RPC stdout closed" when the real cause was =Model "gpt-5.4-mini" not found=
printed to stderr before the process exited with code 1.

Approach: buffer recent stderr lines, resolve the stdout-close / exit-code
race by deferring briefly, and enrich =#markDead= to append stderr context.

- =packages/spell-server/src/rpc/rpc-client.ts= — implementation
- =packages/spell-server/test/rpc/rpc-client.test.ts= — tests
