* Context

** Problem
The coding-agent has two disconnected tracking surfaces for delegated work:
1. The *todo roster* (~todo_write~ tool) — phases, tasks, statuses, gates, blockers, delegation, org links. Visible in TUI sidebar and injected into prompts.
2. The *job roster* (~AsyncJobManager~) — background job tracking. Visible via ~jobs://~ and ~/jobs~ command.

These are connected only by the manual ~todoRef~ bridge: the agent must first create todo items via ~todo_write~, then dispatch tasks with ~todoRef~ pointing to those items. Without this bridge, async work is invisible to the todo system.

This two-step ceremony (create items, then dispatch with ~todoRef~) is the friction. Wave-based plan execution requires: ~todo_write replace~ to create phases from waves → ~task~ dispatch with ~todoRef~ to link each subagent. The intent is one operation but requires two tools.

** Approach: Task-First Model (Model A)
Every ~task~ dispatch auto-creates todo roster entries. The task tool becomes the primary entry point for parallel work, and the todo system is the canonical view.

- ~task~ = "run this work" (roster entry is automatic)
- ~todo_write~ = "structure the roster" (pre-plan, add gates, reorganize)
- Both write to the same data. One creates items by dispatching. The other curates them.

** Key Design Decisions
1. *Task-first*: Every dispatch auto-creates roster entries in the existing todo system. ~todo_write~ remains for pre-structuring/upgrading.
2. *Hybrid DAG scheduling*: Task tool handles intra-batch DAG scheduling (within one ~task~ call using ~blockers~ on task items). Agent manages cross-batch orchestration via todo state.
3. *Phase naming*: New ~phase~ parameter on task tool names the auto-created phase.
4. *Agent-level suppression*: ~AgentDefinition.roster~ boolean; ~quick_task~ defaults to ~roster: false~. Global ~task.autoRoster~ setting is the kill switch.
5. *Progressive lifecycle*: Auto-created items start with status + delegation metadata. Agent upgrades via ~todo_write update~ (add gates, org links, blockers).
6. *Unified wave path*: Plan mode prompt changes to use task dispatch with ~phase~ + ~blockers~ instead of manual ~todo_write~ + ~todoRef~ ceremony. ~plan-to-todos.ts~ utility remains for fluid-mode consumers.
7. *~jobs://~ unchanged*: Remains a low-level debugging view. The todo roster is the primary tracking surface.

** Key Risks (from Metis gap analysis)
- *Mutation serialization*: ~#todoRefMutationQueue~ is per-TaskTool instance, not session-global. Concurrent manual ~todo_write~ + task lifecycle updates can interleave. Fix: session-level lock.
- *Normalization edge case*: Auto-created items without delegation metadata are "direct" and trigger the one-direct-in_progress rule. Fix: set minimal delegation object at creation time.
- *Async delivery mismatch*: Current model is per-job delivery but batch-style UX. Decision: keep per-job delivery but include batch correlation in progress text.
- *Cancellation orphans*: Auto-create then abort leaves orphan pending items. Fix: compensation handler marks orphans as failed.
