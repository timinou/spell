* Initial Message

i want the telegram-bridge command to be folded into spell server. ask me questions

* Context

The =telegram-bridge= package is a standalone Telegram bot that connects to Spell via RPC. The =spell-server= package is an autonomy daemon with scheduling, goal execution, HTTP dashboard, and hooks. spell-server already depends on telegram-bridge for its RPC layer (RpcClient, RpcEvent, RpcSpawnOptions) and for notification sending.

The user wants to merge telegram-bridge entirely into spell-server: one package, one binary (=spell server= subcommand), one config format (KDL). The telegram-bridge package gets deleted.

** Key decisions
- *Config format*: All telegram config moves from =~/.spell/telegram.yaml= (YAML) into =channels.kdl= (KDL). The =yaml= dependency is dropped. The KDL schema extends the existing =telegram= node with users, projects, modes, idle-timeouts, etc.
- *Package structure*: telegram bot, bridge, commands, log-viewer move into =packages/spell-server/src/telegram/=. RPC layer moves into =packages/spell-server/src/rpc/=.
- *Session management*: telegram-bridge's =ProcessManager= is replaced by spell-server's existing =SessionManager<K>= with =TelegramLifecycle=. A new =TelegramBotService= class wraps SessionManager + grammy bot + log-viewer into a single lifecycle unit.
- *CLI entry*: =spell server= becomes a subcommand of the main =spell= CLI in coding-agent. The standalone =spell-server= binary remains as a development convenience.
- *Bot startup*: The bot starts automatically when channels.kdl has a full telegram config (bot-token + users + projects). With just bot-token + owners (minimal config), only notification hooks work — no interactive bot.
- *Dependencies*: =grammy=, =qrcode=, =@types/qrcode= move to spell-server's package.json. =yaml= is dropped entirely.
