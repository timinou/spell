* Context

** Problem
Post-implementation audit of PLAN-018 (browse research library integration) found five issues:
1. ~normalizeUrlForDedup~ uses ~parsed.hostname~ instead of ~parsed.host~, dropping non-default ports and causing false dedup
2. QML ~normalizeUrl~ diverges from the TS function: lowercases path (TS preserves case), strips trailing slash from wrong position when query params present
3. ~findingsCount~ in BrowseShell monotonically increments without accounting for dedup merges or 200-entry cap, inflating the footer badge
4. ~SearchGroupDelegate.parseSources()~ calls ~JSON.parse~ redundantly in every binding expression (~57 times for 10 expanded sources)
5. URL-keyed ~ContentStore~ entries accumulate without eviction in long sessions

** Approach
All five fixes are surgical, non-overlapping, and contained in a single work item. No architectural changes required.
- Fix 1: ~parsed.hostname~ → ~parsed.host~ (one line)
- Fix 2: Rewrite QML normalizeUrl to match TS logic using regex URL parsing
- Fix 3: Replace manual ~findingsCount += 1~ with ~Qt.callLater~ readback from panel's ~findingCount()~
- Fix 4: Cache parsed sources in ~property var cachedSources~, replace all ~parseSources()~ calls
- Fix 5: Add LRU tracking (~_order~ array, max 20) to BrowseContentStore.js

** Key Design Decisions
- QML normalizeUrl uses regex-based URL parsing (no URL constructor available in Qt JS engine) to extract scheme, host (with port), path, and query components independently
- findingsCount uses ~Qt.callLater~ for readback to ensure the panel has processed the dedup before reading. Fallback to existing counter when panel is not yet loaded (pending queue scenario)
- ContentStore LRU limit set to 20 (higher than the 10 tab limit to allow URL-keyed entries to survive longer for tab reopening)
