* Context

** Problem
The Spell Browse Canvas has WebEngine browser windows with persistent cookie support (=ForcePersistentCookies=, =WebEngineProfilePrototype=), but there is no way to:
1. Name and manage browser profiles for specific services (LinkedIn, Google, GitHub)
2. See which services have active sessions
3. Automatically launch authenticated browsers when the agent needs to interact with a service
4. Reuse login sessions across Spell sessions

** Approach
Named service profiles stored in a JSON registry (=~/.spell/browser/services.json=). Each service maps to a WebEngine =storageName= directory at =~/.local/share/omp-qml-bridge/QtWebEngine/<storageName>/=. The agent can query available services, launch browsers with the right profile, and validate session health by observing pages (LLM-driven, no heuristic code).

** Key Design Decisions
- *Session inheritance*: child services share parent's =storageName= (logical aliases). A "YouTube" service points to the "google-personal" profile's cookie store, enabling SSO completion without re-entering credentials.
- *Domain resolution*: exact domain matching with manual aliases (no eTLD+1 / PSL dependency). Users configure explicit domain lists per service.
- *Agent-driven validation*: the agent uses =browser:observe= on a service homepage and uses LLM judgment to determine login status. No heuristic code in the codebase.
- *System prompt injection*: name-only (='Connected services: linkedin, google-personal'=). No domains/URLs/descriptions in prompts (privacy). Agent queries details on demand via =service:list=.
- *Service commands*: =service:list=, =service:connect=, =service:disconnect= are handled in TypeScript (not forwarded to QML). Separate type file (=service-protocol.ts=) to avoid conflating with =browser:*= WebEngine commands.
- *BrowseShell profile model*: BrowseShell tabs share the default ='spell-browse-mode'= profile. Service-specific sessions launch in standalone =BrowserWindow= instances with the service's =storageName=.
- *Remove = hard delete*: removing a service deletes the registry entry AND the WebEngine storage directory. Clean break, no ambiguity.
- *Atomic writes*: registry uses temp file + rename to prevent corruption from crashes or concurrent writes.
- *Favicon*: extracted via =WebEngineView.icon= QML property at save time, stored as PNG in profile directory.
- *Profile locking*: daemon-level protection (existing socket-based singleton). Two daemons on the same socket path reconnect rather than conflict.
- *Multi-account from day one*: profiles are freely named (='linkedin-personal'=, ='linkedin-work'=), each with its own WebEngine storage.
- *Connect flow*: hybrid \u2014 manual 'Save Session' button always available in BrowserWindow toolbar, plus auto-prompt on first successful login in a new profile.
- *Profile picker*: merged into BrowserWindow toolbar (same FEAT as Save Session to avoid two items touching the same QML =RowLayout=).
- *Test teardown*: =BrowserJourney.teardown()= extended to clean WebEngine storage dirs (prevents orphaned test profiles).
