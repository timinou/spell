* Initial Message

Look up online and in grammy. explain why i still only get the final message in telegram and I don't see any typing or streaming indicator. There was supposed to be a whole system to be made aware of the work as it was being done.

* Context

Users only see the final message from the Telegram bot — no typing indicator, no streaming text, no tool progress — despite the =ResponseStreamer= correctly accumulating and scheduling draft updates every 334ms.

** Root cause

The =sendDraft()= function in =rpc-to-telegram.ts= casts ~ctx.api~ to a speculative ~DraftCapableApi~ and checks ~ctx.api.raw.sendMessageDraft~. This property does not exist. grammY 1.41.1 (installed) exposes =sendMessageDraft= as a first-class method:

- ~ctx.api.sendMessageDraft(chatId, draftId, text)~ — direct API
- ~ctx.replyWithDraft(text)~ — context alias (auto-fills =chat_id= from context, =draft_id= from =update_id=)

The check ~if (!rawApi?.sendMessageDraft)~ at line 22 always returns early, silently discarding all drafts. There is also no =sendChatAction('typing')= anywhere in the handler, so the user gets zero feedback.

** Approach

1. Replace the =DraftCapableApi= / =raw.sendMessageDraft= hack with ~ctx.replyWithDraft(text)~. This uses grammY's native API: auto-fills =chat_id= and uses =update_id= as =draft_id= (same ID → animated transitions).
2. Add a typing indicator (=sendChatAction('typing')=) that fires immediately on message receipt and refreshes every 4s. Clear it when the first draft succeeds or on finalization. This covers the gap before text content is available (thinking, tool execution).
3. Log draft send errors at warn level instead of silently swallowing them.

** Key decisions
- Use ~ctx.replyWithDraft()~ (not raw API) — simplest, grammY handles =chat_id=, =draft_id=, and topic threading
- Manual 4s typing interval (not =@grammyjs/auto-chat-action= plugin) — avoids dependency for one =setInterval= call
- Typing indicator stops on first successful draft — drafts provide their own visual feedback via the "typing bubble" mechanism

** Key file: =packages/spell-server/src/telegram/bridge/rpc-to-telegram.ts=
Lines 11-29 (=DraftCapableApi= hack + =sendDraft()= function) are the core problem. The =ResponseStreamer= class (lines 108-365) is otherwise correct — its draft scheduling, text accumulation, and finalization logic all work. Only the =sendDraft= call at line 321 needs to change.
