* Goal
Make `edit` ergonomic for the common operation: find an anchor, then insert content before/after it. Prevent model loops caused by the current `replace` shape rejecting `find` + `place`.

* Observed incident
Session `/home/user/.spell/agent/sessions/-code-ora-spell/2026-06-15T21-23-37-748Z_150a981da51e09f3.jsonl` emitted 15 failed edit calls combining `find` + `place`. The intent was valid: locate an anchor and insert relative to it. The API made the invalid shape easy to emit and the diagnostic was not corrective.

* Scope
- Rust lowering: permit `replace { find, place: before|after, content }` as anchor-relative insertion by lowering to existing file/symbol find-replace operations with synthesized replacement content.
- Diagnostics: keep rejecting nonsensical `find + place:start|end`, but explain both valid alternatives.
- Prompt/schema docs: document anchor-relative insertion explicitly.
- Tests: add regression coverage for accepted before/after and rejected start/end.

* Non-goals
- Do not add a new kernel Op unless existing find-replace lowering cannot express the behavior.
- Do not rename the public `replace` verb in this wave; explicit `insert` can be a follow-up if schema/tool migration warrants it.
- Do not make `find` ignored with `place:start|end`; that hides mistakes.

* Verification
- `cargo test -p pi-code-path replace_find`
- targeted coding-agent tests if schema/prompt code changes require them
