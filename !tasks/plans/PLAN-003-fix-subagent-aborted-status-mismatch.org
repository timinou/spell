Why do subagents return aborted even though the message in the chat is that it's completed?

* Context

** Problem
Subagents show "⏹ aborted" status in the TUI when they produce valid output but fail to call ~submit_result~. The agent's output text shows completed work, but the status badge shows "aborted". This confuses users because their work appears cancelled when it actually completed.

** Confirmed scenario
From session ~2026-03-28T16-43-06-667Z_14a4a2500aebfa8c~: Agent "Aphrodite" using ~gpt-5.3-codex~ produced 225 lines of design analysis. After 3 ~submit_result~ reminders, the model called ~fetch~ with URL ~https://submit_result://complete~ instead of calling the actual tool. The session shows all 3 reminders (lines 26, 36, 42 in JSONL) and the confused ~fetch~ call (line 44). Result: status "aborted" despite complete, valuable output.

** Root cause
In ~packages/coding-agent/src/task/executor.ts~, the "missing submit_result" handler (lines 1121-1126) sets ~aborted = true~ and ~exitCode = 1~. This:
1. Prevents ~finalizeSubprocessOutput~ fallback path (~allowFallback = exitCode === 0 && !doneAborted~ → false)
2. Forces ~wasAborted = !hasSubmitResult && done.aborted~ → true (line 1241)
3. Status = "aborted"

** Approach
Decouple "missing submit_result" from "aborted". Remove ~aborted = true~ and ~exitCode = 1~ from the missing-submit-result block. Keep only the error message for diagnostics. The existing ~finalizeSubprocessOutput~ fallback logic already handles this case correctly when ~doneAborted = false~:
- With schema: tries ~resolveFallbackCompletion~; if fails, prepends warning to output
- Without schema: accepts raw output directly
- Both cases: ~exitCode = 0~ → status "completed" (with warning embedded in output)

Genuine aborts (signal cancellation, explicit abort via submit_result) are unaffected — they flow through different code paths (~abortSignal.aborted~ check in finally block, ~abortedViaSubmitResult~ flag).

** Key design decisions
- "Missing submit_result" is a protocol compliance issue, not an abort. The agent executed its work.
- Status "aborted" reserved exclusively for: (1) external cancellation (signal), (2) explicit abort via submit_result with ~status: "aborted"~
- Warning text ~SUBAGENT_WARNING_MISSING_SUBMIT_RESULT~ preserved in output for diagnostic visibility
