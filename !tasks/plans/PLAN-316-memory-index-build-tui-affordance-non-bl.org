* Initial Message
The memory.search call hung for ~4 minutes on a cold cache. Daemon was building the recall warm state inline under the slots mutex; ~2700 .org files re-embedded sequentially. User wants:
1. Non-blocking warm so the daemon doesn't freeze on cold first-call (TDD, thoroughly tested).
2. Spinner suffix on memory tool calls when building.
3. Status-line widget (core controller) showing background indexing is in progress.
4. Eager warm on session_start so most sessions never see the spinner.

Rationale:
- `crates/pi-knowledge-worker/src/repo_cache.rs::open` currently holds `slots().lock()` for the entire `OrgLane::warm_load(...)`, which serialises all daemon work for the duration of a cold rebuild. This is the architectural reason `stats` cannot poll progress today.
- `crates/pi-natives/src/recall_engine.rs::query_via_rpc` already routes via the daemon socket; once daemon-side state is unblocked, the existing route benefits automatically.
- `packages/coding-agent/src/modes/components/status-line.ts::setHookStatus(key, text)` is the existing hook-status surface used by `caveman` extension; reusing it keeps the core widget consistent with established patterns.

* Edge Cases

- Daemon worker thread for warm-load panics → state transitions to `LaneError`; subsequent stats reports `status: "error"`; memory tool surfaces the error to the model rather than hanging.
- Two `open` calls for the same repo land while the slot is `Warming` → the second call must return the same handle and NOT spawn a duplicate worker.
- `stats` is called for a slot that is `Warming` → must respond in microseconds without acquiring the lane's heavy lock (use atomics, not Mutex<OrgLane> read).
- `MemoryStatusController` running while the session uses a repo without any org memory → `recall_stats` returns `status: "warm", items: 0`; widget stays hidden.
- Eager warm fires for a repo that has no .org files → daemon scan returns empty items; warm-load completes in ms; widget never shows.
- Session running in an `--unsafe`/RPC mode without StatusLineComponent → controller no-ops gracefully (guard with `if (!statusLine) return`).
- Memory tool calls during eager-warm: `recall_stats` shows warming, tool emits onUpdate, then waits for daemon to finish — exact behavior we want.
