* Context

** Problem
Spell-server runs autonomous goals from a project-local =.spell/= directory. Growth (=../growth/=) is a running instance with cron goals, Telegram integration, and workflow state. Currently all execution is local. We need persistent remote execution on Hetzner (NixOS) or any VPS, with bidirectional sync between the developer's local repo and the remote server.

** Approach
New =packages/spell-deploy/= package with =spell deploy= CLI. The design separates concerns cleanly:

- *Config*: =.spell/sync.kdl= defines deployment targets and sync behavior (KDL format, committed to git)
- *Bundle*: Compiled binary via =bun build --compile --target=bun-linux-x64= — one standalone ~120MB =spell= binary shipped to remote. No node_modules, no bun installation on remote, native addon embedded.
- *Sync*: Bidirectional — push (local->remote) config+code via rsync/SSH, pull (remote->local) state/artifacts via rsync. Continuous watch mode with Bun native =fs.watch= + debounce.
- *Restart*: Atomic swap — rsync to staging dir, stop service, swap directories, restart. Push itself only does rsync+dir-swap; service stop/start is orchestrated by CLI commands (separation of concerns).
- *Secrets*: Age-encrypted =.env.age= files per target. Decrypt locally, pipe to remote via SSH stdin (no plaintext on disk during transfer).
- *Service*: Systemd template units =spell@.service= per project. Hardened (NoNewPrivileges, ProtectSystem=strict, ProtectHome, scoped ReadWritePaths, PrivateTmp).
- *Multi-project*: One remote hosts multiple spell-server instances, each with own systemd unit, data dir, secrets.
- *NixOS*: Optional module for Hetzner provisioning (Caddy reverse proxy, user creation, directory setup).

** Key Decisions
1. =server.kdl= already supports =env()= for all fields via =resolveEnvValue()=. FEAT-264 is a minor chore (update growth example + add test coverage). Not blocking.
2. Compiled binary eliminates most complexity: no node_modules shipping, no path resolution, no bun installation, Rust native addon embedded.
3. Push and pull file sets are completely disjoint — no bidirectional conflict on same files.
4. SQLite pull safety: run =.backup= command via SSH before rsync.
5. Watch mode uses Bun native =fs.watch= (already used throughout codebase), not chokidar.
6. Push operation is pure rsync+dir-swap (no service awareness). Service stop->push->start orchestrated by CLI commands. This avoids scope overlap between FEAT-267 (rsync) and FEAT-270 (systemd).

** sync.kdl Schema
#+begin_src kdl
default-target "production"

target "production" {
    host "spell.example.com"
    user "spell"
    port 22
    ssh-key "~/.ssh/id_ed25519"
    project-root "/srv/spell/growth"
    service type="systemd" unit="spell-growth"
    secrets ".spell/secrets/production.env.age"
    include "src/" "package.json" "bun.lock"
    exclude "node_modules/" ".git/" "*.sqlite" "*.sqlite-wal" ".env"
}

sync {
    push-debounce "2s"
    pull "data/" "artifacts/" "shared-sync/"
    pull-interval "30s"
    sqlite-backup true
}

bundle {
    platform "linux-x64"
    cache-dir ".spell/bundle-cache/"
}
#+end_src

** CLI Commands
- =spell deploy init <target>= — provision remote (dirs, bundle, systemd unit, user)
- =spell deploy push <target>= — stop service + atomic push + start service + health check
- =spell deploy pull <target>= — SQLite backup + rsync pull state
- =spell deploy watch <target>= — continuous bidirectional sync
- =spell deploy status <target>= — check remote health
- =spell deploy secrets <target>= — decrypt and push .env
- =spell deploy bootstrap <target>= — init + secrets + push

** Critical Risks (from Metis analysis)
1. *Native addon on headless server*: arboard (clipboard) depends on Wayland. Compiled binary embeds it but server won't use it. Lazy loading prevents crash.
2. *Atomic swap failure recovery*: If =mv staging current= fails, =.old= backup exists for manual recovery.
3. *Version mismatch*: Bundle version marker prevents pushing config that references features absent from the remote binary.
4. *Process management during sync*: Atomic swap with service stop eliminates partial-read races.
5. *Session/log management on remote*: Session dirs grow unbounded; remote log rotation needed (future improvement).
