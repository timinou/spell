* Context

** Settled Design Decisions

1. *Four generic tools*: =get= (reads/queries/nav/graph/files/dirs/regex/URIs/extraction), =edit= (mutations + LINE#ID + patch mode + 18 EditAction kinds), =manage= (lifecycle), =create= (new-file creation, lowers to =edit { action: create }= at TS layer). Drops the =code= prefix because addresses now span FS/text/code/URIs uniformly.

2. *Hard-cut, no aliases*: =code.ts=, =read.ts=, =find.ts=, =grep.ts=, =ast-grep.ts=, =ast-edit.ts=, =edit.ts= (=patch/index.ts=), =write.ts= deleted in one cycle. ~5860 LOC removed. Migration taught only via new prompts + =code-migration.md=.

3. *NamePayload = Raw(String)*: kernel keeps =NamePayload::Raw(String)= per FUP-071. Each NameLexer re-parses on demand (microseconds). Sidecar cache deferred.

4. *URI resolver = SchemeRegistry pattern*: single =SchemeHandler= trait (in =pi-code-path=) + =HashMap<UriScheme, Box<dyn SchemeHandler>>= (in =pi-natives=). Adding a scheme = registering a handler.

5. *Resolver-trait location*: traits in =pi-code-path= (=Resolver=, =CodeResolver=, =EdgeResolver=, =UriResolver=, =SchemeHandler=, =FormatExtractor=, =FsAnchorContext=); concrete impls in =pi-natives=. Avoids cyclic crate dep.

6. *9 URI schemes*: artifact, memory, skill, agent, jobs, local, pi, *rule*, *mcp* (last two added vs PLAN-255 spec).

7. *11 document extraction formats*: PDF/DOC/DOCX/PPT/PPTX/XLS/XLSX/RTF/EPUB → markitdown; JSON → pretty-print; HTML → readable. Spec extension already drafted.

8. *Image pipeline kernel-owned*: =#image= qualifier + =#thumbnail[N]= + auto-resize + 20 MiB threshold + =inspect_image= hand-off hint live in =pi-natives::code_path::image_pipeline=, not in tool wrapper.

9. *Patch mode preserved*: =edit { operations: [{ action: { kind: "patch", diff: "..." } }] }= ports unified-diff parsing from today's =edit.ts=.

10. *Binary content via create*: =create { path, content: string | { kind: "bytes", artifactUri } | { kind: "base64", data } }= supports binary writes.

11. *Guards at TS tool layer*: =write-shrink=, =parse-regression=, =force=, =sandbox=, =mode-guard= preserved verbatim at =edit.ts= and =create.ts= entry (before NAPI). =force= flag bypass.

12. *Behavioral parity corpus*: 30-50 representative invocations per deleted tool (~275 entries total). Semantic equivalence, not byte-equivalent output.

13. *ast-grep $A/$$$A captures deferred*: cutover uses simple =[name=$pat]= predicate matching. Full capture binding =(Q) as $m= → FUP-069.

14. *Performance benchmarks deferred*: 1.2× of =find=, 1.5× of =grep=, 100 MiB RSS / 1 GiB file → FUP-070.

15. *Test corpus = Medium* per dialect: 50 round-trip + 20 resolver fixtures + 10 negative cases = ~880 corpus entries across all 11 dialects.

16. *LINE#ID stale-detection preserved*: =edit { operations: [{ action: { kind: "replace", pos: "10#AB", end: "12#CD", content: "..." } }] }= retains the same hash-based stale-detection contract as today's =edit= tool. Per user's ergonomic requirement during planning session.

17. *Bare-string file paths*: =target: "foo.ts"= parses as =FsLocator= with no =::Query= — cheapest path, no kernel overhead. Use bare strings for plain-text edits; CodePath syntax only when structural addressing is needed.
