* Context

Spell's task dispatch and todo systems were designed for independent parallel tasks with a flat phase-based ordering model. Interconnected agent swarms require fundamentally different primitives: mutable DAGs, URI-addressable tasks, live inter-agent communication, dynamic graph mutation, and isolation-gated concurrency.

** Problem
1. Static DAGs: =batch-scheduler.ts= builds an immutable graph. No runtime mutation.
2. Phase-as-barrier: =TodoPhase= imposes sequential ordering that the DAG doesn't enforce. Phases lie about the execution model.
3. Opaque task IDs: =task-3= carries no context about ownership, session, or scope.
4. No inter-agent data flow: subagents are fully isolated. No shared state, no live notifications.
5. Underused =::= sub-outlines: plan mode documents the =PARENT-ID::sub-slug= pattern but plans rarely use it, preventing =org wave= from computing execution order.

** Approach
Converge the todo system, event bus, and DAG scheduler into a unified architecture:
- *Phases eliminated.* Flat task list with explicit DAG edges. Cosmetic groups (like org headings) for human readability, no scheduling semantics.
- *URI addressing.* =task://= for executable work, =data://= for passive data. =artifact://= remains physical storage. Short slugs resolve contextually.
- *Same DAG, different node types.* =task://= and =data://= participate in one =MutableDag=. Scheduler dispatches work nodes, satisfies data nodes on artifact arrival.
- *80/20 events + LOGBOOK.* Keep =applyOps()= state machine. Emit fine-grained typed events. Org LOGBOOK for timeline reconstruction. Event types future-proofed for later event-sourcing.
- *Typed EventBus.* Generic =EventBus<E>= with compile-time channel/payload safety. =FakeEventBus= for testing.
- *Isolation-gated concurrency.* Multiple direct tasks in_progress when isolation active + no file overlap.
- *Dual agent tools.* =handoff= (transfer control) and =spawn_successor= (extend DAG) for dynamic swarm execution.
- *Org blackboard.* Separate persistent store. Bridges to =data://= nodes via event bus.
- *Plan =::= enforcement.* Prompts require structured sub-outlines. ERT + TypeScript tests harden the dependency graph.

** Key Decisions (settled during planning)
1. Phases are purely cosmetic (=TodoGroup=), DAG is sole ordering authority.
2. URI scheme: =task://<session>/<agent>/<slug>=, =data://<session>/<agent>/<slug>=. Short slugs as tool input, full URIs canonical.
3. =task://= and =data://= in same DAG, different node =kind= field. Scheduler behavior varies by kind.
4. 80/20 event model: state machine + fine-grained typed events + org LOGBOOK. Not full event-sourcing yet.
5. Typed EventBus with =EventMap= generic. =FakeEventBus= for TDD.
6. Isolation-gated concurrency: multiple in_progress when =task.isolation.mode= active AND independent DAG components AND no =filesDeps= overlap.
7. Handoff = agent transfer (ends current), spawn_successor = DAG extension (continues current).
8. Blackboard separate from DAG. =data://= nodes bridge via =swarm:artifact= events.
9. Plan prompts require =PARENT-ID::sub-slug= sub-outlines with =:DEPENDS:= properties.
10. ERT tests for org graph algorithms. TypeScript tests for blocker resolution (dangling refs, cycles).
