* Initial Message

is the cache control at the system level prompt? as in, is there a way to make the system prompt a cache checkpoint so that i re-use cache when I start a new session (or a new planning session for example)? do you understand me?

* Context

** Problem
The system prompt (~30-50KB) is assembled as a single string with dynamic content (date, memory, MCP instructions) interleaved early in the template. For Anthropic/Bedrock, cache keys are prefix-based: any byte difference in the prefix invalidates the cache. Currently, every new session cache-misses on the entire system prompt because dynamic content appears before stable content.

For OpenAI, =prompt_cache_key= is tied to =sessionId=, preventing cross-session cache reuse even though the system prompt is largely identical across sessions.

** Approach
1. Introduce =SystemPromptBlock= type with a =stable= flag through the full pipeline: AI types → Agent types → Coding-agent assembly → Provider consumption
2. Reorder the system prompt template so stable content (~90%) forms a contiguous prefix: Preamble → Workspace → Context → Identity → Environment → Rules. Dynamic content (cwd, date, memory, MCP) moves to the end
3. Providers that support multi-block caching (Anthropic, Bedrock) place =cache_control= breakpoints only on stable blocks. Other providers join blocks to a string
4. OpenAI derives =prompt_cache_key= from a hash of the stable block content instead of sessionId, enabling cross-session cache server routing
5. Subagent sessions preserve the stable prefix from the base prompt, so sibling subagents share cached prefix via the existing stagger delay mechanism
6. Cache rate percentage added to per-turn display, footer, logging, and stats dashboard for observability

** Key Decisions
- =SystemPrompt = string | SystemPromptBlock[]= — backward-compatible union type
- =SystemPromptBlock = { text: string; stable?: boolean }= — =stable= defaults to =true= when absent
- Template uses a =CACHE_BOUNDARY= Handlebars helper that emits a unique marker; after rendering, the output splits at the marker to produce two blocks
- =appendPrompt= (memory, MCP, services) moves from between Context and Identity to after the Rules section (in/adjacent to the Now section)
- Anthropic/Bedrock: stable blocks get =cache_control=/cache points, dynamic blocks don't
- OpenAI: =prompt_cache_key= = hex hash of stable block text via =Bun.hash()=
- Subagent template (=subagent-system-prompt.md=) removes ={{base}}= inline rendering; callback constructs blocks array with base stable prefix + dynamic overlay
- Max Anthropic TTL remains 1h (maximum available)
