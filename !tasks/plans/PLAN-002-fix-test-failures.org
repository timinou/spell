* Root Causes

** RC1: Stale ".omp" references — should be ".spell" (3 tests)

Several test files reference =.omp= as the config/XDG directory name, but the codebase has standardized on =.spell= (=APP_NAME = \"spell\"=, =CONFIG_DIR_NAME = \".spell\"=).

Affected tests:
- =packages/coding-agent/test/discovery/pi-config-dir.test.ts= line 34: expects =source: \".omp\"= → should be =source: \".spell\"=. Also adjust =PI_CONFIG_DIR= value from =.config/omp= to something like =.config/custom= (to test override behavior, not the .omp name) and fix the expected path accordingly.
- =packages/coding-agent/test/discovery/disabled-extensions.test.ts= line 21: creates =.omp/AGENTS.md= → should be =.spell/AGENTS.md=
- =packages/coding-agent/test/plugin-extensions-discovery.test.ts= line 18: creates =$XDG_DATA_HOME/omp= → should be =$XDG_DATA_HOME/spell=

** RC2: Exit-plan-mode error message mismatch (1 test)

=packages/coding-agent/test/tools/exit-plan-mode.test.ts= line 76: expects substring ="Title may only contain letters, numbers, underscores, or hyphens."= but source (=packages/coding-agent/src/tools/exit-plan-mode.ts= line 37) now says ="Title may only contain letters, numbers, underscores, hyphens, or dots."=

Fix: Update test expectation to include "or dots".

** RC3: Google schema sanitizer mishandles property named "properties" (1 test)

=packages/ai/src/utils/schema/sanitize-google.ts= line 112-115: When the sanitizer is inside a =properties= map (where keys are property names, not schema keywords) and encounters a property literally named ="properties"=, it incorrectly sets =insideProperties: true= for the recursion into that property's schema value. This means the schema keywords inside the =properties= parameter's type definition (like =patternProperties=) are mistakenly treated as property names and NOT stripped.

The =org= tool has a parameter called =properties= (=Type.Record(Type.String(), Type.String())=) which generates =patternProperties=. After sanitization, =patternProperties= survives because of this bug.

Fix in =sanitize-google.ts= line 114: change =insideProperties: key === \"properties\"= to =insideProperties: key === \"properties\" && !options.insideProperties=. When we're already inside properties (processing property names), recursing into a property value should return to schema mode, not stay in property-name mode.

The provider-schema-compatibility test (=packages/coding-agent/test/tools/provider-schema-compatibility.test.ts=) should then pass without changes.

** RC4: QML evaluate does not expose component IDs or context properties (3 tests)

=packages/coding-agent/test/modes/qml-canvas-structured-input.test.ts= lines 81, 102, 115: Tests call =harness.evaluate(\"canvas.submitPromptResponse(...)\")= and =harness.evaluate(\"bridge.send(...)\")=. But the bridge's =evalInWindow= (=packages/qml/bridge/windowmanager.cpp= line 457-476) uses =QJSEngine::evaluate()= which only has access to the JS global scope. It injects =root= but not QML component IDs (=canvas=) or context properties (=bridge=).

Fix in =packages/qml/bridge/windowmanager.cpp= =evalInWindow()=:
1. Also inject =bridge= from the root context: =globalObj.setProperty(\"bridge\", jsEngine->newQObject(it->bridge))= (the bridge object is already stored in the window info struct)
2. For QML =id=-bound children: iterate root's children and inject any named ones, OR use =QQmlExpression= instead of =QJSEngine::evaluate()= to run expressions in the QML context scope (where IDs are visible)

Simplest approach: Use =QQmlExpression= which runs in the proper QML context:
#+begin_src cpp
QQmlExpression expr(it->engine->rootContext(), root, expression);
QVariant result = expr.evaluate();
#+end_src
This makes both QML =id= references and context properties (=bridge=) accessible.

Also clean up: delete the old =root= global injection if using =QQmlExpression=.

** RC5: QML WM-close test times out (1 test)

=packages/coding-agent/test/tools/canvas-wm-close.test.ts=: "WM close without prior close event" times out at 5s. This test simulates a window manager closing the window without the agent sending a close command first. The bridge's event handling may have a race condition where the =closed= state isn't emitted/detected.

Investigate in =packages/qml/bridge/windowmanager.cpp= how WM-initiated close events (=QWindow::close()= or =QCloseEvent=) propagate. Verify the test harness properly simulates this case. May need to increase timeout or fix event propagation.

** RC6: llama.cpp health check too permissive (1 test)

** ITEM Fix QML WM-close event handling
:PROPERTIES:
:EFFORT: 30m
:END:

=packages/coding-agent/test/tools/canvas-wm-close.test.ts= line 51-58 times out (5s) waiting for =closed= event.

The test calls =bridge.close(\"wm-test2\")= which sends ={ type: \"close\" }= to the C++ bridge. The bridge's =closeWindow()= (=windowmanager.cpp= line 212-225) does:
1. =delete it->engine= — deletes the QML engine
2. =m_windows.remove(id)= — removes from map
3. =writeEvent(...)= — sends =closed= event

Suspected issue: On the offscreen QML platform (=QT_QPA_PLATFORM=offscreen=), =delete it->engine= may not complete synchronously or may block, preventing the =closed= event from being written/flushed.

Investigation approach:
1. Add stderr logging in =closeWindow()= before and after =delete it->engine= to confirm it reaches the writeEvent call
2. Check if =fflush(stdout)= in =writeEvent= is being called (the test uses stdio mode, not daemon sockets)
3. If engine deletion is the culprit, try deferring it: emit the closed event first, then delete the engine via =QTimer::singleShot(0, ...)= or =engine->deleteLater()=

Likely fix: Change line 217 from =delete it->engine= to =it->engine->deleteLater()= and move the map removal + event write before the deletion. This lets Qt clean up the engine asynchronously while the =closed= event reaches the client immediately:

#+begin_src cpp
void WindowManager::closeWindow(QLocalSocket *client, const QString &id) {
    auto it = m_windows.find(id);
    if (it == m_windows.end()) return;

    QLocalSocket *owner = it->owner;
    QQmlApplicationEngine *engine = it->engine;
    m_windows.remove(id);

    QJsonObject ev;
    ev["type"] = "closed";
    ev["id"] = id;
    writeEvent(owner ? owner : client, ev);

    engine->deleteLater();  // deferred cleanup
}
#+end_src
