* Goal

Make `find`/CodePath location-style output carry and render enclosing symbols for multi-file hits consistently and efficiently.

Desired model-facing shape for grep-like hits:

#+begin_src text
path/to/file.ts
::Symbol
  42:  matching line
  47:  another hit

::<file>
  12:  top-level hit
#+end_src

For structural nodes with content:

#+begin_src text
path/to/file.ts
::Symbol   [§function_declaration] L42
function Symbol() { ... }
#+end_src

* Non-goals

- No TypeScript-side parsing or alternate CodePath resolver.
- No prompt inline strings generated in code beyond formatter literals.
- No behavioral changes for filesystem listing/stat/tree/image outputs.
- No git commit.

* Architecture

Producer metadata in Rust, renderer grouping in TypeScript.

** Metadata contract

Location-style `NodeRef.metadata` may include:

- `symbolPath` — copy-pasteable symbol path without file prefix, e.g. `Foo.bar`, for nodes that are themselves symbols.
- `symbolKind` — source symbol kind from outline/graph.
- `symbolLine` — symbol declaration line.
- `enclosingSymbolPath` — nearest/smallest enclosing named symbol for non-symbol hits.
- `enclosingSymbolLine` — enclosing symbol declaration line.

The renderer chooses `symbolPath` first, then `enclosingSymbolPath`, then `::<file>` fallback.

** Rust enrichment

- `crates/pi-kernel/src/walker.rs`: code resolver already parses each file once. Build outline entries from the same root/source/profile once per resolve, then attach symbol metadata to every query result using an interval lookup over outline byte/line spans.
- `crates/pi-kernel/src/parse.rs`: pure text grep returns line nodes from `TextResolver`. Enrich only `shape=match` nodes after text resolution. Group hits by file, parse each code file at most once through the existing `CodeResolverImpl` outline path/registry helper, then attach nearest enclosing symbol by line. Non-code files remain unchanged.
- `crates/pi-kernel/src/edge_resolver.rs`: graph symbols already know `qualified_name`, `kind`, and `line`; attach `symbolPath` metadata when converting graph symbols to `NodeRef`.

** TypeScript rendering

- `packages/coding-agent/src/tools/codepath-result.ts`: extend match grouping from `path -> hit` to `path -> symbol -> hit` when symbol metadata is present, with `::<file>` fallback for top-level/no-symbol rows.
- Group structural/content nodes by `path -> symbol` when symbol metadata exists; preserve legacy generic node-list fallback when no symbol metadata exists.
- Include symbol metadata in `CodePathNodeData` for programmatic consumers.
