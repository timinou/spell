* Context

The Phoenix inspector extension (~.spell/extensions/phoenix-inspector/~) lets users browse a LiveView app, pick DOM elements, resolve their source via Tidewave annotations, and send edit requests to the main agent session. Three gaps prevent it from being a self-contained frontend-fix tool:

1. *Premature event dispatch.* Clicking an element in pick mode immediately fires Tidewave resolution events via ~bridge.send()~, which can trigger agent turns before the user types their request. Fix: stage the selection visually without firing bridge events until the user explicitly confirms.

2. *No element screenshot.* The context sent to the agent is text-only (DOM path, annotations, styles). A screenshot of the selected element region would significantly improve the agent's understanding. Fix: add a toggle (default on) that captures the element's bounding rect as a base64 PNG.

3. *No targeted task dispatch.* The only dispatch path is "Send to agent" which calls ~pi.sendUserMessage()~ to the main session (typically a large model). The user wants a "Quick Fix" button that spawns a lightweight SMOL-model subagent with a pre-loaded frontend-fix prompt and structured output describing changes to the surface DSL (~DjinnUI.Surface~), journey DSL (~Agentmaker.E2E.Journey~), standard components (~DjinnUI.Components~), and project components.

** Approach: New ~canvas:task~ tier

The canvas event system already supports three dispatch tiers:
- ~_tool~: direct armed-tool invocation (fire-and-forget)
- ~_tier: "orchestrator"~: scoped read-only subagent via ~CanvasOrchestratorManager~ → ~runSubprocess()~
- ~_tier: "agent"~: full ~session.followUp()~ to main model

Adding ~_tier: "task"~ follows the orchestrator pattern but with full flexibility: configurable model role (~pi/smol~), custom system prompt, custom tool set, and structured JTD output schema. This is a general-purpose extension to the canvas event system, not inspector-specific.
