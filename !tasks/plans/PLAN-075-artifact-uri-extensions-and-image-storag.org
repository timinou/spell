* Context

The artifact:// URI system currently uses bare numeric IDs (=artifact://5=) and stores all
artifacts as flat files (={id}.{toolType}.log=) in the session directory. Screenshots and
generated images bypass the artifact system entirely, saving to tmpdir. Subagent artifacts
are not addressable from the main agent.

This plan introduces four changes:
1. *Session-scoped URIs with extensions*: =artifact://<session-id>/<agent-name>/<tool>/<number>.<ext>=
2. *Image artifact integration*: Screenshots and generated images stored in artifact dir
3. *URI everywhere*: All tool output truncation notices use full artifact:// URIs
4. *Prompt documentation*: Plan mode prompts reference artifact:// for verification evidence

** Key decisions

- URI format: =artifact://<session-id>/<agent-name>/<tool>/<number>.<ext>=
  - Example: =artifact://14b64b9276f08680/main/bash/0.txt=
  - Example: =artifact://14b64b9276f08680/0-FindArtifactFiles/screenshot/1.png=
- Session ID: Snowflake hex string (no timestamp)
- Agent name: =main= for main agent, task prefix (e.g., =0-FindArtifactFiles=) for subagents
- Default extension: =txt=; screenshots: =png=; generated images: mime-derived
- Monotonic ID counter per ArtifactManager instance (per agent scope)
- Backward compat: old =artifact://{id}= URIs still resolve via current-session root scan
- Cross-session resolution: resolver scans =~/.spell/agent/sessions/= across project repos
- =InternalResource.contentType= stays text-only union; binary artifacts return =sourcePath=
- Plan artifact recording: prompt-guided only (no automatic tracking)
