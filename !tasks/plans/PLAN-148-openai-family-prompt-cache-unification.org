* Initial Message

Look at the recent commits around cache optimisation and tell me how well you've done that for Codex models. Here is the reference for optimising this: https://developers.openai.com/api/docs/guides/prompt-caching


how can you cleanly (i.e. one overarching logic, or at least a shared library) implement caching?

* Context
Prompt caching across OpenAI Responses-family providers (openai-responses, openai-codex-responses, azure-openai-responses) is inconsistent. The direct OpenAI Responses provider correctly resolves =CacheRetention= and sends both =prompt_cache_key= and =prompt_cache_retention=. The Codex and Azure providers have bugs: they set =prompt_cache_key= unconditionally (ignoring =cacheRetention === "none"=) and never set =prompt_cache_retention=.

Per OpenAI docs, Codex models (gpt-5.1-codex, gpt-5.1-codex-mini, gpt-5.1-codex-max, gpt-5-codex) support extended 24h prompt cache retention. This is entirely unused because:
1. Codex never sends =prompt_cache_retention=
2. The OpenAI Responses provider gates extended retention on =api.openai.com= hostname, excluding Codex's =chatgpt.com/backend-api=

** Approach
Extract a shared =resolveOpenAICacheParams(cacheRetention, sessionId)= utility that:
- Resolves =CacheRetention= via the existing =resolveCacheRetention()=
- Returns ={}= when retention is ="none"= or sessionId is missing
- Maps ="long"= → =prompt_cache_retention: "24h"= unconditionally (no hostname gate)
- Maps ="short"= → =prompt_cache_key= only (in-memory default)

All three providers spread this into their params objects, eliminating duplicate logic and fixing the bugs.

** Key decisions
1. No hostname gating: ="long"= always maps to ="24h"=. Safe because the server silently falls back to in-memory for models that don't support extended retention.
2. No model-ID allowlist: unnecessary given the safe-to-send nature of the parameter.
3. Utility lives in =packages/ai/src/utils.ts= alongside =resolveCacheRetention=.
4. =getPromptCacheRetention= in openai-responses.ts is deleted (absorbed into shared helper).
5. =RequestBody= in codex =request-transformer.ts= already has =prompt_cache_retention= field — no type changes needed.
