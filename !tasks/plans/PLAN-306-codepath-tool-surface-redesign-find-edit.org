* Goal

Collapse 7+ overlapping tools (get, code_search, lsp, manage, read, grep, find, ast_grep) into a 5-tool surface backed by the existing pi-code-path grammar. JS-side ships first using current NAPI; kernel rebuild happens after the JS surface and full language-matrix test suite are green.

* Final tool surface

| tool   | input                  | role                                                    |
|--------|------------------------|---------------------------------------------------------|
| find   | { target }             | read · search · list · stat · diff · graph              |
| edit   | { target, action }     | mutations, symbol-first, owns undo/redo                 |
| status | { command, file? }     | kernel observability (was: manage; no save/diff/buffers)|
| create | { path, content }      | new files only                                          |
| bash   | { command }            | processes only (build, test, git, scripts)              |

CodePath grammar is the only DSL the agent learns. `find { target: "src/**/*.ts::§line[text~=\"TODO\"]" }`. Errors render at kernel via ariadne — read & retry.

* Non-goals

- Do NOT change kernel grammar in JS-side waves. JS uses what the kernel already accepts.
- Do NOT touch PLAN-304 (typed Op surface) territory — coordinate via rebase, not parallel edit.
- Do NOT add a TS-side parser. The kernel is sole authority; TS calls `parseCodePath()` via NAPI.

* Post-smoke separation discipline

The initial separation of concerns is **TS = transport envelope, kernel = sole authority on grammar/Ops/diagnostics**. Every parallel surface that exists today (31-variant per-Op TS schemas, bag-of-fields legacyActionSchema, dual range-syntax doc) must be **deleted** after the smoke-test gate passes — not deprecated, not kept behind a flag.

** What gets deleted in Wave 11 (post-smoke)

- =packages/coding-agent/src/tools/codepath-types.ts=: the per-variant Op exports (=fileCreateOp=, =fileWriteOp=, =symbolReplaceOp=, ... all 31). Replaced by bag-of-fields passthrough alone.
- =legacyActionSchema= once kernel diagnostics are good enough (Wave 8 miette work makes this possible).
- =editOpSchema= union — unused by editOperationSchema, just exported for legacy callers; delete with their last reference.
- Any TS-side validation logic for CodePath target strings; only =parseCodePath= NAPI call validates.
- Any TS-side format inference (auto-#raw, auto-#listing); kernel auto-attaches.
- Legacy tool aliases (=get=, =manage=, =read=, =grep=, =find= the tool, =ast_grep=, =ast_edit=, =write= the tool, =code=, =resolve= for non-deferrable sessions).
- Any TS-side mapping between =kind= legacy aliases (=write= → =fileWrite=, etc.); kernel does this.

** During execution (waves 2-7)

- NEW tools (find, status, edit refactor) are **envelope-only** from day 1
- NO new TS-side enumeration of kernel-owned concepts (Op kinds, diagnostic variants, qualifier names, edge kinds, language ids)
- Wave 1 already-shipped findSchema/statusSchema are the model: =target: string= only, =command: enum-of-5= for status
- Adding =kind: "undo" | "redo"= to a TS-side Op union is the exact smell to avoid — undo/redo dispatch via top-level =history?= field or =edit { operations: [{ target: "", action: { kind: "undo" }}]}= where =kind= is passthrough string
