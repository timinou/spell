* Context

The system prompt is the agent's declaration of being — mirror, compass, handbook.

Its content is already well-compressed (thinking-mode, behavior, code-integrity, design integrity
all received token-reduction passes in a prior session). But the *structure* buries the compass
(Contract, Design Integrity) at position ~75%, after 2000+ tokens of tool documentation.

Research-backed finding: critical instructions at START and END retain 20%+ better than
middle-positioned content. Contract and Design Integrity are the most critical behavioral
content and belong in the Identity section, not after tool reference material.

** Approach

1. Reorder system-prompt.md: move Contract and Design Integrity from the "Rules" section
   into the "Identity" section (after =<stakes>=)
2. Rename "Rules" section separator to "Procedure" (only Procedure content remains)
3. Add two minor refinements to the thinking-mode block (abbreviation hints, compression guard)
4. Verify AGENTS.md boundary remains clean post-restructure
5. Architectural spec written to =specs/system-prompt-architecture.md= for cross-session reference

** Key Decisions

- Section order: Workspace → Identity (absorbs Contract + Design Integrity) → Environment → Procedure → Now
- Contract position: after =<stakes>=, before Environment — urgency primes absolute constraints
- Cache boundary: unchanged (between Procedure and Now)
- AGENTS.md: no changes — clean boundary, different concern (project conventions vs behavioral identity)
- caveman.md: no changes — correctly placed in dynamic appendPrompt
- Thinking-mode: add abbreviation examples + "Compression ≠ simplification" guard
