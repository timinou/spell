* Context

** Problem
The investigated session showed three distinct failure modes, but the plan scope is intentionally narrow:
- a real `code edit` ambiguity in `profile.rs`;
- agent-side misuse/retry corruption in `query.rs`;
- and, most importantly for this plan, false delegated verification / false delegated completion in the task runtime.

This plan addresses only the third class. The system currently allows a delegated task to surface as successfully completed without durable proof that required gates were observed at runtime, and it lacks an explicit first-class audit-trail field for persisted verification evidence.

** Settled Decisions
1. Scope is limited to task-agent reliability plus durable verification evidence / audit trail. Code-tool ambiguity work is explicitly out of scope for this plan.
2. Runtime ownership is authoritative: when proof is missing, the delegated subagent runtime gets exactly one retry opportunity before success is rejected.
3. There is no parent-side second retry in this plan. The parent may consume runtime outputs, but it must not own the retry loop.
4. Durable evidence has two layers:
   - always-on structured verification summary in delegated `delegation.result`;
   - optional dedicated evidence artifact only when a task explicitly opts in.
5. The opt-in path is a new explicit field, not reuse of `gateArtifact` or `verifyCmd`.
6. Recommended naming is `verificationArtifact` in TypeScript-facing task/todo data and `VERIFICATION_ARTIFACT` in org properties.
7. `gateArtifact` remains the deliverable gate and must stay semantically distinct from verification evidence.
8. The implementation order is strict: first make delegated success truthful, then add audit-trail persistence on top of that trusted contract.

** Recommended Approach
Implement two child items with a hard dependency edge:
- First, fix the delegated runtime contract so success cannot be accepted without observed proof and the runtime owns a single retry.
- Second, thread an explicit optional `verificationArtifact` field through org/task/todo surfaces and persist durable verification summaries / artifacts.

This split keeps scopes non-overlapping:
- `BUG-277...` owns truthfulness of delegated completion.
- `FEAT-568...` owns storage, transport, and audit-trail persistence.
