* Context

The =code edit= tool cannot target Elixir symbols because =resolve_symbol()= in =pi-code-engine= hardcodes =.= as a Container.member separator (max 2 levels). Elixir module names are naturally dotted (=MyApp.Greeter=), making symbol resolution impossible.

Agents fall back from =code edit= to =sed= via bash, bypassing all safety.

Root cause: =crates/pi-code-engine/src/resolve.rs:40=:
#+begin_src rust
let parts: Vec<&str> = symbol.split('.').collect();
if parts.is_empty() || parts.len() > 2 {
    return Err(...)  // "at most 2 levels"
}
#+end_src

Fix approach: try full-string match first, then split at last dot for Container.member. Backwards compatible — TypeScript =Foo.bar= still works (full match fails, last-dot split gives =Foo= + =bar=).

- FEAT-519 (added Elixir outline but no resolve tests)
- FEAT-520 (documented 2-level limitation for deep markdown)
- FUP-052 (deferred Elixir enhancements)
