* Initial Message

loook at the extension in ~/code/ora/hotelcomm, could you enable a puppeteer-like browser window component in the qml stdlib with async tool call registration so that the agent can do things in the browser window that is there?

* Context

** Problem
The hotelcomm extension at ~/code/ora/hotelcomm/.spell/extensions/phoenix-inspector/ demonstrates a production-grade browser window with WebEngineView, JavaScript injection, DOM inspection, and async tool call registration via the armed tools pattern. However, it's a monolithic 1392-line QML file mixing browser logic, Phoenix-specific DOM inspection, and UI chrome. There is no reusable browser component in the QML stdlib — every extension that needs a browser must rebuild from scratch.

** Approach
Extract the browser-as-component pattern into the QML stdlib as two complementary pieces:
1. SpellBrowser.qml — composable WebEngineView wrapper with a full command protocol, usable in any ApplicationWindow
2. BrowserWindow.qml — ready-to-launch standalone browser window with navigation toolbar

The agent controls the browser via canvas send_message with structured browser:* action payloads. Async request-response uses _rid correlation (matching the existing armed tools pattern). The browser can also call agent tools (read, write, grep, find) via the armed tools system for reverse communication.

** Key Design Decisions
- Dual control planes: Agent sends commands via canvas send_message, browser calls agent tools via armed tools (_tool/_rid)
- Near-full puppeteer parity: goto, evaluate, click (coord + selector + elementId), type, fill, press, scroll, drag, observe (DOM snapshot), get_text, get_html, get_attribute, wait_for_selector, extract_readable, screenshot
- Serial command queue with _rid correlation and exactly-one terminal response guarantee
- State machine: idle -> loading -> interactive -> error
- Element ID cache (populated by observe, invalidated by navigation) for click_id/type_id equivalents
- Per-command timeout with default 30s
- Bridge isolation: page JavaScript cannot access bridge object
- URL scheme validation (deny file://, qrc://, chrome:// by default)
- Lightweight inline JS for readability extraction (not bundled Mozilla Readability)
- All tests headless via QT_QPA_PLATFORM=offscreen with skip guard when WebEngine unavailable
- BrowserJourney test abstraction on top of QmlJourney for semantic browser test methods
