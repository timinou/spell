* Context

** Problem
The Spell canvas BrowserWindow (QWebEngine-based) enters an unrecoverable rapid-cycling loop when the WebSocket server it's connected to restarts. This happens constantly during Phoenix LiveView development because every code recompilation restarts the BEAM Endpoint, killing the WebSocket for ~200-500ms.

The cycling pattern: =loading → interactive → LoadStopped → loading → interactive → LoadStopped → ...= repeats indefinitely. The browser never stabilizes and subsequent navigation commands fail silently.

Bug reference: =ecosystem/djinn/!tasks/bugs/BUG-001-spell-canvas-browserwindow-fails-to-reco.org= in the hotelcomm repo.

** Root Cause
Line 2144-2154 of =SpellBrowser.qml= (=packages/coding-agent/src/modes/qml/canvas/components/SpellBrowser.qml=):

The =LoadStoppedStatus= handler sets =browserState = \"interactive\"= whenever a URL exists, without differentiating network-induced stops from user-initiated stops. Combined with LiveView's JS client auto-reconnection (which triggers micro-navigations), this creates the infinite loop.

No state history tracking exists. No cycle detection. No recovery mechanism.

** Approach
Two-layer fix:

*** QML Layer (SpellBrowser.qml)
1. Add state history tracking: record ={status, timestamp}= tuples for each =onLoadingChanged= event
2. Add cycle detection: detect 3+ rapid =LoadStarted → LoadStopped= pairs within 3 seconds
3. Add automatic recovery: when cycle detected, stop loading, wait 1 second, force =reloadAndBypassCache()=
4. Show status bar feedback: \"Recovering from server restart...\" during recovery
5. Guard against re-entrant recovery with a =recovering= flag

*** Bridge API Layer (new command)
Add =browser:force_reload= command that resets all browser state (helper cache, observations, error state) and forces a cache-bypassing reload. This gives the TypeScript/extension layer a way to programmatically recover from bad page states.

** Key Decisions
- Cycle threshold: 3 pairs of LoadStarted→LoadStopped within 3 seconds (conservative enough to avoid false positives from normal browsing)
- Recovery delay: 1 second after cycle detection (gives server time to restart)
- Recovery method: =reloadAndBypassCache()= — clears HTTP cache but preserves cookies/session (important for Phoenix login persistence)
- State history capped at 10 entries to bound memory
- =recovering= flag prevents detection→recovery→detection re-entrancy
