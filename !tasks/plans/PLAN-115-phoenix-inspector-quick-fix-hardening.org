3. **What:** Quick-fix error handling is not regression-tested.
   **Where:** `.spell/extensions/phoenix-inspector/index.test.ts`, the new `dispatches canonical quick-fix tasks...` case only covers success.
   **Why:** A failed task result could regress to stale or incorrect UI messaging without any test catching it.
   **Effort:** small

* Context
Audit AUD-028 identified three gaps in the Phoenix Inspector quick-fix dispatch implemented by PLAN-099:
1. Screenshots captured by the QML ~dispatchQuickFix()~ are silently dropped by the TypeScript backend (~runQuickFixTask~ never extracts the ~images~ field).
2. ~pi.pi.runSubprocess~ is called without a runtime guard; a missing export would produce a cryptic error.
3. Only the success path of quick-fix dispatch and agent handoff has regression test coverage.

Approach: apply the canonical ~canvas-task-manager~ pattern for image metadata (append a text note to the assignment), add a defensive runtime check, and add three focused error-path tests. Full structural image forwarding through ~ExecutorOptions~ is tracked separately as [[id:FUP-035-thread-images-through-executoroptions-to]].

Key decisions:
- Images are noted in assignment text, not structurally forwarded. This matches the framework pattern in ~canvas-task-manager.ts~ lines 176-178 and is honest about the current limitation.
- The runtime guard is a typeof check with a descriptive throw, not a graceful degradation. Quick Fix should fail visibly if the API is absent.
- Error-path tests depend on the code fixes landing first (the image extraction changes the assignment shape that tests assert against).

All changes are in ~/home/user/code/ora/hotelcomm/ecosystem/agentmaker/.spell/extensions/phoenix-inspector/~ (same 2 files: ~index.ts~ and ~index.test.ts~).
