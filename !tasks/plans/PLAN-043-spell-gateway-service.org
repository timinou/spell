* Context
Spell spawns services prolifically -- MCP servers, dev servers, preview endpoints, databases -- but has no unified way to name, proxy, or manage them. Each gets an ephemeral port, there's no central registry, and services scatter when sessions end. This plan introduces a local reverse proxy and service gateway deeply integrated with Spell.

** Problem
- Services are addressed by ephemeral port numbers (meaningless, session-local)
- No lifecycle management: orphaned processes, no health checks, no cleanup
- MCP HTTP servers require manual URL configuration
- No visibility into what Spell is running without terminal inspection

** Approach
A new =packages/gateway= package implements a standalone daemon with:
- =Bun.serve()= HTTPS reverse proxy on port 443 with wildcard TLS via mkcert
- =.localhost= TLD (RFC 6761, zero DNS config for browsers, programmatic clients use =Host= header override)
- Unix socket control plane (NDJSON protocol, same pattern as QML bridge)
- Persistent JSON service registry with session-scoped and persistent service modes
- Managed backend process lifecycle (spawn, health check, auto-restart, graceful shutdown)
- Gateway agent tool for in-session service management
- MCP HTTP integration with lazy-start (auto-spawn MCP process on first request)
- QML shell panel + standalone system tray icon

** Key Decisions
- Separate package (not embedded in QML daemon) -- different failure domains, must work headless
- Wildcard cert =*.localhost= via mkcert (Bun.serve() lacks dynamic SNI, single cert covers all aliases)
- Port 443 via =sysctl net.ipv4.ip_unprivileged_port_start=443= (no CAP_NET_BIND_SERVICE on bun binary)
- =spell gateway init= first-run wizard handles mkcert install, CA trust, cert gen, sysctl config
- Session-scoped services tagged with sessionId, cleaned up via explicit RPC on session dispose
- Programmatic clients (agent fetch, MCP transport) connect to =127.0.0.1:443= with =Host= header -- no DNS dependency
- stdio-to-HTTP MCP bridge deferred to Phase 2 (significant protocol adapter work)
- Standalone systray requires C++ QML bridge extension (Qt6::Widgets, new protocol commands)
