* Initial Message

When I edit an "Other (type your own)" in the ask tool after I validated it and go back to that question, it gets erased. Can you fix that please?

* Context
When navigating back to a question in the ask tool's multi-question flow and re-selecting "Other (type your own)", the input field is blank — the previously typed custom text is lost from the UI.

The internal state is preserved correctly (~resultsByIndex~ stores ~customInput~ and ~askSingleQuestion~ restores it to a local variable), but the value never reaches the UI because of a four-link failure chain:
1. ~promptForInput()~ ignores the existing ~customInput~ value
2. ~UIContext.input()~ interface omits the initial value parameter
3. The adapter hardcodes ~undefined~ for the placeholder
4. ~HookInputComponent~ receives the placeholder but discards it

Additionally, ~Input.setValue()~ in the TUI package leaves cursor at position 0, which would cause a confusing UX even if the value were passed through — the user would see their text but the cursor would be at the start.

** Approach
Thread the existing ~customInput~ value through the chain: ~askSingleQuestion~ → ~promptForInput~ → ~UIContext.input~ → ~extensionUi.input~ → ~HookInputComponent~ → ~Input.setValue~. Fix ~setValue~ to position cursor at end.

** Key decisions
- Reuse the existing ~placeholder~ parameter on ~ExtensionUIContext.input()~ and ~HookInputComponent~ — they already accept it but ignore it. No new API surface needed.
- Fix ~Input.setValue~ cursor positioning globally — all callers benefit (MCP wizard, settings, model selector, etc).
