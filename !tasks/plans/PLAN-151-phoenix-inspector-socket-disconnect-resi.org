* Context

The phoenix inspector QML window freezes when the daemon socket closes unexpectedly during
concurrent session races or daemon restarts. The QML bridge correctly delivers ~socket_disconnected~
events to callers, but the inspector's ~startBridgeEventLoop~ silently discards them because it only
checks ~event.payload~ (not ~event.name~) before routing to ~handleBridgePayload~. The canvas tool
already handles this correctly with a detect-sleep-retry pattern. This plan applies the same pattern
to the inspector extension.

Key findings:
- ~QmlBridge.waitForEvent~ correctly wakes on ~socket_disconnected~ (line 269) — bridge-level code is correct
- ~QmlProcess.autoReconnect~ runs in background with exponential backoff (100-1600ms, ~3.1s total)
- The canvas tool (~packages/coding-agent/src/tools/canvas.ts~ lines 406-417) checks ~raw.some(e => e.name === "socket_disconnected")~ before iterating payloads
- The inspector extension doesn't check ~event.name~ at all — goes straight to ~handleBridgePayload(event.payload)~
- No changes needed in ~packages/qml/~ — the bridge, process, and daemon code all work correctly

Approach: single bug fix in the phoenix inspector extension (~index.ts~ + ~index.test.ts~), matching the existing canvas.ts disconnect handling pattern.
