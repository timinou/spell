* Context

** Symptom

User session 14b2a06ab0efe245 hit the bug: task-4 was marked completed, vanished from the roster ~60s later, and every subsequent =todo_write= call reports =task-7 references non-existent blocker task-4= (plus the same error for tasks 8, 9, 10, 13). The tracker treats the errors as non-blocking, so work continues, but the noise is misleading and the state can never self-heal.

** Root cause

Two-part defect in the todo subsystem:

1. *Auto-clear is blocker-graph-blind.* =AgentSession.#scheduleTodoAutoClear= (=packages/coding-agent/src/session/agent-session.ts:2953-2986=) arms a =setTimeout= per =completed= task id with delay =tasks.todoClearDelay= (default 60s). When the timer fires, =#runTodoAutoClear= (=lines 2989-3012=) does =phase.tasks.splice(idx, 1)= — physically deletes the task from =#todoPhases= — regardless of whether any other task in the roster still references it via =blockers=. The same hazard exists on session resume in =#syncTodoPhasesFromBranch= (=lines 2936-2946=), which unconditionally strips every =completed= task from the branch snapshot.

2. *applyOps validator is too broad.* =applyOps= in =packages/coding-agent/src/tools/todo-write.ts:640-649= does a post-snapshot sweep over every task's =blockers= array on every call, re-reporting dangling refs that were introduced by the auto-clear timer (step 1). Because =hasUnresolvedBlockers= (=line 430=) treats missing refs as resolved, the functional behavior is already correct — the validator is pure noise.

** Approach

Two independent fixes, landed together, plus a tiny docs fix.

1. *Prevent new dangling refs.* Make auto-clear aware of the blocker graph: a completed task is only eligible for removal when no remaining task's =blockers= array references its id. Re-evaluate on every =setTodoPhases= and at the end of each clear pass. Apply the same invariant to the resume path.

2. *Heal existing dangling refs + suppress false alarms.* Relocate blocker validation from the post-snapshot sweep to per-op (only tasks whose =blockers= were set in the current ops batch are validated). After validation, silently prune every task's =blockers= array to drop any id that no longer resolves. The resulting state is always clean, and legitimate user errors still surface at the moment they are introduced.

3. *Align settings description.* =tasks.todoClearDelay= description currently says "completed/abandoned tasks" but the code only clears =completed= tasks (abandoned are preserved for audit trail). One-line doc fix.

** Key decisions

- *Referenced completed tasks are preserved indefinitely*, even when the reference comes from an abandoned task. Rationale: audit trail integrity. If the user wants to drop the ref, they can =update= the dependent's =blockers=.
- *Blocker pruning is silent, not logged.* A dangling blocker id carries no information the system needs to preserve — it always means "resolved". Logging every prune would be noise.
- *Per-op validation only flags tasks touched in the current ops batch.* Pre-existing dangling refs (from past auto-clears or external mutations) are never flagged — they are just quietly cleaned.
- *Forward-refs within the same =replace= op are valid.* The finalize step runs after all tasks in the batch are built, so task-1 can reference task-2 and vice versa.
- *The existing test =`dangling blocker ref produces warning`= passes unchanged* because the new per-op validator emits the same error string for the same user input (=blockers: ["task-99"]= on a fresh =replace=).
- *Settings description*: the FUP aligns the stale text. Not gating.
