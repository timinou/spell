Root causes (each addressed by a child item below):

- *Write tool has no content-quality gate* on code-supported files. Tree-sitter parses =PLACEHOLDER= as a valid Rust identifier so the managed-buffer path accepts it. PLAN-262 deliberately relaxed the redirect guards on text =edit= and =write= for code-supported files; it did not add a shrink/parse-regression gate. Addressed by [[id:FEAT-585-write-shrink-and-parse-fail-guard-on-man]].
- *quick_task agents have no scope sentinel*. The =CoordBridgeTests= subagent's assignment never named =buffer.rs=, but its tool surface allowed mutation of any file. Addressed by [[id:FEAT-586-quick-task-filesdeps-scope-sentinel-for]].
- *Nested task delegation runs without isolation by default*. A =task= subagent's =task= calls inherit no isolation; children's edits land directly on the live tree. Addressed by [[id:FEAT-587-nested-task-isolation-default-when-paren]].
- *No wave-boundary snapshot in plan orchestration*. When wave-2 destruction was discovered, =git restore HEAD= was a destructive recovery because HEAD predated wave-1's uncommitted work. Addressed by [[id:FEAT-588-wave-boundary-git-snapshot-ref-for-plan]].

Settled decisions:

1. Do NOT reverse PLAN-262 (relax-text-edit-compatibility-and-add-wr). Text =edit= and =write= remain lenient for code-supported paths with the existing compatibility-notice surface. New guards are additive content-quality gates, not path blocks.
2. Reuse existing primitives wherever possible: =filesDeps= for scope sentinel (already in TodoItem + task DAG), =isCodeToolSupportedPath= for code detection (single source of truth), the loop-checkpoint git pattern for wave snapshots (=loop/git/checkpoint.ts=).
3. =force: true= is the universal escape hatch for the new write guard; matches the PLAN-262 compatibility-notice tone (advisory-with-teeth, not security-grade).
4. =quick_task= becomes the only =scopeRestricted= agent in this plan. The general =task= agent stays unrestricted because its assignments are typically broader.
5. Auto-isolation triggers only at =taskDepth >= 1= AND when =task.isolation.mode != "none"=. Top-level task dispatch is unchanged.
6. Wave snapshots use git refs under =refs/spell/plan/<PLAN-ID>/wave-<N>=, not branches. They never advance HEAD.

* Risks and mitigations

- *False positives in shrink guard*: legitimate large-file truncation rejected. Mitigation: =force: true= escape hatch; compatibility notice when force is used keeps the path visible.
- *Parse-regression false positives*: a half-applied refactor that cycles through a broken state. Mitigation: guard skips when the *original* file already had parse errors, so iterative repair is unaffected.
- *quick_task scope friction*: requiring =filesDeps= forces the parent to enumerate scope. Mitigation: =task= (general) agent stays unrestricted; use it when scope is broad. Documented in quick_task prompt template.
- *Auto-isolation cost*: worktree mode adds startup time per nested batch. Mitigation: only triggers at depth >= 1; top-level remains explicit-opt-in.
- *Snapshot ref clutter*: refs accumulate across plans. Mitigation: =/snapshots= command surfaces them with cleanup hints; refs are in a dedicated namespace =refs/spell/plan/=.
- *PLAN-262 reversal pressure*: future maintainers may misread the new shrink/parse guards as a sign that path-level blocks should return. Mitigation: each guard's error message and the FEAT body explicitly call out PLAN-262 as the deliberate prior decision.

* Non-goals

- Re-enabling path-level blocks on text =edit= or =write= for code-supported files (PLAN-262 stands).
- Sandboxing subagent shell processes; isolation only protects file mutations.
- Cross-host or cross-repo coordination.
- Replacing or extending the loop-checkpoint mechanism (=loop/git/checkpoint.ts=); wave snapshots are a sibling concept for plan-mode execution.
- New telemetry beyond logger output.

* Rollout

- After Wave 1 lands, the next plan-mode handoff exercises auto-isolation + wave snapshots end-to-end.
- =quick_task= dispatches in existing skills/templates that omit =filesDeps= will fail loudly until updated; expected breakage radius is small (=quick_task= is rarely used outside parent =task= agents).
- =force: true= compatibility notices on write will appear in transcripts whenever a wholesale rewrite is intentional; review for unexpected hits.
