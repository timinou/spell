* Goals

- (G1) Kernel Op enum is THE source of truth; every Op variant declared once in Rust
- (G2) NAPI carries semantic intent (variant name, field name, field type-kind, required, description); each language renders in its own grammar
- (G3) TS codepath-op-schema.generated.ts produced by =bun run gen:op-schema=; committed; regen byte-equal in CI
- (G4) codepath-types.ts shrinks to hand-authored primitives (~80 lines); imports & re-exports the generated file
- (G5) edit.ts::normalizeStructuralAction deleted; TS wire format IS Op JSON (camelCase kind, no translation)
- (G6) Op::from_legacy reduced to single legacy-input lane at kernel entry; one minor's grace, FUP for hard delete
- (G7) Prompt generators consolidate to one entrypoint (=bun run gen:prompts=); takes NAPI introspection; emits all _generated/*.md fragments
- (G8) Adding a new Op variant: touch Rust Op enum + Op::all_schemas() match arm + resolver. Run =bun run gen:op-schema=. Done. Zero TS hand-edits.

* Non-goals

- No new edit capabilities. Surface stays semantically identical.
- No user-visible behaviour change. Agents using legacy kind names still work via single entry-point adapter (one deprecation note, same as today).
- No schemars dependency. Rust hand-writes Op::all_schemas() match (one screen).
- No JSON-Schema-as-canonical-output. NAPI returns structured =OpSchemaDto= records; TS composes TypeBox locally. (Option A from tradeoff analysis.)
- No reviewer/agent-output grammar change. JTD stays canonical for agent frontmatter. ADR locks the dual-grammar boundary (Wave G).
- No URI-locator mutation surface.
