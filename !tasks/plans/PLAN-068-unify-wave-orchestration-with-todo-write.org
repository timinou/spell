* Context

** Problem
Plan execution has three redundant systems that each own a slice of the same concern:
1. *todo_write* — dependency graph (blockers), status tracking, gates, org hooks. But it can't spawn work and enforces single =in_progress=.
2. *task tool* — subagent spawning and parallel execution. But =todoRef= is read-only (injects context, never writes back status). No dependency awareness.
3. *Fluid orchestrator* (FluidOrchestrator, QueueScheduler, coordinator-runner, OrgFluidBridge) — DAG validation, wave computation, reactive dispatch. But the execution engine is dead code since PLAN-062 moved execution to =session.prompt()= + =todo_write=.

The orchestrator existed solely to achieve parallelism that waves + todo_write couldn't. Now =task= subagents provide that parallelism. The orchestrator's execution engine is redundant.

Additionally:
- Auto-init of todos from plan waves depends on an MCP call (=org-fluid-plan=) that has *never successfully returned data in a real session*.
- Two type systems (=FluidPlan= / =FluidPlanWithComponents=) and two execution prompts (=plan-mode-approved.md= / =coordinator.md=) duplicate the same concepts.
- =normalizeInProgressTask= enforces single =in_progress=, preventing wave-level parallelism.

** Approach
Unify waves, =todo_write=, and =task= into one coherent system:
1. *PlanWave is the canonical intermediate representation.* Both paths converge on it:
   - =/plan= path: =extractPlanWaves()= → =PlanWave[]= → =planWavesToTodoPhases()= → =TodoPhase[]=
   - Canvas path: =FluidPlan= → =computeWaveLayers()= → =PlanWave[]= → =planWavesToTodoPhases()= → =TodoPhase[]=
2. *Bidirectional todoRef*: =task= tool with =todoRef= auto-marks parent's todo item =in_progress= on spawn, =completed= on finish, =failed= on error. Records sessionId + transcriptPath for traceability.
3. *Multi in_progress*: exactly 1 direct =in_progress= (parent works on it) + N delegated =in_progress= (each linked to a subagent via delegation metadata).
4. *Visible nesting*: subagent todo changes propagate to parent via EventBus in real time. Parent's todo list shows nested sub-tasks. TUI and niri overview render the tree.
5. *Result forwarding*: completed predecessor results auto-included in subagent context.
6. *One execution prompt*: merged =plan-mode-approved.md= + =coordinator.md= with Handlebars conditionals.

** Key Decisions
1. *PlanWave canonical, FluidPlanWithComponents deleted.* FluidPlan stays only as canvas planner output schema. The org-fluid-plan MCP stays in Elisp but is no longer required for auto-init.
2. *Components deferred.* Wave-based parallelism via task subagents covers the use case. Component splitting (dedicated coordinator subagents per independent workstream) is a future optimization.
3. *Race condition handling.* Multiple subagents completing concurrently serialize state mutations through the same lock mechanism todo_write uses.
4. *1-level nesting.* Sub-subagent todos stay in their own scope. Only the immediate subagent's phases appear as children.
5. *Supersedes PLAN-066* (AUD-013 audit hardening) — dead code deletion, org hook observability, integration tests, prompt clarity, and retry fix are all addressed here in a more comprehensive way.
