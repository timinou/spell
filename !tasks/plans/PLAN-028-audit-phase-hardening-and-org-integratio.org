* Context

The audit phase (PLAN-027) is implemented but has two behavioral bugs and a missing feature:

** Problem 1: Audits fix things directly
The audit prompt (~plan-audit.md~) tells the agent to "review" but does not prohibit tool use or file modifications. The agent interprets "review" as "review and fix," making tool calls during the audit response. When the agent makes tool calls, the ~agent_end~ handler's tool-call guard (~hasToolCalls~ check at line 883) returns early before ~#checkAuditPhase~ runs. This means the escalation to ultraplan never fires.

Fix: Add explicit read-only constraints to the audit prompt. The agent must report findings only — no tool use, no file edits.

** Problem 2: Summary shown, nothing happens
Even when the agent does produce a clean findings summary (no tool calls), the escalation flow may not fire correctly because:
1. ~#injectAuditPrompt~ passes empty ~{}~ to ~renderPromptTemplate~, so the ~{{#if auditDepth}}~ block never renders — the agent doesn't know about audit cycles
2. The ~AuditState~ doesn't carry ~sourceRef~ — so escalation can't reference the original plan

Fix: Carry ~sourceRef~, ~auditDepth~, and ~maxDepth~ on ~AuditState~ so both the prompt and escalation have full context.

** Missing feature: Org audit category
No ~audits~ category exists. When escalation fires, the audit findings are passed as raw text to ultraplan without being tracked as org items. The user wants:
- New ~audits~ default org category (~AUD~ prefix, ~!tasks/audits/~ path)
- Automatic creation of audit org items with ~[[id:SOURCE_ID]]~ links to original plans
- Ultraplan prompt referencing the audit org item

** Approach
Two sequential changes:
1. BUG fix: Harden audit prompt (read-only) + carry sourceRef/depth on AuditState + fix template rendering
2. FEAT: Add audits org category + auto-create audit items on escalation

** Key Decisions
- ~sourceRef~ is an optional field on ~AuditState~ (not a separate field on InteractiveMode) because it travels with the state the session needs
- ~auditDepth~ and ~maxDepth~ also live on ~AuditState~ so ~#injectAuditPrompt~ can access them without cross-layer coupling
- Audit items use ~appendItemToFile~ + ~generateId~ from ~@oh-my-pi/pi-org~ directly — no heavy OrgContext needed
- ~audits~ excluded from plan-mode ~childCategories~ (agent sees it as internal/programmatic, not a planning target)
