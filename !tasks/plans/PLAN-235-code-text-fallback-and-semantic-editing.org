** Request
- Make semantic editing more prevalent and ergonomic.
- Support `code` undo/redo/buffers for all non-binary text-like files, not only current tree-sitter-supported extensions.

** Settled decisions
1. Evidence first: inspect recent local Spell sessions from the last 14 days under `~/.spell/agent/sessions/` and derive a deterministic replay corpus.
2. Architecture: `code` gains a text-buffer fallback for any non-binary text file, backed by the native rope-based buffer lifecycle.
3. Scope: fallback ships with full mutation parity (`open/read/diff/edit/save/undo/redo/buffers/create/move/delete/replace-content`), not read-only lifecycle only.
4. Semantic guidance: hints appear on `code` results broadly, but semantic-only hints are suppressed when the file lacks semantic support.
5. Migration: `edit` becomes an adapter for all non-binary text files so one lifecycle owns persistence, stale detection, buffers, undo, and redo.
6. Confidence bar: add both fuzz/property tests for history + newline/BOM preservation and a deterministic curated recent-session replay gate as required verification.

** Current code reality
- `packages/coding-agent/src/tools/code.ts` currently owns freshness checks, autosave, formatting preparation, and managed buffer semantics.
- `packages/coding-agent/src/tools/code-supported-files.ts` still gates `code` primarily by supported extensions.
- `packages/coding-agent/src/patch/index.ts` still owns `edit` replace/patch/hashline mutation semantics and therefore represents a separate mutation model today.
- `packages/coding-agent/src/tools/pending-action.ts` / `resolve.ts` already contain buffer invalidation logic that must remain correct once fallback + adapter routing land.

** Evidence from recent sessions
- Last-14-day local transcript scan showed `edit` used 8,395 times vs `code` 7,787 times.
- `edit` payloads were overwhelmingly hashline-style (8,045 hashline vs 350 replace), showing current agents strongly prefer line-addressed text mutation.
- `code` usage skewed toward discovery (`read` 5,484; `outline` 1,034) while `code edit` appeared only 848 times.
- `edit` targeted many files that are text-like but not currently code-supported (`.json`, `.kdl`, `.nix`, `.toml`, `.txt`, etc.), validating the need for a text fallback rather than a code-extension-only solution.
- `edit` also still targeted current code-capable files heavily (`.ts`, `.ex`, `.exs`, `.rs`), validating the migration need toward one lifecycle and better semantic nudges.
