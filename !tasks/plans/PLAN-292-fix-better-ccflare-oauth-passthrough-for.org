* Context

better-ccflare supports two auth modes for Claude CLI:
1. OAuth passthrough: proxy detects Claude CLI user-agent, forwards client's OAuth token directly to Anthropic (bypasses proxy accounts)
2. API key auth: client sends proxy API key, proxy uses its own backend accounts

Spell was stripping ALL auth headers for localhost. This prevented OAuth passthrough (no client token to forward). The proxy fell back to backend accounts which were both broken (Admin rate-limited, GLM paused).

* Fix

Remove localhost auth suppression from packages/ai/src/providers/anthropic.ts:
- Delete ~isLocalhostBaseUrl~ function
- ~~buildAnthropicHeaders~~: remove localhost special case
- ~~buildAnthropicClientOptions~~: remove ~isLocalhostBaseUrl~ checks

The ~ANTHROPIC_API_KEY~ env var (containing a valid OAuth token) flows through ~getEnvApiKey("anthropic")~ which already has a function resolver at ~stream.ts:95-98~.

* Verification

- Spell sends x-api-key / Authorization to localhost proxy
- Proxy detects Claude CLI UA, forwards OAuth token to Anthropic
- Admin OAuth token from ~ANTHROPIC_API_KEY~ env var is used directly
