* Context
A session using ~gpt-5.3-codex~ via the ~openai-codex-responses~ websocket provider crashed silently mid-turn. The process died after writing a tool result to the session JSONL but before the model could respond. Investigation revealed:

1. No crash report was written (SIGHUP handler doesn't call ~writeCrashReport~)
2. Log files for the period were 0 bytes (Winston async transport lost buffered entries on exit)
3. No session crash marker (JSONL just ends mid-turn with no indication of crash)

Root cause analysis found two classes of issues:

*Error handling gaps in providers and agent loop:* All 13 LLM provider stream functions have an async IIFE with a catch block that can itself throw (via ~await finalizeErrorMessage()~ or ~stream.push()~), producing an unhandled rejection. The agent-loop IIFE (~agentLoop()~) has no error boundary around ~runLoop()~, so provider errors propagate as unhandled rejections.

*Missing crash diagnostics:* ~postmortem.ts~ only writes crash reports for ~uncaughtException~ / ~unhandledRejection~, not for SIGHUP/SIGTERM. The logger has no flush mechanism. Session JSONL gets no crash marker.

Key decisions:
- Harden all 13 provider IIFEs (not just codex) with nested try/catch in catch blocks + defense-in-depth ~.catch()~
- Harden agent-loop IIFEs with try/catch around ~runLoop()~
- Write crash reports for all fatal signals (SIGHUP, SIGTERM, SIGINT) using synthetic errors
- Add ~logger.close()~ via ~winstonLogger.end()~ with 2-second timeout in postmortem cleanup
- Add ~CrashMarkerEntry~ type to session JSONL, written by the existing cleanup callback
