* Initial Message

at this point, sessions provide enough to make Quickshell able to do cool stuff, like clearly show me which windows need my input or need me to accept a plan versus which ones are done, quickly, form the DMS workspace, or in its own extension

* Problem

Spell sessions currently show tiny status dots on DankBar workspace buttons. This is enough to know /something/ needs attention on a workspace, but not /what/. The user wants:

1. A DankBar widget with a popout panel listing all active sessions with status, project name, click-to-focus
2. Tooltips on workspace status dots showing session details
3. Toast notifications when a session transitions to =needs_input= or =pending_approval=

* Current State

** Already implemented (spell side)
- =packages/niri/src/controller.ts= writes status files to =~/.spell/status/<windowId>.json= on every status change
- Status file format: ={ status, windowId, pid, updatedAt }=
- Status values: =idle=, =running=, =needs_input=, =error=, =completed=, =pending_approval=
- File deleted on controller destroy

** Already implemented (Quickshell side)
- =~/.config/quickshell/dms/Services/SpellStatusService.qml= — polls =~/.spell/status/= every 2s, maintains =statusByWindowId= map, provides =getWorkspaceStatuses(workspaceId)=
- =WorkspaceSwitcher.qml= — colored dots (lines 1407-1450) with pulsing animation for =needs_input=

** Missing
- Status files lack project name and session title — needed for any richer display
- No DankBar widget or popout panel
- No tooltips on workspace dots
- No toast notifications on status transitions

* Architecture

Three-layer approach: enrich status data → build dashboard widget → add notifications + tooltips.

** Data flow
1. Spell writes enriched JSON to =~/.spell/status/<windowId>.json=
2. SpellStatusService polls every 2s, exposes full session objects (not just status strings)
3. DankBar widget reads from SpellStatusService, renders list
4. WorkspaceSwitcher dots get tooltips from the same data
5. SpellStatusService detects transitions → fires ToastService notifications
6. Click on session → =NiriService.focusWindow(windowId)= to jump to that terminal

* Key decisions

1. *File-based IPC stays*: polling at 2s is fine for status indicators. No need for sockets.
2. *Enrich status files* rather than adding a second data channel. Two extra string fields per file is negligible.
3. *Click-to-focus via NiriService.focusWindow()*: already exists, stable, handles workspace switching automatically.
4. *Toast on transition only*: compare old→new status map to avoid firing on every poll cycle.
5. *Sort by urgency in popout*: needs_input/pending_approval first — the whole point is surfacing what needs attention.
