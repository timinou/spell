## Problem (root, not symptom)
DMS top-bar chips show session states on the WRONG niri windows. Root cause: the
session→window mapping is **guessed** by the producer from ambient state it does
not own:
- v0 (original): captured the FOCUSED window id once at boot → burst launches
  (`spell recover --direct` spawns ~24 windows) race on focus → off-by-N.
- v1 (my first fix, commit 73c09503b): process-ancestry match. BREAKS because
  ghostty runs as a SHARED SERVER — measured pid 3769 owns 15 windows (incl. this
  session) → ancestry collapses to one pid → falls back to focus → same race.
- v1 also added a 30s re-verify timer + file retarget + ghost-file cleanup:
  churn layered on a wrong foundation. Running sessions never loaded it (Bun
  caches imports in-process at launch 20:34; fix committed 21:05).

∴ No producer self-identification via focus/pid can be correct for shared-ghostty.

## Correct architecture — INVERT it
Producer stamps an identity it OWNS onto the window; consumer does the join LIVE.

Keystone = a **title token**. spell already sets its window title via OSC (it owns
this); niri echoes it as `windows[].title` (authoritative). Append the sessionId:
`{project}: {title} ⟨{sessionId}⟩`. Now:

- **Live bar (DMS):** consumer-side join. For each live niri window, parse the
  ⟨token⟩ from its title → look up `~/.spell/status/{sessionId}.json` for state →
  render on THAT window's workspace (`w.workspace_id`, already live). The
  session→window mapping is DERIVED every 2s poll, never stored → immune to focus,
  launch order, pid-sharing, window-id reuse. This is the fix.
- **Recover (crashed sessions):** needs last-known workspace (window is dead →
  can't derive live). Producer resolves its OWN workspace by the SAME token
  self-join against niri (exact match, correct for all topologies), stored as a
  snapshot only. No focus, no ancestry, no 30s timer.

Principle: **derive live what you can (current window, for the bar); store only
what you can't re-derive (last workspace, for dead sessions).**

## Graceful migration (no flag-day)
Old running sessions have NO token in title (old in-memory code) and write
`{windowId}.json`. New DMS must not drop them. DMS join = **token-primary,
legacy-windowId fallback**:
1. legacy pass: file has `windowId` + that window is live → place it (today's behavior).
2. token pass: live window title has ⟨token⟩ matching a file's sessionId → place/override (wins).
Old sessions keep working unchanged until restarted; new sessions are robust.
