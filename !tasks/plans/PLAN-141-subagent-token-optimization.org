* Initial Message

look at the jsonl of the sessions (use jq) and find instances of subagents spinning their own subagents and having their TodoWrite orchestrate stuff. Please.

* Context

Analysis of 5,411 subagent sessions found 49 (0.9%) that spawn their own sub-subagents, costing 5.1x more than regular subagents ($0.94 median vs $0.18). The worst offender ran 141 turns at $9.19 with 14M cache-read tokens. Zero subagents use ~todo_write~ — it is stripped from all subagent tool sets via ~parentOwnedToolNames~.

** Key findings from session JSONL analysis
- 40 of 54 sub-subagent spawns are ~explore~ type (read-only scouts) — low cost
- 6 are ~task~ type (full agents spawning other full agents) — highest cost, least value
- ~task~ agent has ~spawns: \"*\"~ allowing arbitrary nesting; data shows this is almost never productive
- Subagents inherit compaction settings from parent but should NOT compact — they should fail fast and return partial work
- Cost per output token for spawning subagents is 2.7x worse than regular subagents
- Prompt caching between siblings is underutilized: concurrent launches miss the cache window

** Approach
Five coordinated changes:
1. *Cost visibility*: Show per-subagent cost in TUI (progress, results, viewer, batch summary)
2. *Subtask model roles*: New ~pi/subtask~ (fast) and ~pi/subtask-slow~ roles with compaction disabled; overflow fails to parent
3. *Reduce recursion depth*: Default 4 → 2 (main → subagent → sub-subagent max)
4. *Enable todo_write*: Let subagents self-organize with todos instead of spawning children
5. *Restrict spawns + cache stagger*: ~task~ agent spawns only ~explore/quick_task~; 800ms stagger between batch launches for cache hits

** Key decisions
- Fast model default for subtasks: 90% should use ~pi/subtask~ (smol) to enforce clear task definitions
- No compaction for subagents: overflow → fail-to-parent with partial work summary
- ~todo_write~ available to all subagents, not just task-type — simpler, and explore/quick_task rarely need multi-step planning
- Journal files already per-session — no new isolation mechanism needed
- Auto-roster creation stays blocked at depth > 0 — subagents manage their own todos, not parent's roster
- Cache stagger default 800ms — enough for first response to warm Anthropic cache
