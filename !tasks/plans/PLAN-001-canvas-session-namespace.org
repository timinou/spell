* Initial Message

add a namespace: canvas://session/, which are qml files that are ephemeral (saved just for this session)

* Goal

Add a new `canvas://session/` namespace for QML files that are session-scoped and ephemeral to the session lifecycle, while preserving existing `canvas://stdlib/` behavior.

* Requirements Snapshot

- User request: `canvas://session/` should hold QML files saved for this session.
- Clarified decision: session-scoped persistence should survive process restart/resume for the same session ID.
- Keep plan self-contained for fresh execution session.
- No compatibility shim design; implement full cutover for the new namespace in canonical resolver paths.

* Key Findings

- `CanvasProtocolHandler` currently supports only `stdlib` and enforces existence before returning `sourcePath` (`packages/coding-agent/src/internal-urls/canvas-protocol.ts`).
- `CanvasTool` write path resolution currently goes through `internalRouter.resolve(...)`, which requires file existence and therefore cannot create new files at internal URLs (`packages/coding-agent/src/tools/canvas.ts`).
- `sdk.ts` already provides session context and registers protocol handlers; `LocalProtocolHandler` shows the established pattern for session-root derivation and a separate URL-to-path helper that does not require pre-existing files.
- No existing canvas protocol tests cover namespace behavior today; test gap exists in `packages/coding-agent/test/internal-urls/`.

* Design

** Chosen approach

1. Extend `CanvasProtocolHandler` to support two namespaces:
   - `canvas://stdlib/<path>` (existing behavior, read-only built-in assets)
   - `canvas://session/<path>` (session-root assets, read/write via tool flow)
2. Introduce exported helper(s) in canvas protocol module analogous to local protocol:
   - resolve canvas roots (`stdlib`, `session`)
   - resolve `canvas://...` URL to filesystem path without requiring file existence
3. Update `CanvasTool` path resolution so `write` uses URL-to-path resolution (create allowed), while `launch` remains existence-validated by normal resolve/read path.
4. Keep security invariants: relative-path validation + containment checks + symlink escape protection where applicable.

** Trade-offs considered

- Option A: Keep using `internalRouter.resolve()` for `write` and add “create if missing” in protocol resolve.
  - Rejected: mixes read/resolve semantics with mutation intent and weakens protocol contract.
- Option B (chosen): add dedicated URL->path resolver utility for write paths.
  - Accepted: preserves strict resolve semantics for reads/launch, and cleanly supports write-create flow.
