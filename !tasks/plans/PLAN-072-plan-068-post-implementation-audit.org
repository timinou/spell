** Problem
Post-implementation audit of PLAN-068 (unify wave orchestration with todo_write and task subagents). The plan is marked DONE with verification evidence, but source inspection reveals several gaps between what the plan claimed and what shipped.

** Summary of Findings

*** F1: Orphaned types in packages/org/src/types.ts [LOW]
~FluidPlanWithComponents~, ~FluidPlanComponent~, ~FluidPlanWave~, ~FluidPlanAgent~ have zero consumers anywhere in the codebase. They are star-exported from ~packages/org/src/index.ts~ but nothing imports them. FEAT-180 planned to delete them but they survived. Harmless dead code, but misleading API surface.

*** F2: Org hook failures silently swallowed [MEDIUM]
~applyOrgLifecycleHooks~ in ~todo-write.ts~ catches org transition errors at lines 336-341 and 354-359 and only calls ~logger.error~. No notice is pushed to the ~notices~ array, so the agent never learns when an org transition failed. FEAT-175 (from PLAN-066, claimed superseded) specifically addressed this and was marked as covered by PLAN-068, but the fix was not implemented. The agent sees ~INFO:~ on success but nothing on failure.

*** F3: Voided params in executeFluidPlan [LOW]
~executeFluidPlan~ still accepts ~cwd: string~ and ~concurrency: number~ that are immediately ~void~ed. FEAT-180 planned to remove them. All callers thread these values for no reason.

*** F4: Fluid-mode retry discards coordinator todo edits [HIGH]
~startRetry~ rebuilds todos from the original ~FluidPlan~ via ~materializeFluidPlanToTodos~, discarding any todo modifications the coordinator made during execution. BUG-057 (from PLAN-066, claimed superseded) identified this exact bug. PLAN-068 did not fix it — ~collectRetrySubtree~, ~collectPresetCompletedResults~, and ~resolveRetryRoots~ all remain, operating on the old plan-derived data model. ~lastPhases~ is never captured.

*** F5: fluid-drain.test.ts tests local helper, not source [LOW]
~test/orchestrators/fluid-drain.test.ts~ survives with a local ~startPlanningDrainLoop~ helper that reimplements the drain loop from ~fluid-mode.ts~. The FluidOrchestrator describe block was correctly removed, but the \"executePlan planning-phase drain behavior\" block tests this local copy instead of the real implementation. Changes to the real drain loop would go untested.

*** F6: Canvas fluid-mode does not use planWavesToTodoPhases [INFORMATIONAL]
FEAT-184 planned to converge canvas mode onto the ~planWavesToTodoPhases~ pipeline. In practice, canvas mode uses ~materializeFluidPlanToTodos~ which returns a ~FluidTodoPlan~ with ~taskIdByAgentId~ needed by ~syncRuntimeStates~. Both paths call ~materializePlanWaves~ internally, so behavior is equivalent, but the dual entry points remain contrary to the plan's stated convergence.

*** F7: isCoordinator conditional never shipped [INFORMATIONAL]
FEAT-182 planned to merge prompts using ~{{#if isCoordinator}}~ conditionals. The actual implementation uses ~{{#if executionItems}}~ instead, which is behaviorally equivalent (canvas mode passes executionItems, /plan mode does not). The plan's described mechanism differs from reality but the behavioral intent is met.

*** F8: PLAN-066 org lifecycle not closed [LOW]
PLAN-066 remains INIT state. Its child items (FEAT-174, FEAT-175, FEAT-176, FEAT-177, BUG-057) all remain ITEM state despite PLAN-068 claiming to supersede PLAN-066 and being marked DONE.

*** F9: CHANGELOG.md missing PLAN-068 entries [LOW]
Commit ~2267f36dd~ introduced delegation model, wave auto-init, bidirectional todoRef, failed status, sub-task propagation, result forwarding, and dead code deletion, but none of these appear in the Unreleased section of ~packages/coding-agent/CHANGELOG.md~.
