* Initial Message

Goal: simple frontend to spell server. a client can connect with a secret token to a fast websocket that can let you connect with the running sessions by that user on that instance (through spell autodiscovery, consolidate the feature by looking at existing usage of similar features).

On the frontend, you can start new plan sessions, you can request a url, etc. that lets you use both xterm.js and, for example, see the pdf generated from a typst requested by a task whose goal was to generate a report.

easy way to setup templates from the frontend, wiht a linear-like command bar. Template 'document', you run it, you get a nice card in your session list, and then it tells you when it has the artifact ready.

* Context

Spell needs a single-instance web dashboard so a user (or a small group via named bearer tokens) can drive ~spell-server~ and its sessions from a browser. The dashboard must:

- Auto-discover all running spell sessions for that user on that instance: server-spawned RPC sessions (full control) and external CLI sessions registered via the existing ~~/.spell/server.sock~ bridge (read-only feed + answer blocking events).
- Spawn new RPC sessions on demand. Templates declared in ~autonomy.kdl~ as a new top-level ~template "name" { … }~ node provide a Linear-style command-bar quick-launch with typed params and Handlebars-rendered prompts.
- Render two xterm.js tabs per spawned session: Stream (RPC events as ANSI text + prompt/steer/abort) and Bash (RPC ~bash~ command). State and Artifacts tabs round it out.
- Surface artifacts (PDF/img/typst output) over HTTP with bearer auth and short-lived signed URLs for embed cases. WS broadcast ~artifact_created~ events with optional file-extension subscription filter so a "document" template card flips to ~ready~ exactly when the matching ~.pdf~ lands on disk.

Existing infrastructure consolidated:
- ~SocketSessionRegistry~ becomes the unified registry (extended with ~kind: "external" | "spawned"~, ~ownedBy~, ~templateName~, ~rpcClient~).
- ~SessionManager~ + ~RpcClient~ (already used by goals/Telegram) drive web-spawned RPC sessions through a new ~WebSpawnedLifecycle~.
- ~ArtifactManager~ paths + ~resolveArtifactScopeFromSessionFile~ provide the canonical artifact addressing.
- ~startHttpServer~ in ~http/server.ts~ extended with ~/web/*~ routes (SPA assets, REST API, WebSocket upgrade, artifact router).
- Manifest parser/validator/serializer extended with the ~template~ node mirroring goal/setup conventions.
- Bridge protocol (~socket/types.ts~) extended with one new opt-in ~event_log~ message kind for low-fi external-session feeds.

Settled design decisions (from clarifications round):
1. Mount: extend spell-server (no new package); single ~Bun.serve~ owns HTTP + WS.
2. Auth: ~web { token "alice" "env(...)" }~ repeatable; bearer in ~Authorization~ or ~?token=~ for WS upgrade.
3. Sessions: hybrid (spawned full control; external observe + answer blocking events).
4. Templates: new top-level ~template~ KDL node; Handlebars prompts; param coercion reuses action-descriptor patterns.
5. xterm.js: two tabs per session — Stream + Bash.
6. Artifacts: header-auth + short-lived signed URLs; WS subscribe with optional ~artifactExt: string[]~ filter.
7. Frontend: Vite SPA in ~packages/spell-server/web/~; build output embedded into spell-server at runtime.
8. Owner: token name → ~ownedBy~ tag; soft (all clients see all sessions).

* Verification

After all child items ship:

1. ~bun check~ green at repo root.
2. Run ~bun run build:web~ inside ~packages/spell-server/web~ → ~dist/~ populated.
3. Start the server with a minimal config:
   #+begin_src kdl
   http port=8787 {
     auth username="admin" password="admin"
   }
   socket path="~/.spell/server.sock"
   web {
     token "alice" "env(SPELL_TOKEN_ALICE)"
   }
   #+end_src
   And a manifest with a ~template "document" { setup "writer"; param "topic" type="string" required=#true; prompt "Generate a typst PDF report on {{topic}}."; artifact-watch ext=".pdf" }~.
4. Visit ~http://localhost:8787/web/~ in a browser; enter the token; observe the empty session list.
5. Run any existing ~spell~ CLI session in another terminal with ~SPELL_BRIDGE_EVENT_LOG=1~ → external session appears in the list with low-fi event log.
6. ⌘K → ~document~ → topic="memory" → submit. Card appears in sidebar; status transitions ~spawning~ → ~running~ → ~ready~ when the .pdf is written; PDF preview renders inline in the Artifacts tab via signed URL.
7. Stream tab: text stream renders in real time; ~Cmd+Enter~ in the prompt issues a follow-up; ~^C~ aborts.
8. Bash tab: ~ls
~ executes the RPC ~bash~ command and prints output.
9. WS reconnect after ~kill -STOP~/~CONT~ on the daemon's socket connection from the browser tab → store re-lists sessions cleanly.
10. ~bun test packages/spell-server/test/web~ + ~bun test packages/spell-server/web/test~ green.

Manual integration smoke (5-10 min):
- Two browser tabs see the same session updates.
- Killing a spawned session from one tab removes the card in the other within 1s.
