* Context

The Elixir language profile in =pi-code-engine= produces useless outlines -- a single "defmodule" entry with no nested functions. This makes the =code= tool (outline, navigate, resolve, edit) ineffective for Elixir projects.

** Approach

Extend the profile infrastructure with:
1. =filter_names= on =DeclarationPattern= and =ClassLikePattern= -- generic filter to disambiguate uniform node types (all Elixir constructs are =call= nodes in tree-sitter-elixir)
2. =name_from_arg= on =DeclarationPattern= -- extract symbol names from arguments instead of the target field
3. =child_by_field_or_kind()= helper -- fallback for positional children (=do_block= and =arguments= are unnamed in tree-sitter-elixir)

Then rewrite =elixir_profile()= with separate patterns for defmodule/def/defp/defmacro/defmacrop and a ClassLikePattern for defmodule as a container.

** Key Decisions

1. =filter_names: Option<Vec<String>>= on DeclarationPattern/ClassLikePattern -- generic, not Elixir-specific
2. =name_from_arg: bool= on DeclarationPattern -- extract name from first argument child
3. =source: &str= added to =declaration_for()= signature (needed for text comparison in filter)
4. Separate DeclarationPattern per keyword -- clean kind mapping
5. Deferred: visibility (def=public, defp=private), additional keywords (defstruct etc), navigate name_text unification
