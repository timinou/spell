* Problem

The canvas QML components — spawned when the agent displays structured data (tables, diffs, trees, logs, prompts) — have poor visual quality. Specific failures:

1. *Typography lacks hierarchy*: 4 font sizes (12/14/16/20px), 2 weights (normal/bold). Everything reads at the same visual weight.
2. *Surface colors are indistinguishable*: 4 dark grays spanning only ~12 L* units (#0e1117 → #242a33). Container boundaries are barely perceptible.
3. *Zero depth system*: No shadows, no border weight variation, no top-edge highlights. Every component sits on the same visual plane.
4. *Crude interactive states*: Qt default RadioButton/CheckBox/Button look alien against the dark theme. No row hover on tables/trees. No focus rings. No transition animations.
5. *DataTable is spartan*: 4px margins, invisible alternating rows, no cell padding, no hover.
6. *DiffView too subtle*: 0.12 alpha on add/remove backgrounds is hard to read. Cramped gutter. No hunk separators.
7. *TreeView uses emoji*: 📁/📄 icons render inconsistently, can't be themed, look unprofessional.
8. *ContentBlock uniform treatment*: Every block type gets the same surface-colored rectangle — no visual distinction.
9. *Prompts unstyled*: Native Qt controls with Fusion style palette.
10. *No micro-interactions*: Only animation is StatusIndicator pulse.

* Aesthetic Direction: Precision Dark (Instrument Panel)

Bloomberg Terminal meets Linear meets JetBrains Fleet. Dense data rendered with absolute clarity where every pixel of contrast earns its keep.

Principles:
- Information density over decoration — enough breathing room to parse at a glance, no gratuitous whitespace
- Contrast through luminance gaps, not color — wider L* steps between surface levels
- Monochrome structure, chromatic semantics — color reserved for meaning (diff +/-, status, accent); structural hierarchy is achromatic
- Motion confirms causality — animation only where user action needs acknowledgment

*Memorable*: Data areas sit in recessed "wells" (darker-than-card background) inside elevated card panels — every component reads as an instrument with its data inset into the panel surface.

* Design Decisions

** Typography

Keep Inter + Fira Code. Expand scale from 4 sizes to 7 (modified major-second scale anchored at 14px body). Add font weight tokens.

| Token | Value | Role |
|-------|-------|------|
| fontSizeXS | 11px | captions, timestamps, line numbers |
| fontSizeS | 12px | secondary labels, table headers, sidebar nav |
| fontSizeCaption | 13px | secondary body, captions in context |
| fontSizeM | 14px | body text (KEPT at 14px for dark-theme readability) |
| fontSizeL | 16px | emphasis body, prompt questions |
| fontSizeXL | 20px | section headers |
| fontSizeXXL | 26px | page titles, hero headers |

Rationale for keeping 14px body: On dark backgrounds, subpixel rendering is weaker. 13px Inter at 400 weight approaches the readability floor for sustained reading at <120 DPI. This is a developer tool where users read dense tables and diffs for extended periods.

| Weight Token | Value | Qt Enum | Usage |
|--------------|-------|---------|-------|
| fontWeightLight | 300 | Font.Light | large display text |
| fontWeightRegular | 400 | Font.Normal | body text |
| fontWeightMedium | 500 | Font.Medium | table headers, nav labels, field labels |
| fontWeightSemiBold | 600 | Font.DemiBold | section headers |
| fontWeightBold | 700 | Font.Bold | page titles only |

Prefer Qt enum names (Font.Medium, Font.DemiBold) over raw integers for readability in QML.

Letter-spacing: trackingTight (-0.3px for 20px+), trackingNormal (0), trackingWide (+0.5px for 11-12px).
*IMPORTANT*: Do NOT apply letter-spacing to Fira Code (mono) text — QML's font.letterSpacing disables OpenType ligatures, which destroys Fira Code's primary value. Letter-spacing tokens are Inter-only.

Line-height multipliers (via QML's lineHeight with default ProportionalHeight mode):
- lineHeightBody: 1.5 (body text)
- lineHeightHeading: 1.25 (headers)
- lineHeightMono: 1.6 (code, diffs, logs — critical for readability)

** Color Strategy

60% deep slate background / 30% elevated surfaces / 10% amber accent. Dark baseline.

*** New surface tokens with 5-6 L* steps between levels

| Token | Hex | L* | Role |
|-------|-----|-----|------|
| background | #0d1117 | 5 | Window background (unchanged) |
| surface0 | #151b23 | 10 | Card/panel surface |
| surface1 | #1e252e | 15 | Elevated surface, header bars |
| surface2 | #2a3240 | 21 | Highest elevation, selected states |

*** New border tokens (three-tier system)

| Token | Hex | L* | Role |
|-------|-----|-----|------|
| borderSubtle | #253040 | 19 | Inner divisions (table rows, tree lines) |
| borderDefault | #3a4556 | 29 | Component boundaries, card edges |
| borderStrong | #4f5d73 | 39 | Focus rings, active borders |

*** Backwards compatibility strategy (CRITICAL)

~15+ out-of-scope files (shell.qml, panels/*, reference/*) consume old token names. Old aliases MUST keep their ORIGINAL hex values to avoid silent visual shifts:

#+begin_src
// Deprecated — keep at original values for out-of-scope consumers
readonly property color surface: "#161b22"        // NOT surface0
readonly property color surfaceHigh: "#1c2129"    // NOT surface1
readonly property color surfaceHigher: "#242a33"  // NOT surface2
readonly property color outline: "#30363d"        // NOT borderDefault
readonly property color outlineVariant: "#21262d" // NOT borderSubtle
#+end_src

New tokens coexist alongside old ones at *different* hex values. In-scope canvas files migrate to new tokens. Out-of-scope files see zero visual change. Old aliases are never removed — they cost nothing in a singleton. Mark them with =// @deprecated= comments.

*** Text adjustments

- textPrimary: #e6edf3 — keep (WCAG AAA on surface0)
- textSecondary: #8b949e — keep
- textTertiary: *RAISE* from #484f58 to #6e7681 (current ~3:1 contrast fails WCAG AA; new gives ~4.8:1)
- textGhost: #484f58 (new token, decorative only — line numbers, tree guides)

*** Diff color tokens

Raise alpha from 0.12 to 0.15. Tint hunk headers blue for visual separation:
- diffAddBg: rgba(46, 160, 67, 0.15)
- diffRemoveBg: rgba(248, 81, 73, 0.15)
- diffHunkBg: rgba(56, 139, 253, 0.10)

*** Row treatment

Remove alternating row colors (insufficient contrast on dark theme). Replace with: consistent surface0 bg + 1px borderSubtle bottom border per row + hover highlight at surface1.

** Motion Rules

Every state change gets exactly one animation. Content arrival is instant (no entrance animations).

| Element | Animation | Duration | Easing |
|---------|-----------|----------|--------|
| Table/tree row hover | bg color → surface1 | 120ms | OutQuad |
| Tree expand/collapse chevron | rotation 90° | 150ms | OutQuad |
| Sort indicator direction flip | rotation 180° | 100ms | OutQuad |
| Button press | scale(0.97) | 80ms press / 120ms release | OutQuad |
| Prompt answer confirmation | left border slide-in, others fade 50% | 150ms / 200ms | OutQuad |
| StatusIndicator pulse | opacity 1.0→0.3 | 250ms (keep existing) | InOutQuad |

No bounce/elastic easing. No parallax. No entrance animations on data arrival.

*** Row hover performance (IMPORTANT)

Do NOT use =Behavior on color= inside ListView delegates — it creates animation objects per delegate, causes scroll jank on 100+ rows, and glitches with delegate recycling.

Instead: track hovered row index as a single property at the ListView level. Bind each delegate's color to =index === hoveredRowIndex ? surface1 : surface0=. For the color transition, conditionally create the Behavior only on the hovered delegate (via States or a ternary on the Behavior's enabled property). DataTable/DiffView/TreeView currently use =interactive: false= so delegate recycling isn't an issue, but LogStream scrolls and would hit this.

** Spatial Composition

Information-dense with controlled padding. Layout philosophy: "inset instrument panel."

- ContentBlock inner padding: 8px → 16px
- Table: row height 36→40px, cell padding 4→12px horizontal, 8px vertical
- Table header: height 32→38px
- Diff: gutter 30→44px line numbers, 14→20px ±gutter, 8px left padding on line text
- Hunk separator: 8px vertical gap between hunks with centered 1px borderSubtle line at 60% width
- Data areas (DataTable ListView, DiffView ListView, LogStream ListView): use background (#0d1117) color inside the card, creating a recessed "well" with 1px borderSubtle border

** Interaction States

All interactive elements need explicit state styling. System Qt controls look alien against the dark theme.

*** Custom controls (inline component or dedicated .qml)

Custom RadioButton:
- indicator: 16px circle, 2px borderDefault stroke, filled 10px inner circle in primary when selected, 150ms ColorAnimation
- contentItem: Text at fontSizeM, fontWeightRegular, textPrimary
- background: transparent (override Qt default)

Custom CheckBox:
- indicator: 16px rounded-rect (cornerRadiusSmall), 2px borderDefault stroke, checkmark path in primary when checked, 150ms ColorAnimation
- contentItem: Text at fontSizeM, fontWeightRegular, textPrimary
- background: transparent

Custom Button (SpellButton inline component):
- background: Rectangle with surface1 bg, borderDefault border, cornerRadiusSmall radius
- contentItem: Text at fontSizeM, fontWeightMedium, textPrimary, centered
- Padding: 8px vertical / 16px horizontal
- Hover: borderStrong border, 120ms transition
- Press: scale(0.97) + surface2 bg, 80ms transition
- Disabled: disabledOpacity
- Focus: 2px primary focus ring

*** Focus ring implementation

QML has no CSS outline-offset. Implement as a reusable =FocusRing= inline component:

#+begin_src qml
component FocusRing: Rectangle {
    anchors.fill: parent
    anchors.margins: -2
    color: "transparent"
    border.width: 2
    border.color: SpellUI.SpellTheme.primary
    radius: (parent.radius || 0) + 2
    visible: parent.activeFocus
}
#+end_src

Apply inside all custom controls (Button, RadioButton, CheckBox, TextField).

*** Per-element states

Table header: default surface1 → hover surface2, pointer cursor
Table row: default surface0 → hover surface1
Tree node: default transparent → hover surface1
Button: default surface1 → hover borderStrong → press surface2+scale(0.97) → disabled 38% opacity
RadioButton/CheckBox: default borderDefault stroke → selected primary fill → disabled 38% opacity
TextField: default borderDefault → focus borderStrong → error red border

** Depth via Light Edges (not shadows)

Drop shadows look like smudges on dark themes. Instead:
- Top-edge highlight: 1px line at top of elevated cards, colored borderDefault
- Inset well: data areas use background color (darker than card), 1px borderSubtle border
- Separator weight hierarchy: 1px borderSubtle for inner, 1px borderDefault for component boundaries, 2px primary for focus

** ContentBlock Per-Type Differentiation (CRITICAL DETAIL)

Currently ContentBlock.qml is a single Rectangle (=color: SpellUI.SpellTheme.surface=) wrapping all types identically. The Loader sourceComponent switch selects content but the container appearance doesn't vary.

Implementation approach: Add a =blockTypeStyle()= function returning {bgColor, borderColor, borderWidth, showTopHighlight} per block type. Bind the outer Rectangle's color and border to this. Add a conditional top-highlight Rectangle child.

#+begin_src
function blockTypeStyle(type) {
    switch (type) {
        case "markdown": return { bg: "transparent", border: "transparent", borderW: 0, topHighlight: false }
        case "table":
        case "diff":
        case "tree":    return { bg: surface0, border: borderDefault, borderW: 1, topHighlight: true }
        case "log":     return { bg: background, border: borderSubtle, borderW: 1, topHighlight: false }
        case "status":  return { bg: "transparent", border: "transparent", borderW: 0, topHighlight: false }
        case "image":
        default:        return { bg: surface0, border: borderDefault, borderW: 1, topHighlight: false }
    }
}
#+end_src

Plus a conditional 1px Rectangle at the top of the card for topHighlight types.

** DiffView Hunk Separator (CRITICAL DETAIL)

DiffView flattens hunks into a single array (flatLines). To get 8px visual gaps between hunks, insert ={ type: "separator" }= entries in flatLines between hunks (not before the first hunk). Add a separator delegate case:

#+begin_src qml
// In delegate:
case "separator":
    Item {
        width: parent.width
        height: 8
        Rectangle {
            anchors.centerIn: parent
            width: parent.width * 0.6
            height: 1
            color: SpellUI.SpellTheme.borderSubtle
        }
    }
#+end_src

** Anti-Patterns to Avoid

- NO glassmorphism/backdrop blur — catastrophic QML perf on 100+ row tables
- NO border-radius > 8px on data components — wastes space, looks toyish
- NO emoji icons — inconsistent rendering, unthemeable
- NO system default Qt controls without custom backgrounds
- NO entrance animations on content arrival — data appears instantly
- NO alternating row colors — insufficient contrast on dark theme
- NO letter-spacing on Fira Code text — disables ligatures
- NO Behavior on color inside ListView delegates — causes scroll jank on 100+ rows
