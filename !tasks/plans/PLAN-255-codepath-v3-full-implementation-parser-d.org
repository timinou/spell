* Context

CodePath v3 is a unified query algebra for addressing code structures across languages. It replaces the current =targetId= (=file::Symbol.member=) addressing with a full path algebra supporting combinators, predicates, qualifiers, edge axis, and set operations — all with language-pluggable NameLexer payloads.

The v3 *extension scope* (resolved in plan turn 2) folds into the same delivery: every CodePath whose Locator is a project-relative filesystem path or an internal URI is also a first-class query, and every file has a parallel text view via =§line=/=§chunk=/=§para= axes. This collapses =find=, =read=, =grep=, and =ast-grep= into specializations of one =code get= surface, mirroring the way the existing graph commands collapse into edge-axis queries (per =specs/code-graph/code-path.md= §5).

Authoritative design for the extension layer: =specs/code-graph/code-path-extensions.md= (specs/code-graph/code-path-extensions.md).

** Settled Design Decisions

1. *3-command surface*: =code get= (reads/queries/nav/graph/files/dirs/regex/URIs) + =code edit= (mutations) + =code manage= (lifecycle). Replaces 20+ current subcommands AND the =find=/=read=/=grep=/=ast-grep= tool family.

2. *targetId → target*: Structured =target= field with CodePath expression. Full cutover, no backward compat shim. Old =file::Symbol.member= is valid CodePath syntax naturally (=Locator :: NamePayload=).

3. *scope field removed*: =#body= qualifier in CodePath target replaces =scope: "body" | "target"=. Complete removal.

4. *Graph commands replaced*: =context=, =impact=, =deps=, =flow= become =code get= with edge axis (=ref→=, =def→=, =call→=, =import→=). =dead_code= and =clusters= accessed via =code get { target: ":dead_code" }=.

5. *Parser*: winnow (not chumsky) in new =crates/pi-code-path= crate.

6. *NAPI*: New =executeCodePath= function alongside existing NAPI exports. Streaming chunked async iterator surface.

7. *Sigils*: =§= (node-kind), =¶= (anchor), =→= (edge), =:= (field), =#= (qualifier). Update =code-path.md= to match dialect files.

8. *Code dialect scope*: Parser + resolver + all 8 NameLexers + edge axis + set ops + qualifiers + predicates.

9. *FS dialect baked in*: Filesystem tree as a kernel-baseline dialect. Globs in Locator, anchors (=¶hidden=, =¶ignored=, =¶code=, …), predicates (=ext=, =lang=, =size=, =mtime=, =name=, …), qualifiers (=#listing=, =#tree=, =#stat=). Standalone =FsLocator= queries (no =::Query=) yield NodeSets of files. Replaces =find=.

10. *Text dialect baked in*: Every file regardless of code dialect supports =§line=/=§chunk=/=§para=/=§span= axes via lazy line-byte index, bypassing tree-sitter. Predicates =[text~=…]=/=[match=…]=/=[len>…]=, combinators =<<=/=>>= for context, qualifiers =#raw=/=#text=/=#match=/=#captures[N]=/=#lines[a..b]=/=#bytes=/=#image=/=#thumbnail=. Format-aware =#text= extraction for PDF/DOCX/JSON/HTML reusing existing pipelines. Replaces =read= and =grep= (and =ast-grep= via =//§NodeKind[name=…]= structural predicates).

11. *URI scheme dialects baked in*: All 7 internal URI schemes (=artifact://=, =memory://=, =skill://=, =agent://=, =jobs://=, =local://=, =pi://=) become first-class Locators. Each is a small dialect that resolves URI→NodeRef, then delegates structural queries to FS/Text/Markdown/JSON sub-dialects. Replaces =read=-with-URL.

12. *NodeRef return shape*: Unified =NodeRef { locator, range, kind, content?, metadata, diagnostics }=. Content populated only when path includes a content-class qualifier. Binary content never inlined across NAPI — staged as =artifact://= handles. Streaming via chunked iterators with cancellation.

13. *Resolver state machine*: Dialect-switch dispatch is mechanical and explicit — the axis chosen determines dialect transition. Initial = FS. =§file= match → file's code dialect. First =§line= axis → text dialect. =→= edge → cross-file new dialect. URI Locator → scheme dialect → delegate. Text→code mid-file rejected (text loses tree position); must =^= and re-enter.

14. *Projection options as sugar*: Tool-layer =limit=, =head=, =tail=, =context: { pre, post }=, =content=, =format=, =root= are sugar for canonical CodePath syntax (=[0..N]=, =[-N..]=, =<<=/=>>=, qualifier defaults). Lowered to syntax in Rust before resolution. Round-trip property preserved.

15. *Tool deletion at cutover*: =find.ts= (491 LOC), =read.ts= (1019 LOC), =grep.ts= (926 LOC), =ast-grep.ts= (466 LOC) deleted in one cycle alongside =code get= projection-option rollout. No transition aliases. Migration table embedded in =code.md= prompt.

16. *Prompts*: Full rewrite of all code tool prompt files for 3-command model + migration patterns from deleted tools. =AGENTS.md= and per-agent role files updated.

17. *Cost discipline*: Pure FS query → walker only. Text-only query → line-index only. Code query → tree-sitter. Edge axis → code-graph. Mixed → composition. No interpreter does work it doesn't need to.
