* Context

This plan addresses the coding-agent hashline edit failure mode surfaced by the transcript excerpt:
- target file existed (=crates/pi-code-engine/Cargo.toml=)
- the request reached hashline =replace=
- neither =pos= nor =end= resolved to a valid anchor
- runtime threw the generic message =Replace requires at least one anchor (tag or end).=

Repository evidence gathered during planning:
- =packages/coding-agent/src/patch/index.ts=
  - default edit mode remains =hashline=
  - =resolveEditAnchors(...)= is the strict gate and currently throws the generic missing-anchor message
- =packages/coding-agent/src/patch/hashline.ts=
  - =parseTag(...)= already distinguishes malformed =LINE#ID= references
  - =HashlineMismatchError= already covers stale-hash recovery and must remain distinct
- =packages/coding-agent/src/prompts/tools/hashline.md=
  - prompt contract is thin relative to =replace.md=
- =packages/coding-agent/src/patch/shared.ts= and =packages/coding-agent/src/tools/code-result.ts=
  - existing shared render/hint patterns should be reused instead of inventing a new reporting surface

Settled decisions:
1. Safety policy = strict fail. The system MUST NOT guess anchors, widen the replace, or fall back to whole-file replacement.
2. Intervention style = end-to-end. Plan includes prompt/schema guidance, runtime validation/diagnostics, shared rendering/reporting, and targeted tests.
3. Relationship to PLAN-254-cross-session-edit-coordination = separate execution. This item only references PLAN-254 where shared edit/TUI surfaces overlap; it MUST NOT absorb broker/journal/coordination scope.
4. Scope bias = broad audit across the coding-agent hashline/edit flow, but still one design decision: malformed text-edit requests must fail truthfully and teach the retry path.

Recommended approach:
- Keep =resolveEditAnchors(...)= strict.
- Introduce a clearer external failure contract that distinguishes:
  - missing anchors
  - malformed anchors
  - stale hashes
- Strengthen =hashline.md= and any relevant schema descriptions so the model learns the valid request shape before runtime.
- Add focused tests that prove the externally observable behavior for valid, missing-anchor, malformed-anchor, and stale-hash flows.
