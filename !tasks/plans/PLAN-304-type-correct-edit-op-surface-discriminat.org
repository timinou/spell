* Initial Message

Edit tool surface today admits "no resolver supports action Write" on symbol-targeted writes — a routing bug rooted in a flat 25-variant ~18-field Action enum where ActionKind is the dispatch key. Bring the (target × action) compatibility into the type system end-to-end so impossible combos can't be constructed, can't validate, and can't dispatch silently.

* Problem (root causes)

| # | Cause | Effect |
|---|---|---|
| RC-1 | Action is flat enum of 25 variants with ~18 mostly-optional fields | invalid combos parse; schema cannot express constraints |
| RC-2 | ActionKind (string) is the routing key, not Action variant | routing decided imperatively per-resolver |
| RC-3 | MutationResolver::supports() is per-resolver match | no totality/uniqueness check across resolvers |
| RC-4 | TS surface uses Type.String() for kind/scope/mode/direction | typos + drift typecheck |
| RC-5 | code_buffer JSON surface is a superset of kernel Action | scope:"body" reachable in code_buffer, silently dropped in kernel |
| RC-6 | edit.md hand-written prose drifts from schema | agents see false affordances |

Concrete holes catalogued today:
- Write+S fails-but-implemented (code_buffer supports; CodeResolver.supports skips)
- Append/Prepend/Patch on symbol targets silently fall through
- Rename+F nonsensical but only fails at apply()
- Procedural Css/Heading variants claim supports() but apply() throws NotImpl
- scope:"body" passed through TS adapter, dropped in kernel deserialization
- Replace/Insert without pos/end/line passes parse, fails at apply()

* Goals

- (G1) Every valid op JSON has exactly one resolver — total + unique dispatch
- (G2) Every Op variant's required fields are statically present (no Option-on-required)
- (G3) Every Op variant's target type ⊆ allowed locator shapes (FileTarget refuses ::, SymbolTarget requires ::)
- (G4) TS schema is a discriminated union on `kind` — Type.Literal narrowing in user code
- (G5) Adapter translates legacy kind names ("write","delete","rename"…) for one minor with deprecation note in result text
- (G6) edit.md prompt is generated from schema; no hand-drift
- (G7) Compile-time exhaustiveness in Rust (match on &Op) and TS (`const _: never = op` tail in switch)

* Non-goals

- No new editing capabilities beyond closing existing holes
- No schemars / Rust-side schema generation (TS is source of truth; parity test); revisit later as FUP
- No changes to LINE#ID anchor mechanism in TS sidecar (`edit.ts` already pre-routes those)
- No URI-locator mutation support (out of scope)
