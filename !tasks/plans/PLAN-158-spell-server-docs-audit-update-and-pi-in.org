* Context

Spell-server has three documentation files in =packages/spell-server/docs/= (getting-started.md, architecture.md, kdl-schema-reference.md). An audit found:

- *architecture.md*: 4 major subsystems missing (workflow, socket, state, actions), stale "missing CLI entrypoint" claim
- *getting-started.md*: accurate but scoped narrowly to autonomy goals; telegram bridge (the primary interactive use case) treated as "optional notifications"
- *kdl-schema-reference.md*: 95% accurate but missing voice config block, auto-send-images, bot-token env() support, wrong socket default
- *telegram bridge*: 12 commands, voice, session management, file delivery, approvals — zero documentation

None of these docs are accessible through =pi://= internal URLs. The existing generator at =packages/coding-agent/scripts/generate-docs-index.ts= scans =docs/**/*.md= recursively, so placing files at =docs/spell-server/*.md= makes them accessible as =pi://spell-server/getting-started.md= etc. with zero code changes.

Additionally, there is no interactive way for a new user to bootstrap a spell-server setup. Two sibling projects (=../growth/.spell/= and =../founder-sidekick/.spell/=) demonstrate mature, modular KDL configurations with imports, state stores, memory systems, and workflow pipelines — but this knowledge is locked in those repos with no way for a new user to replicate the patterns.
