* Context

Two or more =spell= processes editing the same repo currently share no buffer state. Each process owns a per-dylib =BufferRegistry=; the =FileWatcher= detects external writes asynchronously; =History= has no session attribution. This produces =ExternalModification= errors, stale targetIds, and undo that can clobber a peer's work.

This plan removes the class of stale-buffer problems by making every mutating =code edit= a short read-lock-write-release transaction against disk, broadcasting commits through a dedicated Unix-socket broker, and recording CodePath-level attribution in a persistent journal. No CRDT in Phase 1; journal format is forward-compatible with Loro.

Operator directive (axiom): "Equate an edit with a file change. Lock time per edit = literally lock-write-release. Asynchronous across agents and within sessions. Gets updated if the file got updated. Reload and save MUST be standardized; undo/redo are best-effort."

Full design (every implementer MUST read): [[file:specs/edit-coordination/design.md]]

Parent container: [[id:PROJ-050-cross-session-edit-coordination-broker-j][PROJ-050]]

Settled decisions (carried across session boundary):
1. No CRDT in Phase 1. Journal + socket broker + peer-aware reload. Loro as Phase-2 upgrade.
2. Dedicated =pi-edit-broker= daemon. Auto-spawned by first client. Socket at =~/.spell/edit-broker.sock=. Exits 30s after last client disconnects.
3. Attribution granularity = CodePath (per rich tree-sitter node). Falls back to whole-file marker =::*= when no named ancestor encloses the edit.
4. Conflict policy = block + structured error ={conflictingSession, codePath, peerRevision, peerCommitTs}=. Never silent.
5. Stateless edit transaction model. No persistent dirty buffer for mutating paths. Every =edit_transaction= re-reads disk under lock, re-resolves CodePath, applies, writes, commits, broadcasts.
6. Undo/redo per-session, best-effort. =undo_scoped(sessionId)= skips peer revisions and reports them.

* Risks and mitigations

- **Broker binary distribution.** =pi-edit-broker= must be found by =spawn_broker_if_absent=. Mitigation: default to =target/release/pi-edit-broker= in dev; in release artifacts, bundle alongside =pi-natives= in the same directory resolved by =getNativesDir()=.
- **Broker fallback.** Every RPC has a 150 ms budget; on timeout or socket error, degrade silently to =NullCoordClient= for that call and log a single warning per process. The journal still writes locally.
- **Atomicity of disk write.** Replace =fs::write= with temp-file + =rename= in the critical section. Ensure temp file sits on same filesystem as target.
- **Peer commit races inside critical section.** Broker grants intent, but between grant and commit another session could commit. Mitigation: one retry inside the critical section that re-reads disk and re-resolves CodePath; second conflict returns =PeerConflict= to caller.
- **Stale socket file after broker crash.** Auto-spawn path tests =connect()= first; on failure, =unlink()= stale socket before binding.
- **CodePath dep not yet landed.** FEAT-575 references the CodePath dialect interface. If CodePath ships later, FEAT-575's =node_ref.rs= falls back to the existing =line_target= byte-range path plus =LanguageId= name heuristics; the journal entries gracefully degrade to file-level markers until CodePath ships.
- **Subagent session collision.** Each subagent has a distinct =sessionId= via =sessionManager.getSessionId()=. Verify in FEAT-580 that subagent edits attribute to the subagent, not the parent.

* Non-goals (Phase 1)

- CRDT-backed concurrent merge (Loro). Journal format accepts future =op: [...]= payloads.
- Cross-host coordination (broker is local Unix-socket only).
- Semantic conflict resolution (e.g., "peer deleted function, my edit added a call").
- Windows named-pipe support.

* Rollout

Phase 1 — Waves 1–2 (foundation + engine): not yet user-visible; passing tests are the only signal.

Phase 2 — Wave 3 (NAPI): =code edit= starts requiring =sessionId= for mutating commands; coding-agent updates in Wave 4 keep the surface green.

Phase 3 — Waves 4–5 (tool + TUI): user sees =coord: N peers= status-line segment and peer-activity footers. Graceful for single-session users: segment renders empty when no peers.

Phase 4 (future, out of this plan) — Loro adoption for concurrent character-level merge. Journal schema carries the hooks (=op[]= union field).
