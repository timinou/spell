** Approach: Spell-native tool tiering with auto-activation
All intelligence is in Spell — no Anthropic-specific API features. Provider-agnostic.

1. *Tool tiers*: core / standard / specialized. Only core+standard registered initially (~13k tokens).
   Specialized tools (~6k tokens) listed by name in system prompt.
2. *Auto-activation*: When model calls a specialized tool, Spell checks the registry, silently
   activates it, executes the call, and rebuilds the prompt. Zero extra round-trips.
3. *Task classifier*: Lightweight heuristic at session start optionally adjusts which standard
   tools are included (e.g., skip AST tools for simple questions).
4. *Cache stability*: Deterministic tool ordering prevents unnecessary cache invalidation.

** Existing infrastructure (already works)
- =setActiveToolsByName()= — changes active tool set + rebuilds prompt
- =rebuildSystemPrompt()= — rebuilds system prompt from current active tools
- =agent-loop.ts= L529-536 — handles tool-not-found (intercept point for auto-activation)
- =toolRegistry= — contains ALL tools including inactive ones
- =skill://= protocol — already handles on-demand skill content loading
