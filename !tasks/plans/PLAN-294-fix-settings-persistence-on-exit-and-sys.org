* Context

Two related startup issues discovered during memory profiling of Spell v13.12.8:

1. **Changelog always showing**: `settings.set("lastChangelogVersion", VERSION, "user")` queues a 100ms debounced save, but no `Settings.flush()` is called on process exit. The debounce timer races against `process.exit()` and loses. The setting is silently lost — every cold start shows the full changelog again.

2. **System prompt timeout warning**: `buildSystemPrompt()` races ALL 4 prep operations (skills, AGENTS.md, context files, SYSTEM.md) against a single 5s timeout. If any combination exceeds 5s under I/O contention at startup, ALL results are discarded — the agent loses AGENTS.md context, skills, and customizations, and the user sees "using minimal startup context".

On this project (~7365 dirs, 3 AGENTS.md, 10 skills), isolated measurements show all 4 ops complete in <100ms. The timeout only fires under startup I/O contention when model discovery, domain loading, and session creation compete for the event loop. The fix: per-op resilience (never discard good data) + pre-compute immutable results during session creation (no time pressure).
