* Context
The Spell coding agent lacks cross-file code intelligence. It has single-file AST operations (Emacs treesit) and 1-hop cross-file semantics (LSP), but no transitive call graphs, impact analysis, dependency mapping, dead code detection, or architectural clustering.

This plan adds a native Rust code graph engine (=crates/pi-code-graph=) that indexes codebases using tree-sitter, stores the graph as a petgraph with typed edges, and exposes queries as new commands on the existing =code= tool. The agent gains the ability to ask "what breaks if I change this?", "how is this symbol connected?", "what's the execution flow?", and "what code is dead?" — all from a single tool call.

** Approach
- Native Rust crate (=pi-code-graph=) using =petgraph= + =tree-sitter= + =oxc_resolver=
- Trait-based language interface: =LanguageExtractor= (per-file AST extraction) + =ImportResolver= (project-level import resolution). Adding a new language = implement two traits + register.
- Phase 1 languages: TypeScript/JavaScript + Elixir (with full HEEx template parsing)
- Graph persisted as bincode to =.spell/graph/=. Auto-rebuilds on first graph query when stale.
- Concurrency: =Arc<CodeGraph>= snapshot model via =arc-swap= — readers see immutable snapshot, writer rebuilds and atomically swaps.
- New commands on =code= tool: =index=, =status=, =context=, =impact=, =deps=, =flow=, =dead_code=, =clusters=, =search=. File-scoped commands still route to Emacs; graph commands route to NAPI bridge.

** Key Decisions
1. New crate =crates/pi-code-graph= (pure Rust lib). pi-natives depends on it for NAPI.
2. =petgraph::stable_graph::StableGraph<GraphNode, EdgeKind, Directed>= as core data structure.
3. =oxc_resolver= for TS/JS import resolution. Custom resolver for Elixir (CamelCase module → snake_case path).
4. Bincode persistence + git HEAD staleness detection.
5. BM25 in-memory search index (transient, rebuilt after cache load).
6. Agent-optimized output format: compact text with depth grouping and "Next:" hints.

** Prior Art
Studied GitNexus (26k★, PolyForm NC — can't use), Axon (Python, no license), Graphify (Python, MIT, LLM-dependent), code-graph-cli (5★, MIT, good reference architecture). All converge on tree-sitter → petgraph/graph-DB → typed edges → BFS queries.
