* Context

Anthropic API occasionally sends a second ~message_start~ SSE event before the previous message's ~message_stop~. The SDK throws ~AnthropicError("Unexpected event order, ...")~ which our retry loop in ~streamAnthropic~ does not recognize as retryable. The stream is corrupted and the partial response unusable — the same situation as truncated JSON parse errors, which we already retry.

Approach: add ~unexpected event order~ to the ~isTransientStreamParseError~ regex in ~packages/ai/src/providers/anthropic.ts~. This is the minimal, correct fix — it classifies the error the same way as other corrupted-stream conditions, enabling retry with clean state reset even after content has started streaming.
