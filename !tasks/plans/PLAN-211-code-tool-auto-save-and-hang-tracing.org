bro save should be automatic, and trace any reason why using the code tool might make spell hang after result

* Context
The code tool (=packages/coding-agent/src/tools/code.ts=) wraps a native tree-sitter engine via NAPI bindings. Mutating operations (=edit=, =undo=, =redo=) modify an in-memory buffer but do not persist to disk — requiring the agent to issue a separate =code save= call. This wastes tool calls and risks data loss.

Additionally, the code tool can hang during execution with no diagnostic output. The sync NAPI call =executeCodeBuffer= blocks the event loop, and the async =executeCodeGraph= runs on a worker thread. Both lack timing instrumentation.

** Approach
1. Add auto-save to =CodeTool.execute()=: after successful =edit=, =undo=, =redo=, automatically call =executeCodeBuffer({ command: "save", file })=. On save failure, return the entire call as an error.
2. Update the system prompt (=code.md=) to reflect auto-save behavior.
3. Add =performance.now()= timing around all native calls, logging via =logger.debug= and warning at >2s.

** Key Decisions
- Auto-save triggers on: =edit=, =undo=, =redo= (not =read=, =outline=, =navigate=, etc.)
- Save failure = entire tool call error (agent sees error, in-memory edit persists)
- Save success = transparent (original result returned unchanged)
- System prompt updated to remove manual save instructions
- Timing is diagnostic only — no behavioral changes
- =save= command remains available for manual use
