* Initial Message

is there a way for me to see what agents are doing beyond the one-line sumary in the task box in the TUI?

* Context
** Problem
The TUI shows a one-line summary per subagent in the task tool box. ~Ctrl+O~ expands tool output inline but doesn't give a full view of what a specific agent is doing. Users have no way to drill into a running agent and see its full chat (assistant text, tool calls with rendered output, thinking blocks) in real-time.

** Approach: High-fidelity modal viewer
Build a modal overlay (opened via ~Ctrl+Tab~) that renders a running subagent's full activity using the existing stateless rendering components (~AssistantMessageComponent~, ~ToolExecutionComponent~, ~ReadToolGroupComponent~). These components are already decoupled from ~InteractiveModeContext~ -- they only need a ~Container~ to live in, a ~TUI~ reference, and a ~cwd~.

** Key architectural decisions
1. *Stripped event controller, not reused EventController.* The main ~EventController~ handles 18 event types and calls 30+ methods on ~InteractiveModeContext~. The viewer only needs 6 rendering-relevant event types (~message_start/update/end~, ~tool_execution_start/update/end~). A new ~SubagentViewerEventHandler~ class (~150 lines) handles just these, operating against a 4-field ~SubagentViewerContext~ interface instead of the 50+ field ~InteractiveModeContext~.

2. *EventBus subscription, not session access.* The viewer subscribes to ~TASK_SUBAGENT_EVENT_CHANNEL~ (raw ~AgentEvent~ objects forwarded at P1 priority) and ~TASK_SUBAGENT_PROGRESS_CHANNEL~ (coalesced progress snapshots). It filters by agent index. No direct access to subagent ~AgentSession~ instances needed.

3. *Line-based scroll viewport.* pi-tui has no ~ScrollView~ primitive. Follow the ~DebugLogViewerComponent~ pattern: render all children to lines, track a ~#scrollOffset~ integer, slice the visible window. Auto-follow mode tracks the bottom unless user scrolls up.

4. *Modal via showSelector().* Uses the existing ~showSelector()~ factory pattern (same as model selector, agent dashboard, history search). Swaps ~editorContainer~ children, routes keyboard input, restores editor on close.

5. *Tool definition unavailable.* ~ToolExecutionComponent~ accepts ~AgentTool | undefined~. Subagent tools aren't accessible from the parent session, so pass ~undefined~. Renderers fall back to generic rendering -- still shows args, results, and status correctly for all 25+ built-in tools since rendering is driven by ~renderers.ts~ (keyed by tool name string, not ~AgentTool~).

** Terminal key capture note
~Ctrl+Tab~ requires the Kitty keyboard protocol or CSI u mode. Ghostty 1.3.0 supports this. Most modern terminals (Kitty, WezTerm, Ghostty, foot) do. Older terminals (plain xterm, macOS Terminal.app) may not capture it. The keybinding is user-configurable via ~keybindings.json~, so users on older terminals can remap.
