* Initial Message

the /move command should also move where tools liek the Org tool save their files

* Context

The ~/move~ command relocates a session to a new working directory. It correctly updates ~sessionManager.cwd~, the global ~setProjectDir()~, session header, session files on disk, and slash commands. However, tools continue operating against the old directory because:

1. ~toolSession.cwd~ is a static string set once at construction in ~createAgentSession()~ (sdk.ts line 986). No code ever mutates this property after ~/move~.
2. Some tools (OrgTool, SendFileTool, WriteTool) capture ~session.cwd~ at construction and pass it into internal state that never updates.

The fix is two-layered:
- **Layer 1**: Make ~toolSession.cwd~ a getter backed by ~sessionManager.getCwd()~. This auto-fixes the ~20+ tools that read ~this.session.cwd~ at runtime.
- **Layer 2**: Fix tools that cache cwd at construction time — OrgTool (recreates inner tool), SendFileTool (removes cached field), WriteTool (recreates LSP writethrough).

** Key Decisions
1. ~toolSession.cwd~ becomes a getter, not mutated — a getter on an object literal satisfies ~cwd: string~ in TypeScript
2. OrgTool lazily recreates its inner tool on execute when cwd changes — reuses existing EmacsSessionManager (Emacs daemon is project-agnostic for org)
3. No changes to ~AgentTool~ interface — each tool self-manages via lazy cwd comparison
4. CodeTool needs no change — ~createCodeTool(_projectRoot)~ ignores projectRoot (underscore prefix)
5. LoopManager/orchestrators deferred to followup — lower impact
