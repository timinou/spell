* Context

The Phoenix Inspector QML (=.spell/extensions/phoenix-inspector/inspector.qml=) can be launched two ways:
1. *Extension runtime*: via =/inspect= command or =open_phoenix_inspector= tool -- the extension's TypeScript event loop in =index.ts= handles bridge messages directly.
2. *Canvas tool*: via the =canvas= tool's =launch= action -- the canvas infrastructure routes bridge messages through EventBus channels to SDK subscribers.

Both paths use the same QML file and the same =bridge.send()= protocol with =_tier= and =_tool= fields. The canvas path has a =maybeAugmentPhoenixInspectorLaunchProps= function that auto-detects the inspector QML and injects the needed props (=taskTierSupported=, =quickFixSystemPrompt=, =quickFixOutputSchema=, =tidewaveMcpUrl=).

The canvas path correctly handles:
- Armed tool invocations (=_tool: "read"=) via =CANVAS_TOOL_INVOKE_CHANNEL=
- Task-tier dispatch (=_tier: "task"=) via =CANVAS_TASK_CHANNEL= + =CanvasTaskManager=

But it fails on agent handoff (=_tier: "agent"=) because the reply payloads don't match the QML's expected protocol.

** Analysis: Every Button

| Button | Works? | Notes |
|--------|--------|-------|
| Back/Forward/Reload/Go | Yes | Pure WebEngine navigation |
| Pick element / Pick again | Yes | JS injection, no bridge |
| Resolve | Yes | Armed =read= tool via =CANVAS_TOOL_INVOKE_CHANNEL=; Tidewave via browser XHR |
| Send to agent | NO | Reply missing =action: "agent_handoff_result"= -- QML drops it silently |
| Quick Fix | Yes | =CANVAS_TASK_CHANNEL= + =CanvasTaskManager= sends =action: "task_result"= correctly |
| Refresh selection | Yes | JS injection, no bridge |
| Include screenshot | Yes | Local QML toggle |

** Root Cause

The =CANVAS_AGENT_CHANNEL= subscriber in =packages/coding-agent/src/sdk.ts= sends:
#+begin_src typescript
payload.reply?.({ ok: true, status: "submitted", message: "..." });
#+end_src

The QML expects =payload.action === "agent_handoff_result"= to match the reply. Without it, the reply is silently dropped and the UI stays stuck at "Sending selection to the agent..." forever.

The extension path uses =buildAgentHandoffReply(wasIdle)= which includes the =action= field. The canvas path omits it.

** Approach

Single-file fix in =sdk.ts=: add =action: "agent_handoff_result"= and proper =ok= field to all three reply sites in the =CANVAS_AGENT_CHANNEL= subscriber (success, no-session error, catch error).
