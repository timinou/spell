** Architecture
#+begin_example
Telegram <-> grammy Bot <-> Bridge Layer <-> Bun.spawn("spell --mode rpc") <-> Spell Agent
#+end_example

The bridge spawns =spell --mode rpc --tools <list> --resume <session-path>= child processes, one per authorized Telegram chat. It translates Telegram messages to RPC =prompt= commands and streams RPC events back as Telegram messages using =sendMessageDraft= (Bot API 9.5) for real-time streaming.

** Key Decisions
- *Language*: TypeScript + grammy (mature framework, shared types with Spell, Bun runtime)
- *Process model*: 2-3 concurrent sessions max. Spawn on demand, idle timeout (default 1hr, configurable, null for owner = never)
- *Tool access*: Tiered via Spell mode files. Read-only default (=telegram-readonly= mode), /unlock for full access (=telegram-full= mode). Tool list passed via =--tools= CLI flag at spawn time.
- *Auth*: Chat ID whitelist for auto-auth (owner). Temp tokens with QR deep links for guests. Per-user config with mode lists + project whitelist.
- *Config*: =~/.spell/telegram.yaml= for bridge config. =.spell/modes/*.md= for tool access tiers (reuses Spell's existing mode system).
- *Streaming*: =sendMessageDraft= for ephemeral tool status + response streaming. Finalize with =sendMessage= in HTML parse_mode. Throttle drafts to 3/sec max.
- *Response format*: Telegram HTML mode. Markdown-to-HTML converter. Messages >4096 chars split at paragraph boundaries.
- *Thinking*: 1-line summary by default. /think command to toggle full thinking visibility.
- *Session persistence*: Via Spell's existing SessionManager (=--resume= flag). Bridge maintains =~/.spell/telegram-state.json= mapping chat IDs to session paths.
- *File handling*: Text + images + documents. Uploads go to configurable dir (default =/tmp/telegram-uploads=).
- *Log viewer*: =Bun.serve()= on configurable port. Renders session transcripts as HTML.
- *Commands*: /start /help /unlock /lock /project /mode /think /clear /status /invite /btw

** Gaps Addressed
- grammy may not have sendMessageDraft types yet (Bot API 9.5, March 2026): use =ctx.api.raw.sendMessageDraft= or direct fetch fallback
- Draft text is plain text (not HTML): stream plain text in draft, convert to HTML only for final =sendMessage=
- YAML config parsing: use a yaml parser (=yaml= npm package) since =Bun.JSON5= doesn't parse YAML
- No RPC command for mode/tool switching at runtime: not needed -- bridge kills process and respawns with new =--tools= flag on /unlock, /lock, /mode, /project changes
