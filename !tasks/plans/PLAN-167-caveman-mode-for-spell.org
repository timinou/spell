* Context

Implement built-in caveman mode for Spell — token-saving communication that cuts ~75% of output tokens
while keeping full technical accuracy. Inspired by [[https://github.com/JuliusBrussee/caveman][caveman]]
and [[https://github.com/jonjonrankin/pi-caveman][pi-caveman]].

** Key Decisions

1. *Two-part architecture*: prompt injection in =buildSystemPrompt= (covers main + subagents) + inline extension (=/caveman= command, fire status, config dialog)
2. *Config in spell.kdl* via =SETTINGS_SCHEMA=: =caveman.defaultLevel=, =caveman.showStatus=, =caveman.thinkingMode=, =caveman.affectSubagents=
3. *PhD-caveman thinking notation*: a formal reasoning DSL using math/logic symbols (→ ∧ ∨ ¬ ∀ ∃), structural markers (Q: A: Alt: Risk: ∴), and domain abbreviations. Binary mode: caveman or normal. Independent from output level.
4. *Runtime toggle*: =/caveman [level]= uses =settings.override()= (in-memory). Config dialog uses =settings.set()= (persists to kdl). Session entries for resume.
5. *Subagents affected by default*: =caveman.affectSubagents= (default true) controls it. =createSubagentSettings= snapshots all settings including overrides, so mid-session toggles propagate.
6. *7 output levels*: off, lite, full, ultra, wenyan-lite, wenyan, wenyan-ultra
7. *Animated fire status bar*: braille chars + 256-color ANSI fire palette, speed varies by level

** Technical Approach

- =system-prompt.ts=: =buildSystemPrompt()= reads caveman settings, renders =caveman.md= template, appends to dynamic prompt blocks
- =caveman.ts=: extension factory wired into =sdk.ts= via =inlineExtensions.push()=
- =caveman.md=: Handlebars template with pre-computed boolean flags
- =settings-schema.ts=: 4 new settings with UI metadata
