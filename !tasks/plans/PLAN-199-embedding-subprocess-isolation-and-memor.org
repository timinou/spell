* Context
Bun v1.3.10 segfaults (~Segmentation fault at address 0x983E7000~) during normal interactive sessions. Root cause: =fastembed= (ONNX Runtime v2.0.0-rc.11) runs inside the Bun process via NAPI, and the ONNX Runtime's thread pool, memory-mapped I/O, and SIMD operations conflict with Bun's internals. The crash manifests after ~17 minutes, with corrupted RSS display (0.02ZB) indicating memory tracking corruption.

Secondary findings: several unbounded memory growth patterns (cursor provider conversation caches, grep context buffers, job manager retention) contribute to memory pressure in long-running sessions.

** Approach
1. Isolate ONNX Runtime in a separate subprocess (=pi-embedding-worker= binary)
2. Replace direct =EmbeddingEngine= usage in =code_graph.rs= with subprocess IPC via stdin/stdout JSONL
3. Update build system to build and distribute the worker binary
4. Fix unbounded memory growth in cursor provider, grep, and job manager

** Key Decisions
- Worker binary is a standalone Rust crate at =crates/pi-embedding-worker/=
- JSONL protocol over stdin/stdout (not TCP, not Unix socket — simplest and most portable)
- Worker stays alive for session duration (reuse across calls)
- Graceful degradation: if worker is unavailable, semantic features disabled, graph/BM25 still work
- Worker binary build is non-fatal (spell works without semantic features if build fails)
- Memory caps: 20 conversation cache entries, 50 context lines per grep match, 100 retained jobs
