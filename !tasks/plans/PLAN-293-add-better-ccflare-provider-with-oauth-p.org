* Context

better-ccflare is an Anthropic-compatible proxy running at localhost:8080. It maintains its own OAuth accounts and routes requests to Anthropic. It has two auth modes:
1. OAuth passthrough: NO client auth → proxy uses its own configured OAuth accounts
2. API key auth: ~x-api-key: btr-~ or ~x-api-key: dummy-key~ → proxy maps to configured accounts

Spell's current Anthropic provider always sends an auth header (~x-api-key~ or ~Authorization: Bearer~). This breaks OAuth passthrough — the proxy receives ~x-api-key: sk-ant-api03-...~ (the user's Anthropic API key with no credits) and either forwards it to Anthropic (fails with "credit balance too low") or rejects it.

The fix: a separate ~better-ccflare~ provider that reuses ALL Anthropic stealth-mode behavior (Claude Code headers, tool prefixing, user-agent spoofing, billing header, cache control) but sends NO auth header when ~ANTHROPIC_AUTH_TOKEN~ is unset (OAuth passthrough mode).

Users configure models as ~better-ccflare/claude-opus-4-7~ in their ~spell.kdl~ role settings. The provider reuses the ~anthropic-messages~ API type — only the auth path differs.
