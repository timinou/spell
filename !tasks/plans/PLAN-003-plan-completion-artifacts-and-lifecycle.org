* Context

** Problem

Spell's plan lifecycle has a broken feedback loop. Plans transition INIT → DOING on approval via =approvePlanItem()=, but there is no mechanism — prompt-level or programmatic — to transition DOING → DONE. The dashboard shows 71 plans stuck in DOING and only 5 that reached DONE (93% abandonment rate). The =plan-mode-approved.md= prompt says "keep going until complete" but defines "complete" only as "all steps executed," with no definition of done (DoD) covering:

- Verification evidence (screenshots, test results)
- Org lifecycle closure (DOING → DONE)
- Child item resolution (ITEM/DOING → DONE)

Additionally, the browser tool declares a =path= parameter for screenshots in its Typebox schema and prompt documentation, but the implementation ignores it — all screenshots go to =/tmp/= where they're ephemeral and useless as persistent artifacts.

** Approach

Three coordinated changes, each at a different layer:

1. *Infrastructure fix*: Make the browser tool's =path= param work so screenshots can be saved to persistent, meaningful locations.

2. *Prompt engineering*: Add a structured Completion Protocol to =plan-mode-approved.md= that defines the agent's DoD: capture verification artifacts, write a completion report to the org item, close child items, close the plan. Also enrich =plan-mode-active.md= so plans include verification criteria for the executor.

3. *Code helper*: Add =completePlanItem()= to =org-plan.ts= as the symmetric counterpart to =approvePlanItem()=. This enables a future session-end safety net (auto-close orphaned DOING plans when session exits).

** Key Decisions

- *Prompt-first, not tool-first*: The primary fix is prompt instructions, not a new tool. The agent already has access to =org update= and =browser screenshot=. The problem is that it was never told to use them at completion time.
- *Screenshot storage convention*: =plan-artifacts/{plan-id}/= as a subfolder in the same directory as the plan's org file (e.g., =!tasks/plans/plan-artifacts/PLAN-003-foo/=). Co-located with plans, persistent, gitignore-able.
- *Completion report format*: Appended to the org item body as a =** Completion [DATE]= heading with verification, artifacts, and deviations subsections. This keeps the audit trail in the org item itself.
- *Child item handling*: Active/ITEM children are auto-closed. BLOCKED children are left untouched (they need human attention). Already-DONE children are skipped.
- *Conditional on org*: Everything is gated on =orgItemId= being set. File-backed plans (org disabled) are unaffected.
