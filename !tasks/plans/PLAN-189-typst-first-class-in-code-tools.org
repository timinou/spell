* Initial Message

Look at the way we use typst in ~/code, especially the branding and the way we built our last .typ files in BackDesk-C, and make typst first-class in the code tools. make it genuinely useful to make excellent typst documents with ease

* Context

Typst is used across multiple projects for professional documents — pitch decks, technical reports, client proposals, research reports, and brand-compliant deliverables. The Spell coding agent currently has no first-class Typst support: the code tool cannot outline .typ files, the LSP has no tinymist integration, and no skill teaches Typst authoring.

This plan adds Typst as a fully supported language at three levels:
1. *Code intelligence* — Rust pi-code-engine language profile enabling outline, navigate, read, and edit operations on .typ files
2. *Language server* — Tinymist LSP integration for diagnostics, hover, go-to-definition, references, and formatting
3. *Domain knowledge* — A comprehensive authoring skill teaching Typst fundamentals, brand library patterns, template authoring, and compilation workflow

** Key decisions
- Typst profile goes into the Rust pi-code-engine only (Emacs code layer is being deprecated)
- Uses =codebook-tree-sitter-typst= crate (v0.12.1, published on crates.io) for tree-sitter grammar
- Declaration patterns: =let= (functions/variables), =import= (modules), =show= (styling rules)
- Tinymist LSP with =typstyle= formatter
- Skill covers general Typst fluency + brand library awareness pattern + compilation workflow
- Compilation via existing =bash= tool (=typst compile=) + =send_file= — no dedicated tool needed

** Existing infrastructure
- tree-sitter-typst grammar already installed in Emacs daemon (but not used for outline)
- =typst= binary v0.14.2 at =/usr/bin/typst=
- =tinymist= binary at =/usr/bin/tinymist=
- Brand library at =domain/growth/branding/spell-brand/= (colors, typography, components, layout)
- Templates at =domain/growth/templates/= (campaign-brief, client-proposal, competitive-analysis, weekly-digest)
