* Initial Message

how do I start SPell Growth?

* Context

** Problem

Domain detection/loader code exists but is not connected to runtime startup, so growth domain resolution cannot affect session behavior. As a result, Spell Growth cannot be started end-to-end via project domain config.

Source follow-up: [[id:FUP-014-wire-domain-detection-and-loader-into-se]].

** Approach

Implement in three non-overlapping child items:
1. Startup/bootstrap wiring and domain override flag.
2. SDK-level domain policy (prompt/context/tools).
3. Always-canvas launch behavior and shell payload routing.

This preserves clean boundaries: resolution first, policy second, UI launch third.

** Key Decisions

- Startup auto-canvas applies only to interactive sessions; =-p= and =--mode json|rpc= behavior remains unchanged.
- Add explicit CLI override: =--domain <name>=.
- Error policy: fail fast with explicit errors for invalid domain config or manifest load failures.
- Prompt precedence: merge domain prompt first, then CLI/custom prompt additions.
- Tool filtering precedence: explicit =--tools= may bypass domain exclusions.
- Completion bar: run =bun check:ts= plus full =packages/coding-agent/test/= regression.
