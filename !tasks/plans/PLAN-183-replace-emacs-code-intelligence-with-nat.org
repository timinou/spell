* Context

The =code= tool currently delegates all file-local code intelligence (read, outline, navigate, edit, diff) to an Emacs 29+ daemon running tree-sitter + combobulate, communicating via JSON-RPC over socat. This requires:
- Emacs 29+ with =--with-tree-sitter= build flag
- =socat= binary for JSON-RPC transport
- Tree-sitter grammar compilation on first run (~60s startup delay)
- A long-lived daemon process with circuit-breaker lifecycle management

The new Rust crate =pi-code-engine= provides a complete native replacement:
- Tree-sitter grammars for TypeScript, Rust, Python, Elixir compiled into the binary
- Rope-based buffer management with undo/redo history
- All file-local operations: outline, resolution-aware read, navigate (node-at, defun-at, parent, siblings, children, references), structural edits (replace, insert, kill, splice, drag, clone, transpose), diff, save
- NAPI binding =executeCodeBuffer= already exists in =pi-natives=

The org tool runs a separate Emacs daemon for org-mode operations — it is unaffected by this migration.

** Key Decisions

1. *Thin sync wrapper*: Direct NAPI call from CodeTool, no worker thread. Typical parse is <10ms.
2. *Auto-open buffers*: NAPI layer auto-opens on first access via =get_or_open= semantics. Agent never calls open/close.
3. *No Emacs fallback*: Unsupported languages return error. Agent uses =read= tool for non-TS/Rust/Python/Elixir files.
4. *Remove code warmup*: No =emacsSessionManager=, no =warmupCode=, no daemon lifecycle for code tool. Native engine is instant.
5. *Clean pi-emacs*: Delete code-intel exports (client.ts, types.ts, createCodeTool, warmupCode). Keep daemon/detection/session-manager for org.
6. *Rename =references-local= to =references=*: Update system prompt and CodeTool wrapper.
7. *Drop =install_grammar=*: Grammars are compiled in. Keep read-only =languages= command listing built-in profiles.
8. *Buffer lifecycle*: Native BufferRegistry persists buffers across calls. Agent sees =buffers=, =diff=, =undo=, =redo=, =save=.
