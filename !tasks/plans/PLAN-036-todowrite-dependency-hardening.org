* Context
The TodoWrite tool has a =blockers= dependency system that works mechanically (correct rendering, correct auto-promotion skip) but has critical gaps:

1. *No enforcement*: The =update= op sets =task.status= directly with zero validation. An agent can mark a blocked task =in_progress= -- no error, no warning.
2. *Weak prompt guidance*: =blockers= gets one line in Task Anatomy, one example, and a confusingly-worded rule ("On blockers") that's actually about runtime impediments, not dependency-graph blockers.
3. *Poor blocked visibility*: The summary header doesn't show blocked count. No deadlock warning when all tasks are blocked.
4. *Org integration gap*: Plan-mode creates org items with narrative "depends on FEAT-XXX" text but zero =:BLOCKER:= properties. The org-depend parser and manifest-reader fully support BLOCKER/TRIGGER extraction, but the properties are never set.

*Investigation findings* (2026-03-30 djinn sessions):
- 9 sessions today, 7 with todo_write calls. 4/7 used blockers (complex multi-wave plans), 3/7 didn't (simple linear workflows).
- When blockers ARE used, adherence is correct -- agent completes tasks in dependency order.
- =isTaskBlocked()= correctly evaluates resolution. =normalizeInProgressTask()= correctly skips blocked tasks.
- =[blocked]= label and =⛔= symbol render correctly in both model text and TUI.
- Zero =:BLOCKER:= properties on any org item in =~/code/ora/hotelcomm/ecosystem/djinn/!tasks/=.

*Approach*: Four items -- smart gate enforcement (BUG), summary visibility (FEAT), prompt enhancement (FEAT), plan-mode wiring (FEAT). TDD throughout: tests before implementation. Items 1+3 ship together (enforcement without guidance = confusing rejections).

*Key design decisions*:
- Smart gate: reject =in_progress=, allow =completed=/=abandoned= (legitimate out-of-order work)
- Extract =hasUnresolvedBlockers()= from =isTaskBlocked()= (Metis GAP-1: isTaskBlocked guards on status=pending, can't be reused for gate)
- Post-ops blocker demotion pass in =normalizeInProgressTask= covers =replace=/=add_phase= ops uniformly (Daedalus MUST_FIX)
- Dangling blocker ref validation as single post-all-ops pass, not per-op (Daedalus MUST_FIX)
- Rewrite "On blockers" rule to "On runtime impediments" (Metis GAP-3: disambiguate two meanings)
- Deadlock warning when all pending tasks blocked (Metis GAP-2)
- Plan-mode parallel creation ordering constraint (Metis GAP-4: can't set BLOCKER before target exists)
