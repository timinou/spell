* Context

The org tool's ~update~ command supports full ~body~ replacement and ~append~, but nothing for surgically updating a specific section/heading within a body. Plan mode overuses ~note~ (append-only with date prefix) for revisions, causing contradictory information to accumulate in plan items.

** Problem
When a plan evolves during planning, the agent either:
1. Uses ~note~ — appends contradictions without removing stale content
2. Uses ~body~ — overwrites the entire body, losing sections that didn't change

Neither option is right for partial updates to structured bodies containing org headings like ~* Context~, ~* Verification~, ~* Execution Manifest~.

** Approach: Emacs-native section editing
Add a ~section~ parameter to the existing ~update~ command. When ~section~ is set, the operation routes through Emacs RPC to leverage org-element's AST for robust heading navigation and manipulation.

Emacs org-element provides:
- ~org-find-property~ to locate items by CUSTOM_ID
- ~org-element-map subtree 'headline~ to iterate child headings
- ~:raw-value~ for heading title matching (excludes TODO keyword and tags)
- ~:contents-begin~ / ~:contents-end~ for precise region bounds
- ~org-end-of-meta-data~ to skip property drawers

This is more robust than line-based TS parsing because org-element handles edge cases (folded headings, inline formatting, etc.) natively.

** Key decisions
- ~section~ matches heading titles via ~:raw-value~ (case-sensitive, first-match for duplicates)
- Heading level is irrelevant for matching
- Section not found returns an error, does not modify the file
- Creating new sections uses regular ~append~ with heading markup (not ~section~)
- When ~section~ is not set, existing TS mutation path is unchanged
- ~note~ command untouched — still useful for timestamped observations
