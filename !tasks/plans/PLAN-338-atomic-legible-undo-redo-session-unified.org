* B — session-unified log
Kernel: log at <sessionDir>/edit-history.jsonl (was workspace_root_for(file)/.spell/…).
  Entries gain `workspace` field. history_for("") resolves the session log
  directly (no cwd probe). HistoryQuery gains entry_id: Option<String> for
  id-precise undo/redo. NO migration fold-in (fresh start).
Agent (in-chat): status{command:"history"} → ordered newest-first
  { entries:[{id,file,workspace,group_id,kind,reverted,committed,commit?,agent_label,ts}],
    total, undoable, redoable }; file filter supported.
  edit undo/redo op gains `id?` (target a specific entry/group) + `force?`.
  Result payload gains scope:"file"|"group"|"session", remaining:N.
TUI: history palette (list from status:history; select + `u` → id-precise undo).
Team Chat: multi-file undo = one collapsed CodemodTilePanel tile (expands to
  per-file diffs) + agent_label row ("undoing Alice's rename").

* C — commit-awareness
Kernel: before revert, reconcile vs git HEAD (clean-at-HEAD OR entry.commit set
  ⇒ committed). New RevertOutcome::Declined{ entries:[{entry_id,file,commit}] },
  returned by default when any targeted entry committed; nothing written.
  force:true bypasses. Stamp `commit` (git rev-parse HEAD) at record time as
  fallback. git absent ⇒ fail-open (treat as uncommitted, never block).
Agent (in-chat): declined → structured actionable result ("undo declined: app.ts
  committed at a1b2c3d. re-run {force:true} or git revert a1b2c3d").
TUI: amber warning cell + interactive confirm "committed. Revert anyway? [y/N]".
Team Chat: force-undo of committed file → visible channel system notice
  ("⚠ Bob force-reverted app.ts (was committed a1b2c3d)"); non-forced declines local.
