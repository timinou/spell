* Initial Message

when a subtask is associated to a todo (especially relelvant during plan/ultraplan/loop implementations), can you have a soft reminder when the task gets done to make sure to check its validation criteria, tests, artifacts (if any) and to commit ahead of marking the task as done?

* Context
** Problem
When the coding-agent works through plan/ultraplan/loop implementations, each todo task may have gate fields (gateCmd, gateArtifact, gateCommit, gateLlm) and be linked to an org item. Currently:
1. Gate directives fire *after* a task is marked completed — the agent can ignore them and move on
2. Subagents spawned via the task tool have no awareness of the verification requirements; they only know what the parent manually includes in their assignment
3. There is no mechanism linking a todo task back to its source org item, so the agent relies on the end-of-plan orchestrator protocol to update org state, which is fragile

** Approach
Three connected changes:

*** 1. =orgItemId= field on =TodoItem= + two-phase gated completion
Add =orgItemId?: string= to link todos to their source org item. Add =verified?: boolean= to the update op. When a gated task is marked =completed= without =verified: true=, the status change is *rejected* and a verification checklist is returned. The agent must verify, then re-submit with =verified: true=. This creates a deliberate friction point.

"Required gates" that trigger two-phase: =gateCommit=, =gateArtifact=, =gateCmd=, =gateLlm=, =orgItemId=.
=verifyCmd= alone does NOT trigger two-phase (it's a recommendation, not a requirement).

*** 2. Task-level gate injection via =todoRef=
Add =todoRef?: string= to =TaskItem=. When the task tool spawns a subagent, it resolves =todoRef= against the current todo phases, extracts the todo's gates and =orgItemId=, and injects a "Verification Requirements" section into the subagent's context. The subagent inherently knows: which org item to update, which tests to run, which artifacts to produce, whether to commit.

*** 3. Prompt documentation
Update =todo-write.md=, =plan-mode-approved.md=, and =task.md= to document the new fields and the two-phase protocol.

** Key Decisions
- Directive-only approach for org updates: the tool surfaces what needs updating, the agent handles org calls (not automated side-effects)
- Two-phase completion is the mechanism: first attempt → rejection + checklist; second attempt with =verified: true= → completes
- =hasRequiredGate()= is a new function separate from =hasGate()= to distinguish required gates (that trigger two-phase) from advisory ones (=verifyCmd=)
- Subagents still don't get =todo_write= access; they get the verification context injected into their prompt and use =org= tool directly for org updates
- Resolution helper =resolveVerificationContext(todoRef, phases)= is a pure function testable independently of subprocess spawning
