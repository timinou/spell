* Context

The code tool froze a session when called on a =.md= file. The chain:
1. Native engine returned =LanguageNotFound= error → NAPI threw JS exception → TypeScript caught it → returned error to agent
2. Anthropic SSE stream silently dropped while waiting for the model's response → no idle timeout → permanent hang

The SSE idle timeout fix (=9106faa9a=) addresses the transport-level hang. Two structural issues remain:

** Issue 1: NAPI exception propagation
=execute_code_buffer= has ~30 error sites that throw JS exceptions via =engine_err= / =json_err= + =?=. The TypeScript side has two error paths: structured (=result.error= check → full context) and fallback (=catch= block → just the message). All operational errors route through the inferior fallback path.

** Issue 2: No early rejection of unsupported files
The code tool passes any file to NAPI without checking language support. Unsupported files predictably fail, but the error message gives no guidance. The model retries or stalls instead of falling back to the =read= tool.

** Approach
1. Wrap =execute_code_buffer= Rust NAPI function so ALL errors become =\{ output, error: true \}= JSON envelopes — never NAPI throws. Single wrapper function, zero changes to internal =?= operators.
2. Add TypeScript-level =SUPPORTED_EXTENSIONS= check before calling NAPI. Returns a helpful error: "Unsupported file type .md. Use the read tool for non-code files."

** Key Decisions
- Rust wrapper: =execute_code_buffer= calls =execute_code_buffer_inner= + catches =Err= into =json_response(error, true)=
- TypeScript guard applies to file-requiring commands only (outline, read, navigate, edit, undo, redo, diff, save, open, close)
- Extensionless files pass through to NAPI (e.g. =Makefile=)
- =SUPPORTED_EXTENSIONS=: ts, tsx, js, jsx, mjs, cjs, mts, cts, rs, py, pyi, typ, ex, exs
- The TypeScript =catch= block remains as safety net for truly unexpected errors
- No prompt changes needed
