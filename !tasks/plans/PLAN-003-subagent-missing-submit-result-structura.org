* Context

Subagents that complete work but fail to call ~submit_result~ are incorrectly handled. The old code forced ~aborted = true~ (too harsh — penalized good work). The current fix (BUG-001-subagent-status-shows-aborted-when-submi, DONE) removed that coercion, but now schema-less agents silently show green "done" status with no warning. Both are wrong.

The structural fix addresses three orthogonal issues:
1. *Warning propagation*: ~finalizeSubprocessOutput~ must always prepend the warning marker for missing submit_result, even for schema-less agents. The render layer already handles this marker with a yellow warning icon — the marker just isn't being set.
2. *Retry effectiveness*: The 3-retry loop forces tool choice on every attempt. Models that can't handle forced tool choice fail all 3 the same way. Last retry should drop tool choice and use a plain prompt.
3. *Content-aware status*: After all retries fail, use ~progress.toolCount~ to distinguish "did work, forgot protocol" (completed with warning) from "never engaged" (failed).

Key decisions:
- Keep existing 3-retry count (MAX_SUBMIT_RESULT_RETRIES = 3)
- Don't add a new status enum value — use the existing warning path in render.ts that already exists but was never triggered for schema-less agents
- The yellow "warning" badge from render.ts line 744 is the correct visual treatment — it already has the right color and icon
