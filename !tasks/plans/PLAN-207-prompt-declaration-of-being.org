* Context
The current prompt stack is internally inconsistent: some artifacts read like embodied faculties, others read like manuals, stubs, enforcement dumps, or stale examples from an older tool era. The user wants the base skills, the tools, and everything sent to the LLM to become a declaration of being.

Recommended approach: do a full prompt-stack cutover, not selective polish. Start by defining a canonical contract and truthful inventory, then normalize prompt topology so every model-facing artifact has one canonical home, then rewrite tool descriptions, system overlays, agent prompts, and base skills against that contract, and finally lock the change in with topology/semantic regression tests.

Key decisions settled for this plan:
1. Scope is the full prompt stack: system prompt templates, overlays, agent prompts, tool descriptions, inline tool strings, loop tool prompts, and base skills.
2. Acceptance is full cutover: every in-scope artifact must adopt the terse declaration-of-being style; no mixed old/new voice.
3. Canonical tool-doc voice matches the `system-prompts` skill template: one-line capability, then tagged sections only, with no positioning prose between the opening line and the first tag.
4. Prompt content must teach the current tool hierarchy: `code` for source files, `ast_grep`/`ast_edit` for structural code work, `lsp` for semantic questions, `read`/`edit` as fallback where appropriate.
5. Structural cleanup is part of the same initiative: misplaced, deprecated, orphaned, or duplicated prompt assets must be normalized or removed, not left reachable.
6. Stable/dynamic prompt splitting remains an architectural invariant and must survive the rewrite (`memory://root/memory_summary.md`; `packages/coding-agent/src/system-prompt.ts`).

Discovered repo patterns to preserve:
- Prompt rendering flows through `renderPromptTemplate()` and `formatPromptContent()`.
- Specialized tool descriptions are compacted to the first sentence via `compactToolDescription()`.
- Strong in-repo exemplars already exist for tool prompts (`code.md`, `ast-grep.md`, `ast-edit.md`, `code-search.md`, `find.md`, `ask.md`) and agent prompts (`explore.md`, `oracle.md`, `librarian.md`, `reviewer.md`, `designer.md`, `metis.md`, `momus.md`, `daedalus.md`).
- Existing tests validate compileability and semantic anchors, not giant snapshots.
