  - `VERIFICATION_COMMAND_PATTERN` classifies `mix|bun|cargo|npm|pnpm|yarn` + `test|check|lint|fmt|build|precommit` as the bash verification category.
  - Verification currently uses `presentation: "summary-first"` and `persistence: "summary-only"`.

  - `BashTool.execute()` already computes the truthful raw bash result text and truncation metadata.

- `packages/coding-agent/src/tools/context-pressure-policy.ts`, `packages/coding-agent/src/session/messages.ts`, and `packages/coding-agent/src/memories/index.ts`
  - The repo already has separate downstream paths for compact persistence and pruned-message reinjection (`createMemorySafeToolResult()` and `getPrunedToolResultContent()`), so visible-result replacement is not required to keep memory compact.
- `packages/coding-agent/test/tools/bash-churn-policy.test.ts`
  - Current regression coverage codifies the wrong visible behavior by asserting that verification commands render the synthetic summary instead of raw output.

** Settled decisions
1. Scope = all verification/build commands matched by the current bash verification classifier; no one-off `mix test` special case.
2. Visible bash tool results must show raw stdout/stderr inline for verification commands.
3. Compact persistence still matters, but it belongs in memory/pruned-history handling rather than immediate user-visible result replacement.
4. Keep the existing classifier and metadata surface; do not delete context-pressure plumbing.
5. Do not widen raw output for wait/poll churn, git-inspection churn, or transcript/log spelunking.
6. Preserve current spill/truncation/artifact behavior; the fix is about truthfulness of the visible result, not about changing output-size policy.

** Recommended approach
Implement a category-aware split at the `bash.ts` result boundary:
- verification category → keep raw visible output, still attach context-pressure metadata;
- wait/poll, transcript spelunking, git-inspection (and any truly compact-first categories) → keep existing summary-first visible behavior;
- memory/pruned-history compaction → continue using the existing downstream helpers.

This is the lowest-risk cut:
- ✓ restores truthful operator-visible output;
- ✓ preserves compact persistence;
- ✓ avoids re-architecting the shared policy layer;
- ✓ minimizes blast radius to `bash.ts` + focused tests.
