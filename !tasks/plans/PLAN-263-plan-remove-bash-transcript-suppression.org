* Context
The user reports that transcript-analysis bash calls are summarized as:
- "Ran transcript-spelunking bash command ..."
- "Raw output suppressed."

Requested behavior:
- Remove the explicit "Raw output suppressed" experience for this case.
- Return a bounded raw chunk when the caller already chose chunk controls via bash tool options.
- Keep the result customizable by normal tool-call options instead of forcing a summary-only transcript path.

Verified code reality:
- `packages/coding-agent/src/tools/context-pressure-policy.ts`
  - `classifyBash()` marks transcript-spelunking commands as `presentation: "summary-first"`, `persistence: "deny-raw"`.
  - Current summary sentence is `Ran transcript-spelunking bash command ... Raw output suppressed.`
- `packages/coding-agent/src/tools/bash.ts`
  - `applyHeadTail()` already supports bounded output chunks.
  - `classifyContextPressure()` is currently called with only `{ command: rawCommand }`, so policy cannot see `head`/`tail` intent.
  - Bash replaces final content with the policy summary only when `presentation === "summary-first"`.
- `packages/coding-agent/src/prompts/tools/bash.md`
  - Existing guidance already instructs callers to use `head`/`tail` instead of shell piping.

Settled decisions:
1. Keep default transcript-spelunking behavior compact-first when no explicit chunk options are provided.
2. Treat explicit bash `head` or `tail` as user intent to receive a bounded raw chunk for transcript-spelunking commands.
3. Implement the opt-in at the context-pressure classifier boundary, not by special-casing output formatting later.
4. Preserve existing `applyHeadTail()` semantics; do not invent a second chunking path.
5. `head: 0` and `tail: 0` do not count as chunk opt-in.
6. Update tool guidance so future callers know that transcript/log spelunking can return bounded raw output when `head`/`tail` are set.

Recommended approach:
- Wire `head` and `tail` into `classifyContextPressure()` from `BashTool.execute()`.
- In `classifyBash()`, keep transcript-spelunking summary-first by default, but switch to `presentation: "inline"` + `persistence: "allow-raw"` when explicit non-zero chunk options are present.
- Ensure the chunk-enabled path no longer emits the phrase `Raw output suppressed`.
- Verify both policy-level classification and end-to-end bash tool output.
