* Context

~code edit~ (replace, kill, insert-before, insert-after) fails on Typst files with "No
node found at line X" even when ~code navigate node-at~ finds the node successfully.

Root cause: ~find_ancestor~ in ~edit/replace.rs~ only walks UP the tree. In Typst, every
declaration lives inside a ~code~ wrapper node (~code~ → ~let~). When ~node_at_line~ resolves
byte 0 of a ~#let~ line, it lands on the ~#~ character belonging to ~code~. The ancestor
search walks up from ~code~ and never finds ~let~ which is a child, not an ancestor.

Fix: extend ~find_ancestor~ to also search sole-named-child chains downward when ancestor
walk-up fails. This matches the existing pattern in ~outline.rs::entry_for_node~ and is
language-agnostic.

Key decisions:
1. Rename ~find_ancestor~ → ~find_target~, add ~unwrap_to~ helper using sole-named-child heuristic
2. No Typst-specific logic — the fix handles any grammar with wrapper nodes
3. All four edit operations (replace, insert-before, insert-after, kill) use the same fix
