* Context

The ultraplan workflow's Phase 3 (Propose Decomposition) currently instructs the agent to present only high-level fields per item: title, category, scope summary, dependencies, effort. The detailed "Org Item Body Standard" section — which requires sub-outline steps with ~PARENT-ID::sub-slug~ identifiers, test scenarios, file paths, edge cases — is positioned after Phase 4 (Daedalus validation) and framed as a Phase 5 (org creation) requirement.

This causes a concrete failure mode observed in session ~14a84ccd740b8ade~: the agent presented a shallow decomposition (14 items with one-line scope summaries), the user had to manually request "Give me a more detailed thing so the Daedalus validation makes sense", the agent regenerated the entire breakdown with full sub-outline detail, and only then was Daedalus able to perform meaningful validation.

** Approach
Two coordinated prompt changes:
1. Restructure Phase 3 to require full body-standard detail in the initial proposal — sub-outline steps, dependencies, tests, file paths, edge cases. Move the "Org Item Body Standard" section before Phase 3 so the agent sees the expected format before constructing the proposal.
2. Update Daedalus to expect and validate sub-outline structure — step CUSTOM_ID format, intra-item dependency correctness, wave derivability.

** Key decisions
- The non-ultraplan ~/plan~ workflow is NOT changed. It uses a lighter-weight approach without mandatory Daedalus validation.
- Daedalus remains a validator (read-only), not a decomposer. It validates that the agent produced complete sub-outlines, not generates them itself.
- Large plans may need multi-message presentation. The prompt permits splitting across multiple ~ask~ calls but prohibits reducing detail.
