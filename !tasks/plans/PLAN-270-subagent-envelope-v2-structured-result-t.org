* Context

Nested subagent delegation works end-to-end up to depth=3 (task.maxRecursionDepth=3 landed in P0). Empirical probes confirmed: task -> task -> oracle chain returns verbatim markers in ~18s. The remaining defect is envelope fidelity: grandchild ~submit_result~ payloads collapse into truncated text by the time they reach root. Three fragmented status enums (~AgentProgress.status~, ~AsyncJob.status~, ~SwarmNodeStatus~) plus a composed display string obscure outcome semantics across 40+ match sites.

This plan replaces the flat ~SingleResult[]~ envelope with a structured tree:
- Canonical ~SubagentOutcome~ enum (17 values) supplants 3 fragmented enums.
- ~structuredResult~ preserves ~submit_result~ JSON; ~children~ recursively carries grandchild results.
- ~agent://~ URI on every result; inline JSON under 5KB, URI-only beyond.
- Streaming bubble-up via ~TASK_SUBAGENT_PROGRESS_CHANNEL~ to TUI subscribers (root LLM unchanged).
- ~spawnAudit~ populated always, rendered only on non-trivial outcomes.
- Complete cutover of ~output: string~ to ~textPreview + structuredResult~ (no shims).

Full design spec with ADR rationale: ~specs/subagent-envelope-v2.md~ (committed in this session; authoritative for implementation).

Settled decisions (from interactive planning):
1. Scope: full envelope v2 shift, not minimum viable.
2. Status enum: large unification across all three (40+ sites).
3. Consume model: inline JSON <5KB; agent:// URI always present.
4. Output cutover: complete removal of ~output~ field (21 call-sites migrate).
5. Streaming: Pipeline 2 (TUI) only; Pipeline 1 (LLM) unchanged.
6. Spawn audit: always populated; rendering filters trivial cases.
7. Throttling: trust existing 100ms debounce; revisit if flooded.
8. Decomposition: 6 FEAT items (medium granularity).
9. Tests allowed to touch existing fixtures; PLAN-267 stays deferred.
10. Spec stored at ~specs/subagent-envelope-v2.md~ (cross-session resumability).
