* Initial Message

how would you move all of spell's config to spell.kdl config? What would it look like? Could you import bits inside other bits? would it be better to have blocks per mode?

* Context

Spell configuration is fragmented across 5+ formats and locations (config.yml, models.json, keybindings.json, MODE.md YAML frontmatter, spell.kdl). This plan consolidates everything into KDL as the single config format with two file locations: =~/.spell/spell.kdl= (user-global) and =./spell.kdl= (project-local).

Full specification: =specs/kdl-config-migration.md=

** Key Decisions
1. spell.kdl is the single config format — replaces config.yml, models.json, keybindings.json
2. Two file locations: =~/.spell/spell.kdl= (user) + =./spell.kdl= (project). Project overrides user.
3. File-level imports: =import "./file.kdl"= and =import "spell.coding.typescript"= (built-in). Block-level imports deferred.
4. Settings panel 3-tier writes: Enter=session, Shift+Enter=project, Ctrl+Shift+Enter=user
5. Settings singleton backed by KDL — config.yml deleted entirely
6. Models/providers full migration — TypeBox schemas deleted, KDL-native validation
7. Modes: spell.kdl mode blocks + MODE.md with KDL frontmatter
8. =spell migrate= CLI converts old formats. Hard cut — old files ignored after migration.
9. @bgotink/kdl 0.4.0 round-trip API for format-preserving writes

** Risk Profile
- ~67 files import Settings — API unchanged, only persistence layer changes
- ~23 test files create ModelRegistry — constructor signature changes
- ~10 files use parseFrontmatter — return type unchanged
- KeybindingsManager has 1 create() call site — low risk
- Settings.isolated() / _resetSettingsForTest() unchanged — tests unaffected
