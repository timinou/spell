* Context

The loop orchestration system (PLAN-013) was implemented with 16 subsystems, 56 tests, and full TypeScript/biome clean builds. Post-implementation review identified 7 gaps that prevent production-grade reliability. Gap #1 (settings UI for review model) was confirmed already resolved -- MODEL_ROLE_IDS auto-generates the UI entry.

This plan addresses 7 remaining gaps:
1. Missing vendor dependency (s.el) prevents batch Emacs from loading org-ql predicates
2. Loop navigation elisp functions not registered as MCP tools (unreachable from emacs_code)
3. Loop auto-approve timeout not persisted to settings (lost on session restart)
4. Loop dashboard panel not auto-registered in shell sidebar on loop start
5. No gitAvailable guard -- loop_start in non-git dirs hits silent failures in drift/checkpoint
6. Worktree helpers exist but are never called from loop lifecycle (leak on kill)
7. No context refresh hook between iteration phases (conversation accumulates without compaction)

Key design decisions (per Metis analysis):
- s.el vendoring: low risk, same GPL-3.0+ license as existing vendor packages, no transitive deps
- Context refresh: onBeforePhase callback in PhaseCoordinator, NOT AgentSession.prompt() in orchestration layer (layer violation)
- Worktree: opt-in per loop via useWorktree flag, NOT auto-detect
- Git guard: proceed with git features disabled (warn, don't reject) -- add gitAvailable to LoopSnapshot
- Auto-approve: settings-schema entry as global default, per-gate config overrides

*** Deviations
- FEAT-038 (MCP tool registrations): Used =(when (featurep 'mcp-server-tools) ...)= guard instead of unconditional registration. This ensures loop-navigation.el works both standalone (existing test) and when loaded through the MCP bootstrap. The plan assumed require at top-level, but that would break existing tests that load loop-navigation without the MCP server stack.
- FEAT-036: Settings wiring uses a callback-based HumanGateSettings interface rather than passing the Settings instance directly. This avoids coupling the gate executor to the full Settings class and keeps subagent fallback simple (undefined = use default).
