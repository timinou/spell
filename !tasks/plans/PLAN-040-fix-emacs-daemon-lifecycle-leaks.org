* Context
Emacs sessions are NOT reliably disposed on all exit paths. Two near-identical daemon implementations exist with overlapping bugs. Rather than patching each independently, we build a shared =ManagedDaemon= abstraction and migrate both daemons to it, eliminating duplication and all lifecycle gaps in one pass.

** Problem: 5 bugs across 2 daemon implementations

*** Bug 1: No postmortem registration (main daemon)
=packages/emacs/src/daemon.ts= never calls =postmortem.register()=. SSH cleanup is registered at =sdk.ts:432=; Python at =sdk.ts:440=; Emacs is absent. When signals (SIGTERM from outside, SIGHUP, uncaughtException) hit the process, the Emacs daemon is orphaned.

*** Bug 2: Org tool dispose is a no-op
=packages/org/src/tool.ts:890= nulls promise references but never calls =session.stop()=:
#+begin_src typescript
async dispose() {
    emacsSessionPromise = null;
    orgClientPromise = null;
    // session.stop() never called!
}
#+end_src

*** Bug 3: --daemon fork makes proc.kill() ineffective
Both daemons spawn with =--daemon=NAME= which forks internally. =proc= from =Bun.spawn= tracks the pre-fork PID (already exited). All =proc.kill()= calls — org daemon's =process.on("exit")= handler, main daemon's =stop()= fallback — send signals to a dead PID.

*** Bug 4: Exit paths skip session.dispose()
- RPC mode: =process.exit(0)= at lines 672, 701 without =session.dispose()=
- =main.ts:729=: =process.exit(1)= after session creation without dispose
- These leak the daemon even when the graceful path works.

*** Bug 5: Code duplication (maintenance fork)
=packages/emacs/src/daemon.ts= (336 lines) and =packages/org/src/emacs/daemon.ts= (220 lines) implement the same lifecycle. Bugs fixed in one must be manually applied to the other.

** Approach: shared ManagedDaemon → migrate → delete dead code

1. *Phase 1*: Create =ManagedDaemon= in =packages/utils/src/managed-daemon.ts= — the reusable daemon lifecycle (spawn, socket poll, health check, postmortem, graceful stop). TDD: 16 test scenarios.
2. *Phase 2*: Rewrite =packages/emacs/src/daemon.ts= to use =ManagedDaemon=. Switch =--daemon= → =--fg-daemon=. Preserve public API. Remove ~200 lines of manual lifecycle code. Update tests.
3. *Phase 3*: Delete =packages/org/src/emacs/daemon.ts= entirely. Add =StartEmacsOptions= (socket prefix, timeout, flags, reattach) to =startEmacsSession=. Org tool imports from =@oh-my-pi/pi-emacs=. Fix org dispose to call =session.stop()=. New dispose tests.
4. *Phase 4*: Fix remaining exit paths (RPC mode, main.ts) that call =process.exit()= without =session.dispose()=.

** Key decisions
- =--fg-daemon= instead of =--daemon= so =proc= tracks the live daemon PID and =proc.kill()= works as synchronous last-resort cleanup. Emacs 26+ supports this; codebase requires 29+.
- Postmortem registration lives inside =startDaemon()=, not at the consumer level — cannot be forgotten.
- =probeSocket()= and =waitForSocket()= are public exports from utils, reusable beyond Emacs.
- =EmacsSession= interface and =startEmacsSession= signature preserved (additive optional config) — zero breaking changes for consumers.
- Org daemon deleted, not wrapped — one implementation, configurable via options.
