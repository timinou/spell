* Initial Message

yo. how would you gain by getting the code tool interface to be xml instead of json, when communicating with the LLM

* Context

The code tool currently requires the LLM to JSON-escape all code content when making tool calls. Multi-line function bodies, patch find/replace strings, and wrap templates must be encoded as single JSON strings with =
=, =	=, =\\=, =\"= escaping. This:

- Wastes tokens (5-15% escaping overhead on code-heavy payloads)
- Causes tool call failures (broken escaping is common)
- Makes the model reason about code through a string-encoding lens instead of writing code naturally

The hashline edit tool (=packages/coding-agent/src/patch/index.ts=) already solves this for its domain: its =edits[].lines= field accepts =string | string[] | null=, where each array element is a line of code — no =
= escaping needed. Its output is also compact: terse status line + change counts + compact diff preview.

This plan applies the same pattern to the code tool:

1. *Input*: All content-carrying fields (=content=, =patches[].find=, =patches[].replace=) accept =string | string[]= — array elements joined with =
= before passing to the native engine
2. *Output*: =formatCodeToolContent()= rewritten for compact, hashline-style results — terse status, compact diff previews for edits, reduced label verbosity for navigate/outline/undo
3. *Prompt*: Examples in =code.md= updated to show array-of-lines format

** Key Decisions

- Native layer (=CodeBufferOptions=, =Patch=) stays unchanged — normalization from =string[]= to =string= happens in =code.ts=
- Clean cutover: old single-string format still accepted (it's a subset of =string | string[]=), but prompt examples train the model toward arrays
- Edit output uses =buildCompactHashlineDiffPreview()= from =patch/hashline.ts= instead of dumping raw diff
- =read= and =graph= output unchanged (already optimal)
- TUI rendering (=renderResult=) unaffected — it reads from =details=, not the LLM-facing =content= text
