* Problem

** QmlJourney is a passthrough, not an abstraction

12 of 15 methods are single-line delegations to ~#harness~. The only real logic is ~scroll()~ (geometry lookup) and ~expectText/expectTextAbsent~ (text search). This fails the \"earn every line\" rule.

** Manual settle() is boilerplate

Every test does ~agentSends(); await journey.settle(100); expectText()~. The settle is mechanical \u2014 it should be automatic after mutations.

** One-shot assertions are fragile

~expectText()~ queries visible text once and fails immediately. QML rendering is async \u2014 Loader panel switching is async. Assertions should retry/poll with a timeout, like Playwright's auto-retrying expect.

** evaluate() leaks QML internals

Tests use ~journey.evaluate(\"root.activePanelIndex = 1\")~ and ~journey.evaluate(\"panelLoader.item.queueP1\")~ \u2014 depending on internal QML ids that aren't part of the contract.

** Zero input simulation coverage

We built click/type/press/scroll in C++, protocol types, harness methods, and Journey wrappers. Not a single test exercises them.

* Decisions

** Auto-settle after mutations

~agentSends()~, ~click()~, ~type()~, ~press()~, ~scroll()~ auto-settle after executing. Default settle delay configurable via ~launch()~ options (default: 50ms). Existing explicit ~settle()~ calls become redundant but harmless.

** Retry-based assertions with timeout

~expectText(text, opts?)~ polls ~findVisibleText()~ in a loop with 50ms intervals until found or timeout (default 2000ms). This handles Loader async loading naturally. Same for ~expectVisible()~ and ~expectNotFound()~.

** Keep evaluate() as escape hatch

The 5 existing tests use it. Do not remove. Add ~switchPanel(id)~ and ~panelProperty(name)~ as preferred replacements.

** Focus management for typing

In offscreen mode (~QT_QPA_PLATFORM=offscreen~), windows don't receive activation events. ~QKeyEvents~ route to the ~activeFocus~ item. Before any ~type()~ test, either: (a) click the TextEdit via selector to focus it, or (b) call ~evaluate(\"inputField.forceActiveFocus()\")~. The ~type(text, selector?)~ method already handles this \u2014 pass a selector and it clicks first.

** Verify typing via prompt bridge event

When InputBar fires ~messageSent~, ChatPanel calls ~bridge.send({ type: \"prompt\", text: text })~ (ChatPanel.qml line 150). Tests verify this event via ~waitForEvent()~. No test harness QML changes needed.

** Reference QML files are documentation, not production

~canvas/reference/~ contains example QMLs (AgentMonitor, CodeReviewSurface, etc.) not imported by any production code. Track them for reference but don't test them.

*** New method: waitUntil(fn, timeout?)

Generic retry helper on the harness:

#+begin_src typescript
async waitUntil<T>(
  fn: () => Promise<T | null | false>,
  timeout = 2000,
): Promise<T> {
  const start = Date.now();
  let lastError: Error | null = null;
  while (Date.now() - start < timeout) {
    try {
      const result = await fn();
      if (result !== null && result !== false) return result;
    } catch (err) {
      lastError = err instanceof Error ? err : new Error(String(err));
    }
    await Bun.sleep(50);
  }
  // Final attempt
  const result = await fn();
  if (result !== null && result !== false) return result;
  throw lastError ?? new Error(`waitUntil timed out after ${timeout}ms`);
}
#+end_src

#+begin_src typescript
async expectText(text: string, timeout?: number): Promise<void> {
  await this.#harness.waitUntil(async () => {
    const texts = await this.#harness.findVisibleText();
    return texts.some(t => t.includes(text)) || null;
  }, timeout ?? this.#assertTimeout);
}

async expectTextAbsent(text: string, timeout?: number): Promise<void> {
  // Settle first, then check once. Retry-absence doesn't make sense
  // (you'd always succeed on first poll before the text appears).
  await this.#harness.settle(this.#settleMs);
  const texts = await this.#harness.findVisibleText();
  if (texts.some(t => t.includes(text))) {
    throw new Error(`expectTextAbsent: \"${text}\" was found in visible text`);
  }
}
#+end_src

    `root.findPanelIndexById('${id}')`,

* Critical Implementation Notes (for executor)

** Focus in offscreen mode

~QT_QPA_PLATFORM=offscreen~ does not send window activation events. ~QKeyEvents~ are routed to the ~activeFocus~ item. Before any ~type()~ call in tests, MUST either:
- Click the TextEdit via selector: ~await harness.click({ type: \"QQuickTextEdit\" })~
- Or call: ~await harness.evaluate(\"inputField.forceActiveFocus()\")~

The ~type(text, selector?)~ method on the harness already supports this \u2014 pass a selector and it clicks first to focus.

** Signal observation through bridge

InputBar emits ~messageSent(text)~. ChatPanel handles it in ~sendUserMessage()~ which calls ~bridge.send({ type: \"prompt\", text: text })~. Tests observe this via ~waitForBridgeEvent(e => e.payload?.type === \"prompt\")~. No QML harness changes needed.

** Sidebar StateLayer click identification

Shell sidebar delegates are ~height: 44~ rectangles with StateLayer (inner MouseArea). The ~observe()~ method returns all visible MouseAreas. Filter by geometry height to identify sidebar items vs other interactive elements (send button is 36x36, input field is variable height).

** expectTextAbsent cannot use retry

Retrying an absence assertion would succeed on the first poll before the UI updates. Instead: settle first, then check once. This is the correct semantic \u2014 \"after settling, this text should not be present.\"
