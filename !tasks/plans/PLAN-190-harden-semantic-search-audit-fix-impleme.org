* Initial Message

Implement these audit recommendations from org://AUD-058-audit-implementation:

- **What**: `index --semantic` reports success even when semantic indexing fails  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `run_code_graph()` `"index"` branch around `build_semantic_index()` handling  
  **Why**: The command appends `Semantic: failed (...)` to the output string but still returns a successful result. Callers cannot reliably distinguish “graph indexed with vectors” from “graph indexed without vectors after failure,” which can hide missing semantic capability and make later search behavior misleading.  
  **Effort**: small

- **What**: `semantic` is accepted in the public options type but ignored for search behavior  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `CodeGraphOptions` / `CodeGraphTaskOptions` plus `"search"` dispatch branch  
  **Why**: The API accepts `semantic: Option<bool>`, but only the `"index"` branch uses it. Search always auto-uses vectors if cache exists, and never uses the flag to force or suppress semantic retrieval. That is a contract violation: callers can pass input that is silently discarded.  
  **Effort**: small

- **What**: Corrupt or stale vector cache silently degrades to BM25-only search  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `load_vector_cache()` and `"search"` branch fallback logic  
  **Why**: Any cache open/deserialize failure returns `None`, and query embedding failures also fall back silently. Users get plausible-looking search results without any indication that semantic retrieval was unavailable, which makes failures hard to detect and debug.  
  **Effort**: small

- **What**: Vector cache writes bypass the graph cache’s atomic persistence path  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `save_vector_cache()`  
  **Why**: The file is written directly with `File::create(...)` instead of an atomic temp-write/rename flow like the graph cache. A crash or interruption can leave a partial `workspace-vectors.bin`, which is later treated as “no vectors” rather than a surfaced failure.  
  **Effort**: small

- **What**: Vector cache invalidation hashes only a hand-picked subset of fingerprint state  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `compute_fingerprint_hash()`  
  **Why**: The vector cache freshness rule is reimplemented separately from the graph cache contract. If `GraphFingerprint` semantics change later, vector invalidation can drift and keep stale embeddings “fresh” even when the graph cache would consider them stale.  
  **Effort**: small

- **What**: Embedding dimension is hardcoded to `768` instead of derived from model output  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `build_semantic_index()`  
  **Why**: This is correct for the current model, but brittle. A future model/config change can silently break search or produce dimension mismatches. Deriving the dimension from the first embedding would make the implementation truthfully reflect the actual model output.  
  **Effort**: trivial

- **What**: Semantic chunking uses a simple line-range heuristic that is not covered for nested/enclosing symbols  
  **Where**: `crates/pi-code-graph/src/chunking.rs`, `extract_chunks()` end-boundary logic  
  **Why**: A symbol’s chunk ends at the next symbol’s start line. For nested structures like classes with methods, the enclosing symbol can lose most of its body/context, which hurts retrieval quality. Current tests cover flat sibling symbols, missing files, and truncation, but not nested declarations.  
  **Effort**: medium

- **What**: No integration test covers the N-API semantic flow end-to-end  
  **Where**: `crates/pi-natives/src/code_graph.rs` semantic index/search path; test gap across `pi-natives`  
  **Why**: Lower-level unit tests pass, but there is no test proving that: semantic indexing writes the vector cache, stale vectors are ignored, cached vectors are loaded into search, and hybrid results are returned through the N-API entrypoint. That leaves the highest-risk wiring path unprotected.  
  **Effort**: medium

- **What**: Real embedding/model lifecycle is not exercised by automated tests  
  **Where**: `crates/pi-code-vectors/src/embedding.rs`, ignored tests  
  **Why**: The fastembed API already differed from the original implementation assumptions during development. Because all model-backed tests are ignored, future upstream API or runtime regressions can land undetected while the pure unit tests still pass.  
  **Effort**: medium

- **What**: `status` does not report vector-index presence or freshness  
  **Where**: `crates/pi-natives/src/code_graph.rs`, `render_status()`  
  **Why**: After adding a second cache (`workspace-vectors.bin`), the status surface still only reports graph-cache state. That makes semantic indexing hard to inspect operationally and forces users to infer vector availability indirectly from search behavior.  
  **Effort**: small

* Context

** Problem
The hybrid graph+vector semantic search system (implemented in PLAN-184) has 10 audit findings across contract violations, cache reliability, missing tests, and operational observability gaps. The core search works but callers cannot distinguish semantic success from failure, the vector cache can corrupt on crash, and the fingerprint hash can drift out of sync with the graph cache.

** Approach
Four items fix the findings in dependency order:
1. N-API contract fixes (semantic flag tri-state, error surfacing, status reporting, dimension derivation)
2. Vector cache reliability (atomic writes, derived Hash for fingerprint)
3. Test coverage (nested chunking test, hybrid search integration test)
4. Model lifecycle test gate (cargo feature for CI opt-in)

** Key Decisions
1. =CodeGraphResult= gains =semanticStatus: Option<String>= — structured feedback for callers
2. =semantic= field is tri-state: =true= (require vectors), =false= (force BM25), =None= (auto-detect with degradation hint)
3. Atomic vector cache writes via temp-file + =fs::rename()=
4. =Hash= derived on =GraphFingerprint= + =FileFingerprint= — eliminates field-by-field hash drift
5. Embedding dimension derived from first vector, not hardcoded 768
6. Model tests gated behind =test-embedding= cargo feature, not =#[ignore]=
7. =render_status()= reports vector index presence and freshness
8. TS types and code tool schema updated to pass =semantic= flag through
