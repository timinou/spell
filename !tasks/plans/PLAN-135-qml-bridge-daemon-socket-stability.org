* Context
The QML bridge daemon socket (/run/user/1000/spell-qml-bridge.sock) is unstable when multiple spell sessions run concurrently. In a 10-minute session, the socket closed unexpectedly 5 times. The root cause is threefold:

1. *Window orphaning*: When a client disconnects, the C++ daemon keeps windows alive but their ~owner~ pointer becomes a dangling reference. Reconnecting clients get empty state snapshots because ~getWindowStates(newClient)~ filters by owner — the new client doesn't match the dead pointer. Additionally, systray/hotkey lambdas capture the client pointer by value — dangling UB after disconnect.

2. *No auto-reconnect*: When the socket closes, ~QmlProcess~ sets ~#socket = null~ and logs a warning. No synthetic event is dispatched to listeners. In-flight ~waitForEvent~ calls hang until the 600s timeout. The canvas event loop catches the eventual error and terminates silently — windows become unreachable. No concurrency guard on ~ensure()~ means multiple callers can race into connection attempts.

3. *Spawn contention*: Multiple sessions can concurrently call ~#spawnDaemon()~, each spawning a new ~spell-qml-bridge --daemon~. The C++ daemon's ~isSocketLive~ check has a 500ms window where a new daemon may think the socket is stale and remove it, disrupting existing connections.

** Approach
Four changes, layered in dependency order:

- *Wave 1 (BUG-156)*: Fix C++ daemon to orphan windows on client disconnect (set ~owner = nullptr~), add re-ownership on reconnect (~claimOrphans~), fix systray/hotkey pointer safety, handle WM-close of orphaned windows.
- *Wave 2 (BUG-157 + BUG-158, parallel)*: Add ~socket_disconnected~ protocol type. Implement auto-reconnect in ~QmlProcess~ with exponential backoff and ~#connectingPromise~ concurrency guard. Propagate through ~QmlBridge~ (route before window lookup, wake waitForEvent). Canvas event loop retry on reconnect. Separately, add filesystem lock for daemon spawn.
- *Wave 3 (FEAT-315)*: Add ~heartbeat~ protocol type. C++ QTimer broadcast every 30s. TS-side filtering and stale detection.

** Key decisions
- Heartbeat is *daemon-initiated* (every 30s to all clients). Client detects staleness if no data for 90s.
- Orphaned windows get ~owner = nullptr~. ~getWindowStates~ includes them with ~orphaned: true~ flag. TS side only claims windows that match its ~#windows~ map.
- Spawn lock uses ~mkdir~-based lock file at ~/run/user/$UID/spell-qml-bridge.sock.lock~, inline in ~qml-process.ts~ (no new cross-package dependency).
- ~socket_disconnected~ is a synthetic ~BridgeEvent~ with ~id: "__socket__"~. Routed in ~QmlBridge.#handleEvent~ BEFORE the window lookup (same layer as stderr/state/hotkey). Pushes synthetic event into every active window's queue to wake ~waitForEvent~ listeners.
- ~ping~ BridgeCommand removed from scope — dead protocol with no consumer.
- Phoenix-inspector extension has its own bridge/event loop at the project level (~.spell/extensions/~) — out of scope. It benefits from bridge-level improvements when launched via the canvas tool.
