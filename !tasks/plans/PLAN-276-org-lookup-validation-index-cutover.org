* Context

Request:
- Fix broader org lookup/validation performance across plan mode and the org tool.
- Lower approval/validation latency through architectural cleanup.
- Rust is the source of truth; remove duplicate TypeScript work when it is better suited to Rust.
- The user explicitly selected a hybrid design: shared low-level cache/index substrate reused by org + code-graph, but separate org-native commands/data model.
- The user explicitly selected full org read-surface cutover in the first implementation wave, not just the plan hot path.

Observed bottlenecks verified in the current repo:
- `packages/org/src/native-ops.ts` reparses category files in `readCategory(...)` and linearly scans them in `findItemById(...)`.
- `packages/org/src/tool.ts` layers more repeated scans through `fetchItems`, `fetchItem`, `collectItems`, and `collectPlanWaveItems`.
- `packages/coding-agent/src/plan-mode/plan-validation.ts` repeatedly resolves child items and reparses sub-outline bodies while validating.
- `packages/coding-agent/src/plan-mode/org-plan.ts` and `packages/coding-agent/src/tools/exit-plan-mode.ts` re-enter the same lookup path during approval/completion payload building.
- `crates/pi-natives/src/org_buffer.rs` currently exposes parse/query/graph primitives, but does not own a persistent org lookup index analogous to code-graph’s warm-cache model.

Settled design decisions:
1. Extract a shared Rust workspace-cache substrate from the current code-graph cache pattern instead of coupling org indexing directly to the `pi-code-graph` crate.
2. Build a separate persisted org-native index/model on top of that substrate; org semantics stay separate from code-graph semantics.
3. Rust becomes the source of truth for CUSTOM_ID resolution, sub-outline resolution, plan-validation inputs, and warm-cache freshness.
4. The first implementation cut includes the full org read surface: ID-based lookups plus query/dashboard/archive/wave/graph item collection.
5. TypeScript keeps orchestration and presentation only; it must stop doing steady-state repeated category rescans and repeated child-body reparses.
6. Mutation coherence is mandatory in the same cut: after writes, indexed reads must be truthful without manual rebuild steps.
7. Full cutover applies: do not leave the current repeated-scan TypeScript path as a silent warm-path compatibility layer.

Recommended approach:
- Foundation first: shared cache substrate + org index builder/status commands.
- Then truthfulness: all write paths keep the index fresh.
- Then full org read-surface cutover.
- Then coding-agent plan-validation / exit-plan-mode cutover on top of the same native truth path.

Critical files / modules expected to change:
- `crates/pi-code-graph/src/cache.rs`
- new shared cache crate/module extracted from that file
- `crates/pi-natives/src/org_buffer.rs`
- org-index Rust modules under `crates/pi-natives` and/or `crates/pi-org-engine`
- `packages/org/src/native-ops.ts`
- `packages/org/src/tool.ts`
- `packages/coding-agent/src/plan-mode/plan-validation.ts`
- `packages/coding-agent/src/plan-mode/org-plan.ts`
- `packages/coding-agent/src/tools/exit-plan-mode.ts`
- focused Rust/native/TS test files for org query, mutation coherence, and plan validation
