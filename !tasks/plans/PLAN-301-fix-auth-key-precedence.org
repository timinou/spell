* Context

Two auth bugs discovered during normal usage:

1. **Better-ccflare at localhost:8080** receives `ANTHROPIC_API_KEY` from `.env` via the `serviceProviderMap` fallback chain. Better-ccflare expects `btr-` prefixed keys, so it returns 401. The intended behavior (OAuth passthrough — no auth header) is broken because `$pickenv("ANTHROPIC_AUTH_TOKEN", "ANTHROPIC_API_KEY")` picks up the existing `.env` key.

2. **Anthropic provider** silently falls back to `.env` `ANTHROPIC_API_KEY` when OAuth token refresh fails. The user logged in via `/login anthropic` (storing OAuth credentials), but when the token expires and can't refresh, `getApiKey()` falls to the env var fallback. The user sees "credit balance too low" from the stale `.env` key instead of being told to re-login.

*** Design notes
For BUG-336, the implementation used a #providersWithOAuth Set rather than querying #getCredentialsForProvider directly. This was necessary because markAuthFailure → #disableCredentialAt → #resetProviderAssignments wipes the credential store, but the Set survives since it only tracks presence (populated on set/reload, never cleared on disable). This ensures the guard works even after auth failure cascades.

NOTE [2026-05-05]: ** Follow-up fix [2026-05-05]
*** Root cause of "fix not working"
stream() and streamSimple() both independently called getEnvApiKey(model.provider) via `options?.apiKey || getEnvApiKey(...)`. When the SDK passed apiKey: undefined (because authStorage.getApiKey returned undefined due to OAuth guard), the stream functions treated it as "no key provided" and fell back to env vars — picking up ANTHROPIC_API_KEY.

This defeated the BUG-336 fix (OAuth→env guard) in auth-storage.ts because the guard only prevented fallback WITHIN getApiKey(), but the stream functions had their own independent fallback.

*** Fix
Changed stream() line 196 and streamSimple() line 272 from:
  options?.apiKey || getEnvApiKey(model.provider)
To:
  (options && 'apiKey' in options) ? options.apiKey : getEnvApiKey(model.provider)

When the SDK explicitly passes apiKey: undefined (auth failure), the stream now respects it and throws "No API key for provider". When stream is called without apiKey at all (standalone usage), env var fallback still works.
