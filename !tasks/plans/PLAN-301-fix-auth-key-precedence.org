* Context

Two auth bugs discovered during normal usage:

1. **Better-ccflare at localhost:8080** receives `ANTHROPIC_API_KEY` from `.env` via the `serviceProviderMap` fallback chain. Better-ccflare expects `btr-` prefixed keys, so it returns 401. The intended behavior (OAuth passthrough — no auth header) is broken because `$pickenv("ANTHROPIC_AUTH_TOKEN", "ANTHROPIC_API_KEY")` picks up the existing `.env` key.

2. **Anthropic provider** silently falls back to `.env` `ANTHROPIC_API_KEY` when OAuth token refresh fails. The user logged in via `/login anthropic` (storing OAuth credentials), but when the token expires and can't refresh, `getApiKey()` falls to the env var fallback. The user sees "credit balance too low" from the stale `.env` key instead of being told to re-login.

Files affected:
- `packages/ai/src/stream.ts` line 97 — better-ccflare env var resolver
- `packages/ai/src/auth-storage.ts` lines 1994-2001 — `getApiKey()` OAuth→env fallback
