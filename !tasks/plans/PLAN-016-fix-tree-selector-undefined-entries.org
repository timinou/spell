* Context

The tree selector (~packages/coding-agent/src/modes/components/tree-selector.ts~) renders every ~SessionEntry~ in the session via ~#getEntryDisplayText~. Four entry types (~mode_change~, ~service_tier_change~, ~session_init~, ~ttsr_injection~) have no display handler, no search indexing, and are not classified as bookkeeping entries for the filter. This causes them to appear as blank entries in default view and, during streaming partial updates where tool metadata arrives incrementally, can produce ~[undefined] undefined~ text from template literal interpolation of unresolved JS ~undefined~ values.

** Approach

TDD: write the test first defining the display, filter, and search contracts for every ~SessionEntry~ type, then implement the handlers to make the tests pass. Single file change plus a new test file.

** Key decisions

- All four missing types are bookkeeping — add to ~isSettingsEntry~ so they're hidden in default view (same as ~model_change~, ~thinking_level_change~, etc.)
- Display format follows existing convention: ~[type: detail]~ in dim color
- The ~TreeList~ class is not exported, so the test must instantiate it by importing from the module directly — or test through the public ~render~ method by extracting printable text from the rendered lines
