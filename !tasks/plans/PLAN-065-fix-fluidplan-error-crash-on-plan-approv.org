* Context

When =exit_plan_mode= triggers =org-fluid-plan= via Emacs MCP, the Elisp error handler returns an in-band error JSON (not a JSON-RPC error). The =callToolOnce= function parses it as valid JSON and returns it. The TypeScript side then casts it unsafely to =FluidPlanWithComponents=, producing a truthy object that lacks =warnings= and =components= fields. This crashes during plan approval with:

: undefined is not an object (evaluating 'options.fluidPlan.warnings.length')

Root cause chain:
1. =org-fluid-plan.el= returns errors as content text, not JSON-RPC errors
2. =exit-plan-mode.ts= uses an unsafe =as= cast without shape validation
3. =interactive-mode.ts= accesses =.warnings.length= without defensive guard

The fix validates the MCP response shape in =exit-plan-mode.ts= (primary fix) and adds optional chaining in =interactive-mode.ts= (defense in depth). When the response is invalid, the system falls back to wave-based plan initialization (the existing fallback path when =fluidPlan= is =undefined=).
