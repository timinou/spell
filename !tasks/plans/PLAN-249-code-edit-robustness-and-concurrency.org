* Context

PLAN-248 wave-1 surfaced multiple classes of `code edit` failures that caused subagents to abort or silently destroy content. BUG-279 (already ITEM) addresses the cache-staleness class (BufferRegistry serves stale ropes and `save()` clobbers external writes). It does NOT address:

- Silent truncation when `write{scope:"body"}` targets an outer declaration whose body contains many sibling decls (PLAN-248: collections_section.ex lost 213 lines).
- Positional `insertBefore{line}` escaping the `targetId` declaration to land at file-top (PLAN-248: inserted outside the Elixir module).
- `findAndReplace` hard-failing on >1 match with no selector fallback (PLAN-248: duplicate `VectorRetriever.search(...)` lines).

Beyond bug repair the user's stated direction is:
1. auto-discover external edits (supersede reactive mtime with a proactive watcher).
2. play well with other Spell services / processes via OS advisory locks.
3. be concurrency-friendly within a single session so parallel tool calls do not falsely serialise on the registry map.

This plan orchestrates five new child items plus the pre-existing BUG-279 into four execution waves. Completion gate: a medium-scoped Elixir refactor (~100 lines, real collections_section.ex fixture) dispatched via `task { agent: "quick_task" }` must succeed end-to-end without abort, truncation, or escaped inserts.

Key files the implementation crosses:
- `crates/pi-code-engine/src/buffer.rs` (registry, CodeBuffer)
- `crates/pi-code-engine/src/edit/body.rs` (replace_body)
- `crates/pi-code-engine/src/edit/patch.rs` (apply_patches)
- `crates/pi-code-engine/src/edit/replace.rs` (insert_before/insert_after)
- `crates/pi-code-engine/src/line_target.rs` (positional resolution)
- `crates/pi-code-engine/src/resolve.rs` (ResolvedSymbol, decl counting helper)
- `crates/pi-code-engine/src/error.rs` (new variants)
- `crates/pi-code-engine/src/watcher.rs` (new)
- `crates/pi-code-engine/src/file_lock.rs` (new)
- `crates/pi-natives/src/code_buffer.rs` (NAPI dispatch)
- `crates/pi-natives/src/org_buffer.rs` (callers of buffer_registry)
- `packages/coding-agent/src/tools/code.ts`, `code-result.ts`, `prompts/tools/code.md`

Non-goals (this plan):
- Restructuring the action schema beyond the targeted additions (`allowSiblingDelete`, `occurrence`).
- Replacing `Arc<Mutex<CodeBuffer>>` with async locks.
- Cross-machine coordination.
- Pushing fs-watcher events to JS/TS clients (future FUP).

Decisions settled during planning:
1. Size-delta guard is `lost_decls >= 1 AND original_count >= 2`, not raw line count. Rationale: line-count is a proxy for a structural loss; structural count is the truthful signal.
2. Default `findAndReplace` behavior stays unique-or-fail. `occurrence` is explicit opt-in; matches caller intent and keeps safe-by-default.
3. `notify`-rs `RecommendedWatcher` with per-path watches, not recursive. Matches the "watch only what is open" principle and avoids inotify quota blowups.
4. Advisory lock uses `fd-lock` (cross-platform RAII) with 500ms budget on `save`, 100ms on revalidation. Cooperating Spell processes share the contract; non-cooperating external editors continue to rely on the fs-watcher path.
5. `DashMap` over manual sharded RwLock. Same major-version pin policy as `notify`/`fd-lock`.
6. Subagent re-enablement is gated behind all five new items + BUG-279 via a live repro fixture.
