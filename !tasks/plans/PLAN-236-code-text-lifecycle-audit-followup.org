** Settled Decisions
1. Canonical terminology is `semanticCapable` / semantic-capability, not `supported`. This is a full naming cutover inside coding-agent helpers and result typing; no compatibility aliases remain after implementation.
2. `code-result` structured details must preserve native `semanticCapable` metadata for `open` and `buffers`; callers must not need injected prose hints to distinguish semantic vs fallback buffers.
3. Non-binary text persistence must converge further on one managed-buffer lifecycle: patch mode joins replace/hashline on the shared freshness / mutation / save flow, and migrated writes regain immediate diagnostics/writethrough metadata.
4. `code` grows explicit top-level file commands for `move` and `delete`; the plan does not overload declaration-level `edit` operations or reuse symbol-level `rename` for file moves.
5. Replay verification remains deterministic and repo-local: checked-in sanitized `.jsonl` fixtures are parsed through the real session parser/migration path; the gate must not read `~/.spell`.
6. Execution remains split by design decision, not by file count: metadata/naming cleanup, lifecycle/diagnostics convergence, move/delete parity, then replay-gate finalization.

** Recommended Approach
- Fix the metadata contract and naming drift first so downstream tests/assertions target the right structured surface.
- Converge patch mode and diagnostics on the managed-buffer lifecycle next; move/delete parity then extends the same lifecycle outward through `code` instead of leaving more behavior inside `edit`.
- Upgrade the replay gate last so the deterministic corpus locks the final behavior instead of a transient intermediate state.
