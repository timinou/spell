* Initial Message

The org tool in pi-tui just shows "Org". Can you make it clearer what part of the Org tool is being used? Creating vs. updating vs. etc. and e.g. if an org-ql is made what that org-ql query was?

* Context
The Org tool in pi-tui shows only "Org" for all operations — create, query, update, get, etc. are all indistinguishable. Other tools (Grep, LSP, Bash, Read, etc.) show operation-specific labels with relevant details via ~renderStatusLine~.

OrgTool already has ~renderResult~ on the class instance (entering path 1 at tool-execution.ts:381), but no ~renderCall~. The fix is to add ~renderCall~ to the class using the same ~renderStatusLine~ pattern every other tool uses.

Secondary fix: the coding-agent adapter's ~orgSchema~ is missing ~query~ and ~ql~ params that exist in pi-org's tool definition. These pass through via ~lenientArgValidation = true~ but aren't in the schema, so the LLM doesn't know about them.

** Key decisions
- Add ~renderCall~ on the OrgTool class (not in ~toolRenderers~ registry) — because the class already owns ~renderResult~ and the tool-execution.ts rendering path is already wired for instance methods
- Show command as description (e.g. "Org: create"), relevant context as meta
- Single file change: ~packages/coding-agent/src/tools/org.ts~ plus no registry changes needed

** Critical file paths
- ~packages/coding-agent/src/tools/org.ts~ — the only file to modify
- ~packages/coding-agent/src/modes/components/tool-execution.ts~ — rendering flow (read-only, for reference; line 381-404 is the active path)
- ~packages/coding-agent/src/tui/status-line.ts~ — ~renderStatusLine~ API: ~{ icon, title, description?, meta?, badge? }~
- ~packages/coding-agent/src/tools/render-utils.ts~ — ~truncateToWidth~, ~TRUNCATE_LENGTHS~
