* Initial Message

Empirical analysis of recent agent sessions across 3 repos / 8 sessions / 3115 bash calls shows ~580 line-range file reads expressed as `sed -n 'A,Bp' FILE` (472), `awk 'NR>=A && NR<=B' FILE` (92), `head -n` / `tail -n`, `cat | head` (37). Plus 103 `grep -n` and 97 `wc -l`. These should all flow through CodePath / `get`.

Three independent faults blocked native usage:
1. `§line[A..B]` returns one node per source line ⇒ ~4× output expansion. Agents try once, give up.
2. `offset` on the `get` tool is interpreted at *node* count by the kernel; combined with `head`/`tail` it returns `§no-results pagination-overshoot` on bare paths.
3. No bash-style file:line shorthand; no native shape that matches `grep -n`; `#stat` lacks lineCount so `wc -l` survives.

Strategy: keep CodePath as "views over a path", do not turn it into a DSL. Add the missing line-view affordances at the grammar layer; thin out `get` to just execute paths.

* Goals
- `get { target: "foo.ts:80-130" }` ⇒ lines 80..130 as ONE sliced text body
- `get { target: "foo.ts:50" }` ⇒ first 50 lines (head)
- `get { target: "foo.ts:-50" }` ⇒ last 50 lines (tail)
- `get { target: "foo.ts:80-" }` ⇒ lines 80..EOF
- `get { target: "foo.ts:80+50" }` ⇒ 50 lines starting at 80
- `get { target: "foo.ts::Bar.method:80-90" }` ⇒ symbol with absolute clamp (validated against symbol span)
- `get { target: "foo.ts::Bar.method:±5" }` ⇒ symbol + 5 lines before/after (relative)
- `get { target: "foo.ts::Bar.method:-5..+10" }` ⇒ 5 lines before symbol-start to 10 after symbol-end
- `get { target: "foo.ts::§line[text~=PAT]" }` ⇒ rendered as `LINE: content` per match (grep shape), not `LOC#ID  [§line]
  body

`
- `get { target: "foo.ts#stat" }` ⇒ payload includes `lineCount`
- `get` schema drops `head` / `tail` / `offset` / `limit` (limit migrates to internal kernel option only)

* Non-goals
- No mutating verbs in CodePath (sort/uniq/reverse stay in bash on `get`'s output)
- No multi-file reduction inside CodePath grammar (already handled by glob + code_search)
- No new sigil (use existing `§line[]` and the `:A-B` bare-path branch)
