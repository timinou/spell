** Settled decisions (inherited)
- No CRDT in Phase 1. Journal + socket broker + peer-aware reload.
- Dedicated pi-edit-broker daemon at =~/.spell/edit-broker.sock=, auto-spawned by first client, exits 30s after last disconnect.
- Attribution granularity = CodePath; falls back to =::*= when no named ancestor.
- Conflict policy = block + structured =PeerConflict{sessionId, codePath, peerRevision, peerCommitTs}=. Never silent.
- Stateless edit_transaction: every mutating call re-reads disk under lock, re-resolves CodePath, applies, writes atomically via temp+rename, commits to broker, journals.
- sessionId is REQUIRED on mutating NAPI commands; missing → structured =MISSING_SESSION_ID= error. Read-only commands ignore sessionId.
- Fallback when =getSessionId()= null: =tui-${process.pid}= (matches =packages/coding-agent/src/main.ts=:129).
- Undo/redo per-session, best-effort; =undo_scoped(sessionId)= skips peer revisions and reports them.
- Broker binary discovery: =target/release/pi-edit-broker= in dev; bundled alongside =pi-natives= via =getNativesDir()= in release.

* Risks and mitigations (inherited)

- Broker binary distribution: =spawn_broker_if_absent= resolves =pi-edit-broker=. Dev uses =target/release/pi-edit-broker=; release bundle co-locates with =pi-natives= via =getNativesDir()=.
- Broker fallback: every RPC has 150 ms budget; on timeout / socket error, degrade silently to =NullCoordClient= for that call, log one warning per process. Journal still writes locally.
- Atomicity of disk write: temp file + =rename= on the same filesystem as target; cleanup on error.
- Peer commit race inside critical section: broker grants intent but a peer could commit between grant and local commit. Mitigation: one retry inside the critical section that re-reads disk and re-resolves CodePath; second conflict returns =PeerConflict= to caller.
- Stale socket file after broker crash: auto-spawn path tests =connect()= first; on failure, =unlink()= stale socket before binding.
- Subagent session collision: each subagent has a distinct sessionId via =sessionManager.getSessionId()=. FEAT-580 verification must cover subagent attribution.
