* Context

Users place =planMode.allowedFolders= (and other settings) in =.spell/agent/config.yml= at the project level, mirroring the global =~/.spell/agent/config.yml= convention. This file is silently ignored because the builtin settings discovery provider only loads =.spell/settings.json= (JSON format from the =.spell/= root).

The global config path works because =Settings.#loadYaml()= reads directly from =~/.spell/agent/config.yml=. But project-level settings go through the capability system's =loadCapability(settingsCapability.id)=, and the builtin provider's =loadSettings()= function (=builtin.ts= line 763) only reads =settings.json=.

** Approach
Add YAML =config.yml= loading to the builtin =loadSettings()= function. For each config directory returned by =getConfigDirs()=, also check for =agent/config.yml= (exact mirror of global path structure, per user decision). Parse with =Bun.YAML.parse()= and push as a settings capability item. JSON items are pushed first, YAML second — so YAML wins on key conflicts within the same level via =Settings.#deepMerge()=.
