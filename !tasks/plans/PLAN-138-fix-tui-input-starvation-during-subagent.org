* Initial Message

text entry hangs when many subagents are working at the same time

* Context

Text entry hangs when many subagents are working concurrently. Root cause is two-layered:

** Event loop priority inversion
=requestRender()= schedules renders via =process.nextTick()=, which runs BEFORE I/O callbacks in the Node.js/Bun event loop. When subagents generate frequent progress updates (~67/sec with 10 agents at 150ms coalescing), the render loop starves stdin of processing time.

Flow:
1. N subagents running → each emits progress via =onProgress= callback (coalesced at 150ms per-agent)
2. Progress flows to main agent as =tool_execution_update= events
3. EventController handles each update → calls =ui.requestRender()=
4. =process.nextTick= schedules render BEFORE next stdin I/O callback
5. Render is synchronous and blocks until complete → stdin never fires

** Expensive full-tree renders
=Container.render()= unconditionally re-renders ALL children on every frame. No dirty flags, no caching. With a deep component tree (many ToolExecutionComponents, AssistantMessageComponents from a long session), each render traverses the entire tree even when only one component changed.

** Fix approach

Two complementary changes:

1. *Render scheduling* — switch =process.nextTick= → =setImmediate= (runs AFTER I/O), add 16ms frame throttle. This guarantees stdin always processes before the next render.

2. *Container dirty tracking* — add =#dirty= flag + cached render output to Container. Only dirty subtrees re-render. Dirty propagates upward via =#parent= references. When ToolExecutionComponent updates (via =addChild/clear= in =#updateDisplay=), dirty bubbles up through chatContainer → TUI. Clean siblings return cached lines in O(1).

** Design decisions
- minRenderInterval defaults to 16ms (60fps), configurable via TUI constructor for tests
- Dirty tracking uses =#parent= reference on Container (set via addChild/removeChild), not on Component interface
- requestRender(force=true) bypasses throttle — needed for resize and full-clear operations
- No changes to Component interface or consuming code in coding-agent — Container's API is unchanged
- Existing tests may need settle() delay increase (Bun.sleep(0) → Bun.sleep(20)) or TUI construction with minRenderInterval=0

*** Deviations

- Container dirty tracking provides less optimization than planned. The plan assumed leaf component changes always go through Container operations (addChild/clear). In practice, leaf components (Editor, Input) mutate internal state without Container operations. To ensure leaf changes render correctly, =#executeRender= calls =markTreeDirty()= which marks ALL Containers dirty every frame. This is equivalent to the old render cost for Container traversal but preserves the infrastructure for future per-subtree optimization when leaf components gain explicit dirty signaling.
- The primary performance win is from render scheduling: =setImmediate= (runs after I/O) + 16ms frame throttle prevents stdin starvation regardless of subagent update frequency.
