* Initial Message

the canvas tool does not transmit to the agent that a window of id xx close. please make it

* Problem

When a user closes a QML window by clicking the X button (or the OS window manager kills it), the C++ ~WindowManager~ never detects it. The ~closing~ signal from ~QQuickWindow~ is not connected to anything. As a result:

- The window disappears visually but the TypeScript side never learns about it
- The agent never receives a close event
- The event loop in ~canvas.ts~ keeps polling a dead window indefinitely

The existing ~closeWindow()~ method only fires when the TypeScript side sends an explicit "close" command. User-initiated (WM) closes are a dead path.

* Root Cause

In ~windowmanager.cpp~ ~loadWindow()~, after creating the ~QQmlApplicationEngine~ and loading the QML file, no signal connection is made to the root ~QQuickWindow~'s ~closing~ signal. Qt emits this signal when the user clicks X or the WM requests close.

* Fix

** ITEM Connect QQuickWindow::closing signal in loadWindow
:PROPERTIES:
:EFFORT: 15m
:END:

File: ~packages/qml/bridge/windowmanager.cpp~

After the root objects are verified (around line 133, after ~engine->load()~ succeeds), the code already accesses root objects. Add a connection to the root window's ~closing~ signal:

#+begin_src cpp
// Detect user/WM-initiated window close
auto *rootWin = qobject_cast<QQuickWindow *>(engine->rootObjects().first());
if (rootWin) {
    connect(rootWin, &QQuickWindow::closing, this, [this, id](QQuickCloseEvent *) {
        // Only act if window is still tracked (not already closed via command)
        if (!m_windows.contains(id)) return;
        delete m_windows[id].engine;
        m_windows.remove(id);

        QJsonObject ev;
        ev["type"] = "closed";
        ev["id"] = id;
        ev["wmClose"] = true;  // distinguish from command-initiated close
        writeEvent(ev);
    });
}
#+end_src

Key details:
- Guard with ~m_windows.contains(id)~ to avoid double-close if the TS side sends a close command while the window is already closing
- Add ~wmClose: true~ field so the TS side can distinguish WM-initiated from command-initiated closes
- ~QQuickCloseEvent~ needs ~#include <QQuickCloseEvent>~ or it may already be included via ~QQuickWindow~
