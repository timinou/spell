* Initial Message

I want a deeper reflection around URI handling across the codebase, and prior art research in pi-mono (where we'll eventually rebase this codebase onto)

* Scope
Move URI scheme resolution from TS-side InternalUrlRouter into the kernel as a declarative SchemeProfile DSL (mirroring the existing language-dialect pattern). Reverses FEAT-721 single-owner direction now that PLAN-309 unified the edit path on the kernel; URI dispatch is the remaining asymmetry. Brush gains native URI awareness via word-expansion hook in the vendored brush-core crate; MCP servers advertise their URI schemes dynamically; canvas:// registers similarly. Net result: kernel owns all URI dispatch, TS becomes a thin callback provider for the 2 truly JS-resident schemes (canvas + per-server MCP).

* Design (locked)

** Four axes
- Root        : ProjectRoot | SessionRoot | UserRoot | AbsoluteRoot | Virtual
- Layout      : Direct | NamedDir { entry_file, subpath_allowed } | NamedFile { ext } | IdFragment { default, fragments } | Indexed
- Loader      : FsRead { mode } | Static { table } | Indexed { lookup } | Callback(Arc<dyn SchemeCallback>)
- Capabilities: fs_backed · codepath_compatible · cache · mime_hint · bash_expandable · callback_budget

** Schemes covered declaratively (9)
skill · rule · memory · agent · artifact · jobs · org · pi · local

** Schemes via Callback escape hatch (2 families)
canvas (single static registration)
MCP servers (N dynamic registrations, one per advertised schemePrefix; auto-derived from sanitized server name when not declared)

** json-query
Not a scheme. Folded into kernel codepath qualifier grammar as #json:<jq-expr>.

* Locked decisions
- Registration via build.rs scanning crates/pi-natives/src/code_path/uri/ → static SCHEMES table (no inventory crate)
- Brush integration: modify crates/brush-core-vendored directly (no upstream); add WordPreprocessor trait; hook expand_word_piece
- TS tests: shadow-mode through phase 4; per-scheme migration with Rust integration test mirroring TS conformance test; fixtures reused
- D1 callback execution: sync with per-scheme callback_budget + cancellation token
- D2 caching: CacheStrategy { None | UntilMtimeChange | Ttl(Duration) }; per-session SchemeCache (~120 LoC)
- D3 MCP routing: per-server scheme registration; no mcp:// wrapper; no catch-all
- D4 brush: vendor-modification, comprehensive test matrix (9 cases minimum)
- D5 session context: Option<&SessionContext> threaded through every kernel call signature
- D6 org lookup: reuse pi-org-engine::locate::MultiRootIndex via IndexLookup trait; lazy + mtime cache
- MCP collision policy: registration against reserved native scheme names is rejected with clear diagnostic; two servers wanting same scheme → second rejected
