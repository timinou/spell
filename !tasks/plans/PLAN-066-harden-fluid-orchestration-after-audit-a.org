** Problem
Post-implementation audit of PLAN-062 (unify fluid orchestration with agent-driven todo_write) identified six findings. The refactor successfully unified execution paths but left dead code, an unsafe retry path, hidden org-hook failures, outdated comments, and contradictory parallelism messaging in prompts.

** Approach
Four independent work streams ordered by dependency:

1. *Wave 1 — Dead code + prompts (parallel)*: Delete the four dead execution engine files plus update prompt/comment text. These have no behavioral coupling.
2. *Wave 2 — Observability + retry fix (parallel, depends on Wave 1)*: Surface org hook failures in tool results; fix fluid retry to preserve coordinator edits. Both touch ~todo-write.ts~ / ~fluid-mode.ts~ but in non-overlapping sections.
3. *Wave 3 — Integration test coverage (depends on Wave 1)*: After dead code is removed, write new tests covering the ~todo:change~ → ~FluidEvent~ bridge that replaced the old orchestrator.

** Key Decisions
- The single-~in_progress~ invariant is correct by design. Parallelism happens via ~task~ subagents with their own todo scopes. Prompt clarification only, no behavioral change.
- PLAN auto-closeout stays out of ~todo_write~ (confirmed in PLAN-062 refinement). The completion report + explicit lifecycle close remain the agent's responsibility.
- ~FluidOrchestrator~ class is deleted entirely; ~dag.ts~, ~event-router.ts~, ~plan-validator.ts~, ~plan-to-todos.ts~, and ~types.ts~ are the retained module surface.
