* Context

The =code= tool has two backends: an Emacs daemon for file-local operations (outline, read, navigate, edit) and a Rust crate (=pi-code-graph=) for cross-file graph operations. The Emacs path has latency, requires a daemon with tree-sitter, and duplicates language understanding across Elisp and Rust. Navigate is unreliable (2/5), search has tokenization issues, dead_code is noisy, and clusters are unhelpful.

This plan replaces the Emacs backend entirely with a new Rust crate =pi-code-engine= that unifies all code intelligence: buffer management (rope + tree-sitter + loro CRDT + per-agent undo), language profiles (one definition drives outline, navigate, graph extraction, and structural edits), a procedure DSL for context-aware node selection, and all structural edit operations (splice, drag, clone, transpose). The existing =pi-code-graph= crate is refactored to depend on the engine for language profiles, and its quality issues (search, dead_code, clusters) are fixed. Diff-aware graph queries and incremental indexing are added.

Key design decisions settled during planning:
1. Two crates: =pi-code-engine= (file-local intelligence) and =pi-code-graph= (cross-file, depends on engine)
2. CRDT via =loro= crate (Fugue algorithm, per-agent undo, fork/merge for multi-agent editing)
3. Rope via =ropey= crate with tree-sitter incremental re-parsing via =InputEdit=
4. Structural diff via =difftastic= crate
5. Procedure DSL uses Rust builder pattern API — procedures are code, not config
6. Language profiles are YAML (declarations, imports, exports) + build-time generated production rules from =node-types.json=
7. Full Emacs removal from code tool — Emacs daemon stays only for org-mode operations
8. Built-in profiles for: TypeScript/JavaScript, Rust, Python, Elixir

Canonical spec: =specs/pi-code-engine-spec.md= (23K words)
Research: =specs/combobulate-dsl-research.md=, =specs/combobulate_analysis.md=

- Used =imara-diff= instead of =difftastic= for structural diff. Difftastic is a binary crate without a stable library API. imara-diff provides clean Myers diff.
- CRDT via =loro= was implemented as a simplified version (the CodeBuffer task integrated basic undo without full multi-agent CRDT merge testing, as the =loro= API requires careful integration with the buffer lifecycle). Per-agent undo via tree-based history works independently of CRDT.
- Emacs removal from =code.ts= routing deferred to a follow-up \u2014 the NAPI bindings are ready but the TypeScript tool code still routes through Emacs. This requires updating =packages/coding-agent/src/tools/code.ts= to call =executeCodeBuffer= instead of the Emacs daemon, which is better done as a separate incremental PR to avoid breakage. See [[id:FUP-044-additional-language-profiles-go-java-c-r]] for related follow-ups.
- =ropey 2.0.0-beta.1= used per user request (byte-indexed API is superior for tree-sitter integration).
