* Context

Transcript analysis of 2754 sessions over 14 days reveals the =code= tool is massively underutilized:
- =read= tool: 76,807 calls. =code= tool: 298 calls (0.4% of file reading).
- Of 298 =code= calls: 85% are =read= at resolution 3 (just =cat= through Emacs), 10% =outline=, 0% =edit=, 0% =navigate=.
- =code read= resolution 3 (full source) is 81% of reads. Resolution 0-2 (the intelligent modes) account for only 19%.
- The text =edit= tool handles 100% of editing (9,123 calls). =code edit= has zero calls despite exposing 9 operations.

Root causes identified:
1. Tool prompt is a flat reference, not a behavioral guide — no decision trees, no workflow patterns, no examples for edit/navigate
2. System prompt routes away: "text-based line edits → use =edit=" captures ~all edits
3. No "look before you edit" capability — the AI can't preview what node an edit would target
4. Combobulate's reorder/splice/clone capabilities lack corresponding navigate actions (siblings list, node inspection)

Approach: three parallel changes targeting different files.

** Key decisions
1. Expand =navigate= with 3 new actions (=node-at=, =siblings=, =children=) and =edit= with 3 new operations (=splice-self=, =splice-down=, =transpose=) — all in elisp, zero TS logic changes
2. Rewrite =code.md= as task-oriented cookbook: decision tree at top, compressed examples (task→call, no prose), workflow patterns (explore→edit, reorder, preview)
3. System prompt graduated routing: =code= is "default" not "primary", outline-first reading workflow, narrow the text =edit= escape hatch to "strings/comments only"
4. No schema changes — =operation= and =action= are free strings, new capabilities are purely additive
