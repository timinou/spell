* Context

Plan mode and ultraplan mode currently enforce strict read-only behavior — the only writable file is the plan file itself. This is enforced at two layers: (1) =enforcePlanModeWrite()= in =plan-mode-guard.ts= which gates =write.ts= and =patch/index.ts=, and (2) system prompts telling the agent not to write.

Users want the ability to configure directories that plan mode can write to, with short descriptions explaining each folder's purpose. The descriptions serve as documentation in the config file and are surfaced in the system prompt so the agent understands what each folder is for.

** Approach
Add a single =planMode.allowedFolders= setting (=Record&lt;string, string&gt;=, default empty) to the settings schema. Modify the plan mode write guard to check if a target path falls under any allowed folder. Update system prompts (both main agent and subagent) to communicate allowed folders with descriptions. Thread the setting through the template context in =buildPlanModeMessage=. Update README with feature docs. Commit incrementally after each logical unit.

Deletions and moves remain unconditionally blocked even in allowed folders — only create/update ops are permitted.

** Key decisions
- =Record&lt;string, string&gt;= over =Array&lt;string&gt;= — values are the description annotations the user requested
- Folder resolution uses =path.resolve(cwd, expandTilde(folder))= for tilde and relative path support
- Prefix-match with separator boundary prevents =/tmp/foo= from matching =/tmp/foobar=
- Subagent write tools are conditionally enabled when allowed folders are configured (gated by same guard)
- No UI metadata — power-user config-file-only setting

** Example config.yml
#+begin_src yaml
planMode:
  allowedFolders:
    ./docs/plans: "Architecture notes and plan artifacts"
    ./scratch: "Temporary exploration files"
    ~/shared-plans: "Cross-project plan output directory"
#+end_src
