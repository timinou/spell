* Context
The current managed-buffer persistence stack still has one live truth problem: `packages/coding-agent/src/tools/managed-code-buffer.ts` can surface a failed mutation *after* bytes already landed on disk via `invalidateManagedCodeBuffersForPaths(...)` (`Edit succeeded on disk, but failed to invalidate the managed code buffer ...`). That violates the user-selected contract for this plan: surfaced failures must imply no disk mutation; if bytes already persisted, the result must be success with warning.

Motivating repro: the user hit a failing Write on `specs/subagent-envelope-v2.md` with `Edit batch would leave the buffer structurally invalid...` and then had to ask whether that failure could still have saved. Current repo evidence shows existing-file invalid edits are rolled back before save, but missing-file invalid-create coverage and post-save invalidation truthfulness are not pinned yet.

Critical repo evidence:
- `packages/coding-agent/src/tools/managed-code-buffer.ts` now routes `edit`, `replace_content`, and `save` through `callCodeBuffer(...)`; the earlier sessionId bug captured by [[id:BUG-303-applymanagedbuffercontent-bypasses-callc]] is already landed and should be preserved, not replanned.
- The same file still throws on post-save buffer invalidation failure.
- `packages/coding-agent/src/tools/write.ts` routes supported-file writes through `applyManagedBufferContent(...)` and therefore inherits that truth contract.
- `packages/coding-agent/src/patch/index.ts` also reuses the same helper path for migrated text/edit persistence.
- `packages/natives/test/code-buffer.test.ts` already proves existing-file invalid edit rejection before save and successful missing-file create through `edit` + `save`.
- `crates/pi-code-engine/src/buffer.rs::test_buffer_registry_open_or_create_missing_file` proves missing-file create begins as an in-memory empty buffer, which is the lower-layer contract to preserve when later persistence fails.

Settled decisions:
1. Do not create a new sessionId/plumbing item. BUG-303 is DONE in repo and serves only as an existing-pattern guardrail.
2. Use one new child item, [[id:BUG-306-managed-buffer-write-failures-must-stay]], for missing-file/existing-file atomicity plus post-save truthfulness.
3. Fix the invariant where it actually breaks:
   - if missing-file invalid-create leaks a file, fix the violating native layer first
   - if bytes persist and only close/invalidation fails afterward, do not report a failed write; surface persisted success with warning instead
4. Keep one mutation representation. No new parallel helper or second sessionId path.
5. Preserve FEAT-585 shrink/parse guards; this plan changes failure truth classification and recovery semantics, not guard policy.

Recommended approach
- Land BUG-306 directly. Its test-first steps pin the missing-file/existing-file contract across native + coding-agent helper/tool paths and then remove the post-save false-failure classification.
