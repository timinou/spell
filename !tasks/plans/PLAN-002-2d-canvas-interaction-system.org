* Vision

Evolve agent-user interaction from 1D (linear chat) to 2D (spatial canvas surfaces). The agent gets a body (QML canvases) alongside its brain (agent swarm), communicating through a priority event queue that can route to independent orchestrator agents.

Three phases, six projects, three waves. Each wave ends with integration checkpoint. Each project ends with human review.

* Design Ethos

Five principles govern all implementation decisions:

1. *The surface is the truth.* If an agent is working, you see it on the canvas. If a queue backs up, you see it. The body never lies about what the brain is doing.
2. *Agents are cheap, coordination is expensive.* Spawn narrow-scope agents over building coordination protocols. The canvas IS the coordination surface -- humans read spatial layout faster than agents pass messages.
3. *Latency is a bug.* Click to visual response < 100ms. Armed tools and local QML state make the body responsive while the brain catches up.
4. *Composition, not configuration.* A canvas is a bag of blocks. An orchestrator is a bag of subscriptions. Components snap together without setup ceremonies.
5. *New needs spawn new worlds.* The agent is a fluid entity -- when a task demands a new surface, it grows one. Extending the system feels like building a new canvas, not wiring into a framework.

* Architecture Decisions (Settled)

These were explored and decided during planning. Implementing agents MUST NOT revisit them.

** AD-1: Tiered Event Dispatch

Three tiers, routed by composition (each tier self-escalates), not configuration:
- *Tier 0: Armed tools.* Direct tool execution from QML, no agent turn. For read/write/simple operations. Existing mechanism, unchanged.
- *Tier 1: Scoped orchestrators.* Lightweight agent session with restricted tools, fixed assignment, and canvas affinity. New concept. Spawned on demand, lives as long as its canvas panel.
- *Tier 2: Full agents.* Full subagent via task executor. User-initiated or escalated from orchestrator.

Escalation is local: armed tool cannot escalate. Orchestrator decides to spawn full agent when its scope is exceeded. QML declares tier via event payload: ~{_tier: "orchestrator", _scope: "review this diff"}~.

** AD-2: Inter-Agent Visibility

Subscription-based channels. Agents subscribe to typed topics. No filtering, no replay, no hierarchies. Priority queue delivers; subscribers pull.

** AD-3: Queue Semantics

Priority levels:
- P0: Armed tool invocations. Always synchronous (fast path preserved, <100ms round-trip). NEVER queued.
- P1: User-initiated events (clicks, prompts, commands). Bounded queue, FIFO within priority.
- P2: Agent-initiated events (canvas updates, status changes). Bounded queue, coalesce on overflow.
- P3: Background (silent events, heartbeats). Bounded queue, drop-oldest on overflow.

Backpressure: P0 bypass queue entirely (sync emit). P1 blocks producer if queue full (user waits, sees loading). P2 coalesces (latest wins). P3 drops silently.

** AD-4: Canvas-in-Shell Architecture

Resolved during PROJ-A (Wave 1). The two options:
- (a) Standalone windows: canvas tool spawns separate OS windows, WM handles layout. Simple. Current model. No shell integration needed.
- (b) Embedded panels: canvas content renders inside shell.qml panels. Richer. Requires panel-scoped event routing.

PROJ-A must produce a proof-of-concept for each and a decision document. All downstream projects depend on this.

** AD-5: Session Model for Meta-Interface

One primary AgentSession owns the chat and session lifecycle. Scoped orchestrators are child sessions (lightweight, restricted tools) with stable panel-scoped IDs. They share the parent's EventBus/priority queue but have independent agent loops.

** AD-6: Persistence

Deferred. "Surface is truth" applies within session lifetime only. QML bridge reconnect() already restores window state from daemon; full content persistence is a future wave.

** ITEM PROJ-C: Priority Event Queue
:PROPERTIES:
:EFFORT: 10h
:LAYER: backend
:END:

*** Objective

Replace the 35-line EventBus with a PriorityEventBus that supports typed channels, priority levels, and backpressure -- without breaking the armed tool fast path.

*** Design

*New class: PriorityEventBus* (replaces ~packages/coding-agent/src/utils/event-bus.ts~)

#+begin_src
interface PriorityEventBus {
  // Sync fast path (P0 armed tools, existing behavior)
  emit(channel: string, data: unknown): void;

  // Async prioritized path (P1-P3)
  enqueue(channel: string, data: unknown, priority: Priority): void;

  // Typed subscription with optional priority filter
  subscribe(channel: string, handler: (data: unknown) => void | Promise<void>, options?: {
    minPriority?: Priority;
  }): () => void;

  // Drain: process queued events (called from agent loop tick)
  drain(maxItems?: number): Promise<number>;

  // Metrics for "surface is truth"
  depth(): { p1: number; p2: number; p3: number };

  clear(): void;
}

enum Priority { P0 = 0, P1 = 1, P2 = 2, P3 = 3 }
#+end_src

*Key invariants:*
- ~emit()~ is synchronous, calls handlers inline. Identical to current behavior. Armed tools use this.
- ~enqueue()~ adds to priority-ordered bounded queue. P2 coalesces (latest per channel+key wins). P3 drops oldest on overflow.
- ~drain()~ is called from the agent loop between turns, processing up to N queued events.
- ~subscribe()~ replaces ~on()~. Same signature plus options.
- Queue bounds: P1 = 100 items, P2 = 50 items, P3 = 20 items. Configurable.

*** Migration

1. Rename current EventBus to LegacyEventBus (keep as fallback during development)
2. Implement PriorityEventBus with tests
3. Update ~packages/coding-agent/src/sdk.ts~:

   - Armed tool invocations (~CANVAS_TOOL_INVOKE_CHANNEL~): keep ~emit()~ (P0 sync fast path)

*** Objective

Implement the three-tier dispatch model: armed tools (existing) \to scoped orchestrators (new) \to full agents (existing). Routing via composition -- each tier self-escalates.

*** Scoped Orchestrator Definition

A scoped orchestrator is:
- A lightweight AgentSession with restricted tool set
- Created on demand when a QML event declares ~_tier: "orchestrator"~
- Bound to a specific canvas window/panel (canvas affinity)
- Has a fixed assignment (natural language scope provided in the event)
- Lives until its canvas closes or it calls ~submit_result~
- Can spawn full agents via a special ~escalate~ tool

*What it is NOT:*
- Not a state machine or rule engine
- Not a framework -- it's literally a task-tool subagent with canvas awareness
- Not persistent across sessions (deferred, see AD-6)

*** Event Payload Protocol

QML events declare dispatch tier in the payload:

#+begin_src
// Tier 0: Armed tool (existing, unchanged)
bridge.send({ _tool: "write", path: "foo.txt", content: "bar" })

// Tier 1: Scoped orchestrator (NEW)
bridge.send({
  _tier: "orchestrator",
  _scope: "Review this diff and suggest improvements",
  _tools: ["read", "grep", "lsp"],  // optional tool restriction
  context: { diffId: "d1", files: ["src/main.ts"] }
})

// Tier 2: Full agent (routes to session.prompt or task tool)
bridge.send({
  _tier: "agent",
  _assignment: "Refactor this module to use the new event bus",
  context: { files: ["src/utils/event-bus.ts"] }
})
#+end_src

*** Implementation

1. *Event extraction* (~packages/coding-agent/src/tools/canvas.ts~ ~#flushEvents~):
   - Currently extracts ~_tool~ events. Extend to also extract ~_tier~ events.
   - ~_tier: "orchestrator"~ \to emit on new ~CANVAS_ORCHESTRATOR_CHANNEL~ at P1
   - ~_tier: "agent"~ \to emit on new ~CANVAS_AGENT_CHANNEL~ at P1

2. *Orchestrator lifecycle* (new file: ~packages/coding-agent/src/orchestrators/canvas-orchestrator.ts~):
   - Subscribe to ~CANVAS_ORCHESTRATOR_CHANNEL~
   - On event: create lightweight agent session via task executor with restricted tools
   - Bind orchestrator to window ID (canvas affinity)
   - If orchestrator already exists for this window, forward event as follow-up
   - On window close: abort orchestrator

3. *Orchestrator agent definition* (new file: ~packages/coding-agent/src/task/agents/canvas-orchestrator.md~):

4. *Escalation tool* (new file: ~packages/coding-agent/src/tools/escalate.ts~):
