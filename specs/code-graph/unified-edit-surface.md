# Unified Edit Surface — Find, Replace, Delete

## 0 · The Agent's Mind

An LLM coding agent doesn't think in OpKind enums. It thinks:

```
"I need to change the body of foo to return 42"
"I need to rename parseConfig to loadConfig everywhere"
"I need to find all console.log and replace with logger.info"
"I need to add a return type annotation to bar"
```

Today the agent must translate intent into taxonomy:

```
"change body of foo" → kind: "symbolReplace" + scope: "body"
"rename parseConfig" → kind: "symbolRename" + newName: "loadConfig"
"replace console.log" → kind: "fileFindReplace" + find: "console.log($$$)" ...
                     → or "symbolFindReplace"? depends on target shape
```

The taxonomy is **kernel knowledge leaking into the agent's decision space.** The agent shouldn't know there's a difference between `symbolReplace` and `fileFindReplace`. It should say "replace X with Y" and let the kernel dispatch.

### The fix: three verbs

```
replace   — universal mutator (body, content, annotation, wrapping, CSS, heading, lines)
rename    — symbol-only rename (rebind identifier, all references)
delete    — remove target (symbol, CSS rule, heading, file)
```

The `target` CodePath determines the mechanism. The `content` template uses positional variables. No OpKind taxonomy. No scope enums. The agent expresses intent; the kernel resolves mechanism.

## 1 · The Unified Action Surface

### `replace` — the universal mutator

```
# Replace symbol entirely (target has ::Symbol, qualifier determines scope)
edit { operations: [{
  target: "foo.ts :: bar",
  action: { kind: "replace", content: "function bar() { return 42; }" }
}] }

# Replace just the body (#body qualifier narrows scope)
edit { operations: [{
  target: "foo.ts :: bar#body",
  action: { kind: "replace", content: "return 42;" }
}] }

# Replace in file by structural find (target IS the find query)
edit { operations: [{
  target: "src/**/*.ts :: §call_expression[name=console.log]",
  action: { kind: "replace", content: "logger.info($1)" }
}] }

# Replace by text find (target is a file, find is text)
edit { operations: [{
  target: "foo.ts",
  action: { kind: "replace", find: "oldPattern", content: "newContent" }
}] }

# Replace a line range
edit { operations: [{
  target: "foo.ts :: §line[10..15]",
  action: { kind: "replace", content: "new\nlines\nhere" }
}] }

# Replace a heading body
edit { operations: [{
  target: "README.md :: Installation",
  action: { kind: "replace", content: "## Setup\n\nNew instructions here." }
}] }

# Replace a CSS selector
edit { operations: [{
  target: "styles.css :: .old-class",
  action: { kind: "replace", content: ".new-class" }
}] }

# Wrap a symbol (content uses $BODY to preserve existing body)
edit { operations: [{
  target: "foo.ts :: unsafeCall",
  action: { kind: "replace", content: "try {\n  $BODY\n} catch (e) {\n  throw new SafeError(e);\n}" }
}] }

# Add annotation before a symbol
edit { operations: [{
  target: "foo.ts :: bar",
  action: { kind: "replace", content: "@deprecated('use baz instead')\n$DECL" }
}] }

# Append text at end of file
edit { operations: [{
  target: "foo.ts",
  action: { kind: "replace", place: "end", content: "\n// generated by spell\n" }
}] }

# Prepend text at start of file
edit { operations: [{
  target: "foo.ts",
  action: { kind: "replace", place: "start", content: "// @ts-check\n" }
}] }
```

### `rename` — symbol rebind

```
edit { operations: [{
  target: "foo.ts :: parseConfig",
  action: { kind: "rename", content: "loadConfig" }
}] }
```

### `delete` — remove target

```
edit { operations: [{
  target: "foo.ts :: deadFunction",
  action: { kind: "delete" }
}] }

edit { operations: [{
  target: "styles.css :: .unused-class",
  action: { kind: "delete" }
}] }

edit { operations: [{
  target: "README.md :: Old Section",
  action: { kind: "delete" }
}] }
```

## 2 · Template Variables

When `content` contains `$NAME`, the kernel substitutes values from the matched node. **The agent never writes capture syntax.** It writes the output it wants, with placeholders for parts to preserve.

| Variable | Resolves to | Example input | Example output |
|----------|-------------|---------------|----------------|
| `$1`, `$2`, ... | Nth child of the matched node (1-indexed) | `logger.info($1)` | `logger.info(x + y)` |
| `$LAST` | Last child of the matched node | `fn($LAST)` | `fn(z)` |
| `$BODY` | Body of the matched declaration (node text between first `{` and last `}`) | `try { $BODY } catch { ... }` | wraps existing body |
| `$NAME` | The name field of the matched declaration | `$NAME_v2` | `parseConfig_v2` |
| `$SIG` | Signature only — everything up to the body opener | `$SIG { ... }` | `function foo(x: number): void { ... }` |
| `$DECL` | Full declaration text (alias for `$MATCH` on declaration nodes) | `@deprecated\n$DECL` | adds annotation above |
| `$MATCH` | Full text of the matched node | `($MATCH) ?? defaultValue` | wraps in nullish coalesce |

### Template variable semantics

`$BODY` on different languages:

```
TS:  function foo() { return 1; }     → $BODY = "return 1;"
RS:  fn foo() -> i32 { 1 }            → $BODY = "1"
PY:  def foo():\n    return 1         → $BODY = "return 1"
GO:  func foo() int { return 1 }      → $BODY = "return 1"
EX:  def foo, do: 1                   → $BODY = "1"
ML:  let foo = () => { return 1; }    → $BODY = "return 1;"
```

All produce parseable output after substitution because the kernel strips the outer delimiters language-appropriately.

### Edge case: `$` in source code

When the source or replacement contains literal `$` (common in bash, PHP, template strings), the kernel distinguishes:

```
Rule:   $NAME  (matches [A-Z][A-Z0-9_]*)  → template variable
        $1, $2, $LAST                     → positional template variables
        $$                                → literal $ (escape)
        $anything-else                    → literal text, passed through

Examples:
  content: "echo $$HOME"          → writes: echo $HOME   ($$ → literal $)
  content: "const x = $PRICE;"    → writes: const x = $PRICE;  ($PRICE has no uppercase, literal)
  content: "${$NAME}_wrapper"     → writes: ${foo}_wrapper     ($NAME matches, substitute)
  content: "$BODY"                → writes: <body text>       ($BODY matches, substitute)
  content: "$$BODY"               → writes: $BODY             (escaped)
```

This eliminates the meta-programming feel. The agent doesn't learn capture syntax — it writes templates with placeholders.

## 3 · Dispatch Chain

The kernel routes `replace`/`rename`/`delete` to the correct resolver based on the target shape:

```
target shape                      → resolver              → internal mechanism
─────────────────────────────────────────────────────────────────────────────
"file.ts :: Symbol"               → CodeResolverImpl      → `replace` → symbolReplace(whole)
"file.ts :: Symbol#body"          → CodeResolverImpl      → `replace` → symbolReplace(body)
"file.ts :: Symbol#sig"           → CodeResolverImpl      → `replace` → symbolReplace(sig)
"file.ts :: Symbol#hover"         → CodeResolverImpl      → `replace` → symbolReplace(sig)
"file.ts" (with `find` field)     → FsResolver            → fileFindReplace
"file.ts" (bare content)          → FsResolver            → fileWrite
"file.ts :: §line[a..b]"          → TextResolver          → lineReplace
"file.ts :: §chunk[text~=...]"    → TextResolver          → chunkReplace
"file.md :: Heading"              → HeadingResolver       → headingReplaceBlock
"file.org :: Heading"             → HeadingResolver       → headingReplaceBlock
"file.css :: .selector"           → CssResolver           → cssRenameClassToken
"file.css :: #id"                 → CssResolver           → cssRenameIdToken
"file.css :: --custom-prop"       → CssResolver           → cssRenameCustomProp
"**/*.ts :: §kind[pred]"          → glob + CodeResolver   → batch replace
"**/*.ts :: Name"                 → glob + CodeResolver   → batch symbol replace

"file.ts :: Symbol"               → CodeResolverImpl      → `rename` → symbolRename
"**/*.ts :: Name"                 → glob + CodeResolver   → batch rename (auto-follows re-exports)

"file.ts :: Symbol"               → CodeResolverImpl      → `delete` → symbolDelete
"file.css :: .selector"           → CssResolver           → `delete` → cssRemoveDeadStyle
"file.md :: Heading"              → HeadingResolver       → `delete` → headingRemove (new)
"file.ts"                         → FsResolver            → fileDelete
```

### How `replace` with `find` field works

When the action has a `find` field, the target narrows the search space, and `find` specifies what to replace within each match:

```
edit { operations: [{
  target: "**/*.ts :: §call_expression[name=console.log]",
  action: { kind: "replace", find: "console.log($$)", content: "logger.info($1)" }
}] }
```

The kernel:
1. Glob expands `**/*.ts` → file list
2. CodePath resolver: for each file, find all `call_expression` nodes with `name=console.log`
3. For each matched node's subtree, match the `find` structural pattern
4. Extract `$1` from the match
5. Substitute into `content` template
6. Compute byte-range edit
7. Apply via `buffer_registry().edit_transaction()`

The `find` field is a **structural pattern applied to the subtree rooted at each resolved CodePath node.** It uses the same ast-grep-style pattern grammar internally but the agent never writes metavariables — positional captures (`$1`, `$2`) and named variables (`$NAME`, `$BODY`) are auto-derived from the tree structure.

## 4 · Error Hints — Friendly Diagnostics

When an edit fails, the diagnostic must guide the agent to self-correct without taxonomy knowledge.

### 4.1 Target not found

```
Diagnostic {
  variant: "no_matches",
  message: "No symbol 'parseConfg' found in foo.ts.
            Did you mean: parseConfig (line 42), parseContent (line 87)?",
  span: Some(parseConfg@5:1-5:11),
  hint: "Try: find { target: \"foo.ts::§function\" } to see available symbols."
}
```

The hint is tool-surface-aware — it suggests a `find` query the agent can use to debug.

### 4.2 Qualifier not applicable

```
Diagnostic {
  variant: "qualifier_not_applicable",
  message: "Qualifier #body does not apply to node kind 'import_statement'.
            #body applies to: function_declaration, method_definition, arrow_function, ...",
  span: Some(#body@22:1-22:6),
  hint: "Drop the qualifier to replace the whole node, or adjust the target path."
}
```

Lists exactly which node kinds accept the qualifier, in language-appropriate terms.

### 4.3 Template variable unresolvable

```
Diagnostic {
  variant: "template_var_unresolvable",
  message: "$BODY used in content but the matched node 'import_statement'
            has no body. $BODY is valid for: function, method, class, module, block.",
  span: Some($BODY@1:5-1:10),
  hint: "Use $MATCH to reference the full matched text, or adjust the target."
}
```

### 4.4 Parse error after edit

```
Diagnostic {
  variant: "post_edit_parse_error",
  message: "Edit produced unparseable output in foo.ts at line 15.
            The edit: replace 'function ()' → 'function ()' caused a syntax error.
            tree-sitter: 'ERROR at (14:1-15:5): expected identifier'",
  hint: "Check that the replacement text is syntactically valid in TypeScript.
         The surrounding code expects a named function, not an anonymous one."
}
```

### 4.5 Ambiguous target

```
Diagnostic {
  variant: "ambiguous_target",
  message: "Target 'foo' matches 3 symbols in bar.ts:
            1. foo (function, line 42)
            2. foo (class method, line 87)
            3. foo (arrow const, line 120)
            Use a more specific path, e.g. 'bar.ts::FooClass.foo' or 'bar.ts::§function[name=foo]'.",
  hint: "Narrow the target with a structural axis: §function[name=foo] or a parent combinator."
}
```

### 4.6 Batch replace summary

When a glob target produces multiple file edits, the result is aggregated:

```

  files: [
    { path: "src/a.ts", matches: 3, status: "applied" },
```

### 5.2 Test harness

```rust
/// Assert that applying { action } to the fixture with { target } produces { expected }.
/// Also verifies the output re-parses without syntax errors.
fn assert_edit(
    lang: &str,
    fixture: &str,             // input file content
    target: &str,              // CodePath target, e.g. "test.ts::foo#body"
    action: serde_json::Value, // { kind: "replace", content: "..." } | { kind: "rename", content: "n" } | { kind: "delete" }
    expected: &str,            // expected file content after edit
) {
    let dir = tempfile::tempdir().unwrap();
    let ext = extension_for_lang(lang);
    let path = dir.path().join(format!("test.{ext}"));
    std::fs::write(&path, fixture).unwrap();

    let cp = parse_code_path(target).unwrap();
    let op = unified_op_from_action(&cp, &action)
        .unwrap_or_else(|e| panic!("failed to build op for {lang}/{target}: {e}"));

    let mut resolver = resolver_for_lang(lang);
    resolver.set_root(dir.path());

    let result = resolver.try_apply(&op, &CancellationToken::new())
        .expect("resolver should accept op")
        .unwrap_or_else(|d| panic!("edit failed for {lang}/{target}: {}", d.message));

    let actual = std::fs::read_to_string(&path).unwrap();
    assert_eq!(actual, expected,
        "\n═══ FAIL: {lang} ═══\nTARGET: {target}\nFIXTURE:\n{fixture}\nEXPECTED:\n{expected}\nACTUAL:\n{actual}\n═══"
    );

    // Verify output parses
    let reparse = reparse_file(lang, &actual);
    if !reparse.errors.is_empty() {
        let error_summary: Vec<String> = reparse.errors.iter()
            .map(|e| format!("  L{}:{} {}", e.row + 1, e.col + 1, e.message))
            .collect();
        panic!(
            "\n═══ PARSE ERROR: {lang} ═══\nTARGET: {target}\nEdit produced unparseable output:\n{}\nOUTPUT:\n{actual}\n═══",
            error_summary.join("\n")
        );
    }
}
```

### 5.5 Dollar sign literal tests

Every language fixture has a `dollar_signs.*` file. These tests verify that `$` in source code never gets incorrectly captured or substituted:

```
# TypeScript template string
Input:  const PRICE = "$100"; const msg = `total: $${PRICE}`;
Target: test.ts::msg#body
Action: { kind: "replace", content: "`amount: $${PRICE} USD`" }
Expect: const PRICE = "$100"; const msg = `amount: ${PRICE} USD`;

# Rust macro
Input:  macro_rules! dollar { ($x:expr) => { format!("${}", $x) } }
Target: test.rs::dollar#body
Action: { kind: "replace", content: "format!(\"\\${}\", $1)" }
Expect: dollar expands to format!("${}", <expr>)  (unchanged semantics)

# Bash/Shell (though not in the test matrix — example of escape rule)
Input:  echo "cost: $PRICE"
Target: test.sh
Action: { kind: "replace", find: "echo \"cost: $PRICE\"", content: "printf 'cost: %s\\n' \"$$PRICE\"" }
Expect: printf 'cost: %s\n' "$PRICE"

# CSS content property
Input:  .price::after { content: " $"; }
Target: text.css::.price
Action: { kind: "replace", content: ".price::after { content: \" \u20ac\"; }" }
Expect: .price::after { content: " €"; }
```

Rule summary for `$`:
- `$NAME` where NAME matches `[A-Z][A-Z0-9_]*` → template variable
- `$1`, `$2`, `$LAST` → positional variables
- `$$` → literal `$` (escape)
- `$` followed by non-uppercase → literal (e.g., `$100`, `$HOME`, `$var`)
- `$` followed by `{` → literal (JS template syntax doesn't collide)
- `$` at end of line → literal

## 6 · Dispatch Architecture

### 6.1 From action to Op

`unified_op_from_action()` maps the unified 3-verb surface to internal `Op` variants:

```rust
fn unified_op_from_action(
    cp: &CodePath,
    action: &UnifiedAction,
) -> Result<Op, Diagnostic> {
    match action.kind {
        "replace" => {
            let content = action.content.as_deref();
            let find = action.find.as_deref();

            match (cp.target_shape(), content, find) {
                // Symbol-scoped: target has ::Symbol and qualifier
                (TargetShape::Symbol { qualifier: Some("body") }, Some(c), None) =>
                    Ok(Op::SymbolReplace { target, scope: SymScope::Body, content: c.into() }),

                (TargetShape::Symbol { qualifier: Some("sig") }, Some(c), None) =>
                    Ok(Op::SymbolReplace { target, scope: SymScope::Sig, content: c.into() }),

                (TargetShape::Symbol { qualifier: None }, Some(c), None) =>
                    Ok(Op::SymbolReplace { target, scope: SymScope::Whole, content: c.into() }),

                // Symbol-scoped with find: find-and-replace within symbol body
                (TargetShape::Symbol { .. }, Some(c), Some(f)) =>
                    Ok(Op::SymbolFindReplace { target, find: f.into(), content: c.into(), occurrence: None }),

                // Glob + symbol path with find: batch structural find-replace
                (TargetShape::GlobSymbol, Some(c), Some(f)) =>
                    Ok(Op::BatchFindReplace { target, find: f.into(), content: c.into() }),

                // Glob + symbol path without find: batch rename/delete
                (TargetShape::GlobSymbol, Some(c), None) =>
                    Ok(Op::BatchReplace { target, content: c.into() }),

                // File-scoped with find: text-level find-and-replace
                (TargetShape::File, Some(c), Some(f)) =>
                    Ok(Op::FileFindReplace { target, find: f.into(), content: c.into(), occurrence: None }),

                // File-scoped bare content: overwrite
                (TargetShape::File, Some(c), None) =>
                    Ok(Op::FileWrite { target, content: c.into(), force: false }),

                // Line-scoped
                (TargetShape::Line, Some(c), None) =>
                    Ok(Op::LineReplace { target, span, content: c.into() }),

                // Heading-scoped
                (TargetShape::Heading, Some(c), None) =>
                    Ok(Op::HeadingReplaceBlock { target, content: c.into() }),

                // CSS-scoped
                (TargetShape::Css, Some(c), None) =>
                    css_replace_op(cp, target, c),

                _ => Err(Diagnostic {
                    variant: DiagnosticVariant::IncompatibleTargetShape,
                    message: format!("replace with this target shape + content/find combination is not supported"),
                    span: None,
                    hint: Some("Use find { target: \"...\" } first to inspect the target shape.".into()),
                }),
            }
        },

        "rename" => {
            // Only for symbol targets
            match cp.target_shape() {
                TargetShape::Symbol { .. } | TargetShape::GlobSymbol =>
                    Ok(Op::SymbolRename { target, new_name: Identifier(content.into()) }),
                _ => Err(Diagnostic {
                    variant: DiagnosticVariant::IncompatibleTargetShape,
                    message: "rename requires a symbol target (e.g. 'file.ts :: funcName')".into(),
                    span: None,
                    hint: Some("Use replace to change text content in non-symbol targets.".into()),
                }),
            }
        },

        "delete" => {
            match cp.target_shape() {
                TargetShape::Symbol { .. } => Ok(Op::SymbolDelete { target, allow_sibling_delete: false }),
                TargetShape::File => Ok(Op::FileDelete { target }),
                TargetShape::Heading => Ok(Op::HeadingRemove { target }),   // new Op variant
                TargetShape::Css => Ok(Op::CssRemoveDeadStyle { target }),
                _ => Err(Diagnostic {
                    variant: DiagnosticVariant::IncompatibleTargetShape,
                    message: format!("delete not supported for this target shape"),
                    span: None,
                    hint: Some("Try: find { target: \"...\" } to inspect the target.".into()),
                }),
            }
        },

        _ => Err(Diagnostic {
            variant: DiagnosticVariant::ParseError,
            message: format!("unknown action kind '{}'. Use: replace, rename, delete.", action.kind),
            span: None,
        }),
    }
}
```

### 6.2 Template variable expansion

Template expansion happens **after** the target is resolved but **before** the byte-range edit is computed:

```rust
fn expand_template(
    content: &str,
    matched_node: Node<'_>,
    source: &str,
) -> Result<String, Diagnostic> {
    let mut result = String::with_capacity(content.len());
    let mut chars = content.chars().peekable();

    while let Some(ch) = chars.next() {
        if ch == '$' {
            match chars.peek() {
                Some('$') => {
                    chars.next(); // skip second $
                    result.push('$'); // literal $
                },
                Some('{') => {
                    // ${...} → literal (pass-through for JS template syntax)
                    result.push('$');
                    result.push('{');
                    chars.next();
                },
                Some(c) if c.is_ascii_digit() => {
                    // $1, $2, ... → positional child
                    let n = parse_number(&mut chars);
                    if n == 0 {
                        // $0 → full match → $MATCH
                        result.push_str(&source[matched_node.start_byte()..matched_node.end_byte()]);
                    } else {
                        match nth_child(matched_node, n - 1) {
                            Some(child) => result.push_str(&source[child.start_byte()..child.end_byte()]),
                            None => return Err(Diagnostic {
                                variant: DiagnosticVariant::TemplateVarUnresolvable,
                                message: format!("${n}: node has fewer than {n} children"),
                                span: None,
                                hint: Some("Use $MATCH for the full matched text.".into()),
                            }),
                        }
                    }
                },
                Some('L') => {
                    chars.next();
                    if consume_token(&mut chars, "AST") {
                        // $LAST → last child
                        match children(matched_node).last() {
                            Some(child) => result.push_str(&source[child.start_byte()..child.end_byte()]),
                            None => return Err(template_err("$LAST", "node has no children", "Use $MATCH.")),
                        }
                    } else {
                        result.push_str("$L");
                    }
                },
                Some(c) if c.is_uppercase() => {
                    // $NAME, $BODY, $SIG, $DECL, $MATCH
                    let name = consume_uppercase_token(&mut chars);
                    match name.as_str() {
                        "BODY" => {
                            let body_range = extract_body(matched_node, source)
                                .ok_or_else(|| template_err_with_hint(
                                    "$BODY", "node has no body", m
                                    "Use $MATCH for the full text, or target a declaration node.",
                                ))?;
                            result.push_str(&source[body_range]);
                        },
                        "NAME" => {
                            let name_text = extract_name_field(matched_node, source)
                                .ok_or_else(|| template_err_with_hint(
                                    "$NAME", "node has no name field",
                                    "Use a declaration node (function, class, variable) for $NAME.",
                                ))?;
                            result.push_str(name_text);
                        },
                        "SIG" => {
                            let sig_end = hover_signature_end(&source[matched_node.start_byte()..matched_node.end_byte()]);
                            result.push_str(&source[matched_node.start_byte()..matched_node.start_byte() + sig_end]);
                        },
                        "DECL" | "MATCH" => {
                            result.push_str(&source[matched_node.start_byte()..matched_node.end_byte()]);
                        },
                        other if other.chars().all(|c| c.is_uppercase() || c == '_') => {
                            // Unknown template var → diagnostic, not silent pass-through
                            return Err(template_err_with_suggestions(
                                &format!("${other}"),
                                "unknown template variable",
                                &["BODY", "NAME", "SIG", "DECL", "MATCH"],
                            ));
                        },
                        other => {
                            // Mixed case (e.g. $Home, $Price) → literal
                            result.push('$');
                            result.push_str(other);
                        },
                    }
                },
                _ => {
                    // $ followed by non-uppercase, non-digit → literal
                    result.push('$');
                },
            }
        } else {
            result.push(ch);
        }
    }

    Ok(result)
}
```

## 8 · Prompt Hint Templates

The agent's tool description for `edit` should include a compact pattern language the LLM can scan. Not a spec — a cheat sheet.

```markdown
## edit { operations: [{ target, action }] }

| want | target | action |
|------|--------|--------|
| change function body | `"file.ts :: foo#body"` | `{ kind: "replace", content: "return 42;" }` |
| rewrite whole function | `"file.ts :: foo"` | `{ kind: "replace", content: "function foo() { ... }" }` |
| rename everywhere | `"**/*.ts :: oldName"` | `{ kind: "rename", content: "newName" }` |
| replace pattern in match | `"**/*.ts :: §call[name=console.log]"` | `{ kind: "replace", content: "logger.info($1)" }` |
| wrap in try/catch | `"file.ts :: risky"` | `{ kind: "replace", content: "try { $BODY } catch(e) { throw new SafeError(e); }" }` |
| add annotation | `"file.ts :: func"` | `{ kind: "replace", content: "@deprecated\n$DECL" }` |
| delete dead symbol | `"file.ts :: dead"` | `{ kind: "delete" }` |
| replace text in file | `"file.ts"` | `{ kind: "replace", find: "old", content: "new" }` |
| replace heading content | `"README.md :: Setup"` | `{ kind: "replace", content: "## Setup\n\n..." }` |
| rename CSS class | `"app.css :: .old"` | `{ kind: "replace", content: ".new" }` |

Template variables: $1 $2 $LAST $BODY $NAME $SIG $DECL $MATCH
Escape $ with $$ for literal dollar signs.
```

## 9 · What Gets Deprecated

When the unified surface ships, the following internal Op variants become **implementation details** of `unified_op_from_action()`. The agent never sees them:

| Internal Op | Absorbed by |
|-------------|-------------|
| `SymbolReplace` (whole/body/sig) | `replace` + qualifier on target |
| `SymbolWrap` | `replace` with `$BODY` in content |
| `SymbolInsertBefore` | `replace` with `content\n$DECL` in content |
| `SymbolInsertAfter` | `replace` with `$DECL\ncontent` in content |
| `SymbolFindReplace` | `replace` with `find` field |
| `SymbolRawTextReplace` | absorbed — structural replace handles it |
| `FileFindReplace` | `replace` with `find` field on file target |
| `FileRawTextReplace` | absorbed as above |
| `FileWrite` | `replace` on bare file target without `find` |
| `LineReplace` | `replace` on `§line[a..b]` target |
| `LineInsert` | `replace` on `§line[a..a]` with inserted lines |
| `LineAppend` | `replace` with `place: "end"` or `§line[last]` target |
| `LinePrepend` | `replace` with `place: "start"` or `§line[1]` target |
| `HeadingReplaceBlock` | `replace` on heading target |
| `CssRenameClassToken` | `replace` on CSS class target |
| `CssRenameIdToken` | `replace` on CSS id target |
| `CssRenameCustomProp` | `replace` on CSS custom property target |

The existing Op enum stays for backwards compatibility in tests and internal dispatch, but the TS tool surface only accepts `replace`/`rename`/`delete`.
