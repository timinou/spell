# Go Dialect

Applies to `.go`. Package is declared at the top of each file; the Locator plus the package declaration disambiguate. Build tags and `_test.go` suffix affect inclusion; the resolver honors the active build constraints from `go.env` / `GOOS` / `GOARCH` / explicit overrides.

---

## A · NamePayload shape

```rust
pub struct GoName {
    package: Option<SmolStr>,           // cross-file reference (other pkg)
    receiver: Option<GoReceiver>,        // (*T) or (T) for methods
    segments: Vec<GoSegment>,
    generics: Option<GenericsShape>,     // Go 1.18+ type instantiation
}

pub enum GoSegment {
    Ident(SmolStr),
    Blank,                              // _
}

pub enum GoReceiver {
    Value(SmolStr),                     // (Buffer)
    Pointer(SmolStr),                   // (*Buffer)
}
```

### Composition rules

```
pkg.Type                    package-qualified type or top-level binding
Buffer.Write                method on type — same dot form Go's own doc uses
(*Buffer).Close             pointer receiver, Go's canonical form
(Buffer).Read               value receiver (rare but explicit)
List[T].Get                 generic type instantiation (Go 1.18+)
`weird.name`                backtick for separator-in-name
_                           blank identifier (addressable in var decls)
```

Pointer-receiver form `(*T).Method` matches `go doc`, stack traces, and `go/ast` canonical output. Value-receiver form `(T).Method` is used only when both receiver variants exist for the same method name — otherwise the bare `T.Method` works.

## B · Registries

### Qualifiers (`#name`)

```
#body                function/method body block
#name                declaration's identifier
#sig                 param list + return types, no body
#receiver            the receiver declaration on a method (e.g. `b *Buffer`)
#returns             the return-type list
#type-params         generic type parameters (Go 1.18+)
#struct-tag[key]     struct-tag value for given key (`json`, `xml`, …)
#interface-method-set the method set of an interface declaration
#named-returns       the named return-value declarations if present
#imports             import specs as a set (module-scoped form)
```

### Anchors (`¶name`)

```
¶defer               every defer statement in scope
¶goroutine           every `go f(...)` launch in scope
¶select-default      the default clause of a select statement
¶init                any `func init()` in the file
¶main                `func main()` in a main package
¶test-body           body of a `func TestXxx(t *testing.T)`
¶benchmark-body      body of a `func BenchmarkXxx(b *testing.B)`
¶return              every return statement
¶guard               early-return pattern at function entry
¶channel-send        every `ch <- x` in scope
¶channel-receive     every `<-ch` in scope
```

### Edges (`→`)

```
ref→         name-use → declaration
def→         declaration → all references
call→        CallExpr → callee declaration
import→      ImportSpec → package being imported
type→        type-position ident → type declaration
implements→  concrete type → interfaces it implements (set-valued)
implemented-by→  interface → concrete implementations (set-valued)
embeds→      struct field that is an embedded type → the embedded declaration
iface-method→ interface method → implementations across the module
```

## D · Edge cases

```
D-1  Value and pointer methods with same name:
         func (b Buffer) String() string
         func (b *Buffer) Reset()
     Bare `Buffer.String` resolves to the value-receiver method.
     Bare `Buffer.Reset` resolves to the pointer-receiver method.
     When both exist for the same name, require explicit receiver
     form:  `(Buffer).M`  vs  `(*Buffer).M`.

D-2  Method set asymmetry: an interface method set with pointer-
     receiver methods is satisfied only by `*T`, not `T`.
     implements→ respects method-set rules; test coverage explicit.

D-3  Blank identifier: `var _ SomeInterface = (*Impl)(nil)`.
     Addressable via ordinal on the file-level var declaration:
         pkg/impl.go :: //§var_declaration[name=_][0]

D-4  Multiple init functions per file: addressable by ordinal
         pkg/init.go :: ¶init[0]  vs  ¶init[1]

D-5  Package-level shadowing: `var fmt = …` in a file shadows the
     imported `fmt`. ref→ on `fmt.Println` inside that file
     diagnoses the shadow and returns the local var.

D-6  Generic type vs generic function: `List[T]` on a type is the
     type, on a call is the instantiation. Payload uses the same
     shape; resolver consults context.

D-7  Embedded type field access: `S.Inner.Method` may resolve to a
     method promoted through the embedded field. Use embeds→ to
     chain explicitly:
         S/embeds→[type=Inner]/Method

D-8  Internal packages: `internal/x` is importable only from within
     the containing subtree. import→ respects the rule and
     diagnoses violations.

D-9  Vendor directories: `vendor/github.com/x/y` resolves as a
     replacement for the external module. Locator uses the
     vendored path; ref→ resolves transparently.

D-10 Build-constrained files: `//go:build linux` restricts
     compilation. Resolver queries use the active build constraint;
     files excluded by constraints are addressable only when
     explicitly requested.

D-11 `cgo` imports: `import "C"` is a pseudo-package. NamePayload
     allows `C.some_fn`; type→ resolves to preamble comments or
     unresolved (with diagnostic).

D-12 Test files: `Xxx_test.go` lives in the same package unless
     `package xxx_test`. The dialect treats both as the same
     dialect; _test package is a separate Locator scope.

D-13 Interface embedding: `type W interface { io.Writer; Flush() }`.
     W's method set includes `Write` from io.Writer; iface-method→
     resolves across embedded interfaces.
```
