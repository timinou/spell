** ITEM hard-fork-from-oh-my-pi-rename-to-spell-scope

Spell hard-forked from upstream =@oh-my-pi/*= npm scope to =@spell/*= on 2026-05-30.

Rationale: BUG-424 (lone-ESC infinite loop in =break_long_word=) surfaced that bun's install cache for =@oh-my-pi/pi-natives@<version>= could shadow our workspace at any resolution boundary. Source-code fixes had no effect on running spell instances when bun resolved imports to a cached published binary instead of the workspace.

The structural fix is name divorce: if our packages don't share a scope with upstream, the cache cannot shadow them by name.

** Topology after rename

| upstream scope          | spell scope            |
|-------------------------|------------------------|
| @oh-my-pi/pi-natives    | @spell/pi-natives      |
| @oh-my-pi/pi-coding-agent | @spell/pi-coding-agent |
| @oh-my-pi/pi-ai          | @spell/pi-ai           |
| ... (19 packages total)  | ...                    |

URLs: =github.com/can1357/oh-my-pi= \u2192 =github.com/timinou/spell=.

** Three layers of structural enforcement

1. =packages/natives/src/native.ts::assertTrustedNativePath= \u2014 rejects any candidate binary path outside {nativeDir, execDir, versionedDir, userDataDir} at load time.
2. =packages/utils/test/no-upstream-references.test.ts= \u2014 repo-wide CI test that fails if any file outside the historical-record allowlist contains =@oh-my-pi/=.
3. =biome.json::noRestrictedImports= \u2014 every =@oh-my-pi/<pkg>= import literal is a lint error with a targeted "use @spell/<pkg>" message.

** Phantom-dep fixes surfaced

The rename exposed three packages with imports they didn't declare (bun's cache had been auto-resolving them silently):

- =@spell/pi-coding-agent=: + =@spell/pi-desktop-common=
- =@spell/react-edit-benchmark=: + =@spell/pi-ai=, =@spell/pi-tui=
- =@spell/swarm-extension=: + =@spell/pi-utils=
- =@spell/pi-utils= (devDep): + =@spell/pi-natives= (test-only)
