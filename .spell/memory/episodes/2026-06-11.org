** ITEM W4-write (FUP-112) shipped: stored PTC-Lisp programs may now MUTATE transactionally, riding D3's all-or-nothing lane + W4-read's guard infrastructure (NO new runtime). KEY DESIGN: three-valued RunIntent supplied by the CALLER (not baked in the program) \u2014 interactive (writes commit) | visible-refresh (dry-run preview, the product for a watching human) | background-tick (inert unless tile armed autoWrite). The intent is a property of the RUN CONTEXT, not the program \u2014 the same stored program behaves correctly in all three depending on how a caller (dashboard tile / canvas / scheduled tick) wires it. KEY LESSON (reviewer caught a P1 silent-mutation): the FIRST design gated on a declared StoredProgram.mode field that defaults to 'read' \u2014 so a write program with OMITTED or lost mode would fall through the read path and COMMIT ungated under visible-refresh/background-tick (the exact silent mutation the feature exists to prevent). FIX = make safety a RUNTIME BACKSTOP not a declared flag: read mode (incl. omitted) runs the program but DISCARDS any file write (force-rollback) in EVERY intent, reporting a loud read-only-violation. Safe-by-discard, not safe-by-declaration. General principle: a safety gate must key on what the code DOES at runtime, never on a declarable/omittable attribute \u2014 the same lesson as D3's W2 (dynamic dispatch guard beats static regex). Added 'inert' TxnOutcome distinct from 'none' so a tile tells 'skipped-unarmed' from 'ran-no-writes'. Structured TxnOutcome {outcome, files, paths, restoreFailures} on details.transaction so tile hosts RENDER from it, never recompute rollback. Wrote 4 grounded consumer use-case FUPs each landing in its natural intent quadrant: FUP-119 codemod tile (visible-refresh drift preview), FUP-120 derived-doc sync (visible-refresh row-diff), FUP-121 format-drift (dual-context synthesis proving intent is contextual), FUP-122 nightly changelog (background-tick, justifies inert-default). 13 W4-write + 192 ptc-runtime tests green.
