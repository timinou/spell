* Overview

Each journey is a numbered, end-to-end scenario that exercises one coherent user
goal.  Steps are written in behavioural language so they can be translated
directly into =GrowthJourney= + =QmlJourney= test bodies.

Fixture references use paths relative to =domain/growth/=.

* Journeys

** J01 First Launch
:PROPERTIES:
:ID:       j01-first-launch
:TAGS:     dashboard empty-state onboarding
:FIXTURES: none
:END:

User opens the Growth shell for the first time.  No data has been scraped.
The dashboard must communicate zero-state clearly and invite the first scan.

*** Steps

1. Launch =GrowthShell.qml= with no =dbPath= (fresh =:memory:= database, no
   seeds applied).
2. Assert the active panel is =dashboard=.
3. Assert the dashboard renders a scan-prompt widget (text contains "No data yet"
   or equivalent empty-state copy).
4. Assert all MetricCard values are 0: =active_ads=, =total_ads=, =total_pages=.
5. Assert no AdCard components are present in the panel.

*** Expected Outcomes

- Dashboard visible, no error state.
- All numeric metrics read 0.
- A visible call-to-action prompts the user to run their first scan.

*** Required Fixtures

None.  The empty database is the fixture.

scan and review the results.

4. Assert =journey.expectMode("intel")= passes (Research defaultMode = "intel").
5. Assert the IntelPanel is the main panel in view.

   =stub-responses/intel-response.json= via =QmlJourney.agentSends=.

8. Assert the result card contains the competitor name from the stub response.

*** Expected Outcomes

- Workspace switch activates the correct layout (intel main, chat secondary).
- Mode is set to =intel= automatically.
- Intel results render after the agent delivers the stub payload.

** J07 Workspace Switching
:PROPERTIES:
:ID:       j07-workspace-switching
:TAGS:     workspace navigation state-preservation layout
:FIXTURES: none
:END:

User cycles through Research → Strategy → Create workspaces and verifies
that each layout loads the correct panels and that chat history is preserved
across switches.

*** Steps

1. Launch =GrowthShell.qml= with the default (=general=) workspace.
2. Submit a chat message: "Test message before switching."
3. Switch to the Research workspace.
4. Assert =journey.expectWorkspace("Research")=.
5. Assert IntelPanel is in the main slot.
6. Switch to the Strategy workspace.
7. Assert =journey.expectWorkspace("Strategy")=.
8. Assert the chat history still contains "Test message before switching."
9. Switch to the Create workspace.
10. Assert =journey.expectWorkspace("Create")=.
11. Assert the editor panel is the main panel.
12. Switch back to the General workspace.
13. Assert workspace is =general= and chat panel is visible.

*** Expected Outcomes

- Each workspace renders its configured panel layout.
- Chat history survives workspace switches (state preservation).
- Switching is non-destructive; no panel state is lost.

*** Required Fixtures

None.

** J08 Multi-Agent Chat
:PROPERTIES:
:ID:       j08-multi-agent-chat
:TAGS:     chat-drawer agents tabs task-agent
:FIXTURES: none
:END:

User opens the chat drawer and sees both the main Spell agent tab and an
active task-agent tab spawned for a background job.

*** Steps

1. Launch =GrowthShell.qml=.
2. Assert the chat drawer has exactly one tab (main agent).
3. Simulate the main agent spawning a task agent via a =_tool= bridge message
   with =action: "spawn_task_agent"= and =id: "task-agent-1"=.
4. Assert a second tab appears in the ChatDrawer with label "Task Agent" or
   the task description.
5. Click the second tab.
6. Assert the active chat view switches to the task-agent conversation.
7. Simulate the task agent sending a completion message.
8. Assert the tab is marked complete (indicator or label change).
9. Click back to the main agent tab.
10. Assert the main agent conversation is still intact.

*** Expected Outcomes

- ChatDrawer renders one tab per active agent.
- Tabs are independently scrollable and state-preserving.
- Completion of a task agent is visually indicated.

*** Required Fixtures

None.

** J12 Template Hydration
:PROPERTIES:
:ID:       j12-template-hydration
:TAGS:     template hydration typst data-binding render
:FIXTURES: test/fixtures/seed-pages.sql test/fixtures/seed-ads.sql
:END:

User selects a template from the TemplateSelector, provides the required data
fields, and verifies the rendered Typst output reflects the input.

*** Steps

1. Create =GrowthJourney=, seed fixture files.
2. Launch =GrowthShell.qml= with seeded =dbPath= and the Create workspace.
3. Open the TemplateSelector component (sidebar action or panel toolbar).
4. Assert the selector lists at least: =campaign-brief=,
   =competitive-analysis=, =client-proposal=, =weekly-digest=.
5. Select =competitive-analysis=.
6. Assert the data-entry form renders with the required fields from
   =templates/competitive-analysis.json=.
7. Fill in the field "client_name" with "Nexus Software".
8. Fill in the field "competitor_name" with "Delta Systems".
9. Submit the form (click "Generate" or equivalent).
10. Assert the Typst editor pane shows a non-empty document.
11. Assert the rendered document contains the text "Nexus Software".
12. Assert the rendered document contains the text "Delta Systems".
13. Assert no compile-error banner is visible.

*** Expected Outcomes

- TemplateSelector enumerates all committed templates.
- Hydration substitutes all named fields into the Typst source.
- The preview renders cleanly for a well-formed substitution.
