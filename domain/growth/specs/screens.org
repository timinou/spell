* Shell Layout
** Overview

Spell Growth runs in always-canvas mode. The QML window is the primary interface; the
TUI serves only as the launcher. The shell reuses the existing =shell.qml= architecture
(=packages/coding-agent/src/modes/qml/shell.qml=) — =SplitView= with sidebar + main
content — but with growth-specific panels, a wider sidebar, and a persistent bottom chat
bar that remains visible across all panels.

** Data Flow
- =bridge.props.panels=: Array of ={id, title, icon, path}= — bootstrapped from
  =growth-mode.ts= analogous to =qml-mode.ts=.
- =bridge.messageReceived=: Dispatches payloads to the active panel via
  =handleMessage(payload)= — same pattern as coding shell.
- =bridge.send({ type: "user_message", text })=: Chat input from persistent bar.
- =bridge.send({ type: "panel_switch", panelId })=: Sidebar navigation click.
- =bridge.send({ type: "new_deliverable" })=: Opens wizard modal.

** Differences from Coding Shell
| Aspect             | Coding (shell.qml)         | Growth (GrowthShell.qml)          |
|--------------------+----------------------------+-----------------------------------|
| Sidebar width      | 240px                      | 280px (richer nav, client badges) |
| Chat input         | Inside ChatPanel only      | Persistent bar, all panels        |
| Default panels     | Chat, Dashboard            | Chat, Dashboard, Intel, Editor, Clients |
| Footer             | None                       | "+ New Deliverable", Settings     |
| Default window     | 1280x800                   | 1440x900                          |

* Panel: Chat
** Overview

Agent conversation panel. Reuses =ChatPanel.qml=
(=packages/coding-agent/src/modes/qml/panels/ChatPanel.qml=) with zero modifications.
Shows agent messages with markdown rendering, tool execution progress (thinking blocks,
tool calls with status), and image results. The input bar at the bottom of the chat
panel is supplementary to the persistent shell-level =ChatInputBar= — when the Chat
panel is active, the shell bar delegates focus to the panel's native input.

** User Interactions
- Click a metric card: navigates to the relevant panel (Intel for ads, pipeline for deliverables).
- Click a competitor ad row: switches to Intel panel, filtered to that advertiser.
- Click a calendar event: opens the linked deliverable in the Report Editor.
- Quick action buttons: trigger agent commands (open modal, start scan, switch to review mode).
- Pull-to-refresh (or button): sends =bridge.send({ type: "refresh_dashboard" })=.

Item {                                       // CompetitiveIntelPanel.qml
    id: intelPanel

    property string viewMode: "grid"         // "grid" | "list"
    property var filters: ({
        query: "",
        dateFrom: "",
        dateTo: "",
        format: "",                          // "image" | "video" | "carousel" | ""
        status: "",                          // "active" | "inactive" | ""
        platform: "facebook"
    })
    property bool drawerOpen: false
    property var selectedAd: null

    function handleMessage(payload) {
        if (payload.type === "ads_loaded") loadAds(payload.ads, payload.total)
        if (payload.type === "ad_detail") showAdDetail(payload.ad)
        if (payload.type === "analysis_result") appendAnalysis(payload)
    }

    ColumnLayout {
        anchors.fill: parent
        spacing: 0

        // Toolbar: search + filters
        FilterToolbar {                      // FilterToolbar.qml
            id: toolbar
            Layout.fillWidth: true
            Layout.preferredHeight: 64

            searchText: filters.query
            onSearchChanged: function(text) {
                filters.query = text
                requestAds()
            }

            FilterChip { label: "Date"; model: dateRangeOptions }
            FilterChip { label: "Format"; model: ["Image", "Video", "Carousel"] }
            FilterChip { label: "Status"; model: ["Active", "Inactive"] }

            ViewToggle {                     // Grid/List toggle
                mode: intelPanel.viewMode
                onToggled: function(m) { intelPanel.viewMode = m }
            }
        }

        // Ad gallery
        SplitView {
            Layout.fillWidth: true
            Layout.fillHeight: true
            orientation: Qt.Horizontal

            // Main grid/list
            Item {
                SplitView.fillWidth: true

                GridView {                   // Shown when viewMode === "grid"
                    id: adGrid
                    visible: viewMode === "grid"
                    anchors.fill: parent
                    cellWidth: 280
                    cellHeight: 320
                    model: adsModel
                    delegate: AdCard { }
                }

                ListView {                   // Shown when viewMode === "list"
                    id: adList
                    visible: viewMode === "list"
                    anchors.fill: parent
                    model: adsModel
                    delegate: AdListRow { }
                }

                // Pagination footer

                    anchors.bottom: parent.bottom
                    currentPage: intelPanel.currentPage
                    totalPages: intelPanel.totalPages

*** AdSnapshot Schema (SQLite: =.spell/growth/ads.db=)
#+begin_src sql
CREATE TABLE ad_snapshots (
    id          TEXT PRIMARY KEY,          -- platform-specific ad ID
    platform    TEXT NOT NULL DEFAULT 'facebook',
    advertiser  TEXT NOT NULL,
    ad_text     TEXT,
    thumbnail   TEXT,                      -- local path or URL
    start_date  TEXT,                      -- ISO 8601
    end_date    TEXT,
    status      TEXT CHECK(status IN ('active', 'inactive')),
    format      TEXT CHECK(format IN ('image', 'video', 'carousel', 'other')),
    spend_lower INTEGER,                   -- in cents
    spend_upper INTEGER,
    impressions_lower INTEGER,
    impressions_upper INTEGER,
    landing_url TEXT,
    starred     INTEGER DEFAULT 0,
    tags        TEXT DEFAULT '[]',          -- JSON array
    notes       TEXT DEFAULT '',
    scraped_at  TEXT NOT NULL,             -- ISO 8601
    raw_data    TEXT                        -- full JSON blob from scraper
);

CREATE INDEX idx_ads_advertiser ON ad_snapshots(advertiser);
CREATE INDEX idx_ads_status ON ad_snapshots(status);
CREATE INDEX idx_ads_start_date ON ad_snapshots(start_date);

*** Agent-Driven Editing Flow
1. User requests a report via chat: "Generate weekly digest for Acme Corp"
2. Agent creates =reports/weekly-digest.typ= using Typst with ora-brand imports
3. Agent sends =typst_update= with content — editor populates, preview renders live
4. User sees PDF forming in real-time as agent streams Typst source
5. User can manually edit after agent finishes — preview updates on each keystroke

*** Click-to-Code Protocol
The =typst-ts= WASM renderer maintains a source map from rendered output coordinates
to source line numbers. When the user clicks on the preview:
1. WebEngine JS captures click coordinates
2. =typst-ts= resolves coordinates → source line via its source map API
3. JS posts =CLICK_TO_CODE:{line}= via =console.log= (intercepted by QML =Connections=)
4. QML calls =editor.goToLine(line)= to move cursor and scroll

- Apply template: agent scaffolds the selected template into a new file.
- Cmd+S: saves current file via =bridge.send({ type: "file_save", ... })=.
- Agent streaming: editor shows incoming text with cursor at end, preview updates incrementally.

Rectangle {                                  // StrategyModeOverlay.qml
    id: strategyOverlay
    anchors.fill: parent
    color: SpellTheme.background
    visible: false
    z: 100                                   // Above panel stack, below modals

    property var checklist: []
    property string briefContent: ""
    property var researchSections: []

    function handleMessage(payload) {
        if (payload.type === "strategy_research") appendResearch(payload)
        if (payload.type === "strategy_brief_update") updateBrief(payload.content)
        if (payload.type === "strategy_checklist") updateChecklist(payload.items)
        if (payload.type === "strategy_activate") activate(payload)
        if (payload.type === "strategy_deactivate") deactivate()
    }

    function activate(payload) {
        visible = true
        briefContent = payload.initialBrief || ""
        checklist = payload.checklist || defaultChecklist()
        researchSections = []
    }

    function deactivate() {
        visible = false
    }

    function defaultChecklist() {
        return [
            { id: "market", label: "Market data reviewed", checked: false },
            { id: "competitor", label: "Competitor analysis complete", checked: false },
            { id: "budget", label: "Budget implications assessed", checked: false },
            { id: "timeline", label: "Timeline validated", checked: false }
        ]
    }

    ColumnLayout {

        anchors.margins: SpellTheme.spacingXL

        RowLayout {

** Data Flow
| Direction | Message Type              | Payload                                     |
|-----------+---------------------------+---------------------------------------------|
| In        | =strategy_activate=       | ={ initialBrief, checklist }=               |
| In        | =strategy_deactivate=     | (none)                                      |
| In        | =strategy_research=       | ={ title, icon, content }= — append section |
| In        | =strategy_brief_update=   | ={ content }= — agent writes brief          |
| In        | =strategy_checklist=      | ={ items: [{ id, label, checked }] }=       |
| Out       | =strategy_exit=           | (none) — cancel strategy mode               |
| Out       | =strategy_approve=        | ={ brief: string }= — approved brief text   |

** User Interactions
- Scroll research panel: review web search results, competitor data, market metrics as
  the agent populates them in real-time.
- Edit strategy brief: user can modify the agent-generated brief before approval.
- Check approval items: must check all items before "Approve" enables.
- "Approve": sends brief to agent, exits strategy overlay, agent proceeds with execution.
- "Exit Strategy": cancels without approval, returns to normal panel view.
- Sidebar navigation: still functional — user can switch panels while strategy overlay
  is active (overlay hides, sidebar state preserved, overlay returns when strategy panel
  re-selected).
