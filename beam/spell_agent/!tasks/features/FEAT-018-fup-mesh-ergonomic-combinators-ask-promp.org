* Sub-items (each independently shippable over FEAT-011/016/017)

** S-A: ask (the function) + prompt:: (the freeze)  [doc 12, 14 Decision 4]
- ask: a STRICT function (ask template bindings) -> runs a SubAgent mission, returns
  DATA. The 90% LLM call. Desugars to spawn + await-session (the sync altitude).
- prompt::: a reader form that FREEZES holes as data (deferred/quoted) — ONLY for what
  a function cannot do (a watch :do, a deferred view, a posted-prompt finding).
  Sibling of tmpl::; reuses PLAN-012 reader machinery.
- NO :await flag (Decision 2); authority (tools/region) GRANTED not inferred (Decision 5).

** S-B: scatter / gather / mesh-map (the fan-out combinators)  [doc 11, 14 Decision 1/2]
- scatter [x xs] prompt-template -> spawn (await-free) N children into a region,
  return handles. = spawn lifted over a collection.
- gather handles -> await-session each, collect results (the fan-in join).
- mesh-map = scatter + gather fused (the 90% fan-out). All FUNCTIONS over mission
  VALUES, not reader forms (Decision: keep sugars as functions).
- cache-aware: scatter posts shared context to the region ONCE + uniform children
  (FEAT-017 lens + FEAT-016 plan) — the "smart passing".

** S-C: on / reconcile / mesh-view  [doc 11]
- on = black/watch sugar (a quoted :do); reconcile = rendezvous + decide; mesh-view =

* S-F: spawn-site introspection (absorbs the cancelled FEAT-016)
The general sugar caching is just ONE instance of. Introspect WHERE an agent was
spawned (the call site's enclosing form + scope) and to-do-WHAT (the prompt/holes),
and infer a BUNDLE of run parameters — NOT just cache layout:

  spawn_profile(call_site, prompt_holes, handle) ->
    {:model     m,            ; cheap classify @ fan-out -> Haiku; deep refactor -> Opus
     :budget    {:max_turns}, ; shallow ask -> 2; open mission -> 12
     :tools     [..],         ; the attenuated set the site implies (still GRANTED, doc 14)
     :cache     placement,    ; <=4 prefix breakpoints over shared (region@W) vs per-child
     :returns   shape}        ; narrowed from the splice site (S-D)

KEY STANCE (per the user, this review): caching is PROVIDER-INCIDENTAL — it exists
only because API providers reward prefix stability. It is therefore NOT a primitive
and NOT its own FEAT; it is one OUTPUT of spawn-site introspection, exploited by this
sugar, derived from the immutable-projection-at-a-watermark the stores already give
for free (FEAT-008/009 + FEAT-011 watermark). If a provider stopped rewarding
prefixes tomorrow, only the :cache field of the bundle goes away; everything else
(model/budget/tools/returns inference) stands.

- the immutable projection at a watermark (handle :watermark, FEAT-011) is the real
  thing; :cache placement is a readout of which projection segments are shared.
- reuse PLAN-012 hole-dependency analysis for the shared/per-child split (same pass
  as the tmpl:: dirty-set — do NOT reimplement).
- generalize anthropic.ex apply_cache_control_cap to accept a placement (it currently
  caps to 1 of 4) — but ONLY as the executor of the :cache field, never as a primitive.

Acceptance (when pulled): spawn_profile returns a sensible bundle for a fan-out site
(small model, cached shared prefix) vs a top-level site (large model, no cache
bother); the :cache field is OPTIONAL and absent when projection sharing is trivial.
