* Goal

Stop paying O(forest size) =Sanitize.term= cost on every keystroke. Sanitize the heavy =data/*= members (=forest=, =vms=) ONCE when they change, cache the result in App state, and reuse the cached sanitized value across keystroke renders. A keystroke that does not change the forest must pay zero forest-sanitize cost.

* Why

=DataBag.build/2= deep-walks the entire span forest (=Sanitize.term=) every frame. The default layout never reads =data/forest= / =data/vms=, and the forest only changes on ={:store_updated}=, never on a keystroke. Measured: full =App.render= grows from 0.5ms (empty) to ~12ms (1200 spans) — entirely from the per-frame forest sanitize + cross-process =Store.spans= copy.

* Design

Two cost sources to eliminate from the keystroke render path:
1. =Store.spans= GenServer.call (cross-process forest copy) inside =DataBag.assemble=.
2. =Sanitize.term= over the forest + vms.

Both inputs (=forest=, =vms=) change only on =reproject= (store update / navigation), which already runs OFF the keystroke-only path for the composer (insert-mode =compose= does not reproject). Cache the sanitized forest+vms in App state, computed in =reproject=, and feed it into =DataBag.build= so render reuses it.

** Concrete shape (adjust to fit during impl)

- App state gains a cached, already-sanitized snapshot, e.g. =:data_cache= holding ={sanitized_forest, sanitized_vms, forest_count}=, plus an identity token (the forest map reference / a monotonic store-version) to detect staleness.
- =reproject/2= (the chokepoint for every forest/gaze change) computes the cache once: it already calls =Store.spans= for projection, so reuse that single read — sanitize forest+vms there, store in =:data_cache=.
- =DataBag.build/2= grows a path that accepts the precomputed sanitized forest/vms instead of re-reading + re-sanitizing. Keep =build/2='s current behavior as the fallback (headless tests, no cache) so DataBag stays pure + total.
- The cache must NOT change observable =data/*= values: =data/forest=, =data/vms=, =data/forest-count= resolve to exactly what an eager build would produce. A hole referencing =data/forest= sees the same sanitized data.
- Insert-mode keystroke render must reuse the cache (no =Store.spans=, no forest sanitize). Verify =compose= path does not invalidate the cache.

** Edge cases
- First render before any reproject: cache may be empty → fall back to eager build (DataBag stays total). mount already calls =reproject(state, :all)=, so the cache is warm by first render.
- Cells: =cell_bag/1= in =tick_cells= builds a SECOND bag for dep-diffing. It must reuse the SAME cached sanitized forest/vms, or the second sanitize re-introduces the cost on store updates. (Acceptable to keep the cost on store-update ticks since C coalesces those, but prefer reusing the cache.)
- Sanitize identity: a NEW forest map each store update means a cheap reference/equality token suffices; do not deep-compare.
- =data/forest-count= = =map_size(spans)= — keep deriving from the raw spans map (cheap), not the sanitized copy.
