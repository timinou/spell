* Goal

During an active mission, =Store= broadcasts ={:store_updated, suffix}= on EVERY telemetry event. Each currently triggers =reproject(:all)= + a full render. A telemetry burst therefore floods the App's single mailbox with heavy reprojects that interleave with =:poll= and keystrokes → input starvation ("char shows next tick"). Coalesce store-update reprojects so a burst produces at most one reproject+render per frame interval, not one per event.

* Why

The App is one GenServer; =:poll=, keystrokes, and ={:store_updated}= share the mailbox. A keystroke queued behind N heavy store-update renders is delayed by N*render_cost. Even with Task A flattening per-render cost, a burst of store updates still does N reprojects (VM rebuilds) when the screen can only show one. Collapse them.

* Design

Debounce/coalesce store-update reprojects on a short timer (one frame ~16ms, tunable). The first ={:store_updated}= arms a timer and marks a pending reproject; subsequent updates within the window coalesce the dirty =suffix= set rather than each reprojecting. On timer fire, do ONE reproject over the accumulated dirty set.

** Concrete shape (adjust during impl)
- App state gains coalescing fields, e.g. =:store_dirty= (accumulated suffixes / =:all=) and =:store_flush_timer= (timer ref or nil).
- =handle_info({:store_updated, suffix}, state)=: merge =suffix= into =:store_dirty=; if no flush timer armed, =Process.send_after(self(), :flush_store, @store_coalesce_ms)=; do NOT reproject inline.
- =handle_info(:flush_store, state)=: reproject over the accumulated dirty set, clear =:store_dirty= and =:store_flush_timer=.
- Mission-finished (={ref, result}= handler) and explicit nav still reproject immediately (=:all=) — only the telemetry =:store_updated= stream is coalesced. Do not delay the terminal "done/failed" status update perceptibly (its reproject is on the result message, not the stream).
- Choose a coalescing window that is invisible to humans for streamed spans (~16-33ms) but collapses a tight burst. Make it a module attribute.

** Interaction with reactive cells
- =reproject= already arms cell debounce timers; coalescing store updates simply means cells see the quiescent state once per window instead of per event — strictly better (matches the cell debounce intent). Confirm =tick_cells= still fires on the coalesced reproject.

** Edge cases
- A ={:store_updated}= arriving with a flush already armed must NOT re-arm (single in-flight timer); just accumulate dirty.
- Dirty-set merge: =:all= dominates a specific suffix; two specific suffixes accumulate to a list (existing =reproject= already accepts a suffix list or =:all=).
- On mission completion the final state must be rendered even if it lands mid-window — the result handler's immediate reproject covers this; ensure a pending store-flush timer does not later clobber it with stale dirty (clearing dirty on the immediate reproject is fine).
- Headless tests that inject ={:store_updated}= then assert the buffer must account for the debounce: either flush deterministically or assert after the window. Prefer a test seam (send =:flush_store= directly, or a 0ms window in tests).
