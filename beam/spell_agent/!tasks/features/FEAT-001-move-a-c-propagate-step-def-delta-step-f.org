* Problem
Moves A (Step.def_delta) and C (Step.form) live on a per-RUN %PtcRunner.Step{}.
Hist.Recorder iterates step.turns PER-TURN (%PtcRunner.Turn{}), which does NOT
carry def_delta or form. So the per-turn consumer cannot reach the Move data and
is forced to re-diff (map_delta) and re-parse (string program). Carry the two
fields one hop down: Step -> Turn.

* Edge cases
- A turn built without a lisp_step (compile-error-before-eval, budget-exhausted,
  prelude attach failure) has no def_delta/form -> nil. Downstream (FEAT-003)
  must treat nil as "fall back to map_delta / re-parse". Do NOT fabricate empty
  deltas; nil is the honest signal.
- def names in 0.12 are BINARY ("x") not atom (carried fact from PLAN-007 Move
  work). def_delta keys are therefore binary. Keep them binary end to end; do
  NOT atomize.
- form is the raw CoreAST tuple shape {:def,name,val,meta}/{:tool_call,name,args}/
  {:call,{:var,a},args}. Pass through verbatim; no normalization here.
