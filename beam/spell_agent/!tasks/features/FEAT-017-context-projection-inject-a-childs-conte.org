* Goal
A spawned child's context is not PUSHED to it — it is a LENS (projection) over the
append-only stores at its spawn watermark: its own hist, its siblings' hists, and
the region blackboard. This is the "rich context" seam: black/* gives WHAT the
cohort found (findings/goals/verdicts), hist/* gives WHY/HOW (the reasoning Node.form
that produced each), and a context lens JOINS them, scoped to the cohort, at seq<=W.

Read first: docs/agent-mesh-theory/15-context-projection-cache.org (U1: hist/* and
black/* are the same projection at two scopes; context = projection over their union).

* The core idea — context = projection(stores, watermark, scope)
- hist/* projection (Hist.Lens.project, hist/lens.ex) = SESSION scope = a mind's past.
- black/* projection (Mesh.Store.region/by_match, FEAT-009) = REGION scope = the
  collective present.
- a CONTEXT LENS projects over the UNION at the child's spawn watermark W:
  (own hist) ∪ (sibling hists @W) ∪ (region records @ seq<=W).

* The join that makes it RICH (the user's nudge: black/* as context source too)
- a black :finding carries :author (a session_id) + :seq. That is a HANDLE back into
  the producer's hist. So the lens can join:
    finding(author=S, seq=N)  ⟕  Hist node(s) of session S
  → inject "the high-risk findings AND the reasoning traces that produced them."
- neither store alone is the context; the projection over BOTH, joined by
  author/seq, is. black = the conclusions; hist = the derivations.

* Smart passing — snapshot (cacheable) + live pull (fresh)
- CACHEABLE BASELINE: project region@W + sibling hists@W → a uniform, immutable
  prefix across a burst (→ FEAT-016 caches it once). Static.
- LIVE PULL: the child still has black/query at runtime for fresh, per-child,
  uncached, only-when-needed reads. Dynamic.
- the split is the tmpl:: statics/dynamics split applied to CONTEXT (doc 15).

* Use cases
- cohort-aware fan-out: child K sees siblings 1..K-1's findings @W WITHOUT a message
  edge (banned) — stigmergic context, cacheable up to W.
- reasoning-joined findings: WHAT (black) + WHY (hist), one lens.
- deterministic replay: same W → same projection → same context (reproducible).
- selective injection: a lens predicate ("only :high risk", "only my subsystem")
  keeps the injected context small AND cacheable.

* Edge cases
- no siblings yet (first child of a burst): sibling projection empty; own+region only.
- a sibling still RUNNING at W: project its findings posted ≤W (monotone, safe); its
  in-flight reasoning is simply absent (no partial-state hazard — append-only).
- large cohort: the scope predicate + watermark bound the projection size; never
  project an unbounded union (cost + cache-size discipline).
- a finding whose author hist is GC'd/windowed: join yields the finding alone (WHAT
  without WHY) — degrade, never fail.

* SCOPE NOTE (this review) — context-projection stands ALONE, caching is incidental
This FEAT is justified entirely by RICH CONTEXT (the WHAT+WHY join over hist+black at
a watermark), NOT by caching. The fact that a watermark projection is immutable and
therefore cacheable is a downstream BONUS exploited by the spawn-site-introspection
sugar (FEAT-018 S-F) — it is not a reason this FEAT exists and must not drive its
design. Build the lens to be CORRECT and RICH (right scope, right join, right
watermark boundary); whether its output happens to cache well is the sugar's concern,
not this FEAT's. If caching vanished, this FEAT is unchanged and still wanted.
The "smart passing — snapshot + live pull" section: keep the SNAPSHOT (it is the
deterministic cohort baseline — a context correctness property) but read "cacheable"
there as "deterministic/reproducible", not as a caching mandate.

* ADDENDUM (this review) — generalize to a SOURCE-FOLD layer (shared with memory threading)
The user noted memory is HOW bindings were folded, drawing on stigmergic + historical
SOURCES. That fold and this context lens are the SAME source layer with two deliveries.
Generalize FEAT-017 from "a lens" to a SOURCE-PROJECTION LAYER that both consume:

** The sources (all over append-only stores at a watermark)
- hist `sees` per node (node.ex:55) -> EDITED FILES (edit/write effects), FILES READ
  (find/get/read effects), TOOL-CALL history. A fold over a session's `sees`.
- black records -> findings/goals/verdicts (the cohort's conclusions).
- the tape (verbatim messages) -> raw conversation (for continuation children only).
- the def-env -> named bindings.
Each is a projection over an append-only source at seq<=W (deterministic, reproducible).

** Two deliveries over the ONE source layer
- PULL (context lens, this FEAT's original scope): project sources -> injected data/*
  the child's prompt holes read. Lazy, rich, for discovery.
- PUSH (memory fold, FEAT-018 S-E): fold sources -> a seed merged into the child's
  def-env (Session.run :inherit_memory). Eager, small, for precomputed reuse.

** Build implication
Build a `Mesh.Sources` (or extend context_lens) module exposing the source folds:
  edited_files(session|lineage, watermark) -> [%{file, diff|content}]
  files_read(session, watermark, opts) -> [path]
  tool_history(session, watermark, kind?) -> [effect]
  findings(region, watermark, match?) -> [record]      (overlaps black/query)
  conversation(session) -> tape                          (continuation only)
Then: context lens = these folds -> data/* (pull); memory fold = these folds -> def-env
seed (push). One source layer, two consumers. This is U1/U3 of doc 15 (one projection,
read many ways) applied to the spawn-context seam.

** Acceptance delta
- edited_files folds a lineage's `sees` into the changed-file set (assert it matches a
  known sequence of edits).
- files_read excludes files only edited (not read) and vice versa.
- the SAME source fold feeds both a pull (data/*) and a push (def-env) in a test,
  proving the shared layer.
