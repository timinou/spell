## DECISION (current-value binding): `data/current` is the primitive; `%` is sugar.

`lens/update`'s `:fn` is a deferred form, NOT a lambda — consistent with every other Spell transform (tmpl:: holes, cell :query, reactions) which receive input through the ambient `data/*` environment, never a positional param.

The current value at the addressed path is bound as `data/current` in the eval env (same capability-bounded host as HoleResolver). `%` (bare, top-level) is READER SUGAR that expands to `data/current` BEFORE the form is frozen to codec data, so the persisted form is uniform `data/*`.

Why this grounding (meta-programming vision):
- ONE evaluation model — open terms over data/*, not a second lambda paradigm.
- LEGIBILITY: HoleDiff.dependencies/1 statically reads `data/<k>` leaves to drive the cache/cell dependency machinery. Binding as `data/current` makes a transform's dependency on the focused value VISIBLE to that same analysis for free; a `%`-lambda arg would be opaque to it. The transform stays inspectable DATA, not opaque code.
- COMPOSES: `data/current` sits in the same bag as `data/status`/`data/ui`, so a transform can read the current value AND run-state in one expression. `%` only yields the one arg — `data/current` is the general case, `%` the degenerate one-arg shortcut.

Surface = `%` (terse, what the agent writes, primary). Ground = `data/current` (what it means, what the runtime/dep-analysis sees).

Edge to handle: `%` already means anon-fn first-arg inside `#(…)`. Scope the sugar to a BARE top-level `%`; inside `#(…)` it keeps Clojure semantics. Pin with a test (`~(str % …)` expands; `~#(str %1 %2)` untouched).
