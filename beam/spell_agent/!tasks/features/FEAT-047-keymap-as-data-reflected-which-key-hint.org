* Why (the delight thesis)
The TUI is powerful but not DISCOVERABLE: a new user at `mix spell.tui` cannot see what keys do what. Research on delightful TUIs converges on three levers, and this repo already holds the substrate for all three AS DATA:
- **which-key hint bar** — show the chord next to the action, live.
- **help overlay / cheat-sheet** — one toggle reveals every binding, grouped.
- **command palette** — type to filter, Enter to fire; "commands are just data + functions."

The keymap IS that data: `KeymapRegistry` holds `(context, chord, intent, reaction)` live, and each context module exposes `keymap/0` (compiled) + `context_name/0`. Today `HintBar` HAND-LISTS a hardcoded subset per focus — the exact "reflect, don't hand-list" drift AGENTS.md forbids. One reflection primitive (keymap introspection) feeds ALL THREE views off a single source of truth, zero drift.

Doctrine (beam-lisp-maximalist): Elixir REFLECTS live bindings into `data/keybindings` rows; `.ptc` ARRANGES the three views (which-key line, help grid, palette overlay). The body materializes + bounds + falls back; the mind authors the words/arrangement.

* Never-brick ladders (cardinal rule)
- overlay content derive fails \u2192 no overlay, frame intact (cells-drawer rescue).
- palette open swallowing keys \u2192 Esc closes from flags alone; C-r is the out-of-band emergency reset and clears palette flags.
- filter/render crash \u2192 type-check keybindings(list)/query(binary)/cursor(int), rescue \u2192 existing placements.
- unbounded state \u2192 safe_flags 32-entry/4096-byte cap + query length cap; clear all palette* on close/reset/fire.
- fired intent corrupts gaze \u2192 shared apply_intent; invalid ctx/intent = no-op; EffectRegistry already no-ops unknown/protected effects.
