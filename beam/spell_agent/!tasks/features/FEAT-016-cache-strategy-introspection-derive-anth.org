* Goal
Maximize prompt-cache reuse across spawned minds by INTROSPECTING a prompt's holes
to derive where Anthropic cache_control breakpoints go. The mesh's sharing topology
(system → region@W → siblings@W → per-child) IS the cache hierarchy (append-only
stores → a projection at seq≤W is immutable → a perfect cache key). One static pass
over hole-dependencies places ≤4 breakpoints to maximize Σ(tokens × children-sharing).

Read first: docs/agent-mesh-theory/15-context-projection-cache.org (the full
correspondence: context = cache = reactivity, all projections at a watermark).

* Wave / deps

* The mechanism — cache_plan(prompt_holes, watermark) -> segmented_prompt
1. WALK the prompt's holes; CLASSIFY each hole's dependency scope:
   :static | :system | :region@W | :siblings@W | :per-child.
2. ORDER segments most-shared → least-shared (longest-lived prefix FIRST — prefix
   caching requires the stable part leads).
3. PLACE <=4 cache_control breakpoints at scope transitions. Anthropic caps at 4
   (anthropic.ex apply_cache_control_cap, currently uses 1 of 4 on the system block).
   When scopes > 4, CHOOSE the 4 maximizing Σ(segment_tokens × children_sharing) —
   greedy: breakpoint the biggest-shared segments, coalesce the rest.
4. EMIT the segmented prompt with breakpoints.

* Why append-only makes the cache key free
A projection "region R, seq <= W" is IMMUTABLE (store-seq + content_hash never
mutate, FEAT-008/009) → byte-stable forever → a valid prefix cache key by
construction. No cache-invalidation logic needed: the watermark IS the version.

* Anthropic caching model to honor (introspect how it actually works)
- prefix cache: a hit requires the prefix byte-identical to a prior call.
- <=4 cache_control breakpoints; each marks "cache up to here".
- longer-lived (more-shared) content must come EARLIER in the prompt.
- a per-child unique tail must come LAST (uncached) or it poisons the shared prefix.
- INVARIANT this FEAT enforces: never place a per-child segment before a shared one
  (it would make the shared prefix differ per child → zero hits). Order is correctness.

* Edge cases
- a prompt with NO shared holes (all per-child): no breakpoints beyond system; correct.
- > 4 sharing scopes: greedy selection; assert it picks max Σ tokens×sharing.
- a per-child hole accidentally ordered early: the placement MUST reorder or refuse
  (correctness invariant above) — test this explicitly.
- token estimation: use a cheap length proxy; the optimization is approximate, the
  CORRECTNESS (ordering) is exact.
