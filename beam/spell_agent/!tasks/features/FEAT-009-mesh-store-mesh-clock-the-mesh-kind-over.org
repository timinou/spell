* PRE-CODING CORRECTIONS (oracle MeshFinalCheck, agent://1-MeshFinalCheck)
The per-session Lamport clock is REMOVED. A store-owned per-region monotonic
sequence replaces it — this kills three issues at once (P2.1 retrograde lamports,
P2.3 stale claim fold ordering, and FEAT-012 P1.2 watermark) and mirrors exactly
how recorder.ex already assigns node seq (max_seq + idx, recorder.ex:51-54).

** DROP lib/spell_agent/mesh/clock.ex entirely
- No Mesh.Clock module. No per-session Lamport. The original DC-5 clock design is
  superseded: a per-session scalar starting at 0 emits retrograde values across
  nodes (a late joiner posts lamport 1 though causally later), corrupting both
  claim arbitration and the sealed watermark.

** Mesh.Store assigns a per-region monotonic seq ATOMICALLY at put
- put(impl, %Record{region: r} = rec):
    seq = next_seq(impl, r)            ; atomic, per region
    rec = %{rec | seq: seq}
    Store.put(impl, {:mesh, r, seq}, rec)
    if rec.kind in [:finding, :goal, :verdict]:           ; dedup only these
      index_content(impl, r, rec.content_hash, seq)        ; {:mesh_hash, r, h} => [seq]
- next_seq:
    - Store.Memory: :ets.update_counter on a per-region counter row
      {:mesh_seq, region} (atomic, single-node total order). Add this counter row
      to memory.ex; it is the per-region analog of recorder.ex max_seq but O(1).
    - Store.Khepri: the Raft log IS the total order — use a Khepri R/W transaction
      that reads-and-increments a [:hist, :mesh_seq, region] node, so seq is the
      committed log position (linearizable across nodes). This is also what
      FEAT-012's watermark seals against (a store seq, not a lamport).
- ordering: records sort by seq (a true per-region total order), replacing
  "newest lamport first". query returns by descending seq.

** New store kinds (added to hist/store.ex @type kind + both impls' list/2)
- {:mesh, region, seq}        => %MeshRecord{}       (the record)
- {:mesh_seq, region}          => integer            (the per-region counter)
- {:mesh_hash, region, h}      => [seq]              (content dedup index; SEPARATE
                                                      from the Hist {:hash,h} kind)
- the existing {:hash, h} Hist node index is NEVER written by mesh code (P2.2).

** Acceptance delta
- seq is strictly monotonic per region and assigned by the store (not the caller);
  two concurrent puts to one region get distinct seqs (the contract claim
  arbitration depends on).
- two identical-payload :finding records collapse via {:mesh_hash,...}; two
  identical-payload :claim records do NOT collapse (distinct seqs).
- a mesh put NEVER touches a {:hash, _} key (assert the Hist node index is intact
  after mesh writes).
- claim fold ordering uses seq, deterministic and total per region.
