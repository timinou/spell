* Edge cases
- budget exhausted mid-fan-out: the Nth spawn fails fast; the parent's fold simply
  sees fewer findings (a threshold watch with a ttl handles the shortfall, PT-1/PT-4).
- await:false child crashes: the Task's exit releases the slot (link/monitor);
  SessionRegistry drops it; its already-posted findings PERSIST (PT-4 dead author).
- recursion: a child that itself spawns acquires its OWN slot from the same global
  budget — the cap holds across all depths (D11, the ParallelBudget invariant).
- llm inheritance: the child inherits the parent's llm callback (pass opts[:llm]
  through) unless overridden — same resolution order as SubAgent.as_tool.

* DOC-14 RESHAPE (await-free; supersedes the :await steps above)
The Hickey-pass reconciliation (docs/agent-mesh-theory/14-reconciliation.org,
Decision 2) DISSOLVES the :await flag. This FEAT is now TIGHT: ship only the
native tool/spawn-session primitive, await-free. The ask/scatter/gather sugars are
deferred to a FUP (see PROJ-006 / the filed FUP). Concretely:

** tool/spawn-session ALWAYS DETACHES — returns a handle, never blocks
- spawn_session(args) runs Session.run under a supervised Task and returns
  IMMEDIATELY: {"session" => child_sid, "region" => region, "handle" => ref}.
  There is NO :await arg. "Block and use the result" is expressed by the caller
  awaiting the handle (the gather-of-one case), NOT by a flag on the spec.
- include a companion native verb to REJOIN a handle: "await-session" (args
  {"handle"|"session"}) -> blocks on that Task and returns the child's result.
  This is the minimal join primitive the FUP's gather/scatter will build on; one
  handle = the sync case, a list = fan-in. (Name it await-session to avoid
  clashing with any future bare `await`/`gather` sugar.)
- rationale: a primitive that always detaches is already doc-14-shaped, so the
  FUP sugars are PURE ADDITION over it — no rework, no :await to rip out later
  (the churn we explicitly avoided by going tight + await-free).

** the handle
- the Task ref (or child_sid) is the handle. ParallelBudget slot is acquired
  BEFORE the Task starts and released on the Task's exit (normal OR crash, via the
  Task monitor) — so a detached child that crashes still frees its slot and its
  posted findings PERSIST (PT-4). await-session on a crashed child returns a
  clear {:error, reason}, never hangs.

** inventory params (corrected)
- spawn-session params: ["prompt","region","tools","budget"] (NO "await").
- await-session params: ["handle","session"].

** acceptance deltas (replace the await:true/false bullets)
- spawn-session returns {session, region, handle} immediately; the child runs to
  completion writing to the shared region.
- await-session on that handle returns the child's result (the sync case = spawn
  then await-session).
- end-to-end Fork-A: parent posts goal, spawns 3 children (await-free) that each
  post a finding, parent black/fold's 3 — zero sibling messages. (Test waits via
  a black/watch :count 3 threshold OR awaits the 3 handles — both valid.)
- everything else (budget acquire/release no-leak, capacity-exceeded raise,
  capability attenuation, :llm threading, SessionRegistry membership) UNCHANGED.

* HANDLE carries the watermark (forward-compat, doc 15)
The mission handle returned by spawn-session captures the region's seq AT SPAWN —
the one architectural survivor of the (cancelled) caching FEAT. It is cheap
(Mesh.Store.max_seq(region), already built) and deterministic, and it is the hook
context-projection (FEAT-017) and any later spawn-site-introspection sugar
(FEAT-018 S-F) hang on. Tight FEAT-011 CAPTURES it but does not USE it (same
forward-compat stance as await-free).

  %MissionHandle{
    session:   child_sid,     # the child's hist scope
    region:    region_id,     # the shared blackboard
    ref:       task_ref,      # BEAM Task — await-session / monitor / liveness
    watermark: seq,           # = Mesh.Store.max_seq(region) at spawn (deterministic)
    parent:    parent_sid,    # provenance (sibling-context scope for FEAT-017)
    status:    :running | :done | {:error, reason}
  }

- spawn-session returns this struct (string-keyed for PTC); await-session takes
  {handle|session} and rejoins via ref.
- NO caching logic in FEAT-011 — just capture the watermark as a field. Caching is
  provider-incidental and lives in the FEAT-018 sugar, never in this primitive.

** Desired interface (the mind's view)

From the mind's side A6 should read as a peer of the other agency verbs — same
arg-shaping, same budget field, same best-effort guard posture as `clock/*`:

#+begin_src clojure
;; this goal is parallelizable — spawn a sub-mind scoped to it, get a handle back
(let [h (tool/spawn-session
          {:prompt "Audit native_tools; list each as PTC-able or effect-irreducible."
           :region "effect-floor-refactor"
           :tools  ["find" "sh"]              ;; capability attenuation (D12)
           :budget {:turns 20}})]             ;; SAME budget arg as clock/at, self/spawn
  ;; later, rejoin (the gather-of-one case):
  (tool/await-session {:handle h}))
#+end_src

Naming note: the agency-ladder analysis called this `self/spawn`; the mesh design
calls it `tool/spawn-session` + `tool/await-session`. These are the SAME rung. The
mesh names ship (they predate the ladder framing and carry the await-free +
MissionHandle design). If a `self/*` namespace lands for A1, consider whether
`self/spawn` becomes an alias/sugar over `spawn-session` — see open decisions.

** What is already designed (do NOT re-litigate)
- await-free: spawn ALWAYS detaches, returns `%MissionHandle{}`; `await-session`
  joins. (doc-14 reconciliation — settled.)
- capability attenuation: child gets only the named `:tools` subset + its mesh verbs.
- ParallelBudget: slot acquired before the Task, released on exit (crash-safe);
  the cap holds across recursion depth.
- watermark captured in the handle (forward-compat for FEAT-017/018).

** Further design decisions NEEDED (before/while implementing)
1. *Budget unification with A2/A5.* The `:budget` here MUST be the same shape
   Clock threads into `run/2` (`{:turns :cost_ceiling}`) and clamp to the same
   body ceiling. Today Clock passes budget but `Session.run` does not yet ENFORCE
   a ceiling (noted in PLAN-014). A6 should not invent a second budget path —
   decide the single clamp point in `Session.run` first. CROSS-CUTS A2/A5.
2. *self/spawn vs spawn-session naming.* One verb or an alias? Decide when A1's
   `self/*` namespace exists (FUP-015). Avoid two names for one rung.
3. *Who calls spawn — human-prompted vs executive (A4).* Today a child needs a
   prompt the mind authored THIS turn. When A4 (FUP-016) lands, the executive may
   spawn children autonomously; the budget + progress-guard interaction across
   parent-loop AND child-spawns is unspecified. Defer the autonomous-spawn path to
   A4; ship the human-in-the-loop spawn now.
4. *Relationship to loop/continue (A4).* spawn = CHILD (parallelism, new session);
   loop/continue = SAME session (continuity). Both may be used by the executive.
   Keep them distinct primitives (already the stance — restate so it survives).
5. *Recursion + DurableServer.* A child that spawns acquires its own slot (cap
   holds). If deep spawn-trees must survive node death in a multi-node mesh,
   DurableServer (FUP-014) is the primitive; single-node Khepri rehydrate suffices.
   Out of scope for v1 (single-node), noted for the multi-node revisit.
