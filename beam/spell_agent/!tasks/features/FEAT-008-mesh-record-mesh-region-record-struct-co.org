* PRE-CODING CORRECTIONS (oracle MeshFinalCheck, agent://1-MeshFinalCheck)
A final adversarial review found a FATAL id-scheme flaw. The record design changes
as follows BEFORE coding (this supersedes the original §C/Mesh.Record spec):

** P2.2 (FATAL) — records are keyed by per-region SEQ, not by content hash
- The store key is {:mesh, region, seq} where seq is a per-region monotonic
  integer ASSIGNED BY THE STORE at put time (FEAT-009), NOT a content hash.
  Rationale: two :claim records for the same work MUST coexist (arbitration needs
  to see contention); a content-hash key would collapse them and make the fold
  blind. And the existing {:hash,h} kind is OWNED by Hist nodes
  (lib/spell_agent/hist/store.ex:25-30) — reusing it corrupts the node index.
- content_hash is a RECORD FIELD (for dedup of findings/goal/verdict), never the
  store key. Dedup, when wanted, uses a SEPARATE index kind {:mesh_hash, region, h}
  (FEAT-009) — the {:hash,_} kind is never touched by mesh code.

** Revised struct + identity
- defstruct [:region, :kind, :seq, :content_hash, :author, :t, :payload, :parent,
  :watermark, :sealed]. seq is nil at new/1 (the store stamps it on put). NO
  :lamport field (per-session Lamport is dropped — see FEAT-009 P2.1).
- content_hash/1 : hash(canonical(payload) <> region) — a FIELD used only for
  finding/goal/verdict dedup. canonical/1 unchanged (deterministic term encode,
  not NL normalization).
- new/1 : build with seq: nil, stamp :author, :t, :content_hash. Frozen-data guard
  unchanged (reject pid/ref/handle in payload).
- dedup applicability: content collapse is correct for :finding, FIRST :goal,
  :verdict. :claim and :intention NEVER dedup (each is a distinct event) — they
  rely on the unique seq key, so two identical-payload claims still get distinct
  seqs and both persist.

** Acceptance delta
- Record.new yields seq: nil (store-assigned); two :claim records with identical
  payload are DISTINCT once the store assigns seqs (the contract that makes
  arbitration possible). content_hash is stable for identical payload+region.
