* Problem
Two handle-realization deep-walkers exist:
  - Hist.Realize.walk/1 (beam/spell_agent/lib/spell_agent/hist/realize.ex) — used
    on Hist's write path for node fields AND for the L0 continuation tape/memory
    (recorder.ex maybe_record_cont).
  - PtcRunner.Step.freeze/1's private freeze_term/1 (fork step.ex:471) — realizes
    handles inside a %Step{}.
They are the SAME algorithm (realize %Handle{} via HandleStore, recurse maps/
lists/tuples/struct-fields, tombstone on failure). Move B replaces Hist.Realize
for the Step path, but the CONT tape is not part of a Step, so Hist would still
need a walker for it. Solution: expose ONE public realization walker in the
runtime; freeze delegates to it; Hist calls it for the cont tape; Hist.Realize
is deleted entirely.

* Edge cases
- Handle struct itself must NOT be walked field-wise (its `store` is a pid/name).
  deep_realize realizes THROUGH the store then walks the materialized value —
  preserve that exactly (freeze_handle already does this).
- A realized value can nest further handles -> recurse on the realized term
  (freeze_term already does this; keep it).
- Non-Handle struct: realize public fields, preserve struct type (freeze_struct).
- Evicted/tombstoned handle: {:error, reason} from HandleStore.realize ->
  {:__frozen_unrealized__, reason, meta}. Never crash.
