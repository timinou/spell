* Goal
Close the human loop: a render hole declares a fillable :slot (an answer-schema + which
black/* record its fill writes); the render walk AUTO-GENERATES the TUI affordances
(keymap bindings) and the reactions (keystroke -> black/post a resolution). The human
fills the hole by a keystroke; the hole re-resolves from the medium on the next cell
tick. Input is just a hole whose resolver is a person.

Read first: docs/agent-mesh-theory/17-the-human-surface.org (the full thread + HS-1..6),
16-decisions-and-the-human-surface.org (the :decision/:resolution records this fills).

* Why this is small (the mechanism is already two-level)
The keymap registry (PLAN-346, keymap_registry.ex) is ALREADY:
  BINDINGS  {context, Chord}  => intent
  REACTIONS {context, intent} => ptc-source
That indirection IS the affordance->fill loop. This FEAT DERIVES bindings+reactions
from a hole's :slot instead of hand-authoring them. The DSL already turns a keystroke
into a black/post; the new part is the schema -> [bindings, reactions] generator.

* The :slot convention (a field a hole carries)
  :slot {:answer-schema <schema>   ; the flexible structure the answer must match
         :resolves <decision-ref>  ; which black/* :decision this fill resolves
         :tier <:human|:policy|:agent|:any>}  ; who may fill (the capability descriptor)
The render walk recognizes :slot and invokes the generator for the focus context.

* The generator (the one real new logic — a PURE function)
  affordances(slot, context) -> {bindings, reactions}
  by schema kind:
   - enum {:choice [:a :b :c]} -> one binding per variant (a->:a …) + a reaction each
     posting (black/post {:kind :resolution :payload {:decision ref :answer {:choice v}}})
   - :string -> a binding opening a minibuffer; reaction posts the typed value
   - :bool   -> a toggle binding
   - nested map -> a sub-form (compose generators; defer deep nesting to a FUP)
  Pure: (schema, ref, context) -> data. Unit-testable with zero TUI.

* Edge cases
- runtime-intent atom cap (keymap @max_runtime_intents=256): generated intents must
  REUSE a small fixed set (e.g. slot/choice-N parameterized) NOT mint a new atom per
  decision (atom-table DoS, PLAN-346 W3r). Generate intents from a bounded pool.
- a slot whose schema variant count exceeds available chords: page/scroll the choices
  (a list affordance), do not exhaust the keyspace.
- slot leaves the tree mid-fill: tear down its bindings/reactions (no dangling chords).
- :tier :policy on a slot with no human present: the affordance is not rendered; a
  policy resolver handles it (doc 16 symmetry) - the generator emits nothing human-facing.
- two slots competing for the same chord in one context: last-registered wins OR the
  generator namespaces by focus - decide + test.

* Acceptance (observable)
- a hole with an enum :slot renders affordances; pressing the variant key posts a

- a :string slot opens input and posts the typed value.
- generated intents reuse the bounded pool (assert atom count does not grow per decision).
- slot teardown removes its bindings when the node leaves the tree.
- a :tier :policy slot renders NO human affordance.
- mix check clean.
