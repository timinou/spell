* Problem
`lib/spell_agent/harness.ex` still defaults the pane ring to `[:tree, :answer, :prompt]` in three places:
  - `safe_panes(nil)` (L134)
  - `safe_panes(list)` empty-fallback (L138)
  - `safe_panes(_)` catch-all (L143)

`:answer` was renamed to `:detail` in the PLAN-346 W5 pivot (`Ui.@panes` is `[:tree, :detail, :prompt]`; see `ui.ex` W5 pivot comment). `harness.ex:244-247` even documents that `:answer`/`:prompt` are *deliberately* not given their own keymap context because "both panes resolve through `:turn_nav`" — but that comment describes a pane identity (`:answer`) that no longer exists in `Ui.@panes`. A reaction whose gaze round-trips through `Harness.to_ui/1` with no explicit `:panes` (or an empty/invalid one) gets seeded with a dead atom in its ring instead of the live `:detail`.

- `lib/spell_agent/tui/reaction/ptc.ex` — the sibling rehydration path (`rehydrate/2`) has no such default; it falls back to the PRIOR gaze's value, so this bug is isolated to `Harness.to_ui/1`'s bare-default path (used when a reaction round-trips through `harness/*` verbs with an absent/malformed `:panes`).
