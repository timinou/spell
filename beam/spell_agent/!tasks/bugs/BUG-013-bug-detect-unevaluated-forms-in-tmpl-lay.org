The `{:symbol_ref, "str"}` fingerprint is RIGHT THERE but the diagnostic passes the raw
bridge exception through instead of interpreting it. The agent could not act on it.

* Root cause
`tmpl::` is a quasiquote: only `~`-marked forms evaluate; a bare `(str …)` freezes as
inert data (`{:symbol_ref, "str"}` heading a list). After `HoleResolver.resolve_holes`
runs, that frozen form is still in the leaf field; `Materialize`/`encode` then fails with
the opaque coercion error. The invariant is correct — the DIAGNOSTIC is what's broken.

* Fix (additive, pre-encode)
In `lib/spell_agent/tui/layout_diagnostic.ex`, add a detector that runs in `validate/1`
right after `resolve_holes(node, %{})`, BEFORE the `place`/encode walk:
  - walk the resolved node (maps + lists);
  - recognize a frozen call = a list whose head is `{:symbol_ref, name}`;
    recognize a frozen bare ref = the `{:symbol_ref, name}` tuple itself;
  - on hit, emit a `unevaluated_form` diagnostic (path.to.field, the `name`, the field)
    whose detail + expected name the cause and the one-char fix.

Proposed diagnostic text:
  `<path>`: unevaluated_form: `(<name> …)` inside tmpl:: froze as data — only ~-marked
  forms evaluate. Wrap the whole expression in ~:  `:<field> ~(<name> …)`
  expected: a literal, or a single ~-wrapped expression for field `:<field>`

Plug-in:
  with {:ok, resolved} <- resolve_holes(node),
       :ok <- detect_unevaluated_forms(resolved),   # NEW
       {:ok, leaves} <- place(resolved, @probe_rect, "source") do ...

Happy paths find no frozen call → `:ok` → existing logic unchanged (non-breaking). This
SUBSUMES the lone-bare-ref case (`:fg data/status-color` with no `~`) — same fingerprint.
