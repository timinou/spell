* Summary
A cluster of TUI tests (HoleResolverTest, TmplDemosTest, DataBagTest, HoleDiffTest, AppTest store-coalescing) fail intermittently ONLY under full-suite parallel load (`mix test`, max_cases: 32). Every one passes reliably in isolation. The failing set differs run-to-run and by seed \u2014 the signature of shared-state races, not a deterministic bug.

* Evidence
- `mix test --seed 0`: 8 failures, all in the above modules.
- The SAME modules run alone: 95/95 pass.
- Different seeds fail a different subset.
- Root cause hypothesis: these tests share a process-registered reactive-cell registry / store GenServer (Cell.Registry, Tui.Store) and/or timer-based coalescing windows; under 32-way parallelism they observe each other's state or miss a debounce window.

* Impact
LOW for correctness (the code is fine \u2014 proven by isolated passes), but it ERODES CI signal: a green full-suite run is not reliable, and a real regression in these modules could hide behind the noise.

* Fix options
- Mark the shared-registry TUI tests `async: false` (serialize them), OR
- Give each test an isolated registry/store instance (start_supervised a named-per-test GenServer) instead of a global singleton, OR
- Make the coalescing-window assertions tolerant of scheduler jitter (assert eventual state, not exact timer counts).
