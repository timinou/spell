* Finding 1 (P1, all three reviewers) — capability attenuation is NOT transitive
A child spawned with :tools ["find"] still receives spawn-session in its tool
floor. attenuate/2 derived the GRANDCHILD's tools from the new call args alone,
applied against a FRESH Tools.build_tools_map() in Session.run \u2014 so the child
could call (tool/spawn-session {:tools ["sh"]}) (or omit :tools) and hand the
grandchild shell/define-tool access the parent never had. Violates D12 (monotone
attenuation): capability can only NARROW down the spawn tree, never widen.

** Fix
- Thread an ALLOWED CEILING through the spawn seam. Session.run computes the
  attenuated base, then passes Map.keys(base) (or :all for the root) as :allowed
  into Spawn.verbs/2.
- spawn_session clamps the child's requested :tools to the ceiling:
  allowed == :all (root) -> requested list as-is, or :all when absent;
  allowed == list        -> intersect(requested || allowed, allowed) \u2014 absent
                            :tools means INHERIT the ceiling, never widen to root.
- run_opts[:tools] = the clamped list (or nil when :all), so the grandchild's
  Session.run attenuates against the same ceiling.

* Finding 2 (P1, RevBoundaryCap) — clock wakes restore full tools
An attenuated child still got clock/* verbs; Clock.run_wake re-enters
SpellAgent.run/2 with only session_id (opts[:tools] nil) -> attenuate_base
restores the FULL base surface. A :tools [] child could clock/at a wake whose
prompt calls sh.

** Fix
Omit clock/* from ATTENUATED children (opts[:tools] != nil). The root keeps
clock (unrestricted). Threading the ceiling through clock wakes is a larger change
deferred to a FUP (FUP-019); omission is the conservative correct-now posture.

* Finding 3 (P2, RevJoinLifecycle + RevSessionWiring) — budget leak on Join restart
Budget release lived only in Join's in-memory entry. A Join crash/restart while a
child runs under Mesh.TaskSupervisor orphaned the slot (no releaser on child exit).

** Fix
Move budget release into the CHILD TASK CLOSURE (try fun() after
Budget.release_if(budget)), so the releaser is the child itself \u2014 it survives a
Join restart (the Task runs under the independent TaskSupervisor). Join no longer
releases (no double-release); it only records done/crash + replies to waiters.

* Finding 4 (P2, RevJoinLifecycle) — slot leak if Join.spawn fails after acquire
If Join.spawn exits between acquire and task-start, the slot was never released.

** Fix
spawn_session wraps the post-acquire Join.spawn in try/rescue/catch and releases
the slot before re-raising.
