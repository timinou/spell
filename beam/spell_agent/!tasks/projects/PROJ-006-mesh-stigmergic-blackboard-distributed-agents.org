* The thesis (one sentence)
Distributed agents do not coordinate by messaging each other; they coordinate by
reading/writing a shared, append-only medium that converges on its own — and that
medium ALREADY EXISTS here as the Hist store's content-addressed G-Set hash index.

* The boundary this dissolves
MINE vs OURS, at the agent level. Today a session is an island: it runs, records
its OWN history, and a parent can only nest children synchronously in-process.
Drop the island: sessions contribute monotone findings to a shared region and
fold them — coordinating without a single direct message between siblings. The
comm graph among siblings is the EMPTY graph; all flow is through the medium.

* Why it is reachable (what is already built)
The blackboard is not to be poured — it is to be apertured. VERIFIED in code:
- append-only monotone medium  -> hist/recorder.ex (one node/turn, monotonic seq)
- content-addressed dedup       -> hist/node.ex (id = hash(form_src <> parent_id))
- multi-writer union index (G-Set) -> hist/store.ex ({:hash,h} => [{sid,nid}…])
- pure message-passable entries -> hist/node.ex realization invariant (no live handles)
- local->distributed seam       -> Hist.Store behaviour (Memory | Khepri impls)
- Raft consensus engine          -> Khepri on Ra (khepri_cluster.erl, vendored)
- liveness/membership monitor    -> SessionRegistry (pid-monitored, self-cleaning)
- global termination budget       -> ParallelBudget (token bucket, all depths)
What is NEW is small: a black/* verb namespace (the cross-session generalization
of the self-scoped hist/* verbs), one tool/spawn-session, a Mesh.Watcher engine,
and a thin Ra front for black/decide.

* The record taxonomy (what lives on the blackboard)
A region-scoped %MeshRecord{region, kind, id=content-hash, author, lamport, t, payload}.
Five kinds, four monotone (CALM-free), one consensus-only:
  :goal       monotone (supersede-by-newer) — an objective kept active
  :finding    monotone (pure G-Set)          — a contributed result/observation
  :claim      monotone (append; resolve-by-fold) — "S intends to own work W"
  :intention  monotone (standing trigger)     — "when P holds, do A" (prospective memory)
  :verdict    NON-monotone (consensus only)   — a collective decision ("done"/"winner")

* The six verbs (full contracts in docs/agent-mesh-theory/04-surface.org)
  black/post    monotone write (PUT)        — goal | finding | intention
  black/query   content discovery (QUERY)   — predicate over region records (ambient read)
  black/claim   optimistic claim (CLAIM)    — append + Lamport-min fold; never locks
  black/fold    read-time reduce (FOLD)     — count/group/rank/satisfied? (the parent's job)
  black/watch   register intention          — Mesh.Watcher fires :do on matching post; fuel+ttl
  black/decide  consensus verdict           — Ra leader-election + quorum; the ONLY round

* The A/B switch is ONE parameter (region minting)
  Fork A: region_id = hash(goal <> parent_session <> nonce)   -> isolated, capability handed
  Fork B: region_id = hash(canonical(goal))                    -> rendezvous, content-addressed
Independent sessions naming the same goal compute the same region and MEET without
ever referencing each other. Isolation-by-unguessable-id vs rendezvous-by-content-id.

* The consensus stack (three layers, only the top is consensus)
  L1 monotone state   -> NO consensus (single Raft log = total order; CALM confluence)
  L2 claim arbitration -> deterministic Lamport-min fold (consensus-free, every reader agrees)
  L3 non-monotone verdict -> Ra leader-election + quorum (crash-fault, not Byzantine)
Claim gates IDEMPOTENT work; decide gates IRREVERSIBLE work. (See PT-2.)

* Executive-function backing (docs/agent-mesh-theory/03)
Two structurally EXACT mappings drove the surface:
  claim ≡ basal-ganglia action gating (go/no-go winner-take-all, no central lock)
  watch ≡ frontopolar prospective memory (deferred intention fired by a cue)
The latter PREDICTED the webhook + cross-agent-unblock surface. Five record kinds =
the five executive functions a coordinating mind needs; the monotone/non-monotone
line IS the with/without-central-executive line (Fork A = one executive; Fork B =
a collective synthesizing without one). Deferred (kept as backing): set-shifting
verb, salience/attention budget, confidence-weighted collective decision, an
SAS-style mesh supervisor.

* Acceptance (when someday built)
- Fork A: a parent spawns N children into a private region; children post findings
  and exit; parent folds a ranked result with ZERO sibling messages (showcase 04 §3).
- Fork B: three independently-launched sessions rendezvous on hash(goal), reach a
  single committed verdict via one Ra round despite all three watches firing
  (showcase 04 §4); no split-brain under a 2|1 partition (PT-3).
- Unblocking: a blocked agent's standing watch fires when a webhook-spawned agent
  posts the awaited finding; neither referenced the other (showcase 04 §5).
- Safety: a spawn cycle degrades via ParallelBudget + fuel/ttl, never melts the
  BEAM (PT-1). A crashed claim-owner's work is reclaimed via lease expiry (PT-5).

* Open risks (FUP candidates, non-blocking)

- adaptive spawn-rate throttle (PT-1) and adaptive lease = f(turn latency) (PT-5).

  current, correct model for trusted BEAM peers.

* Second-pass corrections (docs/agent-mesh-theory/06-pressure-tests-deep.org)
A deep adversarial pass found two STRUCTURAL corrections (neither fatal; both
strengthen the design by reusing its own primitives) plus CALM sharpenings:

- DC-7 TWO PLANES (the key correction): consensus membership is over stable BEAM
  NODES (the Khepri/Ra cluster), NOT ephemeral sessions. Sessions WRITE monotone
  records + READ the medium; they never vote. black/decide runs Raft on the node
  cluster, so a session may post-then-exit and its finding still folds. Resolves
  the Fork-B quorum deadlock (sessions come/go) AND the watch-SPOF (per-node infra
  on the same node cluster). Single-node = trivial 1-member cluster = local fold.
- DC-4 RENDEZVOUS is discovery, not NL hashing: hash STRUCTURED keys (PR#, path,
  sha, ticket — the common webhook/resource trigger); for human/NL goals use an
  EXPLICIT coordination slug discoverable via black/query. NEVER hash raw prose
  (false neg: same goal phrased differently → no rendezvous; false pos: collisions).
- DC-1 claim/decide re-cut on EFFECTS: claim gates work whose only effects are
  monotone blackboard writes (or externally-deduped); ANY non-deduped external
  effect → decide. Partially-idempotent work is DECOMPOSED (monotone part claimed,
  irreversible tail decided).
- DC-3 goal supersession is a non-monotone RETRACT: re-goaling is owner-only
  (Fork A parent) or via decide (Fork B); "active goal" = owner-serialized
  LWW-register. Keeps finding/claim/intention purely monotone.
- DC-6 watch firing dedups via claim (exactly-once across nodes); Mesh.Watcher is
  PER-NODE infra, not a global SPOF.
- DC-8 decide folds a SEALED watermark snapshot (idempotent across leader
  re-election; a region can have successive verdicts v1≤w1, v2∈(w1,w2]).
- DC-9 a terminal verdict latches region :sealed (monotone); archive via Hist.Window.
- DC-2/DC-5/DC-10: settle_ms barrier for expensive claims; Lamport-min is
  deterministic-not-fair (suffices); watch :do depends on event + re-query only.

Build impact: FEAT-5 (Mesh.Consensus) is explicitly NODE-level Raft over the Ra
cluster; FEAT-4 (Mesh.Watcher) is per-node + claim-deduplicated; region minting
(FEAT-1) takes a structured-key | explicit-slug, never NL hash.
