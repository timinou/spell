* Initial Message

ok your goal is to CONSOLIDATE around the vision of the spell agent so that we can keep building on a strong basis. i want every single action, every single chord, every single intent to be translatable to an operation on code, leveraging the homoiconicity of beam lisp. the `C-w h/j/k/l` is an example of such a thing. i want that logic to extend. * Thesis

`PLAN-009`/`PLAN-021`/`PLAN-346` already made the layout TREE, KEYMAP BINDINGS, and
REACTIONS homoiconic (PTC data, `lens/`+`harness/`+`keymap/` verbs). This plan closes
the remaining compiled boundary: NAVIGATION ROUTING (which pane can be focused, what
"the pane to the left" means, what a fillable value's keystroke does) is still a
closed, compiled dispatch. Close it so a NEW agent-authored layout automatically
inherits the ring, the spatial C-w jump, and (longer-horizon) fillable-hole
affordances — with the atom-DoS discipline and durability the substrate already
demands, applied BEFORE the surface widens further.

* Verified findings this plan is built from (2026-07-04 review)

1. The RING (`C-j`/`C-k`) already generalizes for free today: `Lens.focusables/1`
   collects every node where `type == "pane"`, with NO gate on pane name/vocabulary.
   Confirmed: the `"focusable" => true` tag `DefaultLayout.pane_node/2` stamps is
   NEVER READ anywhere in the codebase (dead data — a tag with a producer and no
   consumer). Panes ARE focusable by default already; this tag should become a real
   opt-out predicate or be deleted, not left as vestigial dead weight.
2. The SPATIAL jump (`C-w` + h/j/k/l) does NOT generalize: `App.focus_stack/1` is a
   hardcoded case dispatch (pane atom -> compiled context-module list); `Ui.safe_pane/1`
   is a closed atom whitelist (`:tree/:detail/:prompt/:history/:cells`); `Spatial.extreme/2`
   (the pure geometry rank) is only ever called from `App.frame_target/frame_regions`
   (Elixir), with no `lens/` PTC surface. An agent-added pane renders (body-slot
   shadow) but cannot be focused, receive a pane-local keymap, or be a spatial C-w
   target.
3. `Harness.safe_panes/1`/`to_ui/1` (harness.ex:134-148) default to a STALE pane atom
   `:answer` (renamed to `:detail` in the W5 pivot) — real drift, filed as BUG-024.
4. `FUP-020` (hole affordances, doc 17 "human as resolver of holes") is the deepest
   unbuilt generalization: it extends "every chord is code" from NAVIGATION to ANY
   declared fillable value (a decision, a diff review, a form) via a pure
   `schema -> [bindings, reactions]` generator riding the EXISTING KeymapRegistry
   two-map indirection. Small, high-leverage, currently blocked on FEAT-019 (now
   DONE) — re-check its blocker status before starting.
5. `FUP-007` (atom-DoS hardening) is filed but incomplete; a pane REGISTRY is
   ANOTHER string->atom coercion chokepoint (bounded, but still a chokepoint) —
   harden the EXISTING freeform surface's chokepoints before adding a new one, not
   after.
6. `FUP-009` (durability) — LayoutRegistry/KeymapRegistry/ToolRegistry are all
   in-memory Agents. Every layout/shortcut an agent (or user) authors currently
   evaporates on process exit. This undercuts "the system keeps coming up with
   layouts" as a COMPOUNDING capability — without persistence, nothing survives to
   compound.
7. `FUP-025` (mesh TUI inspector) independently NEEDS the pane-registry generalization
   (new Regions/Board/Spawn panes navigable via the SAME mechanism) — raising the
   priority of Wave 1, since a second initiative is now blocked on it too.
8. `FEAT-028` (zipper-based focus ring) was correctly CANCELLED after tracing the
   real keystroke data-flow and finding the refactor's premise false (`%Ui{}` IS
   canonical on that path, not the tree). Precedent for this plan's discipline:
   VERIFY the actual call graph before generalizing a mechanism — do not assume
   dissolving a boundary is free.

* Waves (dependency-ordered; each wave is independently shippable + reviewable)

** Wave 0 — hardening the chokepoint BEFORE widening it (FUP-007)
Audit + close the atom-DoS hardening checklist for the EXISTING freeform surface
(widget type/field coercions, style/border/constraint enums, slot names) per the
FUP-007 checklist, with the fuzz/property test (stream_data) asserting
`:erlang.system_info(:atom_count)` does not grow beyond a fixed delta. This is a
PREREQUISITE for Wave 1: a new pane registry is itself a bounded-intern
chokepoint, and it should be built to a codebase that has already proven out the
discipline end-to-end, not be the FIRST place it's applied under pressure.
- Reviewer swarm: security-focused pass over every `String.to_atom`/
  `String.to_existing_atom` call site added or touched across PLAN-009's surface.

** Wave 1 — navigable agent-added panes (FUP-005) + the dead focusable tag
- Replace the fixed `Ui.@panes` whitelist with a bounded runtime pane REGISTRY
  (mirror `KeymapRegistry.define_intent/1`: capped count, domain-shaped name,
  intern-once). `safe_pane/1` consults it.
- `focus_stack/1` becomes DATA: a registry entry carries its context-stack
  (default `[Global]` + optional agent-authored reaction context).
- Wire the `"focusable"` tag as a REAL predicate in `Lens.focusables/1` (or
  remove it if the team decides "all pane nodes are focusable, no override" is
  the permanent contract — decide explicitly, do not leave it dead).
- Fix BUG-024 (stale `:answer` pane atom in harness.ex) in the same wave since
  it touches the identical pane-vocabulary surface.
- Reviewer swarm: correctness (registry bounds enforced + tested) + regression
  (168-test reaction algebra still green) + the BUG-007/012 render-adoption-gate
  lesson (pane identity must stay keyed on something a reshape can't move).

** Wave 2 — spatial focus as a lens/ verb (FUP-031, depends on Wave 1)
- Expose `lens/frame-target {:dir}` over `Surface.resolve_holes |> Surface.layout
  |> Spatial.extreme` (the existing pure geometry, new PTC-callable caller).
- Update `App.frame_regions/1`'s candidate filter to consult the Wave-1 pane
  registry (not the bare old `Ui.safe_pane/1`), so a registry-backed pane is a
  valid spatial target.
- Consider collapsing `App.frame_target/frame_regions` into thin callers of the
  new shared verb (one source of truth for the ranking call path) if it doesn't

- Reviewer swarm: does this preserve `Spatial`'s pure-function testability;
  does the collapsed call path risk a BUG-007-class silent divergence between
  the native render path and the lens/ path.

** Wave 3 — hole affordances (FEAT-020, re-verify blocker status first)

  watcher-fire mechanism is far enough along, or scope Wave 3 to the

- Build the pure `affordances(slot, context) -> {bindings, reactions}` generator
  per FEAT-020's spec (enum/string/bool schema kinds; bounded intent pool reuse,

** Wave 4 — durability (FUP-009, can run in parallel with Wave 2/3 once Wave 1 lands)
