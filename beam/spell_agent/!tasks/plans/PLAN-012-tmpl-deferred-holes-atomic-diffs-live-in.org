* Intention

Make a TUI interface fully definable from ratatui-widget data + the PLAN-009 freeform
layer + HOLES filled with dynamic data at render time — at ZERO marginal cost to the
Phoenix/BEAM runtime. "Sending a new value" must be taken dynamically like every other
value, through generic hole re-interpretation: add one `data/*` key, reference it from
any number of holes, and NO new render-path Elixir is written or recompiled.

The freeform floor (PLAN-009) shipped layout-as-data, but interfaces are STATIC: a
`view/` builder freezes its args, and every dynamic value reaches the screen through
hardcoded Elixir (`app.ex` `status_widget/1`, `composer_widget/1`, compiled `Panes.*`).
This PLAN adds the missing "holes that update as it goes" — the §0 use case of
docs/quoting-spec.md, promoted from research-horizon to buildable.

Two forks are SETTLED (do not re-litigate):

* The layering — one reader primitive, three lowerings

`~`/`~@` is ONE reader primitive ("escape a literal region, capture the following form").
VERIFIED STATE (read fast_parser.ex, 2026-06-22): PLAN-011 W2 (sh::) HAS LANDED — `(sh::`
is a head-position branch (L61) and `~`/`~@` are handled INLINE inside `parse_sh_tokens`
(L210-219) as ~6 sh-specific lines that recurse `parse_expr` and keep/splice the
EVALUATED form. So the reader CHAR and the `(form::` hook are proven; the freeze
machinery is not. The other lowerings do NOT share code with sh:: yet.

The three lowerings differ ONLY at desugar — same char detection, totally different fate:

```
form           ~ captures →  desugars to              when ~ runs       built by
─────────────  ────────────  ───────────────────────  ────────────────  ────────
sh:: …         the form      EVALUATED argv element    once (build)      PLAN-011 (inline)
`{…} backtick  the form      EVALUATED via constructor once (build)      this PLAN (W1)
tmpl:: {…}     the form      FROZEN {"__hole__" 'form} EVERY FRAME (host) this PLAN (W2+)
```

The split that matters: sh:: and backtick EVALUATE the unquoted form (eager); tmpl::
FREEZES it as quoted data and the host re-resolves it per frame (deferred). They share
reader-char detection and diverge COMPLETELY at lowering. ∴ the right move (③, see
:Design decisions:) is to promote `~`/`~@` to a GENERAL reader char emitting
`{:unquote, form}`/`{:unquote_splice, form}` AST, then let each form pick its desugar.

** Clojure mapping (where this sits relative to the language it descends from)

Clojure expresses all of this with ONE mechanism (syntax-quote) PLUS `eval`:

```
this PLAN                          Clojure equivalent
─────────────────────────────────  ─────────────────────────────────────
` backtick (eager quasiquote, W1)  ` syntax-quote                  (1:1)
~ unquote (evaluate a hole)        ~ unquote                       (1:1, same char/meaning)
~@ splice                          ~@ unquote-splicing             (1:1)
tmpl:: (deferred holes as data)    NO direct equivalent — the novel rung
```

The gap IS the point of tmpl::. Clojure's syntax-quote is EAGER: `` `(a ~x) `` evaluates
`~x` once, now; there is no built-in "freeze the holes as data and re-resolve later." To
get deferral in Clojure you hand-roll it: store a quoted form `'(str model …)` and call
`(eval …)` per frame — EXACTLY the general `eval` this spec refuses (quoting-spec §6).
tmpl:: replaces that `eval` with the capability-bounded `resolve_holes` host (W3).

Two deliberate SIMPLIFICATIONS vs Clojure's `~` (do not implement these):
- NO symbol auto-qualification (Clojure `` `x `` → `user/x`). Ours is a plain data
  template; a symbol stays the symbol it was written as.
- NO gensym (`foo#`). Templates build DATA, not hygienic macro code, so there is no
  capture to avoid.
These omissions are correct: tmpl:: is data-templating, not a macro system.

The deferred timing is the genuinely new design. Everything else maps 1:1 to Clojure.

* Design decisions (settled this review, 2026-06-22 — verified against code)

Four decisions taken after reading the landed sh:: implementation. They are SETTLED;
later waves implement them, do not re-open.

** ① sh:: has landed — but `~` is INLINE, not shared (R1 resolved, extraction still owed)
VERIFIED: `parse_sh_tokens` handles `~`/`~@` as sh-specific inline clauses (fast_parser.ex
L210-219). The reader CHAR is proven free and working; there is NO reusable sub-reader.
∴ W1/W2 do NOT "reuse a shared sub-reader" (it does not exist) — they must FIRST extract
one (see ③). R1 downgraded from "dependency/blocker" to "precondition proven, refactor owed."

** ② sh:: `~` EVALUATES; tmpl:: `~` must FREEZE — the load-bearing divergence
In sh::, `~form` recurses `parse_expr` and the form is EVALUATED at call time (a live argv
element). tmpl:: needs the OPPOSITE: `~form` freezes as `{"__hole__" 'form}`, never
evaluated at build. They share char detection and diverge TOTALLY at lowering. An
implementer who copies sh::'s "parse_expr-and-keep" gets eager holes — the bug this note
exists to prevent. W2 states this as an invariant.

** ③ Promote `~`/`~@` to GENERAL reader chars (unify the reader work)
Instead of three bespoke `~` handlers (sh, backtick, tmpl), make `~`/`~@` general reader
chars in `do_parse_expr/2` emitting `{:unquote, form}` / `{:unquote_splice, form}` AST
(Clojure's model). Then:
  - sh:: is RE-EXPRESSED on them (its inline clauses become: read a form, get an unquote
    node, lower it sh-style). Behavior-preserving refactor, gated by the existing sh:: tests.
  - backtick `` ` `` (W1) = quasiquote: desugar unquote nodes -> EAGER constructor calls.
  - `tmpl::` (W2) = quasiquote-to-data: desugar unquote nodes -> `{"__hole__" 'form}` via codec.
Net: ONE `~`-char addition + per-form desugar strategy, REPLACING the bespoke tokenizer
tmpl:: would otherwise need (`parse_expr` handles nested data for free). Strictly less
code, strictly more uniform. NB: a bare `{:unquote,_}` OUTSIDE any quote/template is a
reader-or-analyze error ("unquote outside quasiquote") — mirror Clojure.

** ④ W0 codec may already exist — reuse `Step.form` before writing fresh
Commits `effe383b` (Step.form — executed CoreAST as data) + MOVE-A/B/C produce
CoreAST-as-data already. W0 MUST first check whether `Step.form`'s AST->data path (and any
inverse) is reusable as the QuoteData codec before authoring a new module. Verify, don't
assume; if reusable, W0 shrinks to "lift analyze_quote + adopt the existing codec."


* The data-contract invariants (what every layer agrees on)

1. A frozen hole is ALWAYS a string-keyed map `{"__hole__" form}` (or
   `{"__splice__" form}` for variable-length), where `form` is quoted-AST-as-data:
   plain maps/vectors/scalars, JSON-serializable, no tuples, no closures.
2. The persisted layout tree is ALWAYS inert data — it rides the existing
   LayoutRegistry/Khepri path with ZERO storage-schema change.
3. `Surface.resolve_holes/2` is the ONLY place a hole's form is evaluated, and it is
   CAPABILITY-BOUNDED: pure builtins + `data/*` + `view/`/`harness` read fns only. No
   `tool/`, no `layout/set`, no effects (render-purity; philosophy Layer -4).
4. Failure is DATA, never a crash: a hole that raises or yields a wrong-typed value
   falls to its cached last-good value, then a "·" placeholder; the rest of the frame
   always renders (never-brick discipline; mirrors `safe_resolve_node`/`encodable_placement?`).
5. The App fills a GENERIC `data/*` bag ONCE per frame; adding a value = adding one bag
   key. No hole references a value by a bespoke Elixir path.

** W2 — `tmpl::` reader form (deferred holes, the syntax seam)

*** Goal
`(tmpl:: {:type "paragraph" :text ~(str …)})` reads to a layout node where each `~form`
is FROZEN as `{"__hole__" <quoted-form-data>}` and `~@form` as `{"__splice__" <form>}`,

hole (evaluates at build via the W1 path).

*** Design (verified preconditions)
- `tmpl::` is a free token: `:` ∉ symbol_rest_char? ∧ ∉ keyword_char? (same proof as sh::).
- Head-position reader form, detected after `(` like sh:: (VERIFIED hook: the `(sh::`
  branch at fast_parser.ex L61 is the exact template to copy).

- INVARIANT (decision ② — the load-bearing divergence): tmpl::'s unquote desugar FREEZES,

  `path -> form`. For each form, STATIC dependency analysis → the set of `data/<k>` symbols
  it references (walk the quoted form for ns_symbol "data/…").
- Per frame: `changed = keys where data[k] !== prev[k]` (shallow struct compare);
