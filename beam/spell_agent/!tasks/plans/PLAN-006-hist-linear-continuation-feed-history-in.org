* The two-representation model (decision C)
A conversation is kept at TWO fidelities, NOT interchangeable:

| Layer | What | Durable | Editable | Feeds next turn |
|-------|------|---------|----------|-----------------|
| L1 nodes (existing) | homoiconic form/binds/say DAG | yes | yes | NO (lossy) |
| L0 Cont (NEW) | verbatim tape + def env | yes | no | YES |

=Reconstitute.to_messages/1= (the chat lens) is a DISPLAY projection: user
prompt + assistant say only. It DROPS tool calls, tool results, and programs —
fine for a scrollback pane, catastrophic as an LLM feed (the agent would forget
every action it took). So feed-forward cannot use the existing lens.

Decision (user): store BOTH. L0 verbatim tape is the feed-forward source of
truth in the common (linear) case; an edited/branched suffix reconstructing the
tape from L1 is deferred (FUP-EDIT-REFOLD). edit-affects-model = LATER. Caching =
SEPARATE measured FUP (do not conflate with continuation correctness).

* Deferred (comprehensive FUPs)
** FUP-EDIT-REFOLD — edit a term in L1 => the model sees the change next turn
When a node is edited or a branch forked, the L0 tape for the suffix from the
fork point must be RECONSTRUCTED from L1 (a non-lossy =to_llm_messages= lens that
emits tool_use/tool_result faithfully), not replayed verbatim. The unedited
prefix still replays from L0. This is the homoiconic "operable memory" payoff.
Requires: (1) Recorder captures tool_use/tool_result with enough fidelity to
rebuild Anthropic-shaped blocks; (2) a new full-fidelity lens (distinct from the
display chat lens); (3) fork-point detection via =Node.parent_id=. Blast radius
of a bad reconstruction = a wrong continuation, never a corrupt store.

** FUP-PROMPT-CACHE — Anthropic checkpoints, measured
Findings from reading anthropic.ex (UNVERIFIED — confirm via =merge_usage=
cache_read/cache_creation telemetry FIRST):
- Messages are never cached: =apply_cache_control_cap= only ever sets
  cache_control on the LAST SYSTEM block; the growing transcript carries no
  breakpoint => every turn re-bills the whole conversation at full input price.
  The multi-turn win (a moving breakpoint at the last completed turn) is
  unimplemented.
- The system cache likely never hits: =billing_header= injects
  =strong_rand_bytes= (random per request) into the FIRST system block, which is
  INSIDE the cached span (breakpoint on the last block) => prefix bytes differ
  every request => cache write every time, read never.
- TTL: interactive turns often pause >5min (human thinking) => default 5min cache
  expires between turns. The 1h beta (2x write vs 1.25x) likely wins for a coding
  agent; measurable.
Caching ⊥ editing on the same bytes: caching wants a stable append-only prefix;
editing changes the prefix. RESOLUTION = the branch DAG IS the cache structure —
shared prefix + divergent suffix is exactly Anthropic's cache-prefix shape. Put
the cache breakpoint at the fork boundary (=parent_id= tells you where): cache the
unedited prefix, recompute+re-cache from the first edited node. Editing is
"expensive" only for the suffix you actually changed — semantically right.

* PTC vs Elixir boundary (per PLAN-004)
Elixir owns the continuation invariants: building/validating the message list,
the realize-before-persist invariant, cache-breakpoint placement (FUP), fork =>
invalidation (FUP). PTC owns the windowing/compaction POLICY — which nodes enter
the window, where to summarize (a future =hist/window= .ptc default the agent can
author). Elixir materializes the tape + guards the invariant; PTC shapes the
window. A bad PTC window = a worse context, never a corrupt request.
