* Intention

The cleanest interface to write ANY script the runtime would ever need, with three
properties: (1) WRITE almost-native shell with no quoting/escaping ceremony; (2)
COMPOSE scripts with the full Lisp combinator library; (3) REMEMBER a script as a
durable, diffable entry in the toolset. The shell is only the LEAF; Lisp is the
composition layer; results are structured values.

* The three-language seam — Lisp ↔ Elixir ↔ brush (Rust)

This is the heart of the design and the source of TOTAL MODULARITY. Each language
owns exactly one concern, and the boundaries are plain DATA (vectors, maps, terms),
never embedded code. Because every seam is data, any layer is replaceable without
touching the others.

```
┌──────────────────────────────────────────────────────────────────────┐
│ LISP (PTC, the agent's mind)                                           │
│   • surface syntax:  (sh:: rg -l TODO ~dir)                            │
│   • desugars to DATA: (sh ["rg" "-l" "TODO" dir])     ← a plain vector  │
│   • composition:     ->> pmap for filter group-by      ← values only    │
│   • a remembered script = a :ptc tool whose body is (sh …)             │
└───────────────┬────────────────────────────────────────────────────────┘
                │  argv = a vector of STRINGS  (no shell string, ever)
                │  result = a MAP {:exit :out :err :lines}
                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ ELIXIR (PtcRunner + SpellAgent, the orchestrator)                      │
│   • `sh` builtin: validates argv is [string], calls the NIF            │
│   • marshals argv (BEAM list→Rust Vec<String>) and result (struct→map) │
│   • owns lifecycle: timeout, cancel token, supervision, failure ladder │
│   • owns durability: registry → Khepri; recall → hist/crystal          │
│   • NEVER parses shell; NEVER formats Lisp — pure marshalling + policy  │
└───────────────┬────────────────────────────────────────────────────────┘
                │  NIF boundary: Vec<String> argv, env map, opts  →  ExecutionResult
                │  (rustler terms; dirty scheduler; catch_unwind)
                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ BRUSH (Rust, the execution engine)                                     │
│   • runs argv WITHOUT shell-parsing it (inject-proof by construction)  │
│   • owns: process spawn, pipes, redirects, glob expansion, builtins    │
│   • WordPreprocessor bridge resolves skill:// local:// … in argv elems │
│   • returns ExecutionResult {exit, stdout, stderr}                     │
└──────────────────────────────────────────────────────────────────────┘
```

** Why this is total modularity (the load-bearing claim)

Each boundary is a DATA CONTRACT, so each layer swaps independently:

| boundary           | contract (data)                    | swap freely without touching neighbours |
|--------------------+------------------------------------+-----------------------------------------|
| Lisp → Elixir      | `(sh [argv])` vector + result map  | change reader sugar (`sh::`→other) — `sh` builtin unchanged |
| Elixir → brush     | `Vec<String>` + `ExecutionResult`  | swap brush for another exec engine — Lisp/Elixir unchanged |
| reader → analyzer  | desugar to ordinary `(sh …)` call  | reader is pure sugar — analyzer/eval need ZERO change |
| script → toolset   | `:ptc` tool body is `(sh …)`       | durability/recall layer is generic — no shell special-case |

The modularity test (proven by the test suite, §Testing):
- "`sh::` desugars to the SAME data as hand-written `(sh [...])`" → reader is replaceable.
- "the `sh` builtin treats argv as opaque strings" → engine is replaceable.
- "a remembered `(sh …)` tool composes/recalls exactly like a Lisp tool" → toolset is generic.

** The data-contract invariants (what every layer agrees on)

1. argv is ALWAYS `[String.t()]` after desugaring — a hole is exactly one element.
2. the result is ALWAYS a string-keyed map `{:exit int, :out str, :err str, :lines [str]}`.
3. no layer up-leaks the layer below: Lisp never sees a Rust struct; brush never
   sees a Lisp form; Elixir never parses shell or formats Lisp.
4. failure is DATA, never a crash: a panicking/timing-out command returns
   `{:exit nonzero, :err …}`; the agent loop survives (never-brick discipline).

** W2 — sh:: reader form (syntax seam)

*** Goal
`(sh:: rg -l TODO ~dir)` desugars to the SAME AST as `(tool/sh {:argv ["rg" "-l" "TODO" dir]})`. Pure sugar.

*** CONTRACT UPDATE (discovered in W1)
The PTC tool boundary (`build_args_map` in eval.ex) accepts a MAP only — positional
vectors like `(sh [...])` are REJECTED ("named arguments required"). And native
tools dispatch via the `tool/` namespace. ∴ the desugar target is
`(tool/sh {:argv [...]})`, NOT `(sh [...])`. The `sh::` reader builds that map form.

*** Design (verified preconditions — do NOT re-litigate)
- `:` ∉ symbol_rest_char? ∧ ∉ keyword_char? → `sh::` is a free token (no Clojure ::kw collision).
- `~` is an unused reader char.
- analyzer/eval need ZERO change: the desugar target is an ordinary `(sh [vector])` call.

*** Reader change (fast_parser.ex)
- In `do_parse_expr/2`, the `"("` branch: after consuming `(` and ws, peek for `sh::`. If matched,
  delegate to `parse_sh_list(cursor_after_sh::, depth)`; else fall through to `parse_sequence` UNCHANGED.
- `parse_sh_list` reads tokens until the matching `)`:
  - whitespace-separated bare word → `{:string, word}` (word = run of non-ws, non-`)`, non-`~`, non-`"` bytes;
    also stops at `~`).
  - `~` then one form → recurse `parse_expr` (unquote). Splice form `~@` → wrap `{:sh_splice, form}`.
  - `"…"` → existing `parse_string` (a token containing spaces).
  - close `)` → finish.
- Desugar (in the reader, before returning AST): build
  `{:list, [{:symbol, :sh}, {:vector, parts'}]}` where parts' lowers any `{:sh_splice, f}` by emitting
  `(into [] (concat seg …))` segmentation. SIMPLEST correct lowering: if no splices, emit a plain
  `{:vector, parts}`; if splices present, emit `{:list,[{:symbol,:concat}|segments]}` wrapped to a vector
  via `(vec (concat …))`. Keep the no-splice path allocation-free and obvious.
- NO new AST node escapes the reader; `{:sh_splice,_}` is consumed during desugar.

*** Edge cases
- empty body `(sh::)` → `(sh [])` → W1 error path (documented).
- `~` at end with no form → reader error "sh:: unquote needs a form".
- nested parens via `~(f x)` → recursion handles it; bare `(` inside argv (not after `~`) is a literal
  word char? NO — to keep it simple, a bare `(` inside sh:: body is a reader error directing the user to
  `~(…)` for evaluation or a quoted string for a literal paren. (Documented; keeps tokenizer trivial.)
