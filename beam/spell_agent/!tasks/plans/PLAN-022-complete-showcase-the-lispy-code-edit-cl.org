*** P1b — FUP-027: transactional rollback for code/edit (the safety gap)
Today code/edit (code.ex gate_write) does a bare File.write + rename; it is NOT
covered by the execute layer's all-or-nothing file rollback (which tracks the
edit/create PTC tools). So a program that calls code-edit then (fail)s leaves the
file changed. Close it. INVESTIGATE the three FUP options first, then pick:
  1. Route through the SAME seam edit/create enlist in (cleanest IF a native tool
     can reach the execute layer's file-write journal — investigate where execute
     journals a write and whether a native tool can enlist).
  2. Snapshot/restore journal: code-edit snapshots prior bytes + registers a
     restore thunk the run executes on failure (self-contained; duplicates the layer).
  3. Route through pi_kernel_nif::apply_edit + the edit broker (crates/pi-edit-broker,
     txn_journal) — richest (cross-session conflict detection) but needs apply_edit
     to accept a whole-file/form-tree replace.
Decision criterion: prefer (1) if reachable; fall back to (2) for a self-contained
fix; (3) only if the broker path is already ergonomic. Record the decision in the
FUP before coding.
Files: lib/spell_agent/code.ex (the write path) + whatever execute-layer seam (1)
needs; a focused test (code-edit then fail -> file restored; code-edit then succeed
-> file kept).
Accept: a program that code-edits then fails leaves the file at its pre-edit bytes;
a successful program keeps the write; existing code_edit/code_apply tests green.
