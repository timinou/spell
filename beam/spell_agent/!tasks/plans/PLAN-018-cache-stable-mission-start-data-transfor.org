* Goal

Make multi-turn missions cheap and coherent WITHOUT LLM-driven compaction, by
exploiting what spell_agent's history IS: not a prose transcript but an
append-only, content-addressed DAG of CoreAST nodes carrying def-env deltas and
realized tool_calls. Two mechanisms, one decision:

1. CACHE-STABLE MISSION START — close the prompt-cache leak (today: the growing
   message tape is re-read at FULL price every turn; only the system block is
   cached). Freeze a byte-stable prefix; roll a message-level cache breakpoint
   forward each turn.

2. DATA-TRANSFORM REDUCTION — compaction as a PURE FOLD over the node DAG
   (dead-bind elimination, tool-call CSE, stale-read collapse, restorable
   payload spill), not an LLM summary. Deterministic, zero-inference, provably
   lossless for the lossless tier, restorable for the lossy tier.

3. THE RATE-CONTROLLER — a mission-start harness that decides, per turn, from
   cheap token estimates (no inference): roll the cache forward (P-frame) vs.
   reduce + reanchor the cache (I-frame). Reduction is a keyframe; caching is
   the delta between keyframes.

The policy lives as beam-lisp .ptc files (editable, forkable, durable-promotable
by the agent itself); Elixir is a thin mechanism that executes the policy and
owns only what the sandbox cannot (the HTTP body / cache_control, and the
node->tape refold).

Design-only item: review the architecture before any code lands.

* Why this is the right shape (the BEAM-Lisp uniqueness)

Every mainstream harness compacts a PROSE transcript. The only operation prose
admits is "summarize" -> an LLM call: lossy, nondeterministic, an extra
inference, and it mutates the prefix (busting cache) without a provable gain.

spell_agent's tape is NOT prose. Each Hist.Node (lib/spell_agent/hist/node.ex,
recorder.ex) carries:
  - form      : the executed CoreAST (a tree a lens walks; NOT a re-parsed string)
  - binds     : the def-env DELTA the turn introduced (introduced ∪ changed)
  - sees      : realized tool_calls (name, args, result, status)
  - result / prints / say / tokens
  - a content hash (Id.node_id), indexed at {:hash, h}

Five already-built substrate properties, each unlocking a reduction prose can't do:

| substrate property                         | reduction it enables                                   |
|--------------------------------------------+--------------------------------------------------------|
| env is deltaized + reconstructible         | DEAD-BIND ELIM: a (def x v1) rebound before any read   |
|   (Reconstitute.fold_env)                  |   -> drop the value AND its computation; the fold       |
|                                            |   recovers final env. Compiler dead-store elimination. |
| content-addressed nodes ({:hash,h} index)  | TOOL-CSE: hash-identical (tool/sh ...) calls -> keep   |
|                                            |   one, reference the rest. Exact, not heuristic.       |
| structured tool_calls (sees)               | STALE-READ COLLAPSE: N reads of a path, only the last  |
|                                            |   feeds current state -> collapse to last (keep errors).|
| append-only + retained store               | RESTORABLE COMPRESSION is a PROPERTY not a discipline: |
|                                            |   reduced tape holds a node-id stub; original stays in |
|                                            |   the store; hist/recall (built) pulls it back.        |
| the reducer is a lens in the same language | the agent FORKS its own compaction policy at runtime,  |
|                                            |   like hist/lens forks a query. Homoiconic.            |

LLM-driven compaction GUESSES what to forget; data-transform compaction PROVES
what is redundant.

| axis             | LLM compaction            | data-transform compaction          |
|------------------+---------------------------+------------------------------------|
| cost             | an extra inference        | zero — a fold                      |
| determinism      | nondeterministic          | same watermark W -> same bytes     |
| reversibility    | explicit discipline       | free (store retains; tape refs)    |
| cache interaction| mutates prefix, busts     | output is content-addressed ->     |
|                  | cache, no gain back       | itself a cache key                 |
| exploits         | only prose meaning        | env-recoverability, hashes, AST    |

  - billing_header injects cch=<sha256(body)>+rand3 into a system block PREPENDED

  - a mid-session (tool/define-tool ...) mutates the `tools` array -> cache

Net: worst of both — full tape replayed (no pruning) AND re-read uncached.

* The reduction primitives (the data transformations)

A reduction is node-space [node]->[node], then projected to tape-space. Two tiers.

LOSSLESS (env + reasoning provably preserved; safe to apply silently):
  - dead-bind-elim     : drop computations whose ONLY output is a binding
                         overwritten before any read. Fold recovers final env.
  - tool-cse           : collapse hash-identical tool calls to one + references.
  - stale-read-collapse: last read of a path wins; intermediate reads dropped
                         (ERRORS EXEMPT — Manus: preserve failures).
  - print-prune        : prints no later form references -> drop from tape, keep
                         in store.

LOSSY-BUT-RESTORABLE (drop payload, keep a structural handle):
  - result-spill       : tool_result over a token threshold -> replace inline
                         with {node_id, path, digest}; agent re-fetches. Restorable
                         STRUCTURALLY (the store + hist/recall is the path back).
  - span-fold          : a run of turns under a :clearing mark -> replace with a
                         STRUCTURAL digest computed by a lens (tools called, files
                         touched, defs introduced, net env delta) — NOT an LLM
                         prose summary. Window.distill already drops the :clearing
                         mark; this gives its body a data-driven shape.



** Effect taxonomy — the precondition for sound reduction

The primitives above implicitly assume READ-IDEMPOTENCE (tool-cse and
stale-read-collapse are valid only for calls that don't change the world and
re-run to the same answer). Edits and test runs violate both. Reducibility is a
function of a call's EFFECT CLASS, not its token size:

| class    | examples              | idempotent | result value          | reduction                                  |
|----------+-----------------------+------------+-----------------------+--------------------------------------------|
| read     | cat, grep, ls         | yes        | content snapshot      | CSE + stale-collapse + spill (re-runnable) |
| mutation | edit, write, rm, mkdir| no         | confirmation (low)    | dead-store elim; spill body, keep the fact |
| check    | mix test, cargo, lint | no (light) | verdict + diagnostics | structural distillation; collapse superseded|
| external | curl, date, random    | no         | unrepeatable          | NEVER spill (no path back); keep/digest    |

The `external` row is the guardrail: a network/clock/random result has NO
restorable handle — re-running yields a different answer — so it can never be
marked re-fetchable. Restorable compression is valid ONLY when the world can
reproduce the payload.

*** Edits = dead-store elimination on the filesystem

Deep symmetry: a FILE is a binding in the "world env"; successive edits are
REBINDS. dead-bind-elim (for the def-env) has an exact filesystem twin.

  turn 1: edit A (patch P1)   <- dead store IF its span is overwritten before any read of A
  turn 3: edit A (patch P2)
  turn 5: read A              <- live: observes the composed result

An edit's RESULT observation ("applied, 3 lines") is near-worthless — the real
effect is on disk, recoverable by (read A). So:
  - a run of edits to A, no intervening read, where a later edit PROVABLY
    overwrites the earlier span -> the earlier patch body is a dead store: spill
    it, keep the fact "A modified @ {seqs}".
  - edit targets carry span info (foo.ex::Bar.method) -> overlap is decidable.
    NO provable overlap -> keep both (non-overlapping edits compose; conservative).
  - failed edits STAY (error evidence).

Asymmetry vs reads: an edit's restorable handle is NOT "re-run it" (patches are
not idempotent) — it is "the CURRENT file reflects it." The reduced tape asserts
"A is at its current on-disk state"; the path back is the file itself.

*** Test/check runs = structural diagnostic distillation (NOT LLM)

Test logs are the dominant token sink in a coding tape. The reduction is a
DETERMINISTIC parser keyed to the runner's output grammar (mix/cargo/pytest emit
structured results):

  "5 tests, 2 failures
  test foo (file.ex:42) ** (MatchError)..."
    -> a .ptc extractor (a lens over the result string; zero inference)
    -> {passed: 3, failed: 2, failures: [{test, file, line, kind}]}

  - superseded runs collapse to their digest — a 5->2->0 failure trajectory
    survives as {verdict, counts, delta} (tiny; keeps the recovery story Manus
    says to preserve); full logs spill to the store.
  - the LAST run stays high-fidelity (it describes current state).
  - distinction from LLM compaction: the digest comes from a PARSER, not "ask the
    model what mattered" — same determinism guarantee as the rest of the regime.

*** The correctness core — cannot collapse reads across a write (world-epoch model)

Naive stale-read-collapse is a BUG here:

  read A  ->  edit A  ->  read A
  (epoch 0)           (epoch 1)   <- different worlds; BOTH may be load-bearing
                                     (read v1, change, verify v2)

The reducer needs a WORLD-VERSION (epoch) model: per path, order all read/write
events by seq; a WRITE bumps the path's epoch. Reads collapse ONLY within a
maximal write-free run of the same path — last wins, earlier spill. Provably
safe: same-epoch reads returned identical content, and that content is restorable.

This is the SAME dirty-set / hole-dependency analysis doc 15 names (U3: one pass,
read three ways): a read DEPENDS ON its path's world-version; a write INVALIDATES.
Reduction, reactivity, and cache-invalidation are one dependency graph.

*** How the reducer learns a call's effect class

  1. DECLARED — define-tool carries :effect :read|:write|:check|:external;
     built-ins get classes. Clean, homoiconic (effect class is tool metadata the
     projection exposes).
  2. INFERRED from argv head — in this agent EVERYTHING is sh (read/grep/write are
     sh compositions), so reduction must classify by the underlying command head:
     cat/rg/ls->read, >/rm->write, mix test/cargo->check, curl->external. The
     substrate EXISTS: hist/forms {:shell head} already projects turns by shell
     command head (Query.forms(..., {:shell, head}) in namespace.ex); the effect
     classifier is that same projection, head -> class. sh-parse makes argv walkable.

*** Rate-controller tie-in

Edit/test loops are precisely WHY you reduce: they manufacture huge
low-residual-value payloads (patch bodies, test logs). So hist/reducibility is
EFFECT-CLASS-WEIGHTED — a tape thick with superseded test logs and overwritten
edits scores high reducible_tokens, lowering the break-even K* -> reduce SOONER.
The thing that bloats the tape is the thing cheapest to shed, and the estimate
sees that without doing the work.

*** Added invariants (fold into the Edge cases section)

  - EFFECT SOUNDNESS: a reduction MUST consult effect class; never CSE/collapse a
    mutation or external call as if it were an idempotent read.
  - WRITE BARRIER: reads are collapsible only within one world-epoch of their path;
    a write between two reads forbids collapsing across it.
  - NO-SPILL FOR EXTERNAL: a network/clock/random result is never marked
    restorable (no reproducible path back); keep verbatim or digest in place.
  - EDIT OVERLAP: collapse an edit body only on PROVABLE span overwrite with no
    intervening read; otherwise keep the fact and both bodies.
  - CHECK DIGEST FIDELITY: the last check run stays high-fidelity; only superseded
    runs reduce to a parsed digest.

* The rate-controller — reduce vs. cache-a-previous-header (NO inference)

The crux. The two routes are in genuine tension: caching WANTS a frozen prefix;
reducing CHANGES the prefix, busting the cache it was enjoying. Model it as
video encoding: a reduction is an I-FRAME (keyframe — expensive, content-
addressed, becomes the new cache anchor); a normal turn is a P-FRAME (append +
cache-read off the last keyframe). The harness is the rate-controller deciding
keyframe placement.

State at mission-start (session S, turn T):
  W  = watermark (Mesh/Hist max seq)
  A  = seq of last cache anchor (last keyframe)
  F  = est tokens of full prior tape          ) from hist/reducibility — a cheap
  R  = est tokens after reduction             ) lens that estimates WITHOUT
  reducible_tokens                            ) doing the reduction
  K  = expected remaining turns (max_turns - T)

Economics (Anthropic-shaped: read ~0.1x, cache-write ~1.25x base):
  savings(K) = K · 0.1 · (F − R)  −  max(0, 1.25R − 0.1F)
  break-even  K* = (1.25R − 0.1F) / (0.1 · (F − R))

Decision ladder:
  tok_full > window_HARD  -> REDUCE incl. lossy ops   (overflow: can't cache out of it)
  tok_full > window_SOFT  -> REDUCE lossless only
  K > K*                  -> REDUCE now (amortizes)    <- the pure economic trigger
  else                    -> CACHE: roll breakpoint forward, append tail

All inputs are cheap estimates; K from the budget. ZERO inference in the
decision.

"Cache a previously-used header" composes with reduce — TWO cache layers:
  1. STORE-SIDE memo of the reduction. A reduction at (S, W, policy_hash) is a
     deterministic value -> memoize at {:reduced, S, W, policy_hash} in Hist. A
     revisit at the same watermark+policy is a FREE lookup, not a recompute.
     This is literally "reuse a previously-used header."
  2. PROVIDER-SIDE KV cache of the bytes. The reduced prefix is immutable +
     content-addressed -> byte-stable -> the Anthropic prefix cache hits on it
     for every P-frame until the next keyframe.

Strategy: REDUCE RARELY (only when K>K* or pressure), MEMOIZE each reduction
(free recompute on revisit), CACHE CONTINUOUSLY between keyframes. Keyframes are
the only turns that pay a cache-write; everything between is a 0.1x delta off a
content-addressed anchor.

This is one readout of the projection-at-a-watermark doc 15 identified: context
= cache = reduction, all the same immutable-projection-at-W.

* Edge cases / invariants

  - PROVIDER VALIDITY: every reduced/refolded tape must keep tool_use<->tool_result
    pairing (Anthropic rejects orphans). refold MUST guarantee it; reduce MUST NOT
    drop a tool_result whose tool_use survives (or vice-versa).
  - ERRORS EXEMPT: stale-read-collapse and dead-bind-elim never drop a failed
    tool_call or its evidence (Manus: error recovery needs the failure in context).
  - LOSSLESS PROOF: for the lossless tier, Reconstitute.fold_env over the reduced
    slice MUST equal the fold over the full slice — the test that defines "lossless".
  - RESTORABILITY: a lossy spill MUST leave a node-id/path stub that hist/recall
    resolves to the original (the store is retained; the tape only references).
  - CACHE ORDERING (from FEAT-016): never place a per-turn-unique segment before a
    shared one; a shared prefix must lead. Order is correctness, not optimization.
  - DEGENERATE: turn 1 (cold start) — no tape, no reduction, no message breakpoint;
    must behave exactly as today.
  - DETERMINISM: same (S, W, policy_hash) -> byte-identical reduced tape (the memo
    key depends on it).
  - BEST-EFFORT POSTURE: a failing reducer/refold/policy MUST degrade to the full
    cached tape, never crash the mission (same posture as Session.record_history /
    load_continuation today). A bad policy is a worse cache, not a dead agent.

* DESIGN NOTE [2026-06-30]: Resolving the caching <-> compaction tension from first principles

Grounded in: the CWL paper (arXiv 2606.11213, "Beyond Compaction: Structured
Context Eviction for Long-Horizon Agents", Semenov & Dorofeev, 2026-06-11), this
repo's doc 15 (context-projection-cache), and the existing rate-controller
section of this PLAN. Written to settle the architecture before W1 code lands.

** 1. The two objectives, stated exactly

Both are functions over the MESSAGE TAPE — the growing prefix sent every turn.
Let the tape at turn T be bytes [0..N_T].

CACHING maximizes prefix reuse:
  V_cache = Σ_T  longest_common_prefix(tape_T, tape_{T-1}) × read_discount
  read_discount ≈ 0.1  (cache-read ~10% of fresh).
  => MAXIMIZED by FREEZING the past: never touch a byte already sent.

COMPACTION minimizes carried tokens (subject to N_T ≤ window):
  V_compact = Σ_T  N_T × fresh_price
  + two non-token terms: keep N_T in the ATTENTION-HEALTHY regime (CWL: below
    ~30% window) and avoid the per-turn RE-READ of dead weight.
  => MAXIMIZED by REWRITING the past: drop/fold what is no longer load-bearing.

The conflict is mechanical and exact: every compaction edit at byte position p
sets longest_common_prefix = p, ZEROING V_cache for [p..N]. Caching rewards a
frozen history; compaction rewrites history. Move the boundary, burn the cache
below it.

** 2. Why it FEELS fundamental — and why it is not

It feels like a law because of two assumptions that are artifacts of
REPRESENTATION, not of the problem:

  (a) the tape is PROSE -> the only compaction prose admits is "summarize" -> an
      LLM call: lossy, nondeterministic, mutates the prefix with no way to PROVE
      the mutation safe or to REUSE it.
  (b) compaction's output is a fresh, un-addressable thing -> it can never itself
      be a cache key.

Both are FALSE in spell_agent. The tape is a content-addressed DAG of CoreAST
nodes (Hist.Node: form, binds delta, sees tool_calls, content hash). The moment
compaction is a PURE DETERMINISTIC FOLD over addressed nodes, both walls
dissolve. That is the bet of this PLAN, and it is correct.

** 3. The resolution, in three deepening layers

*** Layer 1 — Amortization (the CWL answer, and its failure mode)

CWL meets this tension head-on (§5 "KV cache invalidation") and is honest:

  "CWL's graduated, incremental eviction fragments the prefix more frequently...
   In the worst case, CWL at maximum utilization is NET-NEGATIVE for caching:
   more is spent on cache writes immediately discarded than would have been spent
   on uncached inference. This is, in a narrow sense, WORSE than compaction,
   which produces a single stable prefix after each pass."

Their fix is AMORTIZATION: cap the budget at τ ≈ 80k (~30% of window). Eviction
holds active size CONSTANT near τ, so the bulk below the eviction head stops
moving — new at the tail, equal volume dropped at the head, stable middle accrues
hits. Measured: 20-70% cost reduction, best on "repetitive, structurally similar
turns (iterative code editing)", worst on highly variable tool outputs.

LESSON: caching cost amortizes over the INTER-COMPACTION INTERVAL. Compact every
turn -> no interval -> no amortization -> net-negative. The FREQUENCY of
boundary-moves is the dial.

*** Layer 2 — Rate control (this PLAN's I-frame/P-frame model — the generalization)

This PLAN already frames it better than CWL, as VIDEO ENCODING:
  - compaction = I-FRAME (keyframe): expensive, mutates prefix, pays a cache
    WRITE, becomes the new anchor.
  - normal turn = P-FRAME: append at tail, pays a cache READ off the last keyframe.
  - the mission-start harness is the RATE-CONTROLLER choosing keyframe placement.

This DISSOLVES "cache vs compact": they are the delta and the keyframe of ONE
encoding, not two competing policies. You never pick one globally — you SCHEDULE
keyframes so caching runs free between them. Closed-form economic trigger
(Anthropic-shaped: read 0.1×, cache-write 1.25×):

  savings(K) = K·0.1·(F − R)  −  max(0, 1.25R − 0.1F)
  K*         = (1.25R − 0.1F) / (0.1·(F − R))
  F = full-tape tokens, R = reduced tokens, K = expected remaining turns.

REDUCE only when K > K* (enough future turns to amortize the keyframe write);
else roll the breakpoint forward and append. CWL's τ-ceiling is the OVERFLOW
GUARD on top of this — the window_HARD/window_SOFT rungs of the same ladder.

*** Layer 3 — Content-addressing (the deepest layer: compaction FEEDS the cache)

The part neither CWL nor mainstream harnesses can reach. If the reduction is
DETERMINISTIC + CONTENT-ADDRESSED — same (session S, watermark W, policy_hash) ->
BYTE-IDENTICAL output — then the compacted output is ITSELF a cache key, twice:

  1. STORE-SIDE memo: memoize the reduction at {:reduced, S, W, policy_hash}.
     Re-entry at the same watermark is a FREE LOOKUP, not a recompute. (Literally
     "reuse a previously-used header.")
  2. PROVIDER-SIDE KV: the reduced prefix is immutable + addressed -> byte-stable
     -> the Anthropic prefix cache hits it for every P-frame until the next
     keyframe.

So compaction stops FIGHTING the cache and starts PRODUCING cache anchors. doc 15
already wrote the unification this implies:

  context = cache = reduction = reactivity
  — all one immutable projection over an append-only store at a watermark.
    cache hit ≡ projection at W' shares a prefix with projection at W
    reduction ≡ a pure fold from projection at W to a smaller EQUIVALENT
    reactivity ≡ recompute only the holes whose deps changed since W

Three names, one operation: project an append-only store at a watermark; reuse
what didn't change. The tension was only ever between two READOUTS of the same
projection.

** 4. The spell_agent superpower — why it strictly beats CWL on this axis

CWL's KV-invalidation is IRREDUCIBLE for it: prose eviction is a destructive
in-place mutation with no content-address, and its correctness currency is "the
agent annotated it" (CWL Principle 2 — agent declares episode types + deps, and
§5 admits mis-declaration degrades the policy). spell_agent flips both:

| axis                  | CWL (prose + annotation)        | PLAN-018 (addressed fold)                     |
|-----------------------+---------------------------------+-----------------------------------------------|
| what compaction IS    | drop annotated spans            | pure fold: dead-bind-elim, tool-CSE,          |
|                       |                                 |   stale-read-collapse                          |
| correctness currency  | agent annotation (mis-declarable)| STRUCTURAL INVARIANCE: fold_env(reduced) ==   |
|                       |                                 |   fold_env(full), PROVED                       |
| output addressable?   | no -> invalidates cache         | YES -> IS a cache key                          |
| cost of a pass        | zero inference                  | zero inference                                 |
| redundancy detection  | guesses (which span?)           | PROVES (rebound-before-read, hash-identical)   |

THE DECISIVE ONE — restorability collapses CWL's central dial. CWL's τ is a 3-D
tradeoff (their §5): cost (↓ better), model quality (↓ better), look-back (↓
WORSE — the ONLY dimension pulling up). spell_agent's RESTORABLE compression
(spill payload -> {node_id, path, digest}, re-fetch via hist/recall) engineers
away the look-back dimension: a dropped payload is recoverable from the retained
store.

  => CWL's 3-D dial collapses to 2-D, BOTH favoring a tighter ceiling.
     spell_agent can safely run a LOWER τ than CWL — cheaper AND better-attention

This is the novel synthesis: RESTORABILITY BUYS A TIGHTER BUDGET FOR FREE. It
strengthens CWL's own empirical conclusion ("err toward a lower τ") by removing

  (b) DISTILL CONTEXT -> SHORTER TEXT (LLMLingua-2; "use the model to compress").
      This IS LLM-summarization compaction — exactly what this PLAN REJECTS for
      the lossless tier (the four CWL limitations: unpredictable lossiness,
      structure destruction, blocking cost, hallucination-at-the-worst-moment).

Honest mapping: this PLAN's reduction is NOT distillation in either sense — it is
a STRUCTURAL FOLD, not inference. The one legitimate entry point is the lossy
